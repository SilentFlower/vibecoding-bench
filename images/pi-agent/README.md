# Pi 模型故障恢复

每个账号使用独立 Node 子进程。私有配置从标准输入接收，公开事件从标准输出发送；模型只能调用 Python 所有者提供的业务工具。

临时故障统一识别真实 HTTP 响应、SDK 错误和服务端重试提示，覆盖 408、409、425、429、全部 5xx、连接超时与断流。服务端明确允许恢复的其他状态也可进入有限恢复，但认证、权限、请求格式和明确的内容策略拒绝优先终止。上下文错误采用下述独立的输入缩减路径。SDK 确认的流式 `finish_reason=content_filter` 使用原模型重试链路；业务正文中提及状态码或内容过滤不会触发恢复。

409 和 `content_filter` 先在原模型续接两次；持续失败时可切换到用户配置的其他模型，并暂时冷却失败模型。模型不存在或额度不足只尝试其他配置模型。成功模型会被记住，后续轮次优先使用。单轮最多八次额外恢复，所有重试沿用原停止信号、工作预算和已经确认的工具结果；失败响应中的工具不会执行。只有一个模型时也会先重试该模型。

Pi 指挥及 SDK 默认等级都保持 `thinkingLevel=off`，避免从非思考模型切换时恢复 SDK 的默认思考等级。模型 ID 为 `deepseek-*`（大小写不敏感，支持 `vendor/deepseek-*` 前缀）时，显式声明 SDK 的 DeepSeek 思考格式与能力，使请求带上 `thinking: {type: "disabled"}`。自定义代理端点无法按官方域名自动识别该格式；只标记 `reasoning: false` 不会向上游关闭默认思考，切换主模型的工具历史时会因缺少 `reasoning_content` 返回 400。保留原工具历史，不生成或补造思考正文。

恢复只读取配置端点的状态和两个响应头：`x-should-retry`、`retry-after`。明确禁止重试时停止。短等待不会短于服务端要求；超过十五秒的合法等待交给 Python 持久调度，最长接近二十四小时，不占住模型子进程。无效或越界的等待不会被擅自缩短。所有退出路径均恢复原 `fetch`。

Python 先安排三轮快速恢复，基础等待为 60、120、300 秒，并取服务端等待、额度和运行时段门禁的较晚时间。临时故障持续存在时，转为按原计划间隔、至少十五分钟的低频检查。恢复等待和计数跨服务重启保留；成功后回到正常调度。

`content_filter` 耗尽本轮尝试后同样发送 `model_unavailable` 与 `retry_at`，项目迭代和养号迭代共用上述调度；已开启的计划等待冷却后自动续接原工作，定时关闭时保留进度并暂停。显式禁止重试或等待头无效时仍发送 `provider_content_filter` 并停止。旧版本已经阻塞的工作可在更新后显式启动一次，沿既有模型故障恢复入口重新检查原会话。

手动暂停、未确认的终端输入、累计预算耗尽、身份变更以及明确硬错误不会被自动解除。用户显式启动可重新检查原会话的已知模型故障，仍须通过全部业务门禁。

Pi 的上下文在同一工程目标内连续使用，默认达到 **350,000 token** 时触发模型摘要压缩。页面“Pi 模型配置”可将 `compaction_threshold_tokens` 保存为 10,000～900,000 的整数；旧 schema 1 配置缺少字段时补 350,000，旧客户端省略字段时沿用已保存值。保存后在下一次启动或恢复时使用，项目迭代和工程养号共用该设置。

用量优先读取最近一次有效 SDK 助手的 input、output、cacheRead、cacheWrite，包含缓存输入；尚未计量的新内容使用 SDK token 估算。错误或取消的零用量不会覆盖此前成功用量，压缩前保留消息里的旧 usage 在新摘要边界后不再沿用。已移除先前未部署的 12／24 KiB 字节裁剪和请求硬上限。

启动／恢复前和连续工具批次结束时检查阈值。需要压缩时先等待工具回执持久化，再在 SDK 空闲边界调用公开摘要能力；较早历史分段归纳，保留此前摘要、关键决定、已投递输入、当前进度、待办及约 12,000 token 的近期完整交互。所有片段成功且未取消／超时后才发布新摘要；失败保留原历史。原生自动压缩关闭，由本入口统一调度，避免 0.75.1 仅在提示前和循环结束检查而漏掉持续工具流。

摘要请求和普通推理共用本轮有界重试、模型优先级、服务端等待、取消信号和截止时间，并记录实际用量。新目标直接隔离上个目标历史，不额外请求模型总结已完成目标；原 Pi 文件、Claude 会话、工作区、累计耗时及业务事实保留。目标清单和公开材料继续按需分页读取。

真正上下文拒绝最多在强制摘要后续接一次，不将同一超长输入盲目发给备用模型。禁止重试、服务端等待及原预算仍优先。已确认 `context_limit` 可通过显式启动恢复；旧通用错误必须先有绑定原错误事件的已核实诊断，不能解除其他阻塞。SDK 中自定义模型的规划窗口跟随压缩阈值；这不改变上游真实容量，真实模型仍可拒绝超出其窗口的请求。

本地验证使用真实 SDK 与回环假服务，不调用真实模型：

```sh
npm test
```

测试覆盖可配置 350K 阈值、缓存 token、百万级历史分段恢复、连续工具流与摘要计量、分页材料完整性、上下文恢复边界，以及错误分类、内容过滤重试与降级、跨轮记忆、调度交接、等待、取消、预算、工具不重放、请求隐私和 `fetch` 生命周期。
