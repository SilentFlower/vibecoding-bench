# Pi 模型故障恢复

每个账号使用独立 Node 子进程。私有配置从标准输入接收，公开事件从标准输出发送；模型只能调用 Python 所有者提供的业务工具。

临时故障统一识别真实 HTTP 响应、SDK 错误和服务端重试提示，覆盖 408、409、425、429、全部 5xx、连接超时与断流。服务端明确允许恢复的其他状态也可进入有限恢复，但认证、权限、请求格式、上下文和内容拒绝优先终止。业务正文中提及状态码不会触发恢复。

409 先在原模型续接两次；持续失败时可切换到用户配置的其他模型，并暂时冷却失败模型。模型不存在或额度不足只尝试其他配置模型。成功模型会被记住，后续轮次优先使用。单轮最多八次额外恢复，所有重试沿用原停止信号、工作预算和已经确认的工具结果。

恢复只读取配置端点的状态和两个响应头：`x-should-retry`、`retry-after`。明确禁止重试时停止。短等待不会短于服务端要求；超过十五秒的合法等待交给 Python 持久调度，最长接近二十四小时，不占住模型子进程。无效或越界的等待不会被擅自缩短。所有退出路径均恢复原 `fetch`。

Python 先安排三轮快速恢复，基础等待为 60、120、300 秒，并取服务端等待、额度和运行时段门禁的较晚时间。临时故障持续存在时，转为按原计划间隔、至少十五分钟的低频检查。恢复等待和计数跨服务重启保留；成功后回到正常调度。

手动暂停、未确认的终端输入、累计预算耗尽、身份变更以及明确硬错误不会被自动解除。用户显式启动可重新检查原会话的已知模型故障，仍须通过全部业务门禁。

本地验证使用真实 SDK 与回环假服务，不调用真实模型：

```sh
npm test
```

测试覆盖错误分类、备用模型及跨轮记忆、长等待、暂停与预算、已确认工具不重放、请求隐私，以及 `fetch` 的完整生命周期。
