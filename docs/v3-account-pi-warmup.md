# v3 账号 Pi 养号

从账号页的养号现场入口或 `#warmup` 打开。页面展示当前账号、原生 Claude Code 终端、Pi 交互、轮次进度、累计工作耗时、真实用量和下一次计划。交互与轮次记录按最新在前分页；进入页面只读取状态。

## 计划与业务

- 新版本保留每个账号原来的养号开关、额度阈值和随机间隔；关闭的账号保持关闭，不因部署、访问页面或保存指南自动运行。原默认间隔仍为 3–5 小时。
- 正常定时扫描继续由原 `WarmupScheduler` 负责。Pi 完成整轮后按该账号的随机间隔安排下一轮；临时等待另按门禁或故障恢复时间检查。
- 每轮从已启用的原题库选择题目，结合旧养号记录与新轮次的最近 20 次选题避重。初始需求、原补充抽样、时间计划和 Claude 设置在开轮时冻结，恢复时继续使用。
- Pi 负责观察、发送冻结需求、讨论澄清与推进实现。完成记录要求真实主会话消费全部冻结需求，并有沿实际父链产生的正常回复；排队回执、工具消息、合成错误和 Pi 自述均不算完成。
- 已开始的养号轮可完成本轮；已用达到配置的软阈值时阻止下一轮。真正额度耗尽、认证异常、运行时段、账号身份变化、累计预算与未确认输入仍会阻挡执行。

## 指南与人工控制

“给 Pi 的业务指南”按用户填写原文保存，并随每次指挥载入；指南与累计预算按账号独立保存。默认指南要求 Pi 使用英文与 Claude 交流，并完整传递冻结需求。页面展示语言与 Claude 输入语言分别处理。

- **启动 / 恢复**：要求原账号养号计划已开启；继续同一未完成轮、工作区和 Claude 会话，累计工作不会清零。
- **关闭后续定时**：账号配置中的养号开关只关闭未来轮次，已认领的当前轮继续收尾。
- **暂停**：立即撤销当前 Pi 控制并关闭后续计划，保留未完成轮、原会话和累计工作。
- **停止当前轮**：结束当前轮并关闭后续计划；再次开启并启动时创建新轮。人工核对输入不会复活已停止轮。
- **输入核对**：投递结果未知时停止自动输入。核对为“已发送”或“未发送”只保存事实，之后仍需显式恢复，不自动补发。

终端停止尚未确认时，未来计划先关闭，原执行定位与账号控制权继续保留；再次明确停止或完成环境对账后才能交出账号。用量统计缺失不会阻止停止终端。

## 恢复与账号互斥

临时模型故障先沿用 Pi 现有模型重试和备用模型能力；整次请求仍失败时，按 60、120、300 秒逐轮恢复，持续故障转为按原计划的低频检查，并保留可信的更长等待时间。每次恢复沿用原轮和会话，不重新选题。

恢复不会自行开启已关闭计划，也不会清除未确认输入、身份变化、认证错误、真实额度耗尽、人工暂停或预算门禁。模型配置冲突等需要人工修正原因后再显式恢复。

Projects 与养号共享账号 Pi 控制权，从 Pi 选题和思考阶段就互斥；原生执行仍受 `AccountRuntime` 原子租约保护。旧 worker 或其它账号工作尚未结束时养号顺延，保持原执行。

## 兼容与验证

旧 `runs`、task 与执行历史保留，新 Pi 轮次独立记录，不创建伪装成旧 run 的记录。实际接管后的旧 worker 回调在同一数据库写事务内核对接管标记，不能覆盖 Pi 的新状态。

服务入口为 `/api/accounts/warmup/pi`，旧账号 `/warmup/run` 与 `/warmup/resume` 入口分派到 Pi。新 v3 默认启用此执行方式，可用 `WARMUP_PI_ENABLED=0` 保留旧 worker 模式；该开关不会开启任何账号的养号计划。

测试使用独立 SQLite、临时文件、假 Pi 和假终端，验证原生主会话证据、未知投递、暂停、恢复、互斥、旧 API 与额度行为。测试不连接真实账号、模型或付费上游。
