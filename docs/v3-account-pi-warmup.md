# v3 项目迭代与养号迭代

`#projects` 与 `#warmup` 是两个独立的工程任务空间。两边共用 ProjectsService、原生 Claude 终端和独立工程验收代码，各自保存项目池、业务指南、预算、计划、进度、Pi 会话和工程工作目录。

## 真实工程与循环

两边都使用研究项目中的工程目标。只有冻结交付通过独立业务、回归和范围检查，才记为完成；问答、Claude 自述或旧题库轮次不会转为工程通过。

项目迭代保持已有累计源码与进度，不自动清空。养号迭代在本轮完整工程池的全部目标通过后，在下一次计划认领时核对独立通过证明，删除该账号该空间该轮的注册项目源码及输入标记，再从原始 seed 新建项目。当前完整项目池为 100 个项目、600 个工程目标。

缩小授权池只能限制当前可执行范围，不能把少量目标冒充完整600项而触发清理。新轮进度从 0/600 开始，使用新的工作区与 Pi 会话；旧轮的通过证明不能满足新轮前置。冻结交付记录、耗时、会话证据和内容制品保留用于核查。未完成、失败、未知输入、身份不符、原生执行未收口时不会清理。清理中断先保留原轮，后续幂等继续清理；不会在目录未清理时提交新轮。

## 独立计划和入口

养号入口使用 `/api/accounts/warmup/pi`，复用工程 API 的 catalog、work、submissions、schedule、snapshot 和 SSE 协议。交互与工程记录按最新在前分页，进入页面只读取状态。

原项目迭代的计划与工作保持不变。新养号工程空间默认关闭，计划默认随机等待 180–300 分钟；显式保存其计划后才定时运行，手动启动可运行一次。两个空间各用自己的计划，停止或暂停养号不修改项目迭代计划。账号页的额度设置仅修改共用额度阈值，不隐式开关任一计划。

已保存的养号指南按原文幂等导入养号工程空间，复制该账号已有授权项目池；没有授权池时保持空池。旧题库 Pi 已产生真实轮次或会话时阻止自动接管，保留原事实等待处理。

## 凭据、额度和恢复

同一账号从 Pi 思考阶段即互斥，原生执行再受 AccountRuntime 租约保护。两套空间共用账号额度、运行时段和凭据权威。

绑定 cc2api 的账号由 cc2api 统一刷新 OAuth，CLI 只得到 AT 副本、不持 RT。每账号独立发布锁覆盖读取到全部运行副本发布，避免迟到的旧 AT 覆盖新副本；不同账号不互相等待。未绑定账号保持原本地凭据权威。写入新磁盘副本不等于证明已经运行的 CLI 内存凭据即时更新。

模型临时错误沿用真实重试、备用模型及持久恢复计划；恢复不会清除未知输入、硬认证错误、身份变化、真实额度耗尽、人工暂停或原目标累计预算。

## 验证

测试使用隔离 SQLite、真实注册工作区、冻结内容和模型/终端替身，覆盖双空间隔离、六百目标循环、连续重开、旧轮证据隔离、清理中断、账号互斥和 AT 并发发布。浏览器核验两个入口、独立表单、分页、迟到回执和移动布局，不调用真实付费模型。
