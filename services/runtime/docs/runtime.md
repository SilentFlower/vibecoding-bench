# 运行时构建与常驻执行

运行时固定使用官方 Claude Code 2.1.293、Bun 1.4.3 及其原生发送/CCH 能力。普通 API 经过交互 CLI 的工具、提示词和消息上下文装配；默认 preserve 下，完整原生 CC 正文只做必要身份和 CCH 占位改写，再复用同一原生发送上下文。显式 sub2api 在原生封口前处理消息断点，第一方遥测默认 off；配置规则见 [接口说明](./api.md#配置)。原版预加载入口与精简静态入口共用适配代码。

本轮已重建独立二进制，加入原始输入私有协议、运行时内白名单处理及 cc2api 消费能力。最新身份列于下表，接入配置见 [cc2api 原生转发](./cc2api-native293.md)。历史构建的时延、资源和用例数字在下文保留其原批次含义。

既有 CLI 产物已通过请求对照、部署体积、独立部署与重复构建验证。2026-11-05 用户已接受当前延迟，**不再以 vm2api 的速度作为验收门槛，以请求正确性、安全与稳定为优先**。历史速度失败数据继续保留，不改称性能已修复；历史 SDK 产物的速度结果不适用于本产物。

## 构建配方

需要 Linux x64、项目 Bun/TypeScript 依赖、Python 3、GCC、tar、unshare 和固定官方文件。输出必须是尚不存在的路径；构建结束后清理临时提取目录。

```bash
bun scripts/build-runtime.ts \
  --source /绝对路径/固定官方claude.exe \
  --out /绝对路径/新目录/claude-293-cli
```

7-Zip 26.05 工具及 C SDK 默认从固定官方 GitHub 发布下载并核验完整 SHA256；离线准备同一版本后可增加 `--sevenzip /绝对路径/7zz --sdk /绝对路径/7z2605-src.tar.xz`。SDK 的解码与 SHA256 部分静态编入自有加载器；未引入 UnRAR 代码。

当前配方依次执行：

1. 核对官方 SHA、ELF/Bun 容器、内嵌 Bun revision，提取模块及资源并逐项登记摘要。
2. 以原版 Bun 编译专用常驻入口。AST 转换已核验的静态依赖，保留函数名，关闭 dotenv/bunfig/tsconfig/package.json 自动加载，记录闭包和残余动态调用。
3. 对固定 Vt 工具工厂的顶层 create 执行体设置明确拒绝。工具名称、schema、prompt、描述和可用性继续保留；当前产物包含 80 处工具执行守卫。
4. 对明确为 local/local-jsx 的顶层命令对象阻断执行 load/call，保留名称、描述及可用性判断；当前包含 54 处 load 守卫，prompt 技能不裁剪。
5. 对仍可达的终端附件加载点设置明确拒绝，当前为 1 处；音频及剪贴板附件均不进入部署闭包。
6. 对六个已核验的纯正文格式化工厂复用文本结果；每轮继续读取模型、工具和功能条件，动态段落、memory 读取及原生钩子保留。函数定义和全部条件键进入闭包审计。
7. 核验并无损解压 134 份 zstd 文本资源，完整原文交由外层统一压缩。官方读取器本身接受原文，资源正文没有裁剪；清单保存转换前后长度及 SHA。
8. 按 LANG=C.UTF-8 裁剪 ICU locale 定制，保留 root/en、字符/规范化数据和全部语言分词规则/字典。原生 .text、.bun_builtins、.data 保持固定源对应节的摘要。
9. 用固定 BCJ2/LZMA2 配方压缩完整执行体，加入便携 -O3 编译的 C SDK 加载器，核对完整部署大小并输出配方 9 的 manifest。

原生 OM 查询准备、技能定义及文本资源保留。单轮桥接在构造边界阻止本地工具和代理循环。上述符号、布局和数量只对应固定 293；新版本须重新定位、读取定义和回归，不能仅替换版本字符串或哈希。

静态复用只发生在精简构建内的纯格式化函数，原版保留为未改写对照。每个函数只保留最近一次可缓存的原始条件及字符串，单项键和值按 UTF-8 计不超过 64 KiB，六项合计最多 384 KiB；不代表 JS 堆或 RSS 上限。命中直接比较条件，异常或超限结果不入缓存。不缓存整份提示词、原生会话段落表、工具选择或请求正文；详细依赖和失败尝试见 [静态复用记录](../.trellis/tasks/11-05-cli-alignment/research/static-text-reuse.md)。

## CLI 请求与常驻生命周期

进程设置 CLAUDE_CODE_ENTRYPOINT=cli，采用原生交互状态、markdown 问题预览和内置技能。主请求来源为原生 repl_main_thread；User-Agent 不再附加桥接主动设置的 SDK client-app。

普通 API 每轮通过官方权限、代理定义和状态工厂装配，禁用内置工具池。pie、VA/Kz/LT/Uz 及 OM 负责按实际工具集生成 CLI system、提醒和模型参数。省略 tools 与 [] 均无工具，非空列表完整采用调用方定义，不补入 CC 工具；省略 system 使用默认正文，显式值（包括空文本或空数组）按 --system-prompt 替换。真实 CLI 对照也禁用工具。详细输入边界见 [API 说明](./api.md)。

原生入站先核对固定版本、metadata/billing 及显式上下文，再保留完整业务正文和省略状态；不将原生历史重新交给 OM 拼装。取得账号身份所需的本地种子构造与唯一发送复用同一 SDK，种子中的默认正文不会进入原生出站。metadata 只改设备和账号归属，原会话、billing 后缀及轮次保留。默认 preserve 保留业务缓存位置；显式 sub2api 仍优先保留调用方已有的消息标记，实际改动与跳过原因写入中间阶段说明。

K_t 的 fetchOverride 完成对应路径的保留核验后，复用同一 SDK 的发送上下文，由 Ree 唯一发送。桥接独占原始 Response，直到读取收口后取消原生调用；SDK 不继续解析、重试或执行工具。初始化只构造，不产生模型请求。自动辅助压缩关闭，调用方显式 compaction 保留。

HOME、专用配置、显式凭据、代理和 cwd 固定绑定引擎。控制配置明确提供的 API key 使用官方本地规则记录确认标识，完整密钥不写入 CLI 配置；已有拒绝决定保持有效，不登录或刷新账号。更换引擎配置须关闭并重建。

创建服务只校验程序，读取日志或 PID 不启动 CC。首个作业惰性启动，原生初始化与隔离根的本地构造完成后发 worker_ready，其成本全部计入总启动时间。正常串行作业复用同一物理进程，不再附加 16 项准入门槛，排队策略交前置服务；每轮 nEr 新建根、取消信号和日志作用域，同 sessionId 也独立。

新进程完整核对分发文件，通过已核验 FD 启动，握手后独立核对 /proc/<pid>/exe。暖复用检查真实路径、dev/inode、大小和纳秒 mtime/ctime。唯一终态与匹配 worker_idle 均到达后才能复用；取消、异常和协议错误退役，下一轮重建，失败请求不重放。

私有 JSONL 使用 schema 2，以 worker_id/request_id 绑定进程和作业。cc_prepared 的原文、长度及 SHA 在 Ree 前固定，快照输出与发送并行，两者成功后才交付响应事件；失败时取消并释放未交付响应。原始正文和头仅走私有管道，控制层先注册秘密再脱敏持久化，stdout 不作为普通日志。HTTP 和外部请求事件继续使用 schema 1。

最新入口在 worker_ready 声明 raw_input_protocol=1，接受 request_input 原始输入。每个作业内执行 parseInput/prepareInput，并先返回实际 header_policy 决策。业务格式错误以本次 error/idle 收口；协议故障和运行异常使进程退役。cc2api 从实际 cc_prepared 取得受限诊断摘要，TLS 最终值由独立上游实收核对。

握手前的配置失败通过不带 request_id 的 worker_error 帧报告，固定为 native_configuration/503；已拒绝的显式密钥保留受控中文原因。入口先脱敏并限长，等待帧写入后才退出；未知异常使用通用说明。控制层只在握手前接受该帧，错归属或握手后的初始化错误仍属于协议故障。失败进程退役，下一次请求重新启动，不重放失败请求。

加载器校验载荷后写入封存 memfd 并 fexecve，同 PID 执行。内存文件约 107.60 MiB，与部署文件和 RSS 分列。当前独立部署在私有挂载/网络空间隐藏官方源、整个项目和旧 /tmp 后，分别以 preserve/off、sub2api/on 完成四轮请求及 shutdown；每组只观测到 189 B 配置增量。/tmp 限制为 16 MiB，未观测到完整执行体的磁盘展开。关闭组零遥测上传，开启组收到原生批次。该计数是观测值，不是内存或未来遥测文件的硬上限。

## 安全复核与验证结果

普通 API 保留完整原生 CLI 首发装配；原生入站保留其已有正文，两条路径共用原生发送及 CCH，不采用首发消费裁剪、环境副本或跨作业权限/工具选择缓存等研究原型。六个纯正文缓存仍限定于已验证的不可变字符串和条件键；每轮继续创建独立原生根。

本轮可选缓存与遥测产物完成双次独立构建，分发文件、执行体及配方一致，22 份桥接构建输入摘要与当前 manifest 匹配。原版与精简版各通过 52 项原生用例，包含默认行为、缓存所有权/预算、四种配置组合、遥测 500/慢响应、开启后取消与重建；每份套件保存 80 份实际模型正文。连同独立部署的 8 份，168 份最终正文由 libxxhash.so.0 独立核验 CCH。关闭组零上传，开启组收到真实原生事件，所有事件均归属合成业务会话，入口为 cli；慢遥测场景退出约 1.02–1.05 秒，不重试模型。

首次精简矩阵曾因连续场景压满既有有界日志队列，失败记录保留；夹具改为响应计时后逐项等待异步日志排空并断言无采集错误，随后重新跑完原版与精简套件。生产日志上限及热路径未改。最终每份套件的 66 份业务日志均可读取且无采集错误。

上一轮原生入站分支修复了原生构造错误收口及工具历史投影。该轮 49 项原生用例、707 个断言中的普通 API 和原生矩阵继续保留在当前套件；原 23 组普通 API 场景为 17 次成功出站、6 次明确拒绝，新增 26 组原生场景为 20 次成功出站、6 次明确拒绝。历史独立展示样本不改写。

工具历史的两项超时来自原生将同次已知提醒合并进 tool_result，或将 Environment 提醒提升为 system，旧投影无法关联且构造异常被上层消费。修复只接纳同次已知提醒的完整内容，业务丢失、改变和未知注入仍拒绝；构造异常及原生失败事件直接收口。第三项强制工具选择由固定 293 的实际 thinking 能力判定，不支持组合及时返回 400，不触发隐式 fallback。

这些检查验证已覆盖条件下的凭据处理、单次发送、隔离和取消边界；原生请求与 CCH 一致不构成账号免封承诺。测试全部使用合成凭据，真实上游请求为 0。

当前 memfd 执行体另与原版完成 108 组分词和 24 组 Unicode 规范化对照，覆盖默认/en/zh/ja/th/ar、组合字符及 emoji，结果一致；该验证不扩大 locale 保留范围。

## 按需最后出站验证（当前源码）

默认 `CCRB_TLS_CAPTURE=off`，保留官方原版直接发送。可选 `CCRB_NATIVE_BASE_URL`、`CCRB_MODEL_OVERRIDE` 在进入 CC 前生效；缺省不覆盖。本轮不重建旧精简产物，它们未获得显式上游配置或验证能力。

verify 链路为原版 CC → 实例私有 TLS 接收器 → HTTP 原字节 → 固定画像 TLS 上游。业务、账号身份和 CCH 仍由原版生成；独立辅助程序仅提供传输、最后写出观测及受限代理，不是官方 TLS 实现。对齐范围是已测试组合的完整公开握手、HTTP 字节及连接行为，随机数、实际公钥、绝对时延和实现细节不作为一致承诺。

独立源码在 `native/tls-verifier`，许可及 craftls 快照来源在 `native/vendor/craftls`；Cargo.lock 固定版本与注册表校验值，生产不访问外部 cc2api 目录。固定目标为 x86_64-unknown-linux-gnu，登记构建使用 rustc 1.96.0 (ac68faa20 2026-05-25)、release、thin LTO 和路径映射。当前产物约 3.8 MB，依赖平台系统库；不纳入旧精简 CC 的单文件体积声明。

```bash
bun run build
bun run build:tls-verifier
# 在本机 .env 中配置后重启：
# CCRB_TLS_CAPTURE=verify
# CCRB_TELEMETRY=off
bun run start
```

辅助程序在 `dist/tls-verifier`，清单在同名 `.manifest.json`。独立执行体 SHA256 登记于 `src/runtime/tls-verifier-profile.ts`，启动通过已核验文件描述符执行；构建不会自动修改授信清单。其他编译器或依赖导致新哈希时，需要重新验收并登记，不能只改版本字符串。关闭模式不依赖该产物、OpenSSL、私有 CA 或监听器。

开启时生成仅本实例信任的私有 CA 和正常叶证书，不改系统证书库。只接纳冻结目标的认证 CONNECT，并以 Linux TCP 表和 worker 的实际 socket 文件描述符验证 PID；随后核对当轮头、正文长度及仅用于校验的 CCH 槽位。最后写出记录绑定实例、worker 代次、请求、连接和单调序号；取消或退休会关闭本代连接后收口，旧帧不能填入下一请求。原生进程继续驱动复用、关闭和响应解析，辅助程序不建立 HTTP 池，不新增请求重试、跟随重定向或默认总时限。

独立回环验收命令：

```bash
cargo fmt --manifest-path native/tls-verifier/Cargo.toml --check
cargo clippy --manifest-path native/tls-verifier/Cargo.toml --locked -- -D warnings
cargo test --manifest-path native/tls-verifier/Cargo.toml --locked
CCRB_TLS_REPORT=artifacts/tls-verifier/report.json bun run test:tls
```

`test:tls` 构建后进入仅有 lo 的新网络空间，使用实际固定原版及合成凭据。独立 OpenSSL 服务端逐字段对照 TLS1.2、TLS1.3、HRR、关闭重连及恢复策略，并核对最后写出整体 HTTP 哈希、有序头、正文、CCH、2/8 MiB 原生正文、36 秒流、取消、错误证书、部分写出、进程失效和双客户端各三个子代理。普通 API 的超大消息可能在原版 CLI 构造阶段被拒绝；该结果与完整原生正文的透传验收分开，不能称为 TLS 丢失。

采集原始范围与预览上限分开；日志 mode=summary/off 时不保存正文。`native_tls_verifier` 表示最后 TLS 本地接受/刷出的明文证据，不能当作上游执行证明。旧显式池工具继续保留 `local_pool_node_tls_receiver` 的接收来源，不升级为最后一跳写出。关闭 verify、删除端点及模型覆盖并重启，可分别恢复官方直接路径和原生默认选择。
