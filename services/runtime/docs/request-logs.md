# 请求日志与展示

本文件描述首版日志实现，参考 vm2api 的摘要和原始数据查看能力。

## 页面

列表展示时间、request ID、模型、类别、session、状态、耗时和采集状态，agent 和父 agent 位于详情。支持按时间、模型、状态、类别、session 与 request ID 筛选，request ID 为包含匹配，其余身份字段为精确匹配。

详情提供概览、头部处理、性能、原始数据：

- 概览：版本、运行时标识、接入路径、调用来源、父子关联、完成或取消状态；历史记录没有接入路径时显示未标注。
- 头部处理：字段的保留、删除、重建、冲突和原因。
- 性能：各阶段采集时间、总耗时、从发送参数就绪至响应头和首个有效输出的耗时；未观测指标为空。
- 原始数据：脱敏入站头和正文、CC 组装或原生改写中间值、可用最终采样、响应头及正文或 SSE。

支持格式化查看和复制脱敏内容。详情保留请求发生时的快照，进程或账号引用失效后仍可查看。

## 采集阶段

| 阶段 | 含义 |
| --- | --- |
| ingress | HTTP 原始 UTF-8 正文及头部，脱敏后保存；保留原始空白与转义 |
| header_policy | 字段处理动作与原因 |
| cc_prepared | CC 交给发送链路的中间参数 |
| wire_final | 原生最终处理后的真实发送采样 |
| upstream_response | 上游 Response 与响应流 |

每段保存采集来源、时间、完整性、观测字节数、保存字节数及适用哈希。wire_final 只有采集位置已验证时才成立；没有最终值就显示“未采集”，不以重算值补写。

默认发送链路的 wire_final 仍为 unavailable，生产自动采集能力为 false。本机隔离 TLS 接收端样本另以 offline_tls_receiver 标明实际来源；这些样本不改变生产能力状态。普通 API 的 cc_prepared 来源为 claude_code_293_cli_prepared；原生入站为 claude_code_293_native_ingress_prepared，页面标为“原生改写（中间值）”。默认 preserve 只完成身份及 CCH 占位改写；显式启用 sub2api 时，阶段说明还会记录断点处理结果与跳过原因，不代表重新生成业务提示词或已经命中缓存。历史 SDK 记录保留原来源，演示来源为 demo_fixture。响应以 response_logical_bytes 表示，不能称为 TLS、压缩或网络帧原文。

正文哈希与 CCH 核验使用明确的原始表示，不能把脱敏或格式化后的显示内容当成原始校验输入。

显式本地池联调模式的 wire_final 来源为 `local_pool_node_tls_receiver`，表示 Node TLS 接收端实际收到的 HTTP 实体正文和有序原始头，位于 deepseek-flash 映射之前。该实例在采集端自检后提供最终采样能力；普通启动仍未配置自动采集。兼容分支的中间段另说明同次 CLI 入口、账号归属和 CCH 占位准备，不能与最终段混用。

池 Key 在日志初始化时注册，TLS 样本在处理池响应头前保存，防止响应中的敏感标志值污染此前请求预览。采集提供者缺失或失败分别显示 unavailable/failed，不用 cc_prepared 补写；日志模式及截断限制与普通服务相同。

## 关联和完整性

- request ID 关联全部阶段；首版关闭隐式重试，每个请求仅有 attempt=1。
- 保存 session、agent、父 agent 和类别的来源信息，可查看关联请求。
- 正常完成、取消、上游错误、流中断、截断、未采集和采集失败分别记录。
- HTTP 200 不直接等于 SSE 成功，流内错误及缺失终态按实际情况显示。

## 记录模式

- off：不保存。
- summary：仅摘要、关联与采集状态。
- debug：摘要和经过脱敏的阶段原文；本地首版默认采用此模式。
- 可配置保留时长、单段字节上限和总存储上限，触顶明确标注截断。
- 摘要和阶段索引用 SQLite，正文独立有界存储，运行数据位于被 Git 忽略的 data 目录。

默认正文单段上限 1 MiB、总载荷上限 512 MiB、摘要 7 天、正文 3 天。总载荷按 SQLite JSON 的 UTF-8 大小及正文文件字节数计算，SQLite 页、索引和 WAL 有额外开销；执行中记录暂不因容量删除，完成后回收最旧记录。清理在启动、写入和每分钟进行。原文过期后保留摘要，阶段标明原文已过保留期。

日志线程队列上限为 64 个快照或 16 MiB。写入、清理或队列故障会停止本次服务的后续采集，并在健康接口和页面提示；已持久记录仍可查询。重启后无法确认终态的运行中记录标为 incomplete。off 不新增记录，也不删除已有历史。

截断保留完整 UTF-8 字符。对可能截在凭据中间的响应前缀，会额外省略边界部分；该变化只影响日志预览。原始观测哈希对应实际见到的字节，不能用脱敏预览复算。

## 流、故障及访问

主响应边读边返回，日志通过独立有界队列保存，不等待完整响应落库。下游取消传播到上游与采集器；写入失败必须可见，不阻塞当前响应，也不为补日志重放模型请求。

响应通道最多等待一段未消费片段，取消或超时会解除等待。已经发出 HTTP 头后，本地取消或故障直接结束字节流，不拼接新的 SSE 错误事件；日志保留错误或取消终态，调用方应检查上游协议终态。

观察器为单个 SSE 事件设置 256 Ki 字符上限，为非流式 JSON 设置 10 Mi 字符上限；超限只影响终态确认，不改写返回字节，日志不会宣称已验证成功。

凭据、Authorization、API key、Cookie 和代理密码不进入可查询日志。未知扩展头的转发与日志展示规则分开。

原生端会在私有 JSONL 管道传递实际 SDK 头部，控制层先注册其中的凭据再生成脱敏快照，以覆盖凭据只存在于原生配置的情况。该私有管道不作为诊断日志输出，也不直接落盘。

日志 API 和页面首版只绑定回环地址，读取不触发登录、刷新或模型调用。请求及模型输出用文本渲染，不能解释为 HTML。

实验中的 Response.clone().text() 不能直接当成生产流式采集方案；原生 fetch 解压后的逻辑内容也不能标作线上压缩字节。
