# 技术设计

## 现有边界与复用

- `service/v3_scheduling.rs` 统一执行请求配置冻结、硬容量筛选、人工优先级、即时容量优先、评分和近优轮转。
- `SchedulingConfig::parse` 从完整字符串设置解析原子配置；`SettingsStore`、管理 PUT 及 `apply_config` 已提供事务与热更新链路。
- `model/account.rs::Account::usage_quota` 已区分未知、待刷新和有效额度。重置奖励只读取真实窗口的未来 reset，额度状态继续由原投影维护。
- `diagnostics.rs::AttemptTrace::finish` 已有完整成功终态、首输出及本次总耗时。总耗时交给调度器估算并发等待，首输出继续用于原延迟因素。
- `Settings.vue` 与 `settingsSchema.ts` 已有字符串草稿、统一控件、保存／取消与定位校验；在原调度分组扩展字段。

## 配置合同

| 设置键 | 默认 | 语义 |
| --- | --- | --- |
| `v3_smart_weight_reset` | `0` | 重置偏好主权重 |
| `v3_smart_weight_queue` | `0` | 等待排序独立权重 |
| `v3_smart_reset_weight_5h` | `1` | 5 小时重置窗口权重 |
| `v3_smart_reset_weight_7d` | `1` | 周重置窗口权重 |

- 新权重均为有限 0–10、至多一位小数；配置整体校验后保存和热替换。
- 保留 `config.weights` 原四元素结构，新增 `reset_weight`、`queue_weight`、`reset_window_weights` 字段；前端新增字段使用可选类型兼容旧响应。
- 主重置权重或两个窗口权重全零时重置偏好关闭。有效排序权重总和必须大于零；仅排队权重启用时即时候选使用等偏好轮转。
- 默认值复用 `V3_SCHEDULING_DEFAULTS`。新增设置按现有 `ensure_native_idle_timeout` 的幂等补齐模式写入历史库，保留显式值；已冻结的 `database_schema.rs` 和迁移登记保持原定义。

## 重置偏好

- 分别读取普通 `five_hour`、`seven_day` 的合法利用率和 reset。
- 对严格未来的 reset 使用 `h / (h + remaining_seconds)`，其中 `h=周期秒数/7`；同类窗口只计算一次。
- 按两个窗口系数计算加权平均；缺失周期贡献 0，分母包含全部启用窗口权重，防止少报窗口增加偏好。
- 将该因素加入原四因素的归一化基础分；主系数为 0 时严格复用原公式。
- 到期或未知窗口不获得奖励；资格、硬额度和已有会话绑定继续先行。

## 排队等待偏好

1. 继续执行原硬容量、人工优先级和即时容量筛选。
2. 有即时容量时使用基础分；该路径排除排队权重及其分母。
3. 全部需要等待且排队权重大于 0 时，运行负载使用 `active_units/max_units`，等待因素独立计算。
4. 并发等待按待容纳的加权单位和同组完整成功请求总耗时 EWMA 估算：`max(active_units + queued_units + request_units - max_units, 0) / max_units * service_ms`。RPM 等待继续复用当前容量快照的最早提交时间；综合等待取二者较大值。
5. 有真实耗时样本时，等待偏好使用 `1 / (1 + estimated_wait_ms/10000)`。缺少样本且并发需等待时，使用归一化队列压力与已知 RPM 等待作回退，预计毫秒值为 null。
6. 等待因素与基础因素按各自权重归一化，继续使用 0.05 的近优差值和稳定轮转。
7. 排队权重为 0 时，原负载中的排队／发送等待保留，严格复用原选号行为。

等待结果属于估计；真正执行继续由原并发许可、FIFO、发送闸门与统一期限裁决。

## 耗时采样与分组开销

- 在已有完整成功终态取得总耗时，追加给既有反馈入口；失败、取消、采样不完整的请求保持原采样规则。
- 原 `LatencyClass` 键继续冻结模型、思考配置与流式方式；每账号最多 64 组，淘汰最旧组。
- 首输出 EWMA 与服务总耗时分别保存；首输出不充当并发槽释放耗时。
- 查分按组键读取内存表，不创建后台任务、不等待样本、不查询数据库、不探测模型。
- 无样本沿用中性延迟或压力回退。性能微基准以 1／8／32／64 组、1／10／100 个候选构造离线样本，报告每轮评分耗时；计时观测不设置依赖机器的 CI 硬阈值。

- `SmartFactors` 增加重置、排队及等待估算来源／可空毫秒摘要。`score` 保留基础分语义，等待排序分单独提供，页面明确区分。

- 历史响应缺字段时保持既有展示；从管理 GET 读取不会触发刷新、续租或发送。

## 增量决定：删除旧评分系统

- 删除 `select_by_score`、旧权重缓存、阶梯用量衰减与只服务旧评分的 DTO 字段。容量快照保留真实并发、排队和退避字段。
- `AccountService` 持有统一 `selection_scheduler`；独立部署只复用其内存评分和近优轮转，v3 装配时与正式调度器共享同一实例。独立部署继续沿用原会话与 RPM／并发准入入口。
- 旧 `score_weight_7d/score_weight_5h/score_weight_concurrency` 和 `v3_scheduling_mode` 进入废弃键处理；启动补齐智能设置时清理旧键，API 不再暴露或保存旧键。响应配置的 mode 只读固定为 smart，以兼容现有管理摘要。
- 删除管理端模式选择、兼容排序权重、旧评分解释与旧分数字段；设置和摘要集中展示智能评分。
- 追加修改 account.rs、router.rs、Accounts.vue 及对应测试；已有其它会话的后台请求选线修改需逐 hunk 保留，并在最终提交预检时披露混合文件归属。
