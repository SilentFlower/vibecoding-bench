# cc2api 窗口用量与费用设计

## 边界与数据流

正式 `/v1/messages` 上游响应 → 共用 Token 摘要解析 → 本地定价 → SQLite／PostgreSQL 统计记录 → 账号分页 API 批量汇总 → 5h／7d 卡片。

官方 `usage_data` 继续只表示额度观察；新增本地统计与之分离。手动额度查询不制造业务用量记录。`count_tokens`、本地 mock、本地缓存命中、被拒绝且没有消费数据的重试不计作有消费的请求；首次实际执行的探针请求按其真实上游 usage 记录。统计入口与 `auto_telemetry` 独立。

## 采集与一次性记录

- 复用 `MessageTelemetryUsage` 及现有 JSON／SSE 合并规则；保留 max 语义，避免 message_start 和 message_delta 重复累计。需要知道是否观察到 usage 对象，不能用全部 Token 等于零代替“未观察”。
- 为每次实际上游调用创建本地唯一记录标识，保存承载账号、实际模型、请求起止时间、状态、六个 Token 字段、价格版本、已定价费用及完整性标记。优先采用响应明确返回的模型／有效计价模式，缺失才使用已确认的最终上游请求字段；别名匹配必须有参考依据。
- 普通响应走现有 `SlotGuardBody`，EOF、body error、客户端提前丢弃共用一次性 finalize；非流探针缓冲路径调用同一记录入口。唯一键与 `Option::take` 一起防止重复写入。重试按真实调用区分，无 usage 的失败不伪造费用；已有 usage 的中断保存已观察值并标为部分数据。
- 复用已有受限压缩旁路采样／解码能力，不缓存完整无限响应，不修改原始帧。无法完整解析、超限或不支持的编码标记为不完整，不能计算零费用冒充准确值。
- 写库采用现有 Tokio 运行时中的独立短任务，不阻塞响应转发；失败记录脱敏告警。已成功写入的记录可跨重启读取；进程被强杀时的在途／尚未落盘调用不保证恢复，页面不承诺全账号完整计费。

## 定价

- 在 cc2api 中保存有来源版本的紧凑 Claude 价格快照；实施时从参考目录与相应 fallback 规则提取，运行时不依赖 `/root/project/my/sub2api`，不新增远程抓价。
- 按输入、输出、缓存读、5m／1h 缓存写分别折算 USD；缓存写总量与分项不能重复计价，分项不足的剩余部分使用参考实现对应的默认写价格。
- 对照 sub2api 核实模型日期后缀、点／横杠别名、`[1m]`、fast／priority 及长上下文规则，仅对已知规则归一化；未知模型或无法确认的计价模式保留请求／Token，费用标为未完整定价。
- 每条记录保存计算结果与价格版本，更新价格快照不追溯重算已记录费用。汇总保留精度，到页面才显示两位小数。

## 持久化与汇总

- 新增独立 `usage_records` 表和账号／请求开始时间索引；字段只含统计所需标识、数字及受控状态，不保存提示词、正文、凭据或会话明文。新增表通过 `db.rs` 在 SQLite／PostgreSQL 幂等创建，时间保持现有 RFC3339 风格并在比较前统一 UTC 精度。
- 另保存本地统计启用起点，标识首次周期可能缺少历史数据；该元信息属于统计存储，不暴露为管理员可改设置。记录保留至少完整 7d 加安全余量，按时间裁剪，禁止固定条数截断周统计。
- 记录起点持久化，估算覆盖起点另外保守取本进程开始时间与最近写入失败时间；重启保留金额和请求，但在重新完整覆盖该周期前不恢复总额外推，避免把宕机期间可能缺失的调用当作完整记录。
- 后端集中选择窗口：有效未来 reset 对应 `[reset - 5h, reset)` 或 `[reset - 7d, reset)`，统计请求开始时间位于窗口且已观察到的真实调用；查询上限不越过当前时间。到期／缺失／非法 reset 使用 `[now - duration, now]` 的滚动统计并明确来源。
- 分页只批量查询当前页账号所需的最近记录并聚合，避免每 5 秒的页面轮询退化成每账号每窗口一次 SQL。数据库错误返回统计不可用，不能填零掩盖失败。

## API 与前端契约

- `GET /admin/accounts` 的每个账号附加可选 `request_usage`，包含 `five_hour`、`seven_day`；旧字段及分页、画像配置保持原契约。新增 TypeScript 类型与后端 DTO 一起落地，不为费用修改持久化 `Account` 或官方额度 JSON。
- 每个本地窗口提供 `requests`、`tokens`、`cost_usd`、`unpriced_requests`、`partial_requests`、统计起止和 `basis`（额度周期／最近滚动窗口），并提供记录起点或覆盖不足提示。查询失败和旧后端缺字段使用“统计不可用／未提供”，不能使用 0 回填。
- 窗口上方紧凑展示“请求数 · Token · 网关折算 $金额”；没有 A／U 两种结算时不复制双金额。费用不完整时显示已知部分及提示。
- 官方百分比显示独立于本地金额：真实已知零值可显示 0%；缺失显示未知，过期显示待更新。维持现有账号列表定时读取，不自动触发手动 usage 请求。
- 仅当窗口有效、观察值为有限正数、费用为有限正数、无已知未定价／不完整或周期覆盖缺口时，显示 `cost_usd * 100 / utilization`，标明“按网关记录估算总额”；其它入口可能消费相同官方额度，估算不能称为订阅总额度或余额。首个周期样本不足时保留请求／Token／已记录费用，隐藏总额估算。
- 本轮新增费用仅处理通用 5h／7d，Sonnet／Fable 专属窗口保留，不将所有请求费用误挂到模型专属额度上。
- 用户确认补充：统计随页面／列表刷新更新，清零由各自官方周期推进决定；前端以最新 reset 与后端时间重新选择窗口，不能通过刷新动作删除持久化记录。

## 兼容与回滚

不改变调度策略、额度阈值、TLS、请求画像或上游响应。新增表与可选响应字段向后兼容；回滚旧二进制可忽略统计表。参考仓库始终只读。

## 具体风险

流式结束／Drop 重复记录、压缩尾部 usage 漏采、模型别名误定价、跨 reset 长请求归属及多入口消费导致估算偏低。使用一次性记录、明确不完整状态、定价对照样例及窗口边界测试分别验证。
