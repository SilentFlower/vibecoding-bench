# 实施与验证

1. 在账号实体、管理创建和更新、`AccountStore` 映射及前端表单补齐同一个布尔字段。增量迁移补齐 SQLite 版本登记和 PostgreSQL 初始化。同步 `deploy/flower2api/system_release.py` 的网关迁移签发源。
2. 接入普通 AGY Messages 的私有策略快照。原生适配器先复用同形体转换，再根据快照放入用户提醒。核对原生回执来源和采集兼容。用投影前正文覆盖领取、历史、历史兜底和认证恢复，复用现有收口与正文重读。
3. 运行网关格式检查与 `cargo test --locked`。补充账号默认、更新与两账号隔离、升级登记、出站文本、签名保持及历史前缀测试。核对老客户端省略字段和非 AGY 账号拒绝启用。
4. 运行 `npm --prefix apps/web run build` 并扩展现有 `verify_agy_accounts_ui.py` 断言，验证两个账号开关回填、保存差异与重新打开。覆盖默认关闭和窄屏编辑。
5. 扩展 `deploy/flower2api/verify_agy_native_loopback.py` 的隔离用例。使用同一合成工具声明和固定系统样本，验证四种配置组合的原生 TLS 文本、策略回执、回填期间切换、重读零新增提交、三种续轮及失败恢复。

## 实施前证据

通过临时探针在断网容器内调用现有 Messages 网关和 AGY 1.5.9。两组手工构造系统段与用户提醒，采用同一中性指令、样本文本和工具声明。在领取模式下两组初次请求、工具回填与重复读取均返回 200，各观察到两次原生模型提交和一次实际工具结果。终态正文由本地合成端给定。这份基线覆盖提示词位置和工具往返，账号配置生效与真实模型行为分别待验证。

## 实际验收

- `cargo test --locked -j 2` 通过 1,023 项。13 项既有的专用环境或基准测试保持忽略。与任务起点比较，整仓 Rust 格式检查的 9 处差异全部来自原提交。
- `test_agy_*.py` 通过 117 项。数据库定义回归通过 9 项，实际登记达到网关版本 10，旧步骤摘要保持原值。
- 账号管理 HTTP 夹具验证默认关闭、显式创建和保存、两账号列表回读、非法值及非 AGY 启用拒绝、重新授权后保留设置。前端构建和 390px 浏览器验收通过。
- 固定 AGY 1.5.9 的断网 TLS 回环核对四种组合及回执来源。共 7 组工具场景，每组恰好两次合成模型提交，覆盖领取、历史续轮、确认退出后的历史兜底、待回填切换和重复读回填。另观察到一次 Gemini 原生直连生成。
- 断网合成发送器验证同一 HTTP 在认证恢复前后保持相同私有策略。下一 HTTP 读取调整后的设置，原始正文用于后续工具归属。
- 真实模型指令遵循、缓存和账号状态归因留待独立对照。现有验收使用合成账号、固定模型响应和隔离网络。
