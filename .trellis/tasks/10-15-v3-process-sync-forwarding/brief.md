# 任务摘要 — 修复进程指标同步与验收容器转发

## 目标

- 修复 cc2api 的进程指标同步，并取得请求实际经目标账号容器和代理往返的完整证据。

## 范围

- 进程指标采集、首次创建导入、已有账号指标更新及卡片展示。
- 正式 API 的 JSON/SSE 容器链路、错误处理与生产公网传输检查。
- 账号页按用途拆分四个入口：

| 按钮 | 行为 |
| --- | --- |
| 创建 cc2api 账号 | 未关联时创建并关联；发现已有匹配只提示关联，不自动转换。 |
| 关联已有账号 | 未关联时显式选择目标，校验后关联，不创建账号。 |
| 更新进程指标 | 已关联时仅更新原账号的指标，不刷新凭据或改变配置。 |
| 重新授权 | 已关联时更新原账号及两端凭据；未关联时仅保存本地。 |

- 新建 cc2api 账号采用以下配置：

| 配置 | 值 |
| --- | --- |
| Billing 模式 | 重写 |
| 上游 session 池 | 启用 |
| 池容量 | 4 |
| TTL 刷新策略 | 仅属主刷新（`owner_only`） |
| 并发 | 4 |
| RPM 上限 | 50 |

## 非目标

- 不调整代理线路、地区策略或遥测开关，不用受限账号发模型探测。
- 不伪造历史 RSS，不为填页面额外启动真实模型任务。

## 技术概览

- 读取实际容器内存限制，低频采集真正官方 CLI 的 RSS，保存来源、版本和时间；没有样本时明确显示“未采集”。
- 前后端按四个动作分别限定行为，关联从养号表单移出；旧 API 保持兼容，新页面不再调用笼统“同步”。v3 未知指标不再被兼容默认值冒充实测，普通旧账号继续兼容。
- 六项配置仅在真正新建账号时显式提交；关联已有账号、更新指标和重授权保留原配置。TTL 时长沿用当前默认 60 分钟。
- 用真实调度器与 Docker 账号环境串起正式 API、发送器、代理和隔离上游，交叉核对请求标记、来源和响应；本地测试信任根仅进入测试构建，生产保持证书校验。

## 背景与决定

- 已定位两个缺口：进程字段未导入；已有网关测试主要证明 TLS ClientHello 到达后返回 502，没有证明成功业务响应完整往返。
- 当前线上没有该账号的 API 发送证据；唯一正式账号存在 account_on_hold 历史。
- 真实模型推理需要可用账号，单独记为待验证，不能拿替身成功或网络连通替代。

## 风险

- 第一次采到真实 CLI 进程前，RSS 会显示“未采集”；容器内存上限仍可准确同步。
- 生产网络检查可能临时唤醒一个空闲账号容器，完成后恢复原状态；遵守资源检查，不停止其他部署。

## 验收

| 场景 | 期望 |
| --- | --- |
| S1 创建与关联 | 实际点击两个独立按钮；创建六项配置正确，已有匹配不自动关联；关联不创建、不修改养号配置。 |
| S2 更新指标 | 官方 CLI 采样来源可核对；实际点击后页面、API、数据库一致，凭据/设备/代理/配置不变；无样本明确标注。 |
| S3 重授权与兼容 | 重授权两端结果准确；错误身份/来源/样本/状态拒绝；旧账号/API兼容，四入口明暗窄屏可操作。 |
| S4 完整响应 | 正式 API 的成功 JSON、完整 SSE 均有容器、代理、上游关联证据。 |
| S5 代理与 TLS | HTTP CONNECT/SOCKS 均验证；错误证书和主机名拒绝。 |
| S6 隔离与并发 | 双账号不串号，共享 CLI 期间 API 正常转发。 |
| S7 取消与慢流 | 取消正确收口，活动计数归零，无盲重放。 |
| S8 故障关闭 | 代理、发送器、绑定或代次异常时明确失败，无管理端直连回退。 |
| S9 线上公网 | 生产发送器经账号代理完成非模型 HTTPS 往返并恢复状态；真实推理缺可用账号时不计通过。 |

## 下一步
