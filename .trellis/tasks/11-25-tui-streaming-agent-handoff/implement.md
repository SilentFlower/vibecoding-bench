# 联合实施与验证

1. 在隔离检出中复用已发布代码和当前测试工具，先制作能在 v1.38.0 复现的红例。使用受控事件顺序产生慢父流、早到子请求、晚到回执及定向 SendMessage。
2. 落实两个子任务。共享 Rust 发送器及 Python 受管适配器的改动按职责合并。对任何持锁等待、耗尽准入名额和回执回不到原进程的路径进行检查。
3. 复用 `verify_tui_cli_handoff.py`、`verify_tui_http_handoff.py`、`verify_tui_final_tls.py` 与 `verify_request_detail_design.py` 中匹配的夹具和驱动。将原版 CC 后台启动时序、完整受管 HTTP 链、三阶段头部证据及真实 Vue 渲染联验，记录每一阶段的观测边界。
4. 核对双版本读取、错误或取消后的重试、关采集、前端构建、后端受影响回归及两端实际镜像构建入口。检查后按实际改动准备源码交付。

## 联合验收结果

- 固定版 CC 2.1.293、真实网关和账号发送器在隔离上游完成父首轮、子轮及父续轮，三次请求均为 200。父流延迟 14 秒、子提示多一个 LF 并携带定向消息时，上游只收到一次子任务提交。
- 取消原父轮后，同会话新父轮的同提示工具和启动回执保留给新请求。旧等待按原模型步骤退出。
- 实际子请求快照将被采用的代理标识记为“提取上下文”，代理转发头记为“删除”。旧版读取器成功读取三份快照。浏览器在 1440、720、390 像素复核阶段和筛选。
- 账号侧 75 项通过。Rust 各测试目标复核共 1113 项通过、15 项按配置跳过。首次全量中两条失败用例逐项重跑通过，两个受影响的完整测试目标重跑也通过。
- 控制及账号候选镜像均已完成本地构建与内容核对。正式发行与线上安装按独立流程执行。
