# V2 后台子代理与请求详情

## 目标

用户在 Claude Code 里派后台任务后可以继续父对话。管理员在请求详情中可以查明这次 V2 请求的每个头在哪一阶段出现、由哪个处理动作决定。

## 问题与范围

- 已发布的 v1.38.0 中，后台任务在父回复完成前发起，连续四次收到 400，模型提交次数均为零。随后携带父代理消息的重试也收到 400。
- 同版 V2 已能保存入口、发送器提交及最终 TLS 的请求头。页面目前只用前两阶段按名称做二维对照。V1 另有逐字段决策及动作筛选。
- 账号事件源负责后台工具交接，采集与详情页负责头部证据。父任务直接负责把两项串起来的真实 HTTP、账号发送器及浏览器验收。正式发行与实例安装沿项目的独立流程。

## 验收

- [ ] 父响应仍在流式输出时，合法的后台派工可以交接。需要晚到的启动回执时，原请求能在已有请求期限内等到它，用户无需重试。父回复和归还工具回执均能继续。
- [ ] 原提示末尾多一个 LF，之后又带同一父代理向该子代理投递的 SendMessage，仍可完成交接。各工具单次提交，附加消息原样送达。
- [ ] V2 请求头表与 V1 使用同一套动作标签、颜色、汇总和筛选。入口、提交、最终 TLS 三阶段均可见。未知、截断、未采集和确定的处理动作分别呈现。
- [ ] 在同一候选中运行模拟上游的真实 CC 派工及受管发送链，核对正确子任务、提交次数、管理接口和最终页面。覆盖停用采集、旧记录和滚动期间的新旧组件。
