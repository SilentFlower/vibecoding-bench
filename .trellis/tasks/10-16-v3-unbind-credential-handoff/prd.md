# 修复解绑后的 refresh token 所有权交接与凭据降级覆盖

## 目标

解绑后的账号仍保有可续期凭据，后台收尾不能抹除 RT，用户可以继续显式创建或关联 cc2api 账号。

## 背景与证据

- 用户截图：创建 cc2api 账号失败，提示“bench profile 缺少 refresh token”。本轮沿用用户要求修复并部署 v3 的目标。
- 2026-10-16 只读线上核对：`10-15` id=3 已解绑，管理 profile、固定 HOME 和 runtime/access 都只有 AT；部署前备份的管理 profile 有 RT，而备份 HOME 本来就只有 AT。当前 AT/expiry 与备份一致，四份顶层配置的设备、账号 UUID、组织和邮箱全部相同；无活动运行或提交记录。当前容器因后台刷新重新唤醒，profile mtime 为 01:13:36 UTC，后台刷新状态 failed。
- `orchestrator/main.py:900` 的创建身份读取要求 RT；`orchestrator/account_runtime.py:447` 未绑定时优先已有 HOME；`:680` 的本地作业 release 无条件用 HOME 覆盖 profile。解绑只清绑定并沿用发布，未把管理侧 RT 交接给原 AT-only HOME。
- 现有真实客户端/SQLite/AccountRuntime 的临时隔离复现：正式解绑之后 profile 有 RT，随后 claim → sync_credentials → release 后 RT 消失；无真实 OAuth/usage/模型请求。
- 上轮回归 `orchestrator/test_deleted_binding.py:102` 把“HOME 继续只有 AT”作为解绑后的保留断言，只检查即时结果，没有覆盖后续后台刷新与收尾。

## 需求

- R1：cc2api 绑定解除后，凭据所有权明确回到本地，原账号完整凭据安全交接到固定 HOME。已绑定时继续 AT-only，不向绑定 CLI 发布 RT。
- R2：已经独立运行并轮换的本地 HOME 保持权威，不能被旧 profile 回滚；AT-only、缺字段或坏 JSON 的 HOME 不能覆盖管理侧完整凭据。身份或来源无法确认时保留现有秘密并返回可理解的恢复/重授权提示。
- R3：正常解绑、远端删除后解绑、旧兼容接口的绑定语义及重复调用保持所有权/占用门禁；后台刷新失败、维护、普通执行与重启收尾不再造成 RT 降级丢失。
- R4：从当前账号自己的停机备份恢复本次损失时，必须再次验证账号/设备、原 AT 与 expiry、无新授权/轮换及空闲状态，备份当前现场后只补回明确丢失的 RT。条件变化则停止恢复，不覆盖新凭据。保留账号、环境 ID、设备、HOME、策略及原启用状态。
- R5：合成验证覆盖创建→绑定→远端删除→解绑→后台失败收尾→再次显式创建，并验证 RT 真实轮换保留、坏文件保护、绑定 AT-only、重复/重启及故障收口。修复完成后按 v3 SOP 部署；真实账号恢复只验证本地结构，不以恢复文件代表 OAuth 可用或封禁解除。

## 验收

- A1（R1/R3）：解绑前 profile 含 RT、HOME 仅 AT，解绑后本地 HOME 获得同账号完整凭据；绑定仍为空，养号 off，设备与环境不变，重复解绑成功。
- A2（R2/R3）：本地 HOME 产生新 AT/RT 后，后续同步与收尾保留新 RT；HOME 缺 RT、损坏、身份冲突或写入失败时不能抹掉完整 profile，也不能假报交接完成。
- A3（R3/R5）：真实隔离堆栈验证解绑后后台刷新失败及任务/维护收尾，再次创建不出现缺 RT，重新绑定后 HOME 再次 AT-only；既有占用/HTTP 错误/重授权门禁通过。
- A4（R4）：线上备份恢复前后同账号同设备证明闭合，当前资料先快照，凭据不进日志，恢复后 RT 本地存在且后台收尾不会再次删除。变化或不确定时保留现场并要求重新授权。
- A5（R5）：必要单测、完整堆栈与交付镜像验收通过并部署 v3；明确区分本地文件恢复、合成创建成功和真实 OAuth 可用性。

## 不包含

- 不绕过支持地区或封禁限制，不强制恢复已删除远端账号，不自动创建真实 cc2api 账号，不通过模型/OAuth 请求探测旧 RT，不把其它账号或旧备份的完整 profile 盲目覆盖到当前账号。
