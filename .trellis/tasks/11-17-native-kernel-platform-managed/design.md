# 平台管理内核设计

## 1. 交付链路

本仓库源码 → 准备已接纳的280／293 → 身份核验 → 同批控制／账号镜像 → 旧库兼容演练 → 平台签名发行 → 原排空及环境重建 → 内置内核。

各平台版本绑定完整组合，源版本选择沿现有规则。既有独立beta选择退出执行决策。

## 2. 双版构建

- 扩展prepare-ci-runtime.py，显式选择2.1.280或2.1.293，省略值保留现有280命令兼容。
- 固定npm tarball、SHA512、官方文件字节数和SHA256，只提取精确程序成员，调用既有隔离构建器。
- composite action分别缓存制品和报告，导出既有V3_NATIVE_RUNTIME_280_ASSET、V3_NATIVE_RUNTIME_ASSET。
- 缓存命中核对制品、官方来源和当前bridge_sources摘要；损坏或漂移明确失败。
- stage_asset的293分支收口旧仓库下载回退；本地缺输入时提示本仓库准备命令。
- v3.json.native_runtime保持双版可追溯身份，并与Rust和Docker固定校验值联合验证。既有已接纳二进制和压缩配方继续使用。

## 3. 配置与执行

- 编排器按实际镜像标签建立完整安装表。prepare_sender=False的重建路径保留预算、身份和业务配置，同时归一为目标内置来源。
- 在平台升级的维护阶段完成目标安装表迁移，发送器重建后核对登记、制品及实际就绪，再完成升级提交和恢复准入。此核验遵循原预热与容量策略。
- 旧配置仅登记293时，即便下一请求使用293，API准备也会比对整个sender布局；将双版登记前移可消除升级完成后因养号占用阻止补登记重建的路径。
- 升级前既有养号／CLI活动沿原排空或超时恢复规则处理；停止环境和历史单版镜像继续按各自状态与实际能力处理。
- 根和每版的旧release/kernel_generation在兼容加载边界收口。Rust的deny_unknown_fields与历史配置联合测试。
- 实际artifact装载仅采用所选源版本的内置分发和映像，历史引用退出/runtime-releases执行入口。
- 保持分发FD、摘要、封存、真实worker_ready、源版本、容量与截止时间校验。
- 专用native-kernel-probe、prepare-switch及候选切换路径退役；普通原生预备和业务路径继续保留。

## 4. 历史迁移及回退

- 在平台维护或受控环境重建边界持有原生命周期锁，核对环境、唯一账号、旧记录、sender配置和真实活动。
- 中断迁移使用私有持久日志保存原操作、账号、代次、停止意图与租约。日志先于文件归一及容器副作用写入，发送器就绪并确认释放门禁后删除；重启按受控的当前／下一代次恢复。
- 已完成的选择写为旧程序可读的内置状态，current归空，收口候选／上一版的执行影响。复用原子文件写入并保留有界迁移审计。
- 覆盖两份native-kernel-upgrade记录和root/per-version配置。已归一化状态作为幂等依据。
- 旧中断操作仅在操作ID、owner、lease generation和活动均可核对时收口，随后按目标镜像重建并核验。
- 外来租约、跨账号／代次、未知活动继续保护门禁，显示明确环境对账原因。
- 停止环境保持停止；旧平台回退重建也读取为目标内置选择。历史制品保留供旧发行读取及审计，垃圾回收独立处理。

## 5. API与页面

- 环境公开投影提供平台管理标记、两版内置信息及实际准备观察，只读状态脱离独立原生发行公钥。
- EnvironmentKernel改为只读展示；环境列表收口独立操作轮询。保留预热、TLS、CRIU和维护状态。
- 独立版本发现和操作接口对已鉴权调用返回410，说明内核由平台版本统一管理；保留原鉴权，下载／切换／租约副作用为零。
- 活动版本发现依赖退役。按调用关系保留必要的轻量只读兼容门面，兼顾维护和并行节点模块引用。
- 新sender收口独立公钥和制品挂载依赖，旧部署字段兼容读取。平台更新签名信任根保持独立。

## 6. 风险与验证

- 迁移关注旧记录回写覆盖、未完成维护、外来租约、幂等和旧平台回退。
- 增加旧293单版登记→双版升级→完成升级→养号运行→首笔293／280请求的跨层回归；断言完成升级前布局已收敛，后续请求通过原发送路径且环境代次／容器保持。
- 确认历史配置解码兼容，避免升级后直接解码失败。
- 冷构建、缓存恢复、输入变化及旧仓库访问阻断联合验证。
- 双版真实网关、混合容量、签名修复、TLS和CRIU定向回归；页面覆盖双版只读与明暗移动布局。
- 宿主固定源码包的导入闭包及平台签名、旧库升级回退单独验证。
- 多个目标文件存在并行任务变更，按实际上下文和行为边界合入。
