# 600 题递进需求与随机多轮自动执行

## Goal

让题库的自动任务在完整初始需求之后，按每次运行固化的随机次数自动追加 0～2 条与该题业务相关的递进需求，全程无需人工操作。

## Background

- 用户明确选择继续自动运行任务，否定以手动选择项目、手动继续对话为主的方案。
- 用户已确认：全部 600 个 topic 配置初始需求及两条有业务增量的递进补充；0、1、2 等概率抽取，按前缀顺序执行；同一任务各轮复用目录及 Claude 会话，所有轮次共用总时间预算。
- 线上只读示例 `aade1180bd9d` 对应 topic no=257、id=497、task=45；原题为 Channel Lead Quality Score。2026-10-17 查看时正在运行，已产出导入、评分和渠道排名代码。该历史输入不回填、不向其临时投递新需求。
- 当前题库只存 title/description/category；任务创建后保存最终 prompt。driver 已能向 tmux TUI 投递初始、收尾和有限故障恢复消息，但首个稳定最终回复即结束运行，尚无题目级补充队列。

## Requirements

- R1：逐题重构 600 条初始需求并编写 1,200 条补充需求，保留编号 1～600；题目、分类和全部需求内容为英文。初始需求可独立交付，补充一在其上增加业务能力，补充二可递进依赖补充一，不能靠通用检查话术凑数。分类随不适合的题目调整，保留 600 题总量。
- R2：一次新运行只抽取一次 0、1、2，并保存所选消息正文及次数；执行初始需求、初始加补充一、或初始加补充一加补充二。重试、暂停恢复、服务重启不重新抽签或读取修改后的题库来改变既有计划。
- R3：自动在可核验的轮次结束边界追加所选需求，保留原目录、原账号和原 Claude 会话。全部选定消息完成后才可结束任务；未确认投递的消息不能假报成功或盲目重发。
- R4：停止、认证失败、额度等待、总超时等现有门禁优先于补充；业务补充不伪装成 OAuth/超时恢复，不增加无条件催促或网络探测，不修改凭据、代理和隔离边界。
- R5：题库同步、任务/运行快照、批次恢复、运行详情均能保存并查看本次消息计划和阶段进度。页面提供结果可见性，自动流程无需新增手动操作步骤。
- R6：自然模式的普通/批量/养号任务采用新补充；规范模式及非空自定义提示词保持单轮。历史任务及已排队/运行的既有输入保持，旧记录缺少新数据时按零补充兼容。每次执行各轮共用原 deadline，不改变现有额度恢复尝试的时限策略。
- R7：只认领本任务文件，保留基线 55 个非本任务改动。用户已明确要求使用 auto-loop 自动推进至本次 v3 线上部署：runner 完成本地提交后，由既有 Git/Actions/v3 SOP 衔接推送、镜像构建、空闲停机备份、题库同步及部署验收；授权仅覆盖本功能交付，不修改无关服务/账号状态，不打断活动任务，不执行真实模型探测。
- R8：全部初始需求和补充需求必须可在空工作区直接开始，不依赖用户上传数据、截图、已有仓库、私有文件、账号、API Key 或外部服务。导入等功能若保留，明确自行生成合法的合成示例数据和可复现演示；高度依赖未提供材料的题目替换为自包含应用。不能把编造内容称为真实业务数据。
- R9：遵循用户最新收紧的题库范围：排除生物/医疗、安全/网络协议/代理/网络扫描、逆向/反编译，以及大模型相关内容，包括训练/微调、蒸馏/提取、LLM 客户端或大模型 API 集成。历史规则曾允许 LLM 客户端，本轮按新要求替换；分类、标题、初始需求及两条补充均执行同样检查。

## Acceptance Criteria

- [ ] AC1：600 个 topic、完整编号以及每题两条英文递进补充通过结构/内容检查，并展示跨分类样例。
- [ ] AC2：固定构造 0、1、2 三种运行，观察到恰好 1、2、3 条题目业务消息，且初始需求未提前包含后续全文。
- [ ] AC3：各轮均在原目录、原会话中执行，首轮完成不提前结束多轮任务；最终报告和终态属于最后选定阶段。
- [ ] AC4：额度恢复、服务中断和投递不确定时计划不漂移、不重复确认过的消息；停止/认证异常/超时等优先级通过有意义的回归。
- [ ] AC5：题库更新保留 topic ID 与历史 prompt；新旧记录、批次和其它适用入口按最终约定兼容，运行详情准确显示计划与进度。
- [ ] AC6：实际 worker/tmux 的自动多轮演练及相关测试通过，证据明确区分测试替身、真实 CLI 和生产验证。
- [ ] AC7：原题依赖外部材料的条目有逐题改写或替换依据；样例和全部消息明确可自启动，跨分类演练不因缺少导入文件/账号/API Key 反问用户。
- [ ] AC8：所有分类、标题、初始需求和补充需求通过英文及排除主题校验；LLM 客户端/API 等原允许项目被纳入本轮替换。


## Out of Scope

- 新建手动项目管理体系、跨账号共享工作目录、随机模拟人工输入节奏或捏造人工观察。
- 临时改写正在运行的线上任务、将额外消息预先拼进初始 prompt、绕过现有停止/额度/认证门禁。
- 承诺多轮互动能降低封号率；无关服务变更或使用真实账号做模型探测。

## 交付后部署授权

用户要求自动推送并部署本次功能；按 `release.md` 在 runner 本地代码交付后衔接既有发布流程，直到线上核验完成。代码任务 Close 不代表已部署，生产活动任务先等待安全窗口。
