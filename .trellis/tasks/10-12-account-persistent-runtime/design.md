# 技术设计

## 目标与边界

本任务只调整 bench 运行架构。保持 FastAPI、SQLite、线程调度、现有账号与 run API、原生 Claude CLI 和正式代理链路，新增账号环境与执行的独立管理。下面的数据结构及组件名称是拟新增设计，不是当前代码已有定义。

普通任务、养号、抓包、续聊和账号维护必须共同适配，按一个任务交付；不引入队列服务、虚拟机或 cc2api 推理桥。

## 架构

```text
账号首次登录/导入 ──> 固定环境注册与准备
                         │
任务/批次/养号/抓包/续聊 ─> 账号执行租约 + 额度门禁
                         │
                         └─> 固定 worker 内执行本次 CLI 作业
                               └─> 固定 sidecar MITM
                                     └─> 账号既有上游代理

cc2api 现有凭据接口 ──> bench 现有所有权同步 ──> 环境内 managed AT
```

- 账号环境管理放在 `main.py` 独立分节，封装 Docker 生命周期、准备、停止和启动对账；保留现有 Runner 对上层的组织作用，避免顺带抽取其他业务模块。
- 固定 worker 由 init/supervisor 保持运行，任务通过独立作业入口和 Docker exec 启动；Claude 不需要永久运行。
- 固定 sidecar 持有网络命名空间及既有代理路线；worker 共享其网络。普通执行不新建容器或重建网络环境。
- 环境容器使用 `bench-account-*` 独立命名与 labels，显式区分环境 ID、角色、布局版本；不能匹配旧 run/login/continue 的批量删除前缀。

## 持久化和身份

### 环境注册

拟新增环境注册表，保存不可变 `environment_id`、关联 `account_id`、初始化来源、固化指纹、布局版本、worker/sidecar 实际标识、准备/停止/异常状态、当前执行来源与代次。新表和附加运行关联列遵循 `CREATE TABLE IF NOT EXISTS` / `_ensure_column()`，历史 run 新列可空。

新登录在 `accounts` 提交前就需要环境，因此先建立持久草稿环境 ID，登录成功后绑定正式账号 ID，沿用同一个环境；不改变“成功提交后才出现在正式账号列表”的行为。已有账号按 ID 找到环境，不再按可变显示名称重新派生。

现有账号迁移优先继承有效 profile 顶层配置和已知环境配置。`userID`、Claude `machineID`、Linux machine-id、hostname、MAC、locale、时区、内存配置分别记录来源，不能将不同含义的 ID 混用。可确认的当前环境配置优先；没有历史系统配置时按当前部署规则一次性固化并明确标注迁移基线，不能声称与未知历史配置相同。已有 CLI 身份缺失、来源冲突或无法安全选择时记录错误并停止迁移。不从每次 run 的随机输入生成身份。

显式代理/时区维护和镜像升级只能在账号无执行时进行；需要重建容器时仍使用已固化身份与持久数据，区分环境连续性和 Docker 容器 ID。

### 目录

拟新增每个环境独立的数据根：

```text
data/environments/<environment_id>/
├── home/                        完整 /home/node，含 .claude.json、.claude 和缓存
├── cli/                         按版本复用的 CLI 安装
├── workspaces/<run_id>/          任务文件、transcript 与 run 输出
├── flows/<run_id>/               统计、被动观察和诊断证据
├── executions/<source_hash>/    每代作业临时状态、PID/PTY/退出结果
└── controls/                    编排上下文、确认与只读额度控制
```

物理目录按环境隔离，各账号容器不挂整个全局 `data/` 或其他账号 HOME。编排控制位于可写任务目录之外；worker 对额度信号仍只读，sidecar 对其观察/信号目录可写、对当前凭据只读。若新布局调整既有 quota-controls 挂载形状，专项 spec 同步描述，不能降低 source/identity 校验和挂载权限。

保持 `runs.workspace_dir`、`flows_dir` 和现有文件/统计 API 的用途，统一路径解析支持新物理目录与历史 `workspaces/<rid>`、`flows/...`。历史目录保持原位，不全量复制其他 run 的项目数据到新 HOME。

## 环境生命周期与资源

- 注册/准备：创建目录、补齐缺失默认值、安装 CA 和基础运行条件，固化身份；默认配置合并保留已有用户字段。
- 就绪/执行：启动后检查健康，领取一个正式执行；环境状态与 `runs.status` 分开，不能用容器是否退出判任务终态。
- 空闲/停止：无执行、无打开 PTY 且不处于准备/切换时，可由空闲回收停止 worker 和 sidecar，保留容器和所有持久目录。等待额度不用保持账号容器常驻。
- 再次使用：唤醒同一环境，复用安装与 HOME；启动必要的路由与进程不等于重新初始化账号。
- 异常：身份、控制或健康失败记录原因并阻止执行；无法确认旧作业已停止时，先停止该账号容器隔离请求，保留磁盘证据，不创建新身份重试。
- 镜像重建：显式维护时停工、收口执行、更新布局/镜像并使用同一持久数据；失败可恢复旧镜像与注册记录。

启动对账先消费已有额度观察和控制补证，再确认/停止旧执行并校验代次，最后恢复调度。保留并检查健康的账号环境，不让旧 `cleanup_stale()` 删除它们；旧临时容器按原来源严格清理。排队工作重新检查停止、父任务和账号可用状态，非幂等普通运行不能在失去证据时盲目重发。

## 执行契约和并发

拟新增执行句柄，包含环境 ID、执行 source、代次、run/session 关联、cwd、主 Claude session、CLI 路径、tmux/PTY 归属和结果路径。`worker_container`、`sidecar_container` 仍可报告实际容器，但不能独立充当任务句柄。

所有入口使用同一个账号执行租约；普通/批次/capture run 等待，交互登录、续聊和手动查询在账号忙时返回已有风格的明确冲突，不在同步路由中长时间等待。排队 run 和 quota_wait 不长期占用租约。cc2api AT 的受控同步可以针对当前作业进行，不能因全程持有 owner lock 造成 401 恢复死锁。

短事务领取执行后释放 DB 锁，按已有 owner -> profile 锁顺序重新读取账号并同步凭据，随后准备 sidecar 上下文和启动作业。停止信号、执行代次和当前租约在启动前及终态写回时都复查。停止仅处理匹配句柄的 Claude、tmux 和子进程；正常收口不删除环境。无法确认子进程/连接收口时隔离整个账号环境并报错。

worker 的基础初始化与作业启动拆开。现有 `/tmp/claude-*`、完成钩子、凭据刷新 marker、状态文件、tmux socket/session 和动态 cwd 改为执行专属路径；新 cwd 的 onboarding 处理仍保留任务指定权限模式和原始题目。第二次同版本只校验/复用安装；不同版本缓存按运行快照选择，不能在活动作业中替换全局 CLI。

首次主会话 ID、项目位置和观察偏移写入 run 关联。完成判断和 usage 只读取本 run 的主会话及相关新增输出，排除账号其他项目、历史主会话及未归属子代理。续聊、额度恢复继续原会话和 cwd；旧布局由兼容解析与必要的主会话索引迁移处理，具体 CLI 行为在实施的前置验证中确认。

同账号实际并发上限为 1，Compose 配置和批次创建/显示同步；已有 concurrency > 1 的批次仍可保留历史值，但对执行能力明确标注实际串行，不能生成并行 worker。不同账号并行不引入新的全局运行限制。

## sidecar 上下文、额度与抓包

固定 sidecar 内增加执行上下文控制：当前 source/identity、输出目录、凭据只读位置、额度状态/信号路径和完整记录配置由编排端原子发布，sidecar 校验并写确认；worker 只有收到对应代次确认后才能发起请求。不能试图修改 Docker 环境变量来更新已运行的 `Recorder`。

每个请求在开始时固定上下文，后续响应写入相同来源，不能按响应完成时的新上下文归档。控制必须校验路径处于本账号挂载根下；损坏、过时代次或不一致时不放行正式模型请求。

普通执行继续 MITM，保留 stats 和真实响应的被动额度观察。`QuotaGuard` 的账号身份、逐窗口事实合并、即时门禁、日志优先/控制补证、未知 reset 等待及一次恢复认领保持原有语义；执行关闭前消费并归档观察，旧来源不污染新作业。

抓包执行启用完整 HTTP、原生 `.flow` 和索引，覆盖当前诊断忽略域名规则；抓包续聊按原 run 追加。上下文切换同时覆盖 addon 记录与 mitmdump 的 flow/ignore 选项，不能只改 HTTP JSONL 开关。优先通过 mitmproxy 明确控制接口或 addon 实现；若某个设置必须重启 mitmdump，只在作业间排空连接后重启该进程，保留账号容器、网络、CA 和上游配置，不借机重建账号环境。

作业结束流程为：禁止新请求 -> 停止/确认作业进程 -> 排空或关闭旧连接 -> 落盘证据与额度观察 -> 关闭诊断配置并取得确认 -> 释放租约。异常和取消走相同恢复路径；撤销失败时隔离账号，不启动后续普通任务。

全局 capture 互斥覆盖初次 run、续聊和额度恢复，维持 120 秒间隔和异常至少 15 分钟冷却。SOP 中“清理 worker/sidecar 后再开始”更新为“严格收口对应执行、连接和诊断上下文后再开始”，不再要求删除固定环境。原始文件 0700/0600 与页面脱敏不变。MITM 抓包的上游 TLS 属于 MITM，不能将其宣称为 Claude 原生 TLS 指纹证据。

## 养号和凭据所有权

养号继续用现有随机选题、去重、3–5 小时默认间隔及配置。到期但账号有正式执行、登录/续聊或待执行普通/capture 工作时顺延，下次扫描再判定，不积压、抢占或补跑；人工“立即运行”也遵守账号占用与额度门禁。

保留已有 warmup_enabled、绑定门槛、quota_wait 恢复原 run、终态绑定 ID 校验和认证失败策略。正式取得租约后再次同步凭据，不能用认领时的旧 token。永久认证错误关闭养号、暂停后续投放并保留环境。

profile 继续作为现有凭据接口的兼容入口；完整 HOME 是运行状态来源，两者不再每 run 相互整目录复制。绑定账号 profile 由 cc2api 同步结果管理，worker 本地凭据不含可竞争刷新的 RT，managed 401 marker 带执行代次走既有接口。未绑定账号的刷新器与当前 CLI 刷新继续按所有权锁协调，使用同一账号环境。

首次登录在草稿环境内完成。重新授权仍在同一设备/网络环境内使用暂存配置与凭据事务：保留设备 ID，提交前不破坏真实凭据，取消或失败恢复旧状态；成功后按现有身份切换规则清理过期额度事实，但保留用户 HOME、会话与有效设备身份。已绑定账号要求先解绑才能提交重授权的限制保持。

## 兼容、页面与迁移

- 保留现有账号、任务、capture、login、continue、quota 端点及请求字段；必要返回信息以附加字段提供，不暴露环境凭据或内部 token 哈希。
- 账号页增量展示准备、可用、忙碌、已停止或异常的用户提示；批次并发提示与实际串行一致，已有页面与 SSE/WS 语义保留。
- 旧账号注册在升级初始化时幂等建立元数据，按需准备物理环境，不一次启动所有账号。新账号首次登录/导入就登记并准备环境。
- 迁移在账号空闲且无旧执行时进行。先备份 SQLite/账号配置并写迁移清单，在暂存目录完成、校验身份，再原子发布；失败回滚到原资料，不自动切换身份重试。
- 历史 run 原目录和 flows 不删除，首次需要续聊/恢复时仅导入该 run 的主会话与必要索引并保持明确归属；软删除或永久门禁账号不被迁移流程重新启用。
- legacy `init-account.sh` 改为指向正式 WebUI/环境入口，保留已有 profile 导入说明，不再创建另一套临时设备作为推荐流程。

## 交付、回滚与验证

orchestrator、worker、sidecar 作为兼容组合构建；本地与远程 Compose 环境变量、镜像 COPY 和新脚本一致更新，cc2api 不构建、不修改。

回滚前停止调度、关闭所有执行与 PTY、消费最后观察并确认无请求，停止账号容器但保留数据。使用 SQLite backup API 备份当前状态；回退前同步最新的合法凭据到兼容 profile，避免旧备份 RT 与当前所有者不一致。恢复旧镜像/配置和兼容数据库后校验 CLI 版本与原目录，固定环境保持停止，防止新旧执行并行。原 HOME 和证据不删除。

以现有 unittest 和真实 shell 行为测试覆盖来源隔离、租约、取消/重启竞态、会话归属、抓包撤销、额度恢复、重授权与迁移。Docker 生命周期测试验证容器常驻、exec 退出、子进程收口、空闲唤醒与持久身份；真实首轮/续聊验证遵守既有 SOP，并记录实际运行证据与未执行项目。
