# 账号固定持久环境与任务生命周期改造

## Goal

每个账号从首次建立开始复用同一套持久运行环境，使普通任务、续聊、授权、养号和抓包延续设备身份与完整用户状态，并减少重复初始化。

## Background

- 用户反馈服务器账号再次被暂停，要求核查设备身份一致性，并参考 vm2api 的账号持久环境思路改造 bench。
- 已有检查说明 Claude 的持久设备 ID 曾跨运行保持一致，不能将账号暂停直接归因于容器重建；本任务解决运行环境与生命周期的一致性，不承诺规避平台风控。
- 当前 `Runner.start_run()` 每次创建 worker/sidecar（`orchestrator/main.py:3309`），任务完成后 `Runner.cleanup()` 删除容器（`:3546`）；续聊和登录还有独立启动与清理路径（`:3627`、`:4385`）。
- sidecar 同时承担 MITM、请求统计和被动额度观测（`images/sidecar/recorder.py:396`）；观察配置与完整抓包开关目前在进程初始化时读取，固定容器不能继续沿用上一 run 的来源和输出路径。

## Requirements

- R1：新账号首次登录或导入时建立固定环境，与不可变账号 ID 关联；已有账号迁移继承 profile 中的 `userID`、`machineID`、登录配置以及可确认的环境设置。已有账号设备身份缺失或来源冲突时显示明确原因，不自动覆盖有效身份；新账号首次初始化产生的身份随后固定。环境身份不因任务、停止启动或显示名称变化重新生成，本轮不新增改名功能。
- R2：完整 HOME、Claude 顶层配置、登录状态、会话和缓存持久保存；基础依赖及同一指定 CLI 版本的安装结果可复用。CLI、模型、effort、权限仍按各 run 已有快照执行，单个运行覆盖不污染账号默认配置。
- R3：环境生命周期与执行生命周期分离；普通任务、批次、续聊、首次登录、重授权、显式手动额度查询和未绑定账号的凭据维护均适配固定环境。每个 run 有独立工作目录、主会话关联和证据归属，统计不扫描累加整个账号 HOME。
- R4：同账号正式执行串行，不同账号可并行。取消、超时、额度暂停、WS 关闭及服务重启不能误删共享环境、恢复已取消工作或留下继续请求上游的旧执行；排队和额度等待不长期持有执行资源。批次并发配置与页面必须诚实展示实际单账号串行行为。
- R5：养号在同一环境中作为低优先级任务执行，保留选题、随机间隔、绑定门槛和终态回调语义（`WarmupScheduler._claim_account()`，`orchestrator/main.py:6235`）；账号忙时顺延，不补跑积压，不抢占已运行任务，不改变原有养号启用状态。
- R6：抓包复用同账号 HOME、CLI、网络环境和既有代理，仅对诊断执行开启完整记录，抓包续聊沿用原证据归属。保留全局串行、120 秒间隔和异常后至少 15 分钟冷却要求（`official-protocol-capture.md:112`）；完成、停止、超时和异常均关闭诊断记录，确认无旧请求后再启动下一执行。受限原始文件与脱敏页面展示契约不变。
- R7：保留真实响应驱动的额度保护、原任务原会话恢复、执行快照及封号暂停语义（`database-guidelines.md:531`）。观察与控制按现有 source/identity/代次隔离，未知 reset 不猜测、到期不自动写恢复、不创建主动探测请求；永久认证异常停止后续投放并保留环境证据。
- R8：cc2api 的代码及管理接口保持兼容。绑定账号继续由 cc2api 唯一刷新 AT/RT（`database-guidelines.md:214`），运行取得执行权后同步最新凭据，受控 401 恢复遵循已有 managed 流程。未绑定账号保留原有刷新职责；绑定切换和重授权保留活跃工作检查。重授权取消或失败后旧凭据仍可用，成功提交不删除已有会话与设备身份（当前暂存保护见 `LoginManager.start()`，`orchestrator/main.py:4422`）。
- R9：提供幂等旧账号迁移、启动对账、空闲资源释放、镜像升级及回滚说明。账号删除沿用既有历史保留行为，阻止后续任务并保留持久数据。环境失败可定位原因；身份不变不等于宿主硬件或代理实际出口 IP 恒定，维护操作不得宣传为防封保证。

## Acceptance Criteria

- [ ] A1（R1、R2）：同账号从首次登录到普通任务、养号、抓包及续聊均复用同一环境身份与 HOME；已有有效设备 ID 不被覆盖，同版本再次运行不重复安装或重置 onboarding。
- [ ] A2（R2、R3）：独立 run 的目录、主会话、transcript、token 统计、状态以及 CLI/模型/effort/权限快照正确；共享 HOME 的其他项目、旧主会话和子代理历史不计入新 run。
- [ ] A3（R3、R4）：停止、超时、WS 关闭、额度暂停和服务重启后可确认旧执行及其网络请求已收口；不会误删 HOME、误终止其他账号或被旧代次回调覆盖新执行。
- [ ] A4（R4、R5）：同账号同时仅一个正式执行，普通任务和抓包排队时养号顺延；已运行养号不被抢占，不同账号可独立执行。等待期释放执行资源，批次 UI 不再承诺同账号并发 2。
- [ ] A5（R6）：完整抓包、原生 flow、索引、统计按 run 留存，抓包续聊追加原证据；停止、超时和异常也能关闭完整记录，默认配置下紧随其后的普通运行不留存诊断正文。串行、间隔、冷却和文件权限通过验证。
- [ ] A6（R7）：额度即时门禁与暂停信号仍生效；等待恢复沿用原 run/session 和全部快照，到期只放行一个已有正式执行验证，未知 reset 保持等待。`account_on_hold`、`invalid_grant` 阻止自动恢复及后续养号。
- [ ] A7（R8）：绑定账号的持久 worker 不竞争刷新 RT，排队后使用最新 AT，401 恢复归属正确；未绑定账号刷新正常。取消重授权保留旧凭据，提交成功保留设备身份和已有会话，cc2api 无实现改动。
- [ ] A8（R9）：迁移重复执行安全，已有失败、等待、停用和软删除状态不被激活；历史 run 能查看并在适用时恢复原会话。空闲停止启动及受控镜像重建保留 HOME 和环境身份，回滚说明包含停工、备份、凭据同步及旧执行隔离。
- [ ] A9（R3、R9）：账号创建、登录、批次、续聊和环境异常的页面提示与 API 行为一致；完成本地回归及 Docker 生命周期验证，真实 Claude 首轮/续聊证据按项目 SOP 留存，未执行的验证明确记录而非宣称通过。

## Non-Goals

- 不修改 cc2api 的实现、版本画像、API 推理链路或其独立设备身份。
- 不引入 KVM、QEMU、vm2api 的 patched CLI 或闭源 payload。
- 不在本轮移除普通流量 MITM；TLS 直通及其额度观测替代机制另行规划。默认普通记录维持必要统计与额度观察，显式 `SAVE_FULL_FLOWS` 配置继续兼容。
- 不新增养号策略、主动探测请求、规避封号机制或同账号多进程推理并发。
- 本轮不自动部署线上，也不在规划阶段启动真实账号实验。
