# 修复 V2 请求后的官方额度更新

## 目标

受管 Claude 账号用 V2 处理 Messages 请求后，账号页随现有轮询显示该账号新观测到的官方额度百分比。

## 背景

用户看到请求后的额度百分比仍显示旧值。本地回环已验证两种响应格式的问题。上游返回完整 5 小时和 7 天额度头，V2 事件源的私有应答只有响应状态、内容类型和消息 ID 模式。网关的 V2 分支交付正文并记录请求用量，账号额度另有写入流程。[事件源](../../../images/account/tui_source.py#L275) · [网关 V2 分支](../../../services/gateway/src/service/gateway.rs#L2790) · [账号页](../../../apps/web/src/components/Accounts.vue#L512)

## 需求

- R1 受管 V2 的真实模型响应提供官方额度时，按本次实际执行的账号更新有效的 5 小时、7 天及 Fable 专属周窗口。流式和非流式 Messages、首轮和原工具续轮均适用。真实上游 429 按各窗口自身的拒绝状态保存观察。
- R2 额度来自同一账号已绑定的上游响应。缺失或异常的窗口保留原观察，其他有效窗口独立更新。旧发送器无此信息时正常交付请求，额度沿既有方式可读取和手动刷新。
- R3 沿用现有只读列表、请求用量账本和周期合并规则。额度更新利用此次模型响应。公开 Messages 接口继续交付原状态、正文及工具轮行为。

## 验收

- [ ] R1 用隔离模拟上游依次返回不同百分比。从公开 V2 Messages 分别完成流式、非流式和工具续轮，通过账号列表核对对应账号的 `usage_data`、`usage_fetched_at`、百分比和重置时间。核对 429 拒绝窗口与允许窗口的周期合并结果。
- [ ] R2 使用第二个账号、旧发送器回执、缺失和无效窗口，以及本地提供方的同名头。核对账号隔离及原观察保留，完整窗口仍更新。
- [ ] R3 核对单次模型提交、正常 Token 统计及 SSE、JSON 和 429 的原状态和内容。验证私有额度字段限于内部链路，模型请求路径的增量 OAuth usage 查询数为零。

## 范围边界

本任务限于 V2 的被动额度采集和读回验收。主动刷新策略、账号卡片设计及上线操作各自沿现行流程。
