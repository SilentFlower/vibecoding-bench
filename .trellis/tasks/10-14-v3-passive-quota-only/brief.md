# Brief — v3 手动额度查询与被动采集统一

## Goal

- v3 仅在用户点击时主动查询额度，其余从正常业务请求被动更新，并保留阈值和无人值守恢复。

## Scope

- 接入 CLI 本地 statusLine 额度数据，复用 cc2api／v3 发送器现有响应头采集。
- 移除任务前后、后台等待及失败重试中的自动 usage；禁用 v3 的 cc2api 额度轮询。
- 调整阈值恢复、手动永久错误分类和页面来源／等待提示。

## Non-Goals

- 本轮完成代码与隔离验收；生产镜像切换另走现有发布流程。
- 不更换代理、账号画像、CLI 版本、官方遥测或普通任务原生 TLS，不恢复封禁账号。

## Technical Overview

- CLI 采集器只读取官方 stdin 的 5h／7d 百分比和 reset，按账号、作业和会话归属接入现有观察状态；网关继续消费真实响应头。采集器不发 HTTP、不执行 `/usage`，作业收口恢复原 statusLine 设置。

## Context & Decisions

- 当前普通 CLI 不经过 cc2api 网关，因此两条被动入口需要汇合。
- 首次未知显示未知，允许已有正常任务取得首个响应；有效额度达到阈值时暂停后续任务，已开始任务完整收尾。
- 可信 reset 到期只恢复一个已有正式任务获取新数据；不写成 0%、不创建探测任务。停止、停用及永久账号错误优先。
- 非 v3 实例保持原行为，历史任务、HOME 和凭据保留。

## Risks

- statusLine 窗口可能缺失；会话归属、重复缓存输出、原设置恢复和实际 CLI 数据可用性需隔离验证。

## Acceptance

- 自动执行与后台等待路径零主动 usage；手动点击保留一次查询，失败无自动重试。
- CLI／网关被动样本能更新 5h／7d，0% 有效；缺失、乱序和旧会话不污染状态。
- 阈值暂停、窗口到期单次恢复、重启与用户停止均正确，明确封禁不自动恢复。
- 通过相关回归、隔离官方 CLI／Docker 和页面验证，采集不新增网络请求，不使用封禁账号验证。

## Next Step

- 实现与隔离验证已通过；下一步同步规范并进入既有交付流程。
