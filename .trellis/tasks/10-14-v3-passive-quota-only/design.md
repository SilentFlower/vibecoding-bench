# v3 被动额度采集设计

## 边界

父仓负责 v3 CLI 采集、共享额度状态、任务／养号调度、手动接口及页面；cc2api 子仓负责在 v3 模式关闭后台 usage 轮询，保留既有成功／429 的响应头采集。旧 runner 和非 v3 cc2api 使用原行为，不引入全局停用开关、独立服务或新任务队列。

## 数据流

1. 用户点击查询时，现有手动接口经账号代理调用一次 usage，更新 `account_quota_states`。失败返回本次结果；明确的永久账号错误进入 `record_auth_failure()`，没有后台查询重试。
2. 正常网关响应沿已有 `extract_passive_usage()`／`update_passive_usage()` 处理；v3 发送器的白名单 JSONL 沿 `QuotaGuard.consume()` 进入同一 bench 状态。
3. 正式 CLI 作业临时启用本地 statusLine 包装命令，读取 stdin 中官方 `rate_limits`。仅保存 5h／7d 数值、重置时间和必要作业归属，映射到已有窗口／观察协议。采集命令不访问网络、不调用 `/usage`，不修改 TLS 或模型载荷。
4. 调度器只消费现有观察并判断阈值；后台 tick 仍可读取本地文件和推进已有等待工作，但不查询 usage。

## CLI 生命周期和数据契约

- 复用 `AccountRuntime` 的执行 source、账号 identity、环境／执行代次与会话绑定。采集文件跟随执行来源登记到已有游标；UID1000 只获得专用额度输出位置，不放宽 root 私有 runtime 或其他账号目录权限。
- 官方字段为 `rate_limits.five_hour/seven_day.used_percentage`（0～100）和 `resets_at`（UTC 秒）；0 为有效值。布尔、非有限值、越界、非法时间和不匹配会话拒绝，缺失窗口保持缺失。
- 优先使用已有观察封装及合并函数，必要时增加纯函数转换器；不新增数据库表。不能把完整 statusLine stdin、凭据、prompt 或工具内容写入观察文件。
- 样本按各窗口自身观察时间合并。相同缓存值重复输出不能制造新的上游观察时间；旧 source／会话／代次数据不能清除新拒绝或永久门禁。
- 只在普通任务、养号及原任务恢复执行安装采集；继续对话可更新事实，但保留既有不受账号百分比阈值限制的执行规则。显式抓包保持 Recorder 采集，按已有乱序合并避免同一观察重复影响。
- 保存并恢复原 statusLine 设置；已有用户状态栏命令继续获得原 stdin 并保留输出。未配置时展示简洁额度信息；不增加固定定时刷新。原 worker/profile 的长期设置清理不改为永久安装。
- 安装、取消、停止、异常退出及重启对账都沿原执行清理处理；不能遗留指向已结束作业的配置或采集进程。以隔离官方 CLI 场景核实配置加载和数据归属，不以二进制字符串扫描替代运行证据。

## 阈值与恢复

- 移除 v3 的自动 usage 调用、`_usage_refresh` 失败重试／dirty 门禁及“300 秒过期必须重新查询”的要求。仍保留身份、共同耗尽和永久认证门禁。
- 未知状态不写成 0%；在没有真实拒绝或已命中有效阈值时允许已有正常任务运行，由其正式响应更新额度。页面显示未知或上次观察时间。
- 有效窗口达到用户阈值时暂停后续执行，已开始的执行完整收尾。缺少窗口不能删除另一个已确认的有效阻断。
- reset 到期只产生恢复机会。复用账号恢复认领，让一个已有正式执行继续原题／run／session 和配置；真实允许观察确认新窗口后再推进其他任务。再次拒绝按真实 reset 等待；无可信 reset 时不猜时间、不周期发探测。
- 停止、暂停、账号停用、删除、身份变化和永久认证错误仍优先；服务重启恢复活动批次的原 item 与投放时间，不复活已结束工作。

## cc2api 与手动查询

- 通过既有 v3 运行模式边界阻止 `UsagePollerService` 发主动额度请求，历史 `auto_poll_usage` 值保留供非 v3 兼容，不为禁用轮询修改账号凭据或代理。
- 网关业务成功／429 和模型专属窗口的被动解析不改；手动 `/admin/accounts/:id/usage` 保留，v3 bench 手动查询同样保留。
- 手动查询错误解析只接受已有结构中的明确 `account_on_hold`／`invalid_grant`；普通 401／403、429、网络失败不凭状态码推断永久封禁。错误提示脱敏；不自动清除已经终态的历史认证失败 run。

## 页面与状态兼容

删除 v3 自动查询／下次重试文案，来源显示被动或手动，并保留具体阈值等待、重置时间和账号错误。保留现有公开 DTO 字段，已废弃的 `refresh_retry_at` 为空；不把新的内部会话／身份信息返回浏览器。

## 验证与回退

自动执行路径用 usage 调用即失败的测试替身验证；隔离代理／HTTP 服务统计请求，证明 CLI 本地采集不新增 usage 或模型请求。正常 CLI 本地输出与 API 响应头都通过真实协议形状验证。未具备可用账号时使用隔离官方 CLI 及本地响应，不运行封禁账号。

本轮先完成代码和隔离验收；生产交付另按既有 v3 联合镜像 SOP 核对精确批次、备份和账号 HOME。回退时恢复原镜像与配置快照，不删除 HOME／观察／SQLite 历史；回到旧主动查询版本的行为变化必须明确提示。
