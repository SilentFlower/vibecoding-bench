# cc2api 请求级排障观测设计

## 现状与依据

- `src/service/gateway.rs:2331` 只为成功 messages 响应创建 `UsageCapture`；已有用量表无法表达本地拒绝、认证失败或中间重试。
- `src/service/usage.rs:21` 的观察器已支持 SSE/JSON、限长压缩解码、累计最大值用量及一次性结束，可复用解析机制。`src/service/telemetry.rs:158` 已定义响应状态、首字节、用量和 stop_reason 的安全摘要，但自动遥测开关不能控制本任务采集。
- `src/store/usage_store.rs:16` 的 `UsageRecord` 用于费用统计，保留成功调用语义，不能通过给失败请求写零费用来冒充诊断记录。
- `src/service/gateway.rs:2581` 创建的 `PreparedRequest.request_id` 为空，`src/service/runtime_transport.rs:236` 在 v3 发包时重新生成；目前不能贯穿网关和 sender 证据。
- `/root/project/new-api/relay/channel/api_request.go:588` 已读取响应 `X-Request-Id`，无值时读取 `X-Oneapi-Request-Id`。因此可以通过兼容的响应关联字段让已有 new-api 留下可查询 ID，无需修改该仓库。
- `src/store/memory.rs:145` 池满时保存真实 session 到已有成员的映射；`owner_only` 下借用不会延长目标 TTL。观测只记录解析结果，不额外调用 resolve，不改变映射。

## 边界与数据流

API 令牌鉴权后的 `/v1/messages` 入口生成网关 UUID → 本地准入/缓存/模拟结果 → 每次真实发送建立尝试 UUID → 选定账号与冻结画像、最终请求参数和 session 映射 → 原有传输 → 有界响应旁路摘要 → 一次性终态 → 有界异步写入 → 管理员分页/详情查询。未通过入口令牌鉴权的流量沿用现有处理，不写入本轮诊断表。

一次用户请求对应一条请求记录；每次实际提交对应独立尝试。401 后的认证恢复、签名修复后再次发送、换号和传输未知结果都保留边界，不只记录最终成功结果。本地拒绝或缓存/模拟命中有请求记录，但没有虚构的上游发送尝试。

## 关联契约

- 网关请求 UUID 在整个生命周期中稳定；每次实际发送有不同尝试 UUID。
- 复用 `PreparedRequest.request_id` 传递尝试 UUID：调用方提供合法内部 UUID 时传输层保留，旧调用方未提供时继续生成。sender 现有 observations 使用同一 UUID，不新增服务间秘密或透传用户任意 ID。
- 响应新增 `X-CC2API-Request-Id`，值为网关 UUID；上游已有 `X-Request-Id` 保留，没有时以网关 UUID 补齐。记录最终响应采用的 ID，并允许按该 ID 或上游 request ID 查询，兼容 new-api 的现有读取逻辑。
- 根 ID、尝试 ID 与上游 request ID 分别保存；上游 ID 缺失保留为空，不把三个 ID 当成同一事实。
- 关联字段只在内部元信息和下游响应使用，不添加到发往 Anthropic 的业务请求 headers/body。

## 记录内容

请求记录保存起止时间、结果、最终响应状态与关联 ID。尝试记录保存账号 ID、实际画像版本及选择方式、请求/响应模型、最终 max_tokens、thinking 模式及可用预算、effort、stream、工具数量、真实/上游 session 匿名标识及映射动作、可用的匿名 thread 前驱/响应消息 ID、起止/首字节、响应状态、stop_reason、四类 token 和缓存写明细、partial、重试原因与错误阶段。

版本来源是本次冻结画像和实际账号副本；参数来源是每次实际发送前的最终请求。不能在结束时重读账号全局配置，也不能从请求体版本文案推测。响应内容只保留上述元数据；不知道、未观察到和不适用均为 null，不伪造零值。

session、线程与消息 ID 在进入观测对象前散列，沿用项目 SHA256 摘要惯例并按账号和标识类型隔离。持久化对象不持有明文身份或正文。错误只保留枚举/受控错误码和阶段，禁止原样落入任意 error.message 或 headers。

## 存储与查询

- 新增独立诊断 store；请求主表、尝试子表采用两种数据库共同支持的列类型。请求 ID 唯一、尝试 ID 唯一，按时间/账号/请求 ID 建索引。扩展摘要使用有界白名单 JSON TEXT，避免依赖方言 JSON 查询。
- 迁移为追加建表及索引，SQLite/PostgreSQL 均幂等；不修改、清空或回填既有费用记录。
- 使用有界异步队列和后台写入，热路径不等待数据库；队列满、数据库失败和解码超限均有脱敏错误信号与计数。已提交记录可跨重启读取；进程崩溃前未提交的缓冲不承诺恢复。
- 按时间保留八天，由后台清理过期主记录和尝试；不能固定条数截断当前周，也不在管理列表 GET 时删除。
- 新增 `GET /admin/request-diagnostics` 与 `GET /admin/request-diagnostics/:request_id`，沿用管理员认证。列表按时间倒序分页，默认 50、上限 200；支持时间、账号、关联 ID、结果筛选。详情包含各次尝试，不暴露凭据与正文。非法筛选返回 400，存储失败不返回假空列表。
- 本轮不增加可配置 settings，避免引入无必要开关和前端同步范围；使用固定有界采集与八天留存，并在运维文档注明。

## 兼容与风险

- 保持调度、并发、RPM、session、画像、CCH、重试、认证和上游协议字节原行为；添加的是诊断观察，不是行为修复。
- `SlotGuardBody` 的 EOF/error/Drop、缓存的缓冲分支、签名重试、401 恢复与 early return 都需精确终结一次；流中断必须与 HTTP 200 完整成功分开。
- 尽量复用有界响应解析，不追加全量解压缓存，不为了 stop_reason 重新缓冲完整流。
- 费用记录与诊断记录分开；失败、缓存、模拟和重试不能重复计费。
- 响应关联头属于本轮新增兼容契约：保留上游已有 `X-Request-Id`，不得误覆盖鉴权头或向上游发送诊断头。

## 验证与回滚

使用本地合成 HTTP 上游验证成功、401 恢复、重试、拒绝、模拟、SSE/JSON、压缩、中断及取消。独立数据库连接检查重启留存、过滤分页、清理和幂等；SQLite 与显式本地 PostgreSQL 都验证。对比实施前后转发 bytes/header 及用量次数；注入合成秘密确认白名单边界。线上不新增模型探测。

回滚为恢复旧二进制，追加诊断表保留而不读写，不回滚账号凭据或既有业务表。持久化不承诺进程崩溃前的未提交缓冲。
