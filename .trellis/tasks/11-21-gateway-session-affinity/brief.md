# Brief — Claude 与反重力会话粘性及请求记录展示

## Goal

- 让 Flower2API V3 的 Claude 与反重力在多账号场景中识别连续请求，并在请求记录中显示可复制的会话 ID。

## Scope

- Claude Messages、反重力 Gemini 生成接口的会话选号，以及请求列表和详情的「原始 Session ID」展示。

## Non-Goals

- 历史记录回填、其他协议入口、进程内历史前缀索引和软件发布属于独立工作。

## Technical Overview

- 选号前优先读取客户端 ID，缺省时用请求模型、工具、系统指令和首条有效用户内容派生键。按平台和 Token 隔离，复用数据库原子绑定决定并发首轮的账号。

## Context & Decisions

- **【关键决定】「原始 Session ID」优先显示客户端值。缺省时显示实际用于选号的派生值，标注「网关派生」，支持完整复制。**
- **【关键决定】两入口支持可选 `X-Session-Id`。在同平台、同 Token 下，多个客户端可以用同一个显式 ID 连续会话。**
- **【重要限制】两个对话的派生字段全部相同时可能命中同一账号。裁掉开场历史或每轮只发新问题时，使用显式 ID 可保持会话粘性。**
- 绑定有效且账号符合路由条件时优先复用。暂时繁忙时按原账号的预算等待或返回限流。工具回填继续以已验证的原请求归属为准。

## Risks

- 反重力工具回填重放正在独立演进。联调须以实际合入的版本核对同账号归属及一次提交。

## Acceptance

- 两平台各用双账号验证纯 API 连续两轮、并发首轮、Token 隔离及过期恢复。核对实际发送账号和持久绑定。
- 验证列表和详情显示、复制原始值与派生值，并覆盖旧记录和工具回填重放。

## Next Step
