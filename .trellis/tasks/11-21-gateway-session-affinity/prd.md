# Claude 与反重力会话粘性及请求记录展示

## 目标

让 Flower2API V3 的 Claude Messages 与反重力 Gemini 在多账号环境中识别普通客户端和纯 API 的连续请求。管理员可从请求记录查看并复制本轮的客户端会话 ID 或用于选号的派生值。

## 背景

- Claude V3 从入站正文读取显式会话并原子绑定账号。反重力普通生成每轮选号，工具回填有独立的原请求归属校验。 [Claude 入口](../../../services/gateway/src/service/gateway.rs#L2253) [反重力选账号](../../../services/gateway/src/service/agy_account.rs#L298) [工具回填](../../../services/gateway/src/service/gemini.rs#L727)
- 现有「原始 Session ID」列用于查看及复制客户端入站值。用户要求在缺少客户端值时也能从这一列查看派生值。 [请求记录](../../../apps/web/src/components/RequestDiagnostics.vue#L361) [原始会话字段合同](../../spec/gateway/backend/settings-database.md#scenario-请求级诊断与发送尝试关联)
- Sub2API 用稳定首条用户内容支持 Gemini 纯 API 会话粘性。 [Sub2API 派生规则](https://github.com/Wei-Shaw/sub2api/blob/328db26f450edbdf9f8d4344a3ea903ac6396842/backend/internal/service/gemini_session.go#L19-L60)

## 需求

- **R1** 两个平台优先使用有效客户端会话 ID。没有显式 ID 且入站有稳定首轮信息时，从请求内容派生会话键。纯 API 保留同一开场上下文并追加后续轮次时，复用原键。固定 API Token 下的多个客户端均可使用可选会话头标识各自的对话。
- **R2** 在同平台、同 API Token、绑定有效且账号仍具备本次路由资格时，复用原账号。并发首轮只为一个目标账号建立绑定。暂时繁忙时在原账号的预算内等待或返回限流。绑定过期、账号停用、当前 Token 失去账号权限或账号失去该模型的服务资格时，按既有候选和错误语义处理。
- **R3** 反重力首次工具回填按已验证的原工具轮归属继续。已受理的回填重放沿相邻任务的幂等合同处理。普通会话键只用于账号调度，不作为工具归属凭据。
- **R4** 请求列表和详情沿用「原始 Session ID」。优先显示并复制客户端入站 ID。缺省时显示并复制实际用于选号的完整派生值，附文字「网关派生」。旧记录及无可用会话信息的请求显示「未提供」。
- **R5** 账号绑定、请求记录和会话派生遵循现有 Token 权限与管理鉴权。诊断摘要只增加会话键。请求正文、工具内容、凭据、上游身份及原始字段的现有合同继续适用。

## 验收

- [ ] AC1（R1、R2）两平台分别用双账号跑纯 API 首轮与带完整历史的下一轮，改变候选负载后核对相同派生值、绑定和实际发送账号。不同开场、不同 Token、不同平台得到独立键。SSE 与普通 JSON 口径一致。
- [ ] AC2（R1、R2）覆盖 Claude 新旧正文会话格式、仅原生会话头、两个入口的可选会话头、显式优先、重复或超界头、空首轮，以及已有 Claude 会话绑定的升级兼容。
- [ ] AC3（R2、R3）覆盖并发首轮、账号暂停和限流、绑定过期或失去路由资格、SQLite 和 PostgreSQL 的原子裁决，以及反重力工具回填与已受理重放。核对竞争失败的候选没有额外模型提交和 RPM 消耗。
- [ ] AC4（R4、R5）核对请求记录 API、SQLite 持久化、列表和详情中原始值、派生值、无值、历史兼容及完整复制。info 与 debug 的展示口径一致。测试使用合成请求。

## 范围之外

- 历史记录回填、其他协议入口、Sub2API 的进程内历史前缀索引与软件发布属于独立工作。
