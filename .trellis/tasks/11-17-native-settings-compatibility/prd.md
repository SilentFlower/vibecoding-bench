# Native 转发系统设置兼容补齐

## Goal

补齐用户选定的五项 native 转发兼容行为，使账号切换、缓存和预热符合系统设置，并准确说明代理连接池的适用范围。

## Background

用户要求新建任务并逐项讨论。五项范围和产品行为已逐项确认，复杂子任务的设计与执行计划已整理。

用户明确后续仅存在 native 转发。本任务以全面使用 native 为产品方向，原有转发作为行为规则参考。两类后端长期共存及跨后端换号退出方案讨论。历史后端退役或账号批量迁移需另行定义范围。

## Requirements

| 编号 | 子任务 | 用户选定范围 | 讨论状态 |
| --- | --- | --- | --- |
| R1 | 11-17-native-fable-429-fallback | Fable 配额切换，补齐所有模型明确 HTTP 429 后的分类、退避和换号流程；同步修复原有转发的 PassThrough 缺口 | 已确认，以原有规则为基准 |
| R2 | 11-17-native-message-cache-policy | messages 缓存断点接入 off／sub2api；默认off，作为缓存问题排查的手动备用策略；设置页仅保留这两项；off 保留布局，sub2api 按原有转发清理 messages 断点并重新选点；首次接入将存量sub2api与废弃模式统一转off；随后手动开启的选择持久保留 | 需求已确认 |
| R3 | 11-17-native-peak-prime-routing | 原生峰值模型预热；进程准备保留环境页展示，峰值预热保留设置页记录；统一预热记录 UI 风格 | 需求已确认 |
| R4 | 11-17-native-disabled-thinking-compat | 接入默认关闭、按模型精确匹配的 thinking.type=disabled 最小改写；使用原生执行体与回环验证，真实上游效果后续核对 | 用户明确无真实样例仍继续适配 |
| R5 | 11-17-proxy-pool-setting-scope | 系统设置页标注 Rust 代理连接池开关适用范围；native 使用自身连接复用机制 | 需求已确认 |

父任务维护原始范围、讨论结论和跨项验收。各子任务负责独立交付和验证。讨论顺序为 R1 → R2 → R3 → R4 → R5，执行依赖由design.md和各子任务implement.md明确。

## Acceptance Criteria

- [x] 五项均形成可观测的验收标准，并逐项记录用户决定。
- [ ] 各子任务完成其独立验证。
- [ ] 综合验证账号切换、缓存策略、预热和日志归属之间的交互。
- [ ] 代理连接池设置准确解释其对 native 模型发送的适用性。

## Out of Scope

其余候选兼容功能作为独立后续工作：Hello 探测、字段顺序指纹、环境透传、上下文规范化、后台分类身份注入及版本选择等。

## 验证前置

各子任务先使用合成凭据、隔离网络和回环上游验证。R4按用户最新决定继续接入，当前以280/293原生构造、实际TLS发送和配置控制验收；真实上游失败及实际兼容效果作为后续验证项，独立记录证据。
