# 控制台 Vue 业务页迁移

## Goal

把各 Vue 业务页换用新组件与第二版视觉，信息结构与业务行为不变。对应父任务 `../11-19-console-ui-revamp/prd.md`的 R7，画面见设计稿 `doc/design/console-v2/mock.html`。

## Requirements

- 账号：卡片字段、顺序、接收请求开关、停用账号与五个操作保持不变；状态条按语义着色；1440×900 下三张卡片操作栏落在首屏内。账号编辑沿用居中弹窗与四个页签，转发方式用单选卡。
- 请求记录：四张概览卡（日志级别从页头移入概览卡，点击切换）；分段、ID 搜索、筛选、查询、刷新收进表格卡片头部；表格每格主值 + 一行辅助值。
- 代理管理：四张概览卡；数据表；延迟与到期按数值着色；行操作检测、编辑、删除。
- 访问令牌：由单行卡片改为数据表（名称、遮蔽令牌 + 复制、可用账号、创建时间、启停开关、操作）。
- 会话封禁：状态改为分段筛选并带计数；时区与刷新周期只在工具栏说明一次。
- 节点管理：四张概览卡；「待检查」改为琥珀色；按钮统一为小号。
- 系统设置：分类导航、两列字段、「已修改」标签；草稿与撤销语义不变（页头与浮动保存栏已由子任务 2 换上）。
- 390px 移动端：分段、单列卡片、账号页搜索入口（应用栏与抽屉导航由子任务 2 提供）。各页的 390 形态随所属批次交付。
- 子任务 2 的概览卡、工具栏、实体卡、数据表卡片、居中弹窗在本任务首次接入真实页面，由各页验收；接入中发现组件接口不足时就地扩展并同步演示页。

## 子任务

按父任务 `implement.md` 的分批顺序拆成三个可单独验收、提交的子任务，依次推进：

| 顺序 | 子任务 | 页面 |
| --- | --- | --- |
| 1 | `../11-20-console-pages-accounts/` | 账号管理（卡片、工具栏、编辑弹窗及账号页其它弹窗、移动端搜索入口） |
| 2 | `../11-20-console-pages-records/` | 请求记录、代理管理、访问令牌、会话封禁 |
| 3 | `../11-20-console-pages-nodes-settings/` | 节点管理、系统设置 |

- 各子任务交付自己页面的 1440×900 与 390×844 形态，并改写或分诊依赖这些页面的验证脚本。
- 第一批为账号页扩展的组件（居中弹窗页签带、应用栏页面操作位），后续批次直接复用。
- 账号卡与设计稿实体卡尺寸不同，不套用 `EntityCard`；实体卡的首个真实使用在第三批的节点管理。
