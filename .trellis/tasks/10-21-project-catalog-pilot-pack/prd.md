# 首批三项目真实场景内容包

## Goal

接入 TinyDB、Jinja、schedule 的真实多场景任务和独立验收，形成覆盖三种新业务领域、可离线运行和模拟验证的首批扩容内容包。

## Background

- 来源为本会话用户同意的“先增加 2～3 个项目，再扩到十项目约 150～200 任务”方案；整体目标见母任务 `../10-21-project-catalog-expansion/prd.md`。
- 当前已上线三仓、十三场景、二十任务；本轮预计新增十三场景、三十七任务，合计六仓、二十六场景、五十七任务。新增数量来自逐项业务问题，不套用每仓二十步。
- 研究来源固定为 TinyDB `edff96aeb2616402e9489d46e90a592c05565621`、Jinja `5ef70112a1ff19c05324ff889dd30405b1002044`、schedule `82a43db1b938d8fdf60103bd41f329e06c8d3651`；许可证分别为 MIT、BSD-3-Clause、MIT。

## Requirements

- R1／真实来源：三仓保留完整固定上游工程和许可／归属；正式 seed 与真实 Git 对象对应，环境、临时文件和私有答案不进入源码快照。详情引用母任务 `research/*-candidates.md`。
- R2／真实任务：TinyDB 拟四场景十二任务，Jinja 拟四场景十二任务，schedule 拟五场景十三任务；每仓覆盖五种类型。重复追问、重试或同一改动的测试／文档不计独立任务。
- R3／合理结论：提供需要请求材料、材料无法提供、无需改代码或使用公开 API 即可解决的实际路径；任务不预设必须找到库缺陷。信息不足是业务结果，不把冻结文件丢失当成正常材料不足。
- R4／工程目标：每仓两项窄范围修改，共六项。TinyDB 为 fragment 查询缓存和一次性批量规则；Jinja 为 Mapping URL 编码和显式 None 的 map 默认值；schedule 为 run_all 尾部多余延迟和默认未配置 Job 的 repr。逐项明确现状、允许路径、兼容边界及独立正常／反例，不改变固定 seed 预先修好问题。
- R5／程序与语义：工程任务必须通过独立原生业务及冻结的完整适用上游回归，不能由语义 pass 覆盖失败；问答／诊断／方案使用事实证据及必要可执行示例，原生事实不冒充文字质量。
- R6／材料和依赖：公开业务材料与隐藏披露／rubric 分离；只声明真正同场景 answer/code 依赖。只读任务不接受源码检查点，未接受修改不进入后续无依赖任务基线。
- R7／语言：新首问、材料说明、分支条件和评审规则为英文；页面标题、分类、简介及场景／任务目标为中文。原始代码、报错和用户业务值原样保留。
- R8／离线准入：在本轮采用的正式 account 镜像固定 Python 精确版本、依赖版本及 wheel SHA；分别实测业务和回归资源。运行时无外网、无账号凭据、不增加现有账号资源。
- R9／版本与兼容：产生新 catalog 版本和实际重算的 digest，旧三项目内容、原任务 ID 和历史发布／成果保持原样。新的目录数量、公开摘要和历史 reader 都有对应回归。
- R10／机制验证：用隔离空库、合成账号和 mock CLI 运行新增所有默认任务，并覆盖所有会改变物料或合法结果的非默认入口／披露路径；核候选消费、语义评审、原生验收、页面/API/DB 状态、尝试与用量，真实模型调用为零。
- R11／可信回归适配：新增三仓的原生集合和 Jinja src 布局支持；保留旧三仓默认行为。原版测试、配置、插件和节点合同来自控制端，证明实际导入候选，不允许安装库或删测试替代。
- R12／交付统计：分别记录候选研究、内容准入、模拟机制、真实模型和生产部署。当前只交付本地内容包与验证证据，不能以研究或模拟通过宣称已经上线。

## Acceptance Criteria

- [x] AC1（R1、R2、R9）：静态加载新目录得到六个唯一上游项目、二十六场景、五十七稳定任务；三仓新增内容可追溯到真实来源和逐项业务表，旧三仓内容树摘要不变。
- [x] AC2（R2～R4、R6）：三十七项任务覆盖五类型、信息不足和无需改动结论，正常披露不多算任务或业务尝试；六项工程目标全部在原版可复现并有明确授权。
- [x] AC3（R4、R5、R8、R11）：六项原版预期失败、私有参考候选通过且正常／反例均可执行；每仓当前目标镜像的上游完整适用集合已校准并实际回归，记录结果、跳过和资源，不复用历史计数冒充本轮运行。
- [x] AC4（R5、R6、R10）：所有默认任务及改变实际材料／结论的合法分支通过隔离模拟，源码导入、代码接受、预算和角色分列计量可对账；模拟回答不作为真实质量证据。
- [x] AC5（R7、R9、R10）：英文指令／中文公开投影逐项核对，隐藏 rubric／答案无公开泄漏；新旧内容 install／历史读取、桌面及 390px 页面／API／SQLite 一致。
- [x] AC6（R1、R8、R9、R12）：Git 导出内容全集、逐文件 SHA、catalog digest 和镜像构建上下文一致，源码不含依赖环境、临时凭据或参考修复；输出本地准入和机制报告并正确标识真实模型／生产未验证。

## Non-Goals

- 不一次完成十项目或强行凑到 150～200 任务；后续波次由母任务管理。
- 不修改平台调度、计时、数据库 schema、账号身份、OAuth 或 API/UI 结构，不引入第二评审模型。
- 不自动提交、推送、发布镜像或部署，不读写生产数据，不启用停用账号。
- 不把旧路线的全部增强实现到原版，也不向上游提交 issue／PR 或发送消息。
