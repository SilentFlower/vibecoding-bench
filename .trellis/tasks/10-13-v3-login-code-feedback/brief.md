# Brief — v3 授权码输入反馈与登录恢复

## Goal

- 让授权码能够可靠输入、看到发送结果，并恢复清理失败的未提交草稿。

## Scope

- 独立授权码输入框：支持打字、粘贴、显示/隐藏、长度提示和“发送到 CLI”。
- 发送状态反馈、重复提交保护，以及草稿“恢复检查”入口。
- 补齐草稿代理展示，固化已有焦点与输入提示修正。

## Non-Goals

- 不修改官方 CLI 回显、OAuth 交换或 cc2api 上游处理；Recorder 底层故障治理延后；不重复令牌迁移、不操作真实账号数据，旧服务继续运行。

## Technical Overview

- 输入框通过独立 HTTP 请求，把授权码送进账号原容器的原 tmux；终端显示输出，发送回执与认证检查分别反馈结果。
- 草稿恢复核对环境归属与代次后复用既有对账流程，释放旧会话占用并保留 HOME 和授权产物；代理只展示协议、主机、端口。

## Context & Decisions

- 已证实真实 CLI 隐藏授权码回显，但用户浏览器每次输入是否送达仍不能仅凭终端画面判断。
- “已发送”不等于“登录成功”；结果未知时只查询回执，不自动重发。授权码不进入日志、命令参数或持久缓存。
- v3 授权码改用独立输入框，终端只显示输出；旧版登录、续聊保留交互输入。归属冲突、忙碌或保存中的草稿继续受保护。

## Risks

- 投递后回包丢失可能只能显示结果未知；真实 OAuth 成功流程仍需实际账号验证。
- 草稿恢复解决可操作性，当前证据不足以确定 Recorder 清理失败的底层根因。

## Acceptance

- 真实浏览器验证键盘、粘贴、Enter、按钮，以及窄屏和明暗主题；真实 CLI 禁网实验确认收到输入。
- 超时、重复提交、非法输入、过期会话反馈准确且不泄漏授权码。
- 草稿可安全恢复、代理脱敏可见；HOME/身份不变，新代次与正式历史受保护。
- 关联重授权、凭据同步、保存/删除、终端重连及旧版输入回归通过。

## Next Step

- 确认后先实现并验证原 tmux 的授权码投递与回执，再接入页面。
