# v3 授权码输入反馈与登录恢复

## Goal

让用户能够可靠输入授权码、判断发送与登录结果，并恢复清理失败但归属明确的未提交账号草稿。

## Background

- 用户报告点击终端后打字、Ctrl+V、右键粘贴均没有可见反馈；草稿 10-13 还出现代理不显示和“需检查 / 对账”时无法操作的问题。
- P1：真实 Claude Code CLI 2.1.293 在授权提示处关闭回显。隔离、禁网的真实二进制实验确认，无效测试码会触发 CLI 校验错误；这证明隐藏回显存在，不能据此推断用户浏览器的每次输入均已送达。证据见 `research/evidence.md`。
- P1：终端容器内边距点击存在焦点缺口，已有未提交焦点修正与提示；本任务将其纳入验证并固化。入口：`webui/app.js:770`、`webui/index.html:518`。
- P1：清理中的网络上下文恢复失败会隔离环境并保留执行证明；现有会话对账收口仅覆盖关联重授权上下文，未绑定草稿可能仍占用名称。入口：`orchestrator/account_runtime.py:807`、`orchestrator/main.py:5061`。尚未证明网络恢复失败的底层原因。
- P2：草稿行合并了代理所在列，已有代理配置未在该行显示。入口：`webui/app.js:229`。

## Requirements

### R1 — 可见的授权码输入

- v3 登录窗口增加独立授权码输入框，默认隐藏内容，可切换显示，并展示输入长度；支持键盘、Ctrl+V、浏览器右键粘贴。
- 通过“发送到 CLI”按钮或 Enter 提交一次完整授权码，仍由账号原环境内的真实 CLI 完成登录。
- v3 授权终端负责显示 CLI 输出；授权码输入不依赖终端回显。旧版登录与续聊的交互输入保持可用。
- 输入为空、会话结束、提交保存中或请求尚在发送时，禁止再次发送；关闭窗口后清除授权码及输入相关监听。

### R2 — 真实的发送反馈

- 界面明确区分未发送、发送中、已送到 CLI、结果未知、发送被拒绝和认证通过；“已送到 CLI”不能显示成“登录成功”。
- 发送请求结果丢失或超时时，提供查询该次结果的行为，不能自动重发授权码。相同请求标识不得再次注入 CLI。
- 非法授权码、失效会话或过期草稿必须给出可见说明；错误信息不含授权码。
- 输入框与原 CLI 之间的提交路径不依赖终端 WebSocket 是否连接，仍核对原会话和环境归属；连接中断不得伪造成功反馈。

### R3 — 未提交草稿的受控对账恢复

- 对归属及代次可验证、没有活动作业或未知提交的草稿，提供“恢复检查”入口。恢复完成后重新显示可用的继续、重新登录或删除操作。
- 对账收口同一旧会话的内存占用，避免恢复后仍提示同名登录进行中；不得误清新代次会话。
- 损坏元数据、归属冲突、占用中及保存中仍拒绝快捷恢复，并提供查看环境的诊断入口。
- 对账保留账号环境、HOME、CLI 缓存和未提交授权产物；只有既有“删除草稿”流程执行完整删除。

### R4 — 草稿代理展示

- 草稿行显示已核对的代理协议、主机和端口；用户名、密码及其他秘密不出现在列表响应或页面中。
- 配置未知和明确未配置必须区分，不能把读取失败显示为直连。

### R5 — 兼容与原数据保护

- 延续原环境、原 SID/tmux 和登录代次约束；保留关联重授权、凭据同步、提交保存及取消保护。
- 草稿不得混入正式账号列表和任务、养号的账号选择。
- 旧服务继续运行；本任务验证使用隔离测试数据，不取消、重登、删除用户真实草稿或改动正式账号历史。

### R6 — 授权码隐私

- 授权码仅用于当前输入和投递，不进入日志、命令参数、持久化文件、浏览器缓存或错误响应。
- 发送回执只记录请求标识与状态；不增加本地伪造的授权码终端回显，也不修改官方 CLI 回显模式。

## Acceptance Criteria

- [ ] A1（R1、R6）：真实 Chrome 中键盘、Ctrl+V/右键粘贴对应的原生输入路径、显示切换、长度反馈、按钮和 Enter 可用；桌面及窄屏、明暗主题可操作，关窗清除输入。
- [ ] A2（R1、R2、R5）：隔离浏览器请求进入原账号环境的同一 SID/tmux；真实 CLI 2.1.293 禁网实验收到无效码并校验。合成成功链另行证明认证通过和提交行为，不冒称完成真实 OAuth 登录。
- [ ] A3（R2、R6）：空码、控制字符、超长、过期 SID、并发点击、同请求重复发送及回包丢失均得到准确反馈；重复请求只投递一次，未知结果不自动补发，错误与日志不泄漏测试秘密。
- [ ] A4（R3、R5）：清理失败后安全对账恢复未绑定草稿并释放旧名称占用；活动作业、未知提交、坏元数据、归属冲突及新代次仍受保护，HOME/身份与正式账号历史不变。
- [ ] A5（R4、R6）：已有代理的草稿在 JSON 和页面显示脱敏地址；读取失败显示未知，响应和 DOM 不出现代理认证信息。
- [ ] A6（R5）：原关联重授权、同 SID 终端重连、凭据同步、首次保存/完整删除、旧版登录与续聊回归通过。

## Out of Scope

- 不自行交换 OAuth code、不改变 cc2api 上游请求/TLS 处理、不强制开启官方 CLI 回显。
- 网络 Recorder 的 PID/重启超时底层治理延后，当前证据不足以确定根因；本轮提供受控恢复入口，不承诺消除所有清理失败。
- 不重复已完成的旧服务 API 令牌复制，不搬迁真实账号凭据，不停旧服务。
- 创建任务时已存在的无关捕获规范与两个旧任务记录保留，不纳入本轮提交。
