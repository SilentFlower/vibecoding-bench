# v3 环境面板、当地运行窗口及额度阈值调整

## Goal

让用户在 v3 后台查看环境物理特征、按账号当地时间安排任务，并让运行窗口和自设额度阈值都在本轮完成后阻止下一轮。

## Background

以下代码位置与“当前”行为均为实施前 `7d705e3` 的取证基线；本轮实现按下述已确认需求调整。

- 原始需求：“物理特征面板”“账号当地时间的运行窗口”“这个我们去优化一下。另外可不可以控制下当地可运行时间段？”
- 补充决定：“本轮完成再休息”“之前硬性的超过阈值也改回来……直接 stop 任务……没必要”。此次明确增加额度阈值行为调整，更新本任务范围并新增 P3 子任务，不重新打开已经关闭的旧强停任务。
- 当前环境卡片只展示基础指纹、角色和维护状态：`webui/app.js:83`；环境列表返回固化指纹：`orchestrator/main.py:11196`。
- v3 已有环境时区优先于账号表配置；页面展示不能创建环境：`orchestrator/main.py:2696`。
- 现有普通任务、批次、定时养号及交互续聊入口不同，不能只在前端限制按钮：`orchestrator/main.py:6173`、`:6212`、`:7047`、`:10766`。
- 当前运行中阈值强停入口是 `Scheduler._enforce_running_quota`：`orchestrator/main.py:6515`、`:6793`；v3 普通任务和养号使用 passthrough，见 `orchestrator/account_runtime.py:1244`、`:1270`。

## Task Map

| 交付 | 子任务 | 独立验收 |
| --- | --- | --- |
| P1 物理特征面板 | `../10-20-v3-environment-physical-features/` | 展示完整特征，配置与实测来源及时间清楚，读取不改变身份或生命周期 |
| P2 当地可运行窗口 | `../10-20-v3-account-local-run-windows/` | 账号独立配置，按有效时区执行，窗口状态及下次开放时间可见 |
| P3 额度阈值在本轮完成后等待 | `../10-20-v3-quota-graceful-completion/` | 达到自设阈值不终止当前轮次，下一轮仍受门禁，真实耗尽与认证保护有效 |

父任务负责原始需求、范围决策和最终集成验收；子任务分别规划、实现和检查，不启动父任务承担子任务代码。

## Requirements

- R1：优化物理特征面板，展示截图同类字段，区分持久配置与容器实际观察，显示采集时间及未采集状态，由 P1 负责。
- R2：展示账号有效时区及当地当前时间，使用环境中已固化的时区，由 P2 负责；两处页面的时区口径必须一致。
- R3：支持账号独立设置当地可运行时间段，配置在控制端重启、环境重建后保留，由 P2 负责。
- R4：窗口状态必须在服务端执行；已开始的本轮正常完成，窗口外不启动新一轮或发送新的交互续聊输入；页面解释等待原因及下次允许时间，由 P2 负责。
- R5：保留持久身份、HOME、凭据、绑定、真实额度耗尽及认证门禁；时间窗口与阈值调整不能改写身份或绕过其它拒绝条件，由三个子任务共同负责。
- R6：v3 普通任务（含批次）和养号达到自设 5h/7d 百分比阈值时不再直接 STOP，也不提前注入阈值收尾；本轮按原任务计划和超时正常完成，后续轮次等待，由 P3 负责。

## Scope

以下整体范围已通过统一 Brief 确认；本轮完成语义由用户明确选择：

- 账号可以启用或关闭窗口限制；支持星期、每日多个区间及跨午夜区间，遵循 IANA 时区的夏令时变化。
- 未启用窗口的既有账号继续全天可运行，不批量替用户启用默认作息。
- 时间限制覆盖本平台发起的普通任务、批次、养号、抓包与新续聊；已关联的对外 API 转发、登录、OAuth 维护和手动额度查询暂不纳入。
- 物理特征面板增加按需只读采集；停止或正在维护的环境显示保存配置、上次观察或未采集，不为展示唤醒或重建环境。
- 父任务集成时复用同一有效时区和窗口摘要；各子任务的验收互不依赖隐式数据库改动。
- 普通任务/养号的“本轮”是已经启动的一个 run，包含其原定补充及收尾；交互续聊已经发出的回合可完成，之后的新输入受窗口限制。
- P3 先交付，随后 P1，再完成依赖 P3 的 P2，最后核对两个门禁的组合行为。已完成或历史停止的 run 不重写、不自动复活。

## Context & Decisions

- D1（用户明确）：到当地运行窗口结束时，本轮完成再休息。
- D2（用户明确）：撤销自设百分比阈值触发的运行中强停，恢复只限制下一轮。
- D3（边界）：窗口和自设百分比都可能在本轮完成前被跨过，页面准确说明；上游真实限流、额度耗尽、认证错误、用户停止及原超时仍按原流程处理。
- D4（兼容）：既有账号默认不启用时间限制；原阈值数值及关闭状态不改，现有被动观察和单次恢复许可继续使用。

## Acceptance Criteria

- [x] AC1（R1/P1）：能查看 CPU、内核、操作系统、架构、资源、MAC、DMI、时区及工具信息，并明确来源、采集时刻和缺失项。
- [x] AC2（R2/P2）：账号页及环境页显示相同有效时区，当地时间正确，参考时间可换算为北京时间。
- [x] AC3（R3/P2）：不同账号的时段配置互不影响，重启和重建后仍保留。
- [x] AC4（R4/P2）：窗口关闭后已启动的一轮完整执行，下一轮等待；跨日、周切换、夏令时及所有纳入范围的入口一致。
- [x] AC5（R5/P1/P2/P3）：观察与配置不旋转指纹，不改变 HOME、凭据、绑定或真实耗尽及认证门禁。
- [x] AC6（R6/P3）：普通任务与养号在 5h/7d 等于或跨过自设阈值后完成原轮次；状态来自实际退出，下一轮在门禁解除前不启动。
- [x] AC7（R3/R4/R6/P2/P3）：窗口与阈值同时阻塞时必须全部满足才开始下一轮；服务重启及配置更新不绕过门禁、不重复投放。

## Out Of Scope

- 代理出口自动改时区、随机作息、KVM、指纹重新生成及封号原因判定。
- 将先前发现的失效账号 OAuth 后台门禁收口混入本任务。
- 本轮规划不包含生产发布操作。
