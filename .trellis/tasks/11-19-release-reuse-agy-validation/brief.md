# Brief — 复用可信候选的反重力镜像验收

## Goal

- 让同一套反重力镜像在构建和正式发布之间只做一次完整实测，缩短版本可安装的等待。

## Scope

- 调整正式发布工作流的反重力验收执行条件，补齐候选来源、失败回退和发布门禁回归，并同步发行规范。

## Non-Goals

- 旧库演练提前、镜像并行构建、候选传输优化和生产安装留待独立工作。

## Technical Overview

- 构建侧实测通过后导出候选。发布侧核对同一源码、同一构建 attempt、归档摘要、镜像文件层及运行配置，成功换批后复用构建侧的验收结果。完整构建在发布侧实测。

## Context & Decisions

- v1.19.0 和 v1.19.1 发布侧的重复验收各实测用时 169 秒。本次以这段耗时为提速目标，收益以新发行实测为准。
- **【关键决定】沿用现有候选证明。候选构建已要求反重力验收成功，发布换批只允许修改发行标签。**
- **【重要限制】候选缺失或显式完整构建会运行完整验收。已选候选的来源、摘要或镜像内容有变化时，发布会停止。**

## Risks

- 真实 Docker 换批夹具目前缺少 AGY 能力标签，测试会在校验阶段终止。此次先补齐夹具标签，再实际验证镜像的文件层和配置。

## Acceptance

- 可信候选进入旧库兼容演练前跳过重复探针，缺少或未通过原验收的候选无法触发复用。
- 完整构建路径仍执行真实探针。正反向工作流回归核对签名、兼容演练、镜像验证与发布步骤。

## Next Step

- 开始修改发布侧验收条件并补充工作流回归。
