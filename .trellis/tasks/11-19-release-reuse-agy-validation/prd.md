# 复用可信候选的反重力镜像验收

## Goal

减少同源码候选的正式发布耗时，让反重力镜像实测在完整交付链路中只执行一次。

## Background

- 用户要求优化正式发版速度。v1.19.0 的发布运行 44493364485 在候选复用后再次验收反重力镜像，用时 169 秒。构建运行 44511173730 的同类验收实测为 168 秒。 本轮 v1.19.1 的发布运行 44513301635 再次实测 169 秒。
- `deploy/flower2api/candidate_artifacts.py:21` 已把反重力镜像验收列为候选必需步骤。`deploy/flower2api/candidate_images.py:156` 复核换批后的镜像层、平台和所有运行配置，只允许变更批次标签。
- `.github/workflows/v3-release.yml` 现有路径总会实测。已触发的 v1.19.1 发布采用其冻结源码和原发布合同。
- 开启真实 Docker 回归时，现有换批测试在 `test_system_candidate_build.py:314` 被镜像标签检查拒绝。合成镜像声明 AGY 能力却未设置全部现有能力标签。

## Requirements

- R1：成功复用同源码、同构建 attempt 的可信候选时，正式发布采用其已经通过的反重力实测结果。
- R2：无合格候选及显式完整构建仍必须构建并验收真实镜像。来源、内容或换批核验异常继续阻断发布。
- R3：签名预检、镜像身份核验、旧库兼容演练、正式受信目录和发布授权继续使用现有门禁。
- R4：更新发布规范和正反向回归，记录构建与发布分段耗时，区分历史实测和本次预计收益。

## Acceptance Criteria

- AC1 / R1：可信候选的同一 attempt 中反重力验收成功，且归档和换批核验通过时，构建侧完成实测，发布侧跳过重复实测并继续真实旧库演练。
- AC2 / R2：候选实测缺失、跳过或失败均不可复用，普通缺失和手动完整构建走实际验收。来源或摘要漂移保持失败关闭。
- AC3 / R3：签名、真实旧库、镜像身份和最终发布的原条件均通过工作流回归核对。
- AC4 / R4：验证日志能识别候选复用与完整构建路径，约 169 秒为历史基线推算的目标收益，正式新耗时以未来实际发行记录为准。

## Out of Scope

- 旧库演练提前、镜像并行构建、候选归档传输优化及任何线上安装操作。
