# 反重力镜像验收复用设计

## 复用条件

构建在同一个可信作业内按顺序构建镜像、运行 `verify_agy_images.py`、导出和上传候选。候选解析器已从 GitHub 的原 attempt 作业读取必需步骤，并要求反重力验收完成且结论为 success。它还核对仓库、分支、源码 SHA、归档 ID、归档摘要及解包文件。候选加载后由 `inspect_images` 校验镜像身份。

`adopt_candidate` 在发布侧换批。候选 RootFS、平台和运行配置逐项匹配，唯一许可变更为 `vibebench.release` 标签。镜像验收的模块、二进制、断网容器及进程生命周期依赖这些镜像内容。批次标签的匹配继续由换批后的 `inspect_images` 验证。该链路提供足够证据，无需新增归档协议。

## 执行路径

- 构建侧继续无条件执行镜像验收。导出要求成功，并核对同一清单和镜像。
- 发布侧镜像验收和现有完整构建使用同一条件 `steps.candidate.outputs.reused != 'true'`。解析器仅在全部核验与换批完成后输出 `reused=true`。
- 明确完整构建、旧候选缺必需步骤、失败候选或过期候选由原逻辑回到真实构建和实际验收。已选候选出现摘要、来源、内容或配置变化时保持失败关闭。
- 真实旧库兼容演练、正式镜像发布以及签名目录推进全部沿原有路径。发布工作流权限、产物字段和运行镜像不引入新依赖。

## 验证与恢复

基于真实工作流 YAML 断言两条路径。现有候选解析测试补足验收步骤的失败、跳过、缺失和完整构建回退。真实 Docker 测试核对镜像换批等价及归属。按现行镜像合同给原 scratch 测试镜像补齐 AGY 能力和账号源摘要标签，使夹具走到实际换批；生产的镜像身份验证保持原条件。必要时使用 `full_build=true` 恢复每次发布都执行本次实测的路径。已触发的 v1.19.1 发布和更新目录由既有发行流程核验。
