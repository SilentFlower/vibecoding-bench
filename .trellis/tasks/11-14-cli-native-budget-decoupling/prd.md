## Goal

账号选择原生 API 运行时后，任务和养号 CLI 能按已有资源独立准备，保留原目标进度，并将修复发布为v1.6.2。

## Requirements

- R1：明确区分CLI/管理准备与API发送器准备。选择native293且sender预算缺失或不足时，已有基础环境及首次环境仍能准备CLI；沿实际已生效布局计算CLI资源。
- R2：CLI入口不因目标sender差异重建正在使用的发送器，保留原角色资源、环境身份和正在运行的API。首次基础布局必须保持三角色隔离、账号总预算及CLI最低额度。
- R3：API transport、显式原生预热及后台原生启动继续检查权威后端、目标预算和并发，资源不满足时明确拒绝；目标原生的请求不得转成legacy业务发送。目标选择与实际能力继续独立展示。
- R4：普通任务、养号/项目、交互/登录、额度查询和CLI身份/指标准备按各自执行职责使用正确入口；认证归属、代理、维护、孤儿对账及串行评审资源交接保留。
- R5：受控预算故障显示固定可操作原因；未知启动结果仍保留原人工核对与唯一投递保护。既有11-14失败经人工启动先零模型准备当前环境，再按原现场证据核验续原work/session，保留已通过记录；自动调度保持原未知启动阻塞。
- R6：修复、定向与全量验证、规范同步和精确提交完成后，沿手动发布SOP发布v1.6.2修复版本并核验镜像、发行附件和签名目录。
