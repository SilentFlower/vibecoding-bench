# 设计

## 从 CC runtime 对照到 AGY

| 关注点 | CC runtime | AGY 本次处理 |
| --- | --- | --- |
| 运行身份 | 账号配置及凭据决定池，模型随请求传入 | 监督器只按实际启动条件与凭据身份取 worker，模型进入单次作业 |
| 空闲热进程 | 每个账号保留一个基础热进程，额外空闲进程默认保留 120 秒 | 保留一个最近使用且仍有效的空闲热进程，额外进程空闲 120 秒后回收 |
| 模板可用时间 | 模板登记与空闲 worker 的回收分开 | 维护一个同账号启动模板，模板寿命依据环境和凭据 |
| 模板恢复 | CC 可以从登记模板恢复独立副本 | AGY 当前按原观察器 PID 和管道恢复。消费后归还模板名额，空余容量内重建零业务快照 |
| 观察口径 | 恢复或新建更新来源，热命中复用已有进程 | 记录实际获取与恢复，网关接纳并持久化允许的启动来源 |

## 请求级模型选择

1. 网关和 Rust 发送器已有 `AgySubmission.model` 和 `native_model`，继续沿真实目录、账号和截止校验。Python 监督器将同一对值作为内部 `gemini_request` 的模型选择。公开正文不提供覆盖原生 ID 的入口。
2. 受管内核启动时只绑定凭据、代理、采集环境与固定执行体。`Scope` 持有本轮值，`StartCascade.requestedModel`、`plannerConfig.planModel` 和历史实体所需的原生模型来自该上下文。避免通过修改模块级 `MODEL`、`GEMINI_MODEL` 或共享能力字典实现复用。独立内核现有固定模型启动配置兼容原私有调用；缺失、非法或互相矛盾的选择在产生 RPC 之前拒绝。
3. 监督器按当前账号环境、凭据代次及 AT 摘要、代理及实际影响启动的采集配置选进程。先找相同身份的热进程，再选择相同身份的零业务快照。现有采集条件影响启动时 TLS 观察能力，故仍按生效配置区分。可用容量和旧代清理以现有物理池门禁为准。
4. 原工具等待 worker 保持独占。按已有令牌、请求、历史及函数 identity 找到原轮，在其原模型上下文完成回填。该轮收口后，新业务才接收已准入模型和凭据。回环验收校对实际执行 ID、同一 PID 与各轮原生发送次数。

## 快照与进程的寿命

- 保持 AGY 自有 CRIU 入口的受信角色、实际父监督器目录、进程身份、同 PID 与 FD 校验。模板占位覆盖保存、停放和消费恢复的临界区。成功交接后允许下一份模板，同时保留恢复连接的 worker 退出责任。异常或断开沿原 pidfd 按实际身份清理。
- 监督器在恢复成功时清除已消费的模板标记。可用空位内继续沿既有后台预热入口补位，沿实际请求的截止与凭据，禁止从已接过业务的进程保存模板。上限为 1 或资源满时，同一时刻仍只能按现有物理名额运行。
- 在每个账号的监督器中，最近使用且仍有效的空闲热进程作为基础热进程保留。其余热进程从归还池起空闲满 120 秒后回收。等待工具和正在执行业务的进程保持独占。已就绪模板凭据失效或环境退出时清理。主动换代时拒绝旧代新业务且回收空闲旧代，等待旧活动真实结束。已有恢复失败的原截止和单次模型发送边界保持强制。

## 观测与交付

- 同一请求的 `warm_hit`、`start_source`、阶段耗时分别表达是否复用、进程由何种方式启动、实际获取成本。原生恢复和其失败回退时间纳入获取进程，使用已有诊断记录。`start_source` 仅接纳 `exec` 和 `criu_restore`，老记录缺省代表未知。已有环境 CRIU 状态字段继续读取实际模板、准备和失败。
- CRIU 镜像内源码来自现有镜像发布路径。若控制器变更，两份 `agy.py` 与源摘要清单同步。隔离验收使用正式绑定布局和固定执行体，保留当前容器安全限制与回环测试信任根。
- `v3_environments` 请求网关账号分页时指定 `platform=antigravity`，按已核验账号 ID 投影 `gateway_account_name`。卡片与详情沿现有 `environmentName` 优先展示该字段。其他调用仍沿网关默认筛选，环境原名 `agy:<gateway-id>` 用于现有归属及缺省显示。
