# Brief — 对齐 CC runtime 的 AGY 跨模型复用与 CRIU 加速

## Goal

- 同一 AGY 账号切换已授权模型时可以复用热进程和 CRIU 模板，并能看到实际启动来源。

## Scope

- AGY 的请求模型绑定、进程池、模板回收与补位、请求诊断和运行环境卡片的账号名称。

## Non-Goals

- 本轮交付范围是代码和隔离环境验收。正式上线与节点镜像沿独立流程。

## Technical Overview

- 网关校验并传入本轮模型。内核用该模型构造实际 RPC，监督器按账号运行身份选进程。工具结果回到原请求完成。

## Context & Decisions

- **【关键决定】复用 CC runtime 的设计。模型随请求选择。进程和快照按环境、凭据和实际启动配置复用。**
- **【关键决定】每个账号保留一个最近使用且仍有效的空闲热进程。额外热进程空闲 120 秒后回收。** 模板按凭据和环境有效期保留，恢复消费后有空位就补下一份。
- **【关键决定】记录真实启动来源。** 网关当前丢掉包含 `start_source` 的运行诊断，修复后保留进程、耗时和恢复信息。

## Risks

- **【重要限制】模板补位受账号物理容量约束。** 并发上限为 1 或已满时，等待槽位可用。恢复失败在原截止内回退，模型请求只投递一次。

## Acceptance

- 同一进程交替处理两种实际模型。一个模型准备的快照供另一模型恢复。恢复进程仍在线时可补下一份模板。
- 从正常入口核对模型、PID 和启动来源。工具续轮、凭据换代、启动失败与旧入口回归通过。
- 同一账号连续两批请求可在 120 秒内复用额外热进程。额外进程到期后保留一个有效的基础热进程。
- 反重力环境卡片与详情展示绑定的网关账号名称，环境 ID 和账号编号保持原归属。

## Next Step

- 先把模型从受管内核启动配置移到每次请求，再接通共享池的验收。
