# 对齐 CC runtime 的 AGY 跨模型复用与 CRIU 加速

## 目标

同一反重力账号切换已授权模型时，能复用已有热进程或当前账号的启动快照，用户可从环境状态和请求记录核实实际路径。

## 要求

- **R1 跨模型复用。** CC runtime 的池身份来自账号配置及凭据，模型随请求进入原生作业（`services/gateway/src/service/native_runtime.rs:257`、`services/runtime/src/runtime/293/job.ts:184`）。AGY 现在把模型写进池键和内核全局变量（`services/orchestrator/agy_runtime/supervisor.py:348`、`services/orchestrator/agy_runtime/kernel.py:370`）。将模型改为每次请求的独立选择，继续使用网关从账号真实目录冻结的公开名及执行 ID。保留账号、环境、凭据代次、代理及实际进程启动配置的归属边界。
- **R2 快照可持续补位。** AGY 控制器在恢复成功后仍持有模板锁到连接关闭，监督器也保留已消费 worker 的 seed 标记（`services/runtime/native/criu/agy.py:129`、`:209`，`services/orchestrator/agy_runtime/supervisor.py:167`、`:468`）。恢复后释放模板名额。每个账号保留一个最近使用且仍有效的空闲热进程，额外热进程空闲 120 秒后回收。未消费的快照保留到凭据到期、换代、配置变更或受控退役。热进程和模板准备共用既有物理容量。
- **R3 实际来源可追踪。** Rust 的诊断结构拒绝 AGY 发送的 `start_source`，会丢掉整段本地阶段记录（`services/gateway/src/model/request_diagnostics.rs:112`、`services/gateway/src/service/diagnostics/agy.rs:155`）。恢复耗时归入获取进程，环境的最近扩容只由真实启动或恢复更新。每笔请求保留热命中与进程来源，历史记录允许字段缺省。
- **R4 保留请求归属。** 工具回填始终交给原请求和原进程。凭据换代后原工具轮仍可收口，新轮使用当前有效凭据。保存或恢复失败在原请求截止内回退，模型业务仅提交一次。
- **R5 运行环境显示账号名称。** 反重力环境卡片及详情显示当前绑定的网关账号名称。名称暂不可用时保留环境原标识，账号编号、环境 ID、代次及维护归属继续使用既有数据。

## 验收标准

- [ ] **R1** 同一账号通过正常入口交替请求两个原生执行 ID。传到两个原生 RPC 的模型与各自授权映射吻合，无需更换热进程。给一个模型准备的零业务快照可用于该身份下的另一模型。覆盖 Gemini 和已有 Claude 到 AGY 的业务入口。
- [ ] **R2** 固定执行体真实保存和恢复。恢复进程仍在线时，账号有空余物理名额即可补成下一份快照。额外空闲热进程在 120 秒内可复用，到期后保留一个有效基础热进程。快照经过额外进程的回收期限仍可恢复。并发上限为 1 或暂时满载时始终守住现有名额。
- [ ] **R3** 请求详情出现实际进程、获取进程阶段与启动来源。普通热复用不会改写环境的最近扩容。无模板正常等待、模板准备、模板就绪和失败可分别观察。
- [ ] **R4** 隔离回环核对工具续轮的原模型和调用归属、两代凭据、恢复失败回退及实际模型调用计数。旧配置的独立内核入口及 CC runtime 行为回归通过。
- [ ] **R5** 环境列表能读到反重力账号的当前名称，覆盖分页、错平台和网关失败。浏览器核对卡片和详情展示真实账号名。

## 交付边界

实现、回归和真实进程隔离验收属于本任务。US #14 的现场试用沿现有受控发送器入口。正式发布和节点镜像核验沿独立流程。
