# 旧包清理实施顺序

1. 读取当前材料、平台部署规范、官方包API和身份定义；保存精确工作区基线。
2. 在合成API中建立白名单、保护集、权限、404、归属、版本漂移与部分失败回归。
3. 实现默认预览的维护脚本及受信手动Actions入口，关闭旧三镜像发布入口；更新最小相关合同。
4. 运行单测、Python语法、actionlint和当前构建/手动发行合同回归；完成Check-All与Update-Spec。
5. 展示并执行精确Git计划，默认main只同步工作流注册/退役所需文件。
6. 使用仓库临时令牌执行实际预览；核对三个包ID、全部版本、关联仓库、源SHA及旧发布/部署引用，冻结计划。
7. 按用户已授权的三项范围应用并逐项复查，保存安全收据；权限或身份问题报告实际失败并停止写入。
8. 同步最终进度与Close，交接后继镜像名称迁移子任务。外部操作未完成时保持partial。
