# Brief — 升级 cc2api 与 vibecoding-bench 到 Claude Code 2.1.260

## Goal

- 先全量升级并发布 bench 2.1.260，完成真实抓包后再适配和发布 cc2api，并保留
  2.1.257 旧镜像、数据库备份与版本协调记录。

## Scope

- 四个子任务依次负责：bench 运行时/版本快照/生产发布、2.1.260 抓包证据、cc2api
  协议画像、cc2api 发布与跨项目验收。
- 修复抓包 run 继续对话时因全局设置变化而切换 CLI 版本的问题。

## Non-Goals

- 抓包前不猜测 2.1.260 的 CCH、beta、模型子画像或新增协议。
- 不改变默认模型、1M、配额、代理或 OAuth 所有权，不提交原始抓包和生产凭据。

## Key Decisions

- bench 不做隔离双版本，第一阶段全部生产默认 worker 切换到 2.1.260。
- 每个 run 创建时持久化 Claude Code 版本快照；初始运行和继续对话始终复用该版本。
- bench 先独立发布并供用户抓包；cc2api 保持 2.1.257，待证据完成后再升级。
- Opus、Sonnet、Fable 5.1、Haiku分别取证；实际仍出现 Fable 5 时追加独立样本。
- 2026-09-05 用户确认本次不做完整联合回滚演练，保留未执行说明并取消该收尾阻塞；
  不追加模型测试或生产操作，不把未演练写成通过。

## Key Context

- 规划时 bench 与 cc2api 默认均为 2.1.257；现有部署结果已记录为 2.1.260。
- 规划时 `runs` 没有版本字段，初始 worker 和 continue worker 都重新读取全局版本，
  这是已修复的版本漂移根因。
- bench 模型请求直连 Anthropic，cc2api 绑定只负责凭据同步，允许 bench 先行升级。

## Risks / Deferred

- 历史 run 没有原始版本证据，只能首次继续时按当前有效版本回退并固定快照。
- cc2api 的实际协议差异延期到用户提供 2.1.260 run 后判定。

## Acceptance

- bench 所有 worker 默认 2.1.260 并完成生产发布；旧 run 继续复用自身版本，新 run
  使用创建时版本。
- 抓包形成可复算、脱敏的协议证据；cc2api 新画像和迁移通过 Rust/CCH/Web 检查。
- cc2api 发布后的版本、设置保留、用户实际使用反馈与回滚材料已记录；本次完整回滚
  演练未执行，不作为收尾要求。

## Next Step

- 提交并归档部署子任务的收尾记录，再汇总已完成子任务的 2.1.260 结果；不再追加测试。
