# 将剩余90个研究项目转为正式真实场景内容包

## Goal

将一百项目研究储备中尚未接入的九十个项目，逐批转为与现有十项目同等准入标准的真实场景内容包，使全部一百个研究项目在正式内容库中可实际加载与运行。

## Background

- 用户本轮明确要求“把剩余的研究储备也变成这样”，目标覆盖全部剩余储备，而非只补十项目任务量。
- 用户随后明确要求用auto-loop完成全部批次，授权本次commit-only循环的准备、实现、检查、修复和精确本地提交；不要求逐批普通Brief确认。
- 用户反馈二十三个子任务过多，因此收敛为三个阶段子任务，各覆盖三十个项目；阶段内部的小批不再建任务。
- `research/github-projects/progress.json` 记录一百个已完成研究的独立项目及两千项工程迭代提案；十五个未通过研究完成标准的候选不属于本轮九十项目范围。
- 初始快照 `real-project-scenarios-v4-en` 包含十个项目、四十五个场景、一百零七个独立任务。十个项目均在一百项目研究清单内，因此本轮固定新增集合恰为九十个项目；初始清单另存 `research/inventory-initial.json`。
- 三阶段已分别本地提交，当前正式版本为 `real-project-scenarios-v37-en`，实际一百项目、四百二十六场景、七百二十六任务；母任务仍须完成跨阶段证据、全量API、暂停批次和历史读取的整体复核。
- 现有接入内容、两批子任务完成记录和最近业务提交 `cb57f0c` 是准入基线；其本地原生与模拟证据不代表真实模型效果或生产部署已经验证。
- 原十项目母任务 `../10-21-project-catalog-expansion/` 的数量深化要求独立保留，本任务不修改其目标或替它关闭。

## Requirements

- R1：覆盖剩余九十个研究项目的完整固定清单，逐项追溯官方仓库、完整提交、来源报告及研究路线；不得以替换仓库、重复副本或省略困难项目缩小目标。
- R2：每个新增项目提供真实多场景任务，依据实际业务覆盖理解、咨询、诊断、方案及明确授权的修改；正常无需改代码、兼容方案和材料不足均可成为合法结果。
- R3：每项任务具有独立用户问题、公开材料、必要披露分支、授权范围及可观察的正常和反例验收；追问、重试、测试和文档不重复计数，不机械搬运二十步研究路线。
- R4：完整保留固定原始源码、许可证及必要测试语料，建立当前目标镜像下的实际原生基线、精确离线依赖和资源边界；原研究环境与结果只能作为线索。
- R4补充：用户已确认SQLGlot按固定公开主仓完整源码准入；可选的私有外部集成测试子模块明确未获取、未验证，不能计为通过，也不因此替换固定项目或删掉公开测试。
- R5：每个工程目标有原版失败、参考通过、错误候选拒绝及完整适用原生回归证据；问答任务验证其可执行事实，不把模拟评审当作业务行为证明。
- R6：每批新增内容通过真实产品调度、独立评审与原生验收链的隔离模拟，并核对页面、API、数据库和交付文件；只有实际准入的项目才进入正式目录及完成数。
- R7：模型首问、材料说明及评审规则保持英文，页面标题、目标和浏览路线保持中文；原始代码、报错和业务字面保留原文。
- R8：现有十项目字节、稳定任务标识及历史发布和成果保持兼容；新增内容用新版本注册，不能覆盖已冻结内容或重建退役合成库。
- R9：研究完成、来源复核、场景定义、离线与原生验收就绪、正式接入、模拟完成、真实模型完成、Git交付和生产部署分别记录；任一阻塞项目保留在剩余清单，不能因其他项目通过而宣布全量完成。
- R10：延续项目规范中约六百至八百场景、约两千独立任务的内容池方向，以真实覆盖和独立问题持续深化；不将方向值变为每仓固定配额，也不把原两千工程提案当作已交付任务。

## Task Map

- 母任务维护九十项目清单、阶段顺序、跨阶段统计和最终集成验收；实际内容由三个可独立验证的子任务交付，母任务作为循环最后一项执行整体集成审查及台账收尾。
- 三阶段各覆盖三十个项目，全部前序阶段都完成后的累计项目方向分别为四十、七十、一百；实际完成数始终据正式目录重算。
- 第一阶段内部先复核cachetools、xmltodict、tabulate、python-decouple，再继续同阶段其余二十六仓；内部批次不对应新的Trellis任务。任务边界和准入标准不因减少任务数而缩小。
- 详细固定清单与全部批次在本任务 `research/` 中记录；后续子任务只绑定实际交付范围，不能提前写成完成。

## Acceptance Criteria

- [x] AC1（R1、R9）：原研究一百项目与正式目录逐项对账，十项目基线加九十项目新增无遗漏、无重复；全部一百项目实际准入才能宣称本轮全部接入完成。
- [x] AC2（R2、R3、R7、R10）：每个新增项目有经审查的真实场景、唯一任务、材料、合法业务结果及语言合同；实际场景和任务数可重算，方向值与实际差距如实报告。
- [x] AC3（R4、R5）：每仓来源、许可证、离线环境、实际候选加载和完整适用原生结果有可复跑证据；每项修改保留正反例和原版／参考对照。
- [x] AC4（R6、R9）：每批默认与影响业务结果的分支均有产品链模拟及页面／API／数据库对账，角色、接受代码、尝试和用量独立统计。
- [x] AC5（R8）：新增内容的Git导出与Docker交付文件、摘要一致；旧内容、稳定标识及历史读取不回归，无关工作区与历史数据不被修改。
- [x] AC6（R9）：全量清单没有被静默剔除或误标完成的项目；研究、原生、模拟、真实模型、Git交付及生产状态可独立核实。

六项验收依据为 `research/final-integration-audit.json` 与 `research/final-api-verification.json` 及其绑定的三阶段原件；母任务自身Check-All、规范评价和精确本地提交仍按runner动作顺序执行。

## Non-Goals

- 不执行全部两千工程路线提案，不把制作参考解等同于模型已经完成对应任务。
- 不调用真实模型或OAuth，不使用真实账号、凭据和生产数据；本次auto-loop允许精确本地提交，不push、merge、发布镜像或部署。
- 不重写调度器、评审协议、数据库或页面；确有准入需要的原生适配按受影响合同研究和验证，不顺带重构。
- 不删除、重写或将既有百项目研究的历史零接入快照改成当前进度；当前准入进度另建台账。
- 不挪动或关闭既有十项目深化、额度采集及遥测收尾任务。
