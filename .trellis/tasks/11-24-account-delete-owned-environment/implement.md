# 实施与验证

1. 用合成账号建立两份回归样本。第一份覆盖 AGY 删除后环境仍在列表。第二份覆盖 Claude 草稿保存后删除工程账号，节点升级遇到三个已停止角色。记录 API、中央存储、节点角色及工作目录的初始状态。隔离本次改动与工作区中已有的功能开发。
2. 在两个公开删除入口识别专属和独立工程所有权。保留现有许可、在途检查、无运行时部署和普通解绑流程。先固定删除进度，再在对应本机或 SSH 节点逐个核对和清理资源。在实际完成后更新绑定与可见性。
3. 补齐巡检恢复、删除回执、环境列表、预热和重新创建入口。使旧作业不会再触及同名新账号。对有完整证据的历史残留接回原节点升级，对未知归属保持原有保护。
4. 在 `services/orchestrator` 运行以下模块的回归测试，包括 `test_agy_environment`、`test_agy_node_migration`、`test_deleted_binding`、`test_cluster_draft_login_runner`、`test_cluster_synchronization`。同时覆盖网关删除接口、旧部署、存储兼容、SSH 超时、删除重试、跳过共享资源和资料留存。按实际变更运行 Rust 网关测试及编排层全量检查。
5. 从真实管理 HTTP 入口在隔离本机及 SSH 环境删除合成账号。核对真实 Docker 容器、状态存储和环境列表，用文件摘要核对个人配置与项目。重启服务，运行巡检和节点升级，复核原环境、其他账号和历史记录。留存通过项及可复现的基线问题。
6. 按订阅标签子任务修正 AGY 的展示取值，覆盖列表、详情和旧快照回退。用合成 Ultra 账号从详情返回后删除，联合验收两个改动。
7. 完成任务检查、规范更新和提交交接。新版及线上环境操作另行安排。
