# 账号环境删除的技术设计

## 入口与归属

网关保留 `DELETE /admin/accounts/:id`。工程账号保留 `DELETE /api/accounts/{aid}`。在普通配置静默和单纯解绑之外区分“删除最后一个所有者”。AGY 由 `platform_api_environments` 绑定网关账号，工程环境由 `account_environments.account_id` 绑定工程账号。资格判断同时使用平台、账号空间、环境 ID、节点分配及代次。没有绑定的网关账号沿原删除逻辑。工程账号仍有效时，删除其网关绑定只解除原接入关系，保留工程环境的使用权。

## 顺序与恢复

1. 在删除权威绑定之前冻结归属。复用原配置许可、工程所有者锁、环境锁和节点分配核验，在已有活动结束后处理角色。对已经进入清理阶段的操作持久保存原环境、节点、代次和进度。跨进程的恢复依赖这些信息。
2. 本机沿现有运行时角色校验和移除逻辑，SSH 通过所属节点的受信操作完成相同核对。按精确标签和实际容器 ID 核验三角色。处理已退出、部分缺失及 Docker 创建成功而登记未写回的角色。只移除原环境的运行副本与可重建资源。先保存现有暂存区需要保留的内容。对工作凭据按原所有权合同清理，个人 HOME、工程和历史采集沿既有数据归属保存。
3. 实际角色清空后登记已清理，完成网关或工程账号的删除，当前环境列表、调度、预热、环境再登记与同名重新创建统一读取删除状态。旧的执行位置和历史引用仍能解析。SSH 暂失或提交结果未知时继续核对原操作。保留可重试的状态和明确提示。
4. 复用现有后台巡检恢复中断的删除。删除事务在网关与编排独立存储之间按原身份幂等推进。恢复期间重新核验代次和归属，避免在同名新账号上执行旧操作。清理失败不能因网关账号已消失而失去重试入口。

## 兼容与节点升级

旧版本已有普通账号、软删除账号、独立登录草稿和仅停止的环境。已有公开接口及正常停用、配置变更、解绑、迁移的语义继续兼容。环境列表按真实所有者和删除状态过滤，工程账号 ID 为 NULL 的草稿与 AGY 环境分别识别。同名重新创建时分开已退役环境与新环境的运行身份，保留原路径上的个人资料和历史资料。

节点升级对历史遗留角色复用原删除归属及实际停止证明。对旧版已保存草稿导致的残留，核对已提交的原账号、其删除事实、当前节点及环境、中央登记的原角色 ID、节点实际标签和停止状态。已关闭的登录草稿独立于删除事实。已恢复的线上实例作为合成回归样本的依据。现有迁移撤销和已停止历史副本仍按原回执核验。

## 账号页套餐显示

卡片和详情标题共用档位解析。AGY 优先取已观测的原生用户档位名称，缺失时读取额度快照的档位，再回退至平台计划。界面可简写 Google AI 前缀。详情区区分两个原始字段，Claude 使用原有订阅映射。标签不参与删除归属判断。

## 交付与回退

优先复用现有迁移与删除记录。需要新增持久状态时使用追加式、向后兼容的数据库迁移和既有双存储注册校验。升级中的旧节点只有在能给出可核验的清理结果时才返回完成，其他情况保留原删除进度。回退版本须保留未完成记录和已归档数据，禁止用旧快照覆盖较新的账号或凭据。开发验证与生产发布分开执行。
