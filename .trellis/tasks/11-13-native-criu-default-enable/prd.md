# CRIU 默认启用与实际状态展示

## Goal

让原生账号默认尝试CRIU加速，在前端查看实际状态、检查并选择内核新版，并为新环境提供明确的三角色CPU默认值。

## Background

- 用户已确认默认自动启用、前端展示状态及提供关闭选项，要求尽快修改，并只读核查线上几个账号的准入条件。
- 当前native_sender.criu_enabled、compose及example.env默认关闭；前端environments.js只有内核版本操作，缺少恢复开关与运行状态。
- 默认镜像内核仍为beta.5；已发布并在线使用的beta.6分发SHA为fce50a30d739dbc614e450d4d1913208fa35c6373c4f07a3986657393a99261e，恢复映像SHA为564019c9560e960e96875c9663975491534b27c789ea3d23e5c13309ff293c79。
- 线上只读核查：网关账号10/12为beta.6、sender各1核、内存无限、具备CRIU镜像工具，实际入口仍为普通TLS broker、CCRB_CRIU为空且无控制socket；网关11为普通后端、sender128MiB、账号总RAM1536m。宿主4核、采样可用RAM约3346MiB。安全摘要位于research/online-readonly-summary.json。
- 当前恢复最低sender RAM公式为256+max_workers×(192+108) MiB；无限额度memory_mib=0通过静态预算准入。native_sender.sender_config在全局恢复开启时直接提高业务最低额度，有限账号存在升级后准备被拒绝的兼容风险。

## Requirements

- R1：缺省启用CRIU自动模式；全局显式0保持紧急关闭。账号缺省跟随启用，显式关闭选择持久保存并在重建后保持。
- R2：默认内核固化为已验收beta.6，核对来源、分发/执行体SHA、长度与所有构建准入消费者；已有账号的持久内核选择保持原合同。
- R3：恢复内存准入独立于普通进程池准入。满足普通预算而不足恢复预算的有限账号继续普通启动，前端显示原因；无限内存通过额度条件。维持原并发和真实物理容量上限。
- R4：前端区分期望启用、容器入口生效、模板准备/就绪、正常恢复、普通启动回退及具体原因；缺少旧版本遥测时明确未知。GET列表及刷新保持零模型调用。
- R5：按账号提供开启/关闭操作；沿现有更新门禁、账号/环境锁、维护租约、排空与空闲重建流程，核对generation/revision，失败恢复原配置或进入对账；活动请求与CLI继续受原门禁保护。
- R6：默认能力接入系统更新/环境创建及重建配置一致性检查；旧入口显示需要应用/重建，避免仅镜像标签为1就宣称已启用。显式全局关闭保留可读原因。
- R7：线上核查保留静态准入、实际运行及真实恢复验证三个证据层级，给出账号级结论和所需步骤。

- R8：内核提供检查更新与已发布版本列表，管理员从列表选择进入原准备/验签/显式激活流程；发现失败、限流或缓存陈旧保持当前内核运行，版本发现不代表制品已获信任。
- R9：新隔离环境CPU默认CLI1.5核、sender1核、network0.5核；三角色独立配置覆盖默认值，已有显式cpu-resources.json策略优先。旧V3_ACCOUNT_CPUS=2不覆盖新三角色默认；评审及系统更新恢复沿既有实际额度合同。

## Acceptance Criteria

- [x] 缺省原生账号选择恢复入口，显式平台0及账号关闭生效，旧缺字段配置兼容。
- [x] 新默认内核的全部SHA/长度及发行来源一致；历史账号内核选择可继续运行并明确显示兼容状态。
- [x] 普通预算足够而恢复预算不足时业务仍可准备，恢复显示内存原因；无限内存与足额有限预算可进入模板准备。
- [x] 前端可见真实模板/恢复状态、回退及旧入口/旧遥测原因，轮询无模型提交；显式开关经过原维护流程并可回退。
- [x] 旧容器在受控重建后使用目标入口，状态、配置、权限、HOME与身份一致。
- [x] 单测/接口/页面与必要跨层回归通过，普通exec及每笔唯一发送保持原合同。
- [x] 线上账号10/12/11的只读核查结论可复核，实际启用与性能留待上线验收。

- [x] 管理员可检查新版、从发现列表选择准备并明确激活，异常反馈与缓存陈旧可见；缺省进入页面保持零业务写入。
- [x] 新角色NanoCpus为1500000000/1000000000/500000000，独立默认覆盖、旧总量配置、显式策略优先、评审与更新恢复回归通过。

## Scope Boundary

- 本任务涵盖默认启用、账号开关、实际状态、预算降级、默认配套内核和升级接线。
- 用户于实施中明确要求将另窗口委托的内核版本发现与CPU默认值直接并入本任务。来源为11-13-native-update-cpu-defaults/handoff.md及其两份子任务材料，本任务统一拥有共享源码、验证与交付；源规划作为来源记录。
- 生产重建/权限调整、真实内核切换、资源额度修改及付费模型测试由独立上线操作授权处理。
