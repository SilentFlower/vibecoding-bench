# 上线验收交接

## 交付范围

- CRIU缺省自动开启、账号开关与实际状态，默认配套内核beta.6。
- 内核只读检查更新及已发布版本选择，准备验签与显式激活沿原合同。
- 新隔离环境CLI/sender/network默认1.5/1/0.5核；持久CPU策略及系统更新冻结的实际额度继续优先。

## 发布负责人执行

- 正式发行前按新增功能批次递增平台次版本，使用同批控制与账号镜像、现有签名发布和宿主更新流程。核对部署显式V3_NATIVE_CRIU=0及账号false的既有选择；缺省/空值开启，有限内存不足恢复额度时普通启动。
- 只读核查时网关账号10/12满足静态条件：beta.6、sender1核、内存无限、镜像含恢复器；实际为普通TLS broker入口。受控重建后核对CRIU入口、控制socket、同代巡检及模板ready，再核对真实criu_restore来源。
- 核对业务sender/worker为UID1001、capability0、NNP1、seccomp2，恢复控制器沿既有固定权限。真实请求继续唯一发送；性能记录完整checkout至ready，首次模板创建单列。
- 宿主4核、只读采样可用内存约3346MiB；两账号共享物理容量。验证并发扩容时的RAM峰值、实际进程数量及CPU节流，再决定线上容量。
- 网关账号11当前为普通发送后端，sender128MiB。按现有后端与资源方案单独处理。
- 页面验收：只读检查更新与版本列表、期望/实际恢复状态、旧遥测与降级原因、账号空闲开关；新环境角色CPU默认及旧显式策略优先。

## 回退与恢复

- 全局显式V3_NATIVE_CRIU=0或账号关闭选择后，沿原空闲维护应用普通入口；业务发送前恢复失败沿原exec回退。
- 配置切换失败按私有操作记录核对restored/reconcile；仅由原owner收口维护门禁。内核准备/激活/回滚继续沿现有精确签名与代次合同。
- 本轮交付为源码、规范及本地验证。生产重建、权限/内核切换和真实性能验收进入独立上线授权。
