# Brief — 新增独立项目迭代模式

## Goal

- 新增独立的全自动项目迭代模式，持续交付并保留通过验收的项目修改。

## Scope

- 100 个可运行项目，每项目至少 20 步，共至少 2,000 步，附固定初始数据和业务验收。
- 项目库、账号／批次独立实例、自动调度与修复、成果版本、日志及已有 token 统计。
- 独立页面，以及批次启动、暂停、停止和恢复。

## Non-Goals

- 不改变原题库、批次、养号、抓包和续聊的行为及历史记录。
- 不包含任意 Git 导入、旧运行转项目、新模式人工续聊、无限生成需求、生产部署或全量真实模型测试。

## Technical Overview

- 控制端固定内容与验收版本 → 按需创建工作副本 → 现有执行器修改 → 执行清理后隔离验收 → 保存版本并推进；失败则有限修复或阻塞切换。
- 每步使用新主会话并复用项目文件；额度恢复沿用原步骤、run 和会话。SQLite 新增独立记录，保留原有数据。

## Context & Decisions

- 同项目同版本的初始代码和数据一致；不同账号／批次分别积累成果，不同项目各有功能与路线。
- 默认每账号同时执行一步、每批次最多三个可推进的活动项目；当前项目完成阶段后轮换，业务失败最多追加两次修复。
- 排队和等待期间不建工作目录；首次实际启动才出现，之后暂停、切换、完成和重启均持续保留。
- 继承现有运行窗口、额度、认证和维护约束，账号级阻断不能通过换项目绕过。

## Risks

- 共享项目目录的会话归属、验收快照以及停止／重启竞争需要重点验证，并保留工作区其他任务的改动。
- 实际模型通过率与输出量以运行数据为准；当前规划不承诺达到 vm2api 样本的 token 水平。

## Acceptance

- 全部基线可运行，每项目至少 20 步具有实际行为验收与参考验证。
- 相同基线摘要一致、实例互不污染；连续两步累积、阶段切换及返回续做闭环通过。
- 创建 100 项目批次时可见目录为零，首次启动仅对应实例出现，之后持续保留。
- 假成功、修复上限、等待／停止／重启、旧代次、清理失败，以及原模式回归均通过。

## Next Step

- 实现与本地验证已完成，进入质量检查后的契约整理；Git 动作以精确计划另行确认。
