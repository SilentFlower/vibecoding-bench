# 项目基线、执行实例与运行边界

## 已确认的实例语义

- 项目定义包含该业务项目的固定初始代码、固定样例数据和独立迭代路线。
- 同一项目的相同版本在不同账号或批次中，均从同一初始版本建立工作副本。
- 不同账号和批次的副本、数据及进度互不覆盖；同一实例的后续轮次继续使用已验收成果。
- 扩充项目池和路线属于系统预置内容，不要求用户在运行期间手工给出需求。

## 当前集成点的事实

- `orchestrator/main.py` 的 `runs` 已记录 `task_id/account_id/batch_id/topic_id`、执行状态、模型及 CLI 快照、额度恢复代次、工作目录和日志目录。新模式仍需明确自己的实例与步骤身份，不能将 `topic_id` 当作长期项目进度。
- `Scheduler.submit` 与 `_execute` 是普通运行的投放和执行入口；当前窗口等待会重新检查账号、停止意图、额度身份与父任务状态。新模式应进入共同执行约束，不能另起不经过这些检查的模型调用器。
- `AccountRuntime.start_run` 通过 `_cli_setup` 建立执行，调用 `_project_view(row, run_id)`，为本次 run 创建兼容工作区链接；控制文件保存在独立的 `runtime/runs/<run_id>` 和 `runtime/jobs/<handle>`。
- `AccountRuntime.run_session_path` 同样按环境 ID 与 run ID 求项目别名。设计持久项目目录时必须同步修改新模式的会话路径解析，而不能仅让多个 run 指向同一磁盘目录。
- worker 已有 `RESUME_SESSION_ID` 的额度恢复路径，会下发恢复原任务的控制文本。跨里程碑启动下一项工作与恢复未完成工作是不同语义，不能不加区分地复用该路径。
- WebUI 使用 hash 页签和无构建原生 JavaScript，已有账号、题库、任务、运行、环境入口。独立新入口可以沿用现有页面结构与运行详情。
- cc2api 数据库规范要求其自身的 SQLite/PostgreSQL 同步，但本功能可在 bench 的 SQLite 和运行器边界设计，项目新 API 必须加入 `cc2api/src/service/runtime_bridge.rs` 的管理资源白名单；账号、凭据、协议画像和数据库不涉及修改。

## 后续设计必须覆盖的事项

- 内容版本与实例绑定：源码、数据、路线和验收定义固定版本，已运行实例不静默升级到新的内容。
- 工作区与会话：新模式按实例稳定解析，原模式继续按 run 解析；每轮独立保留输入、执行与验收证据。
- 并发：同一实例只允许一个写入者，账号并发和维护租约继续独立生效。
- 验收：验收定义与结果由控制端持有，不允许执行模型修改验收定义来让步骤通过；程序在隔离的工作环境内运行。
- 状态：区分执行结束、验收通过、修复中、阻塞、额度等待、运行窗口等待、停止与路线完成。
- 重启：先对账在途 run、输入消费和工作区版本，再决定继续验收或恢复执行，不能重复投递或直接跳到下一步骤。
- 原模式兼容：新增字段使用空值或默认值；历史 task/run 不回填新身份、路线或结果，也不自动开启项目模式。
