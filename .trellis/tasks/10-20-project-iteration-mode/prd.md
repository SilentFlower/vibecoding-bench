# 新增独立项目迭代模式

## Goal

提供独立的全自动项目迭代模式，使系统在多个可运行项目上按路线持续交付经过验收的修改，并保留各账号、批次的独立成果。

## Background

- 用户希望在既有项目上持续修改和迭代，并明确要求新增模式、保留原有题库模式。
- 当前系统以 topic 创建任务，新 run 默认获得独立目录；已有固定账号环境、执行门禁和原会话恢复能力，尚无跨 run 的项目路线生命周期。
- 前置对照发现原 bench 与一批 vm2api 样本的输出用量不同，但没有建立任务模式与封禁之间的因果关系；项目数量不能直接推导实际 token 用量。

## Requirements

- R1：提供独立入口及运行归属，能够浏览项目库、建立自动迭代批次、查看项目进度与执行结果。
- R2：维护多个可持续迭代的项目；项目的账号和批次实例独立保存源码、数据和进度，同一实例在多轮迭代间保留已完成的修改，后续工作能够基于上一轮成果继续推进。
- R3：每一步明确目标、范围和可执行的验收条件；验收由系统依据程序行为和证据完成，不能仅凭模型总结或进程退出码推进路线。
- R4：保持原有题库、单任务、批次、养号、抓包及续聊的业务语义和历史记录，不将其默认切换为新模式。
- R5：沿用账号可用性、维护占用、并发、运行窗口、额度等待及认证失败约束；停止和身份变更优先于恢复，不另建绕过共同执行门禁的模型调用通道。
- R6：启用批次后的选任务、执行、验收、修复和后继步骤调度全部自动完成，正常运行不依赖人工提供需求或确认建议；项目局部失败可以切换，账号级阻断必须停止该账号的投放。
- R7：首版交付 100 个不同项目，每个至少 20 个连续迭代步骤，总计至少 2,000 步，并允许后续扩充。同一项目的相同基线版本在不同账号或批次中使用相同的初始源码和数据，不同项目具有各自的初始功能与路线。
- R8：每个项目具有可持续推进的迭代路线，明确阶段顺序、依赖和完成依据；失败、重复修复及路线耗尽时有确定的自动处置或停止状态，避免无限空转。
- R9：项目选择策略以连续推进为主，在已定义的阶段边界或项目阻塞等可解释节点切换；切换后保留原项目的代码、数据与进度，后续可以自动回来继续，不能把切换当成重新初始化。
- R10：项目工作目录按需初始化。选入项目池、建立批次或处于排队／额度／运行窗口等待时，不创建未开始项目的可见工作目录；首次通过执行门禁并进入实际启动后才建立，此后暂停、切换、完成和服务重启均持续保留。

## Acceptance Criteria

- [x] AC1（R1）：独立页面能够浏览项目基线与路线、为账号创建和启停批次，区分执行结果和验收结果，并关联到运行日志、代码版本及已有 token 统计。
- [x] AC2（R2）：连续两轮针对同一项目执行时，第二轮可以读取并修改第一轮保留的代码，已完成成果不会因新一轮运行而被重置。
- [x] AC3（R3）：模型正常结束但业务验收失败时路线不得推进；通过场景具有本步新行为及先前能力的回归证据，执行器不能通过修改验收定义让步骤过关。
- [x] AC4（R4）：原有题库模式的相关回归通过，历史任务及已固化需求保持可查看、可恢复。
- [x] AC5（R5）：新模式受现有账号执行限制约束，等待、停止、恢复与认证失败能够保留明确状态和项目成果。
- [x] AC6（R6）：无需人工追加输入完成选步、修改、验收及后续投放；项目局部阻塞不妨碍其他合格项目，账号级门禁生效时不通过换项目继续调用。
- [x] AC7（R7）：确认 100 个有效项目、每项目至少 20 步且总数至少 2,000；全部初始版本可运行并通过基线验收，项目间具有业务差异；相同版本两个新实例的初始源码和数据摘要一致。
- [x] AC8（R8）：每个项目可查看迭代路线与完成进度，自动推进遵循依赖关系；达到失败上限或路线终点后进入明确状态，不重复执行已完成步骤。
- [x] AC9（R9）：系统可以在一个项目完成阶段或阻塞后切换到其他可运行项目；再选中原项目时接续其未完成步骤，保留原版本和进度，并能查看切换原因。
- [x] AC10（R10）：创建含 100 个项目的批次后，工作目录中尚无这些项目；第一次实际启动一个项目后只有该实例出现，其他未开始项目不出现；该目录在项目切换、暂停、完成和服务重启后仍然存在且内容保持。

## Non-Goals

- 不改写原有题库或将 600 个主题直接当作已交付的项目源码。
- 首版不提供任意 Git 仓库导入、旧运行产物转项目、开放式无限生成需求，或项目模式的人工续聊推进。
- 新模式以当前 v3 固定账号运行环境为执行目标，不扩展到旧版每 run 一套容器的执行器。
- 本次不包含生产部署、真实账号模型压测、账号策略／协议画像调整；不承诺输出量达到某一 vm2api 样本或降低封禁概率。

## Delivery Constraints

- 项目库、控制状态和验收定义由控制端保存，不能提前铺进账号可见项目目录。
- 已有工作区存在其他任务的未提交改动，实施前核对并保留，不夹带其他任务变更。
- 首次完整 Brief 已获确认并进入实施；当前实现与本地验收已完成，生产部署与真实模型用量观察不在本次验证范围。
