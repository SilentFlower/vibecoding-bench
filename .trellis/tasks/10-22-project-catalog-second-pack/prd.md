# 第二批四项目真实场景内容包

## Goal

为配置加载、TOML编辑、SQLite处理和重试策略接入四个真实项目的多场景任务与独立验收，将内容库扩至十个独立项目。

## Background

- 用户在本会话同意第二批四项目继续扩容；先准备 python-dotenv、TOMLKit，再处理 sqlite-utils、Tenacity，最终统一验收。
- 母任务为 `../10-21-project-catalog-expansion/`；首批子任务已 completed／closed，业务与任务记录均已推送。源码基线 `0c09c2600bcc66ff568e843a8a0252fcf3a6f1dc`，`real-project-scenarios-v3-en` 共6项目／26场景／57任务；线上仍为 `ci-39609484070-1` 的3项目／13场景／20任务。
- 本轮逐仓规格见 `research/python-dotenv-plan.md`、`tomlkit-plan.md`、`sqlite-utils-plan.md`、`tenacity-plan.md`，数量与关键取舍见 `design.md`；历史研究仅作来源与选题证据，旧Python、节点数和资源不作为当前镜像准入结论。

## Requirements

- R1／来源：逐仓固定真实源码、完整提交、许可、原生入口及完整适用测试；TOMLKit 测试子模块也须冻结来源。
- R2／任务：覆盖理解、咨询、诊断、方案和修改，以非修改为主；逐项记录业务材料、合法结果、正常／反例及真实依赖，披露、重试和修改附带测试不另计任务。
- R3／验收：每项修改须原版复现、私有参考通过及完整适用上游回归；咨询示例实际调用原生 API，原生事实与语义质量分别验证。
- R4／业务：覆盖配置加载、TOML保真编辑、SQLite处理和重试策略；保留无需改代码、已有API解决及材料不足结论，兼容变化须在具体任务明确授权。
- R5／材料与语言：首问、材料指令、分支和rubric英文，页面标题／目标／路线中文；源码、报错及业务值原样。隐藏复现、参考实现和私有规则不提前进入公开输入。
- R6／离线：在现有目标account镜像冻结精确Python、依赖wheel及SHA；分别实测业务和回归资源，不增加账号配额，不读宿主真实.env。
- R7／模拟：隔离空库、合成账号、mock CLI覆盖全部新增默认任务及改变材料／结果的路径，核实际消费、代码父链、尝试、预算和角色用量；真实模型与OAuth调用为零。
- R8／兼容：现有六项目及环境、稳定ID、历史发布和成果保持原样；生成新catalog版本及真实摘要，核Git导出／Docker上下文及历史读取。
- R9／计数：本批按四仓去重表新增19场景／50任务，其中42非修改、8修改，完成后累计10项目／45场景／107任务；不强制每仓20项，不以候选或分支填充150～200任务目标。数量变化先同步对应规划，不能静默改分母。
- R10／适配：复用内容schema2、policy3、原生验收和现有布局支持；仅增加四套可信回归及接入必需的最小兼容适配，不重做调度／评审／UI。

## Acceptance Criteria

- [x] AC1（R1、R2、R9）：四仓来源、许可及逐项任务表可追溯；静态目录为10个唯一项目／45场景／107任务，新增50个稳定任务ID与去重表一致。
- [x] AC2（R2～R5）：覆盖五类型、正常披露、无需改动与材料不足；仅声明真实同场景answer／code依赖，正常澄清不增业务尝试。
- [x] AC3（R1、R3、R6、R10）：每个修改的原版失败／参考通过／反例与完整回归可执行；当前镜像Python／插件／节点和资源实际校准，跳过有冻结理由。
- [x] AC4（R5、R7）：默认与必要分支通过真实产品链路模拟，问答零代码检查点、评审证据合法、消费与预算／用量可独立对账。
- [x] AC5（R5、R8）：逐项核英文指令与中文公开投影，桌面／390px页面、API和SQLite一致；新旧版本共存，当前库故障时历史仍可读。
- [x] AC6（R6、R8、R9）：Git导出／Docker上下文的全集及字节一致，旧六仓及277个计划外文件保持原样；报告分列内容、模拟、真实模型和部署状态。

## Non-Goals

- 本批不强制完成150～200任务，不重写旧一百仓研究或二十步路线。
- 不改账号、OAuth、调度／计时、数据库结构或UI/API协议，不引入第二评审模型。
- 不读取真实配置、凭据或生产数据，不调用真实模型，不自动提交、推送、发布或部署。
