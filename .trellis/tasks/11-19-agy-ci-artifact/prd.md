# 补齐 AGY 正式构建制品与发布完整性校验

## Goal

让正式 CI 自动生成包含完整 AGY 能力的账号镜像，并在发行前阻止制品缺失或打包遗漏。

## Background

- 用户要求 AGY 经处理后随镜像交付，并要求修复当前打包链路。
- 当前基线为 `7625142c2fbfbf26ee0f09e04309447b4c02f606`，分支 `release/agy-flower2api` 已推送到 `flower2api`。v1.19.0 发布运行 `44459272642` 已取消，正式目录仍指向 v1.18.3。
- `agy_auth.stage_auth_asset` 在缺少 `V3_AGY_AUTH_ASSET` 时生成未提供制品标记。CI 工作流缺少该输入准备；`agy_environment.sender_config` 会拒绝缺失固定摘要的镜像。
- 自动构建运行 `44459216076` 在 `COPY agy-auth/` 处失败；真实 Docker 已复现白名单缺少 `agy-auth` 的问题。本轮同时显式纳入 `orchestrator/agy_runtime` 包。原日志保存在 `.trellis/.runtime/agy-flower2api-release/build-failed.log`。
- 用户明确采用现有处理产物复用路线。已核对本地 `agy.xz`：压缩包 80922084 字节，解码后 265700040 字节，完整 SHA256 与当前运行时合同一致。证据见 `research/processed-artifact-verification.json`。

## Requirements

- R1：CI 自动取得已验证的固定版本输入，生成适配资源并将运行所需文件封装进镜像。部署端拉取镜像即可使用该能力。
- R2：复用现有 1.5.9 已处理压缩执行映像，冻结压缩包和解码执行体两层身份。适配层、观察器及监督协议沿当前源码构建；CI 从本仓版本化附件或缓存取得处理产物。
- R3：Docker 构建上下文完整包含 AGY 固定执行体、包源码和构建资源。源码 Git 只保存准备逻辑、固定身份与证据，原版二进制保持构建暂存输入。
- R4：正式候选与发布在副作用前检查 AGY 制品声明和实际镜像能力。能力缺失、摘要不符或包不完整时明确失败。历史发行读取及通用本地 CC 构建保留原兼容边界。
- R5：正式构建验收使用镜像内实际代码和执行体，覆盖零模型准备、共享映像、两代凭据及退出收口。现有源码研究探针保持明确区分。
- R6：自动构建保持只读发布权限；签名、真实旧库兼容演练和手动发布门禁继续执行。处理产物先在本地核验并准备为本仓版本化附件，附件发布纳入后续精确计划。修复完成后回到 v1.19.0 发版预览，以新源码继续原发行流程。

## Acceptance Criteria

- [x] AC1 / R1–R2：现有 XZ 处理产物为 80922084 字节、SHA256 `22ade718c0914d0a7ea14cac1e1575a78e0c8a7b337f49f3ff5c729291f7cfea`；解码执行体为 265700040 字节、SHA256 `39816d49d5ab92229952987225c23ea3fed7580699dcb4a444e0388e0ac1ce43`。缓存重复准备幂等，损坏、超预算、尾随内容及身份失配拒绝。
- [x] AC2 / R3：真实 Docker 上下文验证包含必要文件，实际镜像可以导入 AGY 模块并核对资源身份；重现本次 COPY 缺失问题的回归通过。
- [x] AC3 / R4：完整能力的候选与发布通过；缺失或失配制品在镜像推送及正式签发前拒绝；历史读取和本地可选构建继续通过回归。
- [x] AC4 / R5：镜像内模式经断网容器完成两代零模型准备、单次共享解码及正常/异常退出；结果来自镜像自身文件。
- [x] AC5 / R6：部署工具、工作流和受影响编排测试通过；发布链保留原来源、签名与兼容检查；明确记录后续新源码发行确认点。

## Non-Goals

- AGY 协议、模型业务逻辑、账号数据或数据库版本变化。
- CC runtime 制备策略调整及旧研究包适配代码替换。
- 新私有制品托管服务、额外仓库凭据、真实账号及外部模型调用、生产实例安装。
- 外部模型调用预算为 0。
