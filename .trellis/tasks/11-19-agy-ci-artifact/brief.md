# Brief — 补齐 AGY 正式构建制品与发布完整性校验

## Goal

- 复用现有 AGY 处理产物，构建完整账号镜像并恢复 v1.19.0 发行准备。

## Scope

- 处理产物导出与 CI 接线、Docker 白名单、实际镜像验收及发布完整性检查。

## Non-Goals

- CC runtime 制备策略、AGY 业务协议、账号数据、数据库版本、额外托管服务、真实模型调用及生产安装。

## Technical Overview

- 固定复用现有 `agy.xz`，校验压缩包和解码执行体两层身份；在构建阶段准备镜像所需输入。
- 处理产物通过本仓版本化附件和缓存供 CI 复用，适配层与观察器沿当前源码构建。
- 补齐 Docker 白名单，使用镜像自身代码验证完整性，正式候选与发布在副作用前核对能力。

## Context & Decisions

- 现有压缩包为 80922084 字节，已核对解码后的 265700040 字节执行体与当前合同一致。
- 复用固定执行映像，保留当前工具、凭据代次和同形体适配源码。
- 自有附件拟使用本仓 GitHub Releases 的 `agy-runtime-1.5.9-v1` 标签。先准备本地附件，附件发布纳入后续精确计划。
- 保留历史发行读取、本地可选构建和原签名、旧库兼容演练门禁。外部模型调用预算为 0。

## Risks

- 附件可达性、缓存漂移及 Docker 过滤遗漏会影响镜像完整性。
- 源码挂载可能掩盖镜像问题，新门禁需要覆盖历史兼容回归。

## Acceptance

- 现有处理产物重复准备幂等，损坏、截断、超预算和摘要失配受控拒绝。
- Docker 上下文、镜像模块导入与资源身份检查通过。
- 镜像自身完成两代零模型准备、单次共享解码及正常/异常退出。
- 缺失能力在推送或签发前拒绝，历史兼容和相关部署、编排测试通过。
- 修复验证后进入精确 Git 与附件发布计划，再按新源码恢复发版预览。

## Next Step

- 激活任务并实现现有处理产物的导出与准备入口。
