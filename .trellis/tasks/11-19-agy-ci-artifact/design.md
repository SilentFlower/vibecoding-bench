- 压缩身份：80922084 字节，SHA256 `22ade718c0914d0a7ea14cac1e1575a78e0c8a7b337f49f3ff5c729291f7cfea`。
- 解码身份：265700040 字节，SHA256 `39816d49d5ab92229952987225c23ea3fed7580699dcb4a444e0388e0ac1ce43`。已完成流式解码核对，与当前 AGY 运行时完全匹配。
- 当前 `agy_runtime` 适配源码、观察器、同形体资源和工具/凭据代次逻辑由仓库当前版本构建。旧研究包中的 Python 代码与观察器具有历史行为，独立于本次固定映像复用。

## 自有附件与 CI 输入

- 本地导出只包含固定压缩映像及有界身份清单，排除 HOME、凭据、日志和原研究目录其他内容。保持二进制在源码 Git 之外。
- 沿本仓现有 GitHub Releases 基础设施交付附件，规划标签 `agy-runtime-1.5.9-v1`，附件名 `agy-execution-linux-x64.xz` 及 `agy-artifact.json`。
- 该辅助制品使用独立标签、预发布标志及 `latest=false`，与 `system-ci-*` 平台发行和签名更新目录分离。
- 标签与附件以固定身份独占发布，已存在时只验收同一内容。上传、远端摘要复核和附件可用性检查属于后续精确发布计划；实施阶段先准备本地可评审产物。
- CI 使用固定的本仓附件 URL 和源码内两层摘要，缓存键绑定压缩身份。复用现有只读下载能力和 Actions 缓存，权限保持 contents:read。

## 准备与镜像打包

1. 自动构建和完整手动构建共用处理产物准备步骤，优先核验现有缓存或显式本地输入，冷缓存读取上述自有附件。
2. 下载核对压缩长度和摘要。XZ 按有界块流式解码，核对实际解码长度与完整摘要，拒绝损坏、截断、超预算和尾随内容；验证完成后原子交付构建输入。
3. 解码出的固定执行体继续交给现有 `stage_auth_asset`，沿原内容身份、Docker 参数及镜像内路径打包。解码发生在构建阶段，账号运行入口保持当前合同。
4. `images/v3/Dockerfile.dockerignore` 精确纳入 `agy-auth` 的执行体/缺省标记和整个受管理 `orchestrator/agy_runtime` 包。既有临时源码过滤与秘密排除继续生效。
5. 账号镜像编译当前观察器和资源清单，执行体与处理组件一起交付。control 保留当前 AGY Python 包。

## 候选与正式发布完整性

- 复用 `auth_asset_identity` 核对固定声明，并补上要求 AGY 能力完整的调用边界。
- 候选导出/采用核对 `agy_auth.available` 及固定身份；正式 `manage.publish` 和 `publish_system_release.publish` 在镜像发布/签发前拒绝能力缺失。
- `inspect_images` 按已声明能力核对 account 的实际标签与源摘要。
- 一般本地可选构建继续支持明确的未提供制品标记，历史已签发行读取保持兼容。
- 候选复用继续核对原 source/run/attempt、ZIP 摘要、换批与组件身份，并执行实际镜像验收。

## 实际镜像验收

- 现有 `verify_agy_runtime.py` 的研究模式挂载源码，容易掩盖镜像内包遗漏。
- 补充显式镜像内模式，使用镜像自带 `/opt/v3/python` 和 `/usr/local/bin`，仅挂载本次合成状态目录。
- 断网、只读根、UID1001、有限内存和权限约束继续执行；断言两代合成 AT 准备、模型入口为 0、单个共享映像及正常/异常物理退出。
- control/account 的包导入与资源身份检查覆盖真实 Docker 白名单过滤后的文件集合。
- CI 宿主通过 `sudo "$RUNNER_TEMP/v3-update-venv/bin/python"` 调用镜像验收，负责合成状态目录和配置文件的 UID1001 归属。验收容器沿原 UID1001、断网及权限约束执行；两个工作流的实际调用由 YAML 回归覆盖。
