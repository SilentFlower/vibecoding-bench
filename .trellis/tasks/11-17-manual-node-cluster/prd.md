# 多服务器人工分配与统一网关转发

## 目标

通过统一后台管理多台服务器，由管理员指定账号环境的执行节点，把账号运行与工程执行的资源消耗分散到其他服务器。

## 背景与约束

- 当前账号环境已拆分为 network、CLI、sender 三个角色；编排服务仍使用本机 Docker、本地账号目录及 SQLite。
- 首版接入长期在线、管理中心可直接访问的 Linux 服务器，沿用现有执行镜像支持的平台要求。
- 用户已确认 SSH 纳管与隧道转发：通过专用密钥和已确认主机指纹接入，控制连接与业务连接分开管理。
- 账号池选择账号继续沿用既有令牌范围、会话与账号规则；人工分配决定账号的执行位置。
- 本任务作为一个可整体验收的跨层交付规划，包含节点管理、账号归属、远程执行与网关转发。
- 当前代码约束及检索依据见 `research/current-architecture.md`。

## 需求

- R1 节点管理：管理员可添加和查看节点，查看连接状态、资源信息及其账号环境；状态包含采样时间，未知或过期数据明确展示。
- R2 人工分配：管理员创建账号环境时指定执行节点，保存固定归属；同一账号的网络、CLI、sender、HOME 和工作目录由所属节点承接。
- R3 默认节点兼容：现有服务器作为默认节点，已有账号环境继续归属现有服务器；新增服务器逐台接入；管理服务重启后保留分配关系。
- R4 统一网关：客户端沿用统一 API 地址和令牌，网关按账号归属发送请求，保持流式响应、取消、并发控制、用量与诊断记录；账号相关的后台上游活动继续遵守同一归属、代理及凭据所有权边界。
- R5 统一操作：后台可管理远程账号环境，并查看日志、使用终端、执行相关工程任务；操作准确关联节点、账号及环境。
- R6 手动迁移：由管理员选择目标节点，暂停新工作并排空在途工作后迁移必要的持久数据及身份，成功核对后切换归属；失败保留可恢复状态。
- R7 异常处置：节点离线或容量不足时明确提示并暂停受影响环境的新工作，已提交请求的状态与处置原因可见；恢复连接后先核对实际作业和环境身份，再恢复符合条件的新工作。
- R8 身份与访问边界：跨机链路具备认证和加密，保持账号凭据所有权与隔离规则；公开接口及日志采用脱敏信息。
- R9 资源边界：节点承接本机账号运行的资源预算，中央展示来源清晰的节点资源和环境使用情况。

## 验收标准

- [x] A1（R1、R9）：后台可登记并区分至少两个节点，分别展示真实来源的连接和资源状态。
- [x] A2（R2、R3）：两个账号可分别绑定不同节点；重启管理服务后归属一致；已有单机环境继续工作。
- [x] A3（R4）：统一网关使用两个账号分别完成对应节点的 Messages JSON 与 SSE 请求，节点和请求证据可关联。
- [x] A4（R4、R7）：验证请求取消、并发额度、流中断及节点断连，状态和用量处理可核对，已提交请求遵守防重复调用边界。
- [x] A5（R5）：从同一后台操作远程账号终端、日志和工程任务，实际执行与文件归属匹配指定节点。
- [x] A6（R6、R8）：空闲账号可人工迁移；身份与必要持久数据核对通过；模拟迁移失败后可恢复；活动工作参与排空判定。
- [x] A7（R7）：节点容量不足或离线后，其账号呈现明确状态；其他节点可继续处理各自工作。
- [x] A8（R8）：错误节点、账号、环境代次或失效的服务认证被拒绝，公开输出通过凭据脱敏核验。
- [x] A9（R3、R8）：在隔离测试副本中验证旧库升级、默认节点归属和备份恢复，保留既有账号凭据所有权。
- [x] A10（R4、R8）：覆盖 legacy 与 native293 两种请求后端，以及额度、预热、遥测和受管 OAuth 刷新等后台路径；核对节点出口、原代理、唯一刷新所有者及不确定提交的隔离状态。
- [x] A11（R1、R3、R7）：新节点按同批镜像、专用 SSH 密钥和已确认主机指纹接入，认证、协议或发布身份不匹配时显示明确原因；节点重启后先对账，再接收新工作。

## 范围外

- 自动选择执行节点、自动均衡、自动迁移与自动故障接管。
- 管理节点或数据库的多副本高可用。
- 跨节点共享可写账号 HOME。
- 自动重放已经提交的模型请求。
- 内网个人电脑临时节点、主动反连隧道和跨架构执行支持。
- 源节点离线时的强制迁移、运行进程热迁移和 CRIU 快照跨宿主恢复。
- 本次开发交付中的线上安装、真实账号迁移、真实模型调用与软件发布操作。
