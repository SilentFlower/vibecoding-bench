## Bug Analysis: 收尾链路中的错误代理条件与跨层遗漏

### 1. Root Cause Category

- **Category**: C / D / E：修改传播遗漏、组合验证缺口及隐含前提。
- LoginManager 的名称占用只检查内存集合，后台原操作完成后缺少持久 closed 状态的收口。正式远程会话同时遗漏 environment_id，使第一次修正仍无法匹配原环境。
- 新 Owner Actor 的操作名已进入 SSH 与服务分派，轻量 AgentClient 白名单仍缺失。真实调用在进入 Node Actor 前被拒绝，容器日志为空。
- 独立迁移把 sender_container_id 当作 Gateway 关联。原生命周期会预建三角色，该条件误拦 binding=None 的合法环境。
- 普通独立 CLI 首次准备只建立布局，原 HOME 尚无完整凭据。迁移使用的当前所有者材料必须由原 sync_credentials 首次发布。
- 备份范围读取使用普通 SQLite 只读连接，复制后 WAL 数据库仍会创建辅助文件，改变刚保存的文件清单。离线已固定快照改用 immutable 连接。
- 镜像来源读取复用系统更新的 CI 编号正则，现有手工构建批次被拒绝。镜像来源按原镜像命名合同校验，签名发行清单继续使用原独立合同。
- 新增进程导入的真实测试未将全局 cc2api_client 指向本次隔离 Gateway，568返回集成未配置。夹具现已明确注入真实客户端，继续复验原产品路由。

### 2. Why Fixes Failed

- 名称占用第一次修正仅增加持久读取。543增加复现后发现会话缺失 environment_id，随后补齐创建来源并以同 SID/同操作/同环境收口。
- 545的固定公开错误只能确定跨机操作失败。547限定诊断显示 Actor 日志为空，沿 SSH→轻量入口→Actor 逐层核对后发现白名单遗漏。
- 554迁移限制依据角色是否存在判断所有权。改为核对原 binding 后，555完成真实独立迁移及双节点故障隔离。
- 565验证首次开启 Node 镜像来源时才触及旧正则。先前无更新目录的测试配置避开了该分支。固定 Node 来源目录并保留真实命名合同，追加手工批次和错误角色/摘要测试。

### 4. Systematic Expansion

- 暂停准入与原操作收尾分开核对。纯身份读取、原停止、解绑和缺失绑定收口依赖冻结范围及实际回执。
- 管理迁移可读取人工停用的 bench 账号，并保持 enabled 原值。退休、刷新未知、登录提交、实际执行、错误归属继续沿原门禁。
- 组合备份记录 pending_operations 和 reconcile_required，保存原恢复事实。完整性验证与恢复后开放接单分别判断。
- 历史日志和运行节点读取使用原执行位置。账号迁移后的当前归属不覆盖历史记录。
