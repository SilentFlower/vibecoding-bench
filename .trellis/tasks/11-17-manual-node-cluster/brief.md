# Brief — 多服务器人工分配与统一网关转发

## Goal

- 通过统一后台人工指定账号环境的执行服务器，分散账号运行与工程任务的资源消耗。

## Scope

- 节点登记、连接与资源状态、账号归属选择和展示。
- 远程账号环境、工程任务、终端、日志与文件操作。
- 统一网关转发及账号相关后台出站、请求诊断和用量关联。
- 空闲账号的手动停机迁移、失败恢复、节点部署和备份兼容。

## Non-Goals

- 自动调度、自动均衡、自动故障接管和管理中心高可用。
- 临时个人电脑、主动反连、跨架构执行和跨节点共享可写 HOME。
- 源节点离线时强制迁移、运行进程热迁移及跨宿主 CRIU 恢复。
- 本次交付中的线上安装、真实账号迁移、真实模型调用和软件发布。

## Technical Overview

- 中央保存账号分配和全局准入，执行节点管理本机环境与数据。现有服务器登记为默认本地节点。
- 网关选定账号后读取所属节点，经中央编排服务私有流式转接、受保护 socket 与独立 SSH 业务通道发送至节点 sender，流式响应返回统一入口。转接固定中央 origin，并核验部署、节点、环境和分配版本。
- 分配版本、环境代次和受限认证共同保护执行；节点断连后关闭新工作，恢复时先核对实际进程和记录。
- 迁移依次排空、隔离源环境、校验并导入持久资料、切换归属，再开放目标节点。

## Context & Decisions

- 首版支持长期在线、管理中心可直接访问的 Linux 服务器，沿用现有 Linux x64 执行制品。
- 节点使用 SSH 专用密钥和已确认主机指纹纳管；控制连接与业务连接分开管理。
- 账号池沿用现有令牌和会话规则，账号执行位置由管理员决定。
- 保持单一凭据刷新所有者和原 API/CLI 并发门禁；覆盖 legacy、native293、额度、预热、遥测及 OAuth 刷新路径。
- 保持两个最终镜像，增加 SSH 纳管和私有执行组件；中央 SQLite 保持权威，节点持有受限执行投影与收据。
- 方案来源为本任务 `prd.md`、`design.md`、`implement.md`。

## Risks

- 本地目录、终端和评审的耦合需要逐条适配，先通过合成账号的完整纵向链路验证边界。
- 网络分区和迁移失败依赖持久回执核对，状态未知时保持维护，避免同一账号在两个节点执行。
- 中央网关继续承接全部流量，带宽与连接容量需要独立观测。

## Acceptance

- 两个账号分别在指定节点工作，管理服务重启后归属一致，原单机环境通过回归。
- 两种请求后端完成节点可关联的 JSON/SSE 转发，取消、断连、并发、后台出站及防重复调用通过验证。
- 统一后台完成远程终端、日志和工程操作，真实资源与数据归属符合分配。
- 空闲迁移保留身份和必要持久资料，故障注入覆盖切换前后恢复与旧绑定拒绝。
- 认证、隔离、旧库升级、节点重启对账、备份和镜像兼容通过隔离验证。
- 采用合成账号与本地上游验收；线上容量和实际跨机网络表现留待部署后观测。
