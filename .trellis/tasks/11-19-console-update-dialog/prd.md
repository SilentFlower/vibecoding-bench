# 系统更新弹窗与步骤记录

## Goal

系统更新不再单独成页：版本号入口打开弹窗，在弹窗里查看版本、发布说明并安装，安装后逐步显示进度。对应父任务 `../11-19-console-ui-revamp/prd.md` 的 R4、R5，画面见设计稿 `doc/design/console-v2/mock.html` 的 `#update` 与 `#update-progress`。

## Background

- 侧栏版本号（`Dashboard.vue:112,141`）点击后打开原生 `<dialog>`，里面内嵌 `SystemUpdates.vue`（`Dashboard.vue:89-103,160-163`）；另有整页路由 `/updates`（`router.ts:49`），网关已登记该 SPA 路径。
- 现有安装流程：点「查看更新计划」后弹出确认框，选等待时长（1/5/15/30/60/120 分钟，默认 1 分钟），再点「确认执行」（`SystemUpdates.vue:154-208`）。回退、恢复走同一确认框。
- 更新器只持久保存当前阶段 `phase`，不记录经过的步骤与时间（`system_updater.py:104-111,377-380`）。宿主恢复路径会直接写 `restoring_data` / `restoring`（`system_update_host.py:1103-1110`），在途等待期间每 0.5 秒重复写入同一阶段（`system_updater.py:408-419`）。
- 子任务 1、2 已提供居中弹窗 `ModalDialog`、数字输入 `NumberInput`、确认框 `ConfirmationDialog`、徽标、图标块等组件。

## Requirements

### 前端（`apps/web`）

- **入口**：侧栏与移动抽屉的版本号、直接访问 `/updates` 都打开同一个弹窗（新组件 `ModalDialog`），撤掉整页形态。
  - 从版本号打开时地址不变，关闭后留在原页面。
  - 直接访问 `/updates` 时背后显示账号页；关闭后地址回到 `/`。
  - 按住修饰键点击版本号仍在新标签打开 `/updates`。
- **概览**（无进行中的操作时）：
  - 版本摘要：当前版本、最新版本、发布时间、最近检查，以及更新状态标签（有可用更新、已是最新、检查中、检查遇到问题、等待检查、暂无可用发行、正在执行维护）。
  - 兼容性结果：兼容 / 待核对（带具体原因）/ 目录待刷新。
  - 发布说明：取前三段，可展开完整原文，按纯文本展示。
  - 安装方式：说明会暂停新接单、预计影响的运行环境数；在途等待上限为数字输入，1～120 分钟，默认 1 分钟。
  - 上一次操作的结果紧凑显示，可进入查看。
  - 底栏：版本记录与回退、运行组件与维护详情、检查更新、安装更新。
- **直接安装（已决定）**：点「安装更新」立即登记安装最新版本，不再弹确认框。
  - 提交后等待上限锁定；网络结果不确定时，重试沿用同一操作 ID 与参数。
  - 返回 409 时在弹窗内提示现场已变化，不自动重放。
  - 回退到历史版本、从版本记录列表安装（含最新版本；列表视图看不到安装方式区）、恢复操作仍弹二次确认；回退与列表安装可调整等待上限。
- **进度**（安装后，或打开时有维护进行中 / 需要恢复）：
  - 摘要：当前版本、目标版本、操作 ID、最近更新，以及进度状态标签和实时 / 重新连接标记。
  - 步骤列表按实际顺序列出已完成 / 进行中 / 待执行；已完成与进行中的步骤显示进入时间。含数据库迁移时多出「保存数据库快照」「执行数据库迁移」两步。在途等待中的阻塞原因、节点同步进度照常列出。
  - 结局（完成、失败、已取消、已恢复原版本、等待对账、清理待重试等）沿用现有文案，错误原样显示。
  - 底栏：操作详情与数据库快照、取消等待（准备与等待在途阶段）、恢复操作（等待对账、清理待重试）。
- **二级视图**：「版本记录与回退」「运行组件与维护详情」「操作详情与数据库快照」在弹窗内切换为对应视图，带返回。现有页面的信息一项不少：
  - 可用版本列表与单条详情（发行标识、清单 SHA256、兼容原因、迁移登记、环境影响）。
  - 历史版本与回退。
  - 运行环境数量、镜像来源、CLI 与请求内核入口。
  - 操作 ID、目标发行、更新时间、数据库快照与各库迁移状态。
- **其他状态**：首次接入、读取中、检查中、检查失败、已是最新、暂无可用发行都有对应呈现；更新服务暂不可用时显示当前版本与错误。
- **断线重连**：维护期间平台切换导致断线时，弹窗保持并自动重连，沿用现有提示「平台正在切换，正在重新连接…」。
- **提示条**：新增组合组件「提示条」（`NoticeStrip`，设计稿 `.strip`）。本任务在更新弹窗使用；任务与工程页账号卡的网关凭据状态提示由子任务 6 接入。

### 后端（`deploy/flower2api/system_updater.py`）

- 操作进入新阶段时，在操作记录的 `steps` 中追加 `{phase, at}`。
  - 覆盖宿主恢复路径直接写入的「正在恢复数据库」等阶段。
  - 与上一条阶段相同的写入不重复记录。
  - 条数设上限。
- 状态与操作接口返回 `steps`；没有记录的旧操作返回空值，照常展示。

## Acceptance Criteria

- [ ] 有新版本时从侧栏版本号打开弹窗，点「安装更新」完成一次安装：进度按步骤推进，已完成步骤显示时间，结束后显示更新完成。
- [ ] 直接访问 `/updates` 打开同一弹窗；关闭后回到账号页（地址 `/`）。从版本号打开并关闭后，地址与页面不变。
- [ ] 安装提交后等待上限锁定，双击只登记一次，所选等待上限按秒提交（如 30 分钟提交 1800）；409 时弹窗内提示，不自动重放。
- [ ] 取消等待、恢复操作、回退到历史版本、查看完整发布说明、查看维护与操作详情均可完成，结果与现有页面一致；回退与恢复使用二次确认，等待上限默认 1 分钟。
- [ ] 旧操作（无步骤记录）显示正常，不报错。
- [ ] 首次接入、检查失败、已是最新、断线重连等状态呈现正确。
- [ ] 1440×900 与 390×844 下弹窗概览与进度画面与设计稿一致，附截图。
- [ ] 更新器单测覆盖步骤记录的追加、去重、宿主恢复路径、上限与旧操作兼容。
- [ ] `verify_system_update_browser.py`、`verify_update_design.py` 等依赖更新页的脚本按弹窗形态改写后通过；其余回归与改动前基线一致。
