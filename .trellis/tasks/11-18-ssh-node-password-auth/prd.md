# SSH 节点支持账号密码认证

## 目标

管理员添加 SSH 节点时可以选择用户名密码认证，现有专用私钥接入继续兼容。按用户要求采用最小范围快速完成。

## 已核实背景

- `services/orchestrator/cluster_nodes.py:113` 的 NodeCreate 强制 private_key；NodeConfiguration 存入节点 config_json。
- `services/orchestrator/cluster_ssh.py:284` 固定关闭密码认证；命令和独立转发覆盖检查、安装、Docker、sender 和 PTY。
- `apps/web/src/components/Nodes.vue` 只提供私钥输入；当前节点管理支持新增、检查、准备、接单和移除。
- `images/v3/Dockerfile:54` 的 control 目标已有 OpenSSH 客户端。
- US 的固定宿主旧模板缺少新版环境配置。两项配置的最小候选及恢复材料已经备好，实际维护等待独立授权。

## 需求

- R1：添加节点可选择 SSH 私钥或 SSH 密码，沿用用户名字段。旧请求及旧节点缺省为私钥方式。
- R2：只接受所选方式的非空凭据。密码保留空格、中文和特殊字符的原值，拒绝 NUL、换行和超长内容。
- R3：密码为只写材料，持久化到中央节点专属私有目录；目录 0700、文件 0600。公开投影仅增加认证方式，公开数据库配置、错误、日志及进程参数保持脱敏。
- R4：密码覆盖检查、安装、执行及 Docker/sender/PTY 独立隧道，服务重启后可重新连接。主机指纹校验、维护门禁及连接生命周期沿用原合同。
- R5：表单仅提交对应凭据。切换方式、成功、关闭和离开页面均清理秘密。
- R6：节点安装缺少必需中央配置时，显示脱敏的具体配置项名称；文档补充密码接入和旧宿主模板维护说明。

## 验收

- A1（R1/R2）：旧私钥及新密码请求有效；冲突材料、空密码和非法控制字符返回固定错误。
- A2（R3）：验证真实文件权限、归属、符号链接防护及登记失败清理；API/数据库公开配置和进程参数均无秘密。
- A3（R4）：隔离真实 sshd 覆盖正确及错误密码、错误指纹、特殊字符、业务 stdin、独立隧道、超时清理和重新连接。原私钥路径通过回归。
- A4（R5）：前端类型检查、生产构建及浏览器表单行为验证通过。
- A5（R6）：缺少配置返回具体配置名。运维文档明确应用镜像升级和受信宿主模板维护的边界。
