# Flower2API 多平台账号、运行环境与请求记录改造

## Goal

在现有 Flower2API 管理体验中接入 AGY 原生账号和 Google 直连，统一账号、受管凭据、运行环境及请求记录。

## Background

- 用户已完成 AGY 1.5.9 原生 Google OAuth 授权。新 CLI 进程复用持久登录态，以 gemini-3.8-flash-low 成功返回 AGY_DIRECT_OAUTH_OK；这是原生 CLI 直连基线。
- 历史原生基线目录返回18个模型档位，包括 Gemini、Claude 和 GPT-OSS。账号平台与模型类型应分别表达。
- 既有 CC runtime 将访问令牌注入业务进程，刷新令牌由凭据所有者管理。AGY 的 AT-only、常驻缓存限制和按代次工作进程已形成研究与实现合同；原规划中的接入门槛由五个子任务分层验收。
- 账号、环境及请求记录页面已有确定的视觉和交互规范，用户明确要求沿用。
- 工作基准由用户指定为 6d4253a29f7a0ee6bbadc0809d5acb570b14781f。分支为 feat/agy-account-runtime，工作树为 /root/project/vibecoding-bench-agy-account-runtime。
- 另一个窗口正在改集群化。目标基准中缺少 cluster_login_contract.py，源目录的集群未提交实现仅作为并行上下文参考。

## 本轮父任务总验收边界

- 当前交付基线为64d72ce633d26734779579c96d1d586226313ad3。五个子任务均completed/closed，其任务记录与业务实现已在当前分支交付。
- 本轮直接交付跨子任务的验收矩阵、证据清单、遗留边界及后续真实供应商验收交接，依次完成父任务Check-All、Spec评估、精确提交和Close。
- AC01—AC09保留原业务验收含义。矩阵分别表达工程验证、历史原生研究与当前产品入口的真实Google验证；父任务工程收尾不将上线后待验项标成已完成实测。
- 当前真实外部模型调用预算为0。生产迁移、部署、真实凭据操作及付费实验由后续独立授权承接。

## Requirements

### R01 平台与账号

- 显式区分 Claude Code 与 Antigravity 账号平台。
- 按账号平台选择认证、运行内核和能力；模型名独立表达。
- 现有账号迁移后保持原身份、绑定、策略和 CC 行为；历史未知值须有明确兼容处理。
- 统一管理授权、重新授权、账号状态、套餐、额度及实际可用模型。

### R02 授权和受管凭据

- 复用现有登录会话、授权链接展示、验证码提交和状态反馈体验。
- 原生登录生成的凭据进入对应账号的权威私有存储。
- 管理层作为唯一刷新所有者，按账号串行刷新并发布带代次的 AT 与到期时间。
- AGY AT-only 运行和凭据更新的具体机制，以子任务验证结果为依据。
- 新 RT 如有返回须与 AT 一起原子保存；轮换结果不确定时进入对账状态。
- 复用现有管理权限、授权和账号接口，通过平台适配接入 AGY。CC 的既有接口及凭据返回保持兼容；浏览器凭据回传的统一收口作为独立议题。日志、持久浏览器缓存和公开实验材料沿既有脱敏规则处理。

### R03 请求中刷新与并发

- 冻结每次实际尝试使用的凭据代次，并关联账号、环境、worker、请求和尝试标识。
- 凭据已在后台更新时，旧读回执保持隔离；持久化采用当前代次条件提交。
- 认证恢复参考现有 CC 单次 oauth_recovery 合同，AGY 认证失败分类按其实际上游协议验证。
- 仅在真实认证失败、同账号权威新 AT 已更新且有效、响应阶段允许重试时，允许有界恢复。
- 已开始向下游发送 SSE 后保持该流的既有终态与取消语义；模型调用及工具副作用须逐次可追溯。
- 工具等待轮次保持原工作进程、调用ID和真实结果归属，凭据换代时保留完整收尾。
- 模型、额度、遥测和预热统一服从账号凭据所有权及活动门禁。

### R04 运行环境

- 按平台管理内核、精确版本、启动、就绪、停止、恢复和升级能力。
- 同版本执行映像允许共享；账号 HOME、身份、凭据、会话及出口配置独立。
- AGY 首期技术验证固定1.5.9，原生执行体身份保持可核验。
- 内核跟随平台镜像交付；分发体积、映像池、worker和控制层内存分别记录。
- AGY 对外协议目标保持 Gemini，格式转换由下游 new-api 承担。
- 模型业务直接连接 Google 官方上游，接线与原生出站应有实际证据。

### R05 请求记录

- 统一列表展示账号平台、账号、内核版本、入口协议、请求模型与实际模型。
- 每个 HTTP 请求保留一条主记录，内部提交和重试以实际尝试关联。
- 工具回填跨 HTTP 请求以会话和工具轮关联；HTTP 响应完成与原生工具轮收尾分别表达。
- 保存真实用量、缓存和思考用量的来源口径，保留平台原始用量字段。
- 请求耗时、首包、取消、认证恢复、工具及上游错误阶段具有可追溯证据。
- 完整头体沿现有账号采集开关、管理员权限及敏感字段保护处理。

### R06 UI 与交互一致性

- 保持现有账号页、运行环境页和请求记录页的风格、布局、色彩及交互。
- 复用现有选择控件、开关、弹窗、授权步骤、分页、状态反馈和详情结构。
- 刷新保持表单草稿、焦点和已有选择；异步旧回执按账号、环境及代次隔离。
- 平台差异通过现有界面的字段和能力呈现。

### R07 AGY 系统提示词同形体替换

- 增加按 AGY 账号独立设置的显式开关，默认关闭，保持原生默认请求行为。
- 参考 /root/project/new-api/scripts/system-prompt-worker 的已研究固定同形字映射。
- 仅定位协议定义的系统提示词文本。用户消息、模型历史、工具定义、参数、结果、ID及签名字段保持原有数据。
- 固定映射需确定、幂等；普通和流式处理应一致，关闭时保持目标文本原样。
- 对实际出站系统文本的生效位置、缓存影响及 token 用量变化进行验证。
- 请求记录保存本次冻结策略、规则版本与实际生效来源，原始入站和处理后的提交副本分开标识。
- new-api 现有研究中的用户句末星号和零宽字符策略属于独立功能。

### R08 跨子任务总验收与收尾

- 逐项关联AC01—AC09、实际子任务、源码合同、有效验证及业务/任务记录提交。
- 核对跨子项交接、CC兼容、迁移/回退、工具/凭据代次和内容权限，按实际影响复用有效证据并补足缺口。
- 明确既有python-dateutil种子摘要错误的基线归属。记录真实供应商验收的授权、预算、环境与观察点。
- 工程收尾以矩阵完整、当前工程检查通过、五子项已关闭和外部待验项明确交接为标准；真实供应商结果继续沿原AC约束保留。

## Acceptance Criteria

- [ ] AC01：CC 账号回归保持原行为；AGY 账号可通过统一入口授权并形成持久私有登录态。（R01、R02、R06）
- [ ] AC02：AGY 账号调用 Claude 与 Gemini 时均选择 AGY 内核，模型能力来自实际账号目录。（R01、R04）
- [ ] AC03：单一刷新所有者、AT下发、到期前刷新与凭据代次更新有可复现实测。（R02）
- [ ] AC04：请求中刷新、旧回执、并发401、SSE已开始、工具等待和刷新中断场景均有明确且可验证结果。（R03、R05）
- [ ] AC05：真实 Google 直连的文本、SSE、工具声明和真实工具结果回填通过，原生遥测与停止排空有证据。（R04）
- [ ] AC06：跨平台筛选、详情、内部尝试及工具续轮关联准确，敏感凭据保护通过。（R05）
- [ ] AC07：新增功能沿现有视觉和交互，账号、环境、请求记录完成样式和行为回归。（R06）
- [ ] AC08：同形体开关按 AGY 账号独立保存，缺省关闭；开启仅改变系统文本，幂等、流式一致、出站证据和策略记录通过，账号间设置及异步回执保持隔离。（R07）
- [ ] AC09：旧账号、历史记录及资源配置迁移可审计；回退保存当前权威凭据与账号身份。（R01—R07）

- [ ] AC10：AC01—AC09均有可核验的工程/历史研究/上线后状态、来源及交接，父任务工程总验收完成并可追溯。（R08）

## Non-Goals

- AGY 与工程任务、养号执行的交互和适配排除在本任务范围之外。
- new-api 源码和现有渠道99配置属于外部系统范围。
- 格式转换网关和新增公共 Anthropic 接口属于后续议题。
- 账号平台以外的通用插件框架、整体 UI 换肤属于独立工作。
- 实际生产迁移、发布和付费扩量需要单独进入对应部署流程。
