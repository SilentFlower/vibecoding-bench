# 账号执行与评审串行复用资源

## Goal

让真实账号在原资源预算内按执行、评审的先后顺序完成项目任务，首次登录后无需额外配置评审资源。

## Background

- 用户认可同账号执行与评审串行，并要求接入真实账号时避免流程中途出现平台卡点。
- 执行、评审和程序验收已经实现并部署；本任务修复账号运行方式及首次接入，真实账号完整闭环尚未验证。
- 现网只读审计及缺布局拒绝的本地复现位于 `.deploy/v3-real-account-readiness-20261022/`；本任务创建时已记录 262 个既有脏文件的基线，须保留其内容。

## Requirements

下列问题来源及行号对应开工前基线 `2d5a99051a5a95600be6d7b0f1c01777d35c91d4`，用于保留修复前证据；各 R 项的目标行为保持有效。

- R1：同账号评审与其他 CLI 执行互斥，先确认已有执行停止并释放资源，再开始评审；排队时保留任务和成果。当前 `orchestrator/project_scenarios.py:1037` 优先投放评审，但 `orchestrator/project_review_runtime.py:396` 仍认领共享槽位，可与其他任务重叠。互斥覆盖跨批次、普通 Tasks、续聊和后台 CLI；无评审时普通任务之间的既有并发规则保持，不影响其他账号。
- R2：执行与评审复用账号已有资源预算，串行流程不依赖常驻划出的 512 MiB 评审份额；不提高账号或服务器总预算。当前固定划分见 `orchestrator/resource_budget.py:46`；`orchestrator/project_review_runtime.py:314` 校验预留及实际容器配置，单改批次并发不会消除此门禁。
- R3（阻断，READINESS-01）：新账号按正常登录、授权、保存流程建立环境后，可直接进入项目执行和评审，无需用户手动补布局或重建环境。现有首次登录 `orchestrator/account_runtime.py:2116` 未请求评审布局，首次角色创建才处理预留（同文件 `631`、`723`），保存登录 `2201` 保留原角色，导致首次评审受阻。
- R4：保留独立评审会话、私有评分材料和凭据边界，以及同实际模型、程序失败不可被模型放行等既有验收约束。
- R5：切换、超时、停止、额度等待和控制服务重启均保留可恢复状态；资源或进程停止未确认时不得启动下一执行或伪报释放。待评审工作须获得推进机会，不能被持续新任务饿死；排队不扣业务修正次数。
- R6：现有账号的身份、HOME、项目现场、历史及网络发送连接按原契约保留；旧布局按实际配置核验，未知或冲突状态明确受阻。不自动修改既有容器的固定限额或重新生成设备画像，旧隔离版本仍沿用显式空闲升级要求。

## Acceptance Criteria

- [ ] AC1（R1）：两个项目批次与普通 Tasks 使用同账号时，评审与任何其他 CLI 执行没有重叠；等待及结束后队列继续推进。
- [ ] AC2（R2）：在现有 1536 MiB RAM、2048 MiB 额外 swap 配置下，观测执行、评审和恢复三个阶段的实际容器状态及限制；同时运行角色的上限之和不超过账号总预算，既有容器配置未被静默改写。
- [ ] AC3（R3）：从尚未创建环境的新登录路径建立并保存账号，在同一环境完成候选、评审和结果落盘；缺少旧预留文件不会导致评审中途受阻。
- [ ] AC4（R4）：候选无法读取私有评分材料；评审使用独立会话和冻结的实际模型；程序验收失败不能被评审通过覆盖。
- [ ] AC5（R5）：覆盖切换中断、迟到回包、停止未确认、额度中断和重启恢复，既无重复执行，也无预算叠加或丢失现场；持续有候选排队时待评审仍能启动，排队不增加业务尝试次数。
- [ ] AC6（R6）：既有普通布局和旧评审布局分别验证；账号身份与持久目录保持，独立发送连接不被任务切换中断。
- [ ] AC7（R1–R6）：本地机制验证、真实模型调用、推送与生产部署分别留证，不能以模拟结果声称真实账号已跑通。

## Non-Goals

- 不调整项目内容、评分标准、账号总预算或服务器规格。
- 不新增模型供应商、独立认证所有者或绕过原额度门禁的调用通道。
- 本地开发和验证不调用真实模型、不使用既存账号凭据、不改写生产账号数据；正式推送、部署及真实账号验收按对应流程单独执行。
