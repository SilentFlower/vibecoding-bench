# 交接摘要：CLI scratchpad 迁入磁盘

## 目标

降低 CLI 临时文件的刚性内存占用，保持功能、会话隔离、历史续跑和 sender 性能。

## 范围

- 账号 scratchpad 的磁盘存储、旧数据转存及容器重建。
- 本地与指定远程节点、备份恢复、节点迁移及失败回退的兼容。

## 范围外

- 历史文件清理、sender 架构及分配器调整、跨账号映像共享。
- 线上发布及现有账号的实际迁移另按部署操作推进。

## 技术概览

- 每账号独立磁盘目录，通过带 noexec/nosuid/nodev 的私有挂载维持 `/tmp/claude-1000` 原路径。
- 旧数据在空闲排他维护中转存，校验并持久化成功后进入原重建流程。节点迁移携带文件，目标按本机路径重建挂载。

## 背景与决定

- 采用完整保留策略，维持原 session 路径、执行归属、HOME 与凭据合同。
- CLI 保持 UID1000、能力清零及只读根。普通 `/tmp` 沿用原 tmpfs。
- 本地安全挂载原型已通过禁止执行与重建读回验证。完整兼容和性能仍待实施验收。
- 现场三个养号文件合计约108.8 MiB。该数字代表预期退出 tmpfs 的数据量，磁盘页缓存另行计量。

## 风险

- 磁盘I/O、挂载元数据开销、磁盘满及旧数据转存中断。
- 节点挂载能力差异、备份文件树一致性及回退时 tmpfs 容量不足。

## 验收

- 两账号、多会话、普通任务、项目与养号的文件、暂停恢复及兄弟执行归属正确。
- 原路径文件的内容、权限、链接与历史续跑通过真实 CLI 隔离验证。
- 实际安全挂载、完整及精简备份、节点迁移和故障回退通过核验。
- 3×8 MiB合成文件退出 tmpfs，页缓存与磁盘成本单列。
- 同宿主交错重复测试 sender 吞吐、TTFT、延迟、冷启动及CPU；可重复退化的候选停止接纳。

## 下一步

补齐两账号挂载与逻辑文件树验证，随后接入原空闲维护生命周期。
