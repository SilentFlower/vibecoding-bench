# 技术设计：账号 scratchpad 磁盘持久化

## 边界与既有合同

由 AccountRuntime 管理环境，沿用 `_root(row)`、`host_data` 和现有节点归属核验。账号持久根内新增 `cli-scratchpad` 作为数据上层目录；HOME、工作区、原生 JSONL、session ID 与执行 source 维持既有映射。普通 `/tmp` 沿用当前128 MiB tmpfs，旧评审布局保持自身原限制。项目评审的独立临时环境按自身生命周期处理。

## 挂载机制

普通 bind 的 noexec 参数在本地实验中未生效。候选使用 Docker local driver 的 overlay 文件系统挂载：每账号独立空 lower、磁盘 upper 和私有 work，文件系统挂载参数固定 noexec/nosuid/nodev，容器内目标固定 `/tmp/claude-1000`。CLI 继续 UID1000、cap_drop=ALL、no-new-privileges 和只读根。

`cli-scratchpad` 是唯一持久逻辑文件树。空 lower、work 及挂载回执由管理端在 `runtime/scratchpad-mount` 持有。卷标签与选项绑定部署、节点、环境及布局协议；复用前逐项核验名称、driver、真实源路径和标签。新协议是本次拟新增的内部合同，实施时集中定义。

单容器隔离原型已验证 UID、挂载参数、禁止执行和删除重建后原路径读取，证据见父任务 `research/evidence/scratchpad-overlay-mount.json`。正式接纳前须验证实际节点内核与文件系统能力、目录及链接操作、元数据保全、退出卸载和备份恢复。能力核验失败沿用旧布局。overlay 特性若使逻辑文件树或性能合同无法满足，则停止该候选并回到设计评估。

## 旧数据转存与生命周期

1. 仅从已有显式空闲维护／更新重建入口进入；环境锁内核对节点归属、原代次、三角色、执行记录、孤儿进程和 API 活动，取得原排他维护租约。
2. 为旧 CLI 仍可读取的 `/tmp/claude-1000` 建立私有暂存。流式传输并按文件有界校验，控制导出内存峰值。符号链接作为链接保存；路径逐级拒绝逃逸、设备及未知文件类型。
3. 转存记录绑定环境、节点、源 CLI ID、源代次、源 StartedAt 和清单摘要。导出后复核源启动身份。仍在同次启动内运行的源直接沿用当前文件；重启后的实例按快照恢复，确认本次启动恢复完成后才允许下一次转存，已开始的恢复继续受待恢复记录保护。重读源清单与目标清单一致，文件及目录持久化后发布数据目录。重复执行按同一记录恢复；未知目标保留现场并失败关闭。
4. 数据完整后进入原停止／移除／创建链路。新 CLI 实际核对挂载和文件，完成时保存回执。旧布局在活动期间继续运行。普通 GET、API发送及后台预热保持既有重建边界。
5. 所有可能移除原 CLI 的空闲重建入口复用同一转存保护。审计 `_stop_environment`、布局／配额变化、系统更新、代理维护、评审交接和故障恢复路径。旧 CLI 已消失或 tmpfs 已清空时如实记录可读取状态；存在未完成转存记录时保持恢复门禁。

## 备份、节点迁移与隔离

账号数据目录属于环境树，精简及完整备份均保留。源节点在停止旧 CLI 前完成转存，原 fence 成功后才导出。`cli-scratchpad` 随环境包校验、传输和恢复。目标按自己的 host_data 和节点身份创建新卷，work/lower 由目标重新建立。

运行态排除仅包含已核验协议的 `runtime/scratchpad-mount`，数据目录始终纳入。工作目录使用 root 私有 `mount.json` 绑定协议与环境，并与持久布局记录交叉核验；未知同名目录纳入迁移包，挂载准备遇到未登记内容时保留现场并阻断。备份和迁移的逻辑树比对须覆盖修改、重命名、删除、链接和权限，验证空 lower 下磁盘 upper 与容器视图等价。任意未知 overlay 特性数据须失败关闭并保留恢复资料。完整备份即使保存运行态文件，恢复挂载仍使用重新建立的 work/lower。

同账号原来共用 CLI 与 UID1000，本次维持原 session 路径及调度归属。不同账号的 upper、lower、work 和卷完全独立，业务容器只挂本账号目标；控制回执保持 root 私有。

## 失败恢复与回退

写入或校验失败保留源 CLI 与私有暂存，阻挡删除源数据。发布后、创建前中断保留已确认数据并幂等续接。卷或容器创建失败沿原 reconcile 收口，持久目录保留。清理仅处理标签、路径和引用都核验通过的本部署卷，数据目录独立保留。

回退版本必须识别并保护持久目录。回到 tmpfs 前，在空闲排他维护中从当前文件视图完整复制并核验；容量不足则保持磁盘布局并报错。最新 HOME、凭据和画像以当前权威状态为准。

### 首次上线的两阶段兼容

- FBK-003修复采用兼容阶段和启用阶段。兼容阶段交付新布局的转存、挂载及恢复能力，账号组件内容摘要须与v1.15.3一致，保持原账号镜像和容器；候选中的私有目录工具由CLI存储模块自身持有，保持原账号镜像输入。
- 发行兼容声明增加可选整数`scratchpad_storage:1`，表示管理端具备新布局恢复能力；启用账号镜像再声明`scratchpad_activation:1`。缺少字段的历史发行保持原合同。旧解析器对新增能力拒绝，宿主执行器先沿原SOP升级能力。
- 启用阶段以真实账号镜像标签生成激活声明，更新器只接受原版已经声明scratchpad_storage=1的来源。兼容阶段完成验收后才能进入启用阶段。
- 显式切换、历史回退、可用版本和回退状态共同检查文件布局能力。启用阶段的失败恢复使用已支持新布局的兼容版本，并保留磁盘布局与最新文件。
- 若异常操作已经开始重建账号且试图恢复不支持布局的原版，宿主执行器在停止控制或重建账号前保留维护门禁并拒绝接管。兼容阶段的账号内容一致性作为首次恢复仍可使用v1.15.3的证明。
- 两阶段候选、完整范围和正式版本说明沿发布SOP展示并确认；验证期间只操作隔离资源。

## 收益与性能

预期收益为 scratchpad 从 tmpfs 退出的刚性驻留。磁盘页缓存、I/O、磁盘使用量及容器内存分别记账。overlay 元数据成本、磁盘满和同宿主I/O竞争属于接纳验证重点。保持CLI文件操作、会话恢复和sender性能是交付条件，测试通过前仅报告机制实验结果。
