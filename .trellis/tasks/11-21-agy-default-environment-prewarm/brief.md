# 反重力默认登记运行环境并持续补热

## 目标

添加 AGY 账号后即可看到环境卡片，符合条件的冷池能在业务请求前自动补出一个热进程。

## 改动范围

- OAuth 就绪时登记环境。启动和巡检补齐未登记的已有账号，包括 #16。
- 新环境首次准备，以及 #14 这类已有环境在重启、进程退出或凭据换代后的补热。页面显示实际准备状态和原因。

## 交付边界

本轮交付代码与隔离验收。线上部署沿项目发布流程。

## 技术概览

账号提交后复用编排的唯一环境绑定。后台沿账号轮转和退避调度，按实际节点与环境代次进入 AGY 发送器的零模型准备，并使用业务共用的进程池。

## 关键决定

- **环境卡片随账号登记出现。** 容器尚未启动时显示「等待准备」。控制链路短时故障后自动补登记。
- **空闲容量优先准备一个真实可接单的热进程。** 余量可供 CRIU 模板使用。后台遵守手动停止、停用、节点维护和迁移。容量满时等候，已有环境继续运行。
- **当前与另一窗口无直接文件冲突。** 另一窗口修 `messages.rs` 的轮内系统补充与缓存前缀。本次修改账号、环境和后台热准备，并共同验证 AGY Messages 与工具续轮。

## 验收

- 新账号保存后立即出现唯一卡片。存量缺绑定在启动或巡检后补齐。并发首次请求仍使用原归属。
- 用原版 AGY 隔离验证补热、CRIU 单名额及首次请求热命中。预热的上游模型提交数为零。
- 验证停用、手动停止、迁移、容量用尽、失败恢复及 Claude Code 原生预热回归。页面和发送器状态一致。
