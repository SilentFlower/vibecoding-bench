# 联合优化设计

## 边界与数据流

本轮交付在同一父任务下顺序实施两个子任务：观察效率负责 Python 等待及 Node 模型视图；attrs 验收负责合同适配与安全反馈。父任务负责两项同时启用时的集成验证。项目和工程养号复用现有实现，不新建服务、队列、数据库列或模型供应商。

观察链路：Pi 工具 → ProjectsService.tool/_observe → PiTerminal.observe → 原始完整观察落库 → ProjectsPi JSONL 管道 → Pi host 模型投影 → SDK 持久化与后续推理。页面 snapshot/events 继续读取原始完整观察，模型增量不进入页面协议。

验收链路：project_submit 冻结候选 → ProjectVerifier 核对旧观察器来源并暂存可信修正版 → 无网络隔离执行 → 校验结果及白名单类别 → ProjectsVerification 的有界反馈 → Pi 按原公开目标决定下一步。原生回归、历史能力回归及语义审查仍是通过所需阶段。

## 等待合并

首次或输入后没有可用 observation_id 时先返回真实现场；正常后续观察默认等待 30 秒，保留显式 wait_sec=0..30。新原生文本、交互事件、进程退出、quota_paused 或终端可读状态变化及时返回。对已核实的 CLI 进度/计时行消除显示噪声后，前台空闲或出现编号选择界面时，新稳定画面约一秒去抖便唤醒 Pi；没有有效变化时才合并到兜底截止。程序不根据屏幕正文判断业务完成或代替 Pi 选择菜单。原 _current 代次检查、stop 取消及本轮计时器持续生效。

钩子仅安装在本次作业的 settings 覆盖中，保留用户原钩子；PermissionRequest、明确提问/方案确认工具及回合结束只产生有界唤醒提示，不输出授权或答案、不声明业务通过。原生工具事件与稳定画面检测补充没有钩子的菜单，30 秒不再是菜单的正常响应上限，而是无有效事件时的兜底。提示按原账号/会话/执行来源核对，未知事件和陈旧事件不触发操作。若默认等待外层剩余预算更短，服从原截止时间和取消，不延长本轮。原生读取游标在等待内只向前推进，不丢失已经观察到的文本。

## 模型观察视图

完整 result 先在 Python 存储，Node 只为 claude_observe 投影模型可见载荷。增加可选严格布尔 full_screen 工具参数，默认 false；该参数只选择画面形态，等待仍由 wait_sec 决定。

Node 在本次会话保留最后一个已交付模型的完整观察基线。首次、显式 full_screen、重新启动及 fresh/摘要成功后使用 full；相同屏幕使用 unchanged；其他屏幕使用带 screen_base_observation_id 的可还原行替换片段。行替换保留原文本的换行和内容，只去掉与基线相同的首尾行，不剥离业务正文或猜测动画。差异序列化后若不比整屏短，则退回 full。所有原生新增事件、观察 ID、运行状态及必要错误仍保留。

基线只能在成功交付合法观察结果后更新，拒绝/取消/其他工具结果不更新。多个工具按实际已确认回执顺序处理；上下文摘要后清空投影基线，下一次重新交付 full。不会改写原始 Pi 历史或重发已经确认的终端输入。

## 验收适配与反馈

复用已有 schema/weighted 适配方式：已确认旧 attrs 观察器按 SHA256、script、args、python_paths 和严格 expected 形状共同匹配，只把临时入口替换为可信修正版，记录原始与实际摘要。未来内容使用同一修正版。未知版本/协议沿原严格路径，不推测改写。

修正版取消未公布的 raise_errors=1/TypeError 要求，分别检查公开合同承诺的顺序、真实对象与异常身份、一次验证/组合语义、禁用、聚合、BaseException 边界和字段不变更。多个调用的检查分别收集事实，不能因检查器自身重复调用而误判候选重复执行。

业务结果仍使用严格 candidate_import/business 布尔；仅受信观察器允许附加白名单 feedback_codes。验证器核验类别、字段与结果一致性后拆出诊断，通用结果比较不宽松化。ProjectsVerification 将已核实类别映射为公开行为说明，继续限制八项及 12 KiB 预算，不透传私有源码、任意异常正文或日志。

## 兼容与回退

没有数据库迁移，原 work/session、observation_id 输入保护、完整审计、账号/空间隔离、失败计数与 deferred 规则继续沿用。旧记录缺少投影字段不受影响，因为新增形态仅位于模型工具回执。回退本轮代码即可恢复原等待和模型视图；新有效观察器版本随内容版本冻结，已有记录不倒写。当前范围不执行发布/生产恢复。

## 验证与风险

用保存的时间/屏幕摘要/原生事件数量回放合并决策，另用合成真实文本验证可还原差异和输入字节；不能把记录时点的重放当作连续线上调度或未来收费预测。真实钩子标记、无钩子菜单、显示噪声、文本到达、停止/超时、代次变化、摘要与混合工具回执须分别覆盖。验收的合法候选与故意违反公开合同的反例必须同时通过期望验证，防止从误拒绝变成误放行。

## 实施收敛

忙碌期间的流式正文也会造成频繁变屏，因而只在交互信号、正式原生文本、状态变化或无有效变化兜底时返回；没有忙碌指示的新稳定画面，以及与后台进度共存的编号选择界面，使用约一秒去抖快速返回。提示只包含事件、来源、会话和标识，不保存完整钩子输入。恢复执行时清除旧 observation_id，重新取得现场后才允许输入。
