# Pi 指挥用量与验收反馈联合优化

## Goal

联合减少 Pi 无有效业务变化时的模型请求与重复上下文，并修正已确认的 attrs 验收合同偏差，使项目与工程养号依据可靠反馈推进。

## Background & Decisions

- 用户先确认等待合并、观察增量和验收合同/反馈三项建议，再要求三项一起实施。在完整联合 Brief 展示后，用户进一步确认采用交互事件立即唤醒 Pi 的方案，解决菜单延迟；此批准覆盖既定三项联合优化。交付范围为本地代码、验证与规范，当前未要求发布或变更生产任务。
- 2026-10-26 12:06 的账号 8 样本：同一约十二分钟目标 Pi 主指挥 355 次、Claude 原生 46 次；341 次观察中 316 次无新原生文本，315 次仅屏幕变化，间隔中位数 2.009 秒。来源：`.deploy/pi-request-usage-audit-20261026/report.md`、`polling.json` 与 `details.json`。
- `orchestrator/projects.py:1831` 的 `_observe` 将任何屏幕变化视作立即返回条件；`orchestrator/pi_terminal.py:283` 读取 tmux 完整画面；`images/pi-agent/host.mjs:194` 将完整工具结果送入模型。
- attrs 目标 `AT-VALIDATION-REPORT-DEV` 的私有观察器在 `project_library/projects/attrs/verification/AT-VALIDATION-REPORT-DEV-observe.py:28` 要求 `raise_errors=1` 抛 TypeError；公开合同只承诺可选聚合异常。线上精确候选已在本地复现该失败，六条公开回归全部通过，不能因此声称完整验收通过。
- 项目与工程养号复用同一 ProjectsService/Pi/验证器，必须同步生效。页面快照、原始观察、原会话、输入事实和累计用量保留。
- 记录时点的规划回放可把 341 次观察合并为 39 次；若其他调用保持不变，模型调用由 355 次估计为 53 次。该结果只评估原等待合并，未计后续新增的交互/画面快速唤醒，仅支持方案选择，不代表实现验收或真实费用，来源为 `research/planning-replay.json`。

## Requirements

- R1：等待期间合并纯屏幕变化，优先响应新原生文本、执行退出、额度/取消等状态；默认等待三十秒，首次或输入后观察可立即取得现场，显式零等待保留。交互钩子及原生提问信号在一个本地采样周期内唤醒；纯画面采用约一秒的稳定变化检测补充，三十秒只作无有效变化兜底。保留原总预算、代次和输入确认约束，菜单答案由 Pi 决定，检测程序不自动授权。
- R2：Pi 默认接收新增原生文本和有明确基线的画面增量；首次、恢复、摘要之后或按需读取完整画面。无变化不重复发送整屏；页面与持久审计仍取得原始完整观察，真实变化可还原。
- R3：按已公布合同修正 attrs 业务验收，检查真实功能而非新增严格 bool 参数要求；现有已冻结目标采用精确来源核对的运行时适配，未来目标使用修正版。合法实现应通过业务检查，违背公开需求的实现仍失败。
- R4：对该业务矩阵提供有界、白名单化、可定位的失败类别；原始日志与私有断言保留私有。旧结果留档，当前三次失败、冷却及依赖证明策略继续适用。
- R5：分别记录模型调用、观察返回及模型可见体积，用确定性回放和 mock 上游验证开销下降，不用真实付费请求获取性能证据。

## Deliverables

| 子任务 | 负责范围 | 对应需求 |

两个子任务按上表顺序实施，父任务负责联合验收。树结构不是并行代理或依赖调度；不启动额外代理。

## Acceptance Criteria

- [x] A1 / R1：连续纯屏幕变化不使已请求的三十秒等待每两秒返回；新文本、退出及额度异常及时返回，取消和代次变化拒绝后续输入，交互事件在一个本地采样周期内可见，无结构化事件的新稳定菜单在约一秒去抖后可见；模型响应耗时另计。
- [x] A2 / R2：首次/重新启动/摘要后得到完整画面，差异带基线，可恢复为原画面；相同画面不重复发送。按需完整读取有效，页面快照与原始观察不变。
- [x] A3 / R3：线上精确候选在隔离本地通过修正后的业务矩阵与六条公开回归；另有顺序、异常身份、聚合、禁用、一遍验证等反例被拒绝；不能跳过原生和历史回归来记通过。
- [x] A4 / R4：冻结旧脚本字节未改写，适配记录原始/实际摘要；未知版本不被猜测适配；具体反馈不泄露私有源码、原始异常正文或任意诊断字符串。
- [x] A5 / R5：确定性回放报告模型唤醒次数及载荷字节下降，模拟上游请求计数与 usage 一致，无请求的等待不产生 usage。以样本由 355 次下降至几十次为优化目标，不承诺真实费用或所有业务的固定降幅。
- [x] A6 / R1–R5：项目与工程养号、终端菜单/多行输入、重复投递、停止/恢复、摘要、通过/暂存收尾及原有适配器回归通过。

## Non-Goals

- 本轮不发布、部署、重启或主动恢复生产任务，不发起真实模型/额度探测。
- 不换模型、调整价格或摘要阈值，不引入任务队列/新依赖，不批量重写全部项目观察器。
- 不降低原测试/覆盖率要求，不更改候选业务实现、账号身份或历史提交。
