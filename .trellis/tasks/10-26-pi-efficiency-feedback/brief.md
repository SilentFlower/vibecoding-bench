# Brief — Pi 指挥用量与验收反馈联合优化

## Goal

- 同时减少 Pi 空转请求和重复上下文，并让 attrs 按公开合同给出可靠验收反馈。

## Scope

- 项目与工程养号共用的交互事件唤醒、等待合并、模型观察增量与按需完整画面。
- attrs 新旧目标的验收合同修复、精确冻结适配、具体失败反馈及反例验证。
- 两个子任务合并执行最终联合检查。

## Non-Goals

- 本轮不部署、重启或解锁生产目标，不使用外部付费模型验证，不修改候选业务实现或历史结果。

## Technical Overview

- 本地监听钩子和原生提问，交互事件立即返回；前台空闲或编号菜单的有效画面约一秒去抖，忙碌进度合并，无有效变化才三十秒兜底。Pi 获得可还原增量，页面和审计保留完整事实。
- attrs 旧冻结观察器仅经精确来源核对使用受信副本，严格校验结果和反馈枚举，再投影公开行为说明。

## Context & Decisions

- 完整联合方案及交互事件立即唤醒决定已获本轮用户确认，两个子任务在相同范围内实施。
- 当前实现的历史记录回放将 341 次观察合并到约 52 次；若其他调用不变，估计总请求约 66 次。真实模型费用与生产表现仍由发布后观察确认。

## Risks

- 固定 CLI 版本的钩子、编号菜单和忙碌显示均有本地回归；其他终端形态不能据此承诺相同延迟，模型接口推理耗时另计。

## Acceptance

- 交互即时唤醒、菜单快速响应、无效等待不发额外模型请求；完整观察、输入去重、停止/恢复和上下文基线正确。
- 原候选实现通过旧冻结适配业务矩阵、六项公开回归和原生回归；真实错误反例、未知来源及错误诊断协议仍被拒绝。
- 双空间、真实 Pi SDK、镜像分发路径与完整通过流程通过联合 Check-All。

## Next Step

- 本地实现、联合检查与规范同步已完成；等待联合 Git 计划确认后提交、推送，并按子任务到父任务的顺序同步完成态。
