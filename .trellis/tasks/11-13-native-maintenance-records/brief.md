# Brief — 修复预热维护恢复并优化更新与请求记录

## Goal

- 修复更新期间预热误报，并让更新确认和请求账号识别更直接。

## Scope

- 原生预热的维护状态、恢复调度及环境页说明。
- 更新确认默认一分钟及前后端默认值、文档同步。
- 请求记录列表、详情和各次重试的账号名称、邮箱展示。
- 将本次业务推送与 v1.3.1 正式发布合并交付，核对签名、附件与更新目录。

## Non-Goals

- 部署、线上配置变更和真实模型调用。
- 原生发送栈、CRIU 实现、账号并发容量和历史账号名称快照。

## Technical Overview

- 维护准入区分合法维护和真实故障；维护等待进入独立恢复队列，每秒核对门禁，开放后重新入队。
- 更新确认与后端缺省期限统一为 60 秒，原操作继续使用已冻结期限。
- 诊断接口读取时关联当前账号名称和邮箱，页面统一展示，内部关联继续使用实际 ID。

## Context & Decisions

- 按预热修复、默认等待、账号展示三个子任务顺序推进，各自验证和交付；本次整体评审覆盖上述三项范围与验收。
- 维护等待与真实故障退避分别处理；未知或损坏门禁继续进入错误路径。
- 一秒表示恢复入队的检测周期，实际 ready 还包含排队及本地初始化。
- 账号名称与邮箱使用当前资料；资料缺失时明确提示并提供 ID 追溯。跨账号重试按各次实际账号展示。
- 新增诊断读取仅查询名称和邮箱等安全字段，沿用现有管理员鉴权。
- 用户追加要求新版发布与本次 push 一起执行，沿现有正式发布 SOP 完成；发行源码绑定本次业务提交，发布验收后写回任务完成态。

## Risks

- 门禁反复开关与晚到回执需要覆盖竞态，原队列和并行上限保持有效。
- 删除账号、旧记录与长邮箱需要兼容验证，手机布局须保持可读。

## Acceptance

- 维护期间显示等待且失败计数不增加；开放后一个检测周期内重新入队；真实故障保留退避。
- 安装及回退确认每次默认一分钟，直接提交 60 秒；显式选择、取消、重试与原操作恢复通过回归。
- 桌面及手机列表、概览、链路、性能和尝试选择器显示对应名称邮箱；缺资料与未选账号有明确降级。
- 网关、调度器、前端构建及合成浏览器场景验证通过，三个子任务完成后汇总集成验收。
- v1.3.1 正式发行及原信任根验签通过，附件摘要、双库兼容证据和两个更新目录核对通过。

## Next Step

- 完成新增版本元数据验证，合并执行精确推送和正式发布，验收成功后关闭任务。
