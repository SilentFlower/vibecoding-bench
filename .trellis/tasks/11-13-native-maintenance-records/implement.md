# 执行计划

1. 收敛父子任务材料并刷新 Brief，完成开工评审。
2. 激活预热子任务，执行 before-dev、实现和聚焦验证。
3. 激活默认等待子任务，按其 Brief 实现和验证。
4. 激活账号展示子任务，按其 Brief 实现和验证。
5. 三项实现完成后激活父任务，执行跨子任务集成验证并汇总证据，统一完成 Check-All、Spec 和精确 Git 计划评审。
6. 按用户追加指令准备 v1.3.1 元数据，执行版本合同、发布入口定向测试与前端构建，合并刷新精确 Git 及发布计划。
7. 业务推送成功后执行 `gh workflow run v3-release.yml --ref flower2api -f publish=true`，冻结实际业务提交，核对工作流来源、发行附件签名与摘要、双库兼容证据以及两个更新目录。
8. 正式发布验收通过后分别写回三个子任务的进度与 Close，再完成父任务集成记录及 Close，精确提交并推送任务记录。

## 集成验收

网关完整 cargo test、cargo fmt --check；Vue 生产构建；真实产物的环境页、更新确认和请求记录浏览器场景；受影响调度器 Python 测试。仍适用的成功证据直接复用，实际变更后补跑受影响验证。

## 边界

保留任务创建时已有的 402 个文件。Git 操作沿精确计划审批。三个子任务 Close 后完成父任务生命周期写回。

发布失败按实际工作流与发行状态恢复，保留已经成功的业务推送和附件事实。父任务完成以正式发布验收成功为前提。

## 执行安排

本次三项范围已经整体批准；聚焦实现按子任务分开归属，最终检查与精确 Git 计划合并呈现。各子任务验收和 Close 独立记录。该安排保持既定目标、范围和验收。
