# 修复原生预热维护恢复并优化更新与请求记录

## Goal

消除平台更新期间原生预热的故障误报，并减少更新确认和请求账号识别的操作成本。

## Background

用户观察到 v1.3.0 更新后环境卡片先显示“本地准备失败”，随后自行恢复。本次明确要求修复该问题、默认等待一分钟及账号名称邮箱展示。此前只读时间线与代码检查指向维护准入错误被计入预热失败退避。

## Requirements

| ID | 需求 | 子任务 |
| --- | --- | --- |
| R1 | 平台维护期间显示预热等待，维护结束及时恢复；真实故障保留失败与退避。 | 11-13-native-prewarm-maintenance-recovery |
| R2 | 更新确认默认一分钟，允许继续选择其它期限。 | 11-13-system-update-default-minute |
| R3 | 请求记录列表、详情与重试显示对应账号名称和邮箱。 | 11-13-diagnostic-account-display |
| R4 | 按用户追加指令，将本次修复推送与正式补丁版本发布合并执行。 | 父任务交付 |

父任务负责需求来源、子任务映射及最终集成验收。子任务各自规划、实施、验证与 Close。

## Acceptance Criteria

- AC1 → R1：维护不累加失败；有效门禁开放后一个一秒检测周期内重新入队，执行沿原并发上限；损坏门禁保持拒绝准入。
- AC2 → R2：安装与回退每次打开默认一分钟，直接提交 60 秒；显式选择和原操作冻结参数保持。
- AC3 → R3：桌面、手机、各详情页签及尝试选择器显示实际名称邮箱；资料缺失有明确提示与 ID 追溯。
- AC4：三个子任务各自验证和 Close 后完成集成验收，测试使用合成数据及离线服务。
- AC5 → R4：本次修复发布为 v1.3.1；正式发行绑定实际业务提交，签名、附件摘要、双库兼容证据和两个更新目录验收通过后完成父任务。

## Out of Scope

部署、线上设置变更、真实模型调用、发送栈及 CRIU 模板改造、并发容量变化、历史账号名称快照。
