# V2 思考签名恢复设计

## 发送与所有权

V2 Gateway 在 `GatewayService` 的 `tui_v2` 分支完成原工具续轮登记、`prepare_tui` 和 `SchedulingRequest::admit`。Rust `TuiSender::send` 在原 Unix 连接上消费持久预留，Python `_Actor.serve_model` 认领一个模型步骤。上游返回非成功状态时事件源仍处于交付首帧之前。这是兼容检查的入口。[V2 Gateway](../../../services/gateway/src/service/gateway.rs#L2669) · [发送器](../../../services/gateway/src/service/tui_sender.rs#L783) · [事件源](../../../images/account/tui_session.py#L630)

1. 在 Gateway、发送器和事件源的既有私有握手协商恢复能力。为本轮冻结初始发送策略、真实会话摘要的命中结果和截止时间。旧侧按现有响应协议处理。原会话派发、`prepare`、`send` 和工具认领仍各完成一次。
2. 事件源取得可信实际提供方的首个 HTTP 错误后，在 `actor.abort` 之前等待恢复决定。完整、符合 V1 判据且可做实际降级时，通过原受信连接通知 Rust 发送器。发送器向 Gateway 交付带私有恢复信号的首个 400，保留同一活跃预留和事件源连接，等待本次决定。控制信号仅由已核验的发送器侧生成。错误体完整性由实际提供方读取结果判定。
3. Gateway 保留首个错误，依据既有发送准入和账号活动门禁申请同账号额外一次发送。恢复控制沿原 sender 私有鉴权，携带原预留与独立尝试 ID。远程账号经编排节点中继的精确 POST 白名单，沿原绑定、代次和排空检查转发。发送前重新核对主体、账号、环境代次、会话、预留、活动状态和截止。发送器在活跃预留内原子消费恢复许可，将决定交给原模型步骤。拒绝许可、过期或连接关闭时唤醒原轮，沿原错误清理并释放资源。
4. 事件源复用同一次持有的凭据、出站会话和模型，只于提交上游模型前替换修复后的正文。第二次响应复用原流转发或 JSON 聚合。确认二次提交后的断线保持提交未知。成功或明确拒绝分别沿原传播路径，首个 400 留在内部诊断。并发、重复控制与迟到决定通过同一个恢复状态收口。原预留的防重放记录持续有效。

## 正文、诊断与历史

- 将 V1 判据与 thinking-only 清理提成可共享的 Rust 协议函数。使用同一个已认证的 sender 处理最终出站副本，包含受管账号和本地开发提供方。必要的正文传递留在本地私有连接上。清理发生在原生会话映射和已冻结的请求策略之后。保留未受影响的消息、工具字段和工具参数精度。固定 V2 原生格式携带 CCH 时复用现有计算规则，长度以实际发送内容为准。[判定](../../../services/gateway/src/service/native_signature_repair.rs#L109) · [清理](../../../services/gateway/src/service/gateway.rs#L7944) · [CCH](../../../services/gateway/src/service/rewriter.rs#L2747)
- 首个 400 在取得实际发送证据时单独收口。追加已准入发送时记实际开始，各用独立 ID。可信发送观察贯穿原请求、实际账号和尝试。满足现有开关时按尝试提供脱敏采集，缺少对应的观察时保留缺口状态。正文和错误中的私有控制信息由服务端消费。[现有诊断入口](../../../services/gateway/src/service/diagnostics.rs#L539)
- 复用 `NativeSignatureRepairs` 的真实会话与原始思考历史前缀。收到本轮可信修复成功证据才记入。命中结果随下一轮私有能力信封进入发送器，在生成上游正文副本时生效。原工具指纹和会话归属继续使用原入站内容。延用进程内存、有效期与容量，无需持久化正文。
- 失败轮释放预留后，同会话的新轮可以恢复原生日志。CLI 2.1.293 可能合并相邻用户行，把本轮标记放入紧随的系统消息。认领时核对合并后最后一个文本块的提示摘要，以及后续系统消息中唯一独立的本轮标记行。

## 兼容与可观测项

- 新旧网关、发送器和事件源共存时以当前已协商能力为准。旧节点中继明确返回发送前拒绝时，Gateway 交付首个 400，通过原取消路由释放预留。关闭新能力后进入普通单次发送，正在等待的原轮按其冻结协议收口。
- 回环模型可看到明确的 400 和一份变更后的正文。建议使用实际模型收包和真实进程身份判断两次出站以及工具交付。等待首次错误和重试可能增加首包时延。正文变化可能影响提示缓存。
