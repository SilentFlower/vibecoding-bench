# 为 Claude V2 兼容思考签名 400

## 目标

Claude V2 遇到明确的上游思考签名 400 时，能在原交互轮内降级重试一次，让客户端继续当前对话和工具续轮。

## 当前行为

V1 已实现同账号降级重试和失效历史记忆。V2 在上游 HTTP 错误到达时结束原交互轮，随后交付错误。原工具续轮绑定已认领的预留和进程。[V1 恢复](../../../services/gateway/src/service/gateway.rs#L4479) · [V2 错误收口](../../../images/account/tui_session.py#L208) · [网关轮次登记](../../../services/gateway/src/service/gateway.rs#L2837)

## 需求

- R1。覆盖 V2 公开 Messages 的普通 API、原生输入、首轮及工具续轮，支持流式和非流式。只有首次上游 HTTP 400 的完整错误体符合 V1 的明确思考签名拒绝判据，且正文可降级且原时限有余量时，才取得一次额外模型发送许可。交付最终一次响应。无法取得许可时交付首个 400。普通 400、本地错误、提交未知及已开始输出的错误沿各自的原路径收口。
- R2。沿用原账号、实际出站会话、模型、现有代理及 TLS 发送路径。一次预留关联同一个交互进程和工具登记。降级仅作用于出站副本，工具声明、调用 ID、参数和结果保留。历史思考按 V1 转文本，移除已隐去的思考块、顶层 thinking 和相应依赖。降级后的原生请求以实际出站正文刷新已有 CCH。
- R3。已取得成功的修复复用 V1 的会话历史摘要。下轮同一真实会话携带失效思考签名前缀时，首发前应用同一降级。缺少真实会话时兼容限于本次请求。修复失败时保留当前摘要状态。
- R4。同一个公开请求下按实际模型发送记录尝试，包含首个 400 和重试结果。第二次尝试标明签名修复。采集和诊断遵循现有脱敏和授权边界，最终响应沿用 Messages 协议。
- R5。新组件通过私有能力确认启用恢复。混合版本组合继续交付原有单次发送结果。私有恢复按预留、实际尝试及原绑定核验，重复、过期及跨归属的指令在提交前拒绝。

## 范围

本轮涉及 V2 Gateway、账号发送器和事件源。V1 与 legacy 作为回归基线。交付验证使用隔离的回环模型，线上发版、原版出站对照及上游风控验证属于独立工作。

## 验收

- [x] A1（R1、R2）。普通和原生首轮覆盖流式、JSON 的 400 后成功。两次实际模型收包相同账号、出站会话和模型，客户端收到最终响应，正文差异符合降级规则。
- [x] A2（R1、R2）。已绑定工具组的续轮触发恢复后，原进程完成同一轮，对照工具回执入账与交付各一次。再次返回 400 时交付第二个 400，原轮收口。
- [x] A3（R1、R5）。普通 400、错误体不完整、提交结果未知、已开流、过期、跨绑定、重复控制及混合部署均核对实际发送次数与轮次清理。已取得完整签名 400 且在申请二次许可时耗尽时限，交付已取得的 400。
- [x] A4（R3）。成功后的真实会话命中原前缀时首发一次。缺少真实会话、不同历史和失败修复各自独立判断。失败后重开的同一原生会话按新轮判定。
- [x] A5（R2、R4）。核对出站正文、Content-Length、已有 CCH、两次出站诊断及独立尝试 ID。正常未触发请求与两条原有后端通过回归。
