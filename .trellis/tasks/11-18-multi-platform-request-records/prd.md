# 多平台请求记录与端到端回归

## Goal

让管理员在现有请求记录页追踪CC与AGY每次HTTP请求的实际执行、用量、策略和工具收口。

## Background

- 承接父任务R03、R05、R06、R07及AC04、AC06—AC09。账号、凭据、运行环境和同形体依赖已完成；当前基线c0c9122e，最近业务提交8348b09b。
- 既有诊断已具有根请求、发送尝试、七天保留、管理员查询、内容采集和四页签详情。当前入口限于/v1/messages；AGY Gemini已有源事件与私有采集材料。
- 用户已确定AGY接入现有体系、沿用现有页面风格和交互。账号平台与模型类型分别表达。工程任务、养号、new-api和真实生产操作保持父任务边界。
- 权威凭据交接为../11-18-agy-managed-credential-contract/research/credential-contract.md；同形体事件来源及实际代码锚点见research/current-contracts.md。真实外部模型调用预算为0；工程验收使用合成身份、独立数据库、断网原版与本地TLS。

## Requirements

### RR01 请求与实际尝试

- 已鉴权的CC messages与AGY Gemini生成请求进入同一请求记录体系，每HTTP一条主记录；目录、后台遥测、预热及独立工具收口操作不计为新的模型请求。
- 内部提交及认证恢复按真实尝试关联。准备阶段拒绝保留根记录与阶段，零发送时尝试数为0；提交状态未知保持可见。
- 冻结平台、入口协议、请求模型；按尝试记录账号、内核及版本、实际提交模型、源响应模型、环境/worker及凭据代次。AGY调用Claude模型仍属于AGY平台。
- HTTP完成、模型尝试完成和原生工具轮收口分别表达。工具下一HTTP关联原请求及原工具，原轮收口更新保持原HTTP结果和耗时。

### RR02 用量、性能与结果

- AGY用量采用实际源usageMetadata，区分输入、输出、缓存、思考及总量；保留有界的平台原始用量及来源/完整性。未知保持未知，真实0保留0。
- 与CC口径不同的字段明确标注；累计源帧不重复求和，跨尝试独立保留，不把重试合计冒充末次用量。不新增AGY价格或费用估算。
- 响应头耗时、首次有效输出、HTTP总耗时、实际尝试耗时分别有来源。取消、截止、流内错误、认证恢复及原生终态阶段可追溯。
- 成功采用现有AGY源终态加控制终态合同，部分文本或单独usage保持实际完整性。诊断故障只产生可见缺口，不改变模型提交、重试、工具副作用、字节、许可或截止。

### RR03 策略与采集

- 展示本HTTP冻结的同形体开关、规则版本、资源身份、实际处理来源、changed和替换数。开启但无替换与真实替换分开表达。
- 原始HTTP逻辑入站、已解码Gemini输入和Cortex原生提交分别标明表示及来源。头体仅按同次日志模式、账号采集策略和管理员权限读取，脱敏、截断、缺失、过期及失败保持可见。
- 原生提交视图与最终Google TLS线字节保持证据边界；当前未采集阶段显示未观测。完整凭据、Cookie、工具参数及正文不进入默认诊断摘要。
- 沿七天及账号容量边界保存私有证据，活跃工具与进程归属保护；读取不唤醒环境，拒绝跨请求、跨账号、路径穿越及链接文件。

### RR04 现有页面与筛选

- 在现有列表和概览/请求链路/性能/原始数据详情中接入AGY；沿用ChoiceSelect、账号选择器、Dialog、Pagination及状态反馈。
- 平台、账号、入口协议、内核版本、请求模型和实际模型支持服务端筛选；计数与分页保持同一过滤范围。既有时间、结果和关联ID组合继续有效。
- 保持草稿、焦点、分页选择与异步归属；切换请求/尝试、关窗、离页使迟到回执失效。390px保留核心信息与详情入口。
- CC原历史字段、采集视图及行为兼容；缺失的新事实显示历史未记录，不用当前账号配置补写旧事实。

### RR05 持久兼容与交付

- 诊断扩展以追加结构和可缺省字段兼容历史。筛选索引及迁移覆盖SQLite与PostgreSQL，冻结已登记迁移摘要。
- 迁移、旧程序读写、重复执行和回退演练仅在独立测试库执行，保留当前权威凭据、账号身份与已完成请求。
- 形成跨子任务场景证据，区分HTTP/SQLite替身与固定原版本地TLS验证。生产身份、Google实际到期、真实缓存/计费留待独立授权和预算。

## Acceptance Criteria

- [ ] RRA01：CC历史及新请求、AGY普通/SSE请求在既有页面可查，每HTTP仅一条根记录，平台/协议/内核/模型来源正确。（RR01、RR04）
- [ ] RRA02：准备拒绝、提交未知、401有界恢复、取消、截断和容量失败的尝试数、阶段和终态准确；诊断故障注入保持原业务行为。（RR01、RR02）
- [ ] RRA03：工具往返跨HTTP关联原请求、worker和凭据代次，旧轮实际收口单独可查，原HTTP结果保持。（RR01）
- [ ] RRA04：源用量、缓存/思考、真实0与未知、重复帧和多尝试口径准确；耗时与首输出分开，CC统计回归通过。（RR02）
- [ ] RRA05：两账号策略隔离，认证恢复沿原快照，后续HTTP沿新快照；原始/提交视图来源及实际处理回执一致。（RR01、RR03）
- [ ] RRA06：info、debug、采集关闭、超限/过期/缺失/故障、管理员权限和跨归属读取通过；公开摘要及预览敏感保护通过。（RR03）
- [ ] RRA07：六类筛选与既有结果/时间/关联条件组合、全量计数、分页、旧记录及桌面/390px交互回归通过。（RR04）
- [ ] RRA08：双库历史升级、重开连接、重复迁移和旧程序兼容演练通过；追加合同与制品来源登记一致。（RR05）

## Non-Goals

- 重构CC执行协议、调度、凭据所有权、费用定价、工程任务或养号。
- 新建另一套请求记录页面、整体换肤或接入任意第三方平台插件框架。
- 改写new-api、渠道99、Cloudflare，或新增公共Anthropic转换接口。
- 在当前任务新增AGY生产TLS旁路探针、执行生产迁移/发布、使用真实凭据或产生真实外部模型费用。
