# Topic 自然提示词变体

## Goal

降低默认 topic prompt 在批量运行中的固定前后缀和同构表达特征，同时保持题目语义、实验可追溯性和正式 benchmark 的可比性。

## Background

- 当前 `build_topic_prompt()` 对所有 topic 固定输出“题目 / 分类 / 描述 / 可运行 MVP / 启动验证取舍”五段式文本，批量运行时容易形成稳定语言特征。
- `topics.md` 中大量描述采用“支持 A、B、C”式单句功能清单；本任务不重写 600 道题正文，优先解决公共包装模板的重复特征。
- 当前所谓随机出题仅随机批次执行顺序，不随机 prompt 表达。
- `tasks.prompt` 与 `task_batch_items.prompt` 已保存实际任务文本，因此无需仅为复现能力新增 prompt 正文存储。
- 养号链路目前会先在 `_create_task_and_run()` 内生成并保存 prompt，随后在 `trigger_account()` 中再次生成下发文本；固定模板下两者相同，引入随机变体后会产生“数据库记录与实际下发不一致”的缺陷。
- 历史决策要求参赛 prompt 保持轻量，超时、权限、网络和收尾策略继续由 harness / worker 负责，不回填到 topic prompt。

## Requirements

- 提供语义等价的规范 prompt 与多种自然表达模板，避免所有默认任务共享完全相同的表头、前缀和收尾句。
- 普通单任务、批次和养号默认使用自然模式；抓包运行默认使用规范模式。
- 单任务、批次和抓包表单允许显式选择自然或规范模式，正式横向 benchmark 使用规范模式。
- 自然模板只改变信息组织和措辞，不新增技术栈、架构、依赖、超时或实现策略要求。
- 每次任务只生成一次 prompt；创建后复用已持久化文本，确保数据库记录、worker 下发和后续查看完全一致。
- 自定义 `prompt` 覆盖继续原样优先，不参与自然模板处理。
- 不修改 `topics.md` 的 600 条题目正文，不引入运行时 LLM 改写服务。
- 相关公共函数、请求 DTO 和公共接口变更必须保留中文 Javadoc/Docstring，参数和返回值说明完整。

## Acceptance Criteria

- [ ] 默认生成器至少提供 5 种结构明显不同、语义等价的自然表达模板。
- [ ] 规范模式继续生成稳定文本；同一输入重复调用结果一致。
- [ ] 自然模式生成的最终 prompt 会在任务创建时持久化，worker 不会再次生成不同文本。
- [ ] 单任务、批次、养号和抓包四条创建链路按最终范围使用正确模式。
- [ ] 单任务、批次和抓包 WebUI 均可选择自然或规范模式，默认值分别与后端 DTO 一致。
- [ ] 自定义 prompt 覆盖在单任务、批次和抓包链路中保持原样。
- [ ] 单元测试覆盖模板集合、规范模式稳定性、自然模式持久化一致性和自定义覆盖。
- [ ] 不需要改动现有 topic Markdown 解析及远程题库同步契约。

## Out of Scope

- 为每道 topic 人工编写多份独立需求文案。
- 使用外部模型实时改写 prompt。
- 改写 worker 的超时收尾、认证恢复或工具权限提示词。
- 为历史 task/run 回填 prompt 变体元数据。
