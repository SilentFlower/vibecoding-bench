# Topic 自然提示词变体

## Goal

降低默认 topic prompt 在批量运行中的固定语言特征，同时保持题目语义、实验可追溯性和正式 benchmark 的可比性。

第二阶段 `natural-v2` 进一步消除少量整段模板和固定收尾句的指纹，使自然模式更接近真实用户提出编程需求时的表达差异。

## Background

- 第一阶段已经提供 `natural` / `canonical` 两种模式、三个 WebUI 选择控件和单次生成持久化契约。
- 当前自然模式只在 6 个完整模板中随机选择，虽然去掉了固定五段式表头，但仍会重复“当前目录、启动、验证、取舍”等相似尾部结构。
- worker 在 `images/worker/entrypoint.sh` 中原样注入 `TASK_PROMPT`；项目规范明确禁止 worker 追加 bench 完成协议，因此自然 prompt 自身仍需保留完整交付语义。
- `tasks.prompt` 与 `task_batch_items.prompt` 已保存实际下发文本，并可通过 `topic_id` 关联标题、分类和描述，无需新增 schema 即可构造近期语言指纹。
- 题库现有 21 个分类稳定写入 `topics.category`，适合归并为少量表达风格，不需要逐题维护文案。

## Requirements

- 保留 `natural` 与 `canonical` 两种 API 模式及现有默认值；不新增第三种用户可见模式。
- `natural-v2` 不再从少量完整模板中选择，而是独立组合分类语气、题目信息顺序、交付要求和结果说明等片段。
- 每个自然候选都必须包含标题、分类、描述，并表达“在当前工作区交付可运行版本、说明启动方式、说明验证结果、说明主要取舍”四类语义。
- 根据题库分类选择少量稳定的表达风格，例如工程/命令行、产品/协作、数据/AI、创意/教育；未知分类必须使用自然的通用回退。
- 自然模式一次生成多个语义等价候选，与近期已持久化 topic prompt 的归一化语言指纹比较，选择最大相似度最低的候选。
- 指纹归一化必须替换标题、分类和描述等 topic 专属内容，再统一空白与标点，重点比较公共包装措辞。
- 近期样本只读取现有 `tasks.prompt`、`task_batch_items.prompt` 及关联 topic 信息；读取路径不需要 `_db_lock`，不得新增数据库列、迁移或外部服务。
- 同一批次内已经选中的自然 prompt 必须立即加入后续 item 的比较集合，避免一次批量创建出现连续同构表达。
- 相似度历史必须使用固定长度滑动窗口；批次创建只读取一次 SQLite，并复用预计算的 n-gram 集合，禁止随历史量或批次长度退化为无界比较。
- `canonical` 输出必须逐字保持现有稳定文本，自定义 `prompt` 覆盖必须原样优先且不读取相似度历史。
- 每个任务仍只生成一次最终 prompt；数据库记录、调度 payload、批次恢复和详情查看继续复用同一字符串。
- 不修改 worker 的原样注入规则，不把超时、认证、工具权限、网络或收尾协议写入 topic prompt。
- 相关公共函数和接口变更必须保留中文 Docstring，参数和返回值说明完整。

## Technical Notes

- 相似度采用本地、确定性的字符 n-gram 集合比较，不引入 NLP/向量依赖。
- 默认性能边界为每个 item 抽取 12 个候选、最多比较 64 个近期指纹、使用 4 字符 n-gram；后续只能在基准证据支持下提高上限。
- 候选选择使用“与近期样本的最高相似度”作为风险分数；优先选择风险分数最低的候选，平分时随机选择。
- 历史样本允许包含规范模式或自定义 prompt；它们不会造成正确性问题，只会在语言相似时参与去重。
- 正式横向 benchmark 继续显式使用 `canonical`，自然模式只负责降低批量运行中的稳定措辞特征。

## Acceptance Criteria

- [ ] 自然模式由多个独立片段组合，候选空间不再等于少量固定整段模板。
- [ ] 每个自然候选都保留 title、category、description 和四类交付语义，但不存在唯一固定收尾句。
- [ ] 21 个现有题库分类均可稳定映射到分类风格或通用回退。
- [ ] 指纹归一化会弱化 topic 专属字段，并使用字符 n-gram 比较公共包装措辞。
- [ ] 给定近期高相似样本时，选择器会优先返回相似度更低的候选。
- [ ] 批次生成会把已选候选加入本批次后续 item 的比较集合。
- [ ] 近期比较窗口固定有界，批次只查询一次历史，n-gram 集合不会为每个候选重复构造。
- [ ] 单任务、批次、养号和显式 natural 抓包均使用近期相似度过滤；自定义覆盖和 canonical 不读取历史。
- [ ] canonical 文本、DTO 默认值、WebUI 字段、自定义覆盖和养号持久化一致性无回归。
- [ ] 不修改数据库 schema、`topics.md`、worker prompt 注入和远程题库同步契约。
- [ ] Python 编译、后端单元测试、JavaScript 语法检查和 Full Check-All 通过。

## Out of Scope

- 为每道 topic 人工编写多份独立需求文案。
- 使用外部模型、embedding 或向量数据库改写和比较 prompt。
- 把公共完成协议移动到 worker 或系统提示。
- 为历史 task/run 回填 prompt 模式、变体 ID 或随机种子。
- 保证统计意义上的绝对“不可识别”；本阶段目标是显著减少稳定语言指纹。
