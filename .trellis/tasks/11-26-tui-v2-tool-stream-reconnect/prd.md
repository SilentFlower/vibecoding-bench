# V2 工具续轮在响应中断后的重试

## 目标

Claude Code 子代理交回工具结果后，遇到短暂断线时能在同一会话继续。保持原账号、对话和子代理身份，按实际模型调用记账，复用已完成的工具结果。

## 已确认的行为

- R1。活跃的续轮与单条客户端连接分离。短暂断线期间继续接收原回复，同一请求重连时接回完整可消费的响应。断线期间模型可能继续产生用量。无人重连时按有界窗口取消仍在生成的请求。
- R2。原进程已经退出时，优先交付留存的原回复。原回复也已丢失时，自动从已核对的客户端历史和工具结果恢复原对话，在新进程中继续生成。用户接受这一次额外模型调用及其可能产生的用量。若原进程在首次接收工具结果前已经退出，恢复后的模型接收这份结果一次。
- R3。用户、账号、会话、子代理及工具归属保持一致。并发重试共用同一次恢复。相同工具结果继续作为历史，已发出的新工具指令按原调用 ID 与客户端回执核对，保护已经发生的外部动作。
- R4。正常后续对话、显式取消、账号权限变化和系统更新继续沿各自现有入口处理。日志区分接回原响应、使用已存回复和重新生成。按每次实际推理记录用量。

## 验收

- 使用公开 Messages、真实 CC/发送器和隔离上游，令子代理收到部分输出后断线，约 6 秒后重试。原回复可接回时，同一消息与工具 ID 贯穿响应，模型投递一次。
- 分别验证原进程在首次接收回执前退出，以及模型已投递后退出且原回复丢失。客户端保留原会话和子代理；后一种场景最多增加一次生成。验证同一 Bash 执行一次，随后还能完成下一次工具调用。
- 覆盖原回复已完成、并发重试、原组与其他子代理并行、已发出新的工具指令、超时后重连、取消与换版。按实际事件核对客户端工具执行数、模型投递数、原尝试与恢复尝试的用量。
- 权限、参数、工具 ID 或历史变化的请求不能获取其他轮次的回复。现场后续重试曾改变 thinking 参数，应验证生成语义和返回表示等价的请求，分别处理确有差异的请求。
