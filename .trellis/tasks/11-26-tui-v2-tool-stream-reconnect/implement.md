# 实施与验证

1. 以远端 flower2api 已签发的 v1.39.0 为复现基线，在独立检出处理产品代码。构造隔离用例，返回 Bash 结果，输出部分 SSE 后断开，约 6 秒后按同一账号、会话、子代理和正文重试；记录旧版拒绝点及上游提交数。
2. 核对普通和无显式会话的既有归属依据、工具组完成事务、sender 进程状态证明和更新门禁。在原工具交付、回执认领与响应输出阶段建立所需恢复证据。按实际持久化变更执行双库迁移及回退校验。
3. 实现独立于客户端读取者的响应保存与接回，串联超时、取消、完整响应回放和用量观察。为真实重试节奏及缓存耗尽分别设定可度量用例。
4. 接通可信退出证明、恢复资格的条件认领和原会话新进程生成。核对重试风暴、取消、不同用户或兄弟子代理、替代提交结果未知、新工具可能已执行及没有原回复的路径。
5. 运行账号端 test_tui_session、test_tui_source、test_tui_message_json，中继 test_cluster_transport，Rust tui_native_drain 与受影响服务和诊断的测试。覆盖完整 HTTP、并发、慢工具、断连后再次断连及混合版本。必要时运行 verify_database_definitions.py 与迁移演练。
6. 使用隔离 CC 2.1.293、网关、发送器和可计数模型上游验收接回、已存回复、重新生成三条路径。同时观察客户端实际执行 Bash 的次数、下一轮工具是否能接回、模型投递次数和用量；按相同身份并发重试。验收证据脱敏后进入 Check-All。
