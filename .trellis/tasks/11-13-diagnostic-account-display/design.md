# 安全资料投影与账号展示设计

## 数据流与合同

诊断读取时 LEFT JOIN 现有 accounts 表，仅查询 name、email。根请求使用根 account_id，各次尝试使用该次 account_id。保留删除账号的记录，避免逐行查询完整账号及凭据。

RequestDiagnostic 与 AttemptDiagnostic 增加兼容缺省的 account_name、account_email 字段，管理查询投影阶段填充。旧 JSON 缺字段正常解析，实时记录构造默认无资料。精确核对全部构造、序列化和记录大小限制。

SQL 显式查询安全列，保持原参数化过滤、排序、分页与保留期。SQLite/PostgreSQL 共用 SQL，按 SQLx Any 现有空值规范实现。

## 前端

api.ts 同步可选字段，统一展示名称及邮箱。名称空时使用邮箱；两者相同避免重复。资料缺失显示“账号信息缺失”及 ID，无账号显示“未知账号”。选择器使用名称邮箱组合，详情提供完整可读文本。

覆盖桌面、手机、概览、链路、性能和尝试选择器。原始诊断 JSON、过滤输入与环境直达继续使用实际 ID。

## 兼容与恢复

接口扩展为可选字段，持久表结构保持。旧后端缺字段时显示资料缺失与 ID。回滚前后可读旧记录；所有测试邮箱与账号使用合成资料。
