# Native 按账号后端执行峰值预热

## Goal

峰值预热按账号实际后端发送模型请求，并分别展示进程准备和配额窗口预热。

产品方向为后续全面使用 native，本项围绕 native 发送能力补齐，原有预热任务作为行为基准。

## Background

实施前，PrimePoller 对活跃账号构造最小模型请求，通过 Rewriter 和通用发送路径执行。native 进程准备由 NativePrewarmer 独立负责。

- PrimePoller::check_once 按服务器本地小时和固定触发分钟执行，同日同小时去重，沿用 peak_prime_enabled／hours／model。
- 当前峰值任务逐账号执行，冷却期记录跳过，结果存入 prime_logs 并在 Settings 的预热记录查看。每账号故障独立处理。
- NativePrewarmer 在启动、账号通知和周期巡检中准备进程，模型调用增量为0；现有环境页已有原生准备快照。

## Requirements

- R3.1：native 账号通过 native 路径执行峰值模型预热。
- R3.2：进程准备与配额窗口预热分别展示。
- R3.3：沿用峰值预热开关、小时、模型设置和预热记录。
- R3.4：用户已确认展示位置：进程准备在环境页面，峰值模型预热在系统设置的预热记录。
- R3.5：用户要求调整预热记录 UI，使其与当前页面一致。沿用现有视觉 token 和列表组件，统一表头、行高、字号、留白、按钮、状态标签和空态；成功／跳过／失败以颜色及文字同时表达；完整错误原因使用现有信息气泡或详情交互。
- R3.6：峰值预热继续按原有定时、最小模型请求和每账号独立的故障处理规则执行。具体 native 构造方式在设计中确定。

## Acceptance Criteria

- [x] native 账号的峰值模型预热由实际原生发送链路完成。
- [x] 两类预热状态及结果具有清晰归属。
- [x] 预热记录保留时间、账号、触发小时、模型、耗时、结果及完整原因，按现有页面视觉规范呈现。
- [x] 长模型名和错误原因、加载中、空态、成功／跳过／失败及窄屏布局经过检查；在390／1440／1920／2560px视口核对阅读与交互。
