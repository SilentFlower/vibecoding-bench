# Brief — Native 峰值预热与记录 UI

## Goal

- 让 native 账号通过实际原生链路完成峰值模型预热，并清晰展示进程准备与模型预热结果，统一预热记录的页面风格。

## Scope

- 峰值预热的 native 发送路径、目标账号与 280／293 来源版本归属。
- 进程准备与配额窗口模型预热的展示归属和说明。
- 系统设置预热记录的表格、状态、完整原因、加载与空态及响应式呈现。
- 调度、账号故障处理、实际原生发送及浏览器回归验证。

## Non-Goals

- 调度槽位、RPM、后台重试和换号业务规则沿现有预热合同执行。
- HTTP 成功与 SSE 终态的现有成功判定口径保持。
- 原有预热任务作为行为基准，本项围绕 native 发送能力补齐。

## Technical Overview

- 沿用现有峰值开关、小时和模型设置，按服务器本地小时的 :10 分触发，30 秒扫描，同日同小时去重，账号间隔 500ms。
- 对目标账号构造最小 hi 消息，使用 max_tokens=512 和既有流式模式，经原生准备及提交接口交由对应版本 CLI 装配和发送。
- 复用账号归属、凭据、代理、版本与维护门禁检查，保持 30 秒首响应及 60 秒耗流预算。
- 沿用 prime_logs 的记录字段和最近 200 条倒序查询，页面复用现有 Table／Button／Badge／InfoTooltip 及视觉 token。

## Context & Decisions

- 产品方向为后续全面使用 native。峰值预热绑定本次目标账号，直接复用原生发送能力。
- 进程准备由 NativePrewarmer 执行零模型初始化，状态展示在环境页；配额窗口模型预热的记录展示在系统设置页。
- 活跃账号按原有规则逐一处理，冷却账号记录跳过。OAuth 首次 401 恢复凭据后原账号重试一次。最终 401／429／403 沿用原有后台状态处理。
- 预热记录统一表头、行高、字号、留白、按钮、状态标签和空态。成功／跳过／失败同时以文字和语义颜色表达，完整原因通过已有气泡或详情交互查看。
- 本 Brief 来源为本任务最新 prd.md、design.md 和 implement.md，发送合同衔接已完成的 R1／R2。

## Risks

- 原生发送须保持目标账号、凭据、代理及版本归属，迟到认证失败的状态写入须遵循原条件保护。
- 原生准备等待、首响应与完整耗流的预算需按实际调用边界核对，HTTP 状态与 SSE 终态需分别留证。
- 长模型名、完整错误原因及窄屏交互需结合现有视觉规范验证。

## Acceptance

- native 账号通过实际原生链路执行峰值模型预热，280／293 的来源、账号归属和真实发送计数可核验。
- 进程准备与模型预热具有清晰的状态和记录归属；准备阶段模型调用计数为 0。
- 原有开关、触发时点、去重、冷却跳过、账号间隔和故障处理经过回归验证。
- 记录保留时间、账号、触发小时、模型、耗时、结果及完整原因，真实 0 耗时正确展示。
- 成功／跳过／失败、加载中、空态、长模型名与错误原因在 390／1440／1920／2560px 视口完成阅读及交互验证。
