# 节点迁移缺陷修复上线与恢复步骤

## 发布范围

- 编排控制镜像：API 额度游标双向交接、旧认证错误重放保护、上传新尝试续接、历史工程抓包只读查询。
- 中央与全部所属 Node 使用包含本次修复的同批控制组件，按 `deploy/flower2api/CLUSTER.md` 的集群升级步骤及项目发行制品核验执行。
- 数据库结构及已发布迁移登记保持现有版本。新增信息保存在既有额度 JSON 和迁移检查点中。

## 11-14 的现场恢复

1. 发布后只读确认账号名 `11-14` 对应 ID 16，当前归属 `main`，原迁移操作已完成。若归属已被人工调整，以当前真实归属核对。
2. 核对已保存的养号项目池、指南、计划间隔、当前轮次、通过事实及累计预算。原故障提示为“API额度来源已登记另一身份或镜像”。
3. 通过原“启动／恢复 Pi”入口执行一次严格核验。API 游标按确认归属交接到远程镜像，累计额度事实和已用恢复机会继续保留。
4. 观察真实被动额度及工作状态。已完成目标保持完成，原工程池继续选择后续工作；额度、认证或运行时段门禁仍按真实情况等待／阻断。
5. 检查两个空间的历史抓包摘要及受限文件可读。已有中断迁移按原操作 ID 继续，旧部分上传资料保留在原尝试目录。

## 成功判据

- 原路径冲突解除，计划按已保存配置进入运行或有明确原因的正常等待。
- 新被动样本更新额度，身份、工程进度、原会话及已用恢复机会保持原合同。
- 上传新尝试可在同一迁移账本中追踪；完整上传的未知回包沿原结果核对。
- 历史抓包从当前已核验资料节点读取；未知活动执行仍沿原操作核对。

## 回滚

回滚前收口活动迁移，尤其是已经产生新 transfer 检查点的操作。旧版本仅使用初始上传尝试，活动新尝试应由本次版本完成或在提交前沿原取消流程撤销。按集群 SOP 保持账号／节点归属、原资料与额度记录，使用原制品回退；禁止删除额度、恢复许可、迁移账本或原部分文件来解除门禁。
