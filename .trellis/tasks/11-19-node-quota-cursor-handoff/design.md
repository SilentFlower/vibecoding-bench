# 技术设计

## 根因与边界

API 事件以 `api:<environment_id>:<identity>` 标识逻辑来源。逻辑身份跨迁移保持，物理读取路径由本机文件切为中央远程镜像。现有两侧注册把来源的路径当作不可变事实，缺少精确的位置交接。

权威继续为中央 QuotaGuard 和既有账号／归属模型。Node 只提供核对范围后的原始片段。数据库表、来源键、API 额度事件格式与公开 HTTP 路径保持。Node 私有请求按下述固定操作扩展，同批组件共同交付。

## 登记机制

1. 在现有额度模块内集中 API 游标的精确登记与位置交接规则，本机消费和 RemoteApiQuota 共用。
2. 用现有账号、身份、环境和数据根推导唯一合法本机路径及远程镜像路径。读取当前归属后决定目标位置。未知路径和身份冲突保持明确错误，禁止通用覆盖。
3. 同路径重入保留文件身份与消费位置。已确认的合法路径切换在短数据库写锁与事务内更新路径并重置文件读取位置；累计额度、认证与恢复许可使用原有表记录。
4. 网络读取在数据库锁外执行；远程读取及登记前后仍核对节点、分配版本与环境代次，覆盖本机回迁和迁移期间迟到响应。
5. 消费游标提交绑定读取时的路径／登记状态，避免旧位置的迟到消费推进新位置的字节位置。遵守现有锁序，禁止把远程 I/O 放进全局数据库写锁。

## 历史重读与恢复

- 切换物理文件后按新文件身份读取。样本合并继续以真实时间和窗口时序处理，验证历史 API 样本重读的幂等性。
- 旧认证失败重放和恢复机会的保护纳入测试；若现有消费者有与重读直接相关的缺口，仅补齐必要的时序校验。
- 原故障已经将计划下一检查时间清空。发布后通过原“启动／恢复 Pi”入口重新核验。只有运行条件满足才继续指挥，已完成目标仍保持完成，其他人工意图沿原逻辑处理。
- 实现阶段交付恢复操作单，生产操作在部署流程的适用授权后执行。禁止用手写 UPDATE 清空额度或批量重排计划来代替产品修复。

## 部分上传恢复

1. 保留现有私有目录、包大小／摘要及原操作标记核验。stage 的结果区分未上传、完整上传和原尝试不完整，业务协调层使用结构化状态处理，禁止按异常文案分流。
2. 原 execution 保存初始尝试。利用现有 transfer 检查点记录当前尝试；仅在原 exporting 阶段、目标尚未核验或发布时允许同操作按 CAS 更换尝试。旧账本缺少 transfer 检查点时沿原初始尝试进入。
3. 完整包回执复用原尝试。不完整包保留在原目录，下一次上传进入新私有目录。新尝试先持久登记后执行 I/O，重启后沿已登记尝试续接。
   最终激活以及 committed 后的协调器重建同样从当前 transfer 检查点读取已发布尝试。缺少该检查点的旧账本沿 execution 初始尝试，避免重新激活原不完整目录。
4. 原归档身份、摘要、目标归属和分配版本保持冻结。已取消、已有发布意图或后续目标检查点时拒绝重建尝试，沿原收据恢复或撤销流程。
5. 本机和 SSH 上传走同一协调判断，兼容各自的原始写入实现。反复网络故障仍由原迁移操作保存待核对状态。

## 历史工程抓包

1. 把历史资料只读定位与活动终端执行定位分开。已结束工作使用中央实际工作记录核对账号、空间和工作 ID，避免为本机历史工作虚构远程执行操作。
2. 本机沿原 ProjectsTerminal.capture 读取。资料已迁入远程时，新增有限的历史抓包只读请求，冻结当前节点、账号、环境、分配版本和实际代次，并携带受限工作定位。
3. Node 仅从该环境 `flows/group-<namespace/work_id摘要>` 推导目录，复用 capture_summary／capture_file_preview 及原文件白名单；拒绝任意宿主路径。读前后核对原归属，保持两个工程空间隔离。
4. 远程历史再次迁移后从当前已核验资料读取。原执行账本继续记录真实执行节点。仅在有确切资料交接依据时选择当前位置，禁止把未知活动执行结果当成历史读取兜底。
5. 新私有操作同步注册 Node Agent、轻量客户端及 SSH 白名单，沿只读通道执行。页面仍调用原公开抓包入口，查询不创建角色或模型请求。

## 受影响代码

- `services/orchestrator/cluster_quota.py`：API 额度登记、远程范围复核及位置交接。
- `services/orchestrator/main.py`：QuotaGuard 本机注册、必要的消费提交与重读时序保护。
- `services/orchestrator/test_cluster_quota.py`、`test_quota.py` 及必要的现有工程计划测试：真实 SQLite／文件合成回归。
- `services/orchestrator/cluster_migration_files.py`、`cluster_migrations.py`、`cluster_migration_runner.py`、`cluster_migration_io.py`：上传状态及原操作的新尝试接续。
- `services/orchestrator/cluster_projects_terminal.py`、`cluster_terminal.py`、`cluster_terminal_sessions.py` 与 Node Agent／轻量客户端／SSH 操作注册：历史抓包的只读位置衔接。
- 对应迁移文件／协调器／工程终端测试及必要的真实 SSH 隔离验证：覆盖新尝试恢复和历史读取。
- 相关 spec 与任务材料记录新的可执行合同。

## 取舍与风险

- 选择按已确认归属惰性交接，覆盖已经完成迁移的历史故障。只在迁移提交时修改记录会遗漏现有 `11-14`。
- 保持逻辑来源键避免修改 sender 事件协议。仅放宽路径相等检查会掩盖未知来源，因此只接受系统推导的精确路径集合。
- 切换后可能重新消费旧样本，必须验证最新额度／认证事实与单次恢复机会保持。回迁及迟到消费与迁出具有同等验证要求。
- 当前工作区存在其他任务变更；实施保留已有改动并基于本任务基线审查新增差异。相关未跟踪集群模块属于此前已有实现，提交范围由后续 Git 计划核定。
- 新上传尝试保持旧证据并绑定原包。未知阶段的保护仍服务原操作完整性，修复只解除已确认的部分上传续接死结。
- 历史抓包新增只读 Node 操作要求中央和节点同批更新。发布前同步核对全部操作白名单及真实 SSH 查询链路。

## 回滚

修复保持现有数据库结构和来源协议。回退程序后，已转交的游标资料保持有效，旧程序在再次跨位置时仍可能出现原问题。保留原额度事实与迁移账本，按原归属核对并停止新增调度后处理恢复；禁止通过删除事实解除门禁。
