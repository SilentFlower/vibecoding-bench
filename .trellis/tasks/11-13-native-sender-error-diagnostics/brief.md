# Brief — 补齐原生发送器安全异常诊断

## Goal

- 让下一次原生失败能按请求查到实际阶段、错误类型、错误码和 cause 摘要。

## Scope

- 补齐 sender 日志初始化与请求、账号、进程关联。
- 补齐内核安全摘要、可选私有协议字段及 sender 校验记录。
- 增加跨语言、错误路径和秘密隔离验证，更新相关规范。

## Non-Goals

- 生产部署、签名内核发行、线上切换及真实账号推理。
- 页面、数据库迁移、历史异常回填及自动重试。
- 保存完整异常正文、堆栈、IPC 或失败进程 HOME。

## Technical Overview

- 内核在实际构造、发送、响应边界生成白名单摘要，cause 最多八层。
- sender 独立校验后写入 JSON 日志，保留 job/attempt、worker/PID、账号和环境代次。
- 旧内核兼容运行，新增字段缺省或非法时明确诊断状态。

## Context & Decisions

- 现场 sender 日志为 0 字节，原生错误被通用文案替代，失败目录随退役清理。
- 普通日志只保存受控类型、错误码和关联信息。未知值显示 unknown。
- 本轮交付源码与验证。完整 cause 采集需要后续发布并接纳配套内核。

## Risks

- 错误对象可能含秘密、循环或异常 getter，提取和消费边界均需安全校验。
- 日志初始化会激活已有 tracing 调用，需要检查其输出范围。

## Acceptance

- 默认 sender 入口实际输出可关联日志。
- 连接、TLS、超时及构造失败保留实际分类，覆盖循环、截断和恶意字段。
- 新旧协议、非法诊断及取消路径回归通过，每请求发送次数符合原合同。
- gateway 格式检查及完整测试、runtime 类型检查、单元、集成和原生离线验证通过。

## Next Step

- 启动任务并内联实现安全异常摘要与 sender 日志链路。
