# AGY 模板启动故障设计

模板路径执行镜像文件，常规路径执行封存 memfd。观察器先核对实际 exe 与固定执行体，验证完整摘要，然后从真实映射确认基地址和指令指纹。隔离对照在 OverlayFS 的真实文件型启动中复现了基地址映射准入失败。同一份执行体经只读绑定挂载后通过观察器并就绪。

文件型路径需在当前进程挂载命名空间核对执行体与实际映射的归属，处理 OverlayFS 两种观察接口的设备号差异。保留 SHA256、执行体归属、inode、访问模式及指纹核验。封存 memfd 继续使用已验证的设备号与 inode。保留普通启动回退和模板唯一持有约束。

隔离 VM 在观察器通过后进入真实 dump，CRIU 4.2 拒绝保存 AGY 的 MPTCP 监听。仅文件型模板启动设置 `GODEBUG=multipathtcp=0`，以普通 TCP 监听完成保存和恢复。

复用 CRIU 诊断规范中的受控阶段、退出分类与保密边界，在原清理前保留首错。依实际复现决定修改的最小阶段。参考 [Linux OverlayFS 文件标识语义](https://docs.kernel.org/6.19/filesystems/overlayfs.html)。
