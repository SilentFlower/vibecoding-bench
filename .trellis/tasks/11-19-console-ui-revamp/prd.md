# 控制台 UI 改版（第二版定稿落地）

## Goal

把已定稿的第二版设计落到正式控制台：用一套自建组件库统一视觉与交互，系统更新改为版本号入口加弹窗，新增主题设置。业务行为不变（只有更新步骤记录需要后端补一点）。

## Background

- **设计定稿**：用户已接受第二版全部画面，含对照页标出的 6 条与现有规范不同的决定。设计稿源码在 `research/design-v2/`，参考取证与画面清单见 `research/reference-and-design.md`。
- **视觉参考**：codex-proxy-rs。用户决定不直接依赖 `@codex-proxy/ui`，参照它的形态自建组件库（token + 主题运行时 + 组件集 + 演示页），代码自行编写。
- **现状**：
  - 前端为 Vue 3.5 + Tailwind 4 + reka-ui + cva，基础组件在 `apps/web/src/components/ui/`，控件 token 唯一源是 `apps/web/src/components/ui/controls/controls.css`，阅读尺寸来自 `apps/legacy-web/ui-foundation.css`。
  - 全局样式 16 个文件共 5,773 行，743 种十六进制颜色、136 处 `!important`、11 种圆角。
  - 没有深色主题，只有 `apps/web/src/style.css:7` 的 `@custom-variant dark` 声明。
- **原生页**：
  - 任务与工程由 `apps/legacy-web` 原生模块在 Vue 文档内挂载（`TasksWorkspace.vue`），CSS 经 `runtimeModule.ts` 改写作用域，能继承根上的 CSS 变量。
  - 运行环境是 Vue 页面（`RuntimeEnvironments.vue`），只沿用原生类名与 `src/native-environment.css`。
  - 旧独立 `/runtime/` 文档读不到 Vue 的变量；新增原生资源要同步运行时桥接白名单（`runtime_bridge.rs:426-449`）。
  - 详见 `research/frontend-architecture.md` §3。
- **设计基准与验证**：
  - 唯一视觉基准是 `doc/design/flower2api-concept.html`（663KB），被 `deploy/flower2api/` 下 13 个脚本引用。它们用 Playwright 同时打开原型和产品构建，比对渲染后的计算样式。
  - 另有部分行为脚本写死了样式值，如 `verify_shared_pagination.py:14-43` 断言分页颜色 `#77648f`。
  - 详见 `research/frontend-architecture.md` §6。
- **系统更新现状**：
  - 版本号已能打开原生 `<dialog>`，里面内嵌 `SystemUpdates.vue`（`Dashboard.vue:114,152-155`）；另有整页路由 `/updates`（`router.ts:49`）。
  - 更新器只保存当前步骤：`_phase`（`system_updater.py:377`）与宿主恢复路径（`system_update_host.py:1103,1108`）都只覆盖 `phase`，落盘统一经 `_record`（`:104`）；返回字段由 `_public_operation`（`:233-235`）白名单控制。
  - 实际步骤：preparing → prepared → draining → switching（越过取消边界）→ snapshotting → migrating → switching → verifying → committing → cleaning → succeeded，无迁移时跳过快照与迁移（`system_updater.py:367-444`）。
  - 在途等待上限 1～120 分钟，默认 1 分钟（`SystemUpdates.vue:31`）。

## Requirements

- **R1 自建组件库与主题运行时**：
  - 种子 token 派生出完整 CSS 变量，第二版浅色取值为默认主题。
  - 支持配色预设与自定义主色、表面材质、尺寸与风格参数，并在首屏渲染前应用，不闪烁。
  - 所有颜色（含阴影、描边、遮罩）都取自语义 token，不写死，为深色模式（R10）预留。
  - 组件覆盖设计稿用到的全部基础控件：按钮、图标按钮、输入、数字输入、选择、分段、标签 / 状态徽标、开关、单选 / 复选、气泡、弹窗、确认框、分页、表格、卡片、页头、空态、骨架、通知。
  - 扩充现有组件演示页。
  - 原生页通过同一组 CSS 变量取值。
- **R2 外壳**：
  - 白色侧栏，选中项浅灰底配主色图标。
  - 品牌旁版本号兼作系统更新入口：有新版本时转成功色并带上箭头图标。
  - 「主题设置」入口位于「系统设置」上方；底部管理员区放折叠、退出，主题模式快捷切换随 R10 加入。
  - 页头去掉分组名，只留标题、一行说明和右侧操作。
- **R3 通用业务组件**：
  - 概览卡、工具栏、实体卡（头像 / 图标块 + 名称 + 副标题 + 状态徽标的统一头部、浅灰信息块、等分操作底栏）、数据表（圆角表头条、斑马行、60px 行高、操作固定最右）、居中弹窗（18px 圆角、浅灰底栏）、浮动保存栏。
- **R4 系统更新弹窗**：
  - 用新组件重做弹窗，撤掉整页形态；`/updates` 改为打开控制台并自动弹出该弹窗。
  - 弹窗包含：版本摘要（当前 / 最新版本、发布时间、最近检查、兼容性结果）、发布说明（可看完整原文）、安装方式（暂停新接单、在途等待上限 1～120 分钟）、检查更新与安装更新。
  - 安装后同一弹窗切换为逐步进度（已完成 / 进行中 / 待执行），支持取消等待与恢复操作。
  - 版本记录与回退、运行组件与维护详情、操作详情与数据库快照都从弹窗进入，现有页面的信息一项不少。
- **R5 更新步骤记录**：
  - 更新器为每次操作记录各步骤的进入时间（及可选说明），状态接口返回给前端。
  - 没有这份记录的旧操作照常显示，只是不显示步骤时间。
- **R6 主题设置页**：
  - 左侧编辑面板（主题预设、表面材质、颜色 / 尺寸 / 风格参数），右侧隔离画板实时预览草稿。主题模式（跟随系统 / 浅色 / 深色）随 R10 加入。
  - 首版只开放全局参数，不显示「组件」页签；组件级 token 在内部照常派生，留待以后开放编辑。
  - 页头显示待应用修改数，配撤销草稿、恢复默认、保存并应用。
  - 主题只保存在当前浏览器；存储值无效时回退默认主题。
- **R7 Vue 业务页迁移**：账号卡片（字段、顺序、开关与操作入口不变）与编辑弹窗、请求记录、代理管理、访问令牌、会话封禁、节点管理、系统设置、登录页（采用第一版登录设计）、390px 移动端，按设计稿换用新组件。
- **R8 原生页对齐**：任务与工程、运行环境改用同一组 token 与组件样式，结构按设计稿不变。
- **R10 深色模式**：
  - 先出深色色板设计稿，经用户确认后再实施。
  - 全部 Vue 页、原生页（任务与工程、运行环境）、终端与弹窗适配深色。
  - 主题模式支持跟随系统（系统切换时实时跟随）、浅色、深色；侧栏底部提供快捷切换，主题设置提供模式选项，选择保存在当前浏览器。
- **R9 规范与基准同步**：
  - 第二版设计稿成为新的唯一视觉基准（`doc/design/console-v2/`）；旧 `flower2api-concept.html` 在全部页面迁移完成后删除。
  - `ui-guidelines.md` 与原生组件规范写入新 token、组件与 6 条已确认的新决定。
  - 依赖旧基准的验证脚本随所属页面迁移，改为 token 断言 + 截图 + 行为断言。

## Acceptance Criteria

- [x] 1440×900 与 390×844 下各画面与第二版设计稿一致：结构、字号字重、圆角、颜色、状态色、控件默认 / 悬停 / 聚焦 / 选中 / 禁用态（R1–R3、R7、R8）。
- [x] 页面样式不再写死颜色与圆角，统一取自 token；全局 grep 无旧色板残留，`!important` 与重复规则显著减少（R1）。
- [x] 现有业务行为不变：字段保存与取消、分页、OAuth、调度筛选、费用气泡、轮询稳定性等既有浏览器验证全部通过（R7、R8）。
- [x] 有新版本时侧栏版本号变为成功色并可打开更新弹窗；直接访问 `/updates` 也打开弹窗；安装、取消等待、恢复、回退、查看完整发布说明、查看维护与操作详情均可完成（R2、R4）。
- [x] 安装过程中弹窗逐步显示进度，已完成步骤带进入时间；旧操作无步骤记录时不报错（R4、R5）。
- [x] 在主题设置中切换预设或改主色后，预览画板立即变化、控制台不变；保存后刷新页面主题保持且无闪烁；恢复默认回到第二版主题；清空或篡改浏览器存储后回退默认（R6）。
- [x] 前端构建（`vue-tsc -b && vite build`）通过，控制台无新增报错；键盘焦点可见，`prefers-reduced-motion` 下无动画（R1–R8）。
- [x] 深色模式下各画面与确认后的深色稿一致，文字对比度不低于 WCAG AA；跟随系统时切换系统主题，控制台随之切换；刷新后保持所选模式且无闪烁（R10）。
- [x] 规范、设计基准与验证脚本已同步，新验证覆盖上述画面与流程（R9）。

证据：子任务 1–7 各自的验收记录，以及父任务最终复核（`implement.md`「实际结果（最终复核）」、`.deploy/console-ui-revamp/final-review/index.html`、69 个 UI 脚本回归）。

## Child Tasks

按可单独验收的交付拆分，依赖写在各子任务自己的文档里：

1. 组件库与主题运行时（R1）
2. 外壳与通用业务组件（R2、R3）
3. 系统更新弹窗与步骤记录（R4、R5，含 `deploy/flower2api`）
4. Vue 业务页迁移（R7）
5. 主题设置页（R6）
6. 原生页对齐（R8）
7. 深色模式（R10，最后交付；前 6 个子任务只验收浅色）

R9 由各子任务按各自范围同步，父任务做最终一致性复核。

## Out of Scope

- 直接依赖 `@codex-proxy/ui`。
- 第一版提出、第二版已撤回的方案：账号列表视图、合并额度行、「⋯」操作菜单、760px 详情侧栏、⌘K 全局跳转、请求导出、令牌「最近使用 / 轮换」。
- 主题设置的组件级 token 编辑（首版只做全局参数）。
- 多语言、移动端底部导航、除更新步骤记录以外的 API 或业务行为变化。
