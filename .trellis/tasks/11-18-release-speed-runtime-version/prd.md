# 发行二期提速：运行时版本与数据库四路演练

## Goal

缩短从源码提交到版本可安装的总等待，完成用户选择的运行时版本读取和历史数据库演练并发优化。

## Background

- 用户选择建议1和2并要求开始优化。建议3的候选消费优化另行处理。
- v1.17.2实测：正式发布478秒；从构建启动到可安装939秒，上一版同口径1031秒。候选就绪442秒；control构建217.409秒；数据库八来源双路演练243.6秒。
- 证据：GitHub构建44301487648、发布44302701047；源码e3bd1db9d2fc4da80dd0fa7b27549a06ecbc70ab。

## Requirements

- R1：平台版本随当前控制镜像提供，纯版本号更新复用前端及Rust编译产物。
- R2：历史数据库演练支持四路并发，保留八来源、两次迁移、新旧读写、快照恢复及失败收口。
- R3：对同一验证对象记录耗时与CPU、内存观测，区分本地合成历史、真实历史及GitHub正式发行。

## Child Tasks

- `11-18-runtime-platform-version`：R1；管理API、前端、Docker和编译缓存、相关回归。
- `11-18-database-proof-workers-four`：R2及R3演练部分；有界并发、资源事件、双路/四路对照、工作流配置。
- 两项独立实施；先完成并发演练，再完成版本与编译解耦，最后复核工作流集成。

## Acceptance Criteria

- [ ] 两个子任务各自通过验收，真实版本展示与发行签名对应。
- [ ] 工作流同源码候选复用和历史演练共同通过；性能报告同时给出分段与全链路口径。
- [ ] 任一验证失败继续阻断正式发行，八来源检查完整保留。

## Out of Scope

- 候选消费摘要读取优化、镜像裁剪、硬件采购、生产安装和本轮正式发版。
