# 完整需求与 BUG 开发周期：简化设计

## 1. 目标和边界

一个完整需求／BUG 持有一个开发者会话和工作目录。复用现有调度、投递、恢复和最终验收，在普通回复后增加一次外部 API 调用生成下一句用户话；不建设第二套 CLI 环境或通用工作流平台。

整体覆盖现有 100 项目。先在隔离环境用一个真实需求和一个 BUG 验证机制，再分批重组全部内容；试点不替代整体交付。普通理解／咨询仅作为任务内部交流。

## 3. 外部请求：一个小客户端

新增 `orchestrator/project_dialogue.py`，集中实现单服务的请求、结果解析和有界顺序降级。使用标准库 HTTP 能力，沿用项目已使用的 `urllib.request`，不为此引入 Agent 框架或 SDK。

配置名称为本任务新增契约：

| 配置 | 值与用途 |
| --- | --- |
| `PROJECT_REQUESTER_BASE_URL` | `https://ai.flower-cli.com/v1`。 |
| `PROJECT_REQUESTER_MODEL` | `gemini-3-flash-agent`。 |
| `PROJECT_REQUESTER_FALLBACK_MODEL` | `deepseek-flash`。 |
| `PROJECT_REQUESTER_API_KEY` | 来自环境初始值或页面保存的私有配置；正文、前端响应、日志、任务和报告均不返回。 |

请求为 `POST /chat/completions`，Bearer 认证、非流式、`messages` 输入。初始实现固定 30 秒单模型网络超时、控制端单轮共用最多 60 秒预留和有界输出，按实测协议使用 `max_tokens`；配置来源与请求日志分开，拒绝携带授权头的自动重定向。

固定提示描述需求方职责，业务输入仅包含任务目标、可公开材料、实际用户／开发者交流、已确认方案和可披露验证反馈。工具日志、思考块、凭据、私有测试源码和参考补丁不进入请求。使用已保存事实构造请求，不要求外部模型维持独立长期会话。

使用三种动作的小 JSON 响应：`reply`（继续问答）、`implement`（明确确认方案并要求实施）、`verify`（对实际交付开始验收），配自然语言 `message`。该小协议已由客户端严格解析。控制端核对当前轮次与合法转换，实际完成仍由独立验收决定。普通回复不输出分数或 pass。

输入和输出有大小上限；对话超过能够完整处理的上限时保留进度并报告原因，不静默丢弃已确认约束。单次请求离开数据库写锁和调度 tick 线程执行，不占用 Claude CLI 许可。

### 主备切换

- 额度不足的明确服务错误、HTTP 402／429、500／502／503／504 按可用模型列表顺序降级，不并发请求多个模型。
- 401／403 认证错误、400 参数错误和错误模型配置明确报告，不自动换模型掩盖配置问题。
- 页面可配置 1～8 个模型，每次生成对列表中的单个模型最多尝试一次，并共用本轮剩余请求时间；全部失败进入可见等待。后台恢复沿用已有调度节奏并限制基础设施重试，不紧密循环。
- 因额度不足切到备用后，当前完整任务后续交流沿用备用，避免每轮再次消耗一次必败主请求；下个任务可重新使用主模型；页面保存新配置版本后，后续请求从新优先级重新选择，已生成消息继续复用。
- 保存实际模型、降级原因、HTTP 结果分类、耗时和真实 usage；服务未提供的统计显示未知，不推算价格。

## 4. 最小任务循环

1. 现有调度器启动完整任务，投递初始业务问题；开发者调查和回复。
2. 按现有父链和原生输入核对，保存当前回答与工作现场并严格释放本轮执行。
3. 在原任务绑定下生成需求方请求，保存完整请求依据的摘要和待处理意图；执行外部 HTTP 调用。
4. 保存通过校验的动作与消息，再由现有投递机制发送到开发者原会话。重放已保存结果不重新调用模型。
5. `reply` 继续正常交流；`implement` 在已形成方案时确认实施；`verify` 仅在实施／修复阶段且已有交付时进入验收。
6. 验收通过后只完成一次任务；真实失败把具体事实送回原会话修复。

实现优先扩展 `ProjectScenarios` 既有 `phase`、`next_prompt`、delivery 和 source 记录。仅为外部调用增加一张小型 `project_dialogue_jobs` 表，绑定业务 task、原回复与代次，保存请求依据、状态、结果、模型、耗时、usage 和重试事实；不含密钥。唯一约束防同一原回复重复生成，迟到／旧代结果不能继续已停止任务。

普通讨论不创建独立评审；实际交付复用现有冻结候选、原生行为及回归。确有语义要求的交付可沿用原有最终评审，需求方不会读取其私有评分答案。

## 5. 断点续做和失败返工

复用原会话文件、工作区和投递证据。保存当前阶段和已确认方案、未完成事项、尚未发送或尚未确认消费的消息，以及待验收的冻结交付。

| 已确认的中断点 | 下一步 |
| --- | --- |
| 外部消息已生成，尚未发送 | 发送已保存的同一条消息。 |
| 已发送，尚未确认消费 | 先核对原生输入；消费事实不明时等待对账，禁止盲重发。 |
| 开发者正在实现或工具执行中超时 | 旧进程严格释放后，恢复原会话及半成品继续当前事项。 |
| 已交付，验证未完成 | 继续原冻结交付的验证，避免再要求实现。 |
| 验证已完成，状态或反馈未收口 | 幂等接受原结果或投递原反馈。 |

历史 Run 保留 timeout；完整任务待续做。同账号可恢复旧任务优先于新需求，停止和有效额度／时段门禁优先；等待不持执行名额。缺失会话、未知进程或现场归属冲突保留阻塞，不重建 seed。

新完整周期的任务工作预算累计开发者工作片段和需求方请求时间，最终评审继续受自身子预算及任务剩余预算约束；调度排队和本地验证管理等待分别有界。重启／续做不重新领取整份预算。普通对话不扣业务修复次数，真实交付失败才使用既有有限修复策略。

失败反馈包含原要求、可公开的复现、预期／实际差异与问题位置。模型审查存在有据异议时对同一冻结版本有限复核，仍存疑则待处理；环境、认证或格式故障不惩罚开发者，也不反复抽评碰 pass。

## 6. 内容和历史兼容

新完整开发内容采用 schema 3 以阻止旧服务把它静默当作短题执行；复用 schema 2 的真实源码、材料、离线环境和原生验收结构，不另造内容框架。执行仍复用当前场景调度入口，按冻结内容版本区分行为。

每个新场景对应一个真实完整任务；任务持有类型（功能需求／BUG）、初始业务 prompt、材料、最终授权范围与独立验收。理解、咨询、诊断和方案材料归入其内部交流。新版本不沿用旧短题默认 4 轮／最多 8 轮的规则，以总预算和无进展／有限返工约束循环。

保留旧 catalog release 和实例 reader。新源码内容在暂存目录逐批生成并验证，最终发布新版本，旧批次仍绑定旧 release；不把正在运行的旧批次转为新模式。100 个项目逐一形成来源与新任务映射，无法准入的项目保留明确阻塞记录，不计完成。

保留各仓原 `project.json` 与 `catalog-v37.json`，新目录通过 `project_manifest: development.json` 选择完整任务定义；原运行的冻结 release 不改写。目录附逐仓准入结果，只有已具备真实工程合同及独立原生验收的项目进入可执行列表；其余项目明确列为阻塞，保留提案与待补合同，不以问答替代。

先复用 Click 错误附注增强和 Cachetools receiver 修复，分别制作真实需求／BUG 试点，再按实际工程目标重审其余仓库。旧 726 与研究 2,000 均不直接继承为新任务数。

## 7. 页面、交付和验证

沿用现有项目、实例、任务详情、成果与 usage 路由；返回新内容版本和完整任务的对话／阶段摘要。优先扩展现有响应，避免新增一套管理 API。仍需调整桥接时只更新既有白名单和测试，不扩鉴权范围。

页面把任务完成数与对话轮数分列，清楚显示调查／方案／实施／验证／返工及待续做原因，外接主备实际调用与 Claude 用量分开。新增一个简洁的外部需求方配置表单：单一 Base URL、受保护 API Key、按优先级排列的可用模型列表。服务端以私有配置文件原子持久化，环境变量作为未覆盖时的初始值。GET 只返回密钥是否已配置；PUT 留空沿用密钥；DELETE 恢复环境配置。保存后替换后续请求使用的客户端，在途客户端和已生成消息保持各自真实来源，不更换开发者会话。管理 API 沿用现有鉴权和窄范围桥接白名单，不建设多供应商管理平台。

本地受保护配置和两模型连通已验证，见 `research/provider-verification.md`；业务循环、动态配置、有界降级、双试点和全部36项内容的独立原生准入均已验证。美国 v3 已部署并通过页面、配置及历史保留核验；真实 Claude 完整业务尚未执行。校验模型行为使用受控 HTTP 服务，避免通过耗尽真实余额测试。

先完成机制和双试点，再重组百项目及整体验收。源码、镜像 COPY、发布快照及私有原生验证制品保持现有来源／字节／权限合同。用户在实现和检查完成后已确认精确提交计划并追加部署授权；按现有美国 v3 目标执行同批镜像更新、停机备份、历史核对和页面验证，真实 Claude 业务任务仍不在范围内。

回退保留原服务及原内容版本；新内容在旧服务上明确不可执行，停止新模式作业后回退，不改写新旧任务记录或删除现场。
