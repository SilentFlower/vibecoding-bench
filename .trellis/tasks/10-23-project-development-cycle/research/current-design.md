## 已定位的 pass 交接故障

- 旧会话最后一份观察快照：`.deploy/v3-real-account-observation-20261023/snapshot-20261023T072245941699Z.json`，采样时间 `2026-10-23T07:22:43.517692+00:00`。这份快照是历史证据，不代表当前线上最新状态。
- 两项候选分别为 `TR-U01`（约 80.5 秒）、`TR-C01`（约 73.3 秒），原生检查通过；首项评审随后两次 timeout，并进入第二次基础设施恢复。
- 原会话工具回执 `call_8b3133b4d2f14422b80c0672e05a68bf` 记录：预期输入 1,678 字节，实际 1,734 字节；CLI 在起始与原文位置 1,608 插入同 ID 的 `<pasted_content>` 标签，后面仍留有未包装的指令后缀。
- `images/worker/task_followups.py:114` 仅接受完全相等或整体单层包装。局部包装加后缀不满足 fullmatch，导致输入未消费、结果通知未生成；评审已有回复仍无法进入控制端解析。
- 本轮仅以内存调用既有 `_matches_input` 复核：原文 true、整体包装 true、局部包装加后缀 false。没有修改实现，也没有新增测试文件。
- 修复应保留精确正文与执行归属校验，覆盖实际 CLI 包装边界；不能通过搜索 pass、删除任意标签或放宽任意额外内容接受结果。

## 已决定的简化接法

- 用户接受动态需求方，并指出双角色 CLI 和额外阶段管理过于复杂，随后明确要求外接模型 API。
- 外接服务为 `https://ai.flower-cli.com`，用户指定 OpenAI 兼容格式及 `gemini-3-flash-agent`。服务端生成下一条需求方消息，开发者始终使用原 Claude Code 会话与工作区。
- 复用现有调度、输入投递、会话恢复与验收能力；需求方无需独立 CLI、容器或长期会话。一次有效回复先保存，再投递；恢复时继续使用保存的消息。
- API Key 只进入本地受限、被 Git 忽略的配置；任务文档只记录服务、模型和脱敏验证结果。外部服务最小连通测试与完整业务接入分别报告。
- 先用一项真实需求和一个 BUG 验证完整循环，再重审现有百项目内容；已有全部项目仍属于总体范围。
