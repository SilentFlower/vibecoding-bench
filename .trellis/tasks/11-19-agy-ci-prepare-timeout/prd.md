# 定位并修复 AGY 正式镜像准备超时

## Goal

让正式CI的AGY镜像自身验收通过，并恢复v1.19.0发行准备。

## Background

- 用户原目标为合入flower2api并发版。上一交付已完成本仓处理产物附件、19个业务文件及11个任务记录文件的推送；源码为 `2dd715d3459668d48051003bc04650f74680f16a`。
- 正式CI `44466706477` 的合同测试、处理产物准备和两个正式镜像构建通过；模块导入、资源校验及监督器就绪通过。`deploy/flower2api/verify_agy_runtime.py:65` 等待首代prepared超时，当时根因待定位。
- 同一探针在本地隔离镜像及实际2核限制下通过，两代准备与正常退出约18.98秒；客户端docker/requests/urllib3版本与CI一致。CI的Docker与宿主内核版本存在差异。事实记录见 `research/ci-failure.json`。
- 当前探针失败后直接清理容器，公开错误只保留通用超时，缺少区分传输、子进程启动、资源及原生就绪的证据。

## Requirements

- R1：失败前保留有界、脱敏的状态与阶段证据，保留首个错误和原清理边界；证据足以指导下一步定位。
- R2：依据真实证据定位并修复正式镜像或CI的启动差异，保持现有凭据、并发、断网准备及物理退出合同。
- R3：以正式完整镜像自身验证两代准备、单次共享映像解码、零模型及正常/异常退出；成功后回到原v1.19.0新源码预览。
- R4：复用已交付的自有处理产物及固定双层摘要，原签名、来源及真实旧库兼容门禁继续执行。

## Acceptance Criteria

- [x] AC1 / R1：故障注入可见必要的阶段、退出和资源摘要；字段白名单、大小边界、原错误与清理保持通过。
- [x] AC2 / R2：根因有源码或实际运行证据，并以定向回归覆盖；工程选择基于证据，不以放宽限制掩盖失败。
- [ ] AC3 / R3：同源码正式CI的镜像内验收和可信候选交付通过；两种退出、两代凭据、单次共享解码及零模型均有实际结果。
- [ ] AC4 / R4：本仓处理产物和既有发布门禁回归通过，按新候选重新展示v1.19.0发行预览。

## Non-Goals

- CC runtime制备方式、AGY业务协议及账号/数据库语义变更。
- 真实账号、真实模型、生产安装及容器权限放宽。外部模型预算为0。

## 已确认的工程根因

- 原45秒探针预算低于运行时60秒退役、90秒启动窗口；正式CI第二代超时摘要与受控45.3秒退役场景完全一致。
- 原监督器在旧代退役后和Popen前缺少原截止复核。三项先失败回归证实过期仍可建代或启动；修复后保持原请求截止并拒绝额外启动。
- 修复后的隔离镜像及受控慢退役通过，正式完整镜像仍由后续CI验收。
