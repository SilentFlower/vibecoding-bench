# 验收鲁棒性与可操作失败反馈

## Goal

减少符合公开需求的交付被误拒绝的情况，并让真实失败能得到可用于返工的具体反馈，提高真实验收通过率。

## Background

- 用户要求：“修复吧，主要就是为了鲁棒性，能提升通过率 而不是转牛角尖”。
- 2026-10-26 21:05 北京时间的线上只读快照中，账号 10-23 的项目空间有 attrs、babel、bibtexparser 三个待复验目标，工程养号空间没有；三项各经历三次不同候选提交失败。
- 已保存候选的 13 项冻结公开测试全部通过，原业务观察器均返回缺少具体失败项的 `business=false`。具体证据与源码锚点见 `research/online-deferred-analysis.md`。

## Requirements

- R1 验收依据已公开的功能与兼容要求。公开合同没有确定的实现细节不得额外成为拒绝条件；不得为提高数字通过率接受真实功能错误、跳过既有回归或降低覆盖率要求。
- R2 修正 babel 带权语言偏好的误拒绝：保留质量排序、同权顺序、别名、可用区域原拼写、通配符排除、输入上限和旧接口兼容检查；对于未明确的“零权重语言前缀与更具体正权重偏好冲突”，接受符合已有公开约定的两种选择，避免强加单一解释。
- R3 修正 bibtexparser 页码规范化的误拒绝：首尾无意义空白保留或移除均可接受；数字文本、双连字符、首次原值记录、非原地修改、其他字段保持、未知格式整体保持和幂等性继续成立。
- R4 复用已修正的 attrs 合同检查，覆盖原候选和原有反例，确保本轮改动不会重新引入非布尔参数要求、重复调用污染或放行真实错误。
- R5 对 babel、bibtexparser 的真实失败提供有界、脱敏、与公开功能对应的具体反馈，兼容同项目历史目标报告；继续保护私有断言、任意日志和异常正文。
- R6 同步未来目标使用的公开说明、公开示例和独立验收口径；既有工作的冻结资产和历史结果保持可审计，修正以独立的受信执行记录生效。
- R7 保留原候选、原工作、会话与原计划；沿用范围限制、身份、取消、未知输入、严格释放及完整验收条件，不把离线检查通过直接变成线上通过记录。

## Acceptance Criteria

- [x] A1：已保存的 babel 和 bibtexparser 误拒绝样例在修正业务检查中通过，既有参考实现同时通过；分别覆盖 R1、R2、R3。
- [x] A2：attrs 原候选继续通过修正合同矩阵和六项公开测试，原有真实错误反例仍失败；覆盖 R4。
- [x] A3：三个原候选的 13 项冻结公开测试通过，并分别执行对应原生回归；发现真实遗留失败时给出事实，不以改门槛宣称整体通过；覆盖 R1、R4、R7。
- [x] A4：错误排序、忽略通配符排除、未规范化页码、丢失原值、修改输入及吞掉真实失败等反例仍会失败，并返回对应公开行为反馈；覆盖 R2、R3、R5。
- [x] A5：未来内容与控制端的验收口径一致；旧冻结资产不被改写，未知来源或非法诊断不能被当作已通过；覆盖 R5、R6、R7。
- [x] A6：项目和工程养号共用反馈路径、原有适配器、候选归属及待复验恢复相关回归通过；覆盖 R4、R5、R7。

## Non-Goals

- 不直接修改三份候选业务代码来迎合观察器，不删除或覆盖旧失败记录。
- 不调整冷却时长、返工次数、模型配置或整个调度架构，不将历史测试产物加入全局范围豁免。
- 不因部分离线验证通过而跳过原生回归、语义验收或账号运行条件。
