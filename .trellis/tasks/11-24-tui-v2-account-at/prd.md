# V2 内核复用账号 AT 注入官方 CLI

## 目标

已有授权的 Claude 账号切到 V2 后，受管的原版交互 Claude Code 自动使用该账号的有效 OAuth Access Token。用户可以通过原有 Messages 入口完成首轮和客户端工具续轮，无需在服务端交互终端重复登录。

## 需求

- R1 V2 按所选账号复用 V1 的凭据解析、刷新和归属校验。受管 CLI 以 `CLAUDE_CODE_OAUTH_TOKEN` 接收该账号的凭据，刷新令牌继续由既有凭据所有者管理。
- R2 模型请求由同一账号凭据鉴权。保持现有 V2 的真流式、Messages 正文与缓存断点、客户端工具执行及同进程续轮。
- R3 账号工具轮按原账号、主体、会话及进程归属收尾。凭据刷新后的新会话使用新的有效 AT。授权失效时按既有账号行为反馈原因，并保留切回 V1 的入口。
- R4 正式版本对所有受管 Claude 账号开放 V1/V2 选择，各账号自行保存目标。休眠账号选 V2 时按需准备环境。已有轮仍在原内核收尾。
- R5 SSH 工作区沿用独立的人工登录流程。签名发行和线上实测由母任务负责。单账号实测是验收样本，全量开放是产品可用范围。

## 验收

- [ ] 已授权的 OAuth 账号在正常账号镜像内切到 V2 后，首条 Messages 得到流式响应，官方 CLI 接收该账号 AT，上游收到同一账号凭据。合成账号 A/B 交错请求时逐轮校验归属。
- [ ] 核对 AT 刷新后新进程使用更新后的凭据。等待中的工具结果仍回原进程，重复或跨账号回填保持原有拒绝条件。
- [ ] 回环接收端核对首轮和续轮的原始正文、缓存断点、响应增量和单次投递。账号凭据不进入请求诊断、会话记录、持久提交账本及公开响应。
- [ ] 授权缺失或撤销时，展示现有账号对应的错误。已知缺凭据时模型零投递。回退后 V1 的首条请求正常。
- [ ] 打开休眠账号配置，能选择 V2。打开页面只读状态。保存时唤醒该账号并核对绑定，失败时保留原选择。确认无原轮后，已休眠的 V2 账号可保存切回 V1。
