# V2 账号 AT 注入设计

## 接入边界

V1 入口先调用 `AccountService::resolve_upstream_token`，再由 native worker 启动器设置 `CLAUDE_CODE_OAUTH_TOKEN`。现有 V2 先认证账号与入口主体，随后通过账号 sender 做单次预留。V2 gateway 路由不解析上游凭据。内层 CLI 使用会话回环口令，独立开发上游从本机 `local_bearer` 取值。[V1 凭据入口](../../../services/gateway/src/service/gateway.rs#L4591) · [V2 私有预留](../../../services/gateway/src/service/runtime_transport.rs#L1517) · [V2 CLI 启动](../../../images/account/tui_sender_launch.py#L275)

## 数据路径

1. 正式 V2 请求沿现有账号准入和凭据归属路径解析有效凭据。凭据随私有的一次性提交交给绑定的 sender。绑定校验覆盖账号、环境、代次、主体、会话和预留 ID。就绪接口只报告能力。
2. 已认领的新会话在独立 HOME 下启动固定版官方 CLI，并从进程环境接收账号 AT。模型回环仍按本次会话和已开放模型步骤核验请求。Mod 回调保留各自的会话鉴权。
3. sender 向受管上游投递冻结的 Messages 正文，使用该次同账号的授权。继续复用原账号的网络隔离和出站策略。发布候选默认使用受管账号 OAuth。显式配置的独立提供方保留给原有本地开发及回归。
4. 先用合成 AT 验证官方 2.1.293 在本地模型入口实际使用的 OAuth 请求头，以及与请求原文保真、工具参数回传的同时工作情况。根据实测固定回环认证合同和允许投递的协议字段。
5. 凭据仅随当前认证和执行生命周期留存。排空期间复用现有的原工具回执许可。新会话读有效 AT，原工具轮按原进程归属接续。验证轮换时同进程续轮的上游认证衔接。模型执行结果未知和已经交付流式正文的请求保留原有单次提交约束。

## 兼容与回退

私有提交能力按已核验的同发版 sender 协商。管理端沿用现有就绪和按账号切换接口。旧 sender 缺少能力时保留可诊断的未就绪状态。账号切回 V1 仍由现有排空和工具归属接管。

配置页按 V2 切换协议是否可用显示选项。即时就绪状态用于提示准备环境。只有提交涉及 V2 的切换时可经现有传输入口唤醒，且仅针对编排只读响应确认当前没有运行绑定的账号。切回 V1 同样须通过账号排空门禁和旧工具账本核对。远端失联、绑定错误等异常继续按原状态对账。

母任务负责签名发布和线上实测。正式版本按账号开放选择。真实订阅的缓存读取量以实际模型回执验收。
