# v3 登录草稿管理与授权终端修复

## 目标

让开始登录即创建的固定环境在账号页可见、可继续登录和可清理，并修复真实授权链接显示及会话结束后的错误连接提示。

## 背景与已确认事实

- 用户报告三个连续问题：终端已有授权链接而独立链接栏为空；退出后重连按钮禁用且提示仍像普通断线；未登录/提交的账号已创建 Docker 容器，却不在账号列表出现，无法从账号页删除。
- `orchestrator/main.py:4675` 在登录开始时预留名称，`:4691` 调用固定环境登录；`orchestrator/account_runtime.py:158` 创建环境记录，`:958` 创建 tmux/CLI。正式账号在 `orchestrator/main.py:8340` 附近提交后才入库，`:7474` 列表只读已保存账号。
- 环境页已有停止/重建/对账，但没有删除登录草稿的入口（`webui/app.js:82`）；取消清理本次执行和内存会话，保留固定容器与目录（`orchestrator/main.py:4897`、`:8414`）。
- 服务器当前 `10-13` 为尚无正式账号 ID 的环境，固定容器存在；新会话的 tmux 读取正常，但原解析器拒绝了 `https://claude.com/cai/oauth/authorize`，其 PKCE 参数结构有效（`orchestrator/login_terminal.py:7`）。真实授权 URL/state/challenge 未打印或保存。
- 原截图会话检查时已先返回 409、随后 404 且 tmux 不存在；原屏幕已消失，不能把新会话的域名拒绝问题直接断言为原截图的唯一根因。`webui/app.js:689` 遇到结束状态停止重连，`:893` 的离线输入提示仍能覆盖结束原因，需一起修正。

## 需求

- R1：新账号开始登录后在账号页可见，明确显示未完成登录/待提交/已结束/需对账等实际状态，不被当成可用账号调度养号、额度查询或普通任务。
- R2：刷新页面、关闭窗口或服务重启后仍可发现未完成环境；可以在账号页继续尚活跃的同一登录，或者在旧会话结束后明确重新登录，避免隐藏的同名占用和重复容器。服务器重启后保留草稿与固定 HOME，显示登录已中断/待提交的真实状态；不承诺恢复已死亡的 tmux/WS 进程。
- R3：账号页提供取消及删除未提交草稿的明确入口。用户已选择全部清理：删除该草稿、专属容器与未提交目录；操作前清楚说明未提交授权产物也会清除。清理必须确认本次登录、容器与目录归属，并保留清理失败/提交未知的可见状态。已保存/关联账号的历史、凭据与重授权策略保持。
- R4：真实 CLI 输出的受支持官方授权入口完整显示到独立链接栏，继续支持复制和打开；有界提取与 HTTPS、精确主机路径、参数校验保持，不允许任意域名或补猜 OAuth 参数。
- R5：普通 WS 断线可以新票据重连原 sid/tmux，不重放输入；CLI/tmux/会话已结束时明确显示原因和重新登录操作，不把结束原因覆盖成“连接恢复后重新输入”。
- R6：取消、重登、删除与提交之间互斥；凭据提交结果未知时保留暂存与门禁供对账，不通过删除绕过。只操作 v3 本环境，不处理旧版服务。

## 验收

- [ ] A1（R1、R2）：新建未登录账号在账号页出现明确草稿状态；刷新与重启后仍能发现；同名继续/重登沿用原环境身份。
- [ ] A2（R1）：草稿不会被普通任务、养号、额度查询或账号绑定入口当成可用账号。
- [ ] A3（R3、R6）：用户删除草稿后草稿记录、专属容器和未提交目录均清理；重复删除幂等，活动提交、归属冲突或结果未知不误删。
- [ ] A4（R4）：真实支持 CLI 脱敏形状、旧入口、ANSI/软硬换行均能提取完整链接，截断/恶意/重复参数仍拒绝；HTTP 页面复制降级可用。
- [ ] A5（R2、R5）：真实 tmux/WS 演练覆盖连接断开、会话退出、重新登录、页面刷新和启动阶段关闭，状态、按钮与实际会话一致，无旧输入重放。
- [ ] A6（R6）：原关联重授权、唯一刷新权、提交回执恢复、现有账号历史/凭据及固定身份回归通过。

## 范围边界

- 不改 cc2api 上游请求/TLS/遥测协议；不迁移真实账号，不自动操作当前真实授权会话。
- 保持当前管理端自动重启、账号容器按需唤醒的策略；用户此次询问重启行为，不表示要求所有账号同时自启。
- 任务已获确认并进入实施。生产清理、Git 推送和部署仍使用后续明确的交付范围，不复用已完成任务的进度。
