# 实施与验证

1. 在独立检出用签发基线重现旧 Gateway 的全局待回执拦截和宿主切换前拒绝，建立账号级、带签名输入的可重放隔离样本。
2. 先落实受信的只读证明和 Gateway 对账，覆盖相同代次的活跃、已退出、失联、账号或代次不同。写事务覆盖拒绝、重复操作、并发迟到回执及无头或显式会话。记录恢复前后的原状态与模型投递次数。
3. 接入系统更新页的脱敏状态及单条动作。复用管理员路由鉴权、更新页轮询和冲突处理。验证按钮立即核对单条记录、结果与账号延期提示、恢复联系后一键续办和自动重试，以及跨账号、旧页面与重复操作。
4. 接入滚动和旧版第一跳，校验控制快照、可保留的账号原环境及单账号租约。按现有 v2 同协议宿主维护流程，从原固定源码树、策略和服务开始，交付经签名来源核验的精确文件清单，验证仓库外导入、服务重启、空闲门禁和原安装状态。记录部分替换或启动失败时的恢复结果。随后经原更新入口用真实旧版 Gateway 演练第一跳，核对自然排空、双库、中央先恢复、正常账号换版及原账号延期续办。覆盖活跃原轮、过期孤儿、远端失联、迟到回执、正常升级和切换前失败回退。
5. 运行 Gateway V2 及系统更新定向测试、账号镜像和 TUI 测试、编排更新和节点回归、宿主发布校验与 Web 构建。用实际旧版流程及合成调用验收。整理证据交主窗口独立复验。
