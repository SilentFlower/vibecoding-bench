# 恢复 V2 孤儿工具回执并解耦平台滚动升级

## 目标

已失去原运行进程的 V2 工具回执可以恢复。平台滚动更新先更新控制服务，仍待处理的原工具轮由对应账号继续处理。管理员能在系统更新页查看状态并恢复可处理的记录。

## 背景

主窗口已在美国节点复现。同一待回执四次收到 422，原 V2 进程约一小时后退出，网关仍有一条待回执。该记录使平台更新预检拒绝继续。

## 需求

- R1 根据受信发送器和编排状态识别失去原进程的回执。已证实失效的记录自动收口。原轮活跃或现场状态未知时显示对应状态，保留原会话归属和真实投递结果。
- R2 受支持的滚动升级可以先完成控制服务切换。有待回执的账号保留原运行环境，该账号的镜像更新待原轮完成或查明失效后继续。平台仍核对全局在途请求、实际写入和数据快照。
- R3 系统更新页按账号显示等待、可恢复及待核对状态。管理员点击「核对并恢复」后立即核对当前单条记录，并收口已确认退出的原轮。操作使用当前版本的记录，同一记录重复操作给出一致结果。节点失联时显示「该账号延期、平台可继续」，保留原记录和账号更新进度。恢复联系后可一键续办，后台也会自动重试。人工恢复受原轮结束证据约束。
- R4 支持已有全局回执门禁的宿主和网关升级到修复版。第一跳通过受信的宿主兼容接入保留已核实的账号运行环境，按原维护流程排空活跃工作，并保持签名、快照和回退校验。
- R5 原结果、后续工具轮及同账号其他会话分别按各自凭证处理。回收后的迟到结果可得到行动提示。模型请求保持单次投递，回收状态真实反映原轮的结论。

## 验收

- [ ] 原发送器确认原会话已退出且无该轮活动时自动恢复。历史记录可以使用受信证据判定。回执收口后该账号的更新继续。
- [ ] 同时安排两个账号。一个仍等待工具，另一个可更新。控制服务更新并恢复接单，原会话仍可正确续轮。原账号回执完成后继续其镜像更新。
- [ ] 远端失联时界面显示「该账号延期、平台可继续」。中央和其他账号继续更新。该账号保留原记录、环境和进度。恢复联系后，一键续办与自动重试均可核对原轮并继续符合条件的账号更新。身份或代次核对不一致时，页面显示相应原因。
- [ ] 从带有一笔历史孤儿回执的实际旧宿主工具与发布网关出发，先按宿主源码维护流程刷新原固定执行器，再通过同一更新入口完成中央第一跳。核对服务归属、双库、正常无阻塞更新、宿主刷新失败恢复、切换前失败回退及恢复后账号状态。
- [ ] 回执抢先认领、恢复抢先完成、重复点击、旧页面、跨账号和未授权请求各自得到确定结果。已投递或结果未知的请求保持禁止重放。

## 范围

业务修复及本地验证由本任务负责。线上待回执处置、独立验收、提交合入及发布由主窗口负责。
