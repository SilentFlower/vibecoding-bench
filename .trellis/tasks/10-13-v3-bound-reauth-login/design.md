# v3 关联重授权与登录终端设计

## 边界与决定

- 沿用两镜像和固定账号容器；本任务涉及 bench 登录后端/静态页面、cc2api 凭据管理服务/存储以及隔离验证脚本。
- 登录与换码仍由真实 Claude Code CLI 在原账号容器的 tmux 中执行；管理页面不会替代 CLI 生成 OAuth 请求。
- 只更新当前绑定的同一 cc2api ID，不新建、猜测或自动改绑；不会更新 cc2api 请求改写、TLS、上游转发或遥测协议。
- 日常 CLI 和 API 继续独立。只有登录维护关闭该账号的新 API 入场，排空旧请求；活动 CLI/run/续聊拒绝开始重授权。复用排空超时并提供明确失败提示，不强制中断旧请求。
- 绑定重授权使用当前账号与 cc2api 的权威代理和固化时区；表单展示这些值但禁止顺便修改。新建账号和未绑定账号保持现有配置入口。
- 本方案只自动恢复明确因 OAuth 凭证失效停用的关联账号；认证错误与停用原因必须一致且属于已有 OAuth 认证失败分类。手动停用、限流、其他错误、bench 启停、养号开关与阈值均保留。该策略与本次完整方案一起评审。

## 绑定重授权流程

1. start 在 `_oauth_owner_lock(name)` 中重读账号与绑定；仅 v3、明确 `force_reauth=true` 且关联 OAuth 账号进入新分支。普通运行仍只允许 active；登录准入可读取 disabled/error OAuth 的现有配置而不放行普通任务。
2. 快照 bench ID、cc2api ID、原身份、环境 ID/代次与租约 owner/generation。领取原环境排他登录租约并持续心跳；开始期间检查已有工作，不让原登录会话被自身空闲检查拒绝。
3. 暂存 HOME 沿用已有设备相关配置与设置，移除旧凭据及旧 OAuth 身份缓存，避免错登后仍读到旧身份。原 HOME/profile 不提前写入。临时 HOME 不产生新的管理端设备画像。
4. CLI 完成后，以当前登录产物和 `claude auth status` 验证 loggedIn、AT/RT、有效期以及新身份。账号 UUID 为主；原有关联 UUID 时不允许降级为邮箱；组织已明确时也要一致。缺少可验证的新身份时拒绝提交，不用复制过来的旧身份补齐。
5. commit 再次持有 owner lock 校验原绑定、环境/租约和活跃工作，按 owner → profile 的锁顺序执行。先记录受控持久提交意图，再调用新 cc2api 导入接口，随后将 cc2api 返回的最终凭据快照写入 bench 管理 profile；主 HOME 只发布 AT。
6. 凭据、配置和状态确认完成后，收口登录 CLI/tmux、销毁暂存 RT，再释放租约。用户看到“已重新授权并同步关联账号”。清理失败或结果不确定时保持需重试/对账状态，不假报成功。

## cc2api 凭据导入契约（拟新增）

- `POST /admin/accounts/{id}/oauth-credentials/import`：仅允许已配置 v3 的可信服务调用，要求现有 admin 鉴权和 `x-v3-service-token`；浏览器不持有服务秘密。
- 输入包含操作 ID、当前登录租约 owner/generation、已验证身份、新 AT/RT/毫秒有效期；严格校验体积、类型、非空与有效期。接口专门处理凭据，不接受代理、device_id、canonical_env 或绑定变更。
- 校验同账号仍为 OAuth，租约是有效 claimed 排他登录租约且活动请求已排空。复用该租约，不能再领取 gateway-config 门禁或 quiesce 掉当前登录容器。
- 在已有 `oauth:refresh:account:{id}` 账号锁内重读身份与状态，通过 store 的同一事务写入 AT/RT/有效期、清除旧认证错误、仅恢复明确 OAuth 认证失败停用，并写入导入回执。恢复不能删除真实限流或覆盖同时发生的人工停用。
- 回执仅存操作 ID、账号 ID、请求摘要与时间/状态，不新增明文凭据副本。新增表在 SQLite/PostgreSQL 幂等初始化；同操作同载荷返回当前权威快照，不重放旧凭据；操作 ID 复用为不同载荷或账号返回冲突。
- `GET /admin/accounts/{id}/oauth-credentials/import/{operation_id}`：相同服务鉴权的只读对账接口，在账号凭据锁内读取回执及当前快照。未提交、已提交或暂时无法确认必须区分；不经管理桥公开凭据响应。
- 返回最小受信任快照与提交结果；bench 给浏览器的响应只包含账号 ID、同步状态和必要脱敏状态，不含 AT/RT。

## 防止旧刷新覆盖

- 导入复用 Memory/Redis 的现有账号 OAuth 锁，而不是新增第二套刷新所有者。
- 当前锁 TTL 为 30 秒，单靠锁不足以防延迟网络回包。刷新成功与失败落库以调用时 AT/RT 快照做条件更新；快照已改变时丢弃旧结果并重读当前状态，不能写旧凭据或旧 auth_error。
- 涉及认证停用的写入同样核对凭据/停用快照；手动停用不得被凭据导入反向覆盖。导入与状态调整原子提交，不能调用当前会清掉限流的通用 enable_account。
- 已绑定 bench 不持 RT 进行自动刷新，日常仍拉取 cc2api 的最新凭据；只有明确 CLI 重授权产物进入导入入口。

## 部分失败、取消与重启

- root 私有的 runtime 提交记录保存操作 ID、绑定/租约快照、阶段及暂存位置，权限 0600；原子写入且不包含令牌、授权码和终端全文。
- 导入尚未调用前取消可以直接收口并保留原 profile。调用之后 HTTP 超时不能判断为未提交；查询回执或以同操作 ID 重试，避免回滚已经在上游轮换的新 RT。
- cc2api 已提交而本地镜像失败时保留暂存资料和门禁，重试先读取 cc2api 当前快照，不把第一次的新 RT 再覆盖到已进一步刷新的账号。
- 对不确定提交禁止普通取消删除暂存或自动 TTL 清理，页面提示需重试/对账。已提交的取消仅放弃终端，不回滚远端凭据。
- 服务重启不承诺恢复同一交互终端；显示会话已失效或待对账。持久提交记录先于现有排他执行清理处理；未确认最终凭据时保持隔离。对账在旧租约失效/撤销且旧导入不能再写入后，串行查询回执，镜像权威凭据、清理暂存，最后释放门禁；无法证明收口时保留 reconcile。
- 同一身份重授权保留额度观察/真实限流和阈值等待，不执行当前通用 commit 的整账号额度状态删除。旧认证错误恢复与额度门禁是独立状态。

## 登录会话状态与授权链接（拟新增）

- 增加 `GET /api/accounts/login/{sid}/status`，返回会话存在/过期、登录阶段、可重连性、过期时间、同步状态和当前授权链接；响应 `Cache-Control: no-store`，继续走管理会话鉴权，不把 SID 当登录权限。
- 授权链接从当前 tmux pane 的有界输出中提取，使用 tmux 的拼接换行模式，处理 ANSI/控制字符及屏幕换行；只展示实际 CLI 输出的 HTTPS 官方授权入口，严格限制长度和主机/路径，不根据片段自行生成 URL。
- 无浏览器连接时也能从同一个 tmux 获取已输出的链接；只缓存当前有效候选，不记录或持久化终端全文。会话终止后清掉 URL。
- 新 UI：只读完整授权链接栏、“复制链接”“打开授权页”、连接状态与“重新连接”。通过真实 DOM 属性/textContent 展示，打开链接加 noopener/noreferrer。
- 优先 Clipboard API；HTTP 不可用或权限失败时选择只读输入框并尝试兼容复制，最后明确提示手动复制，不能未复制却提示成功。
- 去掉授权码额外本地回显，保持 xterm 正常传输；不将授权码写入新日志、回放缓存或浏览器持久存储。

## WebSocket 生命周期

- 登录终端专用可重连连接管理沿用 xterm；可在现有 attachTerminal 增加明确的登录选项，保持续聊默认逻辑不自动重连。
- 每次建连重新请求短票据，使用原 sid/ws_path attach 原 tmux；不能重复执行 `claude auth login`。socket、ticket URL、重试与心跳句柄归 state.accLogin 管理。
- 有界指数重试加手动重连；连通前禁用输入。旧 socket 回调按连接代次校验，避免关闭旧连接导致新连接被判断线。离线时的输入丢弃且提示，不缓存/重放授权码。
- 增加有界心跳/超时以识别半开连接，状态查询只在登录 modal 存续期间进行；退出、401/403、404/过期或主动取消为停止重连条件。
- 服务端任一 pump 结束即取消并等待另一 pump，收口 Docker attach；阻塞 Docker 调用不得阻塞整个异步事件循环。WS 断开仅 detach，不清理登录会话和排他租约。
- endAccLogin 对重连计时器、心跳、请求、当前 socket、xterm/resize 监听统一幂等清理，取消/commit 成功后不重连；保持管理桥 cookie 会话撤销行为。

## 兼容、交付与回滚

- 新分支限 v3 绑定重授权；未绑定登录/取消、续聊终端及旧部署拒绝绑定重授权的保护回归保留。旧端口 5674/8080 不操作。
- 不增加镜像、公共端口、代理架构或前端构建工具；静态资源更新同步缓存版本。
- 新回执表为增量 schema，旧账号/设置值不自动修改；旧二进制回滚前必须确认没有待提交重授权并收口会话，否则保持维护门禁。
- 自动构建、GHCR 推送与生产部署不属于当前规划授权；完成实现检查后按既有发布流程交付同批两个镜像，再按用户明确范围部署。

## 风险与验证边界

- CLI 输出/配置差异可能影响新身份与链接解析，必须以实际支持版本的脱敏产物补足用例；错误时拒绝猜测，保留终端手动操作。
- HTTP 超时与进程退出可能发生在远端提交后，需用回执和持久状态证明是否可清理门禁。
- 假号只验证系统机制；真实 CLI OAuth、上游账号状态与封禁解除不从假号推断。
