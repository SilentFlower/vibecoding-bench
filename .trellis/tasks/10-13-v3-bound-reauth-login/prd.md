# v3 关联账号重授权同步与登录终端改进

## Goal

让 v3 中已关联 cc2api 的 bench 账号可以直接重新授权，并可靠地同步新凭据，同时改善授权终端断线和授权链接复制体验。

## Background

- 用户需求：“有时候他会踢号，bench重新授权的时候能不能把有关联的号同步凭证过去？”；“在授权的时候之前是经常websocket断 也不好复制授权的链接等等。”
- 已绑定账号当前隐藏重授权入口且后端直接拒绝（`webui/app.js:211`、`orchestrator/main.py:7856`、`:8026`）；登录终端没有自动重连或独立链接复制（`webui/app.js:660`、`webui/index.html:519`）。

## Requirements

- R1：已关联账号提供“重授权”入口，完成真实 Claude Code CLI 登录后，将新访问令牌、刷新令牌与有效期更新到原关联账号，不需要解绑、重建或重新选择关联。
- R2：提交前核对登录身份与原关联身份，拒绝错登其他账号；取消、身份不符或登录未成功时保留原凭据和关联。
- R3：重新授权仍使用原账号固定环境；日常 API 转发与养号继续独立，只有重授权维护阶段需要对该账号排他处理。
- R4：凭据同步失败时展示可理解的失败原因并允许重试；不得在只完成部分同步时提示成功，也不得让旧凭据覆盖已确认的新凭据。
- R5：授权终端短暂断线后可以自动重连或手动重连同一登录会话；展示连接状态，不重复启动登录，不重复提交终端输入。
- R6：独立展示完整授权链接，支持打开和复制；在 HTTP 页面、断线和窄屏中也提供可用的复制方式。
- R7：不把访问令牌、刷新令牌、授权码或完整终端内容写入普通日志、浏览器持久存储或错误信息；登录相关数据沿用现有管理鉴权边界。
- R8：成功重授权并同步后，仅自动恢复明确因 OAuth 凭证失效而停用的关联账号；手动停用、限流和其他原因停用保持原状态。保留 bench 启停、养号开关、阈值配置及同一身份已有额度观察，不自动重开养号。
- R9：本轮面向 v3；保持旧服务兼容，不关闭、重启或迁移服务器上的旧 bench 和旧 cc2api。

## Acceptance Criteria

- [x] A1（R1、R3）：已绑定账号可以登录并同步到同一 cc2api ID，绑定、固定环境与设备身份不变。
- [x] A2（R2、R4）：新凭据不会被并发旧刷新覆盖；取消、错登与凭据同步失败不损坏原关联。
- [x] A3（R4）：提交重试具有幂等性，部分失败不会被报告成成功。
- [x] A4（R8）：认证失效自动停用账号在成功重授权后恢复 API 使用；手动停用、其他原因停用、限流、bench 启停、养号开关、阈值配置及同一身份额度观察保持。
- [x] A5（R5）：WebSocket 人工断开后可以继续同一 CLI 登录，重新连接时取得有效鉴权票据。
- [x] A6（R6）：授权链接能够完整显示、复制和打开，包含 HTTP 页面复制降级与窄屏验证。
- [x] A7（R5、R7）：登录会话过期、取消、服务重启及非法鉴权会显示明确状态，不继续向失效会话发送输入，不暴露敏感凭据。
- [x] A8（R1—R7、R9）：使用模拟账号和模拟上游验证凭据同步、失败重试和断线流程，旧服务不受影响；真实 OAuth 成功仅由用户提供测试账号后验证，不混用假号结果证明。

## Constraints

- 重授权会暂时暂停该账号接收新的 API 请求；其他账号维持现有调度。正在运行的任务、续聊或 API 请求不能被强行中断。
- 日常绑定凭据自动刷新仍由 cc2api 单独负责；真实 CLI 重授权不是第二套后台刷新机制。
- 对真实上游登录成功和账号状态的结论须有真实测试证据，不能从模拟账号测试外推。

## Non-Goals

- 不调整 cc2api 的上游请求改写、TLS、遥测或模型协议，不替代真实 CLI 登录。
- 不修改或迁移旧版生产账号/服务，不增加镜像和公共端口；不将构建发布或生产部署包含在本次实现评审中。
- 不保证重授权解除上游封禁，不保证管理服务重启后无缝恢复交互终端。
