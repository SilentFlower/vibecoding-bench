# v3 持久计算机指纹与 vm2api 行为对齐

## Goal

为 v3 账号补齐自有静态计算机指纹生成与常规读取覆盖，使首次生成的身份在任务切换、服务重启与容器重建后保持一致。

## Background

- 用户原话：“我们能不能完全对齐vm2api生成的这个指纹？让他全部都生成随机的，且重建或者重启不会刷新”。
- 用户已选择本项目独立实现相同字段及持久化行为，不接入 vm2api 的闭源生成器；本任务以 R1—R6 的字段、读取范围和生命周期验收定义对齐目标。
- 当前 v3 已按环境持久保存 hostname、MAC、machine-id、时区与语言，CPU／内核画像保存在 `account_environments.fingerprint_json.system_profile`。生成与读取入口分别见 `orchestrator/account_runtime.py:61`、`:271`、`:329`；CLI 挂载见 `orchestrator/account_isolation.py:187`。
- 生产只读核对：10-17 与 10-19 保存了 CPU／内核画像并配置了 CLI 的只读挂载；10-13 与 10-15 没有该画像。当前生产账号容器均已停止，本任务不启动这些账号。
- 当前没有独立生成的完整 DMI 包，也没有截图对应的统一物理特征展示页。常规读取覆盖及限制见 `doc/v3-system-profile.md`。
- vm2api 固定研究版本为 `819ee2a7c40b49fe81ebc3823e20373350a20545`，公开部分可核验身份产物的复用、挂载与采集，内部生成算法未公开。研究依据见 `research/current-evidence.md`。
- 既有已确认边界：CPU 数量、拓扑、指令集、实际限额与 RSS 保持真实；原生 CLI 和现有网络隔离继续保留。来源为归档任务 `10-17-v3-system-fingerprint/prd.md` 的 R3、R4、R7。

## Requirements

- **R1：首次生成与字段覆盖。** 使用本项目可审查的生成器，每个账号首次建立完整静态画像时，生成并保存主机名、MAC、machine-id、DMI 序列号和 UUID；CPU、内核及 DMI 厂商／产品／版本／系列按兼容模板组合选择。已保存且合法的静态字段继续复用。新字段的随机来源与账号 OAuth、官方 CLI 设备 ID、MAC 和其它字段相互独立，不使用真实硬件序列号。
- **R2：身份生命周期。** 新任务、续聊、恢复、服务重启、容器停止唤醒、删除并重建容器、镜像更新均不能重新抽取已保存字段。持久化位置必须独立于可删除的容器层，重复初始化和并发调用也不能生成第二套有效身份。
- **R3：整套一致性。** 随机化不得产生彼此冲突的 CPU 架构、型号、系统家族和 DMI 组合。用户已有显式时区、语言及现有合法身份保留。已安装包管理器／工具链、实际资源约束和运行指标按真实环境观察，不随机虚构。
- **R4：容器内可复核。** 支持字段必须能在约定的容器读取接口中复核，不能仅改变数据库或页面显示。DMI 六个字段覆盖 `/sys/class/dmi/id` 与 `/sys/devices/virtual/dmi/id` 两种常见路径下的动态文件读取、存在性和可读性检查、支持的相对目录读取。保留现有 CPU／内核覆盖，分别记录常规文件接口、语言运行时与未覆盖的直接系统调用／CPU 指令边界；不把 vm2api 页面值当作已实现读取覆盖的证据。
- **R5：兼容与失败行为。** 保留账号 HOME、官方 CLI 设备身份、凭据、代理、绑定及历史任务。已有记录损坏须明确报错并保留证据，不能通过重新随机掩盖问题。活动执行中不切换身份，不能为本功能增加业务容器权限。
- **R6：离线验证。** 使用合成账号和无真实凭据的隔离环境核对生成、持久化、重启和重建；不使用受限账号发送模型、遥测、额度或认证请求。本任务规划不包含生产切换。

## Technical Notes

- 本地规划实验表明：当宿主没有对应 DMI sysfs 目录时，直接 bind 到 `/sys/class/dmi/id` 或 `/sys/devices/virtual/dmi/id` 会在 OCI 初始化阶段失败。采用现有动态读取覆盖机制扩展，不为此扩大容器权限或替换整棵 sysfs；证据见 `research/dmi-read-feasibility.md`。
- 临时原型证明 Python、Node、cat 的内容读取可扩展，但存在性与可读性检查仍需实施与验证。本任务不能把这次原型当作完整实现或正式镜像验收。
- 原厂产品资料只用于核验 CPU 与机型大类的兼容性；DMI 文本属于本项目定义的合成模板，不声称是原厂实际 DMI 快照。模板及来源记录在 `research/hardware-template-sources.md`。

## Acceptance Criteria

- [x] **A1 → R1、R3：** 新建合成账号获得完整合法的静态画像，字段格式及跨字段兼容性均可验证；不同账号拥有各自身份。
- [x] **A2 → R2：** 同账号跨首次初始化重复调用、并发请求、新任务、恢复、重启、容器重建与镜像更新后，所有已保存静态字段及其摘要一致。
- [x] **A3 → R3、R5：** 旧账号的合法 hostname、MAC、machine-id、CPU／内核画像、时区、语言和官方设备身份不被隐式刷新；原 HOME、最新凭据、代理及绑定保留。
- [x] **A4 → R4：** 以容器内实际读取证明每个受支持字段及读取入口与保存画像一致，明确列出未覆盖路径；不能仅检查管理接口 JSON。
- [x] **A5 → R5：** 半写入、损坏字段、未知模板、版本不兼容或活动执行时拒绝切换，不生成替代身份，不影响其他账号或健康的独立 API。
- [x] **A6 → R6：** 完成本地生命周期、既有 CLI／API 基础行为及权限边界验证，验证记录不含真实凭据或额外上游业务请求。

## Non-Goals

- 本次不扩展到 KVM、QEMU、CPU 指令仿真或更换宿主内核。
- 不因补齐指纹新增模型请求、改写官方 CLI、模拟用户活动或改变遥测开关。
- 不顺带改造任务调度、凭据刷新、代理策略或题库。
- 本轮不新增统一物理特征页面，以容器内实际读取及离线验证报告验收。
- 不复刻 vm2api 闭源算法，不接入其二进制。
- 不实现 SMBIOS 二进制表、`dmidecode` 全量输出或完整 sysfs 树仿真；直接系统调用、静态程序和 CPUID 的既有边界不扩大。
