# 反重力工具续轮模式与请求失败修复设计

## 后台摘要与工具回填

已核对的 Claude Code AgentSummary 分支重带完整工具结果，并追加固定的 `Describe your most recent action in 3-5 words` 模板和可选 `Previous:` 行。追加文本改变请求正文，因而产生不同的 `ReplayKey`。真实回填正在准备时，第二个正文碰到 `claimed`。真实回填开始提交后，原待续记录已移除，第二个正文缺少唯一归属。两种错误来自同一类分支在不同时间进入。

在已通过鉴权、请求校验并确认 AGY 路由的 Messages 入口，在 `continuation()` 之前匹配完整模板、用户尾部结构和对应的成对工具调用与结果。匹配依据来自真实脱敏请求和客户端模板。匹配时根据最后一项可识别的工具动作和目标生成 3–5 词的简短状态，失败或无可识别目标时使用如实的通用描述。按客户端的流式选择输出标准 Anthropic SSE 或 JSON。诊断记录为本地摘要和实际零上游用量，工具归属和原生生成资源由真实回填持有。校验普通追加文本时保留原文和原完整正文重读逻辑。[Messages 与续轮处理](../../../services/gateway/src/service/gemini.rs#L832)

## 内核提前收尾

`Receive` 关闭时，`SendUserCascadeMessage` 的结果可能仍在传回。已观察到接收结束且缺少源终态时，内核在原请求剩余时间内等待同一次控制调用，响应原取消并检查真实进程退出。区分真实控制 4xx/5xx、控制调用超时或传输失败、控制成功且源流缺少终态。控制状态码和脱敏错误类别分别记录，例如已确认的响应读取 `unexpected EOF`。已确证的源配额 429 优先。已完整交付的成功结果按现有规则收尾。[原生控制调用](../../../services/orchestrator/agy_runtime/kernel.py#L545) · [隔离回环](research/agy-native-stream-eof.md)

## 网关提前返回 HTTP 200

在公开响应形成首帧的共同入口，对首块之前的用量和元数据做有界累积。按协议判断可交付的第一段内容、完整工具批次或可直接向客户端交付的明确终态，比如真实拒绝。保留支持的思考块和用量含义。用量后异常中断的请求，在提交响应之前通过原 HTTP 错误映射返回。响应已经开始时，Messages 通过标准 `event: error` 收尾。新请求、工具回填结果重读与非流式聚合按相同的真实终态处理。新增诊断记录接收结束、是否观察到源终态、控制调用状态及错误发生时的交付阶段。[公开首帧处理](../../../services/gateway/src/service/gemini.rs#L1594) · [Messages 输出](../../../services/gateway/src/service/gemini/messages.rs#L483)

## 原生调用归属与提交后回执

- 原版隔离回环核对原生路由、SDK Scanner 与 Receive 的归属。原生调用的根、请求身份和帧顺序沿原来校验。对主轮结束后能够确认身份的独立调用隔离其全部帧。独立调用数量不决定主工具回填。主工具帧仍要求主调用的序列、原生轨迹和完整工具批次一致。缺会话 ID 的归属以实际原版观察为依据。
- 回填到发送边界时冻结原尝试的轻量回执。复用既有规范化正文摘要、令牌、模型和账号绑定，附带会话及提交状态。响应帧和真实执行仍按各自现有预算回收。短响应窗口结束后单独保留回执，使同一回填继续指向原尝试并返回实际失败或明确的已过期。回执不持有工具正文、帧或原生许可。发送状态未证实为未提交时保留一次提交边界。

## 环境设置与执行端

在反重力请求内核面板添加独立策略项。设置随逻辑环境持久保存，沿现有环境归属、管理授权及本地和远端控制路径读写。变更校验环境代次和当前配置版本，返回实际已保存值。策略热保存和镜像切换各用自身入口。新派发的原生请求取得当时的环境偏好，工具批次发布时冻结策略及可选路径。发送器和网关使用一致的冻结结果，内部契约的可选字段在默认策略按旧形态发送。包含历史的两项策略要求完整执行链提供对应能力回执，界面说明具体不兼容原因。[环境内核面板](../../../apps/web/src/components/runtime/EnvironmentKernel.vue) · [现有镜像控制入口](../../../services/orchestrator/main.py#L14815) · [发送契约](../../../services/gateway/src/service/agy_contract.rs#L210)

- **领取续轮**继续使用原待续轮和真实结果回执。有效回填只接管一次，匹配的请求正文共享结果。
- **历史续轮**在源工具帧和原生桥确认完整调用批次时登记归属，由发送器复用 `CancelCascadeInvocation` 的真实取消与进程退役路径。客户端执行工具期间，旧轮完成收口并释放原生执行资源。匹配的关闭回执允许接续生成。回填按已登记的原会话、令牌、环境、账号、模型和工具 ID、参数、真实签名核对，以冻结的历史和真实结果构造 `native_history`，在原账号授权和准入校验后开启下一轮原生请求。开放新模式前需在原版 AGY 1.5.9 回环验证提前执行后的退出、结果导入和恢复路径。[工具交付和登记](../../../services/gateway/src/service/gemini.rs#L2137) · [原生取消](../../../services/orchestrator/agy_runtime/kernel.py#L558) · [历史转换](../../../services/orchestrator/agy_runtime/gemini_contract.py#L158)
- **领取优先，历史兜底**沿领取路径等待真实结果。正常收口时沿原路径提交。如果原生旧轮已无法接收回填，使用与原尝试、环境代次和工作进程匹配的实际关闭证明。原回填归属和当前权限校验通过且下一轮明确待提交时，持有原提交权切到相同的历史导入路径。普通 400、单次超时、连接丢失或取消登记本身不作为关闭证明。两条路径共用一次提交和同一重读记录。[旧轮收口与提交边界](../../../services/gateway/src/service/gemini.rs#L173) · [发送器收口回执](../../../services/gateway/src/service/runtime_transport.rs#L297)
- 批次归属和原生执行资源分别收回。兜底策略保留工具批次和关闭状态到原批次截止，因此已确认的原进程退出后仍可验证真实回填。切换设置时使用原批次冻结的策略。旧轮尚在关闭或提交状态未知时，在该次原有预算内核对。已提交的同一回填等待原尝试或重读结果。预算耗尽或状态仍不明时交付明确错误。过期、记录缺失、授权撤销、其他会话重用或冲突结果进入既有校验。日志在原尝试下记录实际续轮路径与受控切换原因。后续提交继续遵守原账号和维护准入。
- 当前 WebSearch 关联由已认证搜索会话和工具调用查询构成，依赖活跃原轮次、账号许可和原发送编号。存在该关联时整个批次冻结为领取。管理设置显示偏好，请求诊断记录生效模式、来源和原因。[WebSearch 回调许可](../../../services/gateway/src/service/gemini/websearch.rs#L231)

## 风险与恢复

- 直接历史模式可在工具执行期间提前收口。领取兜底等待领取失败得到核实后才进入历史，故障路径的回填耗时单独记录。隔离回环比较直接领取与直接历史的关闭时长、回填到可用首块和缓存前缀。真实命中率以实际流量观察为准。环境可切回领取，新派发请求读取恢复后的设置。
- 本次重复携带工具结果的错误已定位到后台摘要与主回填竞争。AstrBot 空流已定位到 Flower2API 首帧提交过早和原生控制状态丢失，源接收通道结束的触发因素仍待识别。原生错误日志记录状态和阶段，正文和凭据按现有约定脱敏。
- New API 在等待上游响应时可能先发送保活。一旦它自己提交响应，当前 Claude 转发分支的普通 JSON 错误无法替代 SSE 尾帧。通过复验记录当前 Flower2API 修复覆盖的实际入口。New API 已开流的错误传播需要从它的 Claude 转发层处理。
