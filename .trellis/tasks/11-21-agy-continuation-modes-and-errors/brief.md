# 反重力工具续轮模式与请求失败修复

## 目标

让 Flower2API 按运行环境选择工具续轮方式，修复工具回填、后台摘要和 AstrBot 空流故障。

## 改动范围

- 运行环境的请求内核设置、AGY 工具回填、原生收流和 Messages 错误输出。全部在同一个任务内验收。
- 纳入主轮 STOP 后额外调用导致工具交付失败，以及同批回填在 120 秒后失去原尝试归属的问题。

## 转发范围

- 代码范围按 Flower2API 规划。经 New API 转发也会复测。**New API 已发出保活或内容时，当前 Messages 转发存在把失败写成普通 JSON 的路径。该场景要收到正确的 SSE 错误，需要 New API 转发层改动。**

## 改动预览

### 工具续轮模式

在「运行环境 → 请求内核 → 工具续轮模式」按环境设置。

- **领取续轮，默认。** 收到匹配的真实回填后收口旧轮，再生成下一步。
- **历史续轮。** 客户端执行工具期间提前关闭旧轮。收到真实工具结果并核对关闭回执后，带完整历史和签名开启下一轮。
- **领取优先，历史兜底。** 先尝试领取。领取无法完成后，只有旧轮已确认关闭、工具批次仍有效、归属和签名通过校验、下一轮明确待提交时才切到历史。相同回填等原请求或重读结果。状态不明先核对。真实过期或归属冲突返回对应错误。

### 两种工具回填 400

Claude Code 后台摘要重带同一批工具结果。主请求正在领取时，摘要触发「工具轮已领取或到期」。主请求已开始下一轮时，摘要触发 `AGY_TOOL_RESULT_MISMATCH`。在 AGY Messages 入口精确识别该摘要并本地返回短状态，让真实回填继续按原归属处理。正常用户追加文本按原请求处理。

### AstrBot 空流

1. **内核提前收尾。** 在原请求剩余时间内等待真实控制结果，分别保留源终态、实际状态码和脱敏错误类别。区分缺少模型结束帧和响应读取中断。
2. **网关提前返回 HTTP 200。** 预先累计用量，在有可交付内容或明确终态时开流。首块有效内容前失败返回非 2xx HTTP 错误，开流后用 SSE `error`。首次请求和重读使用相同规则。

### 主轮结束后的额外调用与回填重读

- 按原生调用和帧身份隔离可核实的独立调用。主轮完整工具批次沿原轨迹交付。
- **已提交回填的轻量回执独立于 120 秒响应缓存。** 同一回填仍关联原尝试并得到原失败或明确过期。保持一次提交。

## 关键决定

- **保存后由新派发的请求读取设置。已发出的工具批次继续使用发出时的策略。** 旧环境缺配置时默认领取。两个包含历史的选项需要当前执行链支持。领取与历史共享一次提交，同一回填只触发一次生成。
- **依赖现有 WebSearch 回调的整批工具使用领取续轮。** 回调需要旧轮的账号和搜索许可。诊断会显示配置策略、实际路径及兜底原因。

## 待验证

- 用原版 AGY 1.5.9 验证提前收口、历史导入和领取失败后的接续。对比直接领取与直接历史的收口时长、回填延迟和缓存前缀，单独记录兜底延迟。
- 原版隔离回环已复现控制结果晚到和用量帧提前开流这两个缺陷。线上那笔请求的原生接收通道关闭原因仍待验证。接续记录沿用进程内有效期，网关重启会丢失在途批次的归属状态。

## 验收

- 验证两个环境独立保存、切换时已发工具继续处理、WebSearch 回调和并行同名工具。覆盖安全兜底、提交状态不明、过期、归属冲突和并发重试。核对实际模型提交数。
- 重放两种 400，确认摘要可返回且主回填只生成一次。重放两种用量后中断，分别核对内核控制状态和 Messages 开流前后的错误。用 AstrBot 形态复测直连和 New API 转发。
- 回归正常 Messages、原生 Gemini、CC Runtime 转发和已修的 Read 缓存前缀。
- 用隔离原版 AGY 检查主轮 STOP 后的两次额外调用、并发帧归属与错归属拒绝。验证回填并发、响应回收和三种续轮策略下的单次提交。
