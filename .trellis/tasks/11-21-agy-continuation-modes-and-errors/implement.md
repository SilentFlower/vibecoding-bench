# 反重力工具续轮模式与请求失败修复实施与验收

## 顺序

1. 提取脱敏的两条摘要、用量后中断和正常续轮夹具，保留旧实现的失败复现。回放结构只含必要的消息、签名字段与合成标识。
2. 修复 AGY Messages 的后台摘要识别和本地响应。覆盖主回填前、主回填领取期间、原轮提交后、重试、可选 `Previous:` 行。核对普通用户追加文本、同类非 AGY Messages、无效工具配对和原账号授权，记录主链恰好一次提交。
3. 修复内核提前收尾。复用已复现的两个用量后中断样本，覆盖控制结果晚于 `model_end` 的顺序，分别断言控制 200 且源终态缺失、控制 500 且真实错误类别为响应读取中断。覆盖实际控制 4xx、原请求超时、取消、进程退出、已确证源 429 和已完整交付结果的保留。
4. 修复网关提前返回 HTTP 200。用相同样本分别断言首块有效内容前返回协议 HTTP 错误、首块有效内容后交付 SSE `error`、相同回填重读得到原失败终态。回归用量后正常完成和正常工具首帧。测试 Messages 流式、非流式和原生 Gemini 的相应场景，保留文本、图片、思考签名和真实拒绝。
5. 先用隔离原版 AGY 1.5.9 验证客户端持有真实工具调用期间提前关闭原轮，再导入完成的工具历史。检查关闭回执、进程和许可归还、下一笔唯一提交、真实出站 ID 和相关签名、完整多工具回填及会话缓存前缀。确认老轮次收到关闭失败、迟到或错身份回执时的可诊断恢复。历史选项以这一步和完整回归成功为可用条件。
6. 接通领取优先策略。核对正常领取、旧轮确认关闭且下一轮待提交后的历史接续，以及提交状态不明、已提交、关闭回执迟到或归属错误、真实过期和账号权限撤销。覆盖同一回填并发、响应断开后重读及不同正文冲突。核对每次成功接续只产生一次模型提交，并能查到实际路径和兜底触发原因。
7. 接通三种策略的按环境保存、能力检查、策略冻结和界面操作。验证旧配置缺省、非法值、未就绪执行端、配置写入冲突、两个环境隔离、本地和远端读写、设置刷新和策略切换中已有工具批次完成。验证混有 WebSearch 的批次、并行同名工具、跨令牌和同请求多读者。重读沿原路径和终态。
8. 重放 AstrBot 形态，检查 Flower2API 直连以及经 New API 未发送保活、已发送保活、已发送内容三个状态。分别记录 HTTP 码、SSE 事件和客户端识别结果。只读复核 New API 转发边界并记录实际影响。
9. 在相同的隔离场景对比直接领取与直接历史的原轮关闭、真实回填到首块可用内容和实际出站缓存前缀，记录领取切到历史后的回填耗时。回归已修的 Read 截断缓存前缀及 CC Runtime 正常转发。生产缓存命中率的比较以有可比样本时的实际观察为准。
10. 复现主调用 STOP 后额外调用导致待交付工具批次失败。使用原版 AGY 的实际路由、Scanner 与 Receive 观察确认归属。构造并发原始帧、空会话 ID、错调用 ID 和同根再次启动，核对错误与主调用计数。
11. 复现同一规范化回填的连续重读与 120 秒后失去归属。验证提交后回执在响应帧回收后仍含原尝试、原失败或明确的响应过期。核对并发、账号范围、会话、签名、正文冲突和零额外提交。
12. 回归三种续轮策略与 AstrBot 首帧、真实控制失败和终态合同。在任务研究记录保留原版证据、合成注入覆盖、验证命令和仍待核实的线上触发因素。

## 验证入口

- 网关在 `services/gateway` 运行 `cargo test --locked gemini`、`cargo fmt --check`，按改动范围补齐发送契约、鉴权与配置相关测试。
- Python 在 `services/orchestrator` 运行 `python3 -m unittest test_agy_runtime test_agy_supervisor test_agy_environment`，并补充环境控制读写及远端放置路径的定向验证。
- Web 运行 `npm --prefix apps/web run build`，用环境页实际执行读取、保存、刷新和失败恢复。
- 使用候选镜像运行 `python3 deploy/flower2api/verify_agy_native_loopback.py --image <测试镜像> --parallel-tools --messages-search`，并在同一隔离回环验证新的提前收口路径、失败重读和保活场景。原生回环使用本地 TLS 和合成结果。
- 使用 `agy_runtime.build` 重建观察器和资源清单。独立运行原版回环的 `--tool-receipts`，核对两个活动 Scanner 的帧归属、空会话重放、16 次重读与 125 秒后的结果。另行执行 `--continuation-modes`、`--messages-search` 和 `--tool-deadlines`。
