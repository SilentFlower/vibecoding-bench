# Brief — 修复 v3 账号同步与重授权状态

## Goal

- 让当前 CLI 2.1.293 的固定账号正常同步到 cc2api，并准确确认重授权后的凭据更新结果。

## Scope

- 修复同步与环境列表的设备身份读取。
- 同步 cc2api 对已验证身份来源的校验。
- 明确已绑定与未绑定账号的重授权完成状态，补充联动回归。

## Non-Goals

- 不恢复被封账号、不改变代理或既有设备身份。
- 不自动创建账号绑定，不猜测未验证 CLI 版本的设备字段。
- 本轮完成本地实现与隔离验收；提交、推送和生产部署另按交付授权执行。

## Technical Overview

- 当前版本从固定 HOME 的官方持久 userID 核验设备身份及账号归属；保留原请求观察与冲突校验，采集不新增模型或额度请求。网关创建账号须确认写入完成后再返回成功。已绑定重授权沿用凭据导入、回执与镜像流程；未绑定明确返回仅本地保存。

## Context & Decisions

- 修复前同步依赖抓包器身份文件，普通 CLI 已改为原生 TLS 透传，导致完成任务也无法补齐文件。
- 无外网的实际官方 CLI 已验证 userID 与请求设备 ID 一致；machineID 是独立字段。当前账号尚未绑定 cc2api，重授权不会自动创建远端账号。
- 现有已绑定重授权的 Python 18 项、Rust 4 项回归通过；保留这套事务与恢复机制。

## Risks

- 新身份来源需要两端同批兼容；历史身份冲突继续阻止同步，不能自动覆盖。

## Acceptance

- 当前 CLI 完成登录后即可同步，无需额外跑题或开启完整抓包；缺失、损坏、账号不符及冲突均准确拒绝。
- 已绑定重授权后核对实际 cc2api 数据库、管理 profile 和 HOME，凭据一致且 HOME 仅发布访问令牌；超时与部分失败不假报成功。
- 页面区分“仅本地保存”和“已同步关联账号”，通过 Python／Rust 回归及官方 CLI、联合堆栈隔离验证。

## Next Step

- 实现、回归、隔离验收和规范同步已完成，两仓业务修复已提交并推送；后续按独立授权部署同批镜像并执行真实 OAuth 验收。
