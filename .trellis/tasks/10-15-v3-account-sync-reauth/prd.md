# 修复 v3 账号同步身份采集并验证重授权凭证一致性

## Goal

让当前官方 CLI 2.1.293 的 v3 固定账号能够安全同步到 cc2api，并明确、验证重授权后的两端凭证一致性。

## Background

- 用户点击“同步 cc2api”后收到“设备身份尚未确认：请先在该固定环境完成一次 CLI 任务，再同步账号”，但账号已经执行过普通任务。
- 用户同时要求核对：重授权后 cc2api 是否会更新凭证。
- 普通 v3 CLI 已使用原生 TLS 透传，而当前同步校验依赖仅由完整抓包链路生成的设备身份记录；两项行为不相容。
- 已绑定账号已有凭据导入、回执查询、凭据镜像和异常对账流程；未绑定账号的重授权仍是本地账号流程。需要验证真实边界，不能将本地保存成功等同于远端同步成功。

## Requirements

- R1：当前已验证的官方 CLI 2.1.293 完成登录后，固定账号能够在原生 TLS 模式同步，不要求额外跑题或开启完整抓包；身份必须有可验证的官方 CLI 来源，不能随机生成或把未证实字段当作设备 ID。
- R2：保留已有账号、设备、绑定、租约和身份冲突校验；拒绝将不匹配的登录身份或凭据写入其它账号。
- R3：已绑定账号重授权成功须确认 cc2api 已提交新凭据，并完成本地镜像；网络超时或局部写入失败不能假报成功，重试不重复覆盖已轮换的凭据。
- R4：未绑定账号的重授权状态应准确反映尚未同步到 cc2api；明确区分本地保存、绑定同步和已绑定凭据更新。
- R5：采用脱敏、隔离验证覆盖真实 CLI 身份来源与重授权流程，不使用受限账号进行模型探测；不输出令牌、授权码或完整会话内容。

## Acceptance Criteria

- [x] A1 → R1：仅完成官方 CLI 2.1.293 登录的合成固定账号在原生 TLS 模式可导出正确身份并同步，普通任务成功后同样可同步。
- [x] A2 → R1、R2：使用实际官方 CLI 的隔离请求验证设备身份取值；身份缺失、格式异常、账号不符及历史冲突均拒绝同步。
- [x] A3 → R3：已绑定账号完成重授权后，cc2api 与管理 profile 的凭据一致，固定 HOME 仅发布访问令牌；原账号 ID、设备身份及配置保持。
- [x] A4 → R2、R3：导入响应丢失、提交结果未知、局部镜像失败和错误登录的测试均保持现有保护，并可按回执恢复。
- [x] A5 → R4：页面和返回结果准确区分本地保存与 cc2api 凭据同步，未绑定账号不会显示已同步。

## Non-Goals

- 本轮不恢复被封账号、不更改地区政策相关配置、不把修复解释为封号解决方案。
- 不自动创建账号绑定、替换现有 cc2api 设备身份或修改代理出口；未验证的 CLI 版本不猜测设备字段映射。
- 本轮先完成本地实现与隔离验收；提交、推送和生产镜像切换按独立交付授权执行。
