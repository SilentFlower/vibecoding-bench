# 修复 Pi 异常中断后的自动恢复与旧目标阻塞

## Goal

让项目迭代和养号迭代在程序自行中断后自动核对并接续原工作，临时故障持续存在时冷却重试，只有存在具体且无法自动解决的问题时才要求人工介入。

## Background

- 用户先报告账号 10-23 被提示“原工作需要人工核对，不能自动恢复”，随后明确要求自动运行自行恢复，并授权修复前述方案。
- 本会话只读核实：账号 ID 为 8，项目工作为 `79ce7f8e88e941bea99e418c26dcaca8`，目标为 `python-frontmatter / FM-FX-01-DEV`。错误事件为 `51015`，北京时间 `2026-11-06 02:22:42`；原 Pi 会话最后的 SDK 错误为 `Stream ended without finish_reason`，模型为 `gemini-3-flash-agent`。当前目标无活跃运行时，两个终端动作均为 `sent`，没有 `intent/unknown`。
- `images/pi-agent/host.mjs:151` 的故障分类没有覆盖上述 SDK 断流终态，最终落入 `images/pi-agent/host.mjs:531` 的通用错误；`orchestrator/projects.py:1716` 将工作置为 blocked，`orchestrator/projects.py:1347` 又拒绝未分类故障的人工恢复。
- 已有恢复机制包括 SDK 内有界重试与配置模型降级、控制端 60/120/300 秒快速恢复，以及至少十五分钟的低频检查；无需另建调度系统。现有恢复事实、计划与工作均已持久化。

## Requirements

- **R1：完整响应与故障分类。** 将 SDK 确认的不完整流式响应及同类传输中断归为可恢复故障；成功正文出现相同文字不能触发恢复。认证、权限、请求不合法、明确禁止重试等有确定依据的错误保留具体处理原因。
- **R2：自动恢复。** 临时模型故障及可确认安全的未分类模型响应失败进入有界重试和冷却调度。自动计划开启时，暂时失败不能永久清空后续执行时间；计划关闭、用户暂停或停止时保持其显式选择。恢复计数与等待时间跨重启保留，复用原目标、Pi/Claude 会话、工作区和累计耗时。
- **R3：先对账，再决定阻塞。** 恢复前核对控制所有者、运行现场、终端投递结果、账号身份、授权与冻结合同、额度和时段；可自动确认的现场自行恢复，确实无法核实的投递或身份问题才要求人工。不能用通用异常直接推断可以重复执行终端操作。
- **R4：恢复入口可用。** 显式“启动／恢复”重新检查当前事实，可安全续接时允许受控恢复，避免仅因历史通用错误永久拒绝。已经确认的工具结果和终端输入不得重放。
- **R5：可解释的状态。** 页面显示具体故障类别、当前恢复阶段、尝试次数和下次恢复时间；需要人工时说明具体待办，不再以笼统“运行异常，等待人工核对”替代原因。
- **R6：旧状态兼容。** 为包括账号 10-23 在内的历史通用错误提供绑定原错误事件的受控诊断与恢复路径，先核实原会话证据与当前门禁，再接续原目标；不得批量重置 blocked。代码验证与实际线上恢复结果分别记录。

## Acceptance Criteria

- [ ] **AC1 → R1/R2：** 使用真实 Pi SDK 和本地 SSE 服务复现缺少 `finish_reason`，验证恢复成功及连续失败后进入冷却；错误响应中的半截工具调用不执行。
- [ ] **AC2 → R2/R3：** 两个迭代空间均在同一 work/session 下自动续接；持续故障转低频检查，服务重启不重置计数或提前绕过等待。
- [ ] **AC3 → R3/R4：** 未分类模型故障仅在可确认安全的边界有限恢复；未确认终端输入、未收口现场、身份变化、授权撤销、真实账号门禁仍拒绝执行并说明具体原因。
- [ ] **AC4 → R2/R4：** 人工暂停、停止目标、关闭计划及更新控制代次优先；取消竞争和迟到回包不能重新启动工作；已确认工具／输入不重复投递。
- [ ] **AC5 → R5：** 等待页面能看到故障原因、恢复次数与下次执行时间；具体人工问题显示可执行说明；切换账号或空间时不混入旧状态。
- [ ] **AC6 → R6：** 合成旧通用断流错误可经绑定原事件的诊断恢复，重复诊断幂等；原错误不匹配、会话证据不符或门禁失败保持现场。10-23 的原 work、会话与完成进度保持可追溯。

## Non-Goals

- 不新增通用任务队列、任意错误无限重试或新的模型供应商配置系统。
- 不改项目目标、验收规则和已通过事实；不清空历史、重建工作或把恢复故障视为目标通过。
- 不将代码验证当作正式部署或真实上游成功证明；生产发布继续遵守项目既有 SOP。
