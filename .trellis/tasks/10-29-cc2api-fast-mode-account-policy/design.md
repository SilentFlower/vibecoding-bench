# Fast 账号策略设计

## 目标与边界

- 复用 `Account.allow_fast_mode`，把禁止行为从旧 beta 过滤扩展为 Fast 正文与 beta 的一致约束。
- 仅处理精确 Messages 与 count_tokens 转发入口的根级 `speed: "fast"`，不扩展为其它字段清洗、模型能力判定或 beta 自动补齐。

## 处理流程

1. 继续按现有流程解码、识别客户端、执行本地拦截和选择账号；不提前修改调度、Session 或缓存使用的原始逻辑请求。
2. 普通 Messages 的账号循环仍从公共 `rewrite_input` 进入普通、身份专用或归因补齐三条改写分支。
3. 在分支汇合后、生成最终 header 前，对本次账号的逻辑 JSON 执行共享 Fast 策略；可复用现有 JSON 解析结果，避免无条件增加解析或 clone。
4. 只有账号禁止且根级字符串精确等于 `fast` 才稳定删除该字段；未实际删减时直接沿用已有正文 bytes。已有 serde_json preserve_order 要求其它字段相对顺序不变。
5. 实际删除后序列化，并按请求画像刷新已有合法唯一根级 billing CCH。复用现有底层定位与刷新算法，不能因 billing 透传模式漏刷新，也不能创建新的 billing/CCH 块。
6. 最终逻辑正文用于生成 header；已有 `filter_account_beta_tokens` 继续过滤完整 Fast token，不改其它 beta、1M、title 或 safeguard 合并边界。
7. 认证、签名修复与实际网络发送继续沿用现有处理。编码发生在最终正文和 CCH 之后，每次发送从当前逻辑正文重编码，长度由 transport 依据最终 bytes 生成。

## count_tokens 与换号

- count_tokens 在选号前已完成通用字段清理和模型规范化，保留这份公共正文。
- 进入账号循环后，为当前账号应用同一 Fast 策略；仅在需要删除时产生新的正文。header 使用本账号最终正文的 JSON 视图。
- 401 认证恢复复用本账号派生正文；换到另一个账号时重新从公共正文派生。
- 普通 Messages 的每次换号同样重新执行本次账号策略。禁止账号不能污染后续允许账号的客户端 Fast 意图，允许账号也不能让后续禁止账号继续发送 Fast。
- count_tokens 保留专用 `token-counting-2024-11-01`、既有方法校验和独立发送链路。

## 说明与规范

- `src/model/account.rs`：更新开关注释，保留 serde 默认 false 和现有字段结构。
- `web/src/components/Accounts.vue`：沿用已有“禁止／允许透传”控件，说明改为“禁止时将客户端 Fast 请求回落普通模式；允许时保留客户端申请，可能产生额外费用或限流”。不新增控件或前端数据字段。
- 协议 Fast 场景：替换原“不得修改正文”的约束，明确精确根字段删除、允许时不主动开启、最终 CCH 和两种入口的一致性。
- 后台状态分类规范：将 Fast 账号策略列为所有真实转发的有限例外，保留 detector、mock、日志脱敏及其它窄改写合同。
- 若实现需要调整已有 CCH 刷新入口的内部命名，同时同步所有调用、测试和规范引用，不复制 CCH 算法。

## 兼容与回滚

- 不新增数据库字段、配置、依赖或迁移；账号开关仍以 cc2api 保存值为权威，bench 同步规则不变。
- `standard`、未知值、大小写或空白异常值、嵌套 speed 维持原有处理，非目标路径不新增过滤。
- 无实际 Fast 删减时不因本策略重排或重新序列化正文；原非 JSON 错误或透传行为不扩大。
- 回滚为本任务的精确代码及规范差异；不能把全局放行 Fast 当作回滚手段。若功能回退，需明确恢复的是原先仅过滤旧 beta 的行为。

## 验证矩阵

| 场景 | 主要断言 |
| --- | --- |
| API／CC × 流式／非流式 × 允许／禁止 × 有／无 Fast beta | 禁止时字段与完整 token 一起消失；允许时正文申请保留；不主动开启 |
| 缺少 speed／standard／异常值／嵌套 speed／相似 token | 无误删，无额外正文序列化，完整 token 精确匹配 |
| 普通／身份专用／状态分类归因分支 | 本次账号策略一致；其它窄改写约束、脱敏与本地 mock 不变 |
| count_tokens 首次／401 恢复／换号 | 本次正文与账号一致，专用 beta、路由和原始公共正文保留 |
| 允许→禁止／禁止→允许换号 | 每次重新判断，禁止不漏删，允许不继承前次删除 |
| 280／293 与合法、缺失、歧义的 billing CCH | 仅刷新已有合法唯一目标，最终 hash 正确，不新建归因块 |
| 明文／gzip、x-gzip、deflate、br、zstd 及已有组合 | 解码后的 JSON 一致，实际 CE／CL 正确，重试不使用旧压缩体 |

验证只使用现有本地合成 Gateway、TCP 接收器及脱敏样本，不声明官方账号实际 Fast 生效或计费结果。
