# Brief — CRIU 恢复实例共享封存执行映像

## Goal

让同账号的独立 CRIU 恢复进程共享封存执行映像，降低重复内存占用并保持请求隔离。

## Scope

- 实现共享映像的持有、准入、恢复移交和生命周期清理。
- 更新 CRIU 补丁、控制器、加载器、监督进程及 Rust 实际映像校验。
- 同步构建配方、镜像输入和来源清单，补充隔离验收与故障回归。

## Non-Goals

- 资源限额调整、跨账号共享、共享可写业务内存、会话合并。
- 前端、公开 API、数据库变更及软件发版、生产部署、真实付费探测。

## Technical Overview

控制器登记模板时核验并持有实际执行体，固定可信所有者与执行权限。各实例独立打开同一 inode，经固定加载器传入 CRIU，统一 FD、映射和执行体三条恢复路径。Rust 复核实际 inode 后完成原有握手；失败清理并回退普通共享映像启动。

## Context & Decisions

- 普通 exec 已能共享。四进程合成实验的映像分配从 430.5 降至 107.6 MiB。
- 保留现有预算、账号开关、物理上限、随机状态重置与唯一业务投递。
- 以运行时源码为权威，通过导出流程同步镜像输入。

## Risks

- 同名异 inode、FD 访问模式和偏移、权限变化及取消清理需要专项验证。
- 本地快照受 seccomp 权限阻塞。完整 CRIU 与真实 CC 验收仍待支持恢复的隔离环境完成。

## Acceptance

- 多恢复实例实际 exe 与映射引用同一受信 inode，摘要、大小和四项 seals 有效。
- 真实 CC 四路及连续请求覆盖流式、工具、取消与单实例退出，保持状态隔离。
- 错误身份、权限、FD、模板失效及恢复中取消正确拒绝和收口，回退保持唯一投递。
- 固定来源编译、导出一致性、Python 回归与 Rust 全量测试通过，并记录内存峰值及延迟。
- 证据完整后共享路径随现有 CRIU 机制默认使用；环境阻塞项保持待完成。

## Next Step

激活任务并进入实现，先核对真实 CC 的执行体 FD 与映射，再完善正式共享恢复补丁。
