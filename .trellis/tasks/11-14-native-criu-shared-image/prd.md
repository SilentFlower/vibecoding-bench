# CRIU 恢复实例共享封存执行映像

## Goal

让同账号、同代次的独立 CRIU 恢复进程共享一份封存执行映像，减少重复内存占用，保持请求正确和进程隔离。

## Background

普通 exec 已共享映像。改动前 CRIU 为各副本重建 memfd，每份112843960字节。四进程合成 exec 对照的映像分配从430.469降到107.617 MiB。私有状态及退出探针通过。正式CRIU构建与真实CC离线KVM验收均已通过。本地WSL快照的seccomp限制由一次性隔离客体规避，详见research/acceptance-summary.json。用户已选定带保护约束的路线并要求实施，依据见 research/evidence.md。

## Requirements

- R1：共享路径随现有 CRIU 机制默认选择。各实例的进程、私有状态、目录、管道、会话和请求归属独立。
- R2：共享恢复仅从同账号、完整池身份匹配且代次有效的模板准入。核验摘要、大小、seals、inode、权限和快照归属，拒绝同名不同身份的对象。
- R3：种子退出、模板撤销、切代及取消时，合法实例保持正确生命周期。引用和物理许可在实际清理后释放。
- R4：恢复准入失败在业务投递前清理并回退普通共享映像 exec；保持唯一提交、原截止及并发上限。
- R5：保留随机状态重置、UUID缓存处理、nonce握手和原生发送栈，保持四路并发和后续串行复用隔离。
- R6：第一阶段沿用现有预算、账号开关和权限要求。报告执行体分配、总内存峰值和恢复延迟。
- R7：权威源码、配方、镜像输入和来源清单同步。旧工具或身份不符时安全回退。

## Acceptance Criteria

- [x] AC1（R1/R2）：支持CRIU的隔离环境中，多恢复实例实际exe及映射引用同一受信inode，大小、摘要和四项seals有效。
- [x] AC2（R1/R5）：真实CC四路及连续请求覆盖流式、工具、取消和单实例退出，私有状态、请求标识及随机状态隔离正确。
- [x] AC3（R2）：错误摘要、大小、seals、权限、同名异inode和不兼容FD语义被拒绝；私有写页正确恢复。
- [x] AC4（R3）：种子退出、模板撤销、切代、恢复中取消及连接断开测试通过，句柄和容量最终释放。
- [x] AC5（R4）：共享失败按原截止回退普通exec，保持唯一投递及物理容量。
- [x] AC6（R6）：同负载采集映像分配、anon/file/shmem、current/peak及恢复延迟，预算公式保持现状。
- [x] AC7（R7）：固定来源编译、导出一致性、相关Python回归及Rust全量测试通过。
- [x] AC8（R1/R6/R7）：证据完整后共享路径随现有CRIU机制默认选择，显式关闭按原语义生效；环境阻塞项保持待完成。

## Out of Scope

- 降低资源限额、跨账号或跨cgroup共享、共享可写业务内存、合并会话及更改单进程串行模型。
- 公开API、前端、数据库改动。
- 软件发版、生产部署和真实账号的付费模型探测。
