# 系统更新分步重启与账号后台滚动实施

## 顺序

1. 锁定基线。用当前 `verify_system_update.py --fast-transition` 的隔离环境建立发布准备、全局门禁、控制就绪和账号维护的时间线。核对固定宿主包的能力输出及持久目录，单独记录线上 v1.25.0 的 73 秒停单参照。
2. 实现准备回执和消费分支。复用原 `/prepare` 并补服务端能力与状态投影，校验跨刷新、重复提交、过期目录、候选丢失和重启恢复。保持旧 `install` 和 `rollback` 读写语义。
3. 实现过渡期账号授权与独立重建。先补编排服务实际镜像、部署、账号与代次核验和网关授权绑定，再接账号级准入。以旧账号可接单及错误镜像、错账号、错代次均拒绝的测试作为切换顺序改动的前置。
4. 将本机账号更新移出中央门禁。拆分控制服务验收与账号结果对账，持久记录过渡授权和账号事项后开放中央准入。验证 AGY 工具轮、普通 SSE、预热任务、CLI、凭据收尾和离线 SSH。补单账号失败、回退、进程中断和下一次安装交接。
5. 接入 Vue 的下载、待重启、立即重启和后台账号进度。复用发布说明、快照详情和历史回退操作。按底座能力保留兼容页行为。处理刷新数据到达顺序和浏览器重新连接。
6. 补固定宿主源码包、现有实例接入与回退说明。证明在开发仓路径和固定包路径都能独立运行，旧宿主可先沿原流程升级。完成隔离环境的端到端和耗时对照后进入项目检查流程。

## 验证

- 宿主和状态机。`PYTHONPATH=services/orchestrator:deploy/flower2api .venv/bin/python -m unittest test_system_updater test_system_host`。覆盖准备回执、全局门禁释放顺序、单账号隔离、超时、重试、旧协议及数据回退。
- 编排与网关。围绕 `system_updates`、`account_update_identity`、账号维护与 `runtime_transport` 补当前入口回归。运行编排定向用例和网关目录下的 `cargo test --locked`。覆盖成功及非授权镜像、跨账号、环境代次、已停用账号、并发尝试和回放保护。
- 浏览器。`npm --prefix apps/web run build`。沿当前管理页验收实际 Vue 组件与隔离管理 API。覆盖下载失败、刷新后待重启、旧宿主显示、重启断线重连、恢复接单和账号待重试，检查窄屏。
- 隔离全链路。扩展 `deploy/flower2api/verify_system_update.py --fast-transition`，用至少三个本机环境、挂起的 SSE 和 AGY 工具轮及离线节点跑完整安装。人为放慢一个账号并注入另一个账号的重建失败，核对新控制恢复后其它模型可请求。记录下载到就绪、停止接单到恢复、账号后台收口三段耗时。结合双库快照验证恢复接单后的新写入。
- 固定包。验证 `SOURCE_FILES` 交付包在仓库外独立导入，使用隔离宿主从旧底座、受信源码刷新到新能力，重启并继续已准备或后台进行的操作。发行候选沿现有签名与迁移兼容演练。

## 恢复边界

- 中央门禁释放前，保护原两库快照、原控制程序和原账号身份。恢复接单后以当前持久状态处理账号失败，显式回退保护后续业务写入。
- 账号创建、重建、恢复及失败重试均用原归属和代次复核。账号维护范围与用户手动开关独立，账号失败可局部解除或继续对账。
- 实际生产安装、宿主更新器刷新及发版各沿现有发布或运维流程执行。
