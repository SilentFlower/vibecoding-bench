# 系统更新分步重启与账号后台滚动设计

## 现状与边界

codex-proxy-rs 下载完成后进入「待重启」，确认重启时关闭监听，存量长请求随进程退出中断。后台落盘沿自己的短窗口收口。参见 `/root/project/codex-proxy-rs/deploy/README.md:763`、`:977` 及 `backend/crates/gateway-host/src/serve.rs:122`。

Flower2API 保持签名镜像与 Compose 部署。宿主更新器负责候选准备和控制服务切换，网关与编排服务负责准入及实际账号归属，Vue 页呈现已登记状态。账号容器是独立的三角色环境，原有 SSH 节点续跑路径可复用。

## 下载和重启

1. 页面将 `POST /runtime/api/system-updates/prepare` 接入「下载更新」。复用受信目录、`validate_operation`、已有服务身份和宿主 `prepare` 入口。保留兼容入口所需的现有请求形状。
2. 宿主完成原签名附件、镜像和项目库准备后，持久投影已准备目标。准备回执关联目标发行、清单摘要、组件选择、当前安装修订和原操作。页面重开依据服务端回执显示「待重启」。目录刷新与过去某次 `prepared` 事件各有自身语义。
3. 「立即重启」消费同一份准备回执。沿现有 `install` 状态机新增基于已准备目标的分支，消费时复核安装修订、候选身份和本地缓存。目标变化或缓存失效回到准备阶段。旧客户端沿原兼容接口。
4. 开始切换后复用原快切取消 HTTP/SSE、工具轮和预热信号。原调用记录继续使用 `system_update`。全局切换保留会影响两库快照或控制平面安全的写入收尾，窗口沿现有快速切换预算，超时恢复原服务接单。账号占用的处理范围缩到该账号。宿主快切期间 SSH 节点状态独立推进。
5. 先校验新控制服务、数据合同和账号准入依据，再持久提交新版本、记录本机账号后台事项并释放中央门禁。`admission_reopened_at` 表示真实开放时刻。后台作业和旧制品清理均单独投影，页面以控制切换结果标识当前版本。

## 本机账号版本过渡

- 沿 `account_update_identity.image_origin` 的私有来源和实际三角色核验。为需要过渡的账号保存本次已验证的例外来源，至少关联部署、账号、环境 ID、当前代次、实际镜像 ID、账号协议和有效目标切换。来源取自验签的初始/目标选择及现场已核对的运行记录。
- 新控制服务经原受限内部传输接口返回已核验的过渡绑定。网关按当前账号和请求的环境代次核对该次绑定，保留原受信域名、环境 ID、凭据身份及绑定保密边界。没有有效过渡证据时继续核对全站配置的账号批次。任意旧批次、不同账号的批次或无效代次均没有放行依据。创建新环境仍只选当前目标镜像。
- 更新单个账号时使用已有账号准入/维护协调能力和 `environment_lock`，把维护所有权与用户的接单、启停设置分开。临时暂停该账号，记录原来源和代次、核对本账号活动与有权回收的角色，再使用原运行时入口重建并验收。成功后先保存新代次与来源，再释放该维护所有者。请求期间的权限判定与重建使用同一账号准入边界。
- 后台事项保存为本次已生效版本的持久子状态，至少支持待处理、处理中、已完成、待重试、需对账。单项超时或失败继续调度其他账号。失败且原环境已证明兼容并完整时可恢复接单。部分重建或归属未明时仅保留该账号隔离，重试先核对实际角色及数据，沿原任务继续。
- 兼容证明失效、当前生效版本变化或账号迁移时，旧后台事项按冻结代次停止写入。下一次中央操作开始时对后台事项和实际来源做交接，仅接纳已核验的运行账号。使用同一环境互斥范围，已开始的不可重复副作用先核对结果。只读观察与待重试项目使用独立账号状态。
- SSH 节点沿现有独立任务、能力核验和来源版本逻辑继续执行。已停止环境在需要启动时使用已生效目标。运行容器以及准备、恢复和后台事项引用的镜像进入现有清理保护集合。

## 兼容、失败与交付

- 新切换行为由宿主与新旧控制/账号组件协商。继续核对签名、可信仓库、组件内容与兼容数据计划。第一阶段接入保留原能力判定及升级入口，旧底座状态接口缺少能力声明时沿原流程展示。
- 中央验收失败且门禁还未释放，继续使用原快照和原控制服务恢复。恢复接单后，从持久子状态继续账号隔离与更新。自动回收仅处理已证实可回收的对象。显式回退沿同一身份与数据合同检查，保护上一次恢复接单后产生的写入。
- 宿主脚本和 Compose 受信模板来自固定宿主包，需要独立刷新。交付需覆盖固定源码依赖、原 v2 实例的同协议源码刷新、服务重启恢复和模板摘要核对。复用已存在的宿主维护说明与服务/存储锁进行可复核交接。首个更新可沿原流程，接入完成后下一次升级可使用新流程。
- 更新页把「下载与校验」「待重启」「正在重启」「已恢复接单」对应到实际服务端状态。重启按钮附近明确仍在运行的请求会断开。账号区复用现有来源、状态和错误样式，保留回退与失败重试入口。
