# 系统更新分步重启与账号后台滚动

## Goal

将 Flower2API 的在线安装改成 codex-proxy-rs 的「下载更新 → 待重启 → 立即重启」，让平台恢复接单的时间取决于控制服务切换，账号环境和 SSH 节点各自更新。

## Background

- 线上 v1.25.0 安装共 155 秒，停接新请求 73 秒。上一版分别为 283 秒和 189 秒。155 秒包含 65 秒准备和恢复接单后的 17 秒清理。
- 宿主已有 `prepare` 操作。管理页的主要入口直接走 `install`，控制服务健康后仍在全局门禁内执行 `update_environments`。参见 `apps/web/src/components/SystemUpdates.vue:284`、`deploy/flower2api/system_updater.py:397` 和 `:462`。
- 本机环境重建接口要求全局门禁关闭和全局排空，网关用全站配置的账号批次校验传输绑定。两处都会阻止兼容旧账号在控制切换后继续接单。参见 `services/orchestrator/system_updates.py:554`、`services/gateway/src/service/runtime_transport.rs:1032` 和 `:1080`。

## Requirements

- R1 下载和重启分成两个明确动作。下载、验签、镜像准备完成后才显示「待重启」。下载、失败和重试期间，旧版继续服务。页面重开后显示服务端已记录的实际阶段。
- R2 管理员点「立即重启」后，快切路径结束剩余推理连接并保留既有记录收尾语义。控制服务和数据就绪后恢复新请求，HTTP、SSE、工具等待及节点连接的自然结束时间与全局停单解耦。
- R3 兼容的旧账号环境可在切换后立即接单。需要重建的账号逐个暂停、更新、恢复。重建失败或占用无法收尾时，记录该账号的错误或等待状态，继续处理其他账号。已停止、停用或关闭接单的账号遵循原来的设置。SSH 节点继续独立同步。
- R4 页面在中央切换完成后明确显示当前生效版本和恢复接单状态，另显示账号更新进度与失败重试入口。全局回退沿既有版本和数据恢复入口，切换后写入继续受到原有保护。
- R5 现有安装实例有受控接入路径。固定宿主更新器和应用能确认双方支持新流程后，管理页才展示对应动作。较旧的底座或组件组合继续提供现有兼容安装方式。

## Scope

- Vue 更新页、受信宿主准备与控制切换、本机账号后台维护、网关传输来源校验、异常和恢复路径，以及固定宿主更新器交付和回归。

## Non-Goals

- 镜像打包和 GitHub 发布提速，运行环境节点迁移，跨不兼容数据库或账号协议的热切换，生产环境操作。

## Acceptance Criteria

- [ ] A1 在真实页面执行「下载更新」，下载和重试期间健康账号持续处理请求。下载完成后在刷新页面与重启更新器后仍能识别待重启的目标。实际删除缓存、目标清单变化和过期页面提交都有明确反馈。覆盖 R1。
- [ ] A2 在独立部署环境制造挂起的推理以及离线 SSH，点击「立即重启」后，兼容账号在控制服务验收通过时即可接到请求。记录全局停单和恢复时间，验证人为延长某一个账号重建时间不会延长全局停单。与同环境的现有流程对照。覆盖 R2、R3。
- [ ] A3 以三个本机账号覆盖旧兼容环境接单、重建成功和暂时失败。确认其他账号持续接单，未通过来源或代次验证的账号保持隔离，失败项可重试，已停止或人工停用的账号保持用户设定。覆盖 R3。
- [ ] A4 分别中断在宿主切换前、中央验收前、恢复接单后以及单账号重建中。验证重启恢复幂等，切换前失败可原位恢复，接单后产生的数据仍可读取，界面能区分已生效、后台更新和待重试。覆盖 R4。
- [ ] A5 在固定宿主源码包环境验证新版本刷新和进程重启后的状态读取，在旧底座验证兼容路径。保留签名、账号身份、数据库迁移与回退链路测试。覆盖 R5。
