# Brief — 系统更新分步重启与账号后台滚动

## Goal

- 把在线安装改成「下载更新 → 待重启 → 立即重启」，缩短平台暂停接单的时间。

## Scope

- 更新页、候选下载与校验、控制服务切换、本机账号后台更新、失败恢复及已有底座接入。

## Non-Goals

- GitHub 发布提速、账号节点迁移、跨不兼容数据库或账号协议的热切换、生产环境操作。

## Technical Overview

- 复用现有下载准备接口。候选准备完成后保存可供重启消费的回执。切换时验证新控制服务和数据，随后恢复接单，受影响的账号按各自的持久状态继续更新。

## Context & Decisions

- v1.25.0 实测停接新请求 73 秒。现有流程在恢复接单前逐个重建本机账号。
- **【关键决定】点击「立即重启」会结束还在运行的推理连接。请求记录沿原快速切换路径收尾。**
- **【关键决定】来源和代次核验通过的旧账号先接单。需要重建的账号逐个暂停、更新、恢复，失败由对应账号单独重试。SSH 节点继续独立更新。**

## Risks

- **【交付风险】宿主更新器和应用镜像各自安装。已有实例需接入新版宿主能力后才会显示新流程，较旧的底座使用原安装入口。**

## Acceptance

- 页面刷新后准确恢复「待重启」状态。用真实网关验证候选下载期间持续接单。
- 制造挂起的推理、较慢的账号重建和离线节点。控制服务就绪后，健康账号恢复接单，并记录实际停单时长。
- 验证单账号失败重试、切换前回退、切换后数据保留和宿主重启恢复。

## Next Step

- 在隔离部署上记录现有停单时间线。
