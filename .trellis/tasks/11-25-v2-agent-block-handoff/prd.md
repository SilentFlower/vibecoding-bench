# V2 流式后台派工

## 目标

一个合法的后台子任务可在主会话继续工作的同时完成启动。主代理发送给该子任务的追加消息能正常送达。

## 已证实的故障

- v1.38.0 的子代理请求在父流结束前约 14 秒到达，连续四次被拒。父续轮随后携带了匹配原工具和子 ID 的成功启动回执。
- 任务提示为 1742 字符，子首轮恰好多一个 LF。后续重试又有 194 字符的独立文本块，其中包含父 SendMessage 的完整 88 字符消息，其 to 与该子 ID 相符。记录多个块的长度和相等关系即可，实际客户文本不进入测试仓库。
- 已使用 v1.38.0 的 WireStep 和 SessionDriver 在隔离内存中复现。一个完整 Agent 工具块已关闭、父回复仍开启时，准备子请求会报归属错误。独立附加文本也会被首轮提示解析拒绝。

## 验收

- [ ] 完整派工先于父轮终态交给客户端。归属已确定时可以在父流结束前启动；需要启动回执的原请求最终成功，能够覆盖此次超过 14 秒的时序差。
- [ ] 父子并发、兄弟同提示、单账号容量吃紧和父工具回执归还均有确定结果；断连、撤销、父流出错及重复提交可收口。
- [ ] 有真实启动回执的末尾 LF 及定向 SendMessage 路径保留完整业务内容，子任务只执行一次。跨账号、主体、会话、环境代次、收件人错配等情况继续拒绝。
