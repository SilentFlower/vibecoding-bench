# 流式登记与回执

- `WireStep.observe` 已按索引验证 tool_use 名称、ID 和完整参数。`_Actor` 在向客户端公开已完整的工具块前登记属于该父轮的派工，并在 `_finish_step` 与同一份记录收口。交错分片、尚未闭合的 JSON 和重复 ID 按原流校验。终态不得覆盖早到认领。等待者与父线程遵守原 Condition 锁顺序。
- 按原绑定、主体、客户端会话、父轮与工具 ID 隔离。早到的子尝试复核同一派工，既有可证明唯一的路径可接入。父流期间仍可能出现同提示兄弟，瞬时唯一或自报子 ID 单独不足以证明归属。需要回执的路径使用原调用可取消的剩余期限，并给父续轮留出进入发送器和队列的名额。区分已知派工等回执、真实容量依赖及无任何受信派工；避免把所有拒绝改成长时间排队。
- 原提示核对仅使用首轮相应的完整文本块和已验证的父工具，严格沿用单个 LF 的受限兼容。追加消息保留在原始 Messages 中。对本次 CC 的 SendMessage 结构核实固定 CLI 封装、同一父会话的定向投递及子 ID；按需在账号内绑定工具 ID、收件人和消息摘要，覆盖消息先于其回执到达。只凭正文中碰巧含有旧提示或消息子串不得放行。旧会话和前台 Agent 沿相应的原有证明处理。
- 检查 prepare、send、模型提交前的复核及 retire 各边界。可取消的准备与已使用的派工分开处理。已提交的模型请求保持单次语义，避免取消后重新派发。未提交等待能被父流失败、明确撤销、断连或原预留到期唤醒。

固定版 2.1.293 的外层原生终端验收还观察到，工具与文本交错的并发响应在父续轮按文本在前、工具在后的布局交还。比较仅对已识别的该版并发 Agent/Task 和纯文本/工具组合采用这一稳定分组，同类顺序、工具 ID、参数及正文摘要逐块核对，含签名或思考的序列沿原合同。发给模型的历史保持调用方字节。
