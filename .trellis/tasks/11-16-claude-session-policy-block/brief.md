# Brief — Claude 会话策略封禁与管理记录

## Goal

- Claude 会话触发明确上游策略拒答后，在可配置时长内本地拦截后续请求，并提供封禁管理与历史记录。

## Scope

- 网关会话封禁、持久记录、管理 API、设置项及“会话封禁”管理页。页面位于左侧“网关 → 请求记录”下方；配置位于“系统设置 → 会话与调度 → 会话策略封禁”，列表顶部提供“封禁设置”链接。
- 覆盖原生与 Rust 转发后端，普通 HTTP 与 SSE 策略拒答，以及已有封禁的消息和 token 计数请求。

## Non-Goals

- 上游解封、内容改写、自动换会话重试、设备或账号级连带封禁、线上部署。
- 主动取消已提交请求，以及追溯撤销历史后台遥测。

## Technical Overview

- 原始会话 ID 与调用方令牌共同生成匿名键。入口在选账号和上游访问前查询封禁，排队后及真正提交前复查。
- 明确拒答建立一轮持久封禁；后续命中本地返回 HTTP 400 和 `session_policy_blocked`，附带到期时间。到期或管理员解除后恢复正常处理。
- 增加兼容数据库迁移，复用现有有界响应解码、管理鉴权、分页和界面控件。

## Context & Decisions

- 默认开启，封禁时长默认 24 小时；设置按分钟输入，默认 1440。修改影响新封禁，重复拦截保持原到期时间。
- 列表展示会话匿名标识、访问令牌、触发账号与模型、原因、起止时间、状态和拦截次数；支持筛选、搜索、分页、请求诊断入口及提前解除。已到期与已解除记录保留。
- 依据客户端真实会话隔离，共用上游 session 的其他会话独立判断；缺少可靠会话 ID 时沿用现有流程。
- 关闭功能暂停自动封禁和拦截，历史保留。重新开启后尚未到期记录继续有效。
- 仅保存安全摘要。结构化错误和拒答事件用于判定，普通回答引用相关词汇保持正常处理。

## Risks

- 首次发现拒答需要上游响应。标记前已提交的并发调用可能继续完成。
- 封禁状态查询失败时返回本地 503，暂停该请求的上游提交。

## Acceptance

- 首次策略拒答后，同一会话后续请求的上游调用次数为零；其他令牌、其他真实会话独立处理。
- 默认 24 小时、修改时长、自然到期、提前解除、重复拦截及再次触发的行为符合上述规则，重启保留记录。
- 普通错误、SSE、两类转发后端、计数请求和排队复查均有测试；认证、限流、正常响应及会话映射保持原合同。
- 管理页在桌面和 390px 可查看、筛选、翻页及解除，明确显示空态和读取失败。
- Rust 测试、前端构建、迁移定义及兼容性验证通过。
