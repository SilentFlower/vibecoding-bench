# Brief — v3 内核与 CPU 随机画像

## Goal

- 为每个账号提供首次随机、后续固定的内核信息与 CPU 型号文本，覆盖常规软件读取。

## Scope

- 实现画像保存、老账号补齐、CLI 常规读取覆盖，以及生命周期和兼容性验证。

## Non-Goals

- 不实现 CPU 指令级仿真，不更换宿主或容器运行时；不调整实际 CPU/内存能力、账号身份和任务目录。本轮不自动部署或请求真实模型。

## Technical Overview

- CLI 挂载只读画像文件和镜像内编译的 libc 覆盖库，处理 uname、常见内核文件和 CPU 型号文本；Node 身份导入继续读取实际容器接口。

## Context & Decisions

- 已确认按账号固定，跨新任务、续聊、重启及重建复用；CPU 只替换兼容型号文本，数量、拓扑和指令集保留真实值。
- 老账号保留既有设备、凭据、MAC 等身份；活动运行中不切换。新 run 使用新项目目录，同 run 恢复/续聊复用，结束后保留文件。

## Risks

- 直接系统调用、静态程序、CPUID 和未覆盖接口仍可能暴露真值；覆盖机制本身也可观察，不能保证免封。
- 覆盖库可能影响 CLI/工具兼容性；必须通过断网原生 CLI 与实际 Docker 回归后才能交付。

## Acceptance

- uname、Node、官方 CLI 的已验证接口及支持的文件读取符合画像，明确列出未覆盖路径。
- 同账号画像稳定；老账号只补齐一次，损坏时明确报错且不重新随机。
- 登录入口、任务、续聊、取消和本地转发回归通过；真实指标、账号数据、项目文件及现有权限边界保持正确。
