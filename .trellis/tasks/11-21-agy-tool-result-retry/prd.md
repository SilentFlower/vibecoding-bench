# 修复 AGY 工具回填重试返回 400

## 目标

AGY 用户在重试已受理的工具回填时能接回原 Gemini 响应，模型生成与原生工具回填各执行一次。

## 证据

- US v1.27.0 的 `gemini-4-neon` 请求 `204c6417` 接受 `d3f14c6c` 的四条工具结果，随后输出下一轮两条调用。其后四笔 `contents[8]` 的 400 都在本地拒绝，完整入站正文摘要与 `204c6417` 一致。`c23d85d0` 后的 `contents[6]` 也重现相同情况。
- 网关在接续模型请求发出后移除上轮记录。相同正文再到达时，工具结果匹配找不到已消费的轮次。断网回环 `--parallel-tools` 通过了现行的重复请求返回 400 断言，六笔模型提交验证原有并行与后续工具回填仍在工作。 [归属检查](../../../services/gateway/src/service/gemini.rs#L684) [上轮清理](../../../services/gateway/src/service/gemini.rs#L1020)
- 线上入站留存遮蔽令牌原值。重复请求的正文及会话一致，令牌 ID 待用同一授权渠道复验。

## 要求

- 当前令牌仍有权访问原账号时，相同令牌、公开模型与完整正文的重复回填接回同一个生成结果。第一笔仍在执行时允许接入原流，已经交付时允许在有效窗口内重读。流式和普通 JSON 保留原 Parts、工具 ID、签名、终态及用量。
- 首次回填沿既有唯一归属检查。缺项、修改结果、跨令牌、超出账号权限和归属不唯一的请求继续拒绝。结果已生效或提交状态未知时维持一次提交边界。
- 重读沿用已受理的接续轮生成截止，不按重试次数顺延。回放内容只保留在网关进程内，容量与截止可回收。网关重启后由新一轮实际请求重新建立归属。
- 保留首笔的增量响应、原工具等待与凭据对账。重复请求记录自身 HTTP 结果和原请求关联，实际尝试数与用量只落在真实发送上。

## 验收

- [ ] 用合成的 `contents[8]`（四个同名调用及四项无 ID 回填）覆盖并发到达、工具 SSE 已交付后重试、回填后的下一轮继续执行三步。核对原生回填与新模型提交各一次，后续工具签名、顺序、ID 和结果内容一致。
- [ ] 普通 JSON 与 SSE 的成功和异常终态可重复读取。核对首帧实时交付、客户端断开、原截止、响应保留容量回收与重试诊断。失败或未知状态保持真实终态且零额外发送。
- [ ] 变更正文、归属不唯一、错误令牌、撤销账号可见范围、已过期各有反例，诊断零新增上游尝试。并行工具 alias、显式 ID、签名、PNG/GIF、原等待与凭据换代回归通过。

## 范围之外

- 跨网关重启或跨实例恢复、改变公网客户端或中转的重试逻辑、工具等待容量与生产版本安装。线上数据用于只读确认现象，验收以合成请求在隔离环境执行。
