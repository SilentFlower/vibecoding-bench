# 从实际决策到同一张请求头表

- 现有 Vue 组件 `NativeStageDetails.vue` 对无 `header_policy` 的 V2 只取入口和提交两个名称集合，因而遗漏最终 TLS。用同一表格、动作徽标、筛选和统计组件承载 V1/V2。V2 对照三份真实快照，可展示“仅入口”“提交时出现”“最终写出”等观测。保留原文分页、阶段来源及未知状态。
- 在 Gateway 选择可传递头、受管适配器组装请求和发送器追加传输字段的实际处理点取得动作及固定原因。选择来源与三个阶段是否实际观测到分开保存。一个同名字段在两阶段都出现也可能经历重建或合并。禁止仅凭字段同名、值相同或字段缺失推定策略理由。最终 TLS 只以已观测的 wire_final 为准。
- 复用现有账号私有快照、管理员读取、长度与条数上限、脱敏及有界后台保存。决策只记录字段名、动作、来源及原因码。核对 TuiCaptureInput、Rust 写入、编排读取台账与 Vue 类型；既有严格信封用已有能力协商或等价兼容路径避免旧组件拒绝。可选新字段对旧快照缺省。修订 V2 读取器当前的阶段集合限制时，保持账号、尝试和来源校验。
- 三阶段缺失分清完整头集合中未出现、预览截断后未知、整个阶段不可用。有序重复头留在原文；计数明确按名称或按决策条目，不能将三个阶段重复计为三次处理。沿用 `request-records.css`、`ChoiceSelect` 和仓库表格设计令牌。
