# V2 请求详情中的头部处理

## 目标

在请求详情的原始数据页，管理员可以像 V1 一样按动作查找请求头，并沿入口、发送器提交及最终 TLS 查看实际去向。

## 范围与验收

- [ ] 新 V2 调试请求展示逐字段动作和实际原因，复用 V1 的标签、行颜色、统计、筛选和仓库样式。覆盖保留、策略跳过、运行时生成或合并，以及仅有观测差异的情形。
- [ ] 三个阶段分别展示。发送器生成的身份头、运行时添加的字段和入口所带的代理头都能看清来源。凭据值按既有规则脱敏。
- [ ] 对旧 v1.38.0 的“43 个入口头、9 个提交头、11 个最终写出头”形态，按证据展示差异。缺少逐字段决策时显示原因未记录；快照缺失或头预览截断时显示未知。数据缺失不会被计成删除。
- [ ] V1 原视图、历史仅提交记录、未提交和外部提供方均能按实际证据查看。采集开关关闭或采集失败不改变模型请求。
