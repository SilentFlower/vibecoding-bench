# v3 账号当地可运行时间窗口

## Goal

让用户按账号实际时区设置可运行时间段，并看清当地时间、当前是否允许运行及下次开放时间。

## Background

代码位置与既有行为描述取自实施前 `7d705e3`；完成情况见实施记录和父任务组合验证。

- 来源为父任务 `../10-20-v3-environment-panel-and-run-windows/prd.md` 的 R2～R5。
- 有效时区由 `_effective_account_timezone` 读取已固化的 v3 环境时区：`orchestrator/main.py:2696`；账号列表已返回 `effective_timezone`：`:8150`。
- 当前只有养号随机间隔与 `warmup_next_run_at`：`orchestrator/main.py:1321`、`:7321`，没有账号当地运行窗口。
- 普通任务调度、批次投放、养号认领和交互续聊分别位于 `orchestrator/main.py:6629`、`:6212`、`:7047`、`:10766`；续聊输入另有 `:5713`，不能仅检查新建会话。
- 额度及认证保护已有独立契约，不可把时间等待写成额度耗尽或认证错误：`.trellis/spec/vibecoding-bench/backend/database-guidelines.md:617`。用户此次要求撤销运行中百分比强停，先由兄弟任务 P3 交付新行为，本任务随后集成。

## Requirements

- P2-R1：账号可独立保存当地可运行时间段；时区沿用环境已固化值，修改时段不能改变环境时区或身份。
- P2-R2：展示有效 IANA 时区、当地当前时间、当前窗口状态及下次开放时间；北京时间仅为参考显示。
- P2-R3：窗口判断必须在服务端执行，并与执行前的账号重读、并发排队、额度恢复和批次重启恢复衔接，不能只隐藏按钮或在入队时检查一次。
- P2-R4：窗口等待不触发额外 usage、模型、遥测或认证探测；账号禁用、删除、用户暂停和永久认证门禁仍优先。
- P2-R5：时段配置随控制端重启、容器重启或重建持久保留，运行历史及已保存 prompt、workspace、session 和版本快照不被改写。
- P2-R6：用户已明确选择本轮完成再休息；已开始的 run 保留原定补充、收尾及超时，不能因窗口关闭提前注入收尾或终止。交互续聊已发送的回合可继续完成，关闭后的新输入不发送、不缓存、不重放。

## Scope

以下整体范围随父任务最终 Brief 评审，本轮完成策略已确认：

- 可关闭限制；未设置的既有账号继续全天可运行。
- 支持星期、多个 HH:MM 区间、跨午夜和夏令时；不另存独立于环境的第二个调度时区。
- 覆盖平台普通任务、批次、养号、抓包和新续聊；对外网关 API、登录、OAuth 维护及手动额度查询暂不纳入。
- 窗口外已创建的普通/抓包 run 保持排队，批次保留待执行项，定时养号延后；交互式“立即养号”和新续聊入口返回明确休息原因及下次允许时间。
- 已开始的一轮自然完成，之后等待下一开放窗口；窗口和自设额度阈值同时等待时，两者都通过才开始。

## Acceptance Criteria

- [x] 按账号有效时区判断边界，跨午夜、星期切换和夏令时场景可复现验证。
- [x] 两账号在相同 UTC 时刻按各自时区和配置独立得到状态。
- [x] 在队列等待、批次间隔或额度等待期间跨过关闭时间，实际启动前仍受窗口限制。
- [x] 所有最终纳入范围的自动和手动入口遵守相同规则，错误或等待信息给出当地时间及下次开放时刻。
- [x] 关闭窗口限制后恢复原有调度行为，且不绕过已有额度、认证、停用、删除和人工暂停条件。
- [x] 窗口关闭不清理在途 run，原定补充和收尾仍执行；新轮次及新交互续聊输入被服务端拦住，通过重启恢复、并发和配置更新测试。
- [x] 与 P3 联合验证：达到自设额度阈值且窗口关闭时当前轮次完成，下一轮同时等待两个条件。

## Out Of Scope

- 代理地理位置自动切换时区、随机模拟作息及绕过服务商限制。
- 物理特征采集实现由 P1 负责；新配置的生产启用与发布需另按部署流程执行。
