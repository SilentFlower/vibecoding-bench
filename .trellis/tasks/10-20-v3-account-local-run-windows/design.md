# 账号当地运行窗口设计

## 数据契约

- accounts 追加可空 TEXT `run_window_json`；NULL 表示限制关闭。保存对象为 `{schema:1, enabled:boolean, days:[0..6], intervals:[{start:'HH:MM',end:'HH:MM'}]}`，0 为周一、6 为周日。
- 时区不写入配置，始终读取 `_effective_account_timezone`，即已有环境固化 TZ。保存配置不调用 runtime.ensure、不更改指纹。
- 严格校验布尔值、整数星期和分钟格式，启用时必须有日期和区间；start=end 拒绝，关闭限制即可表示全天。跨午夜区间按开始日归属，星期交集重复区间取并集。
- runs、task_batches 各追加可空 REAL `window_wait_until`，只存可重算的 UTC 等待提示，运行状态沿用 queued/active，不把时间等待写成额度耗尽或失败。该值不是启动许可，必须按当前配置重新判断。
- 新增 PUT `/api/accounts/{aid}/run-window` 保存完整时段配置；账号、环境、run 和批次摘要统一返回有效时区、服务器 now、当地时间、allowed、next_open_at/next_close_at 及等待原因。未关联草稿仅展示自身当地时间，不提供账号配置表单。

## 时间算法

新增纯函数模块 `orchestrator/run_windows.py`，使用标准库 zoneinfo：当前 UTC 时刻换算当地星期和分钟，采用开始包含、结束不包含的规则。跨午夜归属开始日，前一天尾段同样有效。

为避免手工拼接墙上时间导致 DST 错误，下次边界沿真实 UTC 分钟有界搜索，再转换为当地时间；最多搜索未来 15 天，覆盖每周窗口遇到一次跳时后下一周的情况。只在需要计算下一边界时搜索，按规范化配置、时区和 UTC 分钟做有界缓存；当前是否允许单独即时判断。夏令时不存在的分钟不执行，重复分钟按真实存在的两个时刻判断。已在无网络旧 control 镜像实测全部允许时区的数据可用；新控制镜像在构建时逐个校验这些 IANA 时区，缺失即构建失败，不静默回退为 UTC。

## 执行入口

| 入口 | 窗口关闭时行为 |
| --- | --- |
| 新建普通/抓包 run | 保持 queued 及原 payload，写等待提示，等待时不计执行超时 |
| 批次投放/重启恢复 | 不生成下一 item 的执行，保留原 next_launch_at，另记窗口等待提示 |
| 定时养号 | 未同步凭据/认领新轮前跳过，保留原随机间隔下限，在后续本地扫描重判 |
| 手动立即养号、新建续聊 | 返回明确的休息原因、时区及下次开放时间，不自动缓存用户操作 |
| 活跃续聊新输入 | 服务端拒绝发送，通知页面；已有输出继续，输入不缓存和重放 |
| 真实额度等待恢复 | 先核对窗口，再认领额度恢复许可，随后仍在实际启动前复核 |

普通队列等待使用调度器已有执行去重及可取消的短周期等待；不持有信号量、租约或各类锁。通过窗口后，在信号量/owner 等待结束和真正发起执行前重读账号与配置；如果时段已关闭则释放资源回到等待。

CHK-001 修复：凭据同步等准备动作之后、发布 running 或调用 `start_continue` 之前再次判定窗口。普通/抓包保留同 run 和 attempt 回到窗口等待；新建续聊返回休息提示，恢复续聊保留原等待会话。仅已确认尚未发起执行的路径使用 `QuotaGuard.release(..., unstarted=True)`，按账号、身份及完整 source 条件退还本次持久恢复机会；已执行、失败及其它来源的许可不删除。额度恢复转入新 queued 代次时清除上一代 started_at，避免尚未启动的新代被重启恢复误认作已执行。

一旦本轮已获准并启动，后续不因窗口关闭中止，也不删除原定补充或提前收尾。对话回合已发出的部分可完成，窗口外新 PTY 输入通过 `ContinueManager.send_input` 拦截；显式取消入口仍可用。

## 重启、配置更新与组合门禁

- 启动恢复先核对旧执行和真实停止意图；只有本功能标记、从未发起执行且仍合法的 queued 等待才重投。QuotaGuard.recover 要识别这种排队，不能仅因阈值已启用误判为崩溃运行。
- 恢复队列用原 run、attempt、prompt、followup_plan/timing 和版本快照，沿 Scheduler.is_executing 去重；不重新采样补充。
- 批次 active 等待不改变人工 paused/done/deleted；账号停用、删除及人工停止立即取消等待，启动前仍复核。
- 保存新窗口只影响后续入场；等待者在一个短扫描周期内重算时间，不能盲睡旧 deadline。关闭限制不取消额度/认证/人工暂停条件。
- 与 P3 组合：下一轮必须同时满足窗口、百分比、实际额度和认证门禁，任何单个恢复事件不能绕过其它条件。

## UI、验证及回滚

账号页增加当地时钟、窗口状态和配置按钮，配置星期/多个区间/关闭限制；环境详情显示同口径摘要。当地时钟按有效 TZ 渲染，另给北京时间参考。状态从服务端获取，在下一边界或短轮询后刷新，不能覆盖正在编辑的表单。

纯函数覆盖正常、跨午夜、周末、相邻区间、关闭配置、DST 跳时/重复时刻及坏配置；调度测试覆盖所有入口、信号量等待跨边界、配置更新、停止/删除、quota 恢复和重启去重。真实本地 driver 验证跨关闭时刻后继续原补充和收尾，以及下一轮不提前启动。

回滚前关闭窗口并收口等待；旧版本忽略追加列会失去时间约束，不能当作等价运行。数据恢复仅针对新增字段/配置，不整库覆盖新产生的任务和凭据。
