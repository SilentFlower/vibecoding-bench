# 修复验收误判导致的反馈污染和重复返工

## Goal

让项目迭代及工程养号依据可靠验收事实自动推进，消除错误反馈引发的无效返工和人工确认停顿。

## Requirements

- R1 修复 Arrow 空格式异常误判：公开合同未限定空列表的异常子类，而 expansion_coverage.py:52 只捕获 TypeError。原冻结合同和历史资产不可原地改写，现有工作使用精确版本适配。
- R2 公开失败反馈包含有界、脱敏且可操作的阶段、失败节点及异常事实，不暴露私有验收代码、凭据或任意日志。
- R3 验收器暂时故障本地有限重验；重复失败、无新证据或返工预算耗尽后自动暂存为待复验，继续其他可执行目标，不要求人工确认。
- R4 待复验保留同一 work、工作区、Claude 会话、历史和累计用量；冷却后自动续做，不计通过、不满足依赖、不触发养号整池重开。
- R5 暂存结束本轮工具循环；下一目标沿用已有上下文隔离；旧目标恢复携带可靠纠错事实，原始历史留档。
- R6 核对线上候选，撤销仅迎合误判的覆盖率豁免，保留业务实现和原会话；独立重验后自动恢复计划。
- R7 沿用身份、授权、取消、未知输入和严格释放保护；此次及后续部署按用户要求不备份、不计算内存、不调整资源配置。

## Acceptance Criteria

- [x] A1 空列表合法 TypeError/ValueError 均接受，其他错误参数仍严格验证，真实错误实现失败。
- [x] A2 相同失败不能无限提交或跨轮清零；两空间支持暂存、换目标、冷却恢复和重启持久化。
- [x] A3 保留原 work/session/workspace，待复验不进入 passed 或前置证明；全池等待时自动排期。
- [x] A4 模型获得具体脱敏事实，原始工具结果落库后结束循环；无私有源码或凭据泄漏。
- [x] A5 暂停、取消、代次变化、未知输入和清理失败不被自动复验绕过。
- [ ] A6 本地与真实冻结候选隔离验证通过，线上 v3 页面/API 核对完成，无部署备份或内存计算。

## Background & Decisions

- 用户在五步修复方案展示后要求“那赶快修复”，并追加“验收更加灵活，不要出现死循环和暂停人工确认”。
- 线上账号 8 的 work=388f9e761bcf464eb9b805943daed4fa、Claude session=5047b20a-5a21-4f0b-baed-2140627a1b57；已通过正式 pause 接口临时关闭计划并保留现场。
- 四次相同误判的具体堆栈被 _public_facts 丢弃，Pi 反复猜测路径、时区和覆盖率；候选出现 pragma no cover。

## Non-Goals

- 不降低功能、覆盖率或原测试门槛，不改公开需求迎合候选。
- 不删除历史、重建账号身份或用 seed 覆盖工作区，不绕过真实权限或认证故障。
