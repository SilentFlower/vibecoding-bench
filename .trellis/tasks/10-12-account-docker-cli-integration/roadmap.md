# v3 后续 Roadmap

## 可配置的养号额度阈值

- 来源：2026-10-12 用户要求作为 v3 后续 roadmap，本轮不实施。
- 当前行为：真实响应显示 5h 或 7d 通用额度用满或明确拒绝后暂停，遵循现有恢复逻辑。
- 目标：允许配置 5h、7d 的养号停止阈值；任一启用窗口达到阈值后不再投放养号作业，避免必须用到 100% 才停止。
- 展示建议：明确标注「已用百分比」，同时展示「剩余百分比」；例如已用 20% 对应剩余 80%。默认值尚未确定，示例不是默认配置。
- 后续需确定：账号级/全局配置、阈值禁用方式、已运行养号是否提前收口、恢复与迟滞、额度未知或过期时行为，以及是否仅作用于养号。未确定行为不扩展到普通任务、抓包或网关。
- 沿用真实额度及 reset，不新增阈值探测请求，不把 reset 到期视为额度归零；永久认证门禁优先。
- 本任务只记录需求与保留扩展点，后续另建规划任务并验收。
