# v3 大版本：固定账号 Docker 与统一登录、管理和部署

## Goal

交付可与旧版并行运行的 v3：每账号拥有固定 Docker 和完整持久 HOME，由原生 Claude Code CLI 在 tmux 中登录，并统一账号管理、任务入口和构建启停。

## Background

- 用户选择固定 Docker 环境，要求首次登录真实执行 Claude Code CLI，后续普通任务、养号、抓包与续聊延续同一账号环境。
- 用户要求融合两个项目的管理能力，保留 cc2api 现有协议处理；最新决定将 HTTPS 实际发送放入账号容器，管理端继续负责选号、请求改写、重试及响应处理，API 不改成 CLI 推理。
- 用户确定两个镜像：管理镜像与账号镜像。每账号一个固定容器，承载 CLI、网络、抓包及上游发送；原 worker/sidecar 不再作为两个账号容器部署。
- 用户要求镜像打包、启动一并交付，使用独立容器和宿主端口，不影响现有系统；已有 `origin/v2`，新版本命名为 v3。
- 当前每 run 创建和删除 worker/sidecar（`orchestrator/main.py:3309`、`:3546`）；登录使用真实 `claude auth login`，但直接连接 Docker exec PTY，尚未使用可重连的 tmux 登录会话（`:7469`）。
- 当前绑定只同步账号与凭据（`:6970`），cc2api 创建账号另行生成设备身份（`cc2api/src/service/account.rs:664`）；其上游仍由网关 HTTP 客户端发送（`cc2api/src/service/gateway.rs:2520`）。
- 没有证据证明容器重建是账号暂停的原因；本任务解决持久状态、生命周期与管理一致性，不承诺避免封禁。

## Requirements

- **R1 固定账号环境**：首次登录前建立每账号一个固定容器，成功后绑定不可变账号 ID；普通任务、批次、养号、抓包、续聊、手动额度查询、API 上游发送和维护复用该环境。完整 HOME、CLI 配置、登录状态、会话与缓存持续保存，环境身份不随账号名称、run、空闲停止启动变化。基础依赖和同一 CLI 版本安装结果复用，run 保持独立项目目录与运行快照。
- **R2 真实 tmux 登录**：固定账号容器内的 tmux 执行原生 `claude auth login`，网页终端连接该会话。断线只分离连接，重连不重新授权；取消或到期收口登录进程。CLI 登录状态校验通过后才正式提交账号，保留完整 HOME。重授权在同一环境内进行，提交前保护旧凭据，取消或失败不破坏既有账号。
- **R3 管理融合**：一个后台入口管理账号、环境、CLI 登录、普通/批次任务、续聊、养号、抓包及额度与运行状态。cc2api 管理绑定账号身份、代理配置、认证状态和凭据；bench 管理环境、run 与证据。通过接口访问唯一负责方，不让两个服务直接写同一账号表；保留既有 API 及未绑定账号兼容路径。
- **R4 凭据与身份归属**：绑定账号只由 cc2api 刷新 OAuth；持久 CLI 运行凭据不携带可竞争刷新的 RT，领取执行后同步最新 AT，401 沿用 managed 流程。新 CLI 账号导入继承有证据确认的设备身份和实际环境基础字段；`userID`、`machineID`、Linux machine-id 与 `device_id` 不得直接互换。已有有效身份保持，来源不确定时显示冲突并阻止该项同步。
- **R5 执行协调**：同账号 CLI 作业、登录、续聊、抓包与维护串行，不同账号可并行。普通 CLI、养号、抓包与同账号 API 独立调度，可在 API 活动或等待期间启动，也不阻止新增 API 入场。养号仅对正式 CLI 作业及其等待工作保持低优先级，不抢占、不积压补跑。只有重授权、代理修改、绑定切换、停止及重建等共享环境维护关闭 API 入场并排空已接受请求。粘性请求、额度等待和排队规则保留。
- **R6 账号容器实际发送 HTTPS**：管理端保留选号、请求改写、header/body、版本画像、重试、错误分类及响应处理；抽出并复用现有 HTTP/TLS 发送实现，在目标账号容器建立上游连接并流式返回。连接池、代理和传输实例按账号环境隔离，账号容器不可用时不得绕过它直连，也不得因桥接失败盲目重发。API 不改成 CLI 推理、不强制经过 CLI MITM，SSE、取消、背压及现有协议行为保持兼容。同一容器不代表两条客户端链路的完整指纹相同。
- **R7 作业与证据隔离**：执行拥有独立代次、进程/PTY、cwd、结果、主 Claude 会话和证据归属。取消、超时、服务重启、WS 关闭和额度暂停只收口对应 CLI 执行，普通 CLI 清理及租约故障不得停止账号容器或中断独立 API；不能把固定容器退出当成任务终态，旧回调不能覆盖新执行。统计只计所属 run/session 的新增内容，不扫描累计整个账号 HOME。
- **R8 抓包与额度兼容**：账号容器内的网络与 Recorder 按作业切换上下文，普通任务保留必要统计与被动额度观察，诊断作业保存完整 HTTP/flow。CLI 与 API 的证据标明来源，不因同容器混合归档。切换确认代次，结束、取消和异常后排空连接、撤销诊断。保持全局抓包串行、120 秒间隔和异常至少 15 分钟冷却（`official-protocol-capture.md:112`）。现有额度用满暂停、原 run/session 恢复、永久认证门禁与脱敏契约保留。
- **R9 两镜像统一交付**：管理镜像包含 gateway/orchestrator/UI/题库，账号镜像包含 CLI/tmux/开发工具、网络/抓包和上游发送器。每账号一个容器，管理镜像按角色启动两个服务容器，N 个账号共 N+2 个容器。提供统一构建、兼容版本清单与 Compose 启停入口；清单记录父仓、cc2api 提交及两个镜像 digest，不能混用不同批次或旧 `latest`。启动不再零散复制 WebUI 文件。
- **R10 与旧版隔离**：v3 使用独立分支、镜像名称/标签、Compose 项目、容器/labels、网络、数据库、HOME、CA、证据、宿主端口及管理会话命名空间。默认只发布一个后台/API 宿主端口，内部服务及账号容器不发布端口。配置或实际资源冲突时拒绝启动，不停止旧容器、删除旧资源、修改旧数据库或覆盖旧发布标签。
- **R11 账号与资源隔离验证**：首轮使用独立测试账号、空新数据库和专属代理配置。不复制旧账号有效 RT 到新版并行运行；导入演练仅使用去凭据离线快照，真实接管另行处理。新版限制活跃环境数、CPU/内存和日志保留量，启动前检查宿主余量；同宿主仍共享 CPU、内核及物理资源，不宣称绝对零性能影响。
- **R12 维护与回退**：空闲停止环境保留持久数据和身份，活动 API/SSE、登录与后台连接不被当作空闲。API 需要环境时受预算约束唤醒并校验绑定、代次与健康，未就绪不发送上游。升级、重建、删除、改绑和代理修改检查活跃执行；启动先对账旧进程、代次与额度，再恢复调度。停机/回退只操作匹配 v3 部署标识的资源，保留证据；旧版独立运行，不自动迁移或切流。

## Acceptance Criteria

- [ ] **A1（R1、R2）**：固定环境内真实 tmux 登录；断线重连是同一会话，成功后的首轮、续聊与再次使用保留同一 HOME 和有效身份，同版本不重复安装。
- [ ] **A2（R2、R4）**：重授权取消/失败保留旧凭据；绑定后唯一刷新者成立，运行 HOME 不含 RT，排队后取最新 AT，401 不形成第二条刷新链。
- [ ] **A3（R3、R4、R6）**：统一后台完成账号到环境、任务与抓包管理；身份导入字段有证据，已有身份不被覆盖，CLI 与网关基础版本分别展示。
- [ ] **A4（R5、R7）**：同账号 CLI 入口不能重叠；API 活动/等待期间普通 CLI、养号、抓包可启动，CLI 运行期间新增 API 正常入场；取消及共享 CLI 租约故障不停止 API 流。共享环境维护仍排他，旧代次不能清理新作业。
- [ ] **A5（R5、R8）**：养号在 CLI 忙或有正式 CLI 等待工作时顺延，API 活动与排队不构成养号忙碌条件；额度等待释放资源，恢复原 run/session 和快照；永久认证错误继续阻断。
- [ ] **A6（R7、R8）**：CLI 取消、超时、重启、异常后无遗留 CLI 请求，独立 API 流继续；统计及 capture 归属正确，诊断撤销失败阻止下一作业，限频及文件权限保留。
- [ ] **A7（R6）**：本地 mock 证明实际上游连接来自对应账号容器；不同账号不共用传输实例/连接池。body/header、TLS 规则、SSE、重试和画像回归兼容；断线/取消收口正确，容器故障无直连回退或自动重复提交。
- [ ] **A8（R9）**：一个入口构建管理和账号两个镜像，版本清单完整；N 个账号各一个容器，另有两个管理服务容器。一套命令启动、检查、停止新版，版本组合不一致时拒绝启动。
- [ ] **A9（R10、R12）**：旧容器/端口/挂载冲突在新版启动前拒绝；新版启停、清理和回退只操作自身标签资源，旧服务状态与数据库不变。
- [ ] **A10（R11、R12）**：隔离数据库与账号完成生命周期验证；旧凭据、数据、账号额度无变更；记录资源限制与余量，未执行真实上线/接管时明确标注。

## Non-Goals

- 不合并成单进程、不重写 Rust 协议处理或 Python 调度器、不改成 CLI API 推理，不引入 patched CLI、KVM 或虚拟机。发送位置迁移不等于更换 TLS 或请求画像算法。
- 不修复遥测专项问题、不新增模拟行为，不将固定环境作为防封承诺。
- 不实施 5h/7d 提前停止阈值；用户要求已记录 `roadmap.md`，本轮保留现有额度用满门禁。
- 不操作线上部署、不修改旧端口/容器/数据库、不自动迁移账号，不用生产账号验证；推送、镜像发布、上线及切流不包含在规划授权内。

## 范围关系

本任务是一项共同验收的 v3 交付，环境、管理、协调和部署共享身份及生命周期契约。旧固定环境任务已取消，遥测任务继续暂缓，本任务不改变它们的状态。
