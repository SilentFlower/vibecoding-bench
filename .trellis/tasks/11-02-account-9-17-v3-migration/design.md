# 账号交接设计

## 预检

核对实际源/目标版本、账号 22/42 的身份映射、完整有效凭据、代理和策略、目标同名/同 UUID 冲突、源活动运行（含 quota_wait）、续聊/登录、API active/waiting 与未完成输入。v3 使用现有 2.1.293 身份来源，原 profile 最后观测也为 2.1.293；旧服务环境兜底 2.1.280 不能代替实际 profile 证据。

## 所有权交接

1. 等原工作自然结束，关闭未来旧养号/新作业。仅在无活动工作时，通过旧版现有账号退出入口关闭旧 bench 可用性；已有历史引用使其软退出。执行前验证引用计数和接口前置，不能硬删历史作为迁移捷径。
2. 如 AT 需要满足交接有效期，先通过旧端现有 resolve、force_refresh=false 解析；不直接拿 RT 绕过唯一所有者刷新。
3. 单独通过旧 gateway 状态快速入口停用 42，避免普通整行更新覆盖并发 Token。关闭后，经旧 resolve 的账号刷新锁形成屏障，预期本地 inactive 拒绝，证明在途刷新收口；锁超时或非预期错误不视为完成。
4. 重新读取旧 gateway 最终权威 AT/RT/expiry，核对账号归属、代理与原 CLI 身份；不能直接复制一开始的 profile 快照。关闭源后的旧凭据不会自动恢复。

## 目标接入

- 新号接入期间，对原本允许全部账号的现有 API Token 暂时限定为接入前账号 ID 集合；保留 blocked/status 和密钥，核对无并发配置改变后恢复原值。显式允许列表不扩大；中断保持限制并先对账，避免按创建默认 RPM 提前承接新请求。
- 配置恢复通过包含相同 proxy_url 的现有管理入口取得排他配置门禁，保持原代理；不绕过正式配置门禁直接修改数据库。
- 仅在唯一刷新所有权交接后，通过已有 usage 刷新接口做一次登录态与当前窗口核对，不新增轮询或模型探针。

- 将最新凭据和原 .claude.json 登录配置写入目标私有 profile；新建且未绑定的固定 HOME 必须在空闲停止状态补齐相同的必要登录文件，仅创建缺失文件、不覆盖既有 HOME/身份，之后仍通过正式身份校验；只保留必要登录/身份文件，不复制历史 projects、session、flows、旧运行 hooks 或工作目录。
- 通过现有 bench 创建接口登记 9-17，沿用原代理和时区，按正式 CLI 身份同步路径创建并绑定新的 v3 gateway 账号。
- 使用现有单账号维护/绑定门禁核对并恢复原并发、RPM 和其他可迁策略，不能让新建默认值成为最终策略。状态快捷操作和配置更新按各自真实接口分开提交。
- 新环境使用 v3 固定逻辑环境；CLI userID/账号归属保持，旧 API device_id 不复制。绑定后 profile 持有受控镜像，HOME/access 仅发布 AT，v3 gateway 独占 RT 刷新。
- 保留额度阈值，v3 养号迭代保持未启用；不将旧小时计划映射成新任务。核对现有 API Token 允许范围，保持授权边界，不默认复制旧 Key 或扩大模型/账号权限。

## 结果与失败收口

只读验证新账号可见、套餐字段、运行绑定、身份、代理、最终策略、两侧活动所有权和凭据来源。保存 target ID/environment 与无秘密的哈希比较和状态收据；不保存 Token、完整配置或对话。若步骤部分成功，保留目标门禁并报告具体状态；重试先重读原操作结果与当前权威凭据，不重建重复账号、不用旧 RT 回滚。迁移未通过时禁止永久清理。
