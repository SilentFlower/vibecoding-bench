# 实施与回归

1. 由用户指定的开发窗口在独立检出处理本任务，主窗口独立验收。以 flower2api 当前发布线核对 Sender、网关会话入口、正式请求编码与已有测试，保留先前 ABI 2 分支的提交边界。
2. 基于 `images/account/test_tui_message_json.py` 或 `images/account/test_tui_session.py` 构造首轮实际 SSE 登记和下一轮的回执。先记录现有代码仅省略 `caller` 即拒绝的对照，再实现最小改动。用现有错误和单次认领验证剩余字段及原归属。
3. 运行账号侧 TUI 测试，在隔离网关、候选发送器与回环模型之间跑公开 Messages 接口。对照显式及缺省会话、单轮和连续工具回填，覆盖缓存断点组合、并行工具与失败后仍可正确回填。记录状态、结果、实际投递次数及上游收到的字段，不使用真实账号请求正文。
4. 核验与发布基线的实际差异，确保任何持久化摘要调整有旧记录兼容证据。按 Trellis 检查并同步任务结果。

## 验收记录

- 基线 `fe1735cc` 的正式 Gateway、Sender 和固定 CLI 2.1.293 在隔离网络重现首轮 200、直接调用省略 caller 后续轮 422。回环模型只收到首轮。
- 候选镜像更换 Sender 的回执比较模块。显式/缺省会话 ID 分别覆盖 caller 原样/省略。四组各包含三次成功请求、两次连续工具回填，合计 12 次 HTTP 200、12 次回环模型投递，覆盖 SSE 和 JSON 响应。
- 首轮并行 Bash 调用的每份合成结果按原 ID 交付。实际出站的历史按客户端写法保留或省略 caller，工具与结果的 5 分钟缓存标记传递正确。两种会话下显式 null 均返回 422，模型提交零次，随后用合法回执成功续答。真实上游缓存命中率未测。
- 账号侧 77 项和编排器 TUI 40 项测试通过。产品变更集中在 `images/account/tui_messages.py` 的比较快照，数据库、网关摘要和原请求编码沿用原格式。
