# 修复 V2 直接工具调用回传时报 422

## 目标

Claude Code 回传 Bash 等直接工具调用的结果时，V2 能接续原会话，用户可以继续使用当前 Tool Search 配置。

## 背景

同一会话的四条 422 均发生在模型提交之前。成功请求的入口与 Sender 快照有相同的 56 项工具定义，失败请求的入口工具清单也相同。客户端回传时省略了直接调用的顶层 `caller`。用发行代码的 `WireStep.observe` 登记合成 Bash 调用后，保留字段时 `tool_receipts` 接受；只省略该字段时抛出“原轮助手内容或工具声明发生变化”。

## 需求

- 上轮登记的 `tool_use.caller` 恰为 `{"type":"direct"}` 时，接受客户端省略该字段，也接受原样回传。适用范围为原轮直接调用。
- 结果仍属于原会话、原工具组和原调用。工具 ID、名称、参数、签名及其他调用方信息沿用现有匹配规则。
- 兼容处理局限于回执匹配。发送给模型的工具历史、缓存标记和现有 TTL 策略继续按客户端请求及既有配置处理。

## 验收

1. 显式会话以及未指定会话 ID 的公开 Messages 请求均完成“取得工具调用、回填结果、模型续答”。保留和省略直接调用的 `caller` 均可完成，连续两轮工具回填正常。
2. 每次合法回填只投递一次。在回环上游核对收到的工具块字段、结果 ID、输入以及原有缓存标记。真实供应商缓存命中率不作本次验收指标。
3. 覆盖并行工具组、错归属、改变执行参数或签名、非直接调用，以及工具输入对象中名为 `caller` 的业务字段。其他调用的结果不可被本轮认领。

本次处理已复现的直接调用差异。退出计划模式等工具专用参数转换另作独立兼容事项。
