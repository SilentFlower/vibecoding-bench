# 受管 V2 账号最终 TLS 写出采集

## 目标

管理员在请求详情的「原始数据 → 最终 TLS 写出」查看本次受管 V2 尝试实际被账号发送器的上游 TLS 接受的 HTTP 请求，能与入口和提交快照对照。

## 用户行为与边界

- 开启既有调试采集后，展示脱敏的有序请求头、正文预览、实际 HTTP 和正文字节数及摘要。完整性和预览是否截断分别展示。
- 部分写入、发送前失败、取消或暂时未取得证据时显示实际状态与原因；已经完整写出后收到上游错误，也保留写出事实。
- 旧记录继续按原有证据显示。外部提供方的 TLS 发生在独立进程，页面显示已保存的回环提交阶段。生产安装与签名发布沿单独流程。
- 推理、工具续轮、缓存、代理、连接复用和现有采集权限按原合同运行。只使用请求详情已有的管理员入口与保存期限。

## 验收

- [ ] 真实账号发送器经合成代理和 HTTPS 服务发送一次，TLS 写出证据与服务端解密收到的请求在长度、顺序和原始摘要上相符。
- [ ] 覆盖流式和非流式、流式请求取消、上游错误、短写、大正文及开关关闭。对不完整实体不显示完整摘要，采集失败不影响推理结果。
- [ ] 同账号并发、同连接连续请求、后台额度流量和其他账号相互隔离；受管、本地提供方及历史格式均经实际读取器验收。
- [ ] 从账号私有快照经管理员 HTTP 接口到真实浏览器展示，文件和面板里看不到合成凭据。旧节点、新节点及原生 V1 读取有兼容回归。

发布范围已由用户选择合在 v1.38.0。文件凭据及最终 TLS 写出共用正式发行，生产安装仍由实例管理员决定。
