# 设计

## 当前路径与已核对事实

- 基线为远端 `flower2api` 的 `77a16aa7`。Python `managed_model_response` 把 `reservation_id` 用作本次 `PreparedRequest.request_id`，将单次模型请求交给本账号 Rust sender 的私有发送入口。现有提交快照早于 Rust sender 添加 Content-Length。
- 管理员开启的采集由 Gateway 与 sender 私有握手决定。`TuiSender` 已持有尝试标识、绑定和私有文件写入许可；现有提交快照在读取事件源尾帧后异步保存。
- Rust 出站沿 `send_with_client` 和现有 reqwest / hyper / 项目内 Rustls。当前上游配置只协商 HTTP/1.1。此前的隔离回环实验用此 TLS 配置将 96 字节分三次接受，服务端回显正文一致。该实验验证了采样边界，完整发送链路还需验收。
- 本次使用编排真实 `read_capture` 复现：历史 `http_request_to_local_provider` 可读，基线 Rust writer 新写的 `request_to_account_sender` 和 `http_request_written_to_loopback_provider` 均遭拒。编排另有禁止 V2 顶层出现 `wire_final` 的旧规则；Rust 的 `append_wire` 与 Vue 的 `tlsWire` 当前只接受 V1 来源。修复必须涵盖写入、校验和展示。

## 采集与关联

1. 沿现有私有协议，对已授权采集的受管模型 send 建立一次性观察。完成绑定、账号、环境代次和预留校验后，内层实际发送只可取走同一次尝试的观察句柄。同一 sender 的普通代理、后台请求、外部提供方和其他用途没有此句柄。
2. 将观察归属随请求在进程内交给**实际服务该请求的 HTTP/1 连接**。在发往上游的 TLS 明文写入成功处按实际接受长度累计，覆盖普通写与向量写、短写与取消。代理连接建立及握手数据独立。实现时沿 `hyper` 写缓冲、`reqwest` 连接适配与 TLS writer 核对：只有可证明等价于上游 TLS 接受长度的边界才能作为数据源。连接归还前解除归属。使用现有传输、池策略和 HTTP 字节，无新增上游头、代理、系统权限或第二次发送。
3. 在有界内存内识别当前 HTTP 实体边界，按实际接受的请求行、顺序头和正文增量计数及散列。大正文只保留已有预算内的预览。按已确认的传输分帧提取实体，超出本次请求、出现间隙或无法确认归属时标出缺口。
4. 复用现有账号私有目录、脱敏、写入并发、轮转和读取权限。把 TLS 结果与提交快照按尝试归并。提交尾帧晚到、缺失、流取消、HTTP 错误或落盘失败均须收口观察句柄。已取得的完整证据不被后到的弱状态覆盖；未取得提交阶段的内容不从 TLS 副本倒推。禁止将未脱敏副本写临时文件或打印日志。

## 展示合同

沿 `wire_final` 增加独立的受管 V2 证据来源，保留 `http_entity_from_tls_accepted_write` 的语义。有来源、归属和完整实体证明才展示完整 HTTP/正文摘要；写入已接受、网络刷出和上游响应分别表示。新旧来源用闭合的合法组合分别校验。旧回环记录、本地提供方、V1 和其他平台按原来源读取，不接受伪造组合。

前端复用原始数据标签、脱敏代码块、阶段卡片和已有状态样式。HTTP 请求头保留实际顺序与重复字段。TLS 来源、截断、未采集和不完整在页面上可区分。

## 部署和回退

仅在能读取新格式的控制端和具备该能力的受管 sender 间启用新证据。覆盖滚动期间新旧组件组合；切换或回退时采集能力下降可见，推理和历史工具回执仍由原持有者处理。沿用现有私有文件存储，不增加数据库迁移。

## 回拉后的凭据合同

开发分支快进至 `197025b0`。文件凭据和旧令牌均沿原预留启用受管观察。私有凭据帧与业务请求分开。写出成功处只向有界队列尝试复制字节，后台独立计算摘要、脱敏并保存。

混合版本写入沿用旧 reader 接受的表示，另用可选字段标明本次提交去向。只有新协议可以产生最终 TLS 证据。
