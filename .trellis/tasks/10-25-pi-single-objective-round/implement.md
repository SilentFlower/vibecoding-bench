# 实施计划

## 顺序

1. 共享后端按账号、命名空间和 generation 绑定一个工程目标，完整验收及执行收口后返回可信完成标志。
2. Pi 保存真实工具结果后结束本轮，混合工具批次也不能开启第二目标；人工取消、原预算和账号门禁优先。
3. 新目标从干净上下文开始，同一目标跨指挥代次恢复原 Pi／Claude 会话；目标清单和公开材料按需分页。
4. 在 Pi 模型设置、严格 DTO、私有保存和前端表单贯通 compaction_threshold_tokens；默认 350,000，允许 10,000～900,000，旧配置兼容，启动时冻结。
5. 依据最近有效用量及后续内容估算判断阈值，包含缓存输入；工具批次后安全结束 SDK 子循环，保存回执，分段生成摘要，再 continue 原任务。
6. 摘要及普通推理共用有界重试、模型优先级、停止信号和原截止时间，并纳入真实计量；摘要完整成功才发布检查点，失败不丢原文、不重发工具。
7. 完成最终源码回归；后续按 Pre-Check 状态进入 Check-All、Update-Spec 与精确 Git 提交计划。

## 文件范围

- orchestrator/projects.py：单目标边界、按目标 fresh/resume、模型工具分页、完成与上下文事件。
- images/pi-agent/host.mjs、context-policy.mjs：单目标收尾、token 判定、分段摘要、上下文恢复和共用重试。
- orchestrator/project_requester_settings.py、main.py：阈值私有持久化、旧文件补默认、严格输入及脱敏接口。
- webui/index.html、projects.js：阈值字段、读取回填与提交，两个任务空间共用。
- images/v3/Dockerfile、Dockerfile.dockerignore：配对包含新的运行模块。
- Pi、Projects、RequesterSettings 相关测试；Pi README、项目库说明及任务材料。
- 项目规范的单目标契约为上一阶段已写入内容；本次 token 配置与摘要契约待后续规范阶段同步。

## 风险与回退

- 实际用量优先；未计量内容采用 SDK token 估算。自定义模型的规划窗口不改变上游真实容量，真实窗口拒绝时走一次强制摘要恢复。
- 摘要请求有真实模型成本；计入统计并服从原时限、取消与全轮额外重试上限，不增加单独的无限预算。
- 发布须同时更新后端、Pi host、新策略模块及前端。保留原历史、会话、工作区、累计耗时、通过记录和两空间计划。
- 线上旧通用错误仍需按已核实原始会话证据追加绑定诊断，再由既有显式启动入口恢复，不能泛化解除未知输入、身份或认证阻塞。
- 回退仅回退本次代码，不回滚数据库、已接受成果、已有内容过滤恢复补丁或当前业务进度。
