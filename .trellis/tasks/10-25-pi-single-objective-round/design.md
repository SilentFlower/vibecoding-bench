# 单次指挥的目标边界与有界上下文

## 现有入口与事实

- `ProjectsService` 同时服务 projects 与 warmup；`ProjectsDatabase` 固定改写命名空间，`AccountPiOwners` 协调同账号占用。
- `_run` 创建单次控制者代次、原预算和取消信号；`_start_work` 选择或恢复目标，`_submit` 执行完整独立验收，`_release` 保存通过及停止原 Claude 执行。
- 原实现中 `_submit` 返回成功后 Pi 继续工具循环，只有模型自行结束、用户停止或整轮超时才退出。
- 养号的 `cycle_no` 表示完整工程池轮次，与一次 Pi 指挥不同；`_advance_cycle` 只能在后续认领且全部通过时执行。

## 修复机制

1. 以账号、空间和控制者 generation 为边界锁定本轮工程目标，保留启动时的未完成目标优先级。`_check_round_work(account_id, generation, work)` 查询该代次已有的持久工作；创建／恢复入口和新工作发布前分别在服务锁内核对，拒绝已结束目标或创建第二工作。并发选材不能在发布前绕过复查。
2. 仅在 `project_submit` 完整通过、通过事实保存且 `_release(..., 'passed')` 成功后返回布尔 `round_complete=true`。现有 Python 管道原样交接，Pi 只接受该工具的 `status='passed'` 和严格布尔完成字段，使用 SDK 的 `AgentToolResult.terminate` 正常结束。混合批次的后续工具不再交给父进程，`prepareNextTurn` 在批次结果落盘后阻止下一次推理，并将此次可信完成映射为 settled。用户取消仍优先，成功收尾的零用量本地 aborted 消息不计入上游调用。
3. Pi 指南要求一个目标通过后结束；恢复提示明确先续原目标，旧历史中允许连续选目标的说明不能覆盖控制端硬门禁。
4. 两空间复用同一实现，保留各自数据、计划和整个工程池的循环规则。目标通过不直接调用养号的工程池清理。

## 兼容与持久化

- 复用现有 work.generation 和当前 work，不新增业务表或迁移历史通过记录；SQL 命名空间使该约束分别作用于两个空间。
- 新指挥可以在原目标已通过时选择下一目标；同一指挥中的重复工具调用不能提前获得这个权限。
- 原控制者停止、人工暂停和服务关闭仍按已有 generation 及 owner 释放保护；迟到结果不得重新打开计划。
- 保留单目标跨轮累计耗时和原会话，本次只改变每次指挥的目标数量和正常完成边界。

## 验证与风险

- 使用真实 SQLite、共享服务和本地 Pi 替身覆盖两个 namespace；再用实际 JSONL 管道核对完成信号与退出。
- 重点防止把成功收尾的内部停止信号误记为人工取消、把验收失败误结束为通过、以及正常结束与人工暂停竞争导致重新排程。
- 完成工具结果先经 SDK 保存到原会话；下一进程的完成标志重新初始化，历史结果不会终止新轮。成功后不再额外压缩／推理；内容过滤等既有重试策略保持。

## 上下文增量方案

- 用户最终明确的重置边界是工程目标。目标跨多次指挥代次仍使用 resume；只有开始下个目标才 fresh，不实施每次模型请求重建。
- 用户明确要求按 token 摘要压缩，默认 350,000，并在 Pi 模型配置中可改。本次替换原未部署的 12／24 KiB 字节裁剪方案，不将旧方案验证算作新方案通过。
- 配置入口为既有 ProjectRequesterSettings、/api/settings/project-requester 和两空间共用的 Pi 模型表单。新增 compaction_threshold_tokens，整数范围 10,000～900,000；私有 schema 1 向后兼容，旧文件补默认，省略字段沿用现值。配置仍在每次控制者启动时冻结，不热改在途会话。
- token 判定优先使用最近一次有效助手用量的 input＋output＋cacheRead＋cacheWrite，并估算此后新工具结果；压缩前留下的旧 usage 在新摘要边界之后失效。无有效用量时使用 SDK 的 token 估算并计入固定指南和工具定义。
- SDK 原生自动压缩保持关闭，由入口统一管理。启动／恢复和每次工具批次结束时检查阈值；连续循环需要压缩时先在已确认工具结果后结束当前 SDK 子循环，等待持久化，再压缩并 continue 原工具结果，不重发用户要求或已执行工具。内部停止不虚增模型调用，也不覆盖人工取消。
- 摘要使用公开 generateSummary，保留近期约 12,000 token 的完整工具批次；较早内容和上次摘要按较小的估算 token 块顺序归纳，避免旧百万级会话成为一个超限摘要请求。摘要完整成功且取消／预算仍允许时，才追加 appendCompaction 并重建上下文；中断或失败保留原文和进度。
- 摘要的真实模型调用纳入用量统计，沿用停止信号、原截止时间、同模型重试与备用模型策略。摘要和普通推理共享本轮额外尝试上限，不能隐式无限重试或生成额外工具动作。
- 新目标通过本地空后缀检查点隔离此前目标历史，不调用模型总结已完成目标。原 Pi 文件及 Claude 会话、业务事实和输入去重保留。
- 真正上下文拒绝最多在原预算内强制摘要后续接一次；无缩减空间或再次失败明确报告 context_limit。认证、禁止重试、服务端等待、未知输入和身份门禁优先。
- account_state 及 project_read 保留已实现的分页，页面完整视图不改；上下文事件改为原因和压缩前后 token 数，不发布私有正文。
- 旧通用错误仍只能通过绑定原错误的已核实诊断开放既有显式启动路径，不能直接解除任意阻塞。

## 新增验证

- 真实 SDK + 本地 HTTP 重现百万级历史、aborted/error 零用量、连续工具及混合批次、原模型上下文恢复、取消与硬错误。
- 后端验证两个空间 fresh/resume、600 项分页与材料分段还原；不请求真实模型或修改生产业务数据。
