# Brief — 项目与养号单目标边界及 Pi 上下文修复

## Goal

- 两种迭代每次指挥只处理一个工程目标，并以可配置 token 摘要压缩恢复和持续运行。

## Scope

- 共享后端的目标绑定、第二目标启动拦截、成功收尾及 Pi 指南。
- 项目与养号两空间的调度、续做和取消回归。
- Pi 默认 350K token 的可配置摘要压缩、超大旧会话恢复，以及模型工具清单和公开材料分页。

## Non-Goals

- 其他验收问题、预算策略、模型名单和内容过滤恢复策略调整留待后续。

## Technical Overview

- 在后端按控制代次限制目标；完整验收通过并释放执行后，正常结束 Pi，复用既有排期和清理流程。
- 新目标从干净上下文开始，同一目标连续使用，到配置阈值时分段生成摘要并保留近期完整交互；原文及业务进度留档。

## Context & Decisions

- 两边共用 `ProjectsService`，统一修复；保留原会话、累计耗时、各自计划间隔和账号门禁。
- 养号的完整工程池轮次保持：全部目标通过后，才在后续合法认领时清理重开。
- 用户在实施后明确要求一起修复上下文超限；此增量沿用当前任务，不重复首次 Brief 批准。
- 用户最终澄清为每个新目标全新开场，同一目标内沿用上下文；每次模型请求重建的讨论不纳入实现。

- 用户要求按 token 触发并可配置，默认 350,000；替换前一未部署字节裁剪方案，表单保存后在下一次启动／恢复生效。

## Risks

- 重点验证成功收尾与人工暂停竞争，避免误取消、重复排期或重开已关闭的计划。
- 摘要及续接不能拆散工具调用与结果、丢失持久进度、重放输入或把部分清单误报成全部完成。

## Acceptance

- 两边完成首个目标后均无法在本轮启动第二个，后续自动启动遵守原计划到期时间。
- 失败返工、超时续做、额度等待、人工暂停和两个空间隔离有效。
- 通过 SQLite 与 Pi 管道的本地验证，不调用真实模型或操作生产业务数据。
- 百万级历史恢复及连续工具流的实际请求受边界保护，上下文拒绝只有一次确实缩减后的恢复机会。

## Next Step

- 准备后对当前完整范围执行 Check-All，随后同步规范与提交计划。
