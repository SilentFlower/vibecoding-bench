# V2 子代理慢工具回执与后台进度摘要

## 目标

Claude Code 子代理等待客户端执行慢工具时能持续显示进度，工具结束后在原会话继续，模型续轮执行一次。

## 现场与需求

- R1。v1.38.1 的受管账号在 43 秒的 Bash 完成前已经把工具组登记为原会话退出。隔离的 CC 2.1.293 在单个私有回调约 30 秒时也会提前进入下一步。每段等待采用双方已讨论的 20 秒，结果随到随交付。整组使用原有一小时期限。
- R2。同一个子代理的 24 条辅助请求带有 CC 的官方进度提示。系统设置提供「本地生成子代理进度」，默认关闭。关闭时通过原账号的 V2 模型独立生成进度并返回真实用量；开启时在网关本地生成进度并返回零用量。两种模式均保留工具回执供随后真正的业务续轮使用。普通用户追加文字继续按业务输入处理。启用本地模式时，摘要的 JSON 和 SSE 显式报告零输入、零输出，并沿用可信渠道已识别的本地进度回执。
- R3。等待、重查、取消与过期应保持原主体、账号、会话、进程及工具组的归属。并发子代理各自交回结果。已经消费的回执重复到达时保持原有防重放行为。

## 验收

- 真实 CLI、网关和发送器在隔离上游中完成快速工具和跨多个 20 秒窗口的慢工具。记录上游收到的续轮次数、公开响应与结束原因，核对结果到达即唤醒。
- 在真实回执之前、并发期间及已消费后提交匹配的进度请求。摘要反映工具动作，真实回执只消费一次，普通文字、错误归属及残缺工具组走原业务校验。
- 取消、到期、迟到查询、同轮并行工具及陈旧等待编号有定向回归。晚到的旧查询不能对下一轮产生影响。

## 交付边界

本轮交付账号镜像中的私有回调、网关摘要处理及两者的集成验证。超出一小时后恢复历史执行属于独立能力。发布与生产安装按既有项目流程办理。
