# Brief — 控制台深色模式

## Goal

- 按用户确认的「夜幕紫灰」深色稿给整个控制台加上深色主题，并提供跟随系统 / 浅色 / 深色三种模式切换（父任务 R10）。

## Scope

- 深色稿入库：`research/design-dark/` 同步到 `doc/design/console-v2/`，`mock.html?mode=dark` 成为深色的唯一视觉基准，新增登录终端与色板两个画面。
- 主题运行时：模式存储、深浅解析、深色默认色板与派生规则（中性色、主色、功能色、柔光、阴影）、首帧防闪烁、跟随系统实时切换。
- 切换入口：侧栏底部（含移动端抽屉）的快捷切换按钮；主题设置页「全局」里的模式分段，模式计入草稿并在画板中预览。
- 适配范围：全部 Vue 页（含登录页、组件演示页）、外壳、任务与工程、运行环境、独立 `/runtime/` 文档、弹窗、气泡、通知、调度图表、xterm 终端。
- 收尾：`style.css` 旧变量层改指 token 并删除无引用部分，补齐剩余写死颜色；开关滑块、墨底区块文字改用专用 token；迁移 4 个断言「任务页固定浅色」的脚本；新增 `verify_dark_mode.py`；同步规范。

## Non-Goals

- 高对比度主题。
- 组件级 token 编辑。
- 独立 `/runtime/` 文档应用自定义种子：它跟随深浅，但配色始终是默认主题。

## Technical Overview

- **模式**：存在 `localStorage['flower2api.theme-mode']`，与种子 `flower2api.theme` 分开，种子格式保持 `version: 1`、不需要迁移。缺失、非法或读取失败都按跟随系统处理；保存「跟随系统」时删除该键。
- **首帧**：`apps/web/index.html` 与 `apps/legacy-web/index.html` 的 `<head>` 内联脚本在样式生效前写好 `data-ui-scheme`。`ui-foundation.css` 按这个属性给出浅色或深色默认值，并设置 `color-scheme`。
- **派生**：`createTheme(seed, scheme)` 的深色分支用手调的深色中性色；主色与功能色按规则提亮：实色对卡片底 ≥ 3.2，按钮白字不足 4.5 时改深色字，主色文字 ≥ 5.5。单测断言输出等于确认稿的 `palette.js`。
- **跟随**：`initTheme()` 订阅系统偏好，模式为跟随系统时整组重写变量。侧栏与主题设置页通过 `useThemeMode()` 共享模式。
- **终端**：xterm 配色从 `--ui-color-term-*` token 读取，背景透明，由容器墨色给出底色；切换深浅时已打开的终端无需重建。

## Context & Decisions

- 组件库、外壳和全部页面的样式已只取 `--ui-*` token。剩余工作集中在主题运行时、少数写死颜色，以及只有在深色下才会暴露的取色语义问题。
- **【关键决定】深色色板用「夜幕紫灰」：页面底 `#0f1018`、卡片 `#171824`，与浅色主题、墨色同一色相。实现以确认稿逐值为准，单测断言派生结果等于确认稿 `palette.js`。**
- **【关键决定】默认跟随系统：没有保存过模式的浏览器，包括全部现有用户升级后第一次打开，系统为深色时会直接显示深色，不需要用户自己开启。**
- **【关键决定】侧栏按钮按当前实际深浅切到另一种，并保存为明确的浅色或深色。要回到跟随系统，需在主题设置页选择。**
- **【关键决定】主题设置页的模式属于草稿：画板预览，「保存并应用」后才生效，计入待应用数；恢复默认回到跟随系统。**
- **【关键决定】独立 `/runtime/` 页面跟随所选模式，从控制台进入不会突然变成浅色；配色仍为默认主题。**
- **【重要限制】浅色主题有少量有意变化：终端与代码块文字略亮（`#97a0b2` → `#a7abc3`）、xterm 换成新终端配色（去掉琥珀光标）、请求诊断说明文字加深（`#848894` → `#5f6878`，原值未达 AA）、默认描边色微调。其余浅色画面像素不变。**

## Risks

- **【交付风险】有些取色在浅色下正确、在深色下错误，比如用卡片底色做有色底上的文字色，静态规则查不出来。靠逐页深色走查（含 21 个原生弹窗）加正文对比度抽样兜底，发现后改用正确的 token，不为深色单独加覆盖规则。**
- 在系统深色下运行的验证脚本会开始看到深色。已知 4 个断言「任务页固定浅色」的脚本已列入迁移清单；另有一批按深浅循环、点击已不存在的旧主题按钮的脚本，删除宿主 `data-theme` 后路径与基线相同，不迁移。全量回归中如有新失败，按「是否属于跟随模式的预期变化」逐个判定，不放宽业务断言。
- 开发服务器靠脚本注入样式，会看到闪烁。防闪烁以构建产物为准，在 `DOMContentLoaded` 前断言深浅。

## Acceptance

- 深色下账号、账号编辑、请求、系统更新与进度、任务与工程（含深层弹窗与登录终端）、运行环境、主题设置、外壳与 390 移动端，与深色稿的计算样式一致。其余页面、弹窗、气泡的颜色只取深色 token。
- 深色下正文对其实际底色的对比度 ≥ 4.5；六个预设与边界色的按钮文字 ≥ 4.5，实色对卡片底 ≥ 3。
- 跟随系统时切换系统深浅，控制台、内嵌任务页与独立 `/runtime/` 随之切换。侧栏切换后刷新保持，首帧即为正确深浅，模式存储被篡改时按跟随系统处理。
- 主题设置页改模式后，画板变化、控制台不变、待应用数加一；保存后生效，撤销与恢复默认按约定回退。
- 浅色下既有验证全部通过，失败集合与基线相同（3 个已登记失败）；浅色画面只在登记区域有变化；构建、单测通过，全仓样式无颜色字面量（token 定义处除外），规范与设计基准已同步。
