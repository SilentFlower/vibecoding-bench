# v3 稳定会话绑定、平滑发送与智能调度设计

## 依据与模块边界

- 需求以同目录 `prd.md` 的 R1–R8、AC1–AC10 为准；源码事实与参考差异见 `research/scheduler-comparison.md`。
- 仅接入 v3 Gateway → `runtime_transport` → 账号 sender。原生 CLI、项目、养号及独立后台入口不纳入本轮预算。
- 复用 `Account`、`ApiToken`、SQLx `AnyPool`、SQLite／PostgreSQL、加权 FIFO 和现有 v3 身份验证；增加小型调度服务与存储，不复制参考项目的插件框架。
- 通过现有 v3 运行条件装配新路径；非 v3 保持原行为。采用项目既有的显式依赖装配模式，保留其他调用和测试兼容。

## 改造前基线的锚点

1. `account.rs` 已有 sticky 检查，但 `gateway.rs` 在并发队满／超时后仍排除原账号；需区分“有效但繁忙”和“确实失去资格”。
2. `bind_selected_session` 使用普通 set，没有版本比较；新 v3 绑定必须使用单一持久化事实来源，不能让旧缓存与新表各写一份权威状态。
3. 当前 RPM 按固定分钟计数，且在环境准备前获取；入口限速不能证明环境就绪后的提交平滑。
4. 当前诊断 `ttft_ms` 是响应头到达耗时。新调度复用这一已有口径，明确展示为上游响应头延迟，不扩展首个有效模型输出解析。

## 请求流程

1. 沿用鉴权、Token 范围及解析；首次进入调度时冻结配置快照和一个绝对准入截止时间。
2. 从改写前元数据提取显式会话 ID，按 Token 隔离生成摘要；读取有效绑定并检查现有硬资格。
3. 有效绑定限制到原账号，评分不参与容量迁移。未绑定请求按资格、现有优先级、即时容量及智能／旧评分排序选择候选；无即时容量时只选择可容纳的有界等待位置。
4. 获取现有加权 FIFO 并发许可，排队不扣发送名额。队满或超时返回本地 429；已有绑定保留，未绑定请求也不得无限换队或重置期限。
5. 完成既有凭据、正文冻结和账号环境准备；本地等待使用同一剩余预算。保持账号、环境、generation、release 和请求身份验证。
6. 环境就绪后进入账号发送 FIFO。真正提交前，短事务原子核对／提交绑定并认领当前发送许可。首次绑定冲突不扣预算，释放冲突账号资源，跟随最新绑定并沿用原期限。
7. 获得许可后才启动原 TTFB 期限、提交 `/internal/send`。已有重试的每次实际模型提交都经过该入口，不新增重试次数或条件。
8. 按真实上游结果记录和回灌反馈；响应流沿用现有并发许可生命周期。请求结束不反向覆盖绑定。

### 等待、错误与取消

- 默认总准入期限 120 秒，可配置 1–120 秒；账号、等待层或既有重试变化不重置。环境准备也在预算内，不能再叠加一个独立 120 秒。
- 期限只约束准入过程；已提交的上游调用沿用原 TTFB／流生命周期，不因准入期限经过而中断长流。重试重新准入时检查原期限。
- 本地队满／到期返回现有 Anthropic／OpenAI 可解析 error object、429 和保守 `Retry-After`。无真实提交不记录虚假上游尝试。
- 无合格账号、权限、凭据、硬额度及既有上游响应仍按现行错误分类和返回优先级；不能全部伪装成排队超时。
- 调度状态读写失败返回 503，不失败放行；不因此修改其他功能的旧缓存降级语义。
- 等待位置、并发许可、活动续租登记都有明确租约所有者和取消／Drop 回收。必须用真实 HTTP 断连测试确认取消传播，不能假设客户端断开就会自动取消 handler。

## 持久化绑定

- key 为固定域、`ApiToken.id`、显式会话 ID 的 SHA-256 摘要，不存原始 SID、凭据或正文。
- 沿用现有 Claude Code 元数据的显式 SID 解析规则。无 ID 的普通 API 请求按未绑定请求处理，不把提示词、UA 或小时指纹当作可靠会话。
- 普通闲置有效期沿用 60 分钟滑动 TTL；独立维护循环每分钟按当前版本批量续租活动绑定，防止运行中的绑定被清理。请求 Drop 移除登记，不在响应结束时写回账号。存储恢复后可用活动版本提示做 CAS 续租并重读，提示本身不是权威绑定。
- 重启只恢复有效绑定和最近发送状态，不保存／重放请求体或在途 HTTP 请求。正常环境重建不改变会话到账号的绑定。
- 在现有数据库增加 `gateway_session_bindings`、`gateway_account_send_state`，统一由 `SchedulingStore` 管理；SQLite／PostgreSQL 迁移幂等、原子语义等价。SQLx Any 读取整数统一投影为 TEXT 再严格解析为 i64，避免 SQLite 运行时 INTEGER 被映射到 i32 后截断 UTC 毫秒；表中仍保存非空 BIGINT。
- 会话表保存摘要 key、账号 ID、绑定 revision、首次绑定时间、最近真实请求活动时间、过期时间；发送表保存账号 ID、最近发送许可时刻。账号删除清理关联状态，过期绑定有界清理。
- CAS 版本不能在过期清理／重建后复用而出现 ABA；同版本续租只更新有效期，不制造无意义的绑定竞争。
- 首次绑定与本次发送许可同事务裁决，失败不能扣预算；事务内不等待网络、环境或定时器。
- 容量不足不删除／迁移绑定。真正失去权限、被禁用、硬额度及已有故障排除沿现行策略处理，替换绑定也须 CAS；不引入新迁移策略。
- 审计 Gateway 现有四处绑定：新会话遇到本地 mock／缓存命中不确立“已发送”绑定、不扣发送名额；已有绑定可续期。保留本地响应的正文、状态及缓存语义。

## 新会话准入与智能选择

### 资格和容量先于排序

- 先过滤 Token 允许／禁止范围、状态、排除集、真实有效额度、模型约束；完全没有有界准入容量的账号先剔除，其余沿用人工优先级分组，避免满队列阻挡低优先组。
- 组内优先立即可获取加权并发、无排队压力、发送时间已到的账号；没有即时候选时，只进入有剩余队列容量且预计等待不超剩余预算的账号。
- 沿用普通请求 2 单位、Haiku 1 单位；等待队列上限 `2 × concurrency` 个请求，同级 FIFO 不因请求较轻而越过队首。
- 容量估计辅助选择，最终以真实许可为准。固定等待位置后不因评分抖动来回迁移；竞争失败不能透支容量。

### 智能排序和真实反馈

- 四项统一为 0–1、越高越优：可用负载、有效剩余额度、平滑健康、响应头延迟。负载考虑已占加权并发、排队压力及最近可发送时间。
- 额度只使用有效窗口和 reset 的真实观测；未知／过期中性，不把未知当零用量优惠。5h 不可用时可使用有效 7d，硬门禁独立判断。
- 进程内按账号平滑真实反馈，未知健康／延迟均为中性；重启可重置软反馈。
- 工程初值参考研究仓：普通 EWMA 系数 0.2、上游容量拒绝系数 0.4、失败惩罚半衰期 15 分钟；延迟归一化尺度 10 秒。这些是排序参数，不是官方安全阈值，不新增对应 UI 旋钮。
- 默认权重 1／0.8／1／0.5；归一化总分距最优值不超过 0.05 的候选构成近优集合，按稳定账号 ID 轮转，避免新会话长期集中在唯一极值账号。
- 复用已有响应观察器的完整终态回灌，HTTP 200 内 SSE 错误不能算成功，未知／采样缺失不伪造成功；响应头耗时仍使用真正提交后的口径。只更新一次，本地容量拒绝、取消、用户输入错误和确定的发送前拒绝不降低健康，不新增 SSE 解析器或主动探测。
- `legacy_score` 仅替换新会话排序，资格、持久绑定、等待和平滑发送继续生效。

## 平滑发送闸门

- `rpm_limit > 0` 时最小间隔 `ceil(60000 / rpm_limit)` 毫秒；例如 50 RPM 至少 1200 毫秒。非正值沿用无限制，不积攒空闲名额、不在分钟边界补发。
- Gate 位于环境已就绪、身份校验完成、最终内部 POST 之前。复用 `runtime_transport` 的准备／提交边界，为 Gateway 增加显式受控入口；不向 sender 添加选号逻辑、不新增 RPC、不改变冻结元信息格式。
- 本轮可验证的节奏边界是 Gateway 向 sender 发起提交的时刻，不把内部传输抖动或独立 CLI 流量描述成受控的上游发送间隔。
- 同账号准备就绪的请求进入发送 FIFO，持有许可到实际提交记点；每次仅原子认领当前一个名额，不预订一串未来名额。数据库写锁取得后重新读取当前 RPM 并采样时间；进程内单调时钟从上次许可释放／提交记点计间隔，避免数据库等待或提交准备耗时被提前抵扣。配置保存后唤醒该账号等待者，但不重置请求期限。
- 最近认领时刻在绑定 CAS 完成后、事务提交前保存，重启不能清空节奏；每次生产许可裁决从账号表读取当前 RPM，按新间隔解释最近认领时刻，不使用选号时的旧 RPM。等待不持数据库锁，等待预算用单调时钟。
- 等待请求受既有并发许可和有界队列约束；已认领但提交失败保守消耗名额，提交未知不返还、不重放。
- v3 不再叠加原固定分钟强制闸门；原分钟数如保留展示仅作观测，实际就绪时间取新发送状态。非 v3 保持原规则。
- 本轮不宣称跨实例全局 FIFO／并发配额；数据库 CAS 不等于完成多实例调度。

| `v3_smart_weight_health` | `1` | 同上 |

- 补齐默认、迁移、handler 校验、服务 reload、UI 和测试；旧三权重保留用于旧评分回退。
- 请求冻结配置快照，热刷新不改已等待请求的期限；账号 RPM 在下一次许可裁决生效，不提前透支。
- 管理 API 增加可选 v3 详情：模式、准入／等待原因、下一可发送时间和智能因素。保留旧 `scheduling_score`／`scheduling_detail` 的低分优先含义，不被高分优先智能分覆盖。

- 保持现有请求／attempt UUID 与匿名摘要合同；大正文观察参数在准入前预处理，真正提交时才发布 attempt，未提交草稿丢弃不记假发送。响应头耗时不标成首 token 耗时。

## 发送与当前会话可视化

### 视图与口径

- 账号总览沿现有分页卡片展示：有效绑定会话数、活跃会话数、执行／等并发／准备环境／等发送的请求数、加权槽位、最近 60 秒提交数、配置 RPM 和下一可发送时间；以明确文字说明能否接纳新会话及原因。
- 有效绑定是持久表未过期的绑定；活跃会话是有效绑定中当前有等待／运行请求的不同显式会话 key 数；请求数单独计数，一个会话可以同时有多个请求。尚未确立首次绑定及无显式 SID 的请求计入阶段总数和“未绑定请求”，不生成假绑定会话。
- 沿用已有 `upstream_session_pool_*` 摘要，独立标为“上游 Session 池槽位”，不作为网关会话数，不把池槽位当作官方聊天会话。
- 点击账号打开现有风格的调度详情弹窗：最近 5 分钟的提交时间轴、下一可发送倒计时、当前阶段和等待原因、分页会话列表。仅增加一个聚焦视图，不重做全站样式，不引入图表库。
- 会话列表默认每页 20、最大 100，按最近真实活动时间和摘要稳定排序；显示摘要、绑定账号、首次绑定／最近活动、等槽／等发送／准备／执行请求数及有效期。无等待运行请求时标记闲置；不强迫一个会话只有一个请求状态。
- 时间轴实心点只代表获得许可后真正发起的 Gateway → sender 提交，包括既有重试；下一可发送时刻用虚线／空心标记，表示最早许可时间，不表示已经预订或保证未来发送。取消于提交前的请求不能画成一次发送。
- 旧响应缺字段、采集失败、数据陈旧、事件截断、网关重启后的历史缺口均明确显示，不用 0 或理想等间距点补全。配置 RPM 不标为官方安全阈值，响应头延迟不标为首 token 延迟。

### 只读数据来源与资源上限

- 绑定信息从新 `SchedulingStore` 读取；增加首次绑定／最近活动字段和账号／过期索引，最近活动仅由真实请求推进；管理读取不刷新最近活动或延长绑定，后台活动续租只延长有效期，不刷新最近活动。
- 当前请求阶段由调度租约维护，只保留匿名关联 key、账号、阶段与时间，结束／取消即释放；绑定迁移成功时同步当前绑定标记，旧账号在途请求继续执行但不算该账号当前活跃绑定；同一状态变更一次记账，阶段请求不能重复相加为多个请求。旧 `active_requests` 是已持有并发许可的请求数，不能直接标作“正在上游执行”；保留旧字段，使用明确的新阶段统计。
- 最近事件采用进程内环形缓冲：最多 5 分钟、每账号最多 500 条、全局最多 10000 条，超出淘汰并返回截断提示；账号删除／长期闲置后回收，软反馈及轮转键也有数量上限。最近 60 秒提交统计使用独立有界时间桶，不由截断事件列表倒推。
- 仅绑定及节奏状态持久化；短期事件历史从当前进程启动／采集开始，不承诺重启恢复时间轴。响应携带观测时间、采集起点、完整性／截断信息；观测失败不阻断正常请求发送，也不能被记作账号健康故障。
- 总览按当前账号页批量读取计数，避免每个绑定逐行查询。详情按需加载，不向账号环境、sender 或上游发探测，不扫描正文或完整历史抓包。

### 管理接口与刷新

- 新增只读 `GET /admin/accounts/:id/scheduling`，返回运行快照、短期事件与健康标记；`GET /admin/accounts/:id/scheduling/sessions` 提供有界分页，可筛选活跃／闲置及脱敏摘要。两接口均已接入现有管理员认证。
- 复用现有管理员认证中间件；账号不存在、参数非法、采集不可用分类返回。只返回脱敏会话摘要，不返回原 SID、提示词、凭据或完整 Token；不附带强制切号／清除／取消动作。
- 所有前端请求继续走 `api.ts` 的统一 client。复用账号页 5 秒节奏，详情打开且文档可见时更新，关闭／切页／隐藏后停止额外详情读取；恢复可见时读取新快照。防重叠请求和乱序旧响应覆盖。会话总数缩小时，若当前页已越界，在同一轮读取第一页后再一起更新页码与快照；查询失败仍保留原快照。
- 倒计时根据服务端观测时刻和许可时刻在浏览器本地递减，标明“按上次快照预计”，不增加每秒后端请求；减至零或快照失效后标记待刷新，不能显示确定的“可发”。刷新失败保留最后快照并标为陈旧，不显示为零负载。
- 规划图真源为 `doc/visualize/v3-scheduling-observability.html`；使用静态合成示例说明口径，不能冒充已接入生产的监控页。图模型与源码锚点见 `research/visualization-model.md`。

## 兼容、风险和回退

- 从固定分钟放行变为间隔提交，高峰等待可能增加；环境准备共用 120 秒总预算，冷启动可能更早返回 429。已有绑定保留，客户端可按提示重试。
- 新 key 按 Token 隔离，首次启用不导入无法确认归属的旧缓存绑定，可能有一次重新分配；不能承诺绝对缓存命中。
- 新增数据库热路径，采用键查询、短事务和有界冲突处理；需实际验证 SQLite 锁竞争及 PostgreSQL 原子性。存储失败停止新增发送会影响可用性。
- 原生 CLI、后台独立请求和上游策略仍可能影响账号；本方案不能保证官方账号不会被停用。
- 轻量回退只切 `legacy_score`；完整撤销本轮行为需回到旧构建。新增表增量兼容，旧构建可忽略，不以删库或清空绑定作为回退。
- 本任务交付代码和验证记录，不执行生产发布或线上配置切换。账号删除沿原管理门禁，在同一事务删除账号与新状态，不依赖 SQLite 连接级外键开关；不增加新的管理删除动作。

## 验证设计

- 受控时间验证最小间隔、跨分钟、无积攒、重启、RPM 改动、共享期限和反馈衰减，避免依赖长 sleep。
- SQLite 和隔离 PostgreSQL 验证迁移、并发 CAS、绑定／许可原子回滚、活动续租、清理及状态故障关闭。
- 脱敏本地 runtime／sender 验证真实提交时刻、冷环境同时就绪、重试、断连取消、身份失配、未知提交和 JSON／SSE／压缩字节透传。
- 设置默认／非法值／热刷新及管理端模式／诊断验证；运行后端全量测试和前端构建，不使用真实账号压测。
- 可视化验证覆盖单会话并行多请求、各阶段变更、无 SID、分页／筛选、缺失／陈旧／截断、刷新暂停与失败；证明观察不续租、不消耗发送许可、不触发模型调用。
