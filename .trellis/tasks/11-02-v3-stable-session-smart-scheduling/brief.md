# Brief — v3 稳定会话绑定、平滑发送与智能调度

## Goal

- 老会话稳定绑定，新会话按容量准入，请求平滑发送，并直观看到账号负载、发送节奏和会话状态。

## Scope

- v3 API 网关到账号 sender 的调度链路，以及持久化、设置、账号总览、发送时间轴、当前会话详情和测试。

## Non-Goals

- 原生 CLI、项目、养号出口；第 4、5 项的独立重试／迁移与官方缓存协议改造；长期监控平台、官方聊天记录查询及生产部署。

## Technical Overview

- 显式会话 ID 按 API Token 隔离，绑定持久化并采用版本比较；有效老会话遇到繁忙、队满或超时仍保留原账号。
- 新会话先检查资格、优先级和容量，再结合负载、有效额度、真实健康与响应头延迟，在近优账号中轮转。
- 环境就绪后、向 sender 提交前按账号 RPM 控制间隔；50 RPM 对应至少 1.2 秒，不积攒名额。已有重试也经过闸门。
- 准入共用默认 120 秒截止时间，可向下配置；队满／超时返回 429 和重试提示，保留绑定；调度存储故障返回 503。

- 账号总览展示绑定／活跃会话、各阶段请求数与准入状态；详情展示最近 5 分钟真实提交、预计最早可发时间及分页脱敏会话列表。

## Context & Decisions

- v3 默认智能排序，保留旧评分排序回退；两种排序都执行稳定绑定和平滑发送，并保留现有权限、额度和加权 FIFO。
- 绑定沿用 60 分钟闲置有效期，活动请求续租；重启恢复有效绑定及发送状态，不重放请求。SQLite／PostgreSQL 使用同一合同，不新增强制 Redis 依赖。
- 仅使用真实请求反馈，不发额外模型探测；节奏控制以网关向 sender 提交为边界。
- 会话数、请求数、上游池槽位分别统计；详情复用 5 秒刷新，可见时读取，倒计时在浏览器更新，观察不续租或消耗发送名额。

## Risks

- 高峰等待可能增加，环境冷启动也计入总准入期限，可能更早返回 429；存储故障时停止新增发送。
- 首次启用不能导入归属不明的旧缓存绑定，可能发生一次重新分配；无显式会话 ID 的请求不承诺稳定绑定。
- 保持账号连续性不能保证每次命中缓存或官方不封号；独立 CLI 等流量不受本轮预算约束。
- 近期时间轴为有界进程内观测，重启有历史缺口；未知、陈旧和截断明确展示，不补造数据或未来预订。

## Acceptance

- 验证并发首次绑定、Token 隔离、繁忙／超时不迁移、重启恢复及取消无资源泄漏。
- 验证跨分钟、冷环境同时就绪、重启及既有重试均不集中提交，本地拒绝不污染上游健康。
- SQLite／隔离 PostgreSQL 行为测试、后端全量测试、前端构建和页面验证通过；权限、身份、缓存协议及原始流字节合同保持。

- 可视化准确区分单会话多请求与各阶段，管理员鉴权、分页、隐藏暂停刷新、异常提示及只读无副作用验证通过。

## Next Step

- 确认后进入实现，先完成调度存储、绑定竞争和发送许可的原子裁决，再接入网关与管理端。
