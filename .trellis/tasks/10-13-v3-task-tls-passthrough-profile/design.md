# 修复设计

## 额度采样

v3 的 QuotaGuard 复用现有 usage 查询及标准化合并，不新增数据库表或任务队列。账号 owner 锁串行采样，近期缓存覆盖重复启动；查询失败设置短重试间隔并发布脱敏原因。只为启用阈值且有待运行工作的账号自动查询，避免空闲账号常驻唤醒。

调度器在普通/养号启动前和完整收尾后调用自动刷新；tick 对额度等待且空闲的账号刷新，涵盖尚未生成 run 的批次。v3 普通/养号使用同一判定，未知额度等待自动采样，不领取持久模型请求 admission。旧 runner 保留原行为。阈值约束执行边界，不承诺精确消费上限。

生产 usage 的空闲 0% 窗口可返回过去 reset 或 null，直接记为新的空闲事实，不造未来时间。v3 接受近期的 manual/automatic 空闲观察，消费、重启、缓存过期仍重新采样；活跃窗口清掉旧空闲标记，非零旧窗口不放行。

查询仍认领空闲 CLI 作业以保护凭据与维护，但保留当前 passthrough 监听，不重启网络。GET usage 有界超时，不自动重放 HTTP 失败；合并数据后正常释放作业。绑定先同步 AT，未绑定先使用现有刷新者取得有效 AT，查询自身不建立第二条刷新链。

## 画像与绑定

校正的空闲检查保持，成功状态为 stopped，不要求重授权。启动对账和 ensure 兼容原 profile_reauth，转换为正常生命周期；原 profile_reauth_reconcile 只转为 reconcile，不绕过提交/执行未知。旧 profile v2 与 HOME 不旋转。

养号启用不强制绑定；仅选定或已经绑定时核实 cc2api。未绑定的触发、claim、结束和 tick 使用 NULL 安全比较，凭据同步函数按既有无绑定路径返回。

持久 HOME 的新任务在创建专属项目目录时原子保存该 cwd 的信任确认，保留账号身份及其他项目设置，避免未完成首屏引导时吞掉原题。不扩大到外部目录；生产任务验收观察真实会话响应或工具调用。

v3 生成兼容 driver 时移除无消费者的内部时间戳 Stop hook，完成仍使用现有主会话 JSONL 判定，避免 UID1000 向私有 runtime 写入失败而把错误反复交回 CLI。控制目录权限保持原边界。

CLI 准备在环境锁内合并 HOME settings.env.DISABLE_AUTOUPDATER=1，其他用户设置保留，CLI 精确版本仍由管理端负责。

v3 启动收口旧执行并完成管理器初始化后，复用 Scheduler.submit_batch 恢复仍启用账号的 active 批次；新线程先等待保存的 next_launch_at。只投放既有 pending/paused item，不重新执行终态项，不恢复用户暂停、删除或停用的批次。

## 页面与部署

批次公开同账号 normal 策略摘要作为实际等待原因；run 和批次页面显示自动查询错误和下次重试时间。环境维护提示取消“必须重新登录”，历史状态有兼容说明。终端维持已修复的双通道交互。

部署 up 只对自有 gateway 的精确端口映射放行，其它容器仍算冲突；同批镜像与 labels 核对保持。RAM 额外余量改为可配置默认 256 MiB，显式最低内存仍可提高门槛。

本次管理员密码沿用用户指定值，部署预检的 32 字符要求阻碍启动；用户明确要求关闭后，本次直接用既有 Compose 配置启动，备份、镜像一致性及旧服务核对仍实际执行，不改密码。

停机快照排除无法复制和恢复连接的 Unix socket，其他文件及符号链接照常保存，SQLite 仍走 backup API。部署失败时先恢复 v3 服务并保留修正，不触碰旧服务。

## 验证重点

验证无人值守跨 reset、低额度缓存消费后更新、零 run 批次、自动查询失败恢复、未绑定养号、原 profile_reauth、原生 TLS 查询、自己的端口重复 up、全局运行配置与原 run 快照。合成测试证明状态流，不能替代真实 OAuth；真实认证失效时明确报告。
