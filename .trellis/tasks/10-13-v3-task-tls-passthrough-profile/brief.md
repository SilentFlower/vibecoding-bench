# Brief — v3 原生 TLS、自动额度恢复与环境修复

## Goal

固定账号环境继续使用原生 TLS，额度阈值可无人值守运行，解除不必要的画像重授权和账号绑定限制，并提供准确的等待原因。

## Scope

- 保留已交付的固定 HOME、profile v2、原生 TLS、控制文件隔离和完整交互终端。
- v3 普通任务、批次和养号在执行前后自动查询 usage；未知、过期或查询失败时后台有间隔重试，额度达到阈值才等待恢复。
- 查询使用账号容器的原生 TLS，不启动或切换 MITM；运行中 CLI 完整收尾，阈值约束后续执行。
- 环境校正保留凭据并恢复可用状态；兼容已部署的 profile_reauth，实际认证失败才提示重新授权。
- 有有效本地 OAuth 的未绑定账号可定时养号；绑定账号仍由 cc2api 唯一刷新凭据。
- 批次和 run 展示具体的额度/环境阻塞原因；启动工具支持重复 up 和可配置资源余量。
- 回归全局模型、effort、CLI 版本在固定环境中新 run 的生效行为。

## Decisions

- 2026-10-13 用户在过度设计审查后明确要求“修复”，授权按已展示修复方向更新当前单一任务并实施。
- 正常运行使用 passthrough，显式抓包使用 capture；quota 模式保留旧格式兼容，不再用于 v3 日常查询和养号。
- 原“未知时一次正式养号请求”在 v3 中由只读 usage 查询取代；旧 runner 保留原规则。
- 实际额度耗尽、认证错误、停止/删除、未知凭据提交和代理出口保护继续优先。
- 2026-10-14 用户要求关闭本次启动检查：部署改用现有配置直接运行 Docker Compose，保留既定管理员密码；镜像、备份和旧服务隔离按实际结果核对。
- 2026-10-14 用户要求关闭 CLI 自动更新：使用官方 DISABLE_AUTOUPDATER 标记，CLI 版本继续由全局运行配置和管理端缓存决定。

## Acceptance

- 无需人工查询，未知/窗口过期的单任务及零 run 批次自动采样并恢复；高用量继续等待，失败不产生模型请求或查询风暴。
- 执行后更新真实用量，下一任务命中阈值不运行；普通任务及养号不启用 MITM。
- 已校正画像保持不变，原凭据无需人为重登；真实认证失败仍要求重新授权。
- 未绑定养号、终端键盘/粘贴、全局运行配置、幂等 up、旧服务隔离通过回归。
