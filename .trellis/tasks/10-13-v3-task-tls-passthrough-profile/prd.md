# v3 原生 TLS、自动额度恢复与环境修复

## 目标与修订来源

让固定账号环境正常运行且可无人值守使用额度阈值。2026-10-13 用户在完整过度设计审查后要求“修复”；本版替代原手动额度门禁、强制画像重授权及 v3 养号单次探测规则。此前交付历史保存在 Git，当前仍是一项单任务。

## 需求

- R1：普通任务、批次、养号、登录及本地刷新使用账号原生 TLS；完整抓包显式使用 MITM。查询 usage 在同一账号容器原生发送，只解析返回 JSON，不切换网络监听或注入 CA。
- R2：启用阈值时，执行前自动获得近期真实额度；执行后自动刷新；窗口过期或查询失败由后台有间隔重试。并发启动复用同账号采样，查询失败保持等待并显示原因，不能把未知数据当作 0 或发模型请求探测。
- R3：5h/7d 任一启用窗口达到阈值时阻止下一执行；运行中 CLI 完整收尾。更新为低用量或关闭阻断阈值时沿原 run/批次恢复；停止、删除、身份变化和认证异常优先。新策略作用于 v3，旧 runner 继续兼容。
- R3a：v3 服务重启后恢复仍启用账号的活动批次，保留已保存的投放时间和 item 状态；暂停、删除、停用及已结束题目不被重新执行。
- R4：profile v2 首次随机并固定、时区 locale 配对、HOME 和控制文件隔离保持。显式校正保留原凭据并正常启动，不强制重新登录；兼容旧 profile_reauth 持久状态，真实认证失败才要求重授权。活动作业、未知登录提交和归属冲突不被迁移绕过。
- R5：未绑定账号持有有效本地 OAuth 时可以定时养号；绑定账号仍由 cc2api 唯一刷新。阈值保存不隐式改绑；账号身份切换不能复活旧工作。
- R6：终端完整键盘与粘贴交互继续可用，独立授权码框只作辅助。批次与 run 清楚展示阈值命中、自动查询等待、查询失败/重试时间、环境不可用及实际认证错误。
- R7：同一部署重复 up 可更新自己的服务；外部端口/目录/网络冲突仍拒绝。资源余量可配置，不能靠日常绕过工具上线；默认资源限制和 swap 校验保留。
- R8：固定容器不冻结全局运行配置。新 run 读取 CLI 版本和 effort，模型按第一次启动的配置固化；已运行或恢复的 run 保留快照。旧服务、cc2api 上游协议和用户已有未提交改动保持。

## 验收

- A1：未知/过期的单任务、零 run 批次自动查询后运行；查询高于阈值保持等待，失败在间隔后自动恢复，重复调度无查询风暴。
- A2：真实 usage JSON 与原生 TLS 证明查询不经 MITM；任务结束用量上升后下一 run 不启动。正常养号不进入 quota MITM。
- A3：profile_reauth 兼容恢复保留全部画像/HOME；忙碌、未知提交、认证异常仍受保护。
- A4：未绑定养号完成定时创建、执行、结束与再次调度；绑定刷新所有权和取消/停止回归。
- A5：API 与页面呈现具体等待原因；全局配置新 run 生效、旧 run 恢复不变。
- A6：重复 up、自己已占用端口、外部端口冲突、内存余量配置及同批镜像检查通过。
- A7：后端、部署、账号镜像、浏览器与隔离 Docker 验证通过；部署阶段验证旧服务容器身份不变。
