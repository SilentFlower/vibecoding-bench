# 多平台账号与授权接入设计

## 1. 边界与兼容决定

本任务在现有 gateway AccountService、OAuthFlowService、账号存储及 Accounts.vue 上增加平台适配。用户已确认 CC 的现有接口、凭据返回和调用方保持兼容。浏览器凭据回传收口另行讨论。AGY 独立账号与工程、养号交互属于范围外。

实际源码定义及锚点见 `research/current-contracts.md`。下文的新字段、表和内部路径均为本任务拟新增合同，实施时先核对实际定义及消费者。

## 2. 平台与数据合同

### 2.1 账号平台

- 在 Account、创建 DTO、存储投影及前端类型增加 `platform`：`claude_code`、`antigravity`。新建和生成授权链接省略时使用 `claude_code`，历史行追加同一缺省值。
- 按 ID 的读取、更新、刷新根据已存平台分派；平台在创建时确定，跨平台修改拒绝。模型名称继续单独表达。
- 账号列表扩展可选 platform 筛选：未提供时保持 CC 视图；`all` 用于新管理页全部平台；明确的平台值精确筛选。筛选进入 SQL 计数与分页，缺省旧内部调用继续取得 CC 账号。
- 同平台邮箱去重沿现有邮箱比较语义，增加平台维度。允许同邮箱跨平台独立账号。新登记步骤校验历史重复数据，再建立 `(platform,email)` 唯一约束。历史重复异常报告冲突明细的脱敏摘要，由显式处理解决。
- 未知输入拒绝。未知存量值保持可见并阻止平台操作；读取不得将未知值默认为 CC 后发出请求。

### 2.2 权威凭据与操作元数据

- AT、RT、expiry 继续使用 accounts 的既有权威列。AGY 原生文档在管理适配边界转为现有毫秒时间合同，必要的非秘密原生元数据单独有界保存。
- AGY 增加按账号关联的持久凭据操作元数据，拟使用 `account_credential_states`：account_id、generation、phase、operation_id、更新时间及有界恢复来源标识。该表保存状态和回执，不保存第二份权威 AT/RT。
- 阶段为 ready、refresh_pending、reauth、reconcile。该状态只用于新增 AGY 管理操作；CC 现有 ownership 协议和刷新路径保持原语义。
- 重用现有账号刷新锁、CredentialGate、原子事务和凭据 CAS。CC 的 environment/bench/UUID 交接证明继续服务原有 CC 场景，AGY 使用真实已认证身份及账号归属。
- 增加账号布尔字段 `agy_system_prompt_homoglyph_enabled`，数据库及 DTO 缺省为 false。AGY 页保存回读，文本生效由同形体任务承接。

### 2.3 迁移

新增独立 gateway 迁移步骤及纯定义模块，承接当前 version=4；同步 registry、执行及结构校验分支、冻结源映射和兼容演练。SQLite 与 PostgreSQL 均实现新增结构。已发布基线和先前步骤摘要保持固定。原账号 ID、绑定、画像、代理、策略和凭据逐项比对。

## 3. 沿现有授权接口分派

### 3.1 对外入口

| 现有入口 | 扩展合同 |
| --- | --- |
| POST /admin/oauth/generate-auth-url | 增加可选 platform，缺省 CC；沿现有代理选择及修订校验；重授权场景可绑定目标账号 |
| POST /admin/oauth/exchange-code | 继续提交 session_id、code；由服务端会话冻结的平台及目标选择处理，拒绝跨会话回填 |
| POST /admin/oauth/generate-setup-token-url | 保持现有 CC 能力；AGY 不支持此认证方式时明确拒绝 |
| /admin/accounts 的增删改查 | 增加平台及账号策略字段，保留原 CC 载荷和凭据返回兼容性 |
| /admin/accounts/:id/usage、test | 按已存平台分派，AGY 只使用实际原生能力；验证操作模型提交为零 |

GenerateAuthUrlResponse 继续提供 auth_url、session_id。ExchangeCodeResponse 保留当前 CC 字段和时间单位。AGY 结果转换到相同保存流程，扩展平台和有来源的能力元数据。AGY UUID/组织字段采用实际来源的缺省语义，真实身份核验以已认证账号状态为准。

授权会话继续采用现有 TTL，冻结平台、代理指纹、会话身份和目标账号。平台切换或关闭窗口取消原会话；对新增原生进程补充受控结束入口，并在 TTL、重启恢复时清理本次资源。既有 CC 请求无需提供新增参数。

### 3.2 原生 AGY 适配

OAuthFlowService 的平台分支通过既有受信 runtime_bridge 调用受控 AGY 原生登录驱动。拟新增内部 AGY 授权控制入口，仅接受管理侧服务认证，沿现有内部 HTTP 客户端、配置和超时规则。

驱动使用固定 AGY 1.5.9 原版及已验证 OOB 环境，独立私有 HOME、工作目录和原生 PTY。它从原生终端取得 Google PKCE 链接，将用户提交的授权码回填同一终端。驱动核对 HTTPS、accounts.google.com、S256、原生 callback 白名单和会话归属。授权码投递幂等且有界，未知投递结果先查原会话。

认证完成后先核对原生文件权限、字段、带时区 expiry，再以 AT-only 新进程取得已认证账号状态。原生账号身份、会话目标和创建/重授权载荷保持一致。手工导入 AGY 凭据使用同一已认证状态核验。私有材料仅通过受信内部管理通道传递，普通日志和终端摘要脱敏。

认证驱动与固定制品随现有 account 镜像交付，复用既有构建 staging 及版本身份核验。该任务包含最小授权/刷新依赖准备。制品或内部能力缺失时返回未就绪，已有 CC 功能沿原路径提供服务。原版二进制不进入源码 Git；正式 AGY 请求内核及 worker 池由下一子任务实现。

## 4. 刷新、重授权及持久恢复

1. 通过现有 AccountService 刷新入口识别平台，AGY 在账号排他锁与准入门禁中重读当前账号和操作状态。
2. 新操作先持久化 refresh_pending、原代次及 operation_id。该阶段阻止第二个刷新者，即使短期缓存锁失效也不能重发未知 RT。
3. 唯一管理 helper 在本操作私有 HOME 内消费完整 RT，按同一代理配置运行固定原生目录/状态入口进行刷新。普通业务副本仅消费 AT。
4. helper 超时、停止及管理 HTTP 截止统一有界。成功结果按原账号、平台、代次、操作和原凭据条件，在同一事务提交 AT、新 RT（如返回）、expiry 及新代次。
5. 回复丢失、提交失败或状态未知保留同操作的私有恢复材料并进入 reconcile。已 rename 的新 RT 保持当前材料。恢复按原操作核对，历史快照只用于溯源。
6. 重授权绑定原账号并经过同一门禁及 CAS，先排空相应管理操作。身份冲突、旧页面及迟到会话拒绝；普通配置更新只写本次明确变更字段，保留并发刷新的凭据。
7. 重新授权成功后原生登录进程结束，完整 RT 回到唯一管理所有者。新 worker 采用新代 AT、旧 worker 在途保留的业务行为由运行环境任务接入。

## 5. 能力展示与平台隔离

- CC 的套餐、5h/7d 额度、遥测、预热和 Setup Token 沿现有适配。
- AGY 套餐、分级、模型及额度只来源于实际已认证状态及原生目录。保留原字段、来源、更新时间和未知标志，逐项核对字段含义；GetAvailableModels 全量 catalog 不直接等同账号可用模型。
- 额度未提供时展示未观测，真实零单独表达。AGY 页面按实际能力呈现，CC 的窗口及遥测选项不套用到 AGY。
- CC 账号选择、usage_poller、TelemetryService、native 预热和旧内部凭据绑定入口补平台守卫。按平台分派的平台无关管理接口可使用 AGY；CC 专用入口对 AGY 受控拒绝。
- 本任务完成时 AGY 可管理和授权，正式模型服务处于待运行环境接入状态。旧业务调度选择 CC；模型名不能替代平台判断。

## 6. UI 及异步生命周期

平台筛选采用工具栏紧凑布局，保留无障碍标签。桌面与状态按钮同高对齐；窄屏平台与搜索在首行，状态按钮独占下一行。切换平台时沿用当前状态和搜索，页码回到第一页。

Accounts.vue 继续使用现有卡片、详情工作区、授权弹窗、ChoiceSelect、NumberInput、InfoTooltip、分页和反馈。新建账号及授权流程增加平台选择；编辑展示已存平台。列表增加平台筛选，新 UI 显式请求 all 或指定平台。

授权 generate/exchange/done 步骤及保存手势复用。前端冻结平台、账号、会话和代理上下文，平台切换、关闭及卸载使旧 generation 失效；授权结果只应用到原目标。定时读取保持数字草稿、焦点和未保存内容。

同形体开关位于 AGY 账号现有配置区，默认关闭。保存只提交对应账号的字段差异，旧回执及另一个账号的草稿保持隔离。后续文本任务将消费此字段及冻结策略。

## 7. 验证与回退

- 单元及存储测试使用合成凭据、临时数据库、回环服务和可控原生驱动替身，覆盖两个平台、未知值、并发、故障及重启。
- 浏览器验证使用实际构建和合成 API，覆盖 CC 原载荷、AGY 授权保存、平台筛选、两账号开关、代理修订、取消/乱序、390px 与桌面。
- 隔离集成验证运行真实管理 HTTP、数据库和受控驱动，核对账号权威状态、唯一刷新、旧回执及返回。合成成功与真实原生授权分别报告。
- 真实 OAuth 使用独立私有测试副本。本轮用户明确取消人工验收前置，后续运行环境任务或发布执行方在具备授权账号时补验。模型提交预算为 0；此前研究的 8 次预算保持原记录。
- 回退保留当前平台、账号、权威 AT/RT 和操作日志。旧程序与新平台记录的兼容性通过升级/旧读写演练核验；兼容门禁拒绝会误用 AGY 记录的旧版本。上线及生产回退单独授权。

## 8. 实现合同补充

- 关闭 AGY 链接生成窗口时使原回执失效，并保留有界生成请求，以便取得原会话身份后立即调用取消入口。新窗口保持自己的平台和代次。
- 手工凭据编辑通过内部 prepare 操作先持久保存候选。有效候选采用 AT-only 核验，到期候选按第9节执行同操作受管刷新。未知回复使用同操作回执恢复，避免仅有内存候选时留下待核对死路。
- 操作元数据实际采用 `account_credential_states(account_id,generation,phase,operation_id,updated_at_ms)`，凭据继续只向 accounts 权威列提交。提交确认丢失后按同操作、新代、AT、RT 和有效期读取已提交事实。
- 管理入口补充 `POST /admin/oauth/:session_id/cancel?platform=antigravity`、`GET /admin/accounts/:id/agy-credentials`、`POST /admin/accounts/:id/agy-credentials/recover`。恢复读取原生同操作当前私有文件，身份与代次一致后提交。重授权错账号保留原账号凭据；明确结束旧原生操作后允许由 reconcile 发起新重授权。
- 新列表响应附加 `account_counts`，计数采用当前平台范围。AGY 只附加 `credential_state` 与实际能力，旧 CC 专用调度投影沿原入口。
- 原生驱动为 `services/orchestrator/agy_auth.py`，由既有内部服务鉴权保护。原生授权 TTL 为 30 分钟，生命周期清理每 30 秒运行并在重启后立即检查。关联账号的未知材料继续保留。
- 固定原版制品由构建环境 `V3_AGY_AUTH_ASSET` 提供，完整大小与 SHA256 校验后冻结到本次快照。省略时 account 镜像声明 AGY 能力未就绪。原版文件保持私有。固定宿主源码包同步包含 agy_auth.py 的构建依赖。
- control 镜像声明 `vibebench.account-platforms=1`。受控切换在写入目标组合前检查当前 gateway SQLite 的平台记录；存在新平台或未知平台账号时，旧版 control 镜像受到阻止。实际宿主执行器升级沿独立部署授权执行。
- 自动证据与原生验收的状态记录在 `research/implementation-validation.md`。

## 9. Check-All 四项修复

- CHK-001：账号组件内容身份绑定经校验的 AGY 制品是否可用、固定版本和完整摘要。旧清单缺少该字段时按未提供制品兼容读取。
- CHK-002：新建账号原子保存能力观测。凭据换代时将对应能力和代理与凭据、代次放在同一事务，重授权返回沿原 DTO 扩展可选能力字段。
- FBK-001：缺失驱动操作在账号锁与操作锁内建立持久终止记录，再解除网关原代次门禁。迟到的原操作被该记录拒绝。明确重新授权前先终止同归属旧操作。
- FBK-002：代理切换遇到期 AT 时，在同一候选操作内用新代理运行唯一原生刷新，恢复读取该操作的当前材料。代理、凭据和能力原子提交。普通手工有效凭据继续采用 AT-only 核验。
