## 准入及设置

- `AccessPolicy::check_user_agent` 已先检查禁止区间；目标区间无需改动语法解析器。
- 当前 router 在校验前覆盖用户提交的允许范围，随后画像/账号事务和剩余设置分别写入；须保留客户端模式显式范围，并将本次设置及四项账号软件环境同步放入同一事务。
- gateway 当前分别锁定准入与画像配置；入口检查和冻结之间存在切换窗口。准入和选择配置应合为同一快照，两个请求入口在同一读锁内检查再选择，重试仍复用已冻结画像。
- 账号模式继续采用所选画像的允许范围；客户端模式切换默认回退时不能把已放行 293 的范围压回 280。UI 中客户端模式允许范围可编辑，账号模式保留画像范围行为。
- 保留已有软件环境批量同步语义、设备身份及容量；新增方法注释明确事务与参数，不在 handler 编写 SQL。

## 请求和端点

- Haiku 标题旧结构为 32000/disabled，新结构为精确 Haiku 5.5、128000/省略 thinking/title schema；私有 beta 分类应读取画像，公共标题识别继续支持旧结构及新结构。
- API mimicry 的 Haiku 主请求补齐逻辑已经排除结构化标题；新结构识别需要同时覆盖该分支。
- 默认 SDK 常量被 280、260、257 的 identity 共用；新增默认 SDK 时必须把三者固定到 0.112.1。
- Opus 293 的普通及 Auto/Plan 样本显式携带 context-1m，其他三模型没有。静态基础 beta 不强制启用该能力；精确 safeguard 分支需要保留客户端已携带且通过账号白名单的可选 token，不能因精确 beta 覆盖丢掉这一已观察字段。
- 293 的字段顺序独立登记，fallbacks/safeguards 位于 output_config 前、thread 位于 diagnostics 前；旧版本顺序表保持原值。缺失 thread 时不猜测父响应身份。
- 293 CCH 与 280 相同，线程续轮保留当前入站后缀；不给 run/model 建立后缀缓存。
- 后台端点交叉核对见 `endpoint-contracts.json`，仅包含已采到常量。293 的 remote eval、penguin、MCP 不可复用 280 的 UA；grove 与 bootstrap 也按精确路径处理。
- 本轮原始抓包仅留远端；21 轮受限目录/文件权限审计为 42 个目录、147 个文件，权限偏差为零。
