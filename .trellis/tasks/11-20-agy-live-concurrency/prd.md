# 反重力账号并发上限在线调整

## 目标

管理员可以在账号使用期间保存并发上限，新增容量对应真实可用的发送器执行容量，已接单请求继续运行。

## 现状

从 3 调到 4 时，账号卡片显示 3 个并发被占用、1 个请求排队。保存返回 `account runtime is busy`。反重力把修改并发上限视为运行环境变更，要求空闲后停止并重建环境。Claude Code 的普通配置更新已支持原地调整网关队列。

- `services/gateway/src/handler/router.rs:1441` 附近的反重力保存分支将代理或并发变化纳入维护。
- `services/gateway/src/service/account.rs:1045` 网关普通配置热更。
- `services/orchestrator/agy_environment.py:26` 发送器进程池及内存配置。
- `services/orchestrator/agy_runtime/supervisor.py:386` 发送器物理进程上限。

## 要求

- 从现有账号编辑入口保存。对仅涉及容量的运行时变更，保留现有环境代次、运行中的请求和工具回填。代理真实变更继续走原维护流程。
- 扩容以发送器及实际资源可兑现的容量为准。缩容后新准入遵守新值，已接单请求自然收尾；资源不足时展示具体限制。
- 新建、停止和重启后的环境从已保存的并发配置准备。回包丢失或操作中断后，可通过原操作结果和实际生效状态恢复。
- 部署中仍运行旧发送器时，明确显示在线调整所需的运行时能力及升级提示，保持当前容量和请求。
- 本机先完成闭环。远程账号的归属解析与同一能力的联合验证由[节点迁移](../11-20-agy-node-migration/prd.md)接续。工具等待占槽另有[验收范围](../11-20-agy-tool-wait-capacity/prd.md)。

## 验收

- 3 个请求占用且有排队时，可以把 3 改为 4，排队请求可以使用新增的逻辑及物理容量。
- 4 改为 3 时，既有请求及工具回填自然收尾，新的准入遵守最新上限。
- 有限内存和进程数预算可兑现时支持在线调整。资源不足、并发编辑、应用回包丢失和控制重启后核对网关已保存值、实际容量和在途结果。
- 从账号卡片保存并查看生效值，核对原进程身份、代理、凭据及账号归属。本机与远程按父任务的联合场景验收。
