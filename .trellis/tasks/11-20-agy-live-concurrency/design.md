# 反重力并发在线调整设计

## 现有入口

- 网关 `update_account` 将代理或并发的变化交给 `config_permit`。该入口在队列或运行时有活动时拒绝，空闲时调用 AGY 的 `quiesce` 停止角色。普通网关配置已有 `AccountQueue::adjust_capacity`，它按原队列收回空闲许可并让已占用许可自然归还。
- `update_agy_fields` 在原凭据锁内读取和校验账户差异。实际代理变化、凭据操作及容量变化应分别识别，兼容账号编辑表单提交的未变字段。
- `agy_environment.transport` 使用网关配置计算期望的发送器布局，并比较现有 `sender.json`。`Supervisor` 用其 `max_workers` 控制普通启动、恢复和模板预热。Docker 角色创建还以同一上限计算发送器的 PID 限制。容量写入需要让这些读取路径一致。

## 生效顺序

- 容量编辑沿原网关管理入口、账号锁、系统维护准入和已归属环境的受信控制通路。在环境锁内核对账号、环境代次和当前生效值。创建和传输准备继续读取同一已保存配置。后续节点迁移提供跨节点的同一容量操作入口。
- 扩容先用 `sender_config` 和 `isolated_account_limits` 校验现有预算。有限环境沿原 `512 + 256 × 并发` MiB 的发送器分配、CLI 最小预算及原角色 PID 公式。在线变更与原角色实际额度逐项核对。只有已安全分配的容量才允许网关开放给排队请求。资源不足或无法安全划拨时，保留原可用容量并返回具体原因。
- 缩容先收紧网关新准入，发送器降低新分配的上限。业务执行和待回填 worker 保留到收尾，空闲实例先回收，内存与 PID 额度在缩减安全时收敛。预热、恢复及进程复用共同遵守新分配规则。一个有效基础热进程和 120 秒空闲回收策略仍由进程池管理。
- 网关保存与节点应用跨进程，按同一操作记录已验证值和进展。配置写入复用原有原子写入通路。保存失败时恢复原容量，回包未知时先读实际配置、角色额度和发送器回执。并发编辑、重启与回滚沿同一账号和环境代次收敛，迟到响应不能覆盖较新的配置。
- 未准备的账号与已停止的环境保留其生命周期状态，下一次准备按新值核对角色预算和发送器配置后才开放业务。控制组件与旧发送器混合时，根据实际发送器能力识别能否在线应用。

## 操作记录

- 受信编排接口用同一个操作 ID 准备和收口。网关原账号 `concurrency` 是最终期望值。环境的私有 `runtime/agy-capacity.json` 保存原账号、环境、代次及两端容量，覆盖 Docker 已生效但响应丢失的情况。
- 网关仍持有该操作时，周期检查保留准备好的容量。结束后按网关持久值收口。同一代次的受控容量差异允许继续使用原绑定，原代理和内核仍需匹配。缩容时实际占用较高可暂留原角色额度，监督器已经执行新上限。
- 发送器通过当前配置和代次核验容量指令，更新原监督器的工作池。CRIU 沿当前资源预算选择，额度不足时停止分配已停驻模板，已接单进程自然收尾。
