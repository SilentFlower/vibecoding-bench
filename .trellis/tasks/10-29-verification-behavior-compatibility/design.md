# 技术设计

## 边界与现有入口

`ProjectsVerification.__call__` 按修改范围 → 当前业务观察 → 完整原生回归 → 历史目标 → 独立模型评审 → 候选摘要复核推进。当前阻断位于原生回归的元数据比较。业务观察器也有与实现细节绑定的独立问题，复用既有受信来源适配，不新增评审框架。

主要文件：`orchestrator/project_verifier.py`、`orchestrator/project_native_regression.py`、`orchestrator/projects_verification.py`，以及任务审计已核实的项目 `verification/` 副本。相关类/方法和既有适配测试已读取；后续添加字段或接口前仍核对实际定义。

## 原生元数据的语义比较

- 原始子测试记录继续完整归档，包含 ordinal、上下文和结果；不原地排序、删除或重写原始证据。
- 对完整列表形式的原生子测试合同，按父测试、阶段、上下文和结果比较多重集合；忽略执行序号和列表枚举次序，保留重复条目的真实次数。这里处理测试运行元数据，不改变 `_same_json` 对真实业务数组的比较。
- 用同一比较函数计算是否满足合同与 `subtests_match_contract`，避免执行通过但报告仍显示不匹配。
- 对已经使用摘要格式的合同遵守其原格式；现有 SQLGlot 规范化和字面量保护保留，不从不可逆摘要猜测新的比较结果。
- more-itertools、pyparsing、wrapt 的已核默认 repr 地址按父测试和参数位置限定归一化。优先依据稳定的类型/函数身份与具体形态，不用全局 `0x...` 正则改写任意字符串。未知表示保持精确比较并提供可定位事实。
- 原生跳过清单按身份、原因和重复次数比较，忽略枚举次序。保留原因，不能把依赖缺失引起的跳过变化伪装为通过。

实现可用一个标准库共享模块承载比较规则，由当前回归器与冻结适配器共同调用；不另建策略配置系统。临时只读输入中像 `project_runtime_policy.py` 一样提供受控依赖，来源不能取自候选。

## 业务观察器修正

- Palette：改由实际 Mapping 接口、输入/输出副本、别名和独立实例验证不可变与隔离，不要求 `_colors`。
- Bibtexparser 未知规则版本、Click 软链接拒绝：只在对应无效输入检查点接受合理的参数或文件拒绝异常，同时验证正常输出及无副作用。不得用 `except Exception` 让 AttributeError/NameError 等开发错误充当合法拒绝。
- 对 `inventory.json` 中其余异常分支、私有字段和具体类型检查继续逐项归因；公开合同/示例或原生兼容明确要求的检查保留，确定没有行为依据的条件才修正。待证条目在审计中明确标识，不把静态扫描当作动态验收结论。
- 每个修正点须具有原版、参考、合理替代、真实错误的验证矩阵。未公开的表示差异不通过新增公开要求追认。
- 续查修正 Liquid 的 `_cache` 字段依赖，通过公开模板对象的命中、LRU 淘汰及更新前后输出验证原需求；不引入新缓存语义。

## 冻结报告的有限预算

more-itertools 原冻结子测试 JSON 已约 4 MB；固定 2 MiB 上限与 Docker 日志轮转会使准备标记丢失。原生回归的结果预算取 `max(2 MiB, min(16 MiB, 冻结合同字节数×2+64 KiB))`，日志再为 JSON 转义保留两倍及 64 KiB 空间；业务观察仍沿原 2 MiB 预算。可信回归超出该上限属于环境错误，不算候选业务失败。

## 历史冻结兼容与未来内容

- `_native_regression_adapter` 和 `_native_contract_observer_adapter` 沿精确项目、脚本、参数、路径、expected 及 SHA256 识别已知来源，构建临时可信执行字节；未知来源仍是验收环境错误。
- 不批量覆盖 45 种冻结回归器，不改历史合同、已封存脚本、候选或结果。受影响未来源码副本按已核片段同步，避免丢掉每个项目既有独立适配。
- `runtime_adapter` 继续记录原始/有效摘要及范围，新增元数据比较规则的审计。若增加控制端共享模块，记录其摘要并纳入实际容器读取证明。

## 失败反馈

保留业务失败、环境错误和未验证的区别。元数据比较不满足时给出有限固定原因与差异计数，说明是缺项、次数、状态还是上下文变化，不仅返回泛化失败。只通过既有白名单/体积上限向开发者反馈，不透传私有断言或原始日志。

## 发布与回滚

先做本地和无账号隔离验证，再准备已有发布流程要求的变更范围与推送计划。生产原工作维持原状态直至正常复验；不直接写 passed、重置预算、删提交或改冷却来制造通过。发布后的实际执行摘要和原候选复验结果单独证明；必要的独立模型评审照常进行。

回滚只切回之前的控制端规则/镜像，新旧原始证据都保留；本次不引入数据库迁移。
