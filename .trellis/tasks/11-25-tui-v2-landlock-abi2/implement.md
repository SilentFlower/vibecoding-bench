# 实施与验证

1. 以当前 flower2api 发布线为基准，交由用户指定的开发窗口实施，监督窗口独立核验差异和证据。建立同生产 sender 权限相符的隔离 ABI 2 测试环境。实测 guest 的 Landlock ABI，记录固定 CLI 版本、镜像和内核；普通容器共享宿主内核，ABI 模拟单列。
2. 更新 `images/account/tui_guard.c` 的能力选择、目录规则与 ABI 2 兼容限制。核对 `tui_sender_launch.py` 和 `tui_workspace_launch.py` 的真实启动边界。以项目账号镜像工具链编译，分别检查实际隔离程序的探测和启动。
3. 用合成数据回归可写工作区、私有 HOME、临时保存、同账号并发、已授权的项目共享、跨会话私有文件保护和恢复。补充仅对本次兼容有回归价值的自动化测试。真实内核环境分别覆盖 ABI 2 和 ABI 3+；补测 ABI 1 拒绝和策略加载失败。
4. 复用 `deploy/flower2api/verify_tui_sender_status.py` 与 `verify_tui_account_switch.py` 的测试入口。确认测试部署确实启动候选镜像中的隔离程序和固定 CLI，演练管理端可用性、保存回读、发消息、续聊、进程重启恢复和失败回切。夹具替身的结果单独记录。
5. 监督窗口独立复核跨会话边界、旧版本行为、已有账号更新路径和运行日志。记录实际运行范围及差异，再进入项目验收。生产操作另循发布流程。

## 验收记录

- 在 Debian 12 的 `6.1.0-56-cloud-amd64` 内核实测 Landlock ABI 2。v1.35.0 原隔离程序的就绪检查返回 125，候选程序返回 0。候选制品 SHA-256 为 `bcf405ff612c272c01d34937d240e7b2a06fcb7f2fbd96ab48f2f66531bda0e9`。
- 真实 ABI 2 和 ABI 3 各使用 v1.35.0 的发行网关、候选账号镜像和固定 CLI 2.1.293。测试账号从 V1 切到 V2，重新读取为 V2，三轮请求均成功，重启发送器后原会话历史继续增长。未就绪时保存返回 503，原设置为 V1。编排登记与模型服务使用隔离的回环测试服务。
- 另在 ABI 3 使用同一发行网关重新验证切回 V1，管理端回读为 `native293`。真实 ABI 2 上的四项隔离用例覆盖同账号并发保存、共享项目、私有文件保护和失败关闭。ABI 1 与加载失败通过注入测试分支验证。
- 项目账号侧测试 76 项、编排器 TUI 测试 40 项、隔离回归 4 项全部通过。
