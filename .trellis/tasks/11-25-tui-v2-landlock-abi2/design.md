# 设计

## 现有边界

- 就绪由 `images/account/tui_sender_launch.py` 的 `account_ready` 调用镜像内 `tui-guard --check`。实际会话由同文件的 `launch_session` 交给 `services/orchestrator/tui_workspace_launch.py`，校验账号、环境、主体、已登记工作区与原生会话标识后启动同一隔离程序。
- `images/account/tui_guard.c` 在工作区和私有 HOME 下授权读写，Mod、程序和系统依赖以受限权限开放。不同会话的私有 HOME 独立。同一主体已绑定至同一项目的工作区可以共享。
- 官方文档记录跨目录移动的授权始于 ABI 2，独立的文件截短授权始于 ABI 3。[Linux Landlock 文档](https://docs.kernel.org/userspace-api/landlock.html#filesystem-flags)

## 兼容策略

- 隔离程序读取内核返回的 ABI。就绪探测与进程启动共用规则选择、创建和加载逻辑。依据同一组实际可用权限派生规则集与目录规则。ABI 3 及以上继续使用现有策略。
- ABI 2 复用已有 Landlock 路径授权和已安装的 seccomp 过滤器，在业务子进程内补足对私有文件的截短保护。允许应用通过获准写入的本会话文件正常保存。实施时审查允许的文件打开、已有描述符、间接入口与子进程继承，并核实内核实际检查次序。优先保持 sender 容器既有用户、权限、挂载和数据格式。
- 若局部策略与官方 CLI 的正常保存冲突，先核对真实调用和保护范围，再选择等效的会话文件隔离机制。放宽隔离或提高生产容器权限涉及额外边界，须单独评估。
- 只在隔离策略成功加载并满足既有账号探测条件后报告 V2 可用。管理端继续使用现有账号切换与回读流程。版本过低或加载失败沿既有失败路径处理。

## 升级与恢复

兼容逻辑随账号镜像交付。测试覆盖已有 V1 账号更新镜像后首次切换，以及原 V2 会话恢复。故障场景验证切换拒绝保持已保存设置，验证已有回切 V1 入口。此次验证使用测试账号和受控测试提供方。
