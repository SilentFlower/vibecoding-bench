# Brief — 账号页迁移

## Goal

- 把账号管理页（卡片、工具栏、账号工作区、授权登录弹窗）换成第二版视觉与新组件，字段、顺序与业务行为不变。

## Scope

- **分批**：子任务 4 拆成三批子任务，本次是第一批，只做账号页。第二批为请求记录、代理、令牌与会话封禁，第三批为节点管理与系统设置，各自开工前单独评审。
- **工具栏**：平台筛选、带计数的状态分段、靠右的搜索框。
- **卡片**：
  - 头部：头像带状态点，名称后接平台与套餐徽标，下行为邮箱。
  - 控制行：接收请求开关、停用 / 启用账号按钮。
  - 主体：链接行、语义色健康条（「排队 N」在条内）、转发方式与调度优先级信息块、用量窗口、实时指标、提示条。
  - 底部五个操作。
  - 网格间距 18→16px，列规则不变。
- **账号工作区**：由右侧抽屉改为 820px 居中弹窗。
  - 头部为头像、名称与徽标；页签带固定；配置页按设计稿分区，转发方式用单选卡，底栏通栏。
  - 概览、调度、环境与诊断三个页签按同一视觉排版，内容一项不少。
- **授权登录**：改为 440px 居中弹窗，三步不变。删除确认沿用现有确认框。
- **空状态**：换用空状态组件。
- **390 移动端**：
  - 卡片单列，状态分段用短标签。
  - 应用栏在账号页多一个搜索按钮，点开显示平台筛选与搜索框。
  - 工作区占满可用宽度、单列。
- **共用子组件换 token**：平台徽标、执行节点徽标、代理选线、用量统计与费用气泡、反重力额度、调度详情。
- **组件扩展**：居中弹窗增加固定页签带，外壳应用栏增加页面操作位，同步演示页。
- **样式清理**：账号页颜色与圆角只取 token，删除 `style.css`、`approved-design.css` 中约 400 条账号相关旧规则（含 29 个 `!important` 与 7 个死选择器）。
- **验证与文档**：
  - 新增 `verify_account_page_design.py`，对设计稿逐项比对并截图。
  - 改写或分诊依赖账号页的既有脚本，同步 `ui-guidelines.md`。

## Non-Goals

- 请求记录、代理、令牌、会话封禁、节点、设置页的主体（第二、三批）。代理管理第 4 张概览卡的计数来源，留到第二批开工前决定。
- 新增账号字段、接口变化、首屏加载骨架。现在首次加载时仍会先闪一下空状态，本次不改。
- 深色模式（子任务 7）。

## Technical Overview

- **卡片**：用卡片容器加原子组件排版，样式写在新文件 `accounts.css`（`@layer components`，只取 token），由账号页引入。
  - 原子组件：头像图标块、`Switch`、`Badge`、`NoticeStrip`、浅灰信息块。
  - 健康条色调由新函数 `accountHealthTone` 判定。
  - 进度条配色函数改为返回语义色调，阈值不变。
- **工作区**：基于 `ModalDialog`，新增 `nav` 插槽放页签分段。
  - 内容区成为唯一滚动容器。
  - 配置页底栏的保存按钮用 `form` 属性提交表单。
- **移动端搜索按钮**：账号页通过 Teleport 放进外壳应用栏的空容器，外壳不感知业务。
- **样式清理**：旧规则未分层，会压过新组件样式，所以逐条 grep 确认只服务账号页后删除；与其它页面共用的留给对应批次。

## Context & Decisions

- 子任务 1、2、3 已完成。页头、外壳、组合组件和提示条都已就位。
- **【关键决定】账号工作区由右侧抽屉（概览 470px、配置 860px）改为设计稿的 820px 居中弹窗，四个页签同宽，切换时不跳动。**
  - 依据：第二版设计稿与父任务「居中弹窗（账号编辑等弹窗）」。
  - 影响：打开详情或编辑时背景卡片被遮罩；从代理管理、任务与工程打开账号时也改为居中。
- **【关键决定】健康条按语义着色。**
  - 色调：正常为绿，限流 / 短冷却 / 调度错误为琥珀，异常与认证错误为红，已停用为灰。
  - 影响：认证错误现在显示为琥珀、异常状态现在显示为默认绿色，改后都变为红色。这是本次唯一的状态语义变化。
- **【关键决定】账号卡不套用通用实体卡。**
  - 原因：设计稿里账号卡与实体卡的内边距、名称字号、操作栏尺寸都不同，名称区还是打开详情的按钮。
  - 实体卡的首个真实使用改到第三批的节点管理。上级任务中「在实体卡上扩展五列操作栏」的设想取消。
- **【关键决定】移动端搜索放在应用栏按钮里，默认收起。**
  - 设计稿只画了按钮，展开形态由本任务定义，交截图确认。
  - 有搜索词或平台筛选不是「全部平台」时，搜索行保持展开，生效中的筛选不会被藏起来。
- **【关键决定】平台徽标、执行节点徽标、代理选线弹层是共用组件，这次换新后，请求记录、令牌、运行环境、任务页上的这几处外观同步变化，结构与行为不变。**
- **【关键决定】删除 `verify_exact_design.py`。**
  - 原因：它的账号采样移到新脚本后，只剩已被 `verify_console_ui.py` 覆盖的根字号与无溢出。
  - 它基线即失败（名称字体），删除后从回归集移除并在笔记注明。
- **【重要限制】设计稿只画了卡片、工具栏、工作区配置页与移动端卡片。**
  - 由本任务按同一视觉定义：工作区的概览 / 调度 / 环境与诊断页签、授权登录三步、搜索行展开态、卡片的限流 / 认证错误 / 停用 / 反重力形态。
  - 这些画面交 1440 与 390 截图请你目视确认。
- 状态筛选与工作区页签换成分段控件后，读屏角色由「按钮」变为「单选」；转发方式换成单选卡后不再是原生单选框。相关脚本只改定位方式，业务断言不放宽。

## Risks

- **【交付风险】旧规则分散在两个文件约 400 条，删不干净会压过新样式。** 由新脚本的逐项计算样式比对兜底；发现残留就继续删，不加 `!important`。
- **【交付风险】工作区改为唯一滚动容器后，「滚动时显示滚动条」的标记要落到弹窗内容区。** 先确认滚动事件捕获仍生效，再改对应断言。
- 依赖账号页的既有脚本约 20 个，需要改写或分诊。规则同前几个子任务：样式采样移到新基准，行为断言不放宽，基线已失败的脚本失败点须不变。

## Acceptance

- 1440×900 下卡片、工具栏、工作区配置页与设计稿逐项一致，首行三张卡片的操作栏在首屏内。
- 390×844 下与移动端设计稿一致；点搜索按钮可展开搜索行并完成搜索，页面无横向溢出。
- 设计稿未画的工作区页签、授权登录、各卡片状态在 1440 / 390 下附截图。
- 以下行为全部不变，相关浏览器验证按新视觉更新后通过：
  - 字段保存与取消、分页、授权登录、调度筛选、费用气泡。
  - 接收请求开关、停用 / 启用、排队入口。
  - 从代理与任务页嵌入打开工作区。
- 账号页及子组件不再写死颜色与圆角，账号相关的旧规则与 `!important` 清零。
- 前端构建与前端单测通过，控制台无新增报错；其余回归与改动前基线一致。
