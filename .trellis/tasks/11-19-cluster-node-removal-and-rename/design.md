# 技术设计

## 改名入口

- `Nodes.vue` 使用单字段弹窗及现有管理员会话，通过 `PUT /api/nodes/{node_id}/name` 提交严格校验的 `name` 和当前 `revision`。存储复用登记名称的长度、裁剪和字符校验。
- 在中央短事务内核对节点版本并更新显示名称。显示列为当前名称，登记配置保留初始登记快照，因为迁移、执行、登录草稿和维护回执校验原配置字节摘要。在持有同一节点操作锁时更新版本，避免打断安装的发布回执。`node_key`、SSH 身份、归属代次和运行位置继续作为原标识，改名时无需连接远程宿主。

## 移除入口与状态

- 保留管理员 `DELETE /api/nodes/{node_id}` 和版本字段。确认受理后以 `202` 返回移除状态，原列表轮询同一操作。已经完成的同一动作可返回已完成回执。
- 在现有节点操作锁及中央事务内先校验配置版本、有效账号归属、未结束迁移和节点执行、登录草稿及组件维护。已结束的迁移、执行、登录记录作为历史。遇到真正的在途作业时，给出对应收尾原因，管理员完成原作业后可继续移除。
- 在节点现有持久状态中单独发布移除操作记录，并关闭接单。保存操作 ID、原节点身份、确认的版本和阶段。归属分配、迁移、恢复接单、自动安装、平台切换和移除共享现有互斥与准入检查。远程 I/O 放在中央数据库事务之外。重启后从持久记录恢复观察或同操作续接。
- 平台升级和回退在排空阶段等待正在进行的节点移除。移除待重试时结束本次平台排空并提示续接原移除，避免旧版控制服务重新准备节点。移除完成后，已经清理远端且关闭的无账号草稿作为历史投影，无需远程观测。

## 远端清理与历史

- 复用已固定的 SSH 身份、`cluster-node.json` 安装标记和 `cluster_node_ops.py` 的角色归属核对。执行前验证原规范数据根、部署、`node_key`、Docker 容器和网络的标签及绑定挂载。对于从未安装的节点，确认远端为空即可归档；对未知身份、路径或其他容器的共享挂载返回可核对错误。
- 先停控制组件以结束自动重建，再核对退出并移除其余角色和专属网络。有原控制镜像时用无网络、单一挂载的辅助容器清空原数据根，兼容 Docker 写入的私有文件。按原目录设备及 inode 校验清空结果，保留空目录本身。路径逐级校验，拒绝跟随符号链接或跨挂载。共享镜像和宿主其他资源留在其原归属。
- 允许原数据根所在的独占挂载，保留挂载点。宿主通过实际路径和挂载身份核对其他容器的绑定源，发现同目录、父目录或子目录的共享绑定时在清理前停下。
- 在不可逆步骤前写入原操作的可恢复记录。清理结果丢失后用同一身份及核对结果定位剩余工作，禁止根据目录缺失单独推定卸载成功。远端完成后，中央原子归档节点行、释放当前登记地址并关闭原连接。历史继续用节点 ID 定位；原端独有的日志和文件请求返回节点已移除的明确状态。
- 软删除账号继续保留历史关联。常规账号恢复与移除共用中央写锁，进入移除后，旧账号记录保留为历史，重新登记使用新的账号名称。
