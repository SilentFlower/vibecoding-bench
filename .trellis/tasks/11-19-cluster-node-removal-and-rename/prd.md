# 修复远程节点移除并支持节点改名

## 目标

管理员可以在节点管理修改节点显示名，并能将已退出服务的远程节点组件和专属数据从原主机清除，同时保留中央的节点与操作记录。

## 现状与证据

- 线上「绿云日本」目前有一条 `cancelled` 迁移。有效账号归属、执行记录及登录草稿均为零。节点已安装组件。
- `ClusterStore.remove` 在写软删除前按 `node_migrations` 任意匹配拒绝请求，包含已取消的迁移。`ClusterService.remove` 只在中央归档并关闭管理连接。见 `services/orchestrator/cluster_store.py:215`、`services/orchestrator/cluster_service.py:912`。
- `Nodes.vue` 已有添加、检查、暂停和移除入口。`cluster_api.py` 缺少更新显示名的操作。节点显示名与稳定的 `node_key`、SSH 身份、账号归属分别存储。
- `cluster_runner.py:216` 从原执行节点读取部分日志和产物。移除后，原来只存在该节点上的文件停止提供下载，页面仍可查询中央记录。

## 需求

- R1 节点页支持修改已登记远程节点的显示名。沿现有管理员权限校验名称和并发提交，账号归属与历史继续关联同一节点。
- R2 有有效归属账号的节点须先迁移账号，停用的账号也算归属。空节点可直接退役。已完成、已取消的迁移及其他终态历史保留原 ID 和查询入口。仍在运行或等待恢复的作业先沿原操作收口。
- R3 管理员确认一次即启动卸载，停止并清理该节点自己的组件和远程数据。远程历史日志和产物随专属数据清除。中央节点、迁移、执行及登录记录继续可查询。确认窗说明清理范围，进度反映实际操作，断线或部分失败时可重查或续接，核对远端清理成功后才归档中央节点。

## 验收

- [ ] R1 修改显示名后，列表和账号归属入口使用新名称。陈旧表单提交可识别冲突，SSH 身份和账号分配记录保持同一归属。
- [ ] R2 合成节点只有已取消迁移或已结束执行时可以完成移除。中央历史仍能找到该节点和原记录。有归属账号、正在迁移或待恢复的工作在清理前得到明确结果提示。
- [ ] R3 两个节点共享同一测试宿主时，只有选中节点的组件和专属数据被清理。SSH 中断后可核对或续接，历史和完成结果与实际远端一致。原端独有文件显示节点已移除的不可用状态，同一地址可重新登记。

## 范围边界

- 远程历史文件随卸载清除，中央已有记录和已有文件继续可读。本机节点及宿主其他应用、共享 Docker 镜像和其他节点的文件属于独立范围。
