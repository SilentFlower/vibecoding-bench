# 多服务器人工分配与统一网关转发：技术设计

## 1. 架构与边界

一个管理中心持有网关账号、令牌、任务定义、账号节点归属和全局准入。每台执行服务器运行一个节点服务，管理本机分配的账号环境、Docker、工作目录、执行证据与本地资源。

管理中心通过 SSH 主动连接长期在线且网络可达的节点。客户端与浏览器沿用中央入口。Docker socket、账号 sender 与私有执行操作通过 SSH 通道访问，节点不公开 Docker API 或账号容器端口。首版沿用现有 Linux x64 执行制品的平台要求。

现有服务器登记为默认本地节点，本地执行沿用原调用路径。远程节点采用同批 control 镜像内的私有执行组件及同批 account 镜像，保持两个最终镜像的构建形式。执行组件经 SSH 调用，关闭中央账号调度器、全局任务调度和管理后台，不启动公开节点 API。

本设计中新增表、字段、模块、路由及协议均为拟新增合同。现有类型与调用依据见 `research/current-architecture.md`。

## 2. 权威状态与数据模型

- 中央 bench SQLite 新增节点登记、账号分配与迁移操作记录，保持现有两个业务数据库的权威边界。默认节点通过幂等增量迁移建立，旧账号回填至本地。
- 节点登记包含稳定节点身份、名称、SSH 地址/端口/用户名、已确认主机公钥指纹、远程数据根、配置版本、启用状态、受信发布/协议能力及带时间的最近观测。SSH 私钥保存于中央私有目录的受保护文件，数据库保存引用；读取与备份遵循现有私有文件权限。
- 账号分配覆盖尚未创建环境的账号。环境公开投影兼容增加节点身份、名称、状态及分配版本；网关账号本身不复制为多个账号。
- 分配绑定唯一账号、环境 ID、节点和独立分配版本。环境 `generation` 保持原有用途；迁移或入口重配产生新的分配版本并使旧通道失效。
- 节点保存自己执行所需的配置投影、作业收据和环境实际状态。节点投影仅覆盖分配给本节点的账号。中央任务与账号策略为权威，节点记录用于实际执行和重启对账。
- 中央`node_executions`以独立`bench.node-executions.3`增量保存远程会话，绑定账号/节点/环境、分配及实际代次、原source、操作与CAS版本；同一账号/source只允许一个未收口操作。原节点停止与中央租约释放均明确后，同一工作同代次可用新操作恢复原会话，继续冻结原目标/会话/设置并核对剩余预算。租约、证明序号和节点回执保存在私有记录中。节点删除和账号删除继续核对执行历史引用。
- 禁止同步整份可写中央 SQLite。节点配置投影拒绝旧版本覆盖，不启动中央调度循环。提取执行模块依赖的最小状态访问边界，替换直接读取中央全表的耦合。
- 私有运行数据仍在所属节点。中央保存公开状态、任务历史、事件游标与资源摘要；文件、转录和诊断详情按权限从归属节点读取。

## 3. 节点接入与访问控制

管理员准备节点的 SSH 和 Docker，在中央后台填写节点名称、SSH 地址、端口、用户、专用私钥和远程数据根。先无认证探测主机公钥并展示 SHA256 指纹，由管理员确认后保存。后续使用严格主机校验登录并执行无模型调用的 Docker、资源、路径和镜像能力核验；同批执行组件通过 SSH 部署和调用。

- 跨机加密与服务器认证由 SSH 提供，不依赖额外 HTTPS 证书。采用固定 known_hosts 和显式身份文件，关闭 agent 转发、密码回退、隐式代理、交互提示及无边界重试。
- 本地节点保留现有 Docker 网络协议。控制连接使用长期 SSH 会话与有限超时，业务使用独立有界 SSH 连接池，保留每条流的取消与背压。
- SSH 管理身份与账号传输身份分开。sender 继续验证账号、环境及分配版本，中央本地隧道 socket 仅对服务开放；浏览器只收到脱敏投影。
- 管理浏览器沿用现有管理员登录及 `/runtime/` 会话桥。SSH 私钥不转发给账号容器，不使用浏览器 Cookie、全局管理密码或客户端 API 令牌登录节点。
- 地址只由管理员登记。请求正文中的 URL、文件路径或节点身份不能覆盖中央归属；控制接口按固定操作和参数白名单解释，SSH 命令使用固定模板及严格参数，拒绝向浏览器提供任意宿主命令执行入口。
- 节点删除受分配、迁移及历史引用保护；停用立即关闭新准入，历史记录保留。凭据轮换先排空旧连接、核对新配置，再启用新版本。

## 4. 网关请求与后台出站

1. 网关按现有令牌范围、账号策略和会话规则确定账号，获取原有全局并发及凭据所有权许可。
2. 原 `/internal/v3/transport/{account_id}` 从中央归属记录解析本地或远程通道。中央核验节点可用、分配版本、发布能力及环境实际代次。
3. 本地通道保持现有 binding 校验。远程 binding endpoint 使用中央编排服务固定 origin 和 `/cluster-transports/v2/<部署摘要>/<节点>/<环境>/<分配版本>`。网关先校验 origin、部署及环境身份，再发送独立内部转接认证头；账号 bearer 仍由 sender 核验。
4. 编排服务再次核对当前归属、节点状态与环境代次，经受保护 Unix socket 和独立 SSH 业务连接流式转发至节点 sender，并移除中央转接认证头。此适配沿用固定 reqwest 版本与 TLS 栈。上游仍使用账号已有代理、TLS 画像和请求后端。
5. 响应以流返回中央网关及客户端。网关保留计费、错误映射与诊断，记录本次实际节点、环境及分配版本。

legacy 与 native293 均使用这一节点选择边界。原生准备、预热、空闲策略、内核操作、count_tokens、额度查询、遥测和受管 OAuth 刷新等账号相关路径逐一登记执行位置，避免后台活动留在错误出口。

凭据刷新决策及最终持久提交继续由原所有者完成。需要远程出站的刷新通过受限操作交给所属节点发送，节点仅在该次发送期间处理所需秘密。执行节点不独立取得网关账号刷新权。提交结果不确定时沿用原 reconcile 边界，禁止重复使用未知结果的刷新令牌。

绑定账号的后台usage、托管OAuth刷新、令牌测试及现有两类遥测复用原PreparedTransport与sender。通过仅由网关构造的内部purpose头限定动作；sender先核对purpose对应的精确方法、URL、原账号/环境/代次和截止，再沿原HTTP/TLS客户端发送。usage与遥测保留API域，刷新仅接受原固定OAuth token域；未登记purpose或任意URL在发送前拒绝。该头不来自客户端请求元数据，不转交上游。独立部署保留原直接客户端语义，v3准备失败关闭该次发送。刷新提交未知保持原Internal分类，以保留唯一刷新所有者的持久维护；发送前明确拒绝与上游已提交继续区分。后台响应采用有界期限，SSE原长流期限继续沿用。

SSE 保持逐块传输与有界缓冲，传递客户端取消和下游释放。准备/连接期限与长流期限分别处理。正式业务提交不自动跨节点、跨后端或跨账号重放；发送前明确拒绝和提交后未知结果继续区分。

## 5. 执行适配、租约与恢复

新增节点执行路由，根据中央账号分配选择原本地实现或远程适配器。控制面操作按环境准备、启动、停止、状态、终端、文件、工程资产及评审分组。复用本地执行实现，在受影响模块提取必要边界；不实现通用远程文件系统或远程 SQL。

远程工作携带全局操作 ID、账号身份、环境代次、分配版本和原租约证明。中央保留全局额度、账号门禁与任务调度，节点负责本机实际进程与资源接纳。节点不持有网关管理员口令；现有执行流程对网关租约及刷新动作的调用改为由中央协调并发送受限结果。

- 中央定期续约及拉取有序执行事件。节点将作业收据落盘，重复控制命令按原操作查询结果；模型输入提交回执未知时进入待核对状态。
- 节点与中央失联后关闭新准入和后续模型输入。已经发送的模型请求收口到本次结果；既有进程保留可核对的现场。长任务在原输入边界暂停，恢复连接后由中央核对，禁止盲目重启会话。
- 租约期限不表示作业已停止。迁移、删除或重新分配必须取得源节点真实停止和隔离回执。
- 节点恢复先比对分配版本、Docker 标签、环境执行记录和中央任务身份，恢复事件游标；发现冲突时隔离对应环境。
- 资源接纳在节点核对真实 CPU、RAM、swap 和保存的账号预算，保留原独立 API/CLI 并发及评审资源合同。
- 终端使用已鉴权的中央 WebSocket 转接 SSH 通道；节点终端票据绑定环境、分配版本和会话。文件与抓包通过受限 SFTP 路径读取，按既有目录归属及符号链接规则校验。

### 持久节点执行与有限证明

CLI和终端采用同批control内的持久节点执行进程。该进程只监听私有Unix socket；SSH固定命令经该socket调用受限操作，运行时共享本机jobs、环境锁、容量锁与受限账号配置提供器。既有迁移和准备操作复用同一运行时作用域，避免独立exec进程遗失内存jobs影响API/CLI并行。

SSH的固定docker exec入口使用轻量cluster_agent_client.py，直接读取有界标准输入并连接原私有UDS。账号执行模型由长驻服务装载一次，控制命令继续核对node-control角色、原安装环境变量、服务认证和具体操作白名单。入口沿原ok/result或固定错误字段返回，保持既有请求期限、脱敏与未知提交恢复合同；手工cluster_execution入口继续保留同一转发路径。

中央继续取得原网关真实CLI/排他租约和额度许可。节点只保存绑定节点、账号、环境、分配版本、实际代次、操作及source的有限执行证明；证明包含原owner/generation与截止，更新具有单调序号。节点本地镜像不创建或续长中央真实租约。超期关闭新启动及后续终端输入；已经接受的输入保留原进程和可核对结果。中央失联后的租约过期不构成作业停止证明。

节点保留启动和输入意图、实际进程证明及完成收据。输入同一操作结果未知时只查询收据和实际原生会话，禁止重新投递。重启后原作业先对账，未知状态拒绝新执行。中央仅通过具体CLI、Pi、工程、日志、文件及评审操作适配；工程只读资产按原摘要注册到节点，保留目录归属与快照合同。完整中央SQLite和全局管理密码继续留在中央。

原AccountRuntime在节点使用有限租约镜像：中央已认领的原owner/generation在本次启动上下文内提供prepare/claim兼容回执。低优先级检查只隐藏本次尚未在节点认领的原holder，其他holder继续可见。节点heartbeat仅读取原截止，既有进程超期后保持现场；新启动及终端输入在实际投递前再次核验有限证明。节点release仅关闭本地许可并返回本地收口事实，中央真实租约须由中央核对执行收据后释放。CLI版本安装、工作区准备和监督进程握手后都需复核投递许可。

节点具体终端只接收原work的实际消费字段；library_root由节点冻结摘要计算，runtime_json由节点原启动收据生成。启动意图认领一次，unknown输入先登记未决指针，后续不同输入等待原回执或人工核对。grant续接不等待长安装的环境文件锁，启动/输入收据读取通过原子发布保持有界。中央远程会话登记将按原source保存唯一操作、节点配置摘要、归属/实际代次、工作、租约/序号和节点回执；只有明确原节点停止后才释放中央真实租约和额度许可。重启与提交未知优先查询原收据。

工程快照沿原snapshot_tree的128MiB/10000文件合同。节点基线快照要求新启动且尚无输入；交付快照在原监督器确认进程树冻结后生成。清单和按摘要寻址的对象封装为有界私有包，经原Docker/SSH归档通道逐块下载；中央固定同一文件描述符核对整包、清单、路径、大小和每个对象摘要，保留原snapshot/objects消费者。节点工作投影仅携带has_baseline布尔事实，完整baseline_json继续由中央保存；原工程准备只按该事实保留累计工作区。

工程终端路由按中央归属选择首次启动位置；已经登记的工作始终按冻结执行操作读取和控制，归属变化或记录冲突拒绝改走本机。中央工作仅保存原执行操作、source及实际token的定位，节点文件路径留在私有收据。抓包摘要与白名单预览由所属节点复用原脱敏读取器；人工输入核对先登记中央意图、再保存节点原输入结论，最后完成中央动作状态，跨端失败继续保留原未决操作。

远程额度准入由中央原QuotaGuard认领。节点原生错误通过持久发件箱传回，中央合并后确认；响应丢失继续交付同一事实。正式CLI/Recorder的额度JSONL按原scope推导固定路径，有界读取到中央私有镜像并登记原quota_observation_cursors，继续使用原解析、身份/来源校验和事务游标。中央门禁投影绑定原grant序号和采样时间，首次启动与续接时发布到节点原只读额度挂载；旧序号、旧身份或迟到采样拒绝覆盖。

发送器API额度证据按节点、账号、环境、分配版本和实际代次读取固定observations.jsonl，不依赖CLI作业存在。中央私有镜像与终端采集共用有界文件读取、轮转和游标落盘规则，原QuotaGuard继续核对source与quota_identity。SSH读取在额度全局锁外完成，失败保留已有事实并使该次新准入失败。绑定远程账号的显式手动额度查询沿网关原唯一凭据所有者调用usage，实际HTTPS发送仍由所属节点承接。

独立程序验收在原执行节点复用ProjectVerifier及同批账号镜像。中央保留范围检查、历史通过事实、语义审查和最终通过权威；节点按冻结library_digest/project/objective及定义摘要读取原私有合同，不接受远程任意脚本或路径。输入为原候选快照、原回答及固定business/regression模式。节点保存唯一验收尝试和启动意图，以后台作业执行原隔离验证器；重复提交只读原作业。完整报告封装为私有有界归档返回中央，控制回执仅传范围、阶段与摘要。停止原终端前先取消并确认依赖验收容器收口；节点重启后的未知作业按精确节点/环境/执行/尝试标签核对，未知结果保留待核对状态。

节点重启后的终端恢复只重建原执行的停止能力。受限租约镜像按原证明登记恢复范围，过期或关闭证明继续拒绝新输入；运行时从原私有执行文件核对账号、环境/容器代次、source及原租约模式/代次，恢复原监督器定位后定向停止。没有原执行登记时，要求当前CLI角色确已停止或实际账号进程为空；内存jobs为空和租约TTL均不作为停止证明。中央重启先恢复旧维护占用，再由工程恢复入口取得原节点停止回执；失败保留原定位并阻塞该账号。

独立账号的远程CLI准备沿同一节点投影与原AccountRuntime.ensure(prepare_sender=False)，保留所属节点HOME的完整本地刷新所有权；后续准备复用原本地凭据选择器，已有HOME轮换结果优先。绑定账号继续仅投影AT。中央独立账号许可只包含原额度认领、持久执行登记和有限证明，lease为null；实际节点不取得虚构网关租约。中央记录单独的独立许可释放事实，必须核对节点真实停止及原额度释放后关闭，过期与失联继续保留活动占用。工程Pi两种账号沿同一具体终端协议，原网关绑定版本和独立许可两条路径分别核对。

普通Runner使用具体冻结Run工作及原任务driver。中央路由在原_quota_mounts和本地工作目录创建前选择节点，保留原run/source/attempt、版本、模型、权限、业务补充和时限。节点只投影该次执行所需的任务/运行/项目上下文，中央调度及验收推进保持权威。自动补充、收尾、认证恢复和项目步骤的实际终端投递由按scope绑定的root侧私有输入broker核对原有限证明，复用Pi原stdin缓冲及paste/Enter前校验。输入先登记意图，同操作重读原回执，未知阻断后续输入；控制端恢复继续查询原作业。私有评审沿原专属容器及资源交接，发送目标由原job确定。默认本机worker继续原发送方式。

普通Run实际停止后按原操作冻结轻量产物及摘要，后续额度尝试改写活动文件时仍保留原回执。中央启动先恢复原节点占用，再恢复额度；后台收口启动时冻结的旧来源及原所有者明确标记启动/停止失败的操作，新作业仍由原调度线程持有。重启扫描包含终态Run遗留的未收口操作；旧attempt停止只释放其原许可，继续保留后来attempt的状态。普通Run准入复用Scheduler已经取得的账号owner锁，工程入口自行取得同一锁，避免重复领取不可重入锁。共享作业分别保存额度上下文，账号公共额度只接受更新采样。

普通Run文件、统计与抓包以具体只读节点动作提供，固定原scope和work推导物理目录。文件树使用逐层目录描述符拒绝链接与特殊文件，最多10000条及2MiB清单，分页返回；预览沿原64KiB与UTF-8/二进制合同。统计共享原sidecar与原生session聚合规则，限制扫描文件、行与总读取字节，超限显式失败。抓包继续复用脱敏摘要和公开文件白名单，原始正文保持私有。中央先执行原运行可见性校验，再按冻结执行位置查询；节点不可用时保留明确失败。

续聊沿原ContinueManager的sid/generation、原Run和Claude会话、窗口与额度状态推进。节点使用具体ContinueWork准备原AccountRuntime.begin_continue；中央取得原非共享CLI租约及额度许可。实际PTY沿原resume命令和容器exec启动，先保存一次性意图和实际exec登记，再核对证明并连接原PTY。浏览器WS仍由中央鉴权，经独立SSH隧道访问节点私有UDS上的固定PTY WebSocket；节点独立认证并核对冻结scope。输出有界背压，输入每帧具有原操作收据，原作业身份与有限证明在实际写入前复核。重复输入只查询原回执，未知输入或PTY启动关闭后保持原scope隔离。连接重试不能另起原Claude。续聊暂停、恢复、绑定身份和托管刷新沿原中央规则；实际停止确认后释放中央许可，节点和中央重启先收口原执行。登录草稿另用原草稿身份，后续单独适配。

## 6. 手动迁移

首版为源节点与目标节点均在线时的停机迁移，由管理员明确发起。没有强制接管或自动故障迁移。

迁移记录持久保存以下阶段与原操作 ID：

`requested → draining → source_fenced → exporting → importing → verified → committed → completed`

失败按阶段保留 `failed` 或 `reconcile` 及已完成收据，不把未知状态恢复成 ready。

1. 在owner/profile顺序中核对原归属和目标能力，持久关闭新准入并冻结执行范围。中央网关认领原操作排他租约并持续续约，排空实际API和节点流后再取得环境锁；避免环境锁阻塞排空中的既有transport准备。
2. 核对并排空 API、CLI、终端、评审、登录和未完成凭据交接。停止源账号角色并取得持久隔离回执；源节点失联或无法核对时停止迁移。
3. 按现有备份文件归属及摘要机制导出 HOME、凭据身份、项目工作区、执行/恢复证据与配置。保留文件权限及合法链接。排除 socket、PID、旧容器 ID、可再生程序缓存和 CRIU 内存快照；排除项必须有对应恢复或重建规则。
4. 中央协调有界数据传输，在目标私有暂存目录验证清单、摘要、路径、权限、原身份与可用空间。禁止整包读入中央内存和未验证解包路径。
5. 保留原账号、环境 ID、CLI 版本策略与逻辑身份；目标按实际宿主重新核对资源和物理观察，重新建立容器、网络与热进程。重新生成节点传输秘密，旧租约和 endpoint 不进入新运行配置。
6. 目标完成无模型调用的检查后，中央以 CAS 原子提交新归属和新分配版本，登记源撤销及目标激活收据，再开放新准入。
7. 源副本保留为停止且被隔离的恢复资料。迁回同一节点时，按原停止收据核对所有实际角色，持久保留意图后移除已停止角色并将旧树移动到本操作私有目录；新资料独立发布。目标代次从两端已停止证明的较大代次继续。默认本机目标使用独立执行投影准备，中央环境行只由CAS切换；管理profile保留唯一刷新凭据。清理由既有受控维护入口按明确归属执行，不在迁移成功后自动删除。

切换前失败：目标保持不可服务，取得目标回滚隔离回执后恢复原绑定；目标撤销和源恢复保留取消墓碑，拒绝原操作迟到上传、发布、激活和隔离。失联时保持维护等待核对。切换后失败：保留新归属并进入 reconcile，禁止自动回退到旧副本。

### 迁移归档合同

迁移包在源环境已排空且角色停止后生成，独立于中央数据库。包的清单绑定操作、部署、源节点、账号、环境及原分配版本，记录文件摘要、大小、权限、UID/GID与链接原值。中央协调方另行核对整包摘要；导入目标必须为该操作私有目录中的全新暂存树。

第一层归档机制只接受调用方明确的排除表。socket由既有盘点合同排除。执行层登记 network/sender/access 配置、PID/socket、CRIU、实际容器观察等可再生内容的精确排除项及恢复依据；HOME、项目、历史执行证据、逻辑画像和必要配置由清单保留。未收口执行或未知恢复来源先拒绝导出。账号执行层在源隔离与目标核验后才可发布暂存树。

导入采用流式读取和逐文件校验，限制清单规模、条目数和解包总字节。路径须为规范相对路径，父条目须为目录；文件、目录与链接的类型及摘要逐项匹配。链接在普通文件之后创建，解包不调用通用 extractall。数据核验后恢复权限与归属，目标停留在该操作的私有暂存目录，由后续激活步骤处理。

节点操作目录为 `/data/node-migrations/<操作>/`，以归属标记区分导出与导入。源包保存在 `exports/<导出尝试>.tar`；目标组件先建立 `imports/<上传尝试>/`，再通过 SSH Docker socket 的归档 HTTP API 写入其中的固定 `environment.tar`。中央私有文件中转按整包摘要和大小核对。该路径使用具有读写超时和总传输上限的 HTTPX 流；现有 Docker SDK 的原始归档读取会关闭底层读取超时，因此迁移数据流直接调用同一受保护 socket 的归档 API。

节点采用环境锁保护准备、隔离、导出和目标导入。只读观察尝试共享环境锁并快速返回占用；创建角色时另取短作用域的节点容量锁。大包导出和导入保持对应环境隔离，其他环境已有业务连接继续使用独立 SSH 通道。包排除目标需要重建的 network/sender/access/CLI 控制、原生进程临时区和 CRIU、原镜像物理来源、旧物理观察及旧 group.pid；实际历史证据与逻辑画像继续由清单保存。

源组件按原冻结CLI版本读取已验证设备与账号来源，并在包描述中绑定源实际代次。目标在操作私有树中复用同一只读身份合同核对HOME与中央profile，随后持久发布意图、原子移动环境树，准备三角色；准备后再次核对身份。中央提交新归属后，目标按精确节点、操作、分配和代次保存激活回执，原停止状态予以保留。

远程账号角色增加完整节点身份标签，容器和Docker DNS名称使用节点限定的短前缀，包含环境UUID后仍满足角色DNS标签长度。原默认节点继续使用既有命名及无节点标签的本地角色。角色读取、孤儿收口和容量盘点核对当前节点范围，确保源停止副本与目标实例可明确区分。

## 7. 后台交互

网关配置事务的quiesce回调按原账号归属执行。SSH请求冻结原环境/分配/实际代次与真实gateway-config排他租约的有限截止，节点在环境锁内复核原绑定、实际作业、程序/评审及发送连接后停止空闲角色，并核对Docker停止事实。该操作保留归属、HOME和凭据，不创建迁移fence；原Gateway配置许可继续由原事务持有和释放。回包未知使本次配置失败，后续准备按真实停止状态恢复。普通配置热更新继续沿原无需停止的白名单。

- 新增“节点”页面：节点名称、地址摘要、连接状态、资源、采样时间、账号数量、协议/发布兼容及操作结果。
- 账号创建或首次环境配置增加节点选择，默认选择本地节点。已有环境显示当前节点；变更走独立“迁移”操作，避免普通表单直接改归属。
- 环境与任务页面展示所属节点，日志和请求详情关联实际执行节点；离线显示上次状态和时间，未知容量保留未知。
- 迁移展示源/目标、预检、排空和阶段进度；失败显示当前阶段、可恢复操作及原因。危险操作沿用现有确认控件。
- 使用现有 Vue 组件、Toast、对话框、表格和窄屏规范，公开字段不包含服务秘密。

## 8. 构建、备份、升级与回退

新增 SSH 纳管、隧道生命周期、部署模板和预检，管理镜像安装 OpenSSH 客户端；同步 `images/v3/Dockerfile`、源码布局和固定宿主更新包清单。节点能力包含协议、布局、发行和执行平台，首版要求同批清单；能力不足的节点拒绝新远程执行。

全局更新先核对节点集合和在途工作，再排空并按现有签名发行合同更新。节点未到达兼容版本时保留维护状态；禁止中央升级后向旧节点发送未知协议。实际节点安装沿用管理员受控部署，本任务交付流程和兼容检查。

中央备份包含归属、迁移日志和受保护节点认证材料；环境数据按节点保存带节点/环境身份的备份索引。全局备份完成标记要求所需节点资料齐全，缺少节点时明确报告未完成。单节点备份可独立核验。迁移导出沿用同一文件合同。

数据库通过追加已登记迁移实现，保持旧步骤摘要。回退须先将远程账号迁回本地并收口节点活动，再恢复兼容镜像及相应快照；旧版本不读取远程绑定。开发验证全部在临时数据库和合成节点中演练。

## 9. 关键风险与验证边界

- `AccountRuntime`、终端及评审存在本地文件/数据库耦合，第一条纵向链路需先验证状态边界和最小投影；提取范围以实际消费者为准。
- 网络分区和迁移提交存在双端状态，依赖真实隔离回执、分配版本和持久操作记录；未知状态保持维护。
- 中央网关继续承接全量流量，资源收益主要来自账号进程和任务卸载；压测需分别观测中央带宽/连接和节点 CPU/RAM。
- 验证分为数据库/协议单测、真实进程回环集成、隔离双节点容器链路、前端浏览器及完整回归。合成节点与本地上游的结果用于开发验收；线上容量与网络表现需部署后单独观测。

### 经典项目逐消费者接入

先接通原schema1单步实例，再接schema2计划、schema3场景与私有评审。每次远程Run携带严格冻结的实例/步骤/批次代次、内容摘要及项目键，节点按固定同批资产核对seed。原AccountRuntime按本次调用传入文件提供器，不把中央ProjectIterationManager或全局数据库复制到节点。节点工作区发布与本机共用原marker/seed/别名合同；准入和实际投递仍核对原Scope证明。

中央通过具体项目事实读取核对物化位置、原生会话起止和有界会话字节。原项目管理器在实际节点回执后CAS保存workspace_relative/started_at，保留原native-start首次起点和步骤验收权威。候选通过现有有界源码包返回原objects/manifests；工作区已被后续执行取得时拒绝重新封存旧候选。计划的source、阶段事务、输入父链及场景预算继续在中央执行。后续计划/场景/Review沿这一分界逐条适配。

同会话计划在原Run启动前增加有界预准备。中央取得原真实许可并启动续约后，节点按原Scope保存文件准备意图，物化工作区及原生起点。中央调用原ProjectPlans.execution_configuration保存source与步骤事务，再发布具体计划配置。节点实际exec启动意图单独保存；已进入exec意图的记录只允许查询与收口。原监督放行仍在中央最终批次复核之后。

计划request/state和原生字节进入中央私有镜像，原_evidence、_accept及checkpoint检查继续使用原解析器和事务。中央持久决定通过固定源/阶段/会话的具体操作写入Node root控制目录。每阶段源码包包含原operation和phase_seq，旧候选回执保持原内容。原freeze/resume按run/attempt绑定精确节点Scope。


原生证据按本轮实际字节范围传输。旧会话仅保留尺寸边界，固定计划会话按原接续证明读取；停止后使用原冻结end作为读取上界，后续追加留在后续执行。每片同时限制原fstat大小和本轮剩余字节。中央零新增字节的旧文件跳过正文，64MiB传输预算用于本轮相关证据。准备中的新source等待实际启动回执；旧同Run控制状态仅留给原driver接续，中央只消费当前source通知。

### 场景输入文件分界

场景输入按原业务依赖和实际文件责任拆分。已接受代码job父链、base checkpoint、披露选择及任务状态继续由中央原管理器计算。工作区替换、固定setup复制、ready/replacing标记与旧现场保存提取为本机/节点共用文件执行器。节点仅接受原冻结内容中已定义的setup和中央核对的base对象；每次结果绑定原Scope，先取得实际文件回执及完整manifest/对象，再保存中央原输入事实。先在中央临时树发布ready再等待远端应用会形成失败恢复缺口，实施采用节点实际回执后提交。

场景候选的单调时钟和boot身份来自实际执行节点。source/segment预算与start_permitted仍由中央原事务推进。私有评审继续使用原冻结包、同实际模型、独立HOME/容器与串行资源交接；候选完整输出在真实释放后才进入原机械/语义验收。


场景基线传输复用原Scope源码包合同。原Run先保存固定包暂存意图，再导入完整已接受对象，随后一次准备实际场景文件。输入对象、逐阶段标记和替换前现场随账号环境runtime/scenario-inputs保留；具体操作回执和包保留在原node-runs目录。中央取得每阶段完整对象及真实回执后保存原输入marker和任务事实，再调用原场景配置事务。Node实际boot_id/monotonic进入原中央预算片段，原生镜像保持中央私有权限。

原场景候选沿按次NodeScenarioProject使用既有worker/driver及具体完成决定。Node全局项目管理器保持为空，离线Python环境通过本次冻结文件提供器解析。未进入exec的输入暂存/文件准备失败沿原Run持久墓碑停止，中央保留尚未投递事实；未知文件准备保留原意图和现场，后续核对受原Scope约束。

私有Review沿同一Run协议的冻结角色使用非共享CLI许可。评审包只在具体暂存操作传输完整原件，Work冻结原评测作业、实际模型及包摘要；不将隐藏包放入候选挂载目录。原ProjectReviewRuntime接收按次文件提供器和延后许可，继续使用原串行资源交接及私有session根。中央保存原source/预算和start_permitted后，再发布Node私有controls的监督许可。Node产物、额度、刷新、轮询及实际停止均按原Scope的固定私有根读取，保持原AT-only副本和唯一刷新所有者。

### 独立账号凭据维护与评审401

原固定OAuth刷新脚本与Docker执行解析提取为本机/Node共用核心，保持原目标、client_id、授权scope、账号网络及当前HOME读取。远程独立刷新作为具体凭据维护工作，使用既有login凭据操作族的独立Scope及oauth-refresh来源；中央NodeExecutions保存冻结工作、身份、发布及Node回执。工作不认领模型额度或网关租约，中央执行许可和原CredentialOwnership的refresh_pending仍覆盖实际发送与结果收口。

私有评审待办通过具体run-owner-refresh-defer操作核对原worker请求SHA、原Scope及实际project-review作业，持久待办后返回固定确认。只读review-admission按需投影同身份待办的有界字段；拒绝AT摘要保留在节点。中央按原评审操作及有限复验序号确定维护ID，在严格释放原评审前落账并登记更新占用。已登记且尚未提交有限证明的维护可在重启后继续同一工作；已经提交的旧工作只查询及停止，未知RT结果继续隔离。

中央刷新观察复用原ClusterRunner后台循环。普通独立维护与私有评审维护共享具体执行核心，原不可重入owner锁显式沿用既有调用方。已确认的私有评审维护由Node按原request_id、账号身份和环境代次结束原待办；已知未提交最多复验两次，未知结果保持原所有者隔离。原生会话、实际模型和已消耗工作预算沿原场景恢复合同核对，边界未确认时继续保留未决预算。


私有评审401触发原所有者待办后，worker沿认证失败正常退出并执行原EXIT清理，先由原driver写入最终project-work计时片段。控制侧有限等待同一真实exec结束，再执行原定向停止、私有容器收口和固定CLI资源恢复。该等待只观察原exec，不投递新提示或续开模型。driver未提供最终工作边界时继续沿原未决预算处置。实际TLS刷新在上述严格释放之后执行。

认证观察复用worker已有COMPLETION_BASELINE按文件完整字节游标读取，只识别本轮追加的原生401事件；同一逻辑私有会话保留历史错误，恢复不会重新触发旧错误。原轮内恢复的时间边界与TUI判定保持原合同。共享恢复循环遇到某账号owner锁占用时跳过该条，其他账号继续核对原作业。

### NULL新账号草稿的节点接入

原运行时草稿适配明确携带`id=None`，独立Scope仍省略正式账号字段。只检查产物的恢复作业在原持久执行中标记`draft-login-recovery`，保存原版本且不伪造tmux；停止恢复仅在明确草稿恢复标志、NULL身份、独立登录来源及原工作模式同时匹配时接受该定位。

首次独立登录沿原`record_local_authorization`的来源规则：具备已核验CLI设备来源时保存原证明；原独立新授权允许设备证明暂缺。Node激活始终核对当前HOME与冻结授权的完整集合摘要及RT摘要。存在的中央设备证明必须匹配本次部署、环境、版本和RT。后续关联Gateway继续采用原严格设备证明门禁。

以下为同一任务内拟新增的草稿合同，按原未提交草稿语义逐层落地。

- 新建时管理员选择节点，省略继续使用默认本机。已有草稿沿首次冻结节点，重新登录和恢复保持该节点。当前已有账号重授权继续按正式归属选择节点。
- 新增独立`bench.node-login-drafts.4`登记中央草稿节点记录；一环境一条当前记录，冻结节点、原操作/SID、字符串草稿代次、CLI版本、配置摘要、有限证明、Node回执和CAS版本。保存后的实际账号ID单独可空。该记录通过外键/引用检查保护节点和环境，已提交历史保留；完整删除未提交草稿后才能解除引用。前三步checksum保持。
- 远程草稿仍为`account_environments.account_id=NULL`。草稿Scope单独绑定Node、环境、名称、逻辑草稿代次、实际环境代次及原操作/SID，省略正式account_id和Gateway租约。资源准备明确后才冻结实际代次并发有限登录证明。普通正ID执行合同保持。

- 草稿取消只收口原进程并保留已写授权产物；完整删除另走明确的删除动作。resume有活跃会话时复用原SID；失去原交互时先确认原实际停止，再认领新维护SID/逻辑代次，仅执行原recover_login和认证检查。restart显式收口旧会话后开始新授权，保留原环境、设备、代理与缓存。
- 提交先冻结新授权，保存Node HOME并取得受信原文件/材料，再镜像中央。Node原登录实际停止和暂存清理确认后，中央短事务创建正式账号enabled=0并把新账号首次归属直接设为原节点；原环境ID保持。Node随后投影这一真实正ID、发布正式归属，按空闲规则处理草稿角色的正式额度挂载。原来源证明与所有保存/清理收口后才启用账号。原submitting标记与新增草稿记录同时参与首次保存隔离。
- 任一提交失败保留同一操作、已保存账号ID及原文件；重复提交继续原阶段。已进入submitting继续拒绝取消/删除。NODE激活只接受该次原授权摘要及中央已落库的真实ID，前置阶段不创建占位正式账号。
- 完整删除先持久deleting意图，核对无正式/软删除账号、历史及其它实际工作，再停止/移除原专属角色、清Node专属环境/缓存/profile。Node在环境外保存最终删除回执，响应丢失可按原范围查询。中央收到实际清理事实后才清本地镜像、条件删除记录与NULL环境，最后清原草稿标记。
- Node删除意图与最终回执位于独立`node-draft-deletions/<environment>/<operation>.json`，准备入口遇到原环境删除记录即关闭重建。删除持有原环境锁与节点准备锁，防同名profile在跨环境准备时被重新认领。中央先持久Node最终回执，再清本地副本并在短事务条件删除记录；最后标记失败仍凭环境外回执展示deleting并允许同代重试。
- Scope尚未返回时，恢复沿中央原私有准备，在Node先持久`recovery-only`并永久禁止旧操作的新启动/输入。仅核对或完成同一资源准备后立即调用原停止路径，返回真实Scope及停止事实。过期工作只获得收口能力，后续重登另建SID/逻辑代次。原恢复准入继续使用部署活动门禁。
- 原准备本身失败时，完整删除应只依据原冻结准备及Node实际资源事实收口。generation=0的未启动准备另用独立清理身份，继续拒绝正式执行Scope与有限输入证明。清理不以再次成功配置代理、资源或启动容器为前提；原NULL、正式/软删除、历史与专属资源核验继续保持。该故障分支在512暴露后按同一清理范围继续实现。
- 准备清理请求`DraftLoginPreparationDelete`仅含原node_key、Work与可选已停止前代。Node要求当前操作没有有限证明和实际登录登记，核对自身原私有准备；新准备尚未到达时，仅允许无遗留资源，或按前代私有配置摘要/版本及严格停止事实认领原NULL资源。回执采用独立`login-draft-preparation`身份并携带Node观察的实际代次与准备摘要。普通Scope/Grant/PTY继续拒绝此用途。
- 中央清理重放在草稿和环境行均已同事务删除后，只收口原环境标记；禁止再次按名称删除可能已被新环境复用的profile。新登录和普通profile导入共用名称保护，活动、取消保留及尾段清理中的节点草稿均不能绕过原登录提交。
- 中央本机准入和`owns_local`通过v4记录识别NULL节点草稿；v4尚未登记时沿原私有节点标记保持关闭。环境页仅查询原Node摘要、展示冻结位置，并把草稿操作引导回任务账号页。代理引用沿同一私有准备读取器核对Work/Node/前代，不读取中央sender/HOME；原材料缺失或代次跨越继续保留引用不完整保护。

### 远程登录与明确重授权的逐层接入

先接已有独立SSH账号的明确重授权，使用具体AccountLoginWork、原login:SID来源与login操作族Scope，冻结原账号稳定身份、实际CLI版本和授权TTL。该工作不认领模型额度，不修改当前账号归属；Node沿原begin_login在本环境.v3-login/SID暂存新授权，保留旧HOME、设备及画像。实际启动、授权码投递、PTY输入、CLI认证检查和提交均复核原Scope、代次及有限证明；授权码只进入原stdin，持久回执不保存授权码或终端正文。

中央与Node先登记具体操作再启动原tmux。长交互期间由中央续接有限证明；断连、管理端或Node重启只恢复原工作观察与停止，不重发授权码、不虚构旧交互终端。提交在原owner锁下核对当前绑定和原身份，Node实际新授权经CLI auth status验证后才进入提交；新HOME/profile保存、中央镜像/授权证明和原实际终端释放分别记录，未知提交只查询原操作。原RT未知刷新只有在Node实际closed且完整原Scope确认后，才可在本次明确重授权路径结束旧中央执行占用；CredentialOwnership的refresh_pending保留到新授权来源证明完成。

已有独立账号提交先核对完整暂存OAuth产物与实际CLI认证状态，在原Node操作私有目录冻结授权文件，保存无令牌的摘要与提交阶段。随后沿原commit_login发布当前HOME并镜像Node profile；恢复使用同一冻结授权文件补齐原阶段，不再次调用OAuth。完整授权文件仅留在Node受控文件目录。中央只经原具体操作读取受信快照，镜像管理资料并登记新授权来源后发送同摘要accept；Node确认原tmux实际停止、删除本次暂存与私有授权副本后，中央才释放原工作占用。待确认提交拒绝普通取消与丢弃材料。
