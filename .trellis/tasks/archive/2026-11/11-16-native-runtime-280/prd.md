# 原生运行时增加 Claude Code 2.1.280 适配

## 目标

交付 Claude Code 2.1.280 原生运行时，并接通网关的 280/293 自动选择，使同一原生账号能够处理两版请求，保留 293 默认。

## 背景与已确认事实

- 用户说明：原有转发放行多个版本，293 是默认版本；希望先为 280 制作运行时。
- 传统链路独立执行版本准入与画像选择，客户端模式匹配 260、280、293，其他版本使用默认画像。证据：`services/gateway/src/service/version_profile.rs:200`，`services/gateway/src/service/gateway.rs:1986`。
- 当前原生账号入口为 `request_backend=native293`。证据：`services/gateway/src/service/gateway.rs:2413`、`services/gateway/src/handler/router.rs:948`。
- 原生正文仅接受 293 billing，进程握手与签名制品固定为 293。证据：`services/runtime/src/shared/native-input.ts:45`、`services/gateway/src/service/native_runtime.rs:921`、`services/gateway/src/service/native_release.rs:99`。
- 构建工具固定引用 293 来源、模块绑定和 Bun 基底。新版本须重新定位内部接口并核验原生发送行为。证据：`services/runtime/src/runtime/293/source-profile.ts:2`、`services/runtime/scripts/build-runtime.ts:6`、`.trellis/spec/runtime/backend/runtime-contract.md:235`。

## 需求

- R1：固定官方 2.1.280 的来源身份、实际 Bun 基底与内部接口，形成可复核研究记录。
- R2：沿用既有 CC 适配路线，覆盖结构化 Messages 输入、完整原生正文、原生构造与发送，以及原始响应返回。
- R3：核对主会话、子代理、压缩上下文，以及请求头、metadata、billing、原生 CCH、缓存位置、工具与 thinking 行为。
- R4：交付独立运行时及构建清单，记录来源、分发体、执行体、依赖集合、体积、启动与暖复用时间。
- R5：网关按既有版本选择设置自动分流 280/293。客户端模式精确匹配原始 Claude UA；普通 API 的缺省回退沿既有默认画像，出厂为 293。账号模式沿最终账号画像选择受支持运行时。
- R6：使用合成凭据、隔离 HOME 与本地 TLS 回环验收，区分中间组装与实际出站证据。
- R7：同一账号交错或并发使用两版时，共享原有并发、RPM、凭据所有权及账号资源预算；暖进程、映像、缓存、模板和版本诊断按实际运行时隔离。
- R8：保留旧 `native293` 配置的可读性及原生后端选择，管理界面准确展示自动匹配能力、各版真实准备状态与失败原因。
- R9：构建、镜像安装、制品核验、准备、内核升级及回退按源版本绑定执行体。请求目标版本缺失或准备失败时返回受控错误。恢复模板必须通过对应版本的独立准入。

## 验收标准

- [x] A1 / R1：来源、模块及接口记录可复核；错误摘要和未知布局明确失败。
- [x] A2 / R2-R3：普通 API 与 280 原生正文的适用矩阵通过，覆盖上下文、工具历史、thinking、流式、取消、响应保真和多轮复用；实际出站 CCH 经独立核对。
- [x] A3 / R4：最终产物脱离源码与提取目录完成请求，身份清单完整；体积沿现行预算验收，时延记录实测结果。
- [x] A4 / R5：293 相关回归通过，默认选择行为保持一致。
- [x] A5 / R6：保留回环原始证据，报告明确采集阶段、隔离方式及使用合成凭据的事实。
- [x] A6 / R5、R7：同一账号 280/293 交错、多轮与并发回环发送到对应执行体；配置热刷新和重试沿冻结版本；账号总槽位与物理进程计数始终遵守原限额。
- [x] A7 / R8：历史 `native293` 配置可用；账号界面、准备状态及请求诊断准确呈现实际版本，覆盖迟到结果、版本不符与部分就绪。
- [x] A8 / R9：源版本、签名、摘要、握手与执行体错配均在模型发送前拒绝；准备、升级、取消、回退、模板失效及有限预算行为具有版本隔离证据。

## 范围边界

本轮包含 280 运行时、网关自动选择、账号 sender 多版本池、安装及升级合同与必要管理页面调整。生产部署、真实账号推理与其他 CC 版本适配另行安排。

## 已确认决策

- 用户于本轮明确选择同时接通网关 280/293 自动选择。
- 原生运行时适配集合为 280 与 293；传统转发沿既有版本准入和画像规则运行。
- 其它已准入客户端版本的普通 API 保留现有 293 兼容路径；完整原生正文仍按其版本严格校验。
- 请求目标版本的运行时失败采用受控错误，版本选择在本次请求内保持冻结。
