| 场景 | 观察结果 | 验收 |
| --- | --- | --- |
| A 绑定且繁忙、B 空闲 | 老会话等待／拒绝仍绑定 A，新会话可进入 B | AC1、AC3 |

| 不同 Token 同 SID、无 SID | Token 隔离，无 ID 不制造虚假绑定 | AC2、AC8 |
| 突发跨分钟 | 按间隔提交，无积攒／补发 | AC4 |

| 重启和 RPM 更改 | 有效绑定、发送状态保留，新配置不透支 | AC1、AC4 |
| 队列后再等环境／发送 | 共用期限，取消／超时释放资源 | AC5 |
| SQLite 竞争、PostgreSQL 并发、存储故障 | CAS 正确、原子回滚、故障关闭、无锁内网络等待 | AC2、AC4、AC5 |
| 持续热点、近优账号、未知额度 | 老会话稳定，新会话分担，未知不获优惠 | AC6、AC9 |

| 模式切换、旧字段、非法设置 | 字符串设置原子生效，智能与旧评分可区分 | AC7、AC9 |
| 单会话多请求、阶段变更、上游池槽位 | 会话／请求／槽位独立统计，等待原因和实际状态一致 | AC10 |

## 验证命令与环境

实现后至少执行：

```bash
cd cc2api
cargo fmt --check
cargo test --locked
```

前端变更后执行：

```bash
cd cc2api/web
npm run build
```

- 新存储测试至少运行 SQLite；本任务涉及并发持久状态，另外实际运行隔离 PostgreSQL。沿现有 ignored 数据库测试模式提供专用临时 DSN，禁止使用生产库，未运行不得报告通过。
- 使用受控时间和本地 mock runtime／sender 验证提交时刻、断连和流式透传，不使用真实账号或模型压测。
- 前端构建之外检查实际页面的设置保存、模式和诊断展示；缺少验证环境须据实记录。
- `task.py validate` 只校验任务上下文，不能代替上述行为验收。
