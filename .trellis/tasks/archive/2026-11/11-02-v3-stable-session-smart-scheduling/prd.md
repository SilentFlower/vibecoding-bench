# v3 稳定会话绑定、平滑发送与智能调度

## Goal

改造 v3 API 网关的账号调度：老会话稳定绑定，新会话按承载能力准入，请求平滑发送，通过有界等待减少频繁切号和瞬时集中发送，并可视化当前负载、发送节奏及会话状态。

## Background

- 用户要求三个方向：老会话稳定绑定与新会话准入、平滑发送、参考 `/root/project/codex-proxy-rs` 的智能调度。
- 用户已确认本轮仅覆盖 v3 API 网关到账号 sender，原生 CLI、项目和养号维持现有独立出口。
- 上一轮建议的第 4、5 项暂不做：不独立扩展上游错误重试／迁移策略，不改造官方缓存配置与协议。
- 老版 7-19 的运行记录仅说明需要关注负载热点，不能据此认定封禁原因，也不能代替 v3 源码证据。
- 用户补充要求平滑发送与当前账号会话可视化，本轮纳入同一调度任务。

## Scope

- v3 API 网关的会话绑定、账号准入与选择、并发／RPM 等待、环境就绪后的发送许可。
- 与上述行为直接相关的持久化状态、配置、管理端诊断和行为验证。
- 账号总览与详情的发送时间轴、当前会话分布、逐会话等待／执行状态可视化。
- v3 默认启用智能排序，保留旧评分排序作为回退；回退继续执行稳定绑定和发送限制。

## Requirements

- **R1：稳定绑定。** 对携带可解析显式会话 ID 的请求，账号仍满足身份、权限和可用性约束时保持绑定；本地并发繁忙、RPM 等待、队满或超时均不得单独导致换号。不同 API Token 的会话隔离；并发首次认领只能确定一个账号，有效绑定可跨网关重启恢复。
- **R2：新会话准入。** 先检查资格、容量和预计等待，优先进入能立即接纳的账号；全部繁忙时只能进入有剩余容量的有界队列，无可接纳容量则明确拒绝。等待不提前消费发送名额。
- **R3：平滑发送。** 按账号现有 RPM 和加权并发约束真实提交；环境唤醒、分钟切换、网关重启及既有重试不能造成积攒名额后集中补发。RPM 非正值沿用现有无限制语义。
- **R4：完整调度。** 借鉴参考仓库的资格过滤、会话亲和、容量准入、真实反馈、近优轮转和等待生命周期，不能仅增加评分项。健康和延迟来自实际请求，不发额外模型探测。
- **R5：有界等待。** 准入等待共用一个截止时间，不因等待层或重试重置；默认 120 秒，可向下配置。上游已开始后的长流不受准入计时器中断。超时或队满返回可解析的 429 和重试提示，保留已有绑定；调度状态存储故障返回 503 并停止新增发送。取消、失败和结束均不得泄漏资源。
- **R6：兼容与诊断。** 保留 Token 范围、人工禁用、真实额度门禁、优先级、加权 FIFO、身份快照、流式转发及既有故障处理合同。管理端展示当前模式、容量、等待原因和选择依据；本地拒绝不能误报为上游故障。
- **R7：缓存连续性。** 对有会话 ID 的请求保持账号连续性，不修改上游缓存参数和正文前缀。无显式会话 ID 的普通 API 请求不能依靠提示词或小时指纹获得稳定会话承诺。

- **R8：可视化。** 账号总览显示绑定／活跃会话、阶段请求数、并发与发送就绪状态；账号详情提供最近提交时间轴、下一可发送倒计时、分页脱敏会话列表和等待原因。绑定会话数、活跃会话数、请求数、上游 Session 池槽位分别标明。沿用 5 秒刷新节奏，可见时更新；未知、过期、截断和重启后的历史缺口明确展示，不能把预计时刻画成真实发送。

## Non-Goals

- 不增加上游重试次数、故障换号条件、凭据恢复或永久失效迁移策略；已有重试的实际发送仍受本轮发送限制。
- 不修改 `cache_control`、官方缓存 TTL、提示词与工具前缀、上游 session 池、HTTP／TLS 画像及正文改写。
- 不改造原生 CLI、项目和养号的独立出口；本轮预算不宣称覆盖这些流量。
- 不引入参考项目的 Provider 插件框架、OpenAI continuation 语义或新的强制 Redis 依赖；不扩展为多网关实例的全局并发调度。
- 不修改参考仓库，不部署、重启或改写线上配置，不恢复暂停账号，不使用真实账号进行模型压力测试。
- 不建设长期监控平台，不查询官方账号的完整聊天记录，不新增清除绑定、强制迁移或取消上游请求的管理操作。
- 不承诺通过某个 RPM 数值或算法保证账号不会被停用，也不承诺每个请求都命中上游缓存。

## Acceptance Criteria

- [x] **AC1／R1：** 原账号繁忙、队满、RPM 等待或超时时，已有会话不因此迁移；重启后有效绑定仍可恢复。
- [x] **AC2／R1：** 同 Token 同会话并发首次认领只有一个有效账号，不同 Token 不串号；旧响应不覆盖新绑定，活动绑定不被清理后重新认领。
- [x] **AC3／R2：** 新会话优先进入有即时容量的账号；容量竞争通过真实许可裁决，全部繁忙时有界等待或明确拒绝，不先扣 RPM。
- [x] **AC4／R3：** 突发请求跨分钟、冷环境同时就绪、网关重启及既有重试时，实际提交间隔符合配置，不集中补发。
- [x] **AC5／R5：** 多层等待共用期限，队满／超时为可解析 429，状态存储故障为 503；取消、超时、CAS 冲突、失败和流结束无资源泄漏。
- [x] **AC6／R4、R6：** 真实负载、有效额度、健康和响应头延迟影响新会话选择，未知数据不获虚假优惠，近优账号可分担新会话；本地拒绝不污染健康，无额外探测。
- [x] **AC7／R6：** 模式切换、设置默认／校验／热刷新、权限、额度、优先级、身份快照、JSON／SSE／压缩原始字节及既有故障处理回归通过；非 v3 不被新调度接管。
- [x] **AC8／R7：** 显式会话 ID、无 ID、本地 mock／缓存命中均有验证；无 ID 不伪造会话，本地响应不扣真实发送名额或产生虚假上游反馈，缓存协议及改写结果保持原合同。
- [x] **AC9／R6：** 管理端区分智能与旧评分并能解释等待；验证覆盖多账号、多会话、持续热点、取消、冷启动和重启，不能只看构建。
- [x] **AC10／R8：** 账号总览和详情展示真实绑定与阶段状态；同一会话多个请求不被误算为多个会话，上游池槽位独立标示。时间轴只含真实提交，倒计时不代表预订，未知／陈旧／截断／重启缺口可辨识。分页、管理员鉴权、隐藏暂停刷新及失败显示通过验证，读取不改变调度或发起模型探测。
