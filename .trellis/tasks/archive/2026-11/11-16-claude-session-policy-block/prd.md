# Claude 会话策略封禁与管理记录

## 目标

Claude 会话首次出现明确的上游策略拒答后，在配置的封禁时长内由网关本地拦截该会话后续请求，并提供管理列表和历史记录。

## 背景与已确认约束

- 用户确认按会话封禁，并要求封禁时长可配置，默认 24 小时，同时可查看封禁情况与记录。
- 前序讨论确认会话身份为调用方令牌与客户端真实会话 ID 的组合，拦截在选账号及访问上游之前发生。
- 网关存在上游 session 池映射，同一上游 session 可承载多个客户端会话；封禁必须依据改写前的真实客户端会话。
- vm2api 的拒答缓存可作为行为参考。本功能的隔离单位为会话。

## 需求

- R1：识别结构化上游错误中的策略拒答，覆盖普通 HTTP 错误及流式 SSE 错误；截图中的 safeguards / reasoning_extraction 类拒答纳入识别。两类现有转发后端均适用。
- R2：首次明确拒答建立会话封禁；后续请求命中封禁时本地返回机器可识别的错误，停止向上游提交该请求。
- R3：支持配置自动封禁开关与封禁时长，自动封禁默认开启、时长默认 24 小时。设置位于“系统设置 → 会话与调度 → 会话策略封禁”，按分钟输入正整数，默认 1440 分钟；保存后对新封禁生效。重复拦截保持原到期时间，封禁到期自动允许后续请求再次进入正常处理。
- R4：管理端在“网关 → 请求记录”下方增加“会话封禁”入口，提供列表及记录，展示会话匿名标识、所属访问令牌、触发账号与模型、触发原因、开始时间、到期时间、状态及本地拦截次数，支持状态筛选、匿名标识搜索和分页查询。状态为封禁中、已到期、已解除；管理员可提前解除单条封禁，历史记录保留。
- R5：封禁记录持久保存，重启后有效封禁继续生效；不同调用方、不同真实会话隔离。
- R6：保留已有账号调度、会话映射和协议转发合同；封禁状态针对客户端会话。
- R7：对携带同一真实会话身份的消息请求和 token 计数请求执行封禁检查；计数请求本身不创建封禁。缺少可靠会话 ID 的请求沿用现有流程。
- R8：列表仅读取安全摘要及原因分类，时间按浏览者本地时区展示；提供当前请求诊断关联入口。封禁数据访问失败时返回本地临时故障，避免把封禁状态未知的请求放行上游。
- R10：界面沿用现有控制台视觉、组件和交互，复用表格、分页、设置表单、确认弹窗和操作反馈，覆盖桌面及移动端。
- R9：到期或解除后再次发生明确上游拒答时创建新一轮封禁记录。管理员关闭功能时停止自动封禁与本地拦截，既有历史保留。

## 验收标准

- [x] A1（R1、R2）：明确策略拒答触发记录，后续相同会话请求由本地拒绝；上游调用计数保持不变。
- [x] A2（R2、R5、R6）：不同会话及不同令牌可正常请求，共用上游 session 的其他会话独立判断。
- [x] A3（R3）：新安装默认封禁 24 小时，设置可保存并生效；到期后请求进入正常处理。
- [x] A4（R4、R5）：管理列表展示有效与历史记录，分页、时间和状态一致，重启保留记录。
- [x] A5（R1、R6）：普通参数错误、认证失败、限流及正常响应保持现有行为；普通和 SSE 两类策略拒答均可识别。
- [x] A6（R3、R4、R9）：重复点击“继续”只增加拦截计数；手动解除、自然到期和重新触发保留各轮历史；修改默认时长保持已有记录的到期时间。
- [x] A7（R7、R8）：封禁会话的计数请求本地拒绝；封禁查询失败本地返回 503；排队中的请求在真正提交前复查。
- [x] A8（R4、R8）：桌面及 390px 管理列表可操作，空态、加载失败、翻页及解除确认正确，公开响应与日志仅包含匿名会话标识和原因分类。

## 范围外

- 上游封控解除、内容改写、自动换会话重试。
- 按设备、账号或所有相似正文扩大封禁范围。
- 线上部署与真实账号拒答触发实验。
- 主动取消已提交的请求，以及追溯撤销历史后台遥测。
