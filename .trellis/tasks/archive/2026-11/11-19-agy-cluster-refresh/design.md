- AGY 来源第二父：`48f6029e19bebfa89a541d3703801f6c861678c0`。

## 冲突处理

1. `services/orchestrator/main.py`：同时保留 `cluster_service.start_synchronization(...)` 和 AGY 登录清理任务。退出时沿现有清理顺序关闭各自资源。节点同步由 `ClusterService.close()` 关闭。
2. `deploy/flower2api/test_system_release.py`：按实际使用合并签名、下载重定向、镜像重建及 AGY 制品校验导入。保持全部测试可发现。
3. `account-runtime-v3.md`：按完整场景整合节点同步、暂停迁移、AGY 执行位置和请求记录合同。采用最新 `data_policy=in_place`，保留账号资料、原操作及租约。
4. `platform-online-update.md`：保留上游临时 SQLite 迁移磁盘索引合同，补齐已有 bench5 / gateway6 来源映射与宿主导入闭包。

## 自动合并审查

- `account_runtime.py`：检查大画像读取、文件并发变化检测及 AGY 账号环境路径共存。
- `system_updates.py`、`system_update_host.py`：检查维护排空覆盖实际执行位置；暂停迁移核对停止、身份和租约后保持原游标；节点换批遵循上游原地策略。
- 网关 `runtime_bridge.rs`：保留节点同步 POST 权限和 AGY API 路由边界。
- 前端 `api.ts` 与 UI 合同：保留节点管理同步操作和 AGY 平台状态、环境维护及诊断展示。
- 以共同基线计算交集清单，逐项记录审查证据；同时核对自动合并结果的制品定义来源。

## 数据兼容

- 已核对两侧 bench/gateway 1–4 的注册项一致。实施时验证冻结定义原字节及摘要。
- bench5 为 AGY 环境，gateway5–6 为账号平台及请求记录，沿既有增量使用。
- `cluster_archive_schema.py` 属于每次迁移私有临时目录中的索引，不插入业务迁移链。
- 复用既有旧版本读写演练方式，按实际源摘要判断历史证据可复用性。

## 验证与恢复

- 所有验证采用临时数据库、本地服务及隔离夹具。外部模型预算为 0。
- 先执行受影响行为回归和定义扫描，再执行适当的部署、编排、Rust、Web 与页面验证。新增失败在本任务范围内修复并重检。
- 主要风险为自动合并产生的行为遗漏、陈旧合同覆盖原地换批、环境代次校验顺序变化以及迁移冻结来源漂移。
- 合并前记录 HEAD、索引和工作区状态。失败按实际合并状态恢复至冻结上游或保留现场继续修复，始终保护任务材料与其他工作。
- 实施阶段产生待评审结果。后续提交和推送由精确 Git 计划单独核对范围与目的分支。
