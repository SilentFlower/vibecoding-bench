# AGY 集成分支适配最新 Flower2API 集群改动

## Goal

让现有 AGY 集成功能兼容最新 Flower2API 集群能力，形成可合入的集成分支。

## Background

- 用户要求修复最新 Flower2API 改动与 AGY 集成分支的冲突，继续采用 AGY 接入现有能力的方向。
- 本轮源分支为 `merge/agy-into-flower2api`，冻结提交 `48f6029e19bebfa89a541d3703801f6c861678c0`。上游冻结为 `92ea67e805c4b25b1feba0fd435aadbb9d3c39fe`，包含 v1.18.3 发行准备。共同基线为 `0764b5fa75e0df6c5c12969fdc40b53d3bbf734c`。
- 预演发现 4 个文本冲突，涉及编排启动、发行测试导入、账号运行时合同及在线更新合同。完整记录见 `research/merge-inspection.json`、`research/merge-tree.txt`。

## Requirements

- R1：保留最新节点自动同步、跨主机迁移恢复、暂停迁移维护、已取消目标副本核对及实际账号镜像批次校验。节点组件换批遵循上游原地切换行为。
- R2：保留 AGY 登录清理、账号环境、凭据交接、API 转发和请求记录能力。维护继续按实际执行位置路由并校验环境代次。AGY 维持中央本地执行边界，与工程任务及养号保持原有隔离。
- R3：保持两库已发布步骤 1–4 的标识、来源及摘要冻结，延续 bench 第 5 步、gateway 第 5–6 步的 AGY 增量。临时迁移磁盘清单沿用上游独立临时库合同。
- R4：同步代码和可执行合同，审查自动合并的共同改动，避免启动任务遗漏、更新排空遗漏、维护状态丢失及发布定义来源遗漏。
- R5：以最新上游为第一父提交建立本地集成分支，交付可复核改动及验证证据。沿用 v1.18.3 发行元数据。

## Acceptance Criteria

- [x] AC1 / R1：节点同步启动与关闭、原地换批、暂停迁移维护及恢复、取消目标和账号镜像批次相关回归通过。
- [x] AC2 / R2：AGY 登录清理和环境维护、凭据及请求记录回归通过；真实执行位置与上下文同时保留；代次不符请求在维护租约前拒绝。
- [x] AC3 / R3：两库冻结步骤与上游一致；新增链完整；旧库升级、重复执行和兼容读取证据有效；临时清单通过定义扫描。
- [x] AC4 / R4：4 个冲突及共同改动完成审查；部署测试、受影响编排测试、网关检查及前端构建通过。涉及页面交互时完成对应浏览器回归。
- [x] AC5 / R5：产物基于两个冻结提交，记录实际差异、测试结果和遗留风险，通过 Check-All 后进入 Spec 与精确 Git 计划流程。

## Non-Goals

- AGY 远程节点执行、新产品功能、真实账号与付费模型调用、生产部署及正式发行。
- 迁移历史实验版本 `bench.agy-environments.2`。
- 外部模型调用预算为 0，使用本地隔离夹具与模拟服务。
