# Claude Ultra 适配、9-17 免登录迁移与旧版退役

## 目标

让 v3 与 ai-fund 正确识别 Claude Ultra，免重新登录接管旧版 9-17，并在迁移验收后永久删除旧部署及数据。

## 原始需求与已确认决定

1. 用户要求检查和适配 v3、`/root/project/ai-fund` 的 Claude 新套餐分级，并把旧版 9-17 完全迁入 v3，明确“不要重新登录”。
2. 用户回复“按你建议来”，选择只迁账号登录态、原 CLI 身份、代理与账号配置，不迁历史任务、会话、工作目录和抓包。
3. 用户进一步要求清理旧版镜像、容器与挂载；在已展示旧数据约 7.4 GB、含 17 个账号记录、11,115 个任务、11,116 个运行后，明确回复“删除吧 不归档了”。该决定取代此前保留旧历史的安排。删除在迁移成功及旧入口退出后执行，不再另行询问同一删除范围。

## 背景与证据

- 官方 Max 20x 自动转为 Ultra，已验证 Ultra 无 5h 限制，未验证账号仍可能有临时限制；仍有通用周额度和 Fable 周额度。来源：https://support.claude.com/en/articles/17728952-what-is-the-ultra-plan （2026-11-02 核对）。
- v3 的 `cc2api/web/src/components/Accounts.vue:1423` 无 Ultra 选项；`rewriter.rs:3808`、`telemetry.rs:2068` 将 max 一律映射 20x；`model/account.rs:197` 无独立真实分级字段；`orchestrator/main.py:945` 丢失 profile 中的 rateLimitTier。
- ai-fund 的 `worker/src/pools.js:532` 与 `frontend/src/views/Pools.vue:506` 不识别 Ultra；合成归一化测试将 ultra 转为 null。
- 旧 bench 9-17 为 22，旧 gateway 为 42。只读核对时 AT 有效、RT 齐全，profile 与 gateway 凭据相同；目标无同名或同身份账号。官方登录产物仍为 max/default_claude_max_20x，不能把展示名直接当作协议字段。
- 原 CLI userID 合法但与旧 API device_id 不同。`main.py:9303` 与 `account_runtime.py:2639` 明确校验真实 CLI 身份；本轮采用原 CLI 身份，不复制旧 API 的不同设备值。
- 旧环境、引用和实际代码证据见 `research/findings.md`、`research/retirement-inventory.md`。所有生产状态均为时点快照，执行前重查。

## 需求

- R1：识别明确 Ultra、真实旧 Max 20x 与 Max 5x，保留其他套餐和未知档位；不把普通 max 一律展示为 Ultra。
- R2：保存、导入并传递真实 subscription_type/rateLimitTier，套餐展示与协议改写分开；凭据轮换和重复提交不覆盖新状态。
- R3：区分真实 5h 窗口、明确为空及数据未知，保留真实临时限制、周额度、Fable 和实际 429；未知不伪装为零用量或无限制。
- R4：复用 9-17 现有登录态、原 CLI 身份、代理与适用策略，不重新 OAuth 登录；源端退出、刷新收口后，v3 成为唯一活动所有者。
- R5：继承可迁账号配置，已知并发 4、RPM 40；迁移时以最新值为准。旧版任务和按小时养号计划不迁入 v3；额度阈值保留，v3 不自动新建养号迭代任务。
- R6：适配并部署新版本，迁移后验证 v3 身份、代理、策略、凭据所有权及号池展示；失败保留可核对状态，不恢复旧 RT。
- R7：永久清理旧版指定容器、归属明确且无保护引用的镜像、旧 bind 数据和命名卷，不归档旧数据库、历史、抓包或凭据副本。
- R8：删除前退出 ai-fund 旧 5674 来源，核对并等价切换或停用仍指向旧入口的下游渠道；保留现有 v3 来源、权限、分组和模型边界，不能靠未知故障推定已切流。
- R9：精确清理并留下无秘密的操作收据，按实际可用空间差核对释放量；当前 v3、其他应用与共享资源保持。

## 验收

- AC1（R1–R3）：真实 Ultra/Max 分级在两边一致，协议字段保真；临时 5h、无当前窗口、未知、周额度及 Fable 各场景通过验证。
- AC2（R4–R5）：9-17 在 v3 无重复授权即可使用，身份、代理与最终策略匹配，旧端无法继续执行或刷新；不自动迁入旧任务。
- AC3（R6）：Rust、Python 相关回归和两边前端构建通过，新版部署健康；无真实模型压力探针、无凭据进入日志或前端。
- AC4（R7–R8）：旧业务引用已退出，旧容器及确认的旧挂载不存在、旧命名卷已删除、无保护引用的旧镜像实际回收；没有历史归档。
- AC5（R9）：v3 数据归属、现有账号和其他应用复核通过，删除清单、已完成事实、空间差与最终健康结果可审计。

## 范围外

- 不改变新调度算法、RPM 平滑公式、会话绑定或全局 CLI 版本。
- 不迁移其他旧账号，不导入旧历史，不合并整库，不购买/变更套餐，不处理 API 赠金。
- 不全局 prune，不删除 v3 或其他应用，不整目录删除宿主源码仓库，不新增通用迁移/任意执行产品接口。
