# 总体设计

## 交付边界

三个子任务按套餐适配 → 账号交接 → 旧版退役串行完成。产品代码只由首项拥有；后两项以当前已部署接口、私有受控运维脚本和脱敏收据完成，不开通新产品管理入口。跨仓改动涉及 cc2api、vibecoding-bench 与 ai-fund；NewAPI 只等价切换或停用已证明的旧入口渠道，保留渠道身份、模型、分组和额度关系，不修改其业务代码或扩大授权。

## 跨层合同

原始套餐类型和真实分级进入 v3 持久化及 profile 同步，由明确规则生成展示；协议优先使用真实分级，兼容旧值时不能把回退值误当作套餐事实。5h 的空值/未知保留 JSON 语义，额度保护继续依真实观察。

## 切换与清理

源账号在途工作完成后退出旧调度，旧网关关闭新入口并经刷新锁收口；之后才向 v3 交接最新凭据。目标继承原 CLI 身份和代理、恢复策略并验收。ai-fund 与仍启用的旧入口渠道退出后，才能关闭旧服务并执行精确删除。用户已选择永久删除，不再保留旧历史或凭据备份；只留脱敏收据。

## 失败边界

任一前置验收失败，后续步骤不执行。凭据所有权不确定时隔离并重读最新状态，不用旧快照覆盖。清理开始后按逐项收据报告实际完成状态，不宣称数据可恢复。共享/未知资源不进入清单，当前 v3 数据与其他应用受保护。
