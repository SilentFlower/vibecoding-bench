# V3：合并项目与养号迭代导航

## Goal

通过一个“工程迭代”入口查看同一账号的项目迭代和养号迭代，减少顶层导航重复。

## Background

- 父任务：11-03-v3-credential-handoff-iteration-console。本子任务与凭据改造可独立验收，实施顺序排在其后。
- 用户原话：“项目迭代和养号迭代不能放一个tab里，在里面进行切换不好么”，随后确认“可以”。
- 当前两条路由已共用模板与 ProjectsUI，只在 namespace 和服务路径上区分；切换会卸载旧视图并清空账号选择，见 webui/app.js:56、webui/app.js:97、webui/projects.js:45。

## Requirements

- U1 导航：顶层只保留“工程迭代”；页面内显式提供“项目迭代”“养号迭代”切换，当前模式可辨识且支持键盘操作。
- U2 账号：切换模式时沿用当前账号，刷新页面后恢复有效的当前模式和账号；账号已不可用时准确提示并要求重新选择，不静默操作其他账号。
- U3 独立空间：两边项目池、配置、定时计划、运行记录、完成事实及数据路径保持独立。切换不隐式保存表单、创建配置、启动/暂停/停止迭代或复制另一空间的数据。
- U4 兼容：原 #projects、#warmup 链接、浏览器前进后退和账号页直达养号入口继续有效；统一入口默认展示项目迭代，刷新保留已明确选择的模式。
- U5 生命周期：只订阅当前视图的实时数据；快速切换、慢响应、弹窗和分页不串入另一个空间，卸载时释放 SSE 与定时器。
- U6 体验：保留原终端/交互记录、计划、模型、项目池、抓包与账号配置功能，深浅主题及窄屏都可使用。

## Acceptance Criteria

- [x] UA1：顶层只有一个工程入口，内部两个切换项及选中状态准确，键盘可操作，对应 U1/U6。
- [x] UA2：账号 A 在两种模式间往返、刷新、前进后退后仍选中 A；账号被停用/删除时给出准确提示，对应 U2/U4。
- [x] UA3：分别设置不同项目池、计划和历史，切换后内容准确；请求记录中切换操作只有读取，不产生启动、保存、停止或跨空间写入，对应 U3。
- [x] UA4：旧链接及账号页入口都进入正确模式，当前模式刷新后保持，对应 U4。
- [x] UA5：连续快速切换并延迟旧响应，只有当前空间更新页面；活动 SSE 和定时器数量不随切换累积，对应 U5。
- [x] UA6：两空间已有工作持续运行，终端/记录/分页/抓包/配置功能及深浅主题、窄屏回归通过，对应 U3/U6。

## Non-Goals

- 不合并后端 namespace、数据库记录、项目池或定时计划。
- 不新增双空间并排实时监控、不自动同步两空间配置、不改变后台调度。
- 不扩展为全站换肤或其他导航重构。
