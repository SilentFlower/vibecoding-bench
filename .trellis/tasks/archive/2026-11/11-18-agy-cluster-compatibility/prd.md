# AGY 与 Flower2API 集群版本兼容集成

## Goal

让 AGY 账号运行时与最新 Flower2API 集群版兼容共存，形成可合回 Flower2API 的集成结果。

## Background

- 用户原请求为合回 Flower2API 并查看集群版本冲突，完成检查后要求“能修复下让我们这个兼容下吗”。本任务承接该兼容修复。
- 来源为 `feat/agy-account-runtime@ca198ee979ec968bcd7d1a2063c872edb05850f7`；目标为 `origin/flower2api@0764b5fa75e0df6c5c12969fdc40b53d3bbf734c`。共同基线为 `6d4253a29f7a0ee6bbadc0809d5acb570b14781f`。
- 目标已包含 `feat/manual-node-cluster`，发布说明为 v1.17.2、bench4/gateway4。来源包含完整 AGY 工程交付、bench2/gateway6。原生供应商与生产部署验收由既有 EXT01—EXT07 承接。
- 合并检查确认两侧共同修改 37 个路径，文本冲突涉及 20 个文件。完整列表和内存数据库验证证据统一保存在本任务 `research/`。

## Requirements

- **R1 / 合并完整性**：保留集群版的节点归属、远程执行、登录草稿、升级和运行时版本展示；接入既有 AGY 账号、受管凭据、Gemini、同形体和请求记录功能。依据：`research/conflict-inspection.md` 的来源、目标和冲突文件列表。
- **R2 / 数据库合同**：保留目标已发布 bench1—4 及原 gateway 步骤的身份、摘要与顺序，追加 AGY 环境增量。空库与现有集群库均可迁移并保留账号、节点、环境、凭据和诊断记录。重跑幂等，迁移失败保持原数据及台账。依据：模拟树 `services/orchestrator/database-migration-registry.json:15`；两方向内存验证均返回台账版本或摘要冲突。
- **R3 / 发行与构建**：迁移定义扫描、执行器、签发校验、源码清单和镜像输入覆盖两套功能；保留集群版运行时版本读取和已有构建缓存。依据：模拟树 `deploy/flower2api/system_release.py:24` 与 `:38` 的同名赋值覆盖，`manage.py:539` 的版本/AGY 构建参数冲突。
- **R4 / 环境维护**：远程节点分发、凭据维护门禁、页面冻结的环境代次及两套后台资源收口同时生效。AGY 保持当前独立 API 环境、中央本机执行及 AT-only 工作副本边界。依据：模拟树 `services/orchestrator/main.py:8551`、`:14438`，既有 AGY 合同和集群按工程账号分配的合同。
- **R5 / 诊断与 UI**：实际执行节点及环境归属与 AGY 平台、凭据代次、工具轮和控制终态同时保留。历史缺失字段继续表达未知；两套账号和环境管理页面均能正常展示和操作。依据：模拟树 `services/gateway/src/model/request_diagnostics.rs:231`、`apps/web/src/api.ts:447`、`RequestDiagnostics.vue:361`。
- **R6 / 验证与交付**：覆盖双库迁移、目标旧程序兼容、两套运行时回归、Web 构建和真实本地管理入口。证据逐项关联验收标准，交付集成分支及精确 Git 计划。

## Non-Goals

- AGY 远程节点调度、工程任务或养号接入，以及新增平台能力。
- 旧 AGY 开发分支版本 2 数据库的自动台账转换。其链与已发布集群链分叉，继续沿严格校验受控拒绝；迁移真实此类数据库另行评审和授权。
- 生产部署、发版、真实账号操作及外部模型调用。本任务外部模型预算为 0。
- 原 Flower2API 工作区的本地改动整理。目标分支推进和远端推送沿后续精确 Git 计划授权执行。
