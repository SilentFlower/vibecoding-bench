# Brief — AGY 与 Flower2API 集群版本兼容集成

## Goal

- 让 AGY 与最新 Flower2API 集群版兼容共存，形成可合回的集成结果。

## Scope

- 修复 20 个冲突文件，并复核自动合并区域。
- 接通数据库迁移、发行构建、环境维护、诊断字段及管理页面。
- 完成回归、Check-All、Spec 评估和精确 Git 计划。

## Non-Goals

- AGY 远程节点调度、工程任务及养号接入。
- 生产部署、发版、真实账号操作和外部模型调用。
- 原 Flower2API 工作区本地改动整理、旧 AGY 开发库自动台账转换。

## Technical Overview

- 在当前工作区建立集成分支，合入冻结的最新集群提交。
- 保留集群 bench1—4，追加 AGY 为 bench5；网关保留原链并接入 AGY 的步骤 5—6。
- 合并唯一迁移来源表，同时保留节点路由、环境代次校验和两套诊断字段。

## Context & Decisions

- 集群基线为 `0764b5fa`，AGY 来源为 `ca198ee9`。
- 集群节点执行和运行时平台版本读取沿用现有实现。AGY 保持独立 API 环境及中央本机执行。
- 原 Flower2API 工作区的 323 项本地状态予以保留。
- 提交、推送及目标分支推进沿精确 Git 计划授权执行。外部模型预算为 0。

## Risks

- 旧 AGY 开发分支版本 2 台账与集群正式链分叉。此类库继续受控拒绝。真实此类库迁移需要独立方案。
- 自动合并存在迁移来源表覆盖风险，需要逐项语义复核。

## Acceptance

- 空库、集群旧库升级、旧程序读写、幂等和失败回滚通过；原记录及既有迁移摘要保持。
- 本机 AGY、本机 CC、远程 CC 的维护和请求路径回归通过。
- 节点及 AGY 诊断字段、环境页面兼容，相关 Python/Rust/Web 验证通过。

## Next Step

- 激活任务，进入实现路由并建立集成分支。
