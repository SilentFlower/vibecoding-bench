# Pi 中断自动恢复设计

## 目标与边界

同一条恢复链路服务 `projects` 与 `warmup` 两空间。复用 `ProjectsPi`、`ProjectsService`、事件表和计划调度，不增加任务队列、环境参数或数据库列。自动计划决定是否继续后台运行；人工停止与暂停始终优先。

本设计覆盖 PRD R1～R6。既有正常收尾、单轮时限、额度等待和服务重启接续保留，补充模型流不完整、可以确认来源的未知模型响应和 Pi 子进程意外退出的恢复行为。

## 现状与根因

- `images/pi-agent/host.mjs` 的 `unavailable(message, response)` 根据 SDK 失败终态、配置端点的真实 HTTP 状态和恢复头分类；失败助手与半截工具不会交给控制端执行。
- 普通推理与摘要共享 `recoverFailure`，有限重试后使用 `model_unavailable` 交给 Python。`Stream ended without finish_reason` 未命中当前分类，最终只发出无 `reason` 的通用错误。
- `orchestrator/projects.py` 的 `_run` 对通用错误将工作收口为 blocked；`_manual_retry_event` 只允许有限错误类别，因此通用错误同时失去自动和手动恢复路径。
- `_finish_model_recovery` 已有 60/120/300 秒退避和至少十五分钟的低频调度，恢复记录跨重启保存。`ProjectsPi.run` 的管道 EOF 目前直接返回 error，无法说明是子进程意外退出还是通信协议错误。
- `webui/projects.js` 已有计划时间与倒计时，能够复用；需要补足恢复原因和阶段，避免将模型冷却等同于必须人工处理。

## 故障处理决策

| 已确认事实 | 分类与处理 | 人工介入条件 |
| --- | --- | --- |
| SDK 失败终态为缺少结束原因、连接断开或同类传输中断 | 临时模型故障；复用有限重试、配置模型降级及持久冷却 | 无法安全收口原执行，或当前账号／授权门禁明确拒绝 |
| 配置模型端点返回成功 HTTP，SDK 记录未知的供应商结束码，且没有认证、请求、策略拒绝或禁止恢复证据 | 有来源的未分类模型响应；有限尝试后转低频等待 | 无法证明故障属于模型响应，或现场对账不通过 |
| Pi 已完成 ready 协议后意外退出，原执行可严格收口 | 控制进程中断；交给同一持久恢复调度 | 管道格式错误、初始化配置错误或无法核实的外部执行 |
| 真实限流、5xx、模型不可用等既有可恢复错误 | 沿用原恢复规则和服务端等待 | 当前账号门禁不可重试 |
| 认证、权限、错误请求、明确禁止重试 | 保存具体故障类别；不自动重复请求 | 修复原因后可显式重新预检，仍不得绕过身份／投递门禁 |
| 未确认终端投递、执行收口失败、身份或授权变化 | 保留现场及具体阻塞原因 | 自动对账确实不能确认时，提供对应处理说明 |

成功正文包含错误文字不参与分类；未知 Python 异常、工具回调异常和初始化失败不能凭“未知”推断可安全自动执行。真正上下文超限继续使用现有强制摘要与压缩后的单次续接规则。

## 数据流与实现位置

### 1. SDK 与子进程边界

- 扩展 `host.mjs` 的现有分类器，优先检查取消、真实硬错误、上下文限制、禁止恢复和非法等待，再识别断流及有真实模型响应补证的未知错误。
- 保留 `unavailable` 的分类返回形式及现有重试、降级、取消信号与截止时间，避免另建一条恢复循环。普通推理和摘要同时使用更新后的分类。
- 对模型失败发布有界的结构化故障码与可读消息，不公开原始上游正文或凭据。新增字段使用有限枚举；控制端不信任任意 `retryable=true`。
- `ProjectsPi.run` 区分已就绪后的意外 EOF 与读取／JSON／长度协议错误。只有就绪且通信协议正常的进程意外退出才能进入受控恢复；停止与超时返回原结果，不伪装成模型失败。

### 2. 控制端决策

- `_pi_event` 仅保存定义过的原因、故障码、当前代次及合法等待时间。复用现有 `model_unavailable` 持久恢复语义，新增细分故障码表达断流、响应不完整或进程中断。
- `_run` 必须先严格释放本代 CLI 与租约，再根据当前投递、身份、授权、账号门禁和已确认故障安排恢复。释放失败继续保留具体阻塞，不能用模型错误覆盖执行不确定性。
- 执行收口未确认的优先级高于已保存的可重试准备故障；页面明确要求环境对账，不能继续按准备故障安排恢复。
- `_finish_model_recovery` 继续采用三轮快速恢复后低频检查；同时保存具体原因，便于页面解释。服务端、模型冷却和账号门禁取最晚可执行时间，持久计数不因重启归零。
- 显式 `start` 对可信模型故障重检当前条件；错误类型本身不应让已修正条件永久失去重试入口。未知终端输入、未收口运行时、冻结合同和身份等独立门禁仍须全部通过。

### 3. 历史通用错误

- 为旧通用模型错误增加服务端受控诊断。候选必须是当前 work 绑定的最近错误，且没有更新的 started、manual_retry、gate_wait 或其他错误覆盖。
- 只读本账号、本空间原 Pi 会话的受限尾部；只接受完整 JSONL 行和 SDK 最后失败助手。核对会话归属、时间与原错误相符，拒绝目录越界、链接、坏文件、成功尾消息或不匹配证据。
- 旧断流证据只用于建立已核实的故障类别；没有证据时不统一解锁。诊断绑定原事件 ID、工作和控制代次，使用唯一事件键去重，保留旧错误记录。
- 文件核对不持数据库写锁。发布时再次核对控制所有者、当前工作、最近事件和全部门禁，以事务或等价原子发布保证诊断、工作可恢复状态及计划一致。
- 旧内容／冻结合同读取的 `ValueError/OSError` 只隔离本账号原目标，保留原错误与会话并显示固定内容核对提示；更新提示前复查代次、工作、更新时间和最近错误，避免覆盖新状态。单项诊断失败不能打断其他账号的启动恢复。
- 已启用计划且证据充分时安排原工作自动恢复；未启用计划时只提供有效的显式恢复入口。诊断不能打开被用户关闭的计划。
- 兄弟空间暂时占用账号时仍可保存本空间的只读诊断与检查计划；实际启动必须认领共享控制权，繁忙时顺延，不能因一次占用永久失去自动检查。
- 账号 10-23 采用同一机制，核对事件 51015 与原始会话证据；不写绕过门禁的生产 SQL，不创建替代 work。

### 4. 页面与公开状态

- 从既有持久恢复事件派生当前恢复摘要，公开字段限于已存在的 `phase/attempt/retry_at` 和有限故障码、可读说明；通过可选字段兼容历史响应。不将读取变成诊断或启动操作。
- 复用现有 SSE、页面时钟和 `schedule.next_at`，展示“模型响应中断，等待第 N 次自动恢复”或“连续失败，低频自动检查”及倒计时。
- 明确不可恢复的问题显示对应原因，例如“原终端输入结果尚未确认”；保留现有操作反馈和账号／空间代次校验。
- 若修改 `webui/projects.js`，同步 `webui/index.html` 对应资源版本。无需新增轮询、组件库或全局状态模型。

## 兼容、发布与回滚

- 原始会话、工具结果、终端动作、工作 ID、累计耗时、独立验收和账号身份都继续使用原记录。
- 新字段为事件 JSON 与公开视图的可选增量；旧模型恢复记录仍可读取。旧通用错误仅在受控诊断成功后改变恢复资格。
- 后端、Pi 入口和 WebUI 应随同一发布更新。上线与目标恢复需按项目既有发布 SOP 核对版本和门禁，代码测试通过不等于线上已恢复。
- 回滚先停止相关恢复计划并保留现场与数据库恢复点，再切回兼容批次；不得删除会话或批量改写 blocked。发布操作本身仍遵守其独立审阅门禁。

## 主要风险与验证依据

- 错把真实拒绝当作临时故障会产生重复请求：用硬状态、禁止重试、非法等待和业务正文负例回归约束。
- 恢复时重复工具或输入会改变业务结果：用真实 SDK 半截工具、已确认工具历史、投递审计和取消竞争场景验证。
- 旧诊断若套到新工作会解除错误的阻塞：用事件／工作／代次竞争、重复诊断、会话归属和时间匹配负例验证。
- 生产原 Pi 文件约 87 MB；诊断必须有界读取尾部，不能在 GET/SSE 或持锁状态下扫描全文件。
