# 多平台账号管理与统一凭据生命周期

## Goal

在既有账号界面完成 CC 与 AGY 平台账号管理、原生授权及受管凭据接入，保持账号身份、配置和凭据更新一致。

## Background

- 本任务承接父任务 `../11-18-multi-platform-account-runtime/prd.md` 的 R01、R02、R03、R06 及 R07 中账号开关的保存与回读，支撑 AC01、AC03、AC07、AC08、AC09。
- 凭据研究任务已完成。统一依据为 `../11-18-agy-managed-credential-contract/research/credential-contract.md`，本轮源码核对记录在 `research/current-contracts.md`。
- 当前账号模型没有平台字段，授权、刷新及额度接口按 CC 实现；账号去重只检查邮箱。
- 已验证 AGY 原生 OOB 授权、AT-only 运行及常驻 TokenSource 缓存。文件身份标签与 expiry 的原生宽松解析需要管理层额外核验。
- 用户已明确 AGY 与工程任务、养号执行的交互属于范围外。同形体开关按 AGY 账号独立保存，默认关闭。
- 用户已确认本轮复用现有账号、授权和凭据管理链路，通过平台适配接入 AGY。CC 的既有管理接口及凭据返回保持兼容。浏览器凭据回传的统一收口作为独立议题。

## Requirements

### A01 平台、身份及历史兼容

- 账号平台与模型、认证方式分别表达，按平台选择授权、凭据、套餐、额度和实际模型能力。
- 历史 CC 账号、绑定、策略、设备及运行语义保持兼容；迁移可重复执行，保留当前权威凭据。
- 未知平台输入、历史异常值及身份冲突有明确处理；平台隔离覆盖账号查询、去重及调用分派。同邮箱可分别属于 CC 与 AGY 账号，同平台重复身份拒绝创建。
- 本任务阶段新增 AGY 账号保持平台隔离，正式 AGY 请求接入由运行环境子任务实现。

### A02 原生授权与重授权

- 在现有授权流程增加平台选择，复用授权链接、授权码提交、状态和错误反馈交互，AGY 使用已验证的原生 OOB 入口。
- 授权会话绑定平台、目标账号、代理、操作及代次；关闭、超时、取消和旧异步回执保持隔离。
- 通过已认证账号状态核对真实身份；文件 id_token_email 仅作为元数据。AGY 使用带时区有效期，并在管理侧严格验证。
- 重新授权维持原账号、策略和绑定；错账号、错平台或旧操作结果拒绝导入。
- 复用现有管理接口的权限、授权结果和账号保存合同。平台参数缺省保持 CC 兼容语义，AGY 的授权码及私有原生材料遵循现有敏感数据边界。
- 日志、浏览器持久缓存、测试材料和任务资料保持脱敏；管理响应中的既有凭据返回行为沿用户确认的兼容范围保留。

### A03 唯一刷新所有者与代次

- 管理层按账号独占完整 RT，业务副本只发布 AT 与有效期。
- 同账号刷新串行，成功结果按当前权威代次原子保存 AT、可选新 RT 和 expiry；响应省略新 RT 时保持当前 RT。
- 刷新前持久化待确认操作，断连、坏响应及结果未知进入对账；rename 后确认失败保留已落盘新 RT。
- 并发编辑、过期回执、重授权及刷新结果按原身份和代次条件提交，保持当前权威状态。
- 本任务交付管理侧准入及恢复合同。真实模型认证失败、SSE 首包后换代、工具跨实际到期等业务集成场景交由后续运行环境及请求记录任务验收。

### A04 能力与账号界面

- 沿用当前账号页的视觉、布局、控件、分页、授权步骤和反馈。
- 套餐、额度与模型目录按实际平台能力显示，区分已观测、未知、过期和不支持，保留上游来源及更新时间。
- CC 的额度、遥测及原生预热功能按平台分派；AGY 凭据与模型不会误送 CC 上游。
- 表单刷新保持草稿、焦点与选择；切换平台和账号时隔离旧请求与旧授权结果。

### A05 按账号保存同形体开关

- AGY 系统提示词同形体开关按账号独立保存、回读，默认关闭。
- 开关位置沿用现有账号配置界面；两账号设置、保存结果与旧回执保持隔离。
- 文本转换、规则版本、真实出站验证及请求策略记录由同形体和请求记录子任务交付。

## Acceptance Criteria

- [x] AA01：历史 CC 账号迁移后身份、绑定、配置和授权回归保持；迁移重复执行结果一致。（A01、A04）
- [x] AA02：AGY 账号可在统一账号界面完成原生授权并形成持久私有登录态，真实身份得到核验。（A01、A02）
- [x] AA03：同账号并发刷新只由唯一所有者执行；RT 轮换、原子提交、旧代结果和未知刷新对账有可重复验证。（A03）
- [x] AA04：重新授权、错账号回包、并发编辑及旧操作保持当前凭据和账号归属；故障恢复沿同一操作续接。（A02、A03）
- [x] AA05：列表及授权 UI 按平台展示能力，授权结果及凭据返回满足本轮确认的 CC 兼容合同；错误、取消、草稿和迟到回执回归通过。（A02、A04）
- [x] AA06：两个 AGY 账号分别保存和回读默认关闭的同形体开关，关闭时保持当前请求行为。（A05）
- [x] AA07：AGY 账号在运行环境接入前保持隔离，CC 刷新、额度、遥测和请求链路回归通过。（A01、A03、A04）

## Non-Goals

- 正式 Gemini 业务路由、AGY 请求 worker 池及工具/SSE 接入。
- 同形体文本转换和请求记录 UI 的实现。
- 工程任务、养号执行及其与 AGY 的交互和适配。
- 生产部署、线上数据迁移、新一轮付费模型实验及 new-api 修改。
- CC 管理接口凭据返回的统一收口、旧脚本强制迁移及既有 CC 工程/养号业务重构。

## Dependencies

- 已完成的 AGY 凭据研究合同及固定版本原生授权基线。
- 后续运行环境与请求记录任务消费本任务的平台、身份、凭据及能力合同。

## 本轮交付验收边界补充

用户在四项修复重检后明确“无需我验收，下一步”。本轮按已完成的工程自动验证和固定原版启动/取消证据收尾，人工Google登录不作为本轮交付前置。真实Google授权、身份与刷新保持未验证状态，归入外部系统上线后验证，由后续运行环境任务或发布执行方在具备授权的测试账号条件时补验；预期为真实身份一致、能力可回读、唯一刷新和轮换结果原子保存，模型提交数为0。AA02的本轮完成依据为真实UI至固定原版的OOB链接/取消与合成身份、保存、重授权跨层回归，真实Google登录不记为已测。
