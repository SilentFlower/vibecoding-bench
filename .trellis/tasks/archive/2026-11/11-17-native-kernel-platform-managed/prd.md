# 请求内核随平台版本统一交付与切换

## Goal

每个 Flower2API 版本交付一套固定的 280／293 请求内核，账号随平台升级和回退自动采用对应组合。

## Background

- 用户已确认统一由平台版本管理内核，收口独立检查更新、版本选择、候选准备、激活、回滚和恢复操作。
- runtime 源码已在 services/runtime。293 构建、内核发现和下载仍引用旧仓库 SilentFlower/cc-runtime-bridge。
- v1.14.0 线上核验发现账号10、12的 beta.6 独立选择在升级后保留；用户手动切至 beta.7 后四账号293／TLS／CRIU均ready。
- 当前系统更新按已应用 sender 布局重建，部分历史单版登记在后续API准备时补齐。截图中的10-30环境因养号作业占用而无法完成这次补齐，出现发送前本地503；用户已明确将此遗漏纳入本任务。

## Requirements

### R1 平台绑定

- 每个平台版本固定两版的源版本、分发SHA和执行映像SHA。新建、升级重建、启动恢复、平台回退统一采用目标账号镜像的内置制品。
- 280／293自动匹配、账号模式和既有默认画像规则继续有效。

### R2 管理入口

- 环境页展示平台管理方式、内置版本和实际运行状态。
- 收口独立版本发现、候选和所有独立切换操作。旧页面的退役接口调用取得明确结果，下载、切换和租约副作用为零。

### R3 存量迁移

- 历史root及每版独立选择归一为内置，覆盖beta.6／beta.7、候选、旧布局和重复执行。双版安装表按实际镜像建立。
- 迁移遵守排空、唯一账号绑定、环境代次与维护租约所有权。活动请求沿原生命周期完成，停止环境保持停止。
- 中断旧操作按实际归属和活动收口。未知状态明确进入环境维护对账，保护其他维护租约。
- 迁移结果可由旧平台读取为内置选择，平台回退采用目标旧镜像的组合。

### R4 本仓库双版构建

- 两版均通过本仓库脚本、固定官方来源和隔离构建器准备。活动构建／发布／运行入口的旧仓库附件和版本列表依赖归零。
- 缓存恢复核对固定来源、实际制品及构建输入；相同输入复用已验收产物。
- 两版身份随同批镜像进入平台交付清单和既有签名发布流程。Python、Rust、Docker身份一致性在构建／发布前验证。

### R5 保留运行能力

- 保留预备、暖进程、账号容量、TLS采集、CRIU、空闲回收、请求诊断、422兼容及thinking签名修复。
- 执行仍受固定摘要、封存执行体、实际握手和源版本校验约束。
- 保持平台签名信任根、维护门禁、数据库兼容和历史发行读取合同。

### R6 升级维护阶段完成布局迁移

- 对原生后端，在升级的维护／重建阶段按目标镜像声明迁移完整安装表。双版本目标登记280和293；历史单版目标按其实际能力处理。
- 升级成功条件包含目标安装登记完整、制品身份核验通过及发送器实际就绪。就绪检查遵循既有容量和按需预热策略。
- 升级前运行中的养号／CLI作业沿原排空、超时和恢复规则处理，升级完成时具备目标发送器布局。
- 升级完成后，首笔280或293请求直接使用已迁移布局。后续养号作业正常运行时，API准备保持既有布局，避免再次因补登记要求环境重建而返回本地503。

## Acceptance Criteria

- [ ] AC1：两版随平台镜像交付且实际身份匹配清单；覆盖R1、R4。
- [ ] AC2：旧root/per-version选择和sender配置升级后归一到内置，双版登记完整，重复迁移一致；覆盖R1、R3。
- [ ] AC3：停止账号、在途长流、中断维护和外来租约保持正确生命周期和对账边界；覆盖R3、R5。
- [ ] AC4：回退历史平台后实际使用目标内置组合；覆盖R1、R3。
- [ ] AC5：页面只读展示版本与诊断；退役接口保持鉴权并零副作用；覆盖R2。
- [ ] AC6：冷构建和缓存命中均在当前仓库完成；损坏缓存、输入漂移和摘要错配明确失败；覆盖R4。
- [ ] AC7：真实双版网关消费者、混合容量、TLS／CRIU及签名修复定向回归通过；覆盖R1、R5。
- [ ] AC8：平台签名、旧库兼容、系统更新／回退验证保持通过；覆盖R3、R5。
- [ ] AC9：从仅登记293的旧配置升级至双版目标后，升级完成前280／293登记及发送器就绪核验通过；随后运行养号作业，首笔293和280请求均不触发布局重建或由此导致的本地503；覆盖R3、R6。
- [ ] AC10：升级前已有养号／CLI作业时按原规则排空或超时恢复；目标历史镜像仅支持293时登记与验收遵循其能力；覆盖R3、R6。

## Non-Goals

- 本轮实际软件发版、生产部署和线上账号现场切换。
- 新官方源版本、模型规则、原生协议及压缩配方。
- 历史发行删除、旧仓库归档和生产文件垃圾回收。
- 独立内核发行中心或新的下载服务。
