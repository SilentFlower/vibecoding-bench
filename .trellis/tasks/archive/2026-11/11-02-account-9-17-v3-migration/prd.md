# 9-17 免登录迁入 v3

## 目标与来源

复用现有登录态、原 CLI 身份、代理和账号配置，把旧版 9-17 交接给 us v3。覆盖父需求 R4–R6，依赖套餐适配先成功部署；迁移验收是后续永久清理的硬前置。

## 已确认范围

用户选择只迁账号和配置，旧任务、会话、工作目录及抓包不导入 v3；随后明确要求旧历史全部永久删除、不归档，由退役子任务执行。仅迁 9-17，其他旧号不迁入。

## 事实

旧 bench ID 22 对应旧 gateway 42；原 profile AT/RT 完整、检查时 AT 有效，目标无重复。原 CLI userID 与旧 API device_id 不同，必须按真实 CLI 来源进入 v3，不能直接冒用旧 API 的不同设备值。已知策略为并发 4、RPM 40；当前状态和最新值在执行前重查，相关证据见父任务 research。

## 需求与验收

- M1：不发起新的 OAuth 登录，不要求用户输入授权码；只传递最新凭据与真实原 CLI 身份，不重新生成 CLI userID。
- M2：先完成旧任务、续聊、登录和 API 在途请求收口，关闭旧调度及刷新入口，再交接最终凭据；同一时间只有一个活动刷新所有者。
- M3：继承代理、时区、并发/RPM、适用的账号策略及额度阈值。旧按小时养号和历史任务不自动转换为 v3 新任务，v3 养号迭代初始关闭。
- M4：按现有 profile 创建、CLI 身份导入、绑定和维护门禁完成目标接入；目标持久身份、代理和策略复核通过，原历史未进入 v3。
- M5：无秘密的迁移收据记录源退出、目标 ID/环境、身份和策略一致性、唯一刷新所有权及管理接口健康；真实模型压力探针为零。

## 范围外

不升级全局 CLI，不复制整库、旧 API Key 或旧设备伪装值，不改其他 v3 账号；旧资源删除归后续子任务。
