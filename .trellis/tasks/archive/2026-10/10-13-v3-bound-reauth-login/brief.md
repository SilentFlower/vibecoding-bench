# Brief — v3 关联账号重授权同步与登录终端改进

## Goal

- 让已关联账号重新通过 CLI 授权后同步新凭据，并能在终端断线后继续登录、方便复制授权链接。

## Scope

- v3 关联重授权、凭据同步、失败重试与提交结果对账。
- 登录终端连接状态、自动/手动重连、授权链接显示/复制/打开及隔离验证。

## Non-Goals

- 不调整 cc2api 上游请求、TLS 或遥测协议；不增加镜像和端口。
- 不操作旧版服务；构建发布和生产部署不包含在本次实现范围。

## Technical Overview

- 在原账号容器的 tmux 完成真实 CLI 登录，校验新身份后导入同一 cc2api ID，再同步 bench 凭据副本；主 CLI HOME 只保留访问令牌。
- 通过凭据锁、条件写入和提交回执防止旧刷新覆盖及重复提交；断线重取短票据连接原会话，链接从实际 CLI 输出中提取。

## Context & Decisions

- 采用推荐恢复规则：只自动恢复因 OAuth 凭证失效停用的账号；手动停用、限流、bench 启停、养号开关、阈值及额度观察保持。
- 日常 API 与养号继续独立；重授权期间仅暂停该账号新 API 入场并等待旧请求结束，活动 CLI/续聊拒绝开始重授权。
- 保留原绑定、固定环境和设备身份；代理沿用现有关联配置，凭据自动刷新仍归 cc2api。

## Risks

- 远端提交后可能发生断网或本地写入失败，需保留暂存及维护门禁直到结果确认；服务重启可能需要对账。
- CLI 输出差异需要验证；模拟测试不能证明真实 OAuth 成功或账号限制解除。

## Acceptance

- 同一关联账号获得新凭据；错登、取消、并发刷新和重复提交不会损坏关联或覆盖新凭据。
- 部分失败明确提示且可重试，结果未知时不假报成功、不提前放行；停用恢复符合上述规则。
- WS 断线后继续同一 tmux 登录，不重复登录或重放输入；取消、过期、退出后停止重连并清理资源。
- 完整授权链接可显示、打开、复制；HTTP 复制降级、窄屏和明暗主题可用，凭据不泄漏。
- 通过后端回归、隔离 Docker 与真实浏览器验证，保持未绑定登录、续聊及日常 API/CLI 并行行为。
