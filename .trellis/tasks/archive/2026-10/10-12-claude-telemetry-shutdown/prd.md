# Claude 遥测收尾与原会话状态保留

## Goal

让现有临时 worker 在收尾时给官方 Claude 客户端正常退出和发送遥测的机会，并保留原会话尚未发送的状态。

## Background

- 用户撤销了账号固定环境改造，选择先修复遥测问题；本任务独立于已取消的 `10-12-account-persistent-runtime`。
- 服务器 `10-11` 的九次运行确实观察到遥测批次请求和 HTTP 200 响应，不能将问题描述为所有遥测均未发送。HTTP 200 也不能证明每条事件均已入库。
- 缺陷及客户端原生机制见 `research/telemetry-evidence.md`；账号限制对比见 `research/account-hold-comparison.md`。账号被限制的上游原因未知，本任务不承诺降低封号概率。

## Requirements

- **R1：原会话状态保留。** 原 run 恢复、额度到期恢复和继续对话不得因初始化或清理而删除原会话待发送遥测；登录提交也不主动删除客户端尚未发送的遥测。高优先级缺陷锚点：`images/worker/entrypoint.sh:1630`、`orchestrator/main.py:7671`。
- **R2：正常收尾。** 正常完成、失败、超时、人工停止、额度暂停、继续对话关闭，以及登录会话关闭，应先让本次启动的 Claude 进程有界退出，再结束运行环境及代理；无进程、已经退出、重复关闭或收尾超时均可处理。高优先级缺陷锚点：`images/worker/entrypoint.sh:914`、`:1739`、`:1899`，`orchestrator/main.py:3295`、`:3546`、`:4605`、`:4774`。
- **R3：业务结果兼容。** 收尾产生的退出码或信号不得覆盖原任务的完成、失败、超时、认证失败、额度等待或人工停止结果；额度暂停仍保留原题、配置、产物、会话及代次保护，旧执行未完成清理时不得恢复第二份执行。
- **R4：原生发送与隔离。** 发送、重试、队列格式和会话筛选均由官方客户端处理；不得合并不同会话队列、改写事件身份、伪造事件或主动发送额外模型请求。同账号各 run 的状态仍独立，账号之间不得串用状态。
- **R5：可核查收尾。** 记录正常退出、强制收尾、已退出或未启动的脱敏结果及等待耗时，便于区别发送机会与发送成功；保留既有 managed OAuth 凭据所有权及配置白名单。

## Acceptance Criteria

- [ ] **A1 → R1、R4：** 原会话恢复后，预置的待发送状态仍在原位置且内容未被改写；同账号不同 run、不同账号均不会被新增逻辑合并或串用队列，登录提交不删除待发送目录。
- [ ] **A2 → R2、R5：** 延迟落盘和发送的进程替身证明：收尾信号发给本次 Claude，先完成退出，再停 worker 和 sidecar；已经退出、尚未启动及重复关闭均安全，拒绝退出时有界强制收尾并记录。
- [ ] **A3 → R3：** 覆盖正常完成、失败、超时、人工停止、认证失败、额度等待，原业务状态不因 harness 发出的终止信号或退出标记而变化。
- [ ] **A4 → R2、R3：** 额度暂停与继续对话关闭使用同一收尾契约；容器删除失败时继续阻止恢复，代次变化不误杀新执行，WebSocket 关闭不长时间阻塞事件循环。
- [ ] **A5 → R4、R5：** managed 账号仍由 cc2api 独占刷新；非绑定账号继续按凭据新鲜度回写；无额外模型请求、无假遥测、无敏感字段日志。实际发送情况只依据现有抓包中的请求和响应陈述。

## Constraints & Non-Goals

- 沿用临时 worker、现有 workspace 和 sidecar，保留抓包及养号入口；不恢复账号固定容器、全 HOME 共享或 sidecar 常驻改造。
- 不修改 cc2api、额度策略、选号策略、题目文本、权限模式、原 run/session/cwd 的归属规则，不绕过用户或官方关闭遥测的设置。
- 不实现跨会话队列代发，不承诺断网、进程被强杀、原生重试耗尽或服务端拒收时的必达性；已删除的数据无法补回。
- 本轮交付本地实现和验证；生产部署及真实账号主动验证不在当前执行范围内。
