# v3 后续 Roadmap

## 可配置的养号额度阈值

- 来源：2026-10-12 用户要求作为 v3 后续 roadmap；后续实施任务为 `.trellis/tasks/10-12-v3-warmup-quota-threshold/`。
- 当前状态：账号级阈值已完成本地实现、C 批次两镜像合成验证及完整质量重检；发现的配置/额度并发发布问题已修复。待更新规格、提交及发布，未更新线上部署，旧发布批次仍沿用真实用满保护。
- 目标：允许配置 5h、7d 的养号停止阈值；任一启用窗口达到阈值后不再投放养号作业，避免必须用到 100% 才停止。
- 已确认并实现：每账号的 5h/7d 阈值分别使用 1～100 整数，默认关闭；明确区分已用与剩余，例如已用 20% 对应剩余 80%。
- 已运行养号等已接受请求收尾后暂停，保留原 run/会话；未知或到期只允许一次正式养号请求更新，仍未知就等待，重启或重复保存不重复放行。仅作用于养号，普通任务、抓包、继续对话与网关 API 沿用既有规则。
- 沿用真实额度及 reset，不新增阈值探测请求，不把 reset 到期视为额度归零；永久认证门禁优先。
- 真实官方 CLI/OAuth 与实际额度仍需在后续部署步骤中明确授权并验收；本地合成验证不等同线上验收。
