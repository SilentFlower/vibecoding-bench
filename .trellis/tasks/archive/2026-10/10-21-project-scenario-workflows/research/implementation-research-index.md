## 影响方案的已确认事实

1. 现有内容版本只允许线性 `requires`，默认至少 100 项目／20 步，验收入口固定 `app.py` JSON 行协议；调度的长度计算本身可变。
2. 目前没有语义问答评分器或人工审核 API。已选同模型独立会话自动评审，程序规则优先、人工用于校准／抽查，不新增人工逐项审核系统。
3. 当前开发提示会公开首个程序断言的 expected，失败反馈会带完整内部报告。新任务必须显式分离公开材料、可反馈证据与隐藏判定依据。
4. 当前验收在候选 CLI 冻结时同步进行。共享账号并发满时不能同步等待新增评审，否则会互相等待；待评审事实应持久化，候选执行名额需释放。
5. 通过步骤会同时推进任务下标与代码检查点；新问答不能套用该接受事务。独立场景还需要独立起始代码与会话上下文，避免继承另一场景的未接受修改或答案。
6. 已有同会话／工作区接续、输入消费证明、逐段 token、严格释放和额度原 Run 恢复可复用；尚无完整候选的仅续验收路径或跨 Run 累计有效时间账本。
7. 当前每步最多三次尝试；有些启动／执行基础设施故障也会消耗尝试。新任务应按实际业务输入消费与失败原因计数，并单独限制基础设施恢复。
8. 当前公开输入 token 合计含缓存读写，页面又只展示部分字段；新分类统计必须保留原生分项与未知／部分已知状态，不能从合计倒推。
9. 当前项目管理器初始化依赖现行内容库，空库时历史 API 也可能 503。要承诺历史可读，必须解耦当前内容准入与固定历史读取。
10. 现有验收默认 30 秒／256 MiB、实际超时上限 60 秒；Typer 既有原生完整测试约 181 秒，Pydantic 既有宿主峰值约 348,636 KiB。环境档案应独立准备并实测，不能删测试或将 venv 塞入 128 MiB 源码快照兜底。

研究没有运行新测试、真实模型或生产操作。三项目仍是场景设计样板；正式内容、独立验收与模型结果分别推进和报告。
