# v3 养号额度阈值设计

## 边界与决定

用户已确认：账号级配置、5h/7d 独立启用；命中后等待已接受请求收尾，暂停并保留主会话；未知/到期只允许一次正式养号请求更新额度。整数百分比 1～100，NULL 关闭，默认关闭以兼容既有数据。普通任务、批次、抓包、继续对话和网关 API 不增加养号门禁，真实耗尽与永久异常继续优先。

本轮产品修改集中在 Python orchestrator、额度纯函数、Recorder、worker、固定环境上下文及 bench 页面。不改 cc2api 上游发送、选号、TLS 或 OAuth 所有权；管理镜像包含的新 bench 功能仍走现有 /runtime 桥。旧部署不更新、不启停。

## 现有链路

1. 账号养号弹窗向 `PUT /api/accounts/{aid}/warmup` 保存绑定、开关和间隔。
2. `WarmupScheduler.trigger_account` 检查 CLI/租约和共同额度，创建原 task/run 后排队。
3. `Scheduler` 在实际启动前重读账号和 run，执行 `QuotaGuard.admit`；真实观察由 Recorder/API 的独立文件消费进账号额度状态。
4. Recorder 请求阶段有共同门禁，响应头阶段观察额度；现有 pause.json 由 worker 消费、保存状态后以 43 退出。
5. `QuotaGuard._resume_account` 沿原 run、工作目录、模型/CLI/预算快照和主会话恢复。阈值需要在触发、实际启动、请求与恢复四处接入。

详细源码锚点见 research/current-behavior.md。以下字段与函数是拟新增契约，不是对现有定义的假设。

## 配置与迁移契约

在 `accounts` 新增 nullable INTEGER：

```text
warmup_quota_5h_limit_percent
warmup_quota_7d_limit_percent
```

扩展 `WarmupConfigIn` 与既有 PUT：JSON 整数 1～100 或 null；null 关闭，省略保留原值。拒绝 bool、小数、非数值和范围外值，不允许整数截断。请求字段类型错误使用现有框架错误语义，业务范围错误返回 400，校验必须在凭据/数据库写入前完成。

既有养号开关、间隔、绑定校验及锁顺序保留；阈值与本次既有配置在同一事务更新，重复保存相同阈值不清掉恢复机会。列表返回两个 nullable 配置字段及 `warmup_quota` 摘要，摘要包含启用阈值、命中/未知窗口、等待原因、可信恢复机会时间，不包含内部 identity、policy_key 或 source。

`_SCHEMA` 与 `init_db` 的 `_ensure_column` 同步补齐；新增字段默认 NULL，重复初始化不损坏历史表。运行中修改阈值后原子发布最新策略，后续请求使用新策略，已接受请求继续完成；执行来源与代次仍冻结，不能跨代沿用暂停或单次更新许可。

## 独立养号判定

在 `orchestrator/quota_protocol.py` 添加可测试纯判定，输入真实窗口、两个 nullable 阈值和当前 UTC 秒，输出低于阈值、命中等待或需要单次更新。通过现有 sync-quota-protocol.py 同步到 sidecar，保持两个构建上下文字节相同。

- 仅比较 five_hour、seven_day；不把 Sonnet/Fable 专项额度并入通用阈值。
- 已用比例 >= 阈值即命中，百分比不与剩余百分比混用。缺失用量不能按 0% 判断。
- 用量有限且非负、观察属于当前身份且 reset 未到期时可直接判断；缺少可信 reset 的已知高用量保持等待，不能用未知策略绕过已知命中。
- 多个未到期命中窗口取最晚可信 reset；任一缺可信 reset 时不生成猜测时间。
- 没有仍有效的命中时，未知或到期窗口进入单次更新分支；时间到期不修改旧用量，也不标记真正恢复。
- 真正耗尽、永久认证异常、用户停止/关闭、身份改变优先；不能把养号阈值写成共享额度 exhausted 或让普通 API/CLI 继承它。

## 单次更新机会的持久化

新增独立表 `warmup_quota_admissions`，拟定字段：account_id 主键、identity、policy_key、window_key、source、created_at。policy_key 来自两个实际阈值，window_key 来自各启用窗口的可信 reset/到期阶段；无可信周期的未知状态使用稳定键，不把每次扫描时间或没有额度的响应时间当成新周期。

在实际启动的账号锁与额度认领事务内检查并保存一次许可，绑定 run/source/代次。源未变的同一启动链可以读取已有许可，但另一个执行/恢复代次不能再次获得同一周期的许可。调度触发前先做无副作用检查，最终启动再重读与认领，覆盖排队期间额度变化。

Recorder 在实际发送第一次需要更新额度的请求前，在受保护的本代 controls 目录独占创建 `warmup-sample.json`，匹配 identity/policy/window/source。该标记跨网络进程重启保留，和控制目录一样对 CLI 项目不可写；标记创建/读取失败按执行故障阻断。许可在创建真实执行前持久认领，失败/取消/崩溃后保守等待，不自动发第二个请求。不能仅用 Recorder 内存计数，否则进程或管理服务重启会再放行。

第一次真实响应为所有启用窗口提供有效且低于阈值的数据后可继续正常养号；仍未知、命中或有真实错误则收尾后等待。已有 API/普通 CLI/显式手动查询提供有效新数据后，也可重新判断原养号。新的可信周期或实际策略变化可重新评估；重复保存、按钮重复点击和相同未知响应不重置机会。

该表不替代共同 `recovery_source`，二者同时满足才允许养号执行；养号表不关闭 API 入场，不占用额度等待期 semaphore/长期租约。账号删除/身份切换的清理与查询必须保护旧许可不可在新身份使用。

## 请求阻断与正常收尾

固定账号上下文与旧 sidecar 路径显式传递当前执行是否为养号；network-context 白名单同步该标记。普通任务/抓包/继续对话及 idle 上下文显式清除养号作用域，防止上一作业配置残留。阈值策略与许可从受控账号状态读取，作业 source/identity 不变。

Recorder 仅跟踪当前 source、当前 OAuth AT 所属的正式 messages 流。请求入场前检查门禁，命中时拒绝新上游请求；已入场的流登记在集合中。响应头可立即更新额度和阻断后续请求，暂停信号要等本作业已接受流在 response/error 生命周期完成后才发布。拒绝的新请求不计入正在收尾的流。

共享 API 的观察也可能让养号达到阈值，因此 Recorder 对受控最新状态做有界定期检查；命中后关闭该养号后续请求入口，已有流全部收尾后发布本代暂停信号。账本/标记损坏、作业代次不符或网络故障不能当成正常额度恢复。

阈值暂停继续用 quota_wait 和 43 退出链路，带有限的养号等待原因，不将窗口伪造为耗尽。worker 保留 CLI HOME、原 run 工作目录及主会话；清理执行 token、tmux/hook/Recorder 后释放共享 CLI 租约，不停止整个账号容器或独立发送器。中途用户取消、超时、永久认证错误按现有优先级处理，不能为了收尾无期限忽略这些操作。

现有 response 回调在 `_should_record` 为 false 时早退，新增收尾计数应在统计过滤之外运行；既有正常记录与抓包归档不可被跳过。正常完成与阈值命中同时发生时，不得把暂停错记为成功，也不能复活用户已停止的 run。

## 原任务恢复

`_mark_quota_wait`、`_resume_account`、养号 tick 与立即运行/恢复入口都读取同一最新养号判定。已有等待 run 优先恢复，不能另建题目消耗新额度。恢复沿原 run/task/prompt、workspace/session、CLI/effort/权限/模型快照，仅更新执行代次和独立证据目录。

等待页可显示下次可信恢复机会；到期只有一次请求许可，不显示剩余 100% 或立即恢复。所有阻断窗口解除、或配置修改使阻断解除后重新检查共同门禁再恢复。用户停止、关闭养号、账号停用/删除、改绑/重新授权以及永久异常沿用现有约束；新规则不放宽身份过渡。

## 页面

复用账号养号弹窗：5h、7d 各一个启用控件与百分比输入，关闭时提交 null，显示“已用达到 X% 时暂停养号”，同时显示对应剩余 100-X%。初始默认关闭，不预填为系统默认保护值。

账号状态展示真实窗口的已用与剩余、启用阈值、阈值等待/额度未知、可信恢复机会时间以及已用单次机会后的等待提示。页面渲染、刷新和 SSE 不触发 usage；立即运行/恢复仍经过服务器门禁。沿用 bench 主题，覆盖桌面与 390px 窄屏，不增加 cc2api 新配置页。

## 验证与风险

核心风险是响应头命中时仍有成功长流、周期许可跨重启重复、共享状态污染普通入口，以及同 run 恢复后的 source/证据目录不一致。用真实本地 MITM/HTTPS 流与固定 Docker 演练确认响应收尾、下一请求拒绝、共享 API 连续接收、进程重启不重复发送和原会话参数保留；不把合成 CLI 会话称为官方 CLI 已验证。

阈值依据已观测的真实额度执行；用户要求已接受请求正常收尾，这些请求的后续消耗可能使实际用量超过设定阈值，不能把配置宣传为精确额度上限。

只做本地合成数据验证和两个联合镜像构建，不使用服务器账号或发送真实模型请求。后续真实官方 CLI 会话与公网验证、构建发布及线上部署由单独授权步骤完成；旧部署始终运行。

## 回滚

默认两个阈值 NULL 不改变旧行为。回滚产品前必须关闭两项新阈值、收口等待工作并备份独立 v3 数据；新字段/许可表可保留，不能通过删除数据库或批量标记任务完成恢复。代码/镜像回滚保持同一批 control/account，持久 HOME、原会话和历史证据不删除。
