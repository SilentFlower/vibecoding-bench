# v3 养号 5h/7d 可配置额度阈值

## 目标

让用户分别设置 5h、7d 通用额度的养号停止阈值，在额度用满之前限制继续养号，并能看清停止原因与恢复条件。

## 背景与已确认约束

- 来源：用户在 v3 规划中要求记录额度阈值 roadmap，2026-10-12 明确要求开始实现。需求原文与边界见 `.trellis/tasks/10-12-account-docker-cli-integration/roadmap.md:3`。
- 当前养号配置按 bench 账号保存，包含启用开关、cc2api 绑定和随机间隔；请求定义在 `orchestrator/main.py:7024`，保存入口在 `orchestrator/main.py:7353`，页面入口在 `webui/app.js:317`。
- 当前额度保护消费正式请求的真实响应，不自动查询 usage；5h/7d 用满或明确拒绝后等待，reset 到期仅表示可认领恢复机会，不表示额度已归零。共同门禁见 `orchestrator/main.py:2730`，养号触发见 `orchestrator/main.py:6131`。
- 养号、普通 CLI 与 API 的独立调度已交付；本次额度阈值只作用于养号，不扩展到普通任务、批次、抓包、继续对话或网关 API。
- 新增功能不修改上游请求协议、账号身份、OAuth 刷新所有权或既有固定容器生命周期。遥测专项继续暂缓。
- 用户选择运行中暂停策略：达到任一启用阈值后，已发出的请求正常收尾，随后暂停养号并保留原会话；不再继续消耗下一条模型请求。
- 用户选择账号级配置：每个账号分别设置 5h、7d 阈值，两个窗口可以分别启用或关闭，入口位于账号养号配置。
- 用户选择未知/到期后的单次更新策略：允许一次正式养号请求获取真实额度，根据响应继续或暂停；没有有效额度时保持等待，不自动反复尝试。
- 美国服务器旧 bench 8080 和旧 cc2api 5674 必须继续运行；本轮规划不操作线上业务、不复制账号凭据，也不自动发布或部署。

## 需求

- R1：每个账号可以独立配置 5h 与 7d 通用窗口的已用百分比停止阈值，各窗口可分别启用或关闭；任一启用窗口达到阈值时阻止新的养号执行，并在已发出的请求正常收尾后暂停运行中的养号，保留原 run、工作目录与主会话。
- R1.1：阈值以已用百分比表达，使用 1～100 的整数；两个窗口默认关闭，关闭单个窗口不影响另一个窗口，未提交的阈值配置保留原值。保存后使用最新配置判断后续养号请求。
- R2：阈值检查覆盖定时养号、立即运行、排队后实际启动及额度等待后的养号恢复；不能仅在页面或定时器检查。其他业务入口保持原有保护规则。
- R3：额度依据沿用已观测的真实窗口与 reset，不新增为阈值查询或探测的请求；不得把未知值显示成 0%，也不得把 reset 到期写成已恢复。
- R4：页面明确区分「已用百分比」和「剩余百分比」，展示命中窗口、阈值及停止/等待原因，避免百分比含义再次混淆。
- R5：配置保存后可重新读取，重启不丢失；升级既有数据库时保留账号、绑定、任务、运行记录和有效配置，默认行为与禁用策略在最终方案中明确。
- R6：永久认证异常、账号停用/删除、用户关闭养号或停止工作优先于阈值恢复；其他账号和同账号的 API/正常 CLI 不受养号阈值影响。
- R7：未命中任何未到期阈值或真实耗尽门禁时，已启用阈值的额度未知/窗口到期允许一个正式养号请求更新数据。两个窗口同时命中时需等所有命中窗口的可信 reset 都到期；没有可信 reset 时等待新的真实数据或人工调整，不能猜测恢复时间。
- R8：单次更新机会必须跨重启保留，连续点击立即运行/恢复、调度扫描、取消或执行失败不能重复放行。同一机会未取得各启用窗口的有效数据时继续等待，不使用额外模型探测或自动 usage 查询；新的可信窗口周期或实质配置变更可重新评估机会，重复保存相同配置不重置机会。
- R9：新的真实额度显示各启用窗口都低于阈值，或用户提高/关闭阻断窗口阈值后，可以恢复原养号会话；用户停止/关闭养号、永久异常或身份变化仍优先。暂停原因与窗口到期后的单次恢复机会在页面可见。

## 验收标准

- [x] A1（R1、R1.1、R2）：分别验证 5h、7d 单独命中、同时命中、恰好等于阈值、低于阈值和独立禁用；达到阈值后不启动新的养号执行，默认关闭和旧请求未携带字段时兼容既有行为。
- [x] A2（R2、R6）：定时、立即运行、队列等待期间额度变化与额度恢复入口均遵循同一养号规则；普通任务、抓包、继续对话及 API 不因养号阈值被阻断。
- [x] A3（R3、R6、R7～R9）：未知/到期只放行一次正式养号请求；有效且低于阈值则继续，达到阈值或仍未知则等待；跨重启、重复触发/恢复及失败不重复放行，多个命中窗口按最晚可信 reset 等待，缺少 reset 不猜测；自动路径不调用 usage 或模型探测。
- [x] A4（R4、R5）：配置控件、保存请求、读取响应与调度判断一致；窗口用量与剩余额度文案明确，错误输入不会写入配置，窄屏可使用。
- [x] A5（R5）：既有数据库重复升级后数据与绑定完整；未启用阈值的账号沿用既有行为。
- [x] A6（R1、R6）：运行中养号命中阈值时，已接受请求正常完成，下一条请求不再发出，随后暂停并保存原 run/工作目录/主会话；暂停不停止账号容器或中断共享 API，恢复时沿用原会话。
