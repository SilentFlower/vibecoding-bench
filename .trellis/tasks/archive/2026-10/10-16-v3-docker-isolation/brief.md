# Brief — v3 Docker 账号环境隔离对齐

## Goal

- 为 v3 建立按账号隔离、业务最小权限且网络故障时阻止直连的 Docker 运行环境。

## Scope

- 拆分账号网络、CLI 和 API 发送器三个容器角色，收紧用户权限、文件挂载、系统写入及进程资源。
- 约束 DNS、CLI、API 和服务端 OAuth 出站，覆盖启动、故障和恢复阶段。
- 适配现有任务、登录/重授权、凭据交接、进程指标及账号生命周期。
- 完成旧环境受控迁移、部署管理/备份/回滚适配和真实 Docker 验证。

## Non-Goals

- KVM、闭源组件或硬件/遥测伪装、免封承诺、改造为编辑器开发容器，以及更换 cc2api 的 HTTP/TLS 发送方式。

## Technical Overview

- 网络角色管理 TUN、DNS、代理和抓包；CLI 与发送器分别以普通用户、零 capabilities 和只读系统运行，分开 PID 和秘密挂载。
- 在账号专属网络命名空间实施默认拒绝策略；沿用既有代理、原生 TLS/显式抓包及发送桥鉴权，不修改宿主共享防火墙。

## Context & Decisions

- 沿用环境 ID、HOME、设备身份与最新合法凭据，保持 API/CLI 独立调度；手机/桌面浏览器授权网页的网络仍由用户设备控制。
- 三个角色合计沿用原 RAM/swap 总预算，辅助服务预留会减少 CLI 可用内存，必须实测；不静默增配。
- 官方开发容器用于隔离开发环境，是本次参考；交付仍为现有 v3 服务器后台。

## Risks

- 非 root/只读系统可能影响 driver、tmux、依赖安装和构建；需先验证并适配必要写入路径。
- 资源不足或迁移中断可能使环境不可用；交付前验证峰值、恢复阶段及回滚，失败不得放宽隔离或覆盖新凭据。

## Acceptance

- Docker 实测业务普通用户、无 capabilities、系统只读；CLI 无法读取发送器秘密、私有 CA 或其他账号资料。
- 双账号出口、DNS/IPv6、代理失效及启动/重启故障验证通过，绕过代理直连受阻。
- 官方 CLI 本地工具与构建、API JSON/SSE 并行/取消、合成登录/重授权及解绑后 RT 交接回归通过。
- 身份/HOME 保留，三角色资源正确计入预算，迁移、停机、备份及回滚完整；验证报告明确真实上游未验收项。
