# 技术设计

## 目标与约束

本任务只对齐可验证的 Docker 权限、文件系统和网络隔离，沿用 v3 的账号身份、API/CLI 业务和凭据所有权。以下新增角色、记录和路径是拟实现设计，不是当前代码已定义的接口。

## 账号运行结构

一个逻辑账号环境登记三个角色，复用同批 account 镜像与现有 control 镜像，保持两镜像发布结构：

```text
orchestrator（唯一拥有 Docker socket 的管理端）
  └─ 固定 environment_id
       ├─ network：TUN、路由、DNS、透传/Recorder、受控版本准备
       ├─ cli：普通用户、无 capabilities、只读系统、独立 PID、持久 HOME
       └─ sender：普通用户、无 capabilities、只读系统、独立 PID、受限配置

cli / sender ── 本账号网络命名空间 ── 配置的账号代理
gateway ── 原 TransportBinding / internal send ── sender
```

- 网络角色持有所需 NET_ADMIN/TUN，CLI 和 sender 无网络管理、提权、宿主设备或 Docker socket。CLI 与 sender 分开 PID 和挂载命名空间，避免同 UID 共享文件权限破坏秘密边界。
- 网络角色为每环境建立独立网络命名空间，业务角色加入该命名空间。TransportBinding 保留原 endpoint 名称规则、端口、代次和服务鉴权，网络命名空间所有者使用该受控 DNS 名。CLI 的实际 hostname/MAC 等必须通过前置实验核验。
- 根文件系统收紧为只读，临时目录和日志显式映射；业务按需开放 HOME/工作区和本角色运行目录。网络角色仅挂本账号网络控制、代理配置、版本缓存写入区、Recorder 证据和必要 AT 快照，不挂完整用户 HOME。
- 三角色分配独立资源上限，Docker cgroup 与 PID 命名空间保持默认隔离，不使用 host PID/IPC、privileged、SYS_PTRACE 或宿主 cgroup 写入来方便管理。

## 数据与权限

| 数据 | 管理端 | 网络角色 | CLI | sender |
| --- | --- | --- | --- | --- |
| 持久 HOME、会话与项目 | 管理/备份 | 不挂载完整目录 | 本账号读写 | 不挂载 |
| 精确 CLI 版本缓存 | 管理登记 | 受控准备可写 | 只读执行 | 不挂载 |
| 发送器配置与内部秘密 | 原子发布 | 仅需要的网络配置 | 不挂载 | 只读 |
| 代理认证资料 | 管理 | 受限读取 | 不注入进程环境 | 受限配置读取 |
| CA 私钥 | 管理/备份 | 私有 | 不挂载 | 不挂载 |
| 本次 capture 的 CA 公钥 | 发布 | 发布 | 只读、仅显式抓包信任 | 沿用原 TLS 校验 |
| 作业状态、tmux、刷新 marker | 管理/核验 | 仅网络上下文 | 仅本次必要文件 | 不挂载 |
| API 观察证据 | 管理读取 | 不需要 | 不挂载 | 本账号追加 |
| CLI/Recorder 证据与额度 | 管理读取 | 本账号范围 | 必要暂停信号只读 | 不挂载其他账号资料 |

- CLI 的 `/run/v3` 父目录由 root 持有且普通用户不可写；本代 PID/tmux 仅写受控父目录下的作业子目录。管理端原子 JSON 发布使用逐级 O_NOFOLLOW 目录 fd 和相对替换，chown 不跟随账号文件链接，防止普通用户把宿主写入/属主变更引向其他目录。
- 不再将整个管理 runtime 树或全局 quota 根直接暴露给业务；保留既有宿主解析入口，通过明确子目录挂载提供兼容路径。
- CLI 用户与 sender 用户不拥有控制面秘密。只读配置通过目录挂载接收原子换文件，避免单文件 bind mount 停留在旧 inode。
- 控制路径从未受信的工作区输入中分离；禁止跨目录符号链接、路径逃逸、错误环境/代次读写。控制文件由管理端发布，不能因 driver 改成普通用户把整个 runtime 改为账号所有。
- 沿用绑定 AT-only、cc2api 唯一刷新权、未绑定完整本地刷新权和 credential-handoff 防中断机制；RT 不作为网络服务正常运行所需配置。

## 网络控制与启动顺序

- 新环境在管理门禁内完成网络命名空间与默认拒绝策略，再放行账号内业务。未得到本环境/代次网络就绪确认时，CLI、sender 和账号恢复任务均不可运行。
- 服务端 OAuth 沿用 gateway 内既有刷新/授权客户端，通过账号显式代理出站；它不在账号网络命名空间内。只要 V3_RUNTIME_URL 或 V3_DEPLOYMENT_ID 非空，空白代理在创建客户端前返回 ServiceUnavailable，不能降为 gateway 直连；独立部署保留原空代理语义。无效非空代理继续由原客户端严格解析，不能回退。
- 网络容器仅在本账号命名空间管理防火墙，不修改宿主共享链。允许回环、已有连接、指定代理 endpoint、所需 TUN/DNS 通路和管理端到本账号 sender 的受控入站；其他直接外网、其他账号和管理服务访问默认拒绝。
- 普通 TCP/DNS 走本账号代理，IPv6 要么明确支持并同样受控，要么禁用且有拒绝策略。删除默认路由或杀掉 relay/hev 后仍不能从 bridge 直连。
- API 延续显式代理与原 HTTP/TLS 客户端；普通 CLI 延续 passthrough，capture 才启用 Recorder。切换来源/模式仍在 network.lock 内完成，并逐字段核对 ACK；API 不依赖 CLI 专属监听。
- 代理主机 bootstrap 解析与出口连接分开记录。这里约束的是服务器内程序；用户手机/桌面浏览器授权网页的网络不由容器控制，不能声称被本任务统一。
- 普通 CLI 取消或 Recorder 专属故障只影响 CLI。公共网络故障阻止两条链路；保留已有发送不确定语义，不自动重放模型请求。

## 执行、安装与指标

- 普通用户执行 driver、tmux、登录、刷新探测和继续会话。将 root 初始化、chown、CA 和安装逻辑迁到管理端或受控网络角色，不能简单在旧 driver 外套普通用户而保留 root 前提。
- 使用现有精确版本锁及完成标记，受控安装从相同代理出站，业务缓存只读；API 就绪仍不等待 CLI 安装。
- 当前项目路径、会话索引、原始题目、权限模式、hooks/statusLine 的快照恢复、任务完成判定保持。临时盘大小与 noexec 设置须通过本地依赖安装和编译测试；工作区仍能执行产物。
- 进程指标采样在 CLI 的 PID/cgroup 中通过只读受控脚本完成，管理端绑定环境/版本并写私有记录。不将 sender 或网络容器的内存/RSS 当作 CLI 指标；不新增 SYS_PTRACE，不从账号可改写的观察文件接受事实。

## 持久登记与生命周期

- account_environments 增加角色容器 ID 与隔离布局版本的幂等附加记录，现有 container_id 继续标识 CLI 执行容器。全部角色以 product/deployment/environment/role/release 精确核验。
- 环境 generation 同时约束三个角色及发送绑定。单角色创建失败、旧批次、孤儿实例、缺失网络或未知执行记录均不发布 ready。
- 启动顺序为受控网络准备、sender、按需 CLI；停止顺序先关闭入场与收口业务，再停止网络。部分启动失败撤销已创建的本代实例，持久 HOME/身份和失败证据保留。
- 容量按逻辑环境计数，不能把三个角色当三个账号或漏计孤儿角色。空闲回收、stop/rebuild/reconcile、账号删除、登录草稿清理与启动恢复必须处理完整集合。
- 管理端重启保留健康 sender 的既有 SSE；只清理可归属的旧 CLI 作业。无法确认的执行继续保持原门禁和证据。

## 预算与部署

- fingerprint.mem/swap 保留原账号总预算。网络与 sender 的有限 RAM 从总量中预留，CLI 使用剩余 RAM；额外 swap 仅按原额度分配，合计不超过原总预算。CLI 的 constrainedMemory 导入必须改为核对实际角色额度，不能继续等于账号合计 RAM。
- 角色保留量、进程数和临时盘容量先通过前置实验确定，再在共享预算函数固化，部署预检与创建参数同源。若旧预算太小无法容纳必要角色，明确拒绝启动，不静默增配。
- 同批两镜像保持，清单增加可验证的隔离布局能力并检查匹配。状态按逻辑环境汇总并显示子角色异常；既有管理页和 API 字段尽量兼容，仅增加必要角色状态。
- 旧单容器仅在无活动 CLI/API、无草稿提交/凭据交接未决时受控转换。转换前备份 DB/配置/身份，保存可恢复阶段记录；保持环境 ID、userID、machine-id、MAC、hostname、时区和最新凭据，不自动 reprofile/重新登录。
- 全部 stop/backup/status/pull/load/回滚覆盖新角色；只按本部署标签维护，不 prune 或修改其他服务。迁移不在 GET 或普通请求中悄悄执行。
- 回滚先排空并备份新状态，恢复旧兼容镜像/配置/登记，不删除 HOME/会话。凭据可能已轮换，不能用升级前旧 RT 覆盖最新合法所有者；沿用现有凭据交接保护后再恢复业务。

## 验证与技术未决点

具体场景见 implement.md。前置实验只决定内部实现参数；身份观察、启动阶段故障关闭、非 root driver 和总预算内峰值必须实际通过。任何失败均不得通过放宽隔离或伪造事实降级解决；需要产品/资源范围变化时更新材料并单独确认变化。
