# 养号与任务的 5h/7d 额度耗尽保护

## Goal

让 vibecoding-bench 从真实任务响应中被动记录额度，确认账号 5h 或 7d 耗尽后停止继续请求，窗口到期自动恢复原题，避免跳题、错误成功及持续重试。

## Background

- 用户要求控制养号和跑任务，避免 5h/7d 额度耗尽后仍继续运行；已明确选择“被动的，不主动查，类似效果 cc2api 有”、到期“自动继续恢复”，并确认继续对话和抓包“一起”纳入。
- 本次只读排查发现：10-2 的 7 次 `rate_limit` 运行被记为 success，随后换题投放；17 次 HTTP 429 来自两轮额度耗尽。完整脱敏证据在 `/tmp/vibebench-us-investigation/10-2-account-hold-report.md`。
- 规划基线中额度链路只用于查询与展示，未限制投放：`orchestrator/main.py:2399`、`:3038`、`:6278`，`webui/app.js:373`。
- 养号、批次与单次共用执行器，但继续对话独立：`orchestrator/main.py:4433`、`:4714`、`:4932`、`:7600`。排队后状态变化也需要保护。
- worker 漏掉 rate_limit 等合成 API 错误：`images/worker/entrypoint.sh:984`、`:1037`、`:1047`。不能只改页面显示。
- cc2api 已从成功及 429 响应头被动采集并部分合并：`cc2api/src/service/gateway.rs:6254`、`cc2api/src/service/account.rs:1337`；本任务参考其行为，不改其对外调度。

## Requirements

- R1：养号、单次、批次、已有任务再次运行、抓包和继续对话共用账号额度保护；任一通用 5h/7d 窗口确认耗尽时，不启动新的正式 worker 或继续发送模型请求。
- R2：真正启动前检查已持久化的被动状态；任务排队期间额度发生变化也必须拦截。创建时的检查不能替代启动前检查。
- R3：运行中明确额度耗尽时记录受限结果，停止持续重试和后续投放；rate_limit 及其它合成 API 错误不得记为正常完成。普通速率 429、计费拒绝、认证异常与封号和通用额度耗尽须区分。
- R4：因额度等待时保留当前未完成题目、原 prompt、运行配置、workspace、会话及历史产物；批次不跳题、不增加成功计数，恢复继续同一道题。
- R5：养号等待时保留启用意图，不在每次扫描生成新题、重复 task/run 或正式 worker，不影响其它有额度的账号。
- R6：多个窗口同时耗尽时，全部耗尽窗口的恢复时间到达后才允许再次尝试；较早窗口到期不能提前放行。到期表示可尝试正常任务，不代表已主动查询或确认恢复。
- R7：恢复时间来自真实响应，全部到期后自动继续原题和养号，由正常响应更新额度；再次被拒绝时重新等待，不循环探测。确认耗尽但缺少可信恢复时间时保持等待，不凭空设定 5h/7d；用户暂停、停止、关闭养号或会话优先于自动恢复。
- R8：页面显示被动额度、观察时间、耗尽窗口、等待原因及可信恢复时间。无数据为未知，过期记录不是实时查询；等待不得显示为成功、完成或封号。
- R9：额度状态和批次进度跨服务重启可恢复；重启不丢失等待条件、不集中补跑，旧执行与恢复执行不得重叠。
- R10：自动采集、启动检查、等待与恢复均不得调用 Anthropic usage API 或 cc2api 主动刷新接口，不创建额度查询 worker，不发送额外模型探测。保持绑定账号的凭据所有权、账号代理与敏感信息隔离。
- R11：成功及 429 响应均可更新被动记录，只合并本次有效观察到的窗口；缺失或非法字段不清空已有阻断证据。拒绝信号优先于利用率猜测，跨周期残留高值不能导致永久等待。
- R12：无有效额度记录时允许正常任务获得首次观察，不主动补查，也不伪造为额度充足；首次额度拒绝无法完全提前避免，发生后必须终止持续请求并保护后续投放。
- R13：继续对话与抓包使用同一账号额度事实。继续对话等待时不积攒终端输入用于自动重放，到期自动恢复可交互状态；用户关闭的会话不重建。抓包恢复仍遵守既有限频与运行隔离约束。

## Acceptance Criteria

- [x] AC1 / R1、R2：仅 5h、仅 7d、二者同时耗尽时，六类入口均不能绕过保护启动模型请求。
- [x] AC2 / R2：创建时可用，真正取得执行机会前变为耗尽，仍被拦截。
- [x] AC3 / R3、R4：复现 10-2 的 `isApiErrorMessage=true`、`error=rate_limit` 合成消息，不判 success、不跳题、不继续无限重试；正常最终 assistant 回答仍可完成。
- [x] AC4 / R3：非额度类合成 API 错误不进入成功分支；认证和 API 超时分类不回归，account_on_hold 不按额度到期恢复。
- [x] AC5 / R4、R5：多次扫描不重复正式投放，prompt、版本、effort 等快照不变，保留已有产物和运行记录。
- [x] AC6 / R6、R7：两个窗口不同时间到期，较早窗口不放行，全部到期自动继续原题和养号；再次被拒绝重新等待。暂停、停止或关闭后不擅自恢复。
- [x] AC7 / R7、R8、R12：无记录时可启动正常任务且显示未知；缺失/非法值保留已有有效记录；耗尽但无可信恢复时间时等待并说明原因。
- [x] AC8 / R9：重启后额度等待和批次进度保留，恢复不重复、不与旧 worker 重叠；其它账号正常调度。
- [x] AC9 / R10：绑定与未绑定账号使用已有凭据链路；首次运行、成功、429、扫描和恢复均无主动额度接口、查询 worker 或额外模型探测；不泄漏 token、代理密码或管理密码。
- [x] AC10 / R11：部分观察正确合并，同一 429 中允许/拒绝窗口正确区分，旧周期不永久污染新周期；普通速率 429 不误标为 5h/7d 耗尽。
- [x] AC11 / R13：continue 启动后、首次输入前和交互运行中均受保护，等待期文本/二进制输入不发上游；到期恢复交互而不重放输入，不复活关闭会话。抓包同样受保护，快照与既有限频保持。

## Non-Goals

- 不推断或保证避免 Anthropic 风控封号。
- 不改造 cc2api 对外选号和业务请求调度，不自动切换账号或模型。
- 不改成提前 97% 停跑或引入新的额度阈值设置；本轮针对通用 5h/7d 耗尽。
- 现有用户显式点击的手动额度查询不属于自动采集流程；不因页面渲染或定时刷新调用它。
- 不恢复所有历史失败任务，不重放继续对话等待期间的用户输入。
- 本轮仅本地实现与验证，不自动部署生产、修改远程数据库或恢复 10-2。
