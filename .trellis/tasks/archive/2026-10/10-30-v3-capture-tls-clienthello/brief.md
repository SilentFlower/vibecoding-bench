# Brief — v3：补齐 TLS ClientHello 指纹采集

## Goal

- 保存可复算、可关联到实际执行及 HTTP 请求的客户端 TLS ClientHello 指纹证据。

## Scope

- 新增私有 `tls_clienthello.jsonl`，保存原始本体、有序握手字段和 JA3。
- 普通抓包、续聊、项目迭代与养号迭代传播冻结版本及真实执行来源，HTTP 原始记录和索引补连接 ID。
- 抓包详情共用安全摘要；项目和养号既有文件预览支持新产物。
- 完成验证、精确推送、匹配 Actions 构建、us v3 部署及线上真实产物核对。

## Non-Goals

- 不修改 cc2api TLS 模板，不开展全版本对齐或 JA4 研究。
- 不清理旧抓包、工作区、账号、会话及其他任务，不新增通用原始文件下载权限。

## Technical Overview

- 固定 mitmproxy 11.1.3 的 `tls_clienthello` hook 提取客户端握手本体，严格解析字段，按标准过滤 GREASE 计算 JA3，私有追加到当前执行目录。
- 用 `client_connection_id` 关联一条握手和多个 HTTP flow；私有 `CAPTURE_CONTEXT` 穿过网络入口，记录实际冻结版本与 run 或 work 身份。
- 摘要和预览复用有总预算的逐层白名单，前端共用详情展示；原始握手和不透明恢复材料仅留在私有文件。

## Context & Decisions

- 之前仅验证过六条合成握手，尚无采集实现；本轮补齐真实回调、存储和读取。
- 明确采集方向为客户端到 Recorder，原始格式是 ClientHello 本体，不能当作 pcap 或代理上游握手。
- 沿用现有开关、HTTP 捕获范围、分代目录及停止保留机制；旧目录缺失 TLS 正常兼容。
- 冻结版本是执行配置；官方 CLI 归因还需实际 Claude HTTP 的连接关联。Pi 的兼容 run_id 不冒充数据库 run 身份。
- 采集异常不得阻断转发；沿用 us 不备份、不重算资源的既有选择。用户已授权本任务由子 agent 实施并自主完成推送、构建和部署，期间不再请求确认。

## Risks

- 解析异常、无 SNI、未知扩展及合法空 key_share 需要保留事实，不能生成虚假完整指纹。
- 原始握手可能包含恢复材料；文件权限、链接防护、嵌套白名单及有界扫描必须验证。
- DTLS、QUIC、ECH 内层和重试握手派发完整覆盖不在本轮验收声明内；上线排空须保留正在运行的工程和会话。

## Acceptance

- 固定 11.1.3 的真实 TLS 1.2／1.3 和 HTTPS keep-alive 验证通过，存储本体可独立解析，官方向量可复算 JA3。
- 入口证明版本和来源正确传播，握手与 HTTP 连接 ID 一致；普通及双迭代空间、分代保留兼容。
- API 和共用页面展示安全字段，损坏／半行／超预算／链接／嵌套敏感字段不会泄漏或误报完整。
- 精确提交和匹配 Actions 成功，部署后健康检查通过，并核对线上正常项目生成的新文件、JA3、版本及 Claude HTTP 关联。
