# cc2api 请求级排障观测与调用关联

## 目标

为 cc2api 增加可持久查询的请求级排障记录，让后续能够按同一请求关联实际发送参数、版本、会话映射、重试、响应终态与用量，定位长输出和授权故障。

## 背景

- 用户在 vm2api/cc2api 对照分析后明确希望增加请求级观测，便于后续排查。
- 今早 455 条完整用量均可与 new-api 匹配，但缺少逐请求版本、会话映射、思考设置、停止原因与失败尝试，故障关联依赖时间和 token 组合。
- 用户同时询问并发/RPM 建议与当前 session 池的问题；这些属于分析，不构成本任务调整线上策略的授权。
- 数值依据见 `.deploy/vm2api-cc2api-comparison-20261026/report.md`；原始正文与凭据不进入任务材料。

## 需求

### R1 请求与尝试关联

记录已通过网关 API 令牌鉴权的 `/v1/messages` 请求的内部关联 ID、每次尝试序号、账号 ID、可获得的上游 request ID、开始/首字节/完成时刻，以及成功、本地拒绝、上游拒绝、模拟命中、取消、流中断等终态。客户端可获取稳定关联标识，new-api 留存的响应 ID 可反查诊断。没有发往上游的请求不能被标成上游成功。

### R2 实际请求参数和会话归属

记录每次尝试实际采用的画像版本与选择方式、请求模型与响应模型、最终 max_tokens、thinking 模式/预算、effort，以及真实/上游 session 的匿名标识、映射动作。可获得时记录匿名线程前驱与响应消息标识，用于判断同一会话是否发生重映射；缺失字段保留为空。

### R3 响应、用量和错误

记录 stop_reason、输入/输出/缓存读/缓存写 token、partial 状态、状态码、重试原因及错误发生阶段，区分本地限制、上游认证失败和传输失败；诊断记录不能重复计入现有用量与费用。

### R4 留存与查询

记录重启后可查询，按时间至少保留八天；提供管理员鉴权的分页查询，支持时间、账号、请求关联 ID 和结果筛选。日志故障必须有可观察的失败信号，不能阻塞或改变用户转发结果。

### R5 隐私与兼容

只保存字段白名单和匿名标识，不保存正文、工具参数、凭据、Cookie、完整 headers、真实邮箱、设备 ID、账号 UUID 或完整会话 ID。保持现有调度、协议字节、SSE、重试、认证、session 池与用量统计行为。

## 验收标准

- A1：一次成功调用可以从请求记录定位到实际画像、参数、匿名会话映射和响应用量；对应 R1/R2/R3。
- A2：401 恢复、签名重试及换号均归属于原请求，并保留独立尝试和结果；对应 R1/R3。
- A3：本地拒绝、模拟命中、非流式、压缩响应、流中断及客户端取消均有正确终态；对应 R1/R3。
- A4：可用匿名会话和线程标识核对池映射及 TTL 后的变化，不改变真实映射行为；对应 R2/R5。
- A5：管理员可分页查询并跨服务重启读取；八天外清理不影响当前周记录；对应 R4。
- A6：带合成敏感信息的请求及错误不会泄漏到记录、查询或新增日志；观测故障不改变响应，不重复记费；对应 R3/R4/R5。

## 不包含

- 调整线上并发、RPM、输出上限、session 池策略或发送遥测。
- 本轮增加输出告警或 token 限流执行器。
- 修改 new-api、建设新日志页面或对历史请求补造诊断字段。
- 部署、主动模型探测、重授权和保证避免封禁。
