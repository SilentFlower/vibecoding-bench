# 项目运行环境兼容与失败恢复可见性

## Goal

让项目迭代和工程养号能容忍合理的运行环境变化，并在启动失败或等待恢复时持续向用户展示真实原因与恢复安排。

## Background

- 用户先报告线上 Cerberus 目标一直显示“已暂停、累计执行 0 秒”，随后指出补丁版本检查过严、错误无法从页面直接看出，并要求一起优化流程的可塑性与灵活性。
- 本轮只读排查确认：工作 `16d84f7e6a57475f90241e21a79462e0` 要求 Python `3.12.15`，线上 network/CLI 容器实际为 `3.12.16`，精确版本检查拒绝启动；11:13 至 13:50 多次计划认领都未产生实际执行。
- 启动拒绝只返回给 Pi；控制者正常结束后消息被改写为“Pi 已结束本轮指挥”，工程记录没有持久失败原因，列表只展示状态和耗时。证据：`orchestrator/projects.py:1630` 的工具分发及异常返回、`orchestrator/projects.py:1505` 的轮次收尾、`webui/projects.js:719` 的历史记录渲染。
- 精确 Python 检查分布在 `orchestrator/projects_runtime.py:340`、`orchestrator/account_runtime.py:1532` 与 `orchestrator/project_native_regression.py:1671`；仅放宽首个检查仍会在后续验收遇到相同问题。`images/v3/Dockerfile:68` 使用浮动补丁版本的基础镜像。

## Requirements

### R1：按实际兼容性准入

- 默认允许相同 Python 主次版本内的补丁差异；环境档案可以显式要求精确版本，旧档案无需改写即可使用默认兼容规则。
- 冻结验证版本与实际运行版本分别留证；相同规则覆盖 Projects、工程养号、旧场景启动及本次独立验收的版本判断。
- 缓存命中也核对真实运行环境，不能用旧安装凭据绕过不兼容检查；依赖摘要、锁定版本、原版测试身份及结果规则继续验证。
- 不因为允许补丁差异而删除测试、改变已接受结论或放宽真实业务失败。

### R2：启动与恢复失败是持久事实

- 有效启动及恢复失败保存可供 API 直接读取的原因、发生阶段、首次／最近时间、连续失败次数和恢复方式，提供明确的期望／实际版本等公开事实。
- 控制轮结束、计划等待、刷新和服务重启不能把尚未恢复的错误覆盖成正常结束或无原因暂停。
- 只有实际启动成功才解除当前启动故障；开始重试本身不等于成功，原始错误事件始终保留。
- 不从 Pi 自述、异常字符串关键词或历史无关错误推断当前运行结果；无效模型工具参数不伪装成基础设施故障。

### R3：页面直接解释当前情况

- 当前任务、工程历史和事件中展示失败或等待原因，明确区分人工暂停、尚未启动、启动失败、恢复失败及自动恢复等待。
- 展示最近失败时间、连续失败次数、是否自动重试及已安排的下次时间；没有安排时明确说明需要处理后重试。
- 详情区域补充失败阶段与公开技术事实；概要使用中文说明，不依赖展开 Pi 对话才能知道阻断原因。
- 双主题、窄屏、刷新和实时推送均保持可读，不覆盖尚未保存的配置。

### R4：按故障类别恢复

- 资源暂占和明确临时故障使用现有计划及有界恢复机制，等待期间不反复启动 Pi 空转。
- 明确环境不兼容、依赖制品损坏及工作区身份冲突保留现场并显示需要处理；修复后可手动重试原目标。
- 未知执行结果、认证／身份冲突和严格清理失败继续进入原人工核对流程，不自动绕过。
- 新故障类别通过有限的结构化原因与恢复策略扩展；重试延续原任务、会话、工作区及累计执行事实。

### R5：共享行为与兼容

- 项目迭代和工程养号共用上述行为；旧记录缺少新故障信息时正常展示，不凭空补造失败次数。
- 人工暂停／停止、账号身份、额度、运行时段、未知输入、精确代次及严格清理继续优先，迟到结果不得改写新状态。

## Acceptance Criteria

- [x] AC1（R1）：冻结 `3.12.15`、运行 `3.12.16` 可进入依赖准备、执行及完整原生回归；主次版本不兼容或显式精确策略不满足时返回期望、实际及策略。非法或探测失败的版本不能被默认为兼容。
- [x] AC2（R1、R5）：缓存复用、旧场景入口和两个工程空间使用一致策略；已有冻结内容摘要和测试身份保持，真实依赖损坏、业务失败与回归失败仍被识别。
- [x] AC3（R2）：启动被拒绝后即使 Pi 正常结束，API、刷新后页面和重启恢复仍有同一有效原因；重复认领真实计数，成功启动才解除当前告警，历史错误仍可查。
- [x] AC4（R3）：用户无需翻查 Pi 对话即可从当前任务和工程记录看到阻断原因、失败时间及次数，并判断是否自动重试和下一次时间；没有实际启动不显示成已经执行过。
- [x] AC5（R4）：临时等待不重复请求模型；明确不兼容的环境不会每隔原计划调用 Pi 再次空转。修复后手动恢复仍核对原身份、工作区、未知输入及执行门禁。
- [x] AC6（R5）：两个空间覆盖相同错误及恢复回归；暂停、停止和迟到结果不复活已取消工作，旧记录可读，原任务成果不被覆盖。
- [x] AC7（R2、R3、R5）：浏览器验证明暗主题、390／1280 宽度、刷新与 SSE 更新、异常文本转义、账号切换和配置编辑保留；公开故障信息不包含凭据、私有路径或隐藏验收正文。

## Out of Scope

- 不建设通用工作流引擎，不更改项目验收业务规则。
- 不更改 Python 主次版本、不自动联网下载替代解释器、不增加重试参数设置页面或外部消息通知。
- 本轮开发与验证不修改生产数据库或冻结内容、不启停线上服务、不调用真实模型；生产交付另按部署流程执行。
