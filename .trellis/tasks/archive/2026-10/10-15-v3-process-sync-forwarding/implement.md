# 实施与验收计划

## 1. 执行顺序

1. 完整展示 Brief，得到首次评审确认后运行 task.py start；实现与 Check-All 经 trellis-route 选择执行方式。
2. 按 trellis-before-dev 读取各层规范和真实类型；新增进程观察契约、root 采样、读取与导入校验。
3. 实现显式创建/关联/指标更新入口及账号页四个按钮，关联从养号配置中移出；首次创建显式提交 Billing 重写、session 池开启/容量 4/owner_only、并发 4、RPM 50；指标更新与凭据刷新隔离，保留旧兼容 API、已有账号配置、普通旧画像和重授权事务。
4. 补有业务区分度的定向回归，实际官方 CLI 隔离运行验证 PID/RSS 来源，不依赖合成 Node 进程证明官方 CLI 指标。
5. 增加正式 API 成功 JSON/SSE 的完整容器演练和代理/上游关联证据；生产额外信任根保持编译隔离。
6. 执行以下全部场景，发现偏差先核对部署/镜像批次，再定位并修复；保存每场景证据和资源恢复结果。
7. 执行完整 Python/Rust/前端构建及 Check-All；通过后进入规范更新与精确提交/部署交付流程。

按钮拆分的产品决定已明确：创建与关联不自动互相切换；以下 S1–S3 覆盖四入口状态、实际点击、独立结果以及无隐式副作用。

## 2. 验收场景表

首次 Brief 确认覆盖 S1–S9 全部候选。执行 trellis-run-full-chain 时以此表为选择依据，不再次要求用户圈选同一范围。

| 场景 ID | 路径 | 操作与可观察期望 |
| --- | --- | --- |
| S1 | UI/API/DB | 未关联账号显示独立创建/关联入口；点击“创建 cc2api 账号”后六项为 rewrite/开启/4/owner_only/4/50，TTL 默认 60 分钟，容器上限准确且无样本标未知。已有匹配时创建返回冲突，不自动关联；显式关联只绑定所选合法目标并保留配置，不创建账号、不修改养号设置。 |
| S2 | CLI/API/DB/UI | 实际官方 CLI 在禁外网夹具内运行并采样；核对 PID/版本/来源；已关联账号点击“更新进程指标”后显示真实数值和时间，仅进程字段改变，凭据/设备/代理/配置/绑定及 OAuth 请求次数不变；未关联直接调用此动作拒绝。 |
| S3 | UI/API/DB/回归 | 实际点击“重新授权”，已关联更新原账号并镜像两端，未关联明确仅保存本地；错误内部证明/设备/版本/样本和错误状态拒绝且旧数据不变。覆盖旧账号、旧兼容 API、取消/失败重授权与幂等，关联/指标更新/重授权均不覆盖六项配置；明暗及窄屏四入口可操作、无同名笼统同步结果。 |
| S4 | 正式 API/容器/代理/上游 | JSON 成功与完整 SSE：同一关联标记贯穿实际调度器绑定、目标发送器、代理和合成上游，响应字节/状态/结束标记正确。 |
| S5 | 网络/正式 API | HTTP CONNECT 与 SOCKS 分别完成 HTTPS 成功链路；错误证书/主机名拒绝；无生产 TLS 放宽。 |
| S6 | API/容器/DB | 两账号交替请求和共享 CLI 期间 API：各自代理/发送器归属正确，绑定和配额证据不串号。 |
| S7 | API/代理/上游 | SSE 客户端取消与慢流：流关闭、发送器 active 回零、上游无盲重放；未完成流不能被正常结束掩盖。 |
| S8 | API/网络/DB | 代理认证失败/不可达、发送器不可达、错误绑定/代次/目标：明确失败，上游无额外收包，管理端无直连回退。 |
| S9 | 线上生产发送器/公网 | 当前生产版本经账号容器与账号代理完成固定上游非模型 HTTPS 往返，保存关联证据并恢复基线；另列“真实 Anthropic JSON/SSE 推理”子项，当前账号受限时标缺前置条件，不计通过。 |

## 3. 验证命令与证据

- `python3 -m unittest discover -s orchestrator -p 'test_*.py'`，以及新增采样器/同步相关的定向测试。
- `cd cc2api && cargo fmt --check && cargo test`。
- `cd cc2api/web && npm run build`。
- 使用 canonical v3 构建入口冻结本轮源码及联合镜像清单；在一次性部署执行新转发场景及现有重授权浏览器回归，不只重复旧 verify_stack 的管理 SSE。
- S4–S8 使用首次创建的新配置，至少一个 Claude Code 正式消息场景核对启用 session 池和 Billing 重写后的最终请求；不能为绕过故障而禁用二者。测试请求数量受 RPM 50 约束，在独立测试数据中规划，不提高生产上限。
- 用浏览器驱动/CDP、HTTP 客户端和 SQLite 交叉核对 S1–S3；点击前监听短暂提示，检查实际请求与持久结果，并核对指标更新期间没有凭据解析/刷新请求。能力自检沿用可用 Docker/Python/浏览器工具；不直接打印登录态或 token。
- 线上核查只读配置为主；S9 开始前保存容器状态、账号身份/凭据摘要与证据文件游标，使用非模型无真实凭据请求，结束后对比恢复。
- 场景结果写入任务 research；原始凭据/真实请求正文不进入仓库、任务报告或对话。跨任务 playbook 若有新条目，按技能展示 diff 后才写回。

## 4. 已知验证限制

- 现有生产发送器硬编码允许的 Anthropic origin，公有根 TLS 不能信任隔离自签证书；测试专用构建必须在报告中标明。
- 受限账号无法证明成功推理；S9 只能证明真实公网传输。后续可用账号的实际 JSON/SSE 验收独立记录，不能用 401/403/502 报通过。
- 第一次有真实 CLI 样本前，RSS 保持未采集；不为填页面启动真实上游任务。

## 5. 恢复点

- 变更开始前保留 task.json 中主仓/子仓基线；只提交本任务确认的路径。
- 样本损坏/归属错误不写 cc2api；进程导入失败保留设备和凭据。
- 演练资源用独立标签/目录收口；生产检查尊重活动请求和内存 preflight，恢复原停止/空闲状态。
