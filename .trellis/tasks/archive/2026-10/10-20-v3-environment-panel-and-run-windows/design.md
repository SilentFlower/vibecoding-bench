# 环境面板、运行窗口及额度阈值设计

## 交付边界

父任务拥有统一范围、子任务顺序及组合验收。实现顺序为 P3（额度本轮完成）→ P1（物理面板）→ P2（当地窗口），子任务各有独立设计和实施文件。三项实现已经进入本地验证；父任务负责最终整体验收，生产发布另按部署流程执行。

| 工作负载 | 当地运行窗口 | 自设百分比阈值 | 已开始后的行为 |
| --- | --- | --- | --- |
| 普通任务、批次 item、养号 | 启动前检查 | 启动前检查 | 继续原定整轮，包括补充和收尾 |
| 抓包 run | 启动前检查 | 沿用现有豁免 | 继续原定整轮 |
| 交互续聊 | 新会话及新输入检查 | 沿用现有豁免 | 已提交回合继续，新输入在窗口外拒绝且不缓存 |
| 对外网关 API、登录、OAuth 维护、手动 usage | 本次不加窗口 | 沿用现有规则 | 按已有生命周期处理 |

真实额度耗尽、明确认证错误、手动停止、删除、清理失败和超时仍沿各自原有流程。自设阈值和运行窗口都不是强制消费上限，不保证本轮绝不跨过边界。

## 共同约束

- 环境时区是唯一时区来源，优先已保存 fingerprint；不把服务器时区或浏览器时区当账号时区，不自动修改账号身份。
- P1 增加 root 私有观察缓存，P2 增加账号窗口配置及排队等待字段；二者各自执行幂等升级，互不假设对方的新增列存在。
- 窗口开放和额度允许是下一轮启动的共同必要条件。任何恢复路径必须先通过窗口，再认领一次额度恢复许可，避免休息期消耗恢复机会。
- 长期等待不持有数据库写锁、owner/profile/environment 锁、CLI 租约或账号执行信号量；进入实际启动阶段后重新读取账号和当前窗口。
- 不新增用量查询、模型探测、遥测或代理定位服务。全部验证使用合成账号、本地上游、空数据库及随机部署隔离资源。

## 兼容与回滚

- 旧账号 NULL 窗口等价于不限制，现有阈值数值不修改；历史 stopped/auth_failed/用户停止记录不复活。
- 新字段为可空追加列，新快照放在已有 runtime 私有目录；旧程序可忽略新数据，但不保证执行新窗口策略。
- 回滚 P2 前先关闭时间限制并收口其等待队列，避免旧版本绕过用户设置；回滚 P3 会恢复旧强停策略，须先关闭自设阈值或明确接受原行为。
- 本轮代码交付不等于生产部署；最终检查、规范同步和精确 Git 交付仍按项目流程执行。

## 集成验证

1. 已启动的合成 run 同时跨过关闭时刻与 5h/7d 阈值，原定补充和收尾执行，终态来自真实退出。
2. 下一轮在任一条件仍阻塞时不启动；门禁解除后遵守原投放间隔，只投放一次。
3. 面板、账号时钟和调度使用同一环境时区；在途任务、独立 API、凭据及 HOME 不受只读观察影响。
4. 队列等待中重启、修改配置、手动停止、停用和删除，均保持原所有权及取消语义。
