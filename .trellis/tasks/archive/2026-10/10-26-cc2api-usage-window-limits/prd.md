# cc2api 每账号 5h/7d 用量百分比上限

## 目标

允许管理员限制账号在 5 小时、7 天额度窗口内的用量百分比，达到任一控制线后停止向该账号分配新的消耗额度请求，并在窗口重置后恢复可选。

## 原始需求

- 用户询问是否支持“5h 7d 不能超多少百分比”的限制；在确认当前只有 Fable 专用周限额和收到 429 后的通用窗口判断后，明确希望补充该逻辑。
- 用户最终明确要求给单独账号设置；此前的全局设置选择已被本次修正替代。

## 已确认事实

- `cc2api/src/service/account.rs:1086` 的选号同时处理 sticky 与普通候选；Fable 已有按最近观测用量过滤、无候选返回 429、保留原 sticky 直到替代账号承载请求的实现。
- 通用 `USAGE_HIT_THRESHOLD=97.0` 用于收到上游 429 后识别窗口，并非请求前可配置的百分比上限。
- `cc2api/web/src/components/Settings.vue:787` 已有全局 Fable 配额设置；其默认百分比为 50，仅作用于 Fable 窗口。
- 普通 5h/7d 用量已通过现有 `usage_data.five_hour`、`usage_data.seven_day` 被动采集；本功能无需新增上游额度查询。

## 需求

- R1：每个账号分别配置 5h 与 7d 控制线，各为 0～100 的整数；0 表示关闭该窗口的本地限制，1～100 表示用量百分比。新账号与升级后的旧账号默认均为 0。
- R2：sticky 命中、普通候选与换号重试统一遵守控制线；全部允许账号均被控制线排除时返回可解释的本地 429。
- R3：仅已开启且有效窗口参与判断；任一窗口的最近观测用量达到或超过该账号控制线即排除该账号。窗口重置、关闭限制或调高控制线后重新允许选号，仍须遵守其他有效限制及原有上游冷却。
- R4：控制作用于网关 `/v1/messages` 的所有模型与 OAuth/SetupToken 账号。沿用选号时最近观测的真实用量，不中断已分配、排队或执行中的请求，不保证并发请求或单次响应严格不越线。
- R5：账号新建/编辑页可读取、保存两个限制值，列表额度区显示已配置上限；后端严格校验并持久化，保存成功后的下一次选号使用新值，无需重启。更新未提交某个字段时保留其旧值。
- R6：保持现有 Fable 专用上限、API Token allow/block、RPM、优先级、上游 429 冷却的兼容语义。
- R7：窗口用量缺失、非有限数值、负值，或重置时间缺失/非法/已过期时，不按该窗口拦截；不得新增主动上游额度查询。
- R8：无替代账号时保留旧 sticky 绑定；只有替代账号实际承载请求后才沿用现有机制重绑。限制只影响网关消息选号，不改变账号 active/disabled 状态或写入上游冷却时间。

## 约束与范围

- 按账号独立设置，配置入口是账号新建/编辑页；本轮不增加全局控制线或全局继承关系。
- SQLite 与 PostgreSQL 的新建 schema、旧库升级、创建、更新、单条与分页查询均须同步两个账号字段，迁移幂等且保留已设置的值。
- 旧调用方遗漏新字段时沿用默认或保留既有配置，不影响 bench 的关联、凭据刷新、指标导入和既有账号策略。
- 新规则不作用于 `count_tokens`、管理接口、用量查询、后台 poller、PrimePoller 等路径；本地拦截顺序沿用现有消息链路。
- 默认关闭、未知窗口放行与上述入口边界均已随完整 Brief 获得确认。

## 验收

- AC1（R1/R3）：账号 A 设为 5h=80、7d=60，账号 B 可设不同值；A 的 5h=80% 或 7d=60% 时均不再承载新分配消息，79.9%/59.9% 时仍可选。
- AC2（R2/R8）：sticky 账号达到控制线时不能绕过；有替代账号则换号，无替代账号则返回 429 并保留原 sticky。混合通用/Fable 达线账号时同样不能回退到达线账号。
- AC3（R1/R3）：设为 0 可独立关闭某个窗口；设为 100 时 99.9% 可选、100% 命中。过期窗口或调高限制后不再因旧控制线被排除。
- AC4（R5）：两个字段创建、编辑、详情、分页列表和重启后读取一致；更新遗漏字段保留旧值。负数、101、小数、字符串、布尔等非整数输入被拒绝，失败不覆盖旧配置。
- AC5（R4/R7）：OAuth 与 SetupToken 的有效普通窗口都执行限制；缺失、负值、不完整、非法与过期窗口不误拦截。非消息入口无新增限制，也不新增 usage 请求。
- AC6（R6）：现有 Fable 专用阈值继续对 Fable 生效，通用控制线与其同时适用；未达线账号仍沿用 Token 范围、sticky、RPM、优先级和评分行为。
- AC7（R5）：账号页两个数字输入可保存、重新打开仍回显；列表标明配置上限。后端格式与完整测试、前端类型与构建通过。
- AC8（R1/R5）：SQLite/PostgreSQL 新库和旧库都可迁移，两次迁移不报错且不覆盖已保存上限；旧账号默认关闭，旧 API payload 继续兼容。

## 不包含

- 请求成本预测、额度预扣和正在执行请求的强制中断。
- 新的 usage API 轮询、上游协议改写和生产部署。
- 全局通用上限、API Token 独立阈值、批量设置和精确约束独立 CLI/后台任务造成的全部账号用量。
