# Brief — v3 登录草稿管理与授权终端修复

## Goal

- 让未完成登录的账号可见、可继续和可清理，并修复授权链接及终端结束状态。

## Scope

- 账号页展示登录草稿，提供继续登录、重新登录、取消和完整删除。
- 修复真实 CLI 授权链接显示，以及断线/会话结束时的状态和按钮。
- 页面刷新、管理服务重启后的草稿发现和处理。

## Non-Goals

- 不改 cc2api 上游/TLS/遥测，不操作旧版服务。
- 不把全部账号容器改为随服务器自启，不恢复宕机前已死亡的 tmux 进程。
- 本阶段不删除当前真实草稿、不执行 Git 推送或生产部署。

## Technical Overview

- 复用未关联正式账号的固定环境作为草稿，保存必要的私有登录元数据；草稿单独展示，不进入任务/养号可用账号集合。
- 草稿删除确认归属后收口登录、清理专属容器与目录；失败保留可见状态供重试，提交未知继续对账。
- 授权链接增加已核对的 claude.com/cai/oauth/authorize 精确入口；终端状态区分可重连断线与需要重新登录的结束状态。

## Context & Decisions

- 你已选择完整删除未提交草稿，包括专属容器、目录和未提交授权产物；正式账号及历史继续走原有保护规则。
- 管理端自动重启，账号容器按需唤醒；重启后 HOME 和固定身份保留，草稿显示登录中断或待提交状态。
- 继续连接活跃会话沿用原 sid；明确重新登录才创建新 sid，继续使用同一固定环境，不重放离线输入。

## Risks

- 删除与提交/重登可能并发；提交成功或归属变化必须阻止旧删除请求。清理部分失败不能假报成功或丢失记录。
- 真实 OAuth 成功需要实际账号证据；本次开发验证使用合成数据与隔离环境。

## Acceptance

- 未登录/未提交账号在账号页可见；刷新和重启后仍能处理，草稿不会被调度为可用账号。
- 完整删除只清该草稿资源，支持失败重试和幂等；正式账号、历史及其他环境保持。
- 新旧官方链接、终端换行和 HTTP 复制可用；普通断线重连原会话，结束原因清楚且提供重新登录。
- Docker、真实 tmux/WS、浏览器与数据库验证覆盖新建、刷新、重启、删除、竞态和既有关联重授权回归。
