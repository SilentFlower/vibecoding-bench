# Brief — v3 任务额度门禁与全英文内容改造

## Goal

- 把账号 5h/7d 已用阈值扩展到普通任务，并让 v3 新 run 的题库内容、默认 prompt 和自动催促提示全部使用安全英文。

## Scope

- 现有 5h/7d 阈值同时控制普通单任务、批次 run 和养号。
- 普通 run 在阈值命中、额度未知或窗口过期时进入 `quota_wait`，运行中的 run 正常收尾。
- 更新账号配置和摘要文案，准确说明普通任务、养号和 API 的作用范围。
- 将 `topics.md` 的说明、21 个分类、600 个标题和描述改成英文，并替换 #39、#73、#76 等高风险外观题目。
- 将 natural/canonical 默认 prompt 和 worker 的 resume、超时收尾、认证恢复、API 卡顿恢复提示改成英文。
- 扩展题库校验、SQLite 同步和回滚流程，并只同步生产 v3 题库。

## Non-Goals

- 不翻译或回填既有历史 task/run prompt。
- 不把阈值扩展到 cc2api API、抓包或继续对话。
- 不翻译 WebUI 全站文案、状态消息、错误文本或代码注释。
- 不修改额度遥测来源，不增加自动 usage 查询，不改变 Claude 官方额度算法。
- 不操作旧版 bench 题库或停止旧版服务。

## Technical Overview

- `QuotaGuard` 把通用阈值判定与养号单次 admission 分开；普通 run 对未知额度 fail-closed，养号保留现有一次正式请求机制。
- `Scheduler._execute` 在创建 worker 前按 `run_kind` 应用策略；`_mark_quota_wait` 和 `_resume_account` 复用原 run、prompt、workspace、身份和批次状态。
- 题库解析器同时接受旧中文和新英文分类标题；同步前检查 600/21/1～600、无 CJK 和固定高风险词表，再按 topic.no 原位更新。
- natural/canonical prompt 只替换文本资产，随机去重、稳定输出和自定义覆盖优先级保持不变；worker 四类注入只换默认文本，不改触发时序。

## Context & Decisions

- 现有数据库列名 `warmup_quota_*` 和配置接口继续保留以兼容旧数据，产品语义升级为账号级 bench 阈值。
- 普通 run 未知额度时等待人工查询，不借养号机会发探测请求；这是对额度保护的保守选择。
- 阈值是后续入场门禁，不是硬消费上限；已经运行的任务不会被中止。
- 普通任务仅指 `run_kind='normal'`，包括单任务与批次；抓包、继续对话和 API 维持现状。
- 历史 prompt 是运行证据，题库同步只影响 topics 表和未来新建任务。
- 明确替换 #39 写作风格迁移、#73 多站点自动签到、#76 抢课/抢号监控；公开数据、授权归档和隐私自检类正常场景可以保留。
- 新英文分类格式为 `## 1. Category (N topics)`，题目格式为 `- [ ] ID. **Title**: Description`。

## Risks

- 沿用旧数据库字段名容易造成语义误读，必须通过兼容注释、公开摘要和测试固定新含义。
- 未知额度 fail-closed 会降低无人值守启动率，页面需给出明确的额度查询恢复路径。
- 全量翻译可能发生语义漂移或漏中文，必须用自动扫描、固定 ID、分类抽样和数据库演练共同验证。
- 生产题库同步是原位更新；升级前必须生成一致备份，回滚镜像时同步恢复数据库备份。

## Acceptance

- 5h/7d 用量等于阈值时，普通单任务和批次 run 在 worker 创建前进入等待；运行中任务收尾，API、抓包和继续对话不变。
- 未知额度不发探测请求；显式查询、被动更新或关闭阈值后恢复同一 run，prompt/workspace/身份不变。
- 养号单次机会、Recorder 收尾、重启恢复、身份保护和永久认证错误全部回归通过。
- 浏览器能保存、重读和关闭两窗口，桌面/窄屏和明暗主题准确展示“普通任务与养号”作用范围。
- 题库解析结果恰好 600 题、1～600、21 个英文分类，字段无 CJK、高风险扫描为零，固定三题已替换。
- natural/canonical prompt 和四类 worker 自动注入提示全部为英文，自定义及历史 prompt 保持原样。
- SQLite 演练和生产 v3 同步保留 topic id、task/run prompt、账号及设置；旧版服务保持不变。
- 最终双镜像通过单测、隔离 Docker、真实 Chrome、额度恢复和题库同步验证。

## Next Step

- 启动任务后先实现普通 run 的额度判定与等待恢复回归，再完成英文题库、prompt 和数据库同步。
