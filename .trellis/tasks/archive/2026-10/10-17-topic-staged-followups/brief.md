# Brief — 600 题递进需求与随机多轮自动执行

## Goal

- 让 600 道英文题目能自包含开工，并在自动运行时按固定随机时间计划投递 0～2 条业务需求，直到全部选定轮次收尾。

## Scope

- 重构 600 条初始需求和 1,200 条递进补充，替换大模型、生物/医疗、安全、逆向及其它已排除题材，处理外部文件/账号依赖。
- 扩展题库解析、同步、编辑与任务/批次/run 快照，接入 worker 多轮投递、恢复和运行详情。
- 验证后由 auto-loop 完成本地代码交付，再按用户授权衔接推送、GitHub Actions 和 v3 线上部署及验收。
- 本次增量将“最终回复后追加”调整为“运行预算内随机时间投递”，并区分投递、消费和完成状态。

## Non-Goals

- 手动项目管理、跨账号共享目录、模拟人工输入节奏或捏造人工观察。
- 给历史/活动任务回填补充，或使用真实账号主动做模型探测；不承诺降低封号率。
- 修改无关服务、账号状态、凭据、代理、权限和隔离边界。

## Technical Overview

- 每题独立保存初始需求及两条补充，自然模式普通/批量/养号在创建时冻结候选，新 run 等概率选择 0/1/2 并保存正文。
- driver 使用原 tmux、目录和主会话，到固定随机时间投递下一条；CLI 忙碌时进入原生队列，以入队、主输入和正常最终回复分别确认传输、消费和完成。多条输入可由同一回复处理。
- 持久阶段文件和游标用于额度恢复、重启与输入确认；不确定投递明确失败并保留诊断。
- 输入按完整正文或同 ID 的整体 pasted_content 包装精确匹配；多行按键用 Ctrl+J，末尾单次 Enter，含 Tab/CR 的兼容输入保留粘贴。收尾缺证据明确未完成，不空等至硬超时。
- 通用完成检测与补充阶段共用主会话解析，允许混合思考/正文，并按父链及时间处理乱序落盘，仍保留原字节游标与无 UUID 旧格式兼容。

## Context & Decisions

- 保留 600 个编号与 21 个分类块，AI 类改为普通文档/规则工作流类；全部初始和补充需求为英文，输入类提供自建合成样例或替换题目。
- 原有规范评测和非空自定义提示词保持单轮；历史缺正文计划时默认零补充；已有正文而无时间快照的运行保留旧阶段规则。批次和恢复沿用冻结内容，不重新抽签。
- 各轮共用本次执行原超时，额度恢复沿用既有尝试时限。停止、认证失败、额度暂停和超时优先。

## Risks

- tmux 投递与会话文件之间无原子事务；恢复只能依据真实输入记录确认，未知窗口不盲重发。
- 600 题及其补充必须逐题语义审查；结构和关键词检查不能替代内容质量检查。
- 测试替身与离线 CLI 不代表真实模型推理，线上验收分别记录。

## Acceptance

- 完整 600 题与 1,200 条补充通过英文、主题范围、自启动来源和解析/同步一致性检查。
- 0/1/2 次补充实际对应 1/2/3 条业务输入，原目录和原会话保持，首轮不提前结束。
- 快照、阶段确认、恢复、损坏状态及停止/认证/额度/超时的回归通过，历史输入与 topic ID 保留。
- 页面准确显示计划和阶段，实际 worker/tmux 与同源正式镜像演练通过；发布后验证同批镜像、题库同步、健康及原数据保留。
- 真实包装、额外正文/错 ID 拒绝、收尾缺证据及实际 tmux 多行投递回归通过；按键输入不模拟随机人工节奏。
