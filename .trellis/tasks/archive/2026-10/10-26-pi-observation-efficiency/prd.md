# Pi 观察等待合并与增量上下文

## Goal

让 Pi 在等待 Claude 工作时减少无有效文本的模型调用，并缩小每次观察输入，保留完整现场和真实终端操作。

## Background & Decisions

- 来源为父任务 `../10-26-pi-efficiency-feedback/prd.md` 的 R1、R2、R5；用户已要求三项联合优化，并在联合 Brief 评审后确认交互事件立即唤醒 Pi；此子任务交付前两项及该交互决定。
- 已核查样本为 355 次 Pi 调用、341 次观察，其中 316 次没有新原生文本；等待参数主要为 30 秒，但实际返回中位间隔约 2 秒。
- 等待归 Python ProjectsService 所有，模型视图归 Node Pi 宿主所有；原始观察仍按原协议持久化，并由页面快照消费。

## Requirements

- O1：合并纯屏幕变化；首次观察立即返回，后续观察按合法 wait_sec 等待新原生文本、交互钩子/原生工具事件、稳定新画面、退出/额度等状态或截止时间。默认等待 30 秒，显式 0 保持即时语义；结构化交互在一个本地采样周期内唤醒，无钩子新菜单约一秒去抖后唤醒，模型推理耗时另计。
- O2：默认向模型发送有基线的画面差异及新增事件，相同画面明确无变化；允许显式请求完整画面。新 Pi 进程、上下文隔离和摘要后重建基线，不能引用模型没有看到的画面。
- O3：页面、数据库及审计保留完整原观察；每次输入仍引用最新 observation_id，未知输入禁止重放；等待不延长本轮预算，取消/身份/代次/额度保护继续执行。
- O4：通过 mock 上游和确定性回放分别核对观察返回、模型请求、模型输入字节及零请求等待；不新增真实模型探测。

## Acceptance Criteria

- [x] O-A1 / O1：持续画面噪声下不提前结束 30 秒等待，新文本、退出、额度变化按原采样周期响应；首次/显式零等待有效，结构化交互即时可见、无钩子菜单快速可见；原有钩子保留，通知只作唤醒提示而不自动答题或授权。
- [x] O-A2 / O2：差异可准确还原，包含对应基线；重复整屏不进入模型；full_screen=true、重启和摘要后均返回完整画面。
- [x] O-A3 / O3：两任务空间、页面快照、菜单按键、多行输入、旧 observation_id、停止和代次变化回归通过；提示归属受账号/会话/执行来源约束，输入不重复投递。
- [x] O-A4 / O4：记录固定样本或其统计等价回放的请求和字节前后对比；原样回放与合成近似必须明确区分。目标将该类样本 355 次调用降到几十次，实际以回放报告为准。

## Non-Goals

- 不改变业务决策的归属、自动发送文本/按键、现有单目标收尾、真实额度策略或页面终端协议。
- 不实现通用终端语义识别器，不对所有屏幕变化猜测是否业务完成。
