# Brief — cc2api：按版本绑定 TLS 画像与默认兜底

## Goal

- 让普通 cc2api 和 v3 sender 按请求生效版本使用一致的 TLS 画像，未绑定版本跟随系统默认画像。

## Scope

- 增加 TLS 画像注册和版本绑定，复用现有版本选择设置。
- 贯通普通发送、v3 sender、count_tokens、重试与相关辅助请求。
- 按代理及 TLS 画像隔离连接池和会话恢复。
- 完成回归、规范、两仓推送、Actions 及 us v3 部署验收。

## Non-Goals

- 新增未经采样的生产指纹、辅助端点多模板、修改真实 CLI 或 HTTP 画像规则。
- 新设置 UI、数据库迁移、独立旧版 cc2api 服务切换及真实模型探针。

## Technical Overview

- 网关在入口冻结版本选择及默认 TLS，选账号后解析绑定，将确定的 TLS ID 传给发送层和重试。
- sender 接受已认证元信息中的注册 ID，调用同一 TLS 工厂；旧报文缺字段兼容，未知显式 ID 在接触上游前拒绝。
- 共享工厂按“代理＋TLS ID”缓存客户端，后台后续请求使用当前适用的画像。

## Context & Decisions

- 已确认流程为“抓包确认 → 新增或复用 TLS 画像 → 绑定版本”；缺少绑定时使用系统当前默认版本画像的 TLS。
- 当前只有 293 有完整原生 TLS 基线。默认版本也未绑定时，沿用内置默认 TLS 兼容；未来默认版本绑定新画像后，未绑定版本自动跟随。
- v3 sender 是每账号的 API 发送容器；账号选择和 HTTP 改写由网关完成，原生 CLI 请求走自己的路径。
- 沿用本会话的推送构建部署授权，以及 us 不备份、不重算资源的选择，保留身份、会话、计划和其他服务。

## Risks

- 只换选择变量而复用旧连接，会继续发送旧 TLS；需实际验证不同画像的连接与恢复隔离。
- 热刷新及重试不能改变已冻结请求；测试第二画像只用于验证机制，不进入生产注册表。

## Acceptance

- 绑定优先、未知／未绑定版本回退、默认切换及同画像复用均通过测试。
- 真实内部传输保持 TLS ID，缺字段兼容、未知 ID 拒绝；293 原生字段、TLS1.2／1.3、恢复、HRR、证书、代理及长流回归通过。
- 完整 Rust 回归与 Check-All 通过；匹配镜像上线后核握手、健康、身份／计划保持及旧镜像清单收尾。
