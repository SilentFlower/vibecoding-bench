# 1179c962831a API 卡死样本

## 样本信息

- 远程主机：`186.244.215.29`
- run id：`1179c962831a`
- 任务：`间隔重复闪卡`
- 账号：`auto-2`
- 配置：`timeout_sec=2000`
- 结果：`status=timeout`，`exit_code=124`
- 实际运行：约 `2037s`

## 关键观察

- Claude JSONL 中多次出现 `system api_error`。
- 错误文本为 `Unable to connect to API (ECONNRESET)`，`connection.code=ECONNRESET`，`maxRetries=10`。
- `/api/event_logging/v2/batch` 同期仍返回 HTTP 200，说明 sidecar 和 API 域名访问不是完全不可用。
- `/v1/messages` 有多条 request 没有 response，TUI 长时间停在 busy 状态。
- worker 在临近 timeout 时注入了收尾提示，但提示停留在 TUI 输入框，没有被模型处理。
- 用户后续向同一 session 手动输入 `？为啥卡主了哇` 后，Claude 立即继续并写出 `index.html`、`styles.css`。

## 推论

这是 Claude Code TUI / API 请求管线在连接异常后的卡死，而不是：

- OAuth 401：没有 401 / `/login` / invalid credentials 证据。
- 纯任务难度过高：人工继续后同一 session 能立刻产出。
- sidecar 全断网：event_logging 仍 200。

该类失败适合在 worker 侧做有限 watchdog：明确 API error + 长时间无有效进展时，中断 busy 请求并注入继续提示。
