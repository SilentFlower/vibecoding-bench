## 已核对的隔离与协议证据

- 网关 `runtime_transport.rs:1279–1398` 核对账号、部署、版本、精确本地 sender 或登记的远程 relay origin。远程 client 禁止重定向和环境代理，独立使用 relay token。sender 在同文件 `1447–1553` 核对 Bearer、账号、环境、代次、请求 UUID 和期限，并限制原生请求方法、路径与认证目标。未发现通过当前入口直接混用其它账号绑定的证据。
- `native_runtime.rs:257–283, 1697–1753, 2334–2490` 把绑定、代理及工作身份计入池代次。两版本共享物理许可，空闲异常帧在新请求前触发退役。输出 `next` 对 32 MiB IPC 帧、协议和 worker ID 做读取期间校验。执行另验证请求 ID、事件顺序及结束事件，疑似异常进程不回池。
- `native_criu.rs:31–39,62–122,234–305` 验证 root 控制端、控制字节、已接手 FD 的个数及 CLOEXEC、真实 namespace／worker pidfd、模板和 nonce。 `services/runtime/native/criu/controller.py:68–72` 另核对直属 sender PID 与 UID。 `native_runtime.rs:1157–1229` 核对固定执行体与 sealed memfd，有确认之前不交付 worker。现有 PIDFD 和进程退出清理继续覆盖恢复及被取消的在途实例。

## 需要决定的行为

- **P2，CRIU 前置命名空间计量。** `native_criu.rs:234–259,319–325` 的恢复在接收命名空间 pidfd 后才可等待实际退出。若取消发生在此前，Rust 关闭 socket 时可先归还 sender 物理许可。控制器仍按 `controller.py:205–266,332–349` 持有独立准入并清理命名空间。业务进程要等 start ACK 才能恢复。可能重叠的是未启动模型的命名空间与随后启动的 exec。若也要把前置命名空间计入 sender 的退出等待，建议先明确何时允许正常回退启动，再选择控制器清理收据或保留等待。缺少带真实 CRIU 权限的时序验证。
- **P2，SOCKS 隧道半关闭。** `native_runtime.rs:562–573,661–674` 的 CONNECT 握手有 15 秒上限。已通过认证的 TLS 隧道双向透传，等待两边 EOF。只关闭一侧且另一侧保持静默时会继续占用连接和任务，直到对端关闭或所属 proxy 被回收。半关闭后开始单独收尾计时会改变慢响应的允许窗口。是否增加定向收尾期限及其时长需要决定。

## 合成性能证据

- 从基线源码直接编译 CCH 扫描函数，在相同本机运行同一组合成字节。4,096、16,384、65,536 个匹配项的旧耗时分别约 4.6、88.3、1,204.9 毫秒。最大输入为 3,342,337 字节。这是函数级经过时间，业务实际耗时还包含 JSON 处理和其它阶段。
- 修复后同组数据为约 0.28、0.91、3.84 毫秒。280／293 单测分别逐字节比较包含 16,384 个嵌套匹配字段的完整归一化结果。现有 CCH 夹具继续通过。
