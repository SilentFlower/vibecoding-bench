# Brief — V3：统一运行、项目与养号迭代抓包及账号版本配置

## Goal

- 统一运行、项目迭代和养号迭代的 Claude Code 抓包，并让全部 CLI 入口继承账号版本配置。

## Scope

- 账号版本配置覆盖普通/批量运行、抓包、双迭代、兼容项目及 CLI 评审、登录/重授权、续聊和实际 CLI 维护命令。
- 项目与养号各增加配置按钮，共用账号版本，分别保存当前账号在两个迭代空间的抓包开关。
- 运行抓包保留单次版本选择；三个入口均支持当前及历史抓包查看、停止收尾和已采集数据保留。

## Non-Goals

- 新增抓包暂停后续跑、版本专用镜像、自动修改全局版本或升级 cc2api 协议画像；保留项目已有业务暂停/恢复。
- TLS/303 算法研究、新自动清理策略、未脱敏内容公开展示、真实账号采集及生产部署。

## Technical Overview

- 增加统一账号 CLI 设置接口，接入现有 run/work、会话及草稿版本快照，复用精确版本缓存，核对安装、PATH 与实际启动版本。
- 抓包关闭时保留共享 CLI 透传；开启后使用 CLI 专用独占及逐作业监督，按来源和执行代次输出证据，由服务端校验归属后读取，停止时收尾 Recorder 再释放租约。

## Context & Decisions

- 版本优先级为“单次显式指定 > 账号配置 > 全局”；单次覆盖不回写配置，清空账号版本即继承全局。
- 迭代抓包默认关闭，缺字段旧配置也关闭；保存仅影响后续新执行，当前执行不热切换，关闭后历史证据仍保留。
- 已有运行、工作、会话和登录草稿保留原版本；旧空快照仅兼容回填一次并记录来源。无账号的新登录草稿使用全局版本。
- 沿用一个主任务统一评审与组合验收，原两个子项分别承担版本链路、抓包与数据保留。

## Risks

- 开启抓包需等待同账号其他 CLI 空闲；独立 API 必须保持可用，停止不得影响其他作业。
- 某些 CLI 版本尚需补充身份兼容证据；未知或安装失败要明确报错，不能猜身份字段或静默换版本。

## Acceptance

- 全部 CLI 入口实际版本符合继承规则；单次覆盖、清空配置、非法版本及失败行为正确，修改配置后已有队列、会话和草稿版本保持稳定。
- 两个配置页默认关闭，保存/刷新一致，账号与空间切换及延迟回执不串值；打开和保存配置不启动执行。
- 三个入口能采集并查看所属 Claude Code HTTP 证据；Pi、独立 API、其他账号及兄弟执行的流量不混入。
- 完整及中断响应均如实展示；索引暂缺仍可查看已有文件。停止、刷新、控制面重启及新执行后，旧数据仍可读且不被覆盖。
- 重复停止、自然完成竞态、旧代凭据及强制退出不会误停其他执行；抓包关闭保留共享并发，开启等待期间及收尾后独立 API 正常。
