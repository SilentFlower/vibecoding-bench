# V3：统一运行、项目与养号迭代抓包及账号版本配置

## 目标

统一运行页、项目迭代和养号迭代的 Claude Code 抓包配置及查看，并让全部 CLI 入口采用一致的账号版本继承规则。

## 背景与决定

- 原运行抓包任务要求单次选择版本、提前停止后保留数据；本次将项目/养号配置按钮与账号版本管理合入同一主任务。
- 沿用本任务目录及原两个子项，分别承接版本链路、抓包与数据保留；统一在本主任务做范围评审和组合验收，不创建重复任务。
- 产品选择均已明确，具体规则以 R1～R12 为准。账号版本控制实际 CLI 选择，cc2api 的请求画像、允许版本范围与 OAuth 所有权继续遵守既有契约。

## 需求

- R1：运行抓包表单保留可选精确版本，按“单次显式指定 > 账号配置 > 创建时全局有效版本”解析；单次值不改写账号或全局配置。
- R2：在确定账号并创建 run/work 或登录会话/草稿时冻结版本；排队、恢复、失败处理和历史详情使用同一值。修改账号或全局配置不改写已有非空快照，安装失败不能静默换版本；旧空快照仅做一次兼容回填并记录来源。
- R3：账号版本统一覆盖全部 CLI 入口：普通/批量运行、运行抓包、项目/养号（含兼容调度及 CLI 评审）、登录、重授权、续聊与实际 CLI 维护子命令。复用已有精确版本缓存，不为每次选择重打镜像；无账号记录的新登录草稿使用全局兜底。
- R4：运行抓包可在业务任务未完成时停止，只收口本次执行及 Recorder 上下文，不因停止删除抓包目录、索引、HTTP JSONL、stats 或 .flow；项目/养号沿既有业务暂停或停止语义收口其抓包。
- R5：已落盘数据在停止、页面刷新、控制面重启和后续新执行后仍可读取；不同 run/work/execution 的证据不得覆盖。
- R6：运行中和停止后均可查看脱敏索引、采样数量及文件清单，区分未采到、已有部分数据、响应中断和采集完成；索引暂缺不能被显示为文件丢失。
- R7：中断响应保留真实已持久化内容与中断说明，不伪造未收到的数据或完整响应；停止结果如实反映 Recorder 收尾是否成功。
- R8：保留账号/空间归属、执行代次、租约、代理、鉴权、脱敏、身份来源及凭据所有权校验；不误停其他账号、兄弟作业或独立 API，不通过新增模型/usage 探测验证配置。
- R9：项目和养号各有配置按钮，抓包按账号及迭代空间分别保存。新配置及缺字段旧配置均默认关闭；用户手动开启并保存后，后续新执行抓取 Claude Code HTTP 请求/响应。
- R10：账号版本只有一份权威配置，账号页及两个迭代配置入口读取同一值；清空即继承全局，页面展示账号配置、实际有效版本及来源，历史展示使用已冻结值。
- R11：三个抓包入口都按真实来源及执行代次隔离证据，支持当前工作与历史查看；Pi 模型、独立 API、其他账号和兄弟执行的流量不混为当前 Claude Code 抓包。
- R12：打开或保存配置不启动 Pi/Claude，不热切当前网络。抓包开关在后续新执行认领时采用并记录；再次关闭仅影响后续执行，旧证据保留。已有会话和登录草稿继续使用原版本。

## 实施分工

| 子项 | 责任与独立验收 |
| --- | --- |
| [账号版本继承与单次版本](../10-28-v3-capture-per-run-version/prd.md) | 账号配置、全部 CLI 入口解析、单次覆盖、冻结快照及实际版本准备；不回写全局或旧快照 |
| [三入口抓包配置与数据保留](../10-28-v3-capture-stop-retain-artifacts/prd.md) | 双迭代配置按钮、捕获执行与查看、停止收尾、部分状态、历史保留及兄弟保护 |

最终组合验收覆盖“账号/单次版本 → 实际 CLI → 抓包 → 中途查看 → 结束执行 → 重开历史 → 新执行不覆盖旧数据”。

## 验收标准

- [ ] AC1（R1、R3、R10）：全局 293、账号 303、单次留空时使用 303；单次指定 293 时仅本次使用 293，账号及后续未覆盖执行仍为 303；清空账号后新执行回退全局。无账号覆盖时单次指定 303 仍只影响本次抓包。
- [ ] AC2（R2）：修改账号/全局后，已排队 run、原 work、会话和登录草稿仍用原快照；旧空快照回填一次后稳定；非法版本、安装或实际版本校验失败明确报错，不换用其他版本。
- [ ] AC3（R4、R6、R7）：先取得完整 flow，再在后续流式响应中途停止；HTTP、索引、stats 和 .flow 保留且可读，中断状态不伪造完整响应，收尾失败可观察。
- [ ] AC4（R5、R11）：核对旧执行文件清单及哈希；停止、控制面重启、新 run/work/execution 后证据不被删除或覆盖，允许真实收尾追加。
- [ ] AC5（R6）：索引暂缺但已有文件时仍展示文件和部分状态；未出现目标流量时展示明确空状态。
- [ ] AC6（R4、R8）：重复停止、自然完成竞态、排队停止、旧代 token 和 Recorder 强制退出均不误释放或覆盖其他执行。
- [ ] AC7（R9、R10、R12）：两个迭代页配置默认关闭，保存/刷新一致，展示同一账号版本；切账号/空间及延迟回执不串值，打开或保存不启动执行。
- [ ] AC8（R9、R11）：启用后两个迭代空间产生真实 Claude Code HTTP 证据，当前工作及历史可查；Pi、独立 API 和其他身份流量不混入。
- [ ] AC9（R8、R9、R12）：关闭时保留现有透传与共享 CLI；开启后仅后续新执行采集，当前执行不切换；抓包等待同账号 CLI 空闲，不重启兄弟监听，独立 API 保持可用，关闭后旧证据仍可查。
- [ ] AC10（R3、R8、R10）：普通/批量、抓包、项目/养号、兼容项目及 CLI 评审、登录/重授权、续聊和实际 CLI 维护命令逐项核对配置、DB/草稿快照、安装缓存、PATH 与实际版本；未知身份映射或兼容失败不得冒充通过或切换版本。

## 范围外

- 新增抓包可恢复暂停、SIGSTOP/SIGCONT、暂停让出账号和暂停计时；项目已有业务暂停/恢复能力继续保留。
- 版本专用镜像、自动修改全局版本、升级 cc2api 协议画像或扩大其允许范围。
- TLS ClientHello 采集器及 303 请求体算法研究，继续由原独立研究任务处理。
- 未脱敏凭据/正文的公开展示、新自动清理策略、真实账号抓包与生产部署。
