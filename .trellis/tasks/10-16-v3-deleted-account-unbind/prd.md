# 修复 cc2api 账号删除后的悬空绑定无法解绑

## Goal

远端 cc2api 账号已经删除后，用户仍能通过现有解绑按钮解除本地悬空绑定。

## Background

用户报告：“有BUG我在cc2api把号删了，再点击解绑，解不了。”

2026-10-16 只读线上核对：bench 可见账号 `10-15`（id=3）仍绑定 cc2api id=2，gateway accounts 表为空，三个账号环境均为 stopped；最近四次 DELETE `/api/accounts/3/cc2api-binding` 返回 409。

代码根因：`orchestrator/main.py:8418` 的解绑调用 `_runtime_owner_transition`；`orchestrator/account_runtime.py:504` 的 `owner_transition` 无条件向原绑定请求 lease。`cc2api/src/handler/router.rs:528` 的 lease 查询先读取账号，删除后返回 404。`orchestrator/main.py:714` 将此错误包装为 ValueError，解绑提前退出。

## Requirements

- R1：仅在原绑定账号的远端不存在得到明确确认时，允许解除悬空绑定；不能把鉴权失败、超时、网络断开、5xx、坏响应或普通业务冲突当作不存在。
- R2：仍执行本地运行、续聊、登录、环境作业和实际发送器占用检查。检查失败或存在活动发送时拒绝；确认空闲后停止旧发送实例，再写入本地解绑结果，防止旧传输继续使用。
- R3：解绑成功清空 cc2api_account_id、关闭未来养号并清理对应调度状态，保留原账号、环境 ID、固化设备、HOME 与本地凭据。重复解绑应成功。
- R4：正常远端账号的门禁/释放流程和改绑目标校验保持。共享 target_id=None 的本地账号删除路径复用同一安全清理规则，不引入全局忽略 404。
- R5：覆盖真实 HTTP 404 分类、运行时与 SQLite 状态、实际页面的删除后解绑场景；所有外部请求只访问本次隔离服务，不发送 OAuth、usage 或模型请求。

## Non-Goals

- 不自动重建远端账号、不刷新或恢复已删除的远端凭据、不强行停止活动任务。
- 不直接改生产数据库绕过解绑逻辑；上线使用既有 v3 发布与部署流程。

## Acceptance Criteria

- A1（R1/R3）：隔离账号先在 cc2api 删除，再由 bench 解绑成功；SQLite 绑定为 null、养号为 off，页面显示创建/关联入口；第二次解绑仍成功。
- A2（R1/R4）：仅真实 404 且成功查询远端账号列表确认原 ID 不存在时进入悬空清理；404 路由异常但列表仍有原账号、401/403/429/5xx、网络和坏响应均拒绝且绑定不变；不存在的新目标不能获准绑定。
- A3（R2）：本地活动运行/登录/续聊/环境作业、发送器 active>0 或状态不可确认时拒绝，旧实例与绑定不变；空闲悬空绑定在本地写库前停止旧实例。
- A4（R3/R4）：账号/HOME/设备与凭据保持，正常解绑和改绑门禁回归通过；本地账号删除可清理已不存在的旧绑定。
- A5（R5）：聚焦回归与必要全量检查通过，隔离页面/API/SQLite 场景记录实际结果；发布后通过正式按钮/API处理原悬空绑定并确认成功。
