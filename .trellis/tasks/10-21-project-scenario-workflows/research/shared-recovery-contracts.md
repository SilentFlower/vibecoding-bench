# Research: 本任务相关共享恢复契约

- Query: 为多场景任务改造保留共享调度、持久化与额度恢复边界，避免超大规范注入截断。
- Scope: internal
- Date: 2026-10-21

## Findings

本文是本任务的定向索引与摘要，不是对原规范的修改。原 `database-guidelines.md` 超出单文件上下文注入上限；实现或检查涉及相应边界时，应按以下行段读取原文，不依赖文件前半段的截断注入。

### 持久化与锁

依据：`.trellis/spec/vibecoding-bench/backend/quality-guidelines.md` 的 Required Patterns；`.trellis/spec/vibecoding-bench/backend/project-iterations.md:57` 起的 schema 与验收事务契约。

- SQLite 写操作使用原数据库锁和短事务，IO 与模型执行不能放进锁内。
- 任务接受需复核父状态、generation、任务归属和预期代码状态，并通过唯一约束避免重复接受。
- 执行结果、验收结果、代码检查点和来源边界分开保存；恢复不能覆盖真实超时、失败或已接受记录。
- 历史版本固定原发布与内容摘要，迁移保留已有列、ID、索引及自增语义；不能为新 schema 清空历史。

### 被动额度与恢复

依据：`.trellis/spec/vibecoding-bench/backend/database-guidelines.md:531`–547、616–633（本轮已读取）。

- `quota_wait` 非终态，不算任务完成；真实额度恢复沿用原 run、task、prompt、workspace、session 和执行配置快照。
- 额度等待不持有信号量或长期 owner 锁；到期只代表可重试，不伪造额度恢复。
- 用户停止、暂停、账号状态和父代次优先于恢复；认证失效、严格清理失败等不能退化为普通业务修正。
- 并发、执行窗口、自设比例与真实额度共同限制新投放；不得为评审或恢复建立绕过共享门禁的新模型调用通道。
- 模型真实用量按来源、身份、原生会话边界及响应去重记录；缺证据显示未知，不主动查询或补造。
- 额度等待、服务重启和配置保存不能重新发放已经消费的恢复机会或让已完成工作重跑。

### 项目执行与候选接受

依据：`.trellis/spec/vibecoding-bench/backend/project-iterations.md:75`–113（应随源码变更核对行号）。

- 同一实例至多一个写入执行；工作区实际启动时发布，后续继续使用原目录。
- 控制端接受候选需有真实输入、回复父链、阶段和执行暂停／释放证明；单有退出码零或模型“完成”不能接受。
- 当前版本正常多步使用同 CLI；超时后旧 Run 保持 timeout，恢复另建 Run 关联原计划／session，只处理未完成范围。
- 输入消费不明、会话缺失／截断、检查点损坏或归属冲突时保留现场并阻塞，不能盲发、换会话或重建 seed。
- 验收在冻结副本上独立执行，不能修改持续工作区；基础设施错误本地有限重验，不能误算模型业务失败。

### 新评审的待设计约束

自动独立模型评审和人工审核都必须异步持久化等待。当前候选验证发生在冻结 CLI 内；不能持有候选执行名额同步等待另一个同账号评审，否则账号并发满时可能互相等待。候选回答与版本证据先封存、严格释放，评审再走正常共享调度。此为专题研究得到的设计要求，尚未实现，也未替用户选择评审方式。

## Caveats / Not Found

- 本文不涉及更换账号身份、网络或认证配置；这些不属于多场景内容改造范围。
- 具体表、状态、API 和预算字段须以技术设计为准；上述约束不能冒充已存在的新接口。
