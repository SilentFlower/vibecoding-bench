# Claude Ultra：适配 v3 与 ai-fund

## 目标与来源

让 v3 和 ai-fund 依据真实套餐字段识别 Ultra/Max，正确显示可选 5h 窗口，并提供退役旧来源所需的明确停用能力。覆盖父需求 R1–R3、R6、R8 的能力部分。

## 背景

现有字段、缺口、官方新分级和线上原始值统一见父任务 research/findings.md；关键入口为 cc2api 的 Account/DeviceProfile、账号管理/CLI 同步/遥测，以及 ai-fund 的 pools.js 和 Pools.vue。原始 max/default_claude_max_20x 仍是有效真实来源，不因商业名称变化修改它。

## 需求

- P1：新增可空的真实 rate_limit_tier，端到端支持创建、读取、更新、profile 同步及现有重授权保存；旧调用缺字段保持兼容，更新不覆盖轮换凭据。
- P2：明确 ultra 或 max + 已知真实 20x 分级显示 Ultra；max + 真实 5x 显示 Max，单独 max 只显示 Max 不猜档位；保留 Pro/Team/Enterprise 和未知值。
- P3：协议优先使用已保存的真实分级；未知不拼造新的 Ultra 分级。展示不使用旧协议回退作为事实。
- P4：真实 5h 正常展示与限制；显式 null 显示当前未返回窗口，字段缺失/异常为未知，不声称用户已经验证或无限制；7d/Fable/429 与手工控制线语义保留。
- P5：两个 cc2api 来源支持明确停用，停用后不发送请求、不进入账号计数或来源错误；默认缺开关时沿用既有行为。保持 cc2api-2 的来源身份与 ID。
- P6：部署 v3 联合新批次与 ai-fund 主版 Worker/Pages，保存当前生产域名及资源配置，保留其他已有业务改动。

## 验收

- Ultra、旧内部值 Ultra、Max 5x、无档位 max、其他套餐和未知/冲突信息有真实函数或接口测试。
- 新字段通过 SQLite/PostgreSQL 升级、读取、往返保存、元数据更新与重授权幂等验证；旧请求摘要与凭据轮换保护不回退。
- 5h 对象/null/缺失/异常以及 7d/Fable 限制分别测试；两前端构建和号池来源回归通过。
- 显式停用原来源时零该来源请求，第二来源正常且 ID 不变；默认场景不改变。
- 部署后管理接口、页面、鉴权和数据库检查通过，前端与号池不泄漏凭据。

## 范围外

不改 RPM/调度算法，不新增上游主动轮询或模型探针，不修改 NewAPI 业务代码；实际停用旧来源和清理在第三子任务执行。
