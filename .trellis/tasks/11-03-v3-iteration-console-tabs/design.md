# 统一工程迭代入口设计

## 1. 导航与路由

顶层仅保留“工程迭代”；tpl-projects 顶部提供语义化的“项目迭代 / 养号迭代”切换。原终端/交互记录页签保持在执行区域内。

采用现有 hash 路由，模式继续由 #projects 与 #warmup 表达，新增可选的 account 参数保存显式选择：

    #projects?account=1
    #warmup?account=1

无参数旧链接继续有效；顶层统一入口保留 #projects 默认值。两个 hash 都使同一个顶层入口激活。刷新、浏览器前进后退以 URL 为唯一导航来源，不能另建持久 currentTab/mode 镜像。

## 2. 账号选择

- 切换模式时读取当前有效账号并写入目标 URL，随后显式传给 ProjectsUI.mount。
- 账号选择变化用 history.replaceState 更新 account 参数，避免每次点账号都重建视图；模式切换保留正常浏览器历史。
- 账号页的“Pi 养号迭代”入口直接使用带账号的 #warmup 地址，不再依赖一次性内存变量。
- 账号参数只接受正安全整数且拒绝重复参数；明确未选时内部使用 account=0 保持提示，不能回退到另一账号。请求后端仍保留原账号可用性校验。无效/停用/删除账号给出提示并保持未选择，不默认写入另一账号。
- 第一次进入不带 account 的旧链接沿用已有默认选取规则；一旦实际选中，就将有效账号记录到 URL 供刷新恢复。

## 3. 组件与生命周期

复用 ProjectsUI，给外层提供当前账号读取/选择变化回调的最小接口。接口必须基于实施时实际定义补齐，注释说明目的及参数，不增加通用状态容器。

每次空间切换：

1. 关闭本空间弹窗、SSE、时钟，增加 revision/selection 使旧回包失效。
2. 用目标 namespace、账号和同一鉴权 API 挂载；servicePath 在本次 mount 内固定。
3. 重新读取该空间状态；不复制旧表单、分页缓存或历史记录。
4. 只建立当前空间的订阅和时钟，后台工作不受浏览器卸载影响。

普通页面切换继续清理 ProjectsUI；CLI 配置/抓包弹窗仍携带各自 namespace。空间切换项与内部执行页签分别命名及设置 aria 关系，使用现有主题变量和原生元素。

## 4. 改动边界

- webui/index.html：统一顶层入口、共享模板中的空间切换区。
- webui/app.js：解析 hash 的模式/账号、导航激活、账号直达入口与挂载参数。
- webui/projects.js：最小选择回调/读取接口，保留现有代次、账号和分页保护。
- webui/style.css：切换区的选中、聚焦、窄屏及深浅主题样式。
- deploy/v3/verify_project_browser.py 及必要验证脚本：真实浏览器回归，不更改后端业务路径。

与凭据子任务没有代码依赖；若两者都改 webui/app.js，后实施者保留前者状态展示，整合后进行同页回归。

## 5. 验证与回退

实施时核实 `verify_project_browser.py` 仍绑定已替换的旧批次页面，改为验证当前 ProjectsUI 的两个真实服务空间。准备隔离账号、不同配置/历史/终端观察，真实读取 API/SQLite 和 SSE；不启动真实模型，不将持久运行状态冒充模型执行。通过请求日志与前后数据库事实证明导航没有启停或保存副作用。

隔离网络盘点逐一读取实际 IPAM；若前一套测试刚好删除网络，仅忽略该已不存在网络，其他 Docker 错误仍失败，避免清理时序遮蔽页面验证。

验证只切换视图时 HTTP 为读取，两个空间已有 Pi/工作不被启动或取消；注入延迟及快速切换检查旧回包不会污染当前空间。

无数据库迁移。前端回退可恢复旧顶层导航；保留 #projects/#warmup 旧路径，新增 account 参数不会改变后端记录。联合发布时不能因本 UI 的独立可回退性而单侧回退凭据协议。
