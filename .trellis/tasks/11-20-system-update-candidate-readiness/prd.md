# 修复旧版升级候选验收与项目库准备阻塞

## 目标

从 v1.24.0 升级时，原版继续接单直到候选项目库准备完成。候选验收失败后，管理员能查到失败的是网关还是调度器。

## 现状

- 线上 v1.24.1 操作 `631b48dd-1441-463d-b812-2c5132223cc5` 在 180 秒候选验收窗口耗尽后恢复 v1.24.0，两库恢复完成，门禁解除。宿主仍使用旧更新器，首次升级走包含 SSH 节点的兼容流程。
- 完整 v1.24.1 镜像在隔离环境中约 56 秒后通过调度器快照探测。另一轮冷库对照在 100 秒内未开始监听，跳过项目库的隔离对照归还了两端 200。线上那次失败由哪个探测触发尚待复现。
- `deploy/flower2api/system_update_host.py` 的 `wait_controls` 对连接错误、HTTP 错误和快照校验错误使用同一个超时描述。对 v1.24.0 源码分别注入两端 HTTP 503，可得到相同结果。
- `services/orchestrator/main.py` 启动时同步校验并注册项目库。`ProjectIterationManager` 再次调用 `install`，已冻结的目录仍会被重新扫描。现有 `verify_system_update.py` 的生命周期夹具用空项目库。

## 需求

- R1 兼容升级和快速升级的候选健康验收分别记录网关和调度器的最新结果、已收到的 HTTP 状态、耗时及失败分类。系统更新详情在失败回退后仍可读候选证据，原回退结果独立保留。
- R2 准备更新阶段使用已验签的精确候选控制镜像完成项目库的内容校验和注册。候选控制服务启动时复用同一镜像和同一部署的准备结果。准备失败时原版继续接单，页面显示准备失败。
- R3 保留已有签名校验、不可变项目版本、历史任务、节点归属、双库迁移及失败回退。保留历史镜像和普通启动入口的兼容性。升级所需的更新器源码维护与正式安装纳入独立操作。

## 验收

- [x] AC1 对使用合成 SSH 节点的旧版兼容切换，分别注入网关、调度器错误。安装失败时能在操作详情区分两个来源，核验 HTTP 数值和耗时。无响应时显示失败分类。回退结束后原证据仍可读。
- [x] AC2 使用带真实打包项目库的控制镜像或使用同一注册代码的有内容夹具。核对签名候选已完整校验，注册完成时间早于暂停接单时间。切换时命中有效准备结果，中央健康检查通过，项目、养号和账号页面沿原入口工作。
- [x] AC3 注入准备被中断、候选变化、校验失败、记录损坏和恢复时旧候选归属不符。验证原程序可继续接单或由现有同操作恢复，当前及历史项目、业务数据库和节点归属没有被错误覆盖。
- [x] AC4 从 v1.24.0 起步验证修复后的候选安装和失败回退。用合成节点核对首次仍走兼容交接，并覆盖已支持快切来源。记录失败探测、准备、停机与恢复耗时。验证一组历史缺少新字段的操作仍能读取。

## 本任务交付

- 本地实现、隔离验证和上线承接说明。生产更新器源码刷新、发版及生产切换在候选完成隔离验证后按现有操作边界执行。
