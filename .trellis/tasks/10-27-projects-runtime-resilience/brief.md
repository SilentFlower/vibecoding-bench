# Brief — 项目运行环境兼容与失败恢复可见性

## Goal

- 让合理的环境变化可以继续运行，让每次卡住都有明确原因和恢复安排。

## Scope

- 统一项目迭代、工程养号、旧场景及独立验收的 Python 兼容规则。
- 补齐启动／恢复故障的持久记录、分类恢复和控制轮交接。
- 在当前任务、工程历史和详情展示原因、失败次数、最近时间及重试安排。

## Non-Goals

- 本轮不建设通用工作流引擎、重试参数设置页或外部通知。
- 不自动更换 Python 主次版本、不改冻结业务验收规则；生产部署另走交付流程。

## Technical Overview

- 共享兼容策略贯穿环境准备和原生回归；结构化故障随原任务保存，经现有 API／SSE 展示，并交回现有调度器处理。

## Context & Decisions

- 默认允许 `3.12.15 → 3.12.16`，特殊环境可显式精确锁定；冻结版本和实际版本分别留证。
- 临时故障等待后恢复；明确不兼容或制品损坏停止模型空转，处理后手动重试原目标。
- 错误持续保留到真正启动成功，Pi 正常结束、刷新或重启均不能抹掉原因。
- 恢复复用原任务、会话和工作区，人工暂停、账号身份及未知输入等既有门禁继续优先。

## Risks

- 历史回归脚本也有精确版本检查，需要按已核来源适配；允许补丁差异后仍须跑完整实际回归。

## Acceptance

- Cerberus 冻结 `3.12.15` 能在 `3.12.16` 完成环境准备、启动与原生回归；不兼容版本给出具体原因。
- 模拟启动失败、重复尝试、刷新、重启和成功恢复，核对原因、次数及重试时间真实且持久。
- 暂时等待不反复请求模型，明确环境故障不再按计划空转，人工暂停／停止不被迟到结果复活。
- 两个工程空间验证一致，明暗主题及手机宽度均可读，异常文本安全转义，旧记录正常读取。

## Next Step

- 确认后启动任务，先实现共享 Python 兼容策略及对应回归。
