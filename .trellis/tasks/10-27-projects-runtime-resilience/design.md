# 运行环境兼容与故障恢复设计

## 边界与目标

这是同一条“运行环境准备 → Claude 启动／恢复 → 控制者收尾 → 计划恢复 → 页面状态”的修复，保持单任务。默认 Python 补丁兼容、结构化启动故障与页面解释共用现有 Projects 服务，同时覆盖独立工程养号空间。旧场景和原生回归的相关版本前置检查同步，业务通过条件保持原样。

## Python 兼容策略

- 新增小型共享运行环境策略模块，按严格解析后的 Python 数字段判断，不使用字符串前缀或浮点数。
- 环境 profile 可选 `python_compatibility=minor|exact`；省略时为 `minor`，比较主次版本；`exact` 比较完整发布版本。非法策略、非正常版本或探测失败均返回明确错误。`profile.python` 仍记录原始验证使用的版本，不重写旧发布目录。
- `ProjectsTerminal._prepare_python`、`AccountRuntime.prepare_scenario_python` 与实际原生验收入口复用相同判断。每次真正准备执行先探测真实环境，缓存命中也不例外。
- 安装缓存继续按 profile 摘要复用，每次准备在缓存判断之前核对实际版本，并在原证明中保存最新期望／实际版本及策略；旧凭据缺少运行信息时仅在兼容复核通过后补齐。补丁变化本身不重复安装相同的固定离线 wheel，源码、会话和历史目录不被覆盖。
- 完整回归依然执行冻结测试节点、原控制配置、插件与结果约束；允许补丁差异不改变测试成绩。原始 contract 的 Python 作为验证来源记录，实际版本另行留证。
- 历史冻结 runner 通过现有 `ProjectVerifier` 的受信暂存适配扩展：已核 SHA256、唯一版本校验片段、期望项目／合同同时匹配后才替换版本判断，记录原始与实际 runner 摘要，并与已有重复身份适配组合。未来控制器直接支持兼容规则；未知控制器版本给出可见环境错误，不猜测替换。

## 启动故障合同

- 仅在已经绑定授权工程、进入真实终端准备／启动的边界产生运行故障；普通工具参数拒绝继续采用原返回，不污染工程状态。
- 已知环境准备错误携带有限的 `code`、`phase`、公开 message、恢复类别及白名单事实；不靠匹配中文异常文本决定重试。必要的专用异常限定为 ValueError 的轻量子类，现有 API 层仍可捕获；不建设异常插件系统。
- 在 `projects_work` 增加可空的 `failure_json`，养号表由原 SQL 命名空间映射同步升级。记录包含 `code,phase,message,retryable,first_at,last_at,attempt_count,retry_at,generation,details,resolved_at`；公开 details 只允许期望／实际 Python、兼容策略及异常类型等事实。
- 相同故障的连续真实尝试累计次数；不同原因形成新连续序列。数据变更与对应 `error`／恢复事件同事务保存，事件保留完整历史。`work.message` 继续提供旧客户端可读摘要。
- 写故障时在服务锁内核对当前 agent 代次、current_work 指针、账号身份及非终态工作；工作来自旧控制代次是合法恢复场景，不能简单要求旧 work.generation 等于当前 agent.generation。迟到旧控制者不得写新故障或清除新状态。
- 实际启动成功后标记问题已解决、追加恢复事实并清除当前提示；仅重新启动 Pi、正在准备或模型正常 settled 都不算恢复成功。
- 未知底层异常只公开固定说明和异常类型，不直接暴露路径、令牌或任意 stderr。执行结果未知仍走原人工对账，故障信息不能授权重复发送输入。

## 控制轮与恢复

| 类别 | 状态与安排 |
| --- | --- |
| 资源暂占、已确认的临时运行故障 | 保存原因，交回原调度器等待；复用既有有界恢复节奏及原计划约束，等待不占 CLI 或持续调用模型 |
| 主次版本不兼容、显式精确策略不满足、制品损坏、工作区证明冲突 | 保留工作，呈现需要处理及具体原因，不按原计划反复请求 Pi；修正后支持显式重试 |
| 账号／身份、未知输入、未确认清理、未知执行结果 | 保持已有强门禁与人工对账路径 |

- `claude_start` 的真实运行故障返回可信的控制轮交接标记；Pi 宿主先保存原工具回执，再结束当前循环，不额外要求模型解释或反复等待。
- 此标记仅对该工具及结构化运行故障生效，不复用表示目标通过的 `round_complete`；同批后续工具不能继续写入，下一轮标记重新初始化。
- `ProjectsService._run` 收尾优先读取控制端尚未解决的启动故障，再处理 Pi settled／timeout；错误不能被“Pi 已结束本轮指挥”覆盖。
- 自动重试、手动重试和 recover 都遵守原 owner、代次、身份、额度、当地窗口及未知输入约束。`start` 不提前清除问题；`recover` 保留问题和失败计数，不重置计数或把人工暂停变成自动运行。
- 现有模型暂不可用、验收待复验及业务返工保持各自流程，本次只接通启动／恢复故障的可靠交接。

## API 与页面

- 在原 work 公开投影中增加可空 `failure`；当前状态、历史分页、详情与 SSE 读取同一持久事实，不新增客户端轮询和独立错误 API。
- 展示层根据真实状态投影：没有 started_at 的失败为“启动失败”，已执行任务恢复失败为“恢复失败”；人工暂停／停止优先展示人工动作，同时可查上次故障。
- 当前任务和历史行直接显示原因摘要、最近时间、连续失败次数。自动恢复显示已保存的真实 next_run_at；未安排时写明“处理原因后手动重试”，不推测恢复时间。
- 重试进行中保留“上次失败”提示，真实启动后解除当前提示；历史错误和恢复事件仍可查看。详情展示失败阶段及期望／实际版本，沿用文本转义和主题变量。
- 旧数据 `failure=NULL` 正常展示，不根据 Pi 正文追溯造数。后续成功重新尝试会自然建立新事实。

## 影响文件

- 共享策略及环境：新增运行环境策略模块，`project_scenario_content.py`、`projects_runtime.py`、`account_runtime.py`。
- 验收一致性：`project_native_regression.py`、`project_verifier.py` 及必要的受信版本适配；保留冻结内容本体。
- 状态与调度：`projects.py`、`projects_store.py` 现有命名空间验证；`projects_api.py` 仅在实际投影需要时调整。
- Pi 交接：`images/pi-agent/host.mjs` 与相应管道测试。
- 页面：`webui/projects.js`、`index.html`、`style.css` 及两个既有真实浏览器验证入口。
- 回归、操作说明及 `.trellis/spec/vibecoding-bench/` 对应契约。

## 兼容、验证与交付

- 新 profile 字段是可选策略，不批量修改冻结 profile 或合同。数据库新增字段可空且幂等；旧客户端仍看到原 status/message，新客户端读取 failure。
- 只用合成账号、临时 SQLite、可控 Pi 及禁网隔离容器验证。至少在实际核对为 `3.12.16` 的本地隔离镜像中，用 Cerberus 冻结参考／原版证明版本差异可通过整条准备与回归路径，错误候选仍失败。
- 生产交付另按 SOP，先核在途作业和冻结来源；不得用修复任务直接改线上工作状态、失败次数、已有通过事实或账号环境。
- 回退保留新列、原内容和会话，回滚本次代码即可回到旧读取行为；不删除数据库、缓存或原运行证据。
