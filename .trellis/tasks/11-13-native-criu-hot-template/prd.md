# 原生进程池 CRIU 热模板接入

## Goal

通过恢复已完成本地初始化的账号热模板，降低现有原生进程池扩容时的准备延迟。

## Background（规划时基线）

- 用户选择采用 CRIU 方案，保留多进程池及每进程一次作业的执行方式。
- 当前 `services/gateway/src/service/native_runtime.rs:687` 的 Worker::start 从已核验分发或共享封存映像启动新进程，并完成 ready、执行体及 TLS 观测交接。
- 当前 `services/runtime/src/runtime/293/worker.ts:59` 在 ready 前完成 CLI 初始化及零模型 bootstrap。共享映像重新 exec 仍执行这些初始化。
- 隔离 KVM 研究中，CRIU 4.2 经两处 memfd 执行体恢复修补后，三轮恢复为 120.89／168.62／145.92 ms。同轮共享映像正常启动至 ready 为 1121.36／1074.73／1072.48 ms。
- 三轮恢复后的本地模拟 Messages 均成功，每轮一个 POST，bootstrap 为零 POST。受限轮次恢复后的 UID 1001、CapEff=0、NoNewPrivs=1、Seccomp=2 及四项 memfd 封存已独立采样。
- 研究的三轮分别生成各自快照；同模板多副本、进程池接入及实际 TLS 仍需验证。安全摘要见 research/criu-memfd-summary.json，研究边界见 research/current-boundaries.md。

## Requirements

- R1：现有进程池在存在可用且通过准入的同身份模板时，优先通过 CRIU 获得新 worker。模板首次创建成本与副本恢复成本分别记录。
- R2：保留账号并发、每进程一次作业、实际请求归因、原生构造与唯一原生发送行为；每笔业务最多一次模型提交。
- R3：模板按账号、凭据代次、环境代次、原生分发与执行体身份、代理及有效运行配置隔离。失效模板停止准入并清理。模板仅来自本轮受控、尚未执行业务的零模型准备进程。
- R4：同模板多次及并发恢复获得独立 worker 身份、物理 PID 归属、目录、管道及 TLS 采集归属。恢复实例完成新握手及实际执行体哈希、大小和封存校验后才可执行业务。
- R5：业务 worker 保持受限 UID、能力、NoNewPrivs、seccomp 和网络边界。恢复操作由独立受控控制器承担；其能力预检、IPC 校验和生命周期属于本任务。生产启用按后续部署授权处理。
- R6：取消、截止、恢复失败和下游断开时回收恢复任务、子进程、管道、目录、探针和临时模板。物理容量许可覆盖实际进程退出。恢复与回退共享原接收截止。
- R7：模板或恢复能力不可用时，在零模型提交边界内沿现有正常启动路径回退，并记录受控原因。已提交业务的请求保持既有一次发送与错误收口语义。
- R8：准备延迟、恢复来源及失败回退可观测。PID、warm_hit、checkout_ms、worker_start_ms、prepared_ms 继续来自最终承载请求的实际 worker；已有兼容消费者保持有效。
- R9：模板含账号内存状态，采用私有目录和文件权限，诊断只输出安全元数据。账号或内核切换、维护排空及服务停止清理对应模板与恢复实例。

## Acceptance Criteria

- [x] A1 / R1、R3、R4：同一个模板至少串行恢复三次，再同时恢复四个副本；源模板进程保持存活；每个副本以独立 PID、worker_id、管道和目录完成独立握手及一笔本地模拟请求。
- [x] A2 / R2、R4：并发副本使用不同会话、模型和合成请求，正文、身份、响应和遥测归属独立；主／子 agent 语义、缓存 TTL 和 CCH 回归通过；每请求恰好一次上游提交。
- [x] A3 / R3、R9：账号、凭据、代理、环境及内核代次变化均拒绝旧模板；模板生成阶段为零模型提交；损坏模板及不匹配原生协议在业务前拒绝。
- [x] A4 / R5：受限 worker 恢复后采样 UID、能力、NoNewPrivs、seccomp、网络及文件归属；恢复控制器拒绝任意 PID、路径、命令、跨账号模板和过期绑定。
- [x] A5 / R6、R7：注入恢复超时、控制器退出、管道断开、取消及竞态，核对实际进程退出、物理许可与计数无泄漏；回退场景维持一次模型提交。
- [x] A6 / R4、R8：隔离 TLS 接收端核对实际发送正文、头与采集 PID 归属，准备日志可对应真实恢复实例；cc_prepared 与最终实收的证据层级分别标明。
- [x] A7 / R1、R8：同环境配对至少二十轮，完整恢复到可接单的准备耗时 p50 比正常共享映像 exec 至可接单降低至少 50%；首次建模板、CRIU restore、握手、身份核验与 TLS 交接分别记录。
- [x] A8 / R1～R9：runtime、gateway 与受影响编排的定向及必要回归检查通过；运行环境预检与回退证据可复核；规格同步完成。

## Out of Scope

- 单进程多会话并发、客户端会话与进程一一映射、zygote/fork 及暖归还竞争任务的实现。
- 修改业务原生发送栈、放宽业务 worker 隔离、跨账号共享模板、恢复含业务请求的快照。
- 数据库迁移和管理界面扩展。
- 自动启用生产恢复控制器、修改线上权限、生产部署、真实账号登录或付费模型验证。
