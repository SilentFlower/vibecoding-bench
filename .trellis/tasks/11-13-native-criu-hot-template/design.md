# 原生进程池 CRIU 热模板接入设计

## 边界与所有权

- gateway 的 NativePool 保持作业准入与空闲复用所有者。CRIU 仅替换需要新物理 worker 时的创建方式。
- runtime 负责零业务模板点、恢复后绑定及原生就绪握手，继续用 nEr 与 AsyncLocalStorage 为每轮业务建立独立根。
- 独立恢复控制器负责受控模板、CRIU 子任务、PID／挂载命名空间及恢复后资源移交。业务进程维持现有受限身份。控制器的部署预检与配置接线纳入交付，生产激活另行处理。
- orchestrator 继续拥有账号环境和凭据代次、维护门禁与容器角色布局；新增恢复能力只通过受信任启动配置接入。
- 变更覆盖 services/gateway/src/service/native_runtime.rs 及其生命周期／配置消费者、services/runtime/src/runtime/293/worker.ts、共享协议与构建配方、services/orchestrator/account_isolation.py 和 native_sender.py 的受影响接线，以及受控恢复器、补丁构建和测试。具体文件拆分沿实际接口定义进行。

## 模板身份与生命周期

1. 模板 key 复用现有池身份边界，并纳入固定 CRIU 配方、恢复协议、内核能力及安全配置的版本身份；密钥和令牌只参与受控身份冻结。
2. 在零模型准备阶段生成模板。模板进程完成通用依赖与账号固定配置准备，在受控空闲点接受冻结；快照始终不含业务输入、流或执行中的作业。
3. 首笔业务遇到缺失模板时沿原启动行为执行。后台模板准备服从同一物理／内存预算，避免在业务关键路径执行完整 dump。
4. 模板状态限定为准备中、可用、失效和清理中。并发创建由同 key 的单一所有者执行，失败清理半成品后解除登记。
5. 凭据／代理／环境／原生内核变化以及维护排空同步使旧模板失效。私有目录 0700，快照文件 0600；只保存无秘密清单与安全诊断。

## 恢复实例与命名空间

- 原模板进程存活时，CRIU 保持快照内 PID 需要独立 PID 命名空间。每个副本建立单独命名空间和目录映射，并将模板内固定逻辑路径映射到该副本的独立 HOME/config/cwd。
- 上游代理、CA、固定账号配置及原生缓存的恢复行为须按已读取的实际定义核对。不能仅替换环境变量就认定原生缓存已刷新。缺少可验证重新绑定路径时该模板拒绝准入，并沿正常启动路径维持可用性。
- 每副本创建独立管道，通过 CRIU 继承 FD 交接。恢复后必须完成带新随机挑战、worker_id、模板／代次证明的绑定及新 ready，快照前的旧 ready 不参与本次准入。
- 恢复握手是独立、版本化的私有能力，由共享类型与解码器拥有。普通 exec 和旧内核继续使用现有 worker 协议；不支持恢复握手的内核走正常启动。
- 控制器提供实际可等待的物理进程所有权及外部 PID。握手中的命名空间 PID 与 /proc 的 NSpid 和命名空间身份交叉核对。生命周期所有者核验实际 PID 的执行体 SHA、大小、四项 seals 和该实例映射的 memfd 归属。
- 当前研究补丁会重建 memfd。现有共享映像 exec 的 dev/inode 校验原样保留。恢复分支使用绑定快照和实际映像的独立准入合同，并把执行映像内存纳入既有容量预算。

## 控制器安全边界

- 现有 sender 的 seccomp=2 阻止 CRIU 的 PTRACE_O_SUSPEND_SECCOMP 用法。控制器在单独的受控上下文运行；所需最小能力由隔离实验确定并写入部署预检。
- 控制接口只接受注册模板标识、账号／环境代次及实例标识。校验对端身份、消息边界、当前代次、模板白名单和本组件持有的资源所有权；禁止任意 shell、任意宿主路径与任意 PID 操作。
- 控制器处理恢复元数据，业务请求正文继续走现有 worker 私有管道。CRIU 原始日志及内存镜像保持私有，应用日志仅保留白名单失败码和阶段指标。
- 新恢复功能通过部署侧显式配置启用。开发与验证在自有隔离测试机进行。生产运行需要对应环境能力及发布流程的授权。

## 进程池接入与取消

- 首先复用 idle worker；需要新 worker 时尝试同 key 的可用模板。恢复失败在完成旧任务收口后回退至原 Worker::start，共享原单调截止。
- 将现有 Child、ChildStdin／ChildStdout 和退出等待的具体依赖整理为有明确所有权的物理进程句柄，分别覆盖直接启动与控制器恢复来源。所有释放路径在物理进程实际退出后归还 WorkerLease。
- 模板种子、正在恢复的副本和已恢复 worker 均进入统一容量统计。创建、失败、超时、取消、sender 重启及控制器失联均具有唯一清理所有者。
- 每个恢复副本继续串行执行单次作业。取消仍退役该物理 worker。已发送请求保持原有错误收口，恢复失败回退限定在业务投递前。

## 观测与兼容

- 既有诊断字段沿最终承载 worker 生成。恢复完成时间作为该实例 ready_at，warm_hit 保持按请求接收前是否已 ready 的定义。
- 模板生成耗时、restore 耗时、重新绑定／握手、执行体核验及 TLS 交接分别采样；扩展诊断的类型、序列化、日志落库或页面消费者逐项同步。
- TLS 采集仍绑定实际物理 PID、执行映像和 worker_id，恢复后重新建立 NativeTlsSlot，不能沿用快照中的探针归属。
- 构建固定 CRIU 4.2 与研究 memfd 补丁，记录来源、归档 SHA、补丁 SHA、二进制 SHA、功能配置与许可文件。原生 worker 变更同步构建源清单、实际执行体身份和兼容能力。

## 验证与实施门槛

第一阶段先验证同一模板在源进程存活时的串行和四副本并发恢复、独立资源交接、随机标识与原生缓存行为。该阶段是后续进程池接入的技术门槛；失败按实际限制修正设计，保持业务使用既有路径。

验证包括受限 worker 权限、快照污染与凭据代次、取消及控制器故障、真实 TLS 接收和至少二十轮完整准备性能。恢复命令耗时单列，不能作为完整准备耗时。

## 回退

关闭部署侧恢复配置并清理该代次模板后，进程池回到现有共享映像 exec 路径。正在服务的作业按原生命周期收口。协议和配置采用可识别能力，旧内核与不支持恢复的环境保持原有准入。

## 实施补充：随机源、FD交接与后台种子

- 固定 Bun1.4.3/revision 及 BoringSSL WIPEONFORK 画像。全线程暂停时完成实际执行体核验并复位四字节fork标志；runtime绑定时耗尽旧UUID缓存并以系统熵重新播种主realm。任一画像不匹配则在业务前拒绝恢复。
- 使用私有Unix socket的SCM_RIGHTS直接交接原生管道和命名空间pidfd。先交接命名空间，sender持有后ACK；之后才能创建物理worker。连接关闭触发控制器清理，sender等待命名空间pidfd就绪再归还许可。
- 通过预算内后台补位生成零业务模板，首笔普通启动继续原路径。dump后种子绑定成普通暖进程，快照与冻结目录由控制器私有保存。
- 模板保留同账号稳定代理引用，恢复副本沿相同账号代理端点使用独立连接。旧代繁忙实例持有其代理生命周期，模板失效只撤销新恢复准入。
- 受控恢复归属登记表为TLS broker提供实际父PID、启动时刻和worker_id；直属普通worker仍沿既有归属核对。
- 同模板七副本与产品恢复绑定、随机状态实测见 research/same-template-binding.md。实际池性能与TLS归属验收见 research/bookworm-entry-paired-summary.json 与 bookworm-tls-fault-summary.json。
