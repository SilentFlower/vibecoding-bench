# 技术设计

## 边界与入口

修复归 `AccountRuntime.ensure()` 的布局 2 正式账号准备流程所有。`commit_login()`、草稿保存协议、额度发布路径和 Recorder 判定保持现有合同。首次正式执行以及历史遗漏环境在进入实际准备时受同一校验约束，状态 GET 不调用修复。

`ensure(..., require_quota_mount=True)` 增加兼容的内部可选参数；只有 `transport()` 固定传 false。独立 API 转发不读取 CLI 额度文件，且其调用 `transport()` 前已持有自身并发许可，因此明确缺失时继续复用健康角色，避免等待排空自己。错账号、可写和不可核验的挂载仍拒绝。CLI、登录后普通准备和抓包沿默认 true 进行空闲补齐；不新增 HTTP 参数或用户配置。

主要修改文件为 `orchestrator/account_runtime.py`；挂载构造和核验保持与 `orchestrator/account_isolation.py` 一致。测试扩展现有运行时／登录草稿回归及 `deploy/v3/verify_login_drafts.py`。

## 挂载合同

- 正式账号目标为 `/quota-accounts/<bench_id>`。
- 来源为该部署 `HOST_BENCH_DATA/quota/<bench_id>`，类型为 bind，`RW` 必须明确为 false。
- 对已经核验归属并 reload 的网络角色检查 Docker 实际 Mounts，不根据数据库 account_id 或文件存在猜测挂载完整。
- Mounts 必须是可核验的列表。完全没有账号额度挂载时才归类为可补齐缺失；错账号、错来源、可写、重复或损坏元数据均拒绝使用并保留诊断。
- 正确挂载直接复用，不切换容器或网络；草稿没有正式 ID，不进入该校验。
- 不增加数据库字段、配置项、HTTP 路由或产品依赖。

## 准备流程

1. 沿原账号／环境锁读取环境，继续执行凭据所有权、草稿提交、镜像、隔离版本和角色归属门禁。
2. 角色完整时，在网络复用之前核对本账号挂载。不存在角色时沿现有创建路径，创建后同样核实实际挂载。
3. 明确缺失时，锁内重读本环境归属和状态，拒绝活动评审交接、内存作业、单执行／共享执行登记及未确认提交。不得删除登记来制造空闲。
4. 复用原 `maintenance(..., 'rebuild')` 的排他、低优先级认领；网关 active、waiting、lease 和实际发送器须通过既有空闲检查。有占用时沿原等待／拒绝语义返回，不停止容器。
5. 空闲维护只移除本环境实例；重新读取环境行，使用原画像、HOME、代理和正式账号创建三角色。同步更新当前准备流程使用的容器与代次，不能继续使用旧对象。
6. 核对新网络角色的只读挂载，再继续原 CLI 或发送器准备。并发第二次 ensure 在相同环境锁后重读新角色，直接复用。

## 失败与兼容

- 只读挂载错误或观察失败：拒绝继续准备，使用明确的本地环境说明，不伪造额度耗尽或修改阈值。
- 临时占用：保留容器、任务和会话，沿现有 `RuntimeBusy`／执行入口的等待语义处理。
- 停止／删除／创建或维护租约收口不确定：沿既有对账状态保留实例登记和原始资料，阻止继续执行；不得发布 ready 或盲重建下一代。
- 旧隔离布局继续要求显式升级，不借本分支自动迁移或扩容。坏归属不自动修复。
- 已恢复的线上 11-5 挂载正确，不属于需补建实例；本次仅在隔离数据与合成账号中验证。

## 取舍

Docker 已创建容器不能通过更新账号数据库改变挂载。采用首次实际使用时的一次空闲重建，避免全局目录暴露、额度双写和登录 SID 交接扩张。首次补齐会增加一次环境启动成本；后续有效环境不重复重建。

## 验证设计

- 单元回归从真实草稿行与三角色创建参数开始，绑定正式 ID 后再次 ensure，检查维护门禁、重建后的宿主来源、目标路径和只读属性。
- 分别验证正确挂载、重复 ensure、错误／不可读观察、其他账号挂载、API 活动／等待、CLI 作业、持久登记、评审交接、并发及中途失败。
- 登录草稿现有测试继续覆盖提交失败和重试，不改变提交 UI 行为。
- 在既有本地同批镜像及源码覆盖验证中，扩展真实草稿提交后的首次实际准备。实际网络容器读取合成额度文件、验证写入拒绝和其他账号不可见，再启动既有 Recorder 上下文观察，确认没有因缺文件产生失败信号；代理、CLI 和额度均使用合成夹具。
- 源码覆盖仅证明当前 Python 修复及容器合同；正式镜像发布与生产部署另走既有流程，不将本地验证声称为已上线。

## 回退

代码可回退本任务增量；不回退数据库、HOME 或已轮换凭据。一次成功补齐得到的正常挂载继续与旧版本兼容。若隔离验证失败，只清理本次随机部署的资源并保留脱敏证据。
