# Brief — v3 养号 5h/7d 可配置额度阈值

## Goal

- 让每个账号在设定的 5h/7d 已用额度阈值处暂停养号，并能保留原会话恢复。

## Scope

- 账号养号配置增加两个独立阈值，支持保存、关闭和状态展示。
- 定时、立即运行、排队启动、运行中请求及等待恢复接入养号阈值保护。
- 未知/到期后的单次正式请求机会、跨重启记录、正常收尾和原任务恢复。
- 数据库兼容、页面交互、行为回归和本地两镜像联合验证。

## Non-Goals

- 遥测、账号迁移、指纹或 cc2api 上游发送改造。
- 普通任务、批次、抓包、继续对话或网关 API 的新额度阈值。
- 自动推送、GHCR 发布、线上部署或真实账号消耗。

## Technical Overview

- 复用养号弹窗与接口，保存账号阈值；调度和 Recorder 共用纯规则，单次更新许可持久化。
- 命中后阻断后续养号请求，等已接受请求收尾再发布暂停信号；沿 quota_wait 保存原 run、工作目录、主会话与执行快照，恢复时接着原任务运行。

## Context & Decisions

- 每账号分别设置 5h、7d「已用百分比」，范围为 1～100 的整数；默认关闭，各窗口可单独关闭，旧请求省略字段保留原值。
- 任一窗口达到阈值就暂停；两个窗口同时命中，等所有命中窗口的可信 reset 到期。缺可信 reset 时继续等待，不猜恢复时间。
- 未知/到期只允许一次正式养号请求：有效且低于阈值则继续，命中或仍未知则等待；失败、重启、重复点击或保存相同配置不能反复放行。
- 新真实数据或提高/关闭阈值可解除等待；用户停止、关闭养号、身份变化和永久认证错误优先。页面不自动查询 usage。
- 旧 5674、8080 服务继续运行；同账号 API 与正常 CLI 保持独立调度。

## Risks

- 需要验证成功长流收尾、一次机会跨重启保留，以及阈值作用域不泄漏到其他作业。
- 已接受请求的后续消耗可能超过阈值；本地合成会话验证不代表真实官方 CLI 已验收。

## Acceptance

- 覆盖两个窗口分别/同时命中、等于阈值、独立关闭、严格输入校验、旧数据升级和保存重读。
- 未知/过期、排队变更、失败/重启/重复触发均遵守单次更新规则，无额外自动额度查询。
- 本地 HTTPS/SSE 与固定容器验证当前请求完成、下一请求拒绝、共享 API 不中断，恢复沿原 run/session/workspace。
- 停止、关闭养号和永久异常不会被自动恢复；普通业务和未启用阈值账号回归通过。
- 桌面与 390px 页面可配置并看清已用、剩余、阈值和等待原因。
