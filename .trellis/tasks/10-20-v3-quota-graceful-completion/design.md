# 自设额度阈值在本轮完成后等待

## 行为与范围

仅调整 v3 normal/warmup；批次通过 normal run 进入。沿用当前账号两个 1～100 整数阈值与 NULL 关闭规则，不迁移数据、不增加新开关。历史强停任务保持关闭，本子任务以新需求取代其未来行为。

本轮指已经启动的一个完整 run，允许原冻结补充及收尾继续；既有超时、自然失败、用户停止、真实额度耗尽或认证失败仍可以终止或暂停它，不能把“正常完成”解释为保证成功。

## 具体调整

- 移除 `Scheduler._enforce_running_quota` 的运行中百分比终止及其专用调用。检查 `Runner.wait_worker`、`AccountRuntime.wait_worker` 的 on_running 引用后，删除只为强停增加的回调接口及无用常量。
- 保留 QuotaGuard.consume、后台被动读取及终态发布前的最后消费；UI 仍能看到在途用量更新，下一次投放读取最新事实。
- 保留 QuotaGuard.admit、policy_snapshot、批次投放及养号触发前检查。阈值命中时原轮次不改 stopped，后续正常等待；批次 next_launch_at 和养号随机间隔均不清零。
- 当前 v3 normal/warmup 为 passthrough，driver QUOTA_WARMUP=0；增加真实路径断言，防止旧 Recorder 逐请求限制误入新路径。旧 runner、Recorder、capture/continue/API 的百分比策略不改。
- 已持久化 stopping/stop_requested_at 仍由现有恢复与等待器完成收口；不删除其通用兼容分支，不重新分类历史终态。

## 页面和验证入口

- 更新账号阈值说明、动态提示及部署说明，表达达到阈值后本轮完成再等待；保留一次响应可能跨阈值的实际限制。
- 将旧强停单测改为新边界的行为验证，包括真实运行路径、下一轮门禁、动态配置和历史停止兼容。
- 将 `verify_quota_hard_stop.py` 及浏览器夹具调整为本轮完成验证，更新其导入和操作说明。验证 CLI 的旧参数可以保留为兼容别名，但必须执行新语义并明确实际验证项，不能继续期待 stopped。
- 真实合成 driver 在低于阈值时启动，忙碌期间被动更新至等值或跨值，随后继续执行原补充及收尾，并阻止下一轮。验证文件、会话及同账号独立 API 不被误清理。

## 验证与回滚

- 测试覆盖 normal/warmup、5h/7d、等值/跨值、阈值关闭与运行中降低，以及真正耗尽、认证失败、用户停止、自然结束和重启停止意图。
- 使用现有隔离验证镜像和本地合成资料；不登录、不读取真实凭据、不对真实账号发模型请求。
- 无数据库 migration。回滚代码会恢复旧强停行为，回滚操作前须明确自设阈值状态；此次不自动操作生产。
