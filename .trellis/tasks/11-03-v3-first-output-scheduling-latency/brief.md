# Brief — v3 首输出延迟与账号调度配置热更新

## Goal

- 让智能调度使用实际首输出速度衡量账号响应能力。

## Scope

- 首输出观察、分组延迟反馈、诊断兼容，以及运行中调度配置热更新、表单增量保存、测试和新版部署。

## Non-Goals

- 不改5分轮换、权重、绑定与RPM策略；不修RSS，不重登录或修改codex-proxy-rs。

## Technical Overview

- 扩展已有有界响应观察器，记录有效文字/思考/工具输出；成功终态回灌对应请求分组，保留响应头时间与旧记录。页面显示账号汇总并说明分组口径。

## Context & Decisions

- 用户已选择修改延迟逻辑，沿用本项目提交、推送和部署无需重复确认的授权。用户追加要求活动API期间也能编辑RPM、并发、优先级等配置；只写变化列，身份和凭据修改仍保留维护保护。未知/失败/取消不奖励低延迟，不发送真实模型压力探针。

## Risks

- 首输出受模型、思考参数及流式方式影响，按已知请求参数隔离；新分组和重启后保持中性，避免伪造历史。

## Acceptance

- 有效输出时间与头部时间可区分；心跳/空块不计，成功/失败/取消和压缩分块测试通过，分组不串用，旧诊断可读；活动期间配置保存不打断请求、不回滚凭据，缩容限制后续准入；部署健康、数据身份和其他应用保持。

## Next Step

- 启动任务并实现共享观察与反馈链路。
