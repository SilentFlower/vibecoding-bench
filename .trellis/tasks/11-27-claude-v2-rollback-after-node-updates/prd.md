# 修复 Claude 账号跨代切回 V1

## 目标

让 Claude 账号在关闭接单、环境停止或经历多次换版后，仍能从账号配置保存并应用 V2 到 V1 的回切。

## 现场

线上 v1.40.1 的 11-14 已保存 V1。首次只读核对时环境已停止。用户开启接单并再次保存后，网关的在途、排队和 V2 待回执均为 0。当前发送器第 174 代已就绪且空闲，网关还登记第 168 代，编排仅返回第 172 代的换版凭据。第 168 代原绑定与节点归档相符。同一来源和分配下，第 171 代完成了到第 172 代所在发行的切换。

账号管理回切由网关保存待切目标，检查发送器并提交生效值。现有远端换版核对只读最近一次维护记录。 [网关切换入口](../../../services/gateway/src/service/tui_backend.rs) [节点换版核对](../../../services/orchestrator/cluster_service.py)

## 需求

- R1。接单开关作为独立配置。管理员已保存的 V1 目标在同账号环境经核验已停、原 V2 活动已收尾时生效，环境可以保持停止。
- R2。节点连续换版及中间重建后，已有 V2 绑定经同账号历史核验后可以回切。已有待切记录随后台对账继续推进。
- R3。正在交付的请求、待回执或结果未知的原轮保留原路由，等其按原合同收尾。环境归属或停止状态待确认时，管理页继续显示等待。
- R4。账号配置以生效值作为验收依据。接单开启后，第一条新请求按 V1 路由。重复保存和重启保留原意向及修订控制。

## 验收

- [ ] R1。接单关闭，分别在本机和 SSH 节点确认环境已停。在账号管理入口选择 V1，读取时显示 V1 生效、待切为空，接单仍为关闭，发送器保持停止。
- [ ] R2、R4。用隔离数据复现 168 → 171 → 172 → 174 的换版和重建序列。保留已有待切状态，经默认对账完成回切。打开接单后，第一条合成 Messages 由 V1 处理。
- [ ] R3、R4。原轮活动、待回执、绑定不符、缺少可信停止证据时继续等待。覆盖并发保存、重复保存、网关重启以及新切入 V2 的现有行为。

## 交付边界

源码和隔离回归交付后，11-14 的线上验收沿签名发行和受管部署流程完成。
