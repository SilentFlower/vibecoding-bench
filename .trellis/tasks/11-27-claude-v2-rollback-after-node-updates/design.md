# Claude V2 回切的发送器核验

## 管理入口

沿用 `PUT /admin/accounts/{id}` 保存 `request_backend` 和 `request_backend_revision`。网关沿原账号配置序列、路由写锁、空闲许可、回执查询及事务比较写提交目标。首次保存和周期对账使用同一套回切判断。接单状态由原工作控制管理，账号持久路由继续使用现有表。

## 已运行的环境

继续读同账号发送器并核验空闲。在旧绑定跨发行时，从当前已完成节点维护开始，沿同一节点配置、账号、环境、分配修订和实际账号发行串联有关的已完成归档。当前维护已恢复原发行时，以实际绑定与该记录一致的原发行及冻结代次为查询起点。归档已有原角色隔离凭据和目标账号发行，只有已完成记录可以承接换版。根据本次登记绑定返回必要的前驱证据，保留现有只读状态路径与原轮认领规则。

线上可用的路径是第 171 代从原账号发行完成换版，第 172 代完成下一次换版，之后重建到同位置的第 174 代。第 168 和第 171 代的原账号发行与位置摘要一致。用现有同位置代次严格前进规则验证第 168 到第 171 代，再验证后续已完成的换版记录。中间恢复到原发行的作业记录作为现场证据，已完成的换版记录承接发行之间的关系。历史目标字段缺失时只消费能由相应可信安装回执校验的账号发行。

## 已停止的环境

离开 V2 时，在只读运行绑定为空后查询编排的实际停止核验。复用本机环境锁和 SSH 节点的环境身份、执行记录、隔离及角色停止检查。结果须覆盖原账号、环境、分配和登记绑定，且原路由、活动及回执门禁同时通过。读取数据库的 `stopped` 字段或空传输返回只是查询入口。核验成功后收口待切目标，保留已停环境。后续预热遵循既有运行策略。

## 兼容和恢复

沿用外部管理字段、账号修订和持久意向。私有核验能力按现有的版本协商方式接入。缺少可信观测时保留待切状态，由原后台继续对账。已有 V2 待回执仍按原绑定恢复。完成源码验收后由同批控制组件承接存量意向，线上切换和回退沿现有签名发行流程。
