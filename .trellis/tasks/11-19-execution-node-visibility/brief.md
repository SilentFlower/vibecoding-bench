# Brief — 执行节点可见性

## Goal

让账号、运行环境和请求日志直接展示执行节点，支持迁移后的真实历史追溯。

## Scope

- 任务账号与网关账号列表和详情的节点摘要。
- 运行环境卡片和详情的节点归属及观察状态。
- 请求列表末次尝试及详情逐次尝试的执行节点。

## Non-Goals

- 节点分配、探测、迁移策略变更。
- 新增节点监控面板与日志保留策略调整。

## Technical Overview

批量读取账号已保存的节点归属与缓存观察，复用环境公开投影。请求列表读取末次尝试的 execution_location，详情读取各次尝试原记录，并保持现有管理鉴权、批量读取和页面轮询生命周期。

## Context & Decisions

- **【关键决定】账号和环境显示当前归属，请求日志显示当次实际执行节点。**
- **【关键决定】迁移后保留原请求的节点标识；历史缺字段显示未观测。**
- 控制解耦已通过重检。本任务复用最终账号公开模型，节点展示保持只读。

## Risks

- 远端失联时保留已保存归属，并分别展示当前观察状态。

## Acceptance

- 本机和 SSH 节点在账号与环境主要视图均可辨认。
- 不可达节点、旧日志及无实际尝试的请求有明确展示。
- 跨节点多次尝试和迁移后的历史节点正确，原分页、筛选和工作区可用。
- 前端构建、定向后端和真实浏览器验证通过。
