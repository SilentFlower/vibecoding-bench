# 技术设计：执行节点可见性

## 数据来源

- `AccountNodeAssignment` 是任务账号当前人工归属，使用原节点服务返回的公开投影。
- `RuntimeEnvironment.node` 已含节点名称和稳定标识；`node_observed` 与 `node_message` 表示当前观察，分别展示。
- 网关账号按任务账号的 `cc2api_account_id` 关联当前节点；沿同源 `/runtime/api/accounts` 批量读取安全节点摘要。仅展示节点时读取已保存归属和缓存观察，避免触发环境列表的远端现场巡检。
- 请求节点来源是当前尝试的 `execution_location`；列表复用 `last_attempt`，详情逐次展示。同次记录中的环境和代次是历史事实。

## 服务与前端

1. 任务账号列表由原节点存储批量补充安全归属摘要与已有观察；节点不可达仍返回已保存归属。公开字段明确选择 node_id、node_key、node_name、kind、enabled、revision、phase 和观察状态，排除内部节点配置。
2. 为网关账号声明任务账号节点摘要类型；复用账号页面既有刷新周期并保持每轮批量读取。环境诊断继续使用原环境摘要，节点仅展示不会唤醒环境。
3. 账号及环境卡片放置节点名称和稳定标识；详情保留相同标识。节点暂停与不可达单独展示，禁止解释为账号实际执行完成。
4. 请求列表在账号或模型摘要旁显示末次尝试的节点；链路详情显示每次节点及环境代次。
5. 本机只有 `node_key=local` 的真实记录才显示默认本机；历史缺字段显示未观测，无实际尝试显示无执行尝试。
6. 节点名称可从安全目录解释，历史定位始终使用记录中的稳定标识，禁止用账号当前归属回填旧请求。
7. 保持读取失败反馈、可见页面轮询、AbortSignal 和代次丢弃旧回执，保留列表筛选、分页与弹窗草稿。

## 兼容、安全与风险

- 新增字段均为可选公开投影，老日志 JSON 保持可读。
- 展示只读，不唤醒容器、不探测模型、不续租、不改变节点归属。
- 节点公开摘要只含名称、稳定标识、类型与状态，私钥和认证材料保留原写入边界。
- 网关与编排服务暂时失联时当前归属和最新观测分别呈现；旧快照明确标为待刷新。
- 迁移后历史请求仍显示原节点，跨节点多尝试各自显示真实节点。

## 前置交接

控制解耦已通过重检。账号公开投影新增 `work_control`，整体启停使用独立协调入口。节点归属读取保持只读，与工作开关分别呈现；请求历史继续使用原 `execution_location`。Git 交付当前需要核对分支既有 ahead 和同文件已有改动，节点实施与验证沿本子任务独立推进。

## 最终实现

- `ClusterStore.assignment_summaries()` 单次 SQL 读取全部有效账号的归属和节点缓存，明确挑选公开字段。账号停用继续返回归属；列表与卡片不发起节点连接。
- `ExecutionNodeBadge.vue` 统一 Vue 账号、环境和请求的节点排版；兼容任务与环境入口复用 `renderAccountNode`，正文保持转义。节点标识用等宽字体并可换行。
- 账号节点读取加入原列表刷新，隐藏和卸载取消，旧回执按代次丢弃；失败保留已有归属并标记待刷新。
- 请求列表使用 last_attempt；详情末次执行位置从详情独立返回的有序 attempts 取得。旧记录显示节点未观测，零次尝试显示无执行尝试。手机请求记录采用两列卡片，保留结果与详情入口。
