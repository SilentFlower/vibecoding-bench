# cc2api：压缩请求解码与重编码

## 目标

兼容新版 Claude Code 及其它客户端的压缩请求，让既有正文改写正常执行，并按请求声明的编码发送一致的正文与头，保持普通未压缩请求兼容。

## 背景与已确认决定

- R3-03：`cc2api/src/service/gateway.rs:1786` 直接把入站字节用于 JSON 处理；`rewriter.rs:1468` 重建头时没有保留 Content-Encoding，可能形成压缩正文与编码声明错配。count_tokens 在 `gateway.rs:1545` 有独立入口。
- 用户拒绝对合法压缩请求一律报错，明确要求先支持解码；随后决定改写后恢复原编码，由子 agent 实施。
- 官方 v2.1.300 发布记录确认大请求使用 gzip 的默认行为覆盖遥测关闭场景；环境变量文档还列出 telemetry 和 artifact publish。详见 `research/native-gzip-public-evidence.md`；没有 300 之后的新抓包，不外推容器或画像细节。
- 基线为已发布的 R2 字段／Session／stream 与 R3 beta 修复；这些规则继续按解码后的逻辑正文执行。已有 gzip／deflate／br／zstd 依赖可用，现有响应 helper 无输出上限，不适用于严格入站。

## 要求

- **R1／入口兼容**：覆盖通用 Gateway 转发及 count_tokens 独立入口。合法压缩输入在正文相关策略与账号选择前解码；API token／UA 鉴权和 count_tokens 方法优先级保留。其它路径继续采用各自已有 JSON 或非 JSON 行为。
- **R2／编码声明**：从原始 Content-Encoding 多值识别编码链，支持 gzip／x-gzip、zlib 与兼容 raw 的 deflate、标准 br、zstd；支持大小写、OWS、重复头及有序叠加。identity 与合理空列表项兼容为无操作；未知编码、非法声明或损坏内容不能静默透传。
- **R3／资源与错误**：入站原字节及每层解码结果各最多 10 MiB，最多 4 个实际编码层；标准 br、zstd 解码窗口最多 16 MiB。未知编码／超编码层数返回 415，非法声明／不可完整解码返回 400，压缩请求原字节或解码结果超限返回 413，均为可解析错误。未压缩读取／非法 JSON 的既有结果不扩大改变。入站拒绝发生在账号分配、RPM／槽位、池／Hello、自动遥测及上游请求之前。
- **R4／出站一致性**：在最终逻辑字节上完成身份、字段清理、Session 与 CCH；按入站有效编码链重编码，保留编码方式和顺序，不承诺容器原字节或参数相同。无编码请求不主动压缩。编码头与最终字节一致，长度按发送正文重新生成，容许重压缩开销超过原来的 10 MiB 读取上限。
- **R5／重试与缓存**：401、signature 修复与换号等已有重试沿用同一入站编码选择，每次发送本次改写后的正文；逻辑正文继续用于缓存、调度、策略、诊断及日志。不得引入额外压缩协商或明文回退重试。

## 范围限制

不增加设置、依赖、数据库迁移或前端。保留管理接口、WebSocket、内部管理桥协议与独立自动生成请求的现有行为。本项不修改响应保活／压缩响应、TLS、Claude Code 版本画像或 CCH 算法；不根据 UA 或 Accept-Encoding 强制请求压缩，不新增全局 JSON schema 校验。不使用真实账号推理，不覆盖冻结差分研究。

## 验收标准

- **AC1 → R1／R2／R4**：真实 Gateway＋loopback 对等价压缩／未压缩请求比较上游解码后的最终正文、身份／Session、CCH、根键清理及 stream 三态；覆盖 CC／API、Messages、count_tokens、event_logging 与其它通用转发的非 JSON 样例。
- **AC2 → R2／R3**：编码单项、别名、重复头／叠加、identity／空列表、完整多 member／frame、边界大小可用；未知／非法编码、截断、校验失败、尾随垃圾、中间层超限、窗口及层数越界返回预期错误。用实际入口证明入站拒绝的上游请求和账号副作用为零。
- **AC3 → R4／R5**：实际 TCP 接收证明编码头、长度与最终压缩字节一致；近 10 MiB 合法正文重压缩不因容器开销误拒。401、至少两阶段 signature 修复及换号发送解码后的本次正确正文；本地缓存／拦截维持既有结果且不额外发包。
- **AC4 → R1–R5**：未压缩基线及 R2／beta／CCH 回归通过，`cargo fmt --check`、`cargo test --locked` 与 `cargo test --locked cch` 通过；验证记录明确区分依赖实验、Gateway 合成验证和缺失的新原生抓包。
