# 修复项目迭代全链路验收缺陷

## Goal

修复模拟验收发现的运行与界面缺陷，使项目批次能够稳定自动推进，并清楚展示调度状态和账号运行时段。

## Background

- 用户在全链路测试结果之后要求“修复问题吧”，本任务承接同一报告中的五项缺陷。
- 原验收 31 项通过、2 项失败；跨实例完成了 100 项目、2,000 个唯一步骤内容覆盖，但单批在 849 步、40 个完成项目时进入 blocked。
- 原始报告和诊断位于 `.deploy/v3-production-simulation-report-20261020/`；可随任务保存的事实、源码锚点及证据边界见 `research/evidence.md`。

## Constraints

- 保持原题库、配额／时段门禁、账号身份、同会话计划、部分唯一接受及原生字节边界契约；释放证明不完整时仍保护性阻塞。
- 保持现有 API 字段、数据库结构和静态前端架构。公开停止 API 原先对已终态请求的拒绝行为保留；项目内部停止可按已验证状态幂等收口。
- 不匹配错误文案来吞掉 400，不通过跳过文件校验或冻结证明获得通过。
- 实际运行验证只用合成账号和模型替身；真实模型请求为 0。原生产展示、凭据和业务数据及仓库原有变更保留。

## Acceptance Criteria

- [x] **AC-01**：确定性截取原子发布时刻，UID1000 可以立即读取完整决定；重复相同决定保持同一文件，决定变化及文件缺失时可正确发布／补发；普通私有 JSON 仍为原权限。
- [x] **AC-02**：在 open 与 fstat 之间替换文件可有界恢复；符号链接、硬链接、特殊／过大文件和持续不稳定替换仍失败，所有 fd 关闭。
- [x] **AC-03**：Run 在停止前和条件更新前进入终态的两种竞争均被覆盖；不覆盖终态，不重复清理，局部阻塞原因不被 cancelled／stopped 泛化，兄弟项目持续推进。认证／身份变化和严格清理失败继续维持批次强门禁。
- [x] **AC-04**：实际浏览器覆盖 active、paused、pausing、stopping、stopped、blocked、completed；终态无等待启动／下一投放提示，SSE 重绘保留滚动和路线展开。
- [x] **AC-05**：1280px／390px、明暗主题均无溢出；启用项和星期选择布局正确，关闭后保存不会被禁用的时间输入阻拦，重新启用保持配置，服务端时区与校验仍生效。
- [x] **AC-06**：按用户最新要求改为依据实际运行情况开展针对性验证，不以完整100×20作为本轮阻塞条件。记录同一批次已观察到的项目完成数、接受步数、重复接受检查与实测并发，并结合真实局部故障、停止、超时接续及逐步用量场景评估修复；明确保留尚未完成的全库／全会话审计边界，不拼接或宣称全量通过。
- [x] **AC-07**：相关单元、真实 Docker／driver／UI 验证通过，报告准确标注合成内容及参数；只清理本次隔离资源，保留结果和诊断证据。

## Non-Goals

- 本任务不包含生产发布、推送、真实账号推理测试、账号策略或题库内容修改。
- 不全面改版 UI，不增加依赖或框架，不修复／提交任务开始前的其他工作。
