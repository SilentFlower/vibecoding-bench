# v3 环境物理特征面板与实测信息

## Goal

让用户在 v3 环境页查看完整物理特征，能够分辨持久保存的配置、容器实测结果与尚未采集的信息。

## Background

代码位置与“当前”描述取自实施前 `7d705e3`；完成情况见实施记录和父任务组合验证。

- 来源为父任务 `../10-20-v3-environment-panel-and-run-windows/prd.md` 的 R1、R5。
- `webui/app.js:83` 当前只渲染简要环境卡片；`orchestrator/main.py:11196` 返回指纹但没有完整物理特征采集契约。
- 已有 `system_profile` 和 `computer_profile` 保存 CPU、内核及六个 DMI 字段：`orchestrator/system_profile.py:16`、`:20`、`:97`。
- 当前角色状态检查为只读，不唤醒容器：`orchestrator/account_runtime.py:485`。

## Requirements

- P1-R1：面板涵盖形态、采集时间、主机名、操作系统、内核、架构、CPU 型号及核心信息、内存、根文件系统、MAC、厂商、产品、版本、系列、序列号、UUID、Shell、包管理器、工具链、时区、语言区域和 machine-id 是否存在。
- P1-R2：标明保存配置、容器实测、未采集及观察时间，不能把保存值回填成已实测；有差异时明确展示，不自动修复或随机生成身份。
- P1-R3：实测只读取运行中的当前归属环境；停止、缺失、维护占用或采集失败时说明原因，并保留合法的上次观察信息。
- P1-R4：资源项有明确口径，RAM 上限使用实际 cgroup 限额，不能将宿主 `/proc/meminfo` 的总内存或 RAM 加 swap 当作容器 RAM；未知值不补零。
- P1-R5：页面读取和采集不改变容器生命周期、不调用模型或 OAuth、不改变 HOME、指纹、凭据、账号绑定和已有 CLI/API 隔离。
- P1-R6：复用父任务的有效时区口径，并与 P2 的当地时间和窗口摘要保持一致。

## Acceptance Criteria

- [x] 能在环境详情查看 P1-R1 所列字段，缺失项明确标为未采集。
- [x] 保存值与实测相同、不同、未采集和采集失败四类场景均能正确展示。
- [x] 正在运行的环境可完成有限时长的本地只读采集；停止或占用环境不会被页面或采集操作自动启动或重建。
- [x] 容器 RAM、swap 和宿主内存口径不混淆。
- [x] 采集前后持久身份、凭据和 HOME 摘要保持，独立 API 可继续服务。

## Out Of Scope

- 完整 SMBIOS 仿真、宿主硬件资产管理、KVM 和新指纹策略。
- 运行窗口的调度实施由 P2 负责；最终界面范围随父任务 Brief 一起审核。
