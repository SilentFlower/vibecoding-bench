# 真实项目完整工程目标库

内容 schema 3 包含 100 个真实项目，每个项目 6 个完整工程目标，共 600 个。原有 46 项合同保持原样，新增 554 项。每项都交付一个可运行功能或真实缺陷修复，包含业务源码变更、公开测试、独立行为验收与完整上游回归。

一次提问、源码解读、诊断、方案、测试或文档都不单独计数。调查、澄清、方案确认、编码、交付和必要返修属于同一个目标。研究中的 2,000 项路线提案及旧版短问答也不计入 600 项。

## Pi 如何推进

每个账号由一个 Pi 负责读取项目研究、选择工程目标和操作 Claude Code。Pi 根据真实终端观察发送文本或按键，提出业务要求、解答澄清、确认方案并推进实施；交流次数由实际工作决定。页面和进度说明为中文，项目交流可沿用原材料语言。

同一账号、项目和 seed 共用持久工作区。开始下一个目标时保留已有源码，只补齐本轮尚未安装的公开输入；输入冲突会停止准备，不会覆盖成果。目标的 `requires` 声明真实代码依赖。控制端根据当前账号身份及已通过的独立交付记录判断依赖，页面分别展示可开始和等待前置的数量，Pi 只能启动前置已满足的目标。

例如，Arrow 的严格时间格式导入依赖固定偏移及星期解析修复，日志解析报告又依赖严格格式导入；python-statemachine 从真实状态快照扩展为同步事件执行、异步执行、持久日志和受控重放。每一步分别完成可交付能力，而不是把研究、编码和测试拆成多个目标。

Claude 宣称完成后，Pi 使用 `project_submit` 冻结候选并请求独立验收。当前目标的业务程序和冻结完整回归通过后，同一个候选还需通过该账号在当前项目中此前已验收目标的业务程序。程序验收失败保留原会话返修；环境故障单独记录并有限重试，不能冒充业务通过。

## 运行与门禁

在 Projects 页面选择账号和授权项目池，保存业务指导及预算后即可启动。一次指挥可以继续多个目标；本轮结束后，启用的定时计划按已设置的间隔自动启动下一轮。仍有目标等待前置时不会被标成全部完成。

定时启动和手动启动共用账号身份、人工暂停、运行时段、认证、额度及消费归属门禁。五小时和七天额度阈值继续使用账号现有设置，额度未知或超限时按既有规则等待；计划不会绕过限制，也不为补充进度主动发起额度探测。输入投递结果未知时保留现场，禁止盲目重复发送。

Pi 模型配置复用管理端需求方设置：服务端可提供 `PROJECT_REQUESTER_BASE_URL`、`PROJECT_REQUESTER_API_KEY`、`PROJECT_REQUESTER_MODEL` 和 `PROJECT_REQUESTER_FALLBACK_MODEL`，页面可保存覆盖地址、密钥及有序模型列表。密钥仅保存在控制端私有设置中，读取接口不回显原值。项目合同、研究材料和验收资产均不包含账号凭据。

## 内容与证据

- `catalog.json` 和 `catalog-development.json`：当前 100 个可执行项目及准入状态。
- `projects/<key>/development.json`：6 个工程目标的背景、公开要求、授权路径、输入、依赖及独立验收引用。
- `seed/`：固定真实上游源码、应用与许可证；`environments/`：固定 Python、资源、精确依赖及离线制品。
- `materials/`、`disclosure/`：公开输入及 Pi 可以依据事实补充的需求方材料。
- `verification/`：控制端独立业务断言、公开测试校验、参考补丁及冻结完整回归。这些私有控制资产不进入 Claude 工作区。
- `development-audit.json`：100 项目的来源、研究、旧任务映射、600 项合同与依赖。
- `coverage-validation.json`：逐目标正反验证、来源摘要、完整回归及同仓累计验证证据索引。每项原版不满足要求、参考实现满足要求，六个累计前缀均通过全部已交付目标及完整原回归。

原有研究、真实源码和离线制品保持原样。旧 schema 2 定义保留为冻结兼容资产，不计入本目录目标，也不提供旧 Projects 历史页面。运行中的工作继续绑定开始时的冻结合同；内容更新不会把新验收条件套入旧会话。兼容的旧交付可作为后续目标前置，仍按原合同重验已有成果。

Collective Icalendar 的新目标使用独立资源档案，将完整回归上限设为 600 秒，保留全部 21,960 个原测试节点及其结果要求。原 180 秒档案保持原样，新档案的依赖、制品、内存和进程限制均与原档案一致。

HTML5lib 的新目标另用 1 GiB 回归内存档案，保留原 512 MiB 档案；所有原节点、结果要求、依赖、制品、业务资源和时间限制保持一致。完整报告中较大的诊断数组采用无损压缩档案保存，并单独校验解压内容与摘要。

## 本地复核

```bash
.venv/bin/python scripts/validate-project-library.py
.venv/bin/python scripts/validate-development-content.py \
  --image <本地账号镜像> --data <全新独立证据目录> --projects <项目标识>
.venv/bin/python scripts/validate-development-sequences.py \
  --image <同一账号镜像> --validation <上一命令的证据目录> \
  --project <同一项目标识> --label v1
```

第一条检查内容结构、依赖和离线制品摘要。第二条在无网络、无真实账号及模型调用的隔离容器中验证每个目标：原版失败、参考通过、授权范围、公开测试正反及冻结完整上游回归；有前置依赖时先累计前置实现。第三条按合法依赖顺序连续实施全部参考补丁，每个前缀都重放所有已完成目标的业务、公开测试和完整上游回归。

这些证据说明工程合同和验收链可执行，不代表真实 Claude 已完成 600 项，也不代表模型成绩。真实成绩只来自线上相应账号的独立通过交付记录。
